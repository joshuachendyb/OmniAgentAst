## 第1章 总则

### 1.1 二分法：agent 类与 tool 类

系统所有写盘行为只分两类，判定看「谁决定路径」：

| 类别 | 判定 | 目录规矩 |
|---|---|---|
| **agent 类** | 系统自身产出，路径由系统固定规则决定，与 LLM 意图无关 | 归各自的解析口（日志 / 数据目录 / 任务记录 / 临时区），不挂会话工作区 |
| **tool 类** | LLM 调用的工具，路径由「系统提供的目录」决定 | 落事项工作区的三个子目录之一（`attachments` / `output` / `temp`） |

第三类不入二分法：**用户指定路径**的工具（`copy_file` / `write_text_file` / `write_docx` 等），LLM 调用时已给出目标路径，系统只对目标父目录 `mkdir`，不提供默认目录。

### 1.2 四个目录解析口（唯一出口纪律）

| 解析口 | 位置 | 解析规则 | 服务对象 |
|---|---|---|---|
| `get_tool_dir(kind)` | `app/utils/path_utils.py` | 会话默认工作区优先 → 兜底项目根 | tool 域三个子目录（分配口，建目录；只读场景用同文件的 `get_tool_dir_path`） |
| `resolve_db_dir()` | `app/db/database.py` | `OMNIAGENT_DATA_DIR` 优先 → 兜底 `~/.omniagent` | 数据根：库目录 `db\`、资产 `assets\`、回收站 `recycle_bin\` |
| `_files_root()` | `app/file_persist.py` | 调试 `backend/files`／打包 `exe/files`／正式 `~/.omniagent/files` | 任务工具记录（`Sion_*`） |
| `LOG_DIR` | `app/logger/config.py` | 打包 `exe/logs`／源码 `backend/logs` | 运行日志、提示词日志、诊断转储、供应商验证报告（启动日志例外，见 3.2） |

纪律：**同一类目录只准有一个解析口**。任何地方重拼路径（`Path.home()/".omniagent"`、`Path(__file__).parents[2]/"logs"`）都会在不同运行形态（源码 / 打包 / 测试）下分叉，属缺陷。

### 1.3 三种运行形态的分流

| 形态 | 判定 | 日志根 | 记录根 | 数据根 |
|---|---|---|---|---|
| 源码调试 | `logging.debug=true` | `backend/logs` | `backend/files` | `~/.omniagent`（或 `OMNIAGENT_DATA_DIR`） |
| 源码正式 | `logging.debug=false` | `backend/logs` | `~/.omniagent/files` | 同上 |
| 打包运行 | 进程 `frozen` | `exe所在目录/logs` | `exe所在目录/files` | 同上 |

数据根与运行形态**无关**：库目录 `db\`、资产 `assets\`、回收站 `recycle_bin\` 永远共享 `resolve_db_dir()` 一个根，测试靠环境变量改变它。

## 第2章 tool 域

### 2.1 事项工作区布局

```
{项目根}\{YYYYMMDD-HHMMSS}-{会话id前4}\      ← 会话-scoped，系统生成、面板禁改
├── attachments\   附件：用户上传、同机导入、存为附件、物化、生图生视频
├── output\        工具产物：下载文件、图表、截图、后台命令输出
└── temp\          中间态：执行脚本、注册表备份（用完即弃）
```

目录名由 `workspace_service._build_default_workspace_dir` 生成：时间戳 + 会话 id 前 4 位，Windows 非法字符替换为 `_`；同名已存在则复用同一路径。

建目录只有一处：`_ensure_ws_dir` 只建**默认工作区**；用户在面板添加的目录只做存在性与合法性校验，**系统绝不代建**（磁盘目录归用户处置），失效行由 `prune_unusable_rows` 清库，不删磁盘。

### 2.2 目录分配口契约（`get_tool_dir` / `get_tool_dir_path`）

```python
def get_tool_dir(kind: str = "output") -> str:        # 分配口：解析 + mkdir
def get_tool_dir_path(kind: str = "output") -> Path:  # 纯路径：只解析，不做 IO
```

| 项 | 规定 |
|---|---|
| 参数 | `kind` 只接受 `attachments` / `output` / `temp`，其余抛 `ValueError` |
| 第一选择 | 任务级快照 `session_workspace.get_ws_snapshot()` 中 `is_default` 条目的路径 + `kind` |
| 兜底 | 快照不可用（启动期、无任务上下文）→ `get_config().get_project_root()` + `kind`；项目根未配置时回落用户主目录，故兜底恒有值 |
| 返回值 | 分配口返回已 `mkdir(parents=True, exist_ok=True)` 的绝对路径字符串；纯路径口返回 `Path`，不建目录、不触碰磁盘 |
| 不接受 | **没有 `session_id` 形参**——会话由任务快照带入，调用方不需要也不能传 |

两个函数共用同一套解析规则（分配口内部调用纯路径口后补 `mkdir`），区别只在**是否落 IO**：要往里写文件用分配口，只做边界校验、枚举、存在性判断用纯路径口。

### 2.3 写入口名单（系统提供目录的工具）

| 工具 | 子目录 | 出处 |
|---|---|---|
| `download_file` | `output`（未给 `dest` 时） | `download_file.py:177` |
| `generate_chart` | `output` | `generate_chart.py:216` |
| `shell_background` | `output` | `shell_background.py:107` |
| `screen_capture` | `output` | `screen_capture.py:88/114/124` |
| `generate_image` / `generate_video` | `attachments`（经 `save_generated_bytes`） | `attachment_service.py:344` |
| `registry_read` | `temp`（导出前备份） | `registry_read.py:89` |
| `execute_shell_command` | `temp`（`.bat` 中间脚本） | `execute_shell_command.py:1321` |

给了 `dest` 的 `download_file` 属「用户指定路径」，走 `absolutize_path(dest, 项目根)`，不进本表。

### 2.4 读口不建目录

| 位置 | 行为 | 后果 |
|---|---|---|
| `bg_task_query._within_output_dir` | 边界校验调 `get_tool_dir_path("output")` | 只算路径，不建目录 |
| `shell_background._bg_output_dirs` | 除当前分配口外，额外枚举 `{项目根}/*/output`；枚举本身走 `get_tool_dir_path` | 跨会话找回上一世产物（启动期没有快照，只扫分配口会漏），扫盘不建目录 |

纪律：只读路径（边界校验、枚举、巡检）一律走 `get_tool_dir_path`；只有确实要落文件时才调 `get_tool_dir`。

历史副作用：修复前这两个读口都调分配口，启动期没有会话快照、兜底到项目根，于是**每次重启都在用户项目根新建空 `output\`**；`bg_task_query` 查一次后台产物同样会建。`E:\data-doc` 根上现存的空 `attachments\`、`output\` 即由此累积，属存量残留，可直接删除；修复后重启不再新生。

### 2.5 附件落盘（与 tool 域共用目录）

| 入口 | 用途 | 关键约束 |
|---|---|---|
| `ensure_session_attachment_dir(session_id)` | 附件目录唯一解析函数 = 默认工作区 + `attachments` | 默认工作区缺失时先 `reconcile_session_workspaces` 幂等补建 |
| `save_bytes` | 用户上传 | 校验会话、计入配额、限单文件大小 |
| `save_generated_bytes` | 系统产出（生图生视频） | 不校验会话、不计配额、不设单文件上限；按 `(session_id, sha256)` 去重；登记失败仍返回磁盘路径 |

附件台账在 `attachments` 表，物理目录在事项工作区。会话删除不带走附件文件，全局收藏另存 `assets/`（agent 域）。

### 3.1 写入点全表

|---|---|---|---|---|
| 1 | 运行日志 | `{LOG_DIR}/app_日期.log` + `.log.N` | `logger.config.LOG_DIR` | 按大小轮转（默认 10 MB × 5）+ 保留 10 天 |
| 2 | 提示词日志 | `{LOG_DIR}/prompt-logs/prompt_<消息id后6位>+<uuid8>+<时间>.json` | `prompt_logger.PromptLogger.__init__` | 保留 10 天 |

### 3.2 日志的四个来源

| 来源 | 内容 | 是否走 `LOG_DIR` |
|---|---|---|
| `app_日期.log` | 业务日志，`SafeRotatingFileHandler` 按大小轮转 | 是 |
| `prompt-logs/` | 单次请求的提示词组装快照（JSON） | 是（子目录） |
| `boot_日期.log` | 进程启动期标准输出/错误重定向 | **否**（`console_mode` 自行拼 `logs`） |
| `pyspy/` | 事件循环停摆时的 py-spy 栈转储 | 是（子目录） |

`boot_日期.log` 不走 `LOG_DIR` 是唯一例外：它在日志系统初始化**之前**就要接管 stdout/stderr，无法依赖 `LOG_DIR` 已就绪。它与 `LOG_DIR` 打包后同落 `exe/logs`，源码态同落 `backend/logs`。

保留期清理的判定基准是**目录**而不是文件名：`{LOG_DIR}` 全树递归，超期文件一律删，子目录清空后连同目录一并删，日志根本身不删。不设白名单——白名单本身就是漏网来源，任何未登记的名字（手工副本、早期格式、诊断转储）都会永久残留；改为整目录口径后，新增日志形态自动纳入清理，不必回来改清理代码。正在被 handler 写入的当前文件在 Windows 上删不掉（占用），直接跳过，次日自然命中。目录内的供应商验证报告同样受这一期限约束，需要长期留存的报告应另存到记录根或用户目录。

### 3.3 数据目录

```
{数据根}/                      ← resolve_db_dir()：OMNIAGENT_DATA_DIR 或 ~\.omniagent
├── db\                        5 个库统一入子目录
│   ├── chat_history.db        会话/任务/消息/附件台账
│   ├── operations.db          文件操作台账（回滚依据）
│   ├── timers.db              定时器
│   ├── task_tracker.db        任务统计
│   └── monitoring.db          HTTP 请求监控
├── assets\YYYYMM\             全局收藏资产（跨会话）
└── recycle_bin\{ts}_{uuid8}\  文件操作前的备份副本
```

代码在根上只建三类子目录（库 / 资产 / 回收站），备份与清理可以按类区分，不必在一堆同名 `.db` 里挑。

`assets` 与 `recycle_bin` 挂在数据根而不是项目根：它们与库同生命周期，且必须能被 `OMNIAGENT_DATA_DIR` 一并重定向（测试隔离要求）。

库文件路径只有 `db_file_path(db_name)` 一个拼装点（库文件名真源为 `database._DB_FILES`），不建目录、不迁移，CLI 与只读场景可直接用。历史版本把 5 个库平铺在数据根，`get_conn` 在首次连接前调 `ensure_db_layout()` 完成一次性迁移：主库与 `-wal` 先复制成 `.migrating` 中间名 → 逐个校验大小一致 → 全部通过才改名成正式库 → 最后清原位副本。任一步失败只留中间名并清掉，原库原样不动等下次启动重试，因此不会出现「新库落了却没带上 WAL」这种半套状态（SQLite 会当成完整库读，少掉最近事务）。`-shm` 不复制：它是进程本地的共享内存索引，带过来只是过期状态，SQLite 打开时自行重建。新位置已有同名库则跳过，重复运行与「降级后再升级」都安全；原位副本被其它进程占用删不掉时只告警，新库照常使用。迁移按数据目录各跑一次，`OMNIAGENT_DATA_DIR` 指向不同目录时互不影响；测试注入走 `_db_overrides`，不触发迁移。

回退旧版本的风险要认：旧代码只认根上的库文件，降到旧版会新建空库（表现为历史会话全空）。降级前需把 `db\` 内容搬回根上。

### 3.4 任务工具记录与验证报告

`{记录根}/Sion_<会话id>/Task_<任务id>/` 是任务级落档，两类文件：

- `tool_data_*.jsonl`：一个块 = 一次工具结果；
- `conv_hist_*.jsonl`：一个块 = 一条消息。

目录前缀是常量单一源（`SESSION_DIR_PREFIX` / `TASK_DIR_PREFIX`），物理目录与 `chat_tasks.files_dir` 落库锚都由此拼装。

供应商比对报告是**服务级**产物，落 `{LOG_DIR}/zen_verify/`，与任务记录（会话级）分开放。旧版本把 `zen_verify/` 放在记录根与 `Sion_*` 同级，属语义混放；`_report_dir()` 首次访问时若旧目录存在则一次性 rename 迁入新目录，故历史报告不丢。文件名与内容格式不变，前端经 API 读取，不感知路径。该目录在日志根内，随日志保留期一起清，需要长期留存的报告另行导出。

### 3.5 临时区

| 用途 | 位置 | 清理 |
|---|---|---|
| shell 沙箱工作区 | `%TEMP%/omniagent_sandbox/{uuid}_{ts}` | 执行结束 `destroy()`，重试后仍失败则明确报错 |
| 视频转码缓存 | `%TEMP%/omniagent_video_h264` | 保留 10 天（启动 `sweep_cache`），同源文件复投命中复用 |

沙箱放 `%TEMP%` 是刻意的：它要承接被测命令的临时产物，不能挂进用户项目根，也不该进数据根（避免污染台账）。转码缓存同理——它是可再生的中间态，丢了只会多转一次码。两处保留期都取 `logging.retention_days`，与日志同一口径。

## 第5章 新增写入点的检查清单

任何新增写盘行为，落库前逐条核对：

| # | 检查项 | 判据 |
|---|---|---|
| 1 | 先归类 | 是 agent 类还是 tool 类？（谁决定路径） |
| 2 | agent 类 | 必须复用四个解析口之一，禁止自拼 `Path.home()`、`Path(__file__).parents`、`%TEMP%` 字面量 |
| 3 | tool 类 | 必须走 `get_tool_dir(kind)`；只做校验/枚举不落盘时走 `get_tool_dir_path(kind)`，`kind` 只选 `attachments` / `output` / `temp` |
| 4 | 用户指定路径 | 只对目标父目录 `mkdir`，不提供默认目录、不猜路径 |
| 5 | 会话语义 | 需要会话隔离的必须挂事项工作区；跨会话的才进 `assets/` |
| 6 | 可重定向 | 数据类必须经 `resolve_db_dir()`，库文件经 `db_file_path()`，保证 `OMNIAGENT_DATA_DIR` 生效（测试隔离前提） |
| 7 | 运行形态 | 日志/记录类必须经 `LOG_DIR` / `_files_root()`，打包后不能写进解包临时目录 |
| 8 | 清理策略 | 只增不减的目录必须写明谁清、按什么清；日志类落 `{LOG_DIR}` 内即自动纳入 `logging.retention_days` 整目录清理，临时缓存挂 `sweep_cache`，其余没有清理策略的不得新增 |
| 9 | 读口副作用 | 只读路径（查询、列表、巡检）不得调用 `get_tool_dir` 等会 `mkdir` 的分配口，改走 `get_tool_dir_path` |
| 10 | 文档同步 | 新写入点登记进 3.1 全表，含落点、解析口、生命周期 |

## 附录 A 速查表

| 要写什么 | 用哪个口 | 落到哪里 |
|---|---|---|
| 工具产物（下载/图表/截图/后台输出） | `get_tool_dir("output")` | `{事项工作区}/output/` |
| 会话附件（上传/生成图视频） | `ensure_session_attachment_dir` / `save_generated_bytes` | `{事项工作区}/attachments/` |
| 中间脚本、注册表备份 | `get_tool_dir("temp")` | `{事项工作区}/temp/` |
| 只做路径校验、不落文件 | `get_tool_dir_path(kind)` | 只返回路径，不建目录 |
| 数据库（5 个库） | `db_file_path(db_name)` | `{数据根}\db\` |
| 全局资产、回收站 | `resolve_db_dir()` | `{数据根}\assets\`、`{数据根}\recycle_bin\` |
| 任务工具记录 | `_files_root()` | `backend/files` 或 `~/.omniagent/files` |
| 供应商验证报告 | `zen_verify._report_dir()` | `{日志根}/zen_verify` |
| 运行/提示词/诊断日志 | `LOG_DIR` | `backend/logs` 或 `exe/logs` |
| 启动期标准输出 | `console_mode._boot_log_path` | 同 `logs` 根 |
| 沙箱/转码这类一次性中间态 | `tempfile.gettempdir()` | `%TEMP%/omniagent_*` |
