## 一、天条铁规

| 要求 | 含义 | 违反后果 |
|------|------|---------|
| **打起精神** | 专注不松懈，不敷衍凑合 | 退回重做 |
| **脑子清醒** | 逻辑严密，不凭感觉记忆 | 重新分析 |
| **保持思考** | 每步想"为什么"，不机械执行 | 停止操作 |
| **拒绝糊涂** | 不清楚就问，不确定就查 | 退回重做 |
| **积极主动** | 主动分析，不浅尝辄止 | 退回重做 |

**动手前四问**：
1. 我清楚要做什么吗？
2. 我理解为什么这样做吗？
3. 我检查过相关代码吗？
4. 我确认过改得对吗？

---

## 二、核心原则

```
做对 > 做完
质量 > 速度
完整 > 部分
闭环 > 开环
```

---

## 三、工作流程

```
读 → 画图 → 方案 → 确认 → 修改 → 验证 → 报告
```

| 步骤 | 要求 |
|------|------|
| **读** | 读完整文件，不片段 |
| **画图** | 画数据流程图，列所有情况 |
| **方案** | 说清楚改什么、怎么改 |
| **确认** | 等用户说"同意" |
| **修改** | 追踪数据流，不遗漏 |
| **验证** | 编译 + 测试，实际验证 |
| **报告** | 结构化完整，不糊弄 |

**禁止**：
- ❌ 凭记忆分析 → 必须重新读代码
- ❌ 先斩后奏 → 方案确认后再动手
- ❌ 绕概念 → 直接看数据结构
- ❌ 不画流程图 → 必须列清所有情况

---

## 四、做事流程

| 阶段 | 要求 | 检查项 |
|------|------|--------|
| **做事前** | 完整读设计文档，列所有待办 | 功能点都列了吗？ |
| **做事中** | 边做边检查，追踪所有引用 | 引用都更新了吗？ |
| **做事后** | 全面检查，运行测试，版本管理 | 测试都通过了吗？ |

---

## 五、常见教训

| 教训 | 根因 | 正确做法 |
|------|------|---------|
| thought字段写错 | 没读字段汇总表，照抄 | 先读表再写，写完核对 |
| 多意图重构返工 | 被动应付，没读完文档 | 完整读文档，全面检查 |
| React模式混淆 | 绕概念，凭记忆 | 直接看数据，画流程图 |

---

## 六、正面清单

**做得好**：
- 事前备份 → 可追溯回滚
- grep检查引用 → 不遗漏
- 运行测试 → 保证正确
- 更新文档 → 文档一致
- 规范commit → 历史清晰

**坏的重构**：留旧代码、漏引用、不更新文档、commit随意

---

## 七、文档规范

| 规则 | 说明 |
|------|------|
| 版本历史放开头 | 必须有版本、时间、签名、更新内容 |
| 禁止删除历史 | 只准追加 |
| 时间必须真实 | 执行`Get-Date -Format "yyyy-MM-dd HH:mm:ss"`获取 |

## 八、前端控件规格铁律（2026-11-12 小欧 增补）

| 规则 | 说明 | 违反后果 |
|------|------|---------|
| **控件规格唯一定义点** | 控件高/圆角的**全部档位**只能在 `frontend/src/theme/controlScale.ts` 定义；其它任何文件不得写死控件高数值或另立刻度表 | 退回重做 |
| **禁沿用 UI 库缺省值** | 不得把 UI 库的缺省 token（如 antd 的 `controlHeight` 32 / `borderRadius` 6）当作项目标准；缺省值只作反例 | 退回重做 |
| **禁依赖库的派生公式** | 库按公式派生的档位（antd 的 `controlHeightSM` = base×0.75、`controlHeightLG` = base×1.25 等）必须**显式下发**后再用；放任派生会产出 21/35 这类非 4px 网格值 | 退回重做 |
| **密度只切档位** | 界面密度 = 「哪一档控件高生效」，不是「在某基线上减几 px」；密度**不得改字号** | 退回重做 |
| **字号恒 14** | 控件内字号恒 14px；**禁止用 antd `componentSize` 承载密度**（其 small 档会把 `Select`/`DatePicker` 字号切到 12） | 退回重做 |
| **流水线零变化** | 流水线（消息渲染区）控件在两档密度下必须像素不变；流水线内唯一 antd 控件走 small 档，故 small 档两档同值 | 退回重做 |
| **数字只在 TS 一处** | CSS 只消费 TS 解算出的变量，不得在 CSS 里写像素数字（与 [30] 排版单一真源同源纪律） | 退回重做 |

配套设计文档：`doc-11月优化/[32]全站控件刻度统一与界面密度设计-小欧-2026-11-12.md`（含推导、实证与验收线）。

前端落地执行清单：`frontend/FUNCTIONS_FRONT.md` §使用规则「前端控件规格铁律（强制）」（本条铁律在前端侧的同源登记与唯一执行位置）。
