# [8] 环境变量命名规范

**制定时间**: 2026-11-26
**更新时间**: 2026-11-26 18:46:00
**制定人**: 小欧
**适用范围**: 后端全部自有环境变量（`backend/app` 生产代码）及环境变量名的集中管理；附带常量分层收敛原则。不含框架/OS/第三方生态约定名。

---

## 第1章 总则

### 1.1 为什么要有这份规范

系统自有环境变量此前分三套前缀并存（`OMNIAGENT_`、`OMNI_`、无前缀裸名），且变量名分散在各读取点以字符串字面量硬编码。后果有三：

- **难记**：`OMNIAGENT_` 前缀偏长，日常部署和口述排障都不顺手；同一系统十几个变量又分散在三种写法下，无法凭名字归类。
- **易漏**：变量名没有单一真源。同一个 `OMNIAGENT_ACCESS_TOKEN` 在 `deps.py:47`、`config.py:67`、`settings_registry.py:480` 各写一遍，`AI_PROVIDER` 在 `config.py:155`、`settings_registry.py:268`、`model_service.py:379`、`config_helpers.py:394` 各写一遍。改一次名要横扫全仓，漏一处就是"页面对、实际错"。
- **难维护**：进程宿主的握手与并发参数逐项平铺注入（5 行 env 注入），改动时四处对齐。

本规范把变量统一到**短前缀 `OMNI_`**，把变量名**集中到单一常量文件**，并给出存量清册、收敛映射与**逐文件可落地的改造代码**。本文已进入详细设计阶段：第3章起所有代码块均为可直接实施的最终代码，不再保留"示意"。

### 1.2 适用范围与豁免

- 本规范约束**本项目自有**环境变量（第5章的 19 个）及其名称定义方式。
- 以下属于**外部生态约定名，豁免本规范、保持原名不动**，仅在代码注释中标注"外部约定，勿加前缀"：
  - `<PROVIDER>_API_KEY`（如 `OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`AGNES_API_KEY`）——各厂商 SDK 通用约定；
  - `TAVILY_API_KEY`——Tavily 官方约定；
  - `FORWARDED_ALLOW_IPS`——uvicorn 标准参数；
  - `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`——OS/业界标准代理变量；
  - `SHELL`、`SystemDrive`、`SystemRoot`、`TEMP`、`TMP`、`COMPUTERNAME`——OS 标准变量。

对外部约定名改名会破坏与其他工具的互操作（把 `OPENAI_API_KEY` 改成 `OMNI_OPENAI_API_KEY` 就无法复用用户已有的密钥配置），因此明令禁止。

## 第2章 命名规则

### 2.1 唯一前缀 `OMNI_`

项目自有环境变量一律以 **`OMNI_`** 开头：

- 弃用冗长的 `OMNIAGENT_`，统一收为 `OMNI_`（短、可记、不牺牲区分度；系统本身即 OmniAgent，无需在变量名里再拼全称）；
- 禁用无前缀裸名（`AI_PROVIDER`、`LOG_LEVEL`、`CORS_ORIGINS` 之流统一加前缀）；
- 前缀后紧跟语义名，语义名本身够清晰时**不再强加域段**（KISS-DIRECT：不为分组塞入无意义中间层）。

### 2.2 骨架：`OMNI_<语义项>`

默认骨架是「前缀 + 语义项」，语义项用大写单词、下划线分隔，例如：

```
OMNI_CONFIG_PATH
OMNI_DATA_DIR
OMNI_ACCESS_TOKEN
OMNI_REQUIRE_AUTH
OMNI_ENABLE_API_DOCS
OMNI_ATTACHMENTS_TRUSTED_PROXIES
```

当若干变量构成**同族多变量**、单看语义项易混时，才加**族前缀**区分，例如：

```
OMNI_PROC_HANDSHAKE     # 进程宿主握手（族：PROC，内部注入）
OMNI_PROC_CONCURRENCY   # 宿主并发上限（可选覆盖口）
OMNI_PROC_MAX_OUTPUT_MB # 宿主单命令输出上限(MB)（可选覆盖口）
OMNI_DEBUG_KEEP_CONSOLE # 排障开关（族：DEBUG）
OMNI_DEBUG_SPAWN_STRICT
```

域（CONFIG/DATA/AUTH/AI/LOG/NET/ATTACH/PROC/DEBUG）用于**代码分组与归类**，不是每名必带的三段式；是否进入名字由"单看语义项是否已唯一清晰"决定。

### 2.3 类型后缀与取值约定

| 值类型 | 命名约定 | 读取方式 |
|---|---|---|
| 文件路径 | 花 `_PATH` | 字符串 |
| 目录 | 花 `_DIR` | 字符串 |
| 布尔开关 | 无后缀，靠语义 | 统一 `env_flag()`（空/`0`/`false` 视为关，其余视为开） |
| 数值（带单位） | 后缀带单位 `_DAYS` / `_SEC` / `_MB` / `_MS` | `int()`/`float()` 失败须降级并告警，不得抛穿启动 |
| 列表 | 无后缀，值用逗号或分号分隔 | 由调用方 split 并 strip 去空 |

### 2.4 大小写与分隔

- 变量名**只允许** `[A-Z0-9_]`；
- 不得以数字开头，不得以下划线结尾；
- 全部大写，禁止驼峰、禁止连字符。

## 第3章 变量名集中管理（env_keys.py）

### 3.1 为什么要集中

变量名是**跨层共享的部署契约**：读取点在 `config.py`/`main.py`/`deps.py`/`database.py`/`attachments`/`proc` 等多处，前端"来源=环境变量"标签又经 `settings_registry` 的 `env_key` 依赖同一名字。名字一旦分散成字面量，改名就得靠人肉横扫全仓，必然漏改。

因此把变量名当作常量集中管理，落到**一个文件**：`backend/app/env_keys.py`。

### 3.2 文件定位与依赖约束

- **位置**：`app/env_keys.py`（app 根，与 `constants.py` 同级）。
- **只依赖 `os` 与标准库 `typing`，不 import 任何 app 内模块**。这是硬约束：`config.py` 在 `app.logger` 导入期就被调用，而 `logger→config→services→db` 已是一条早存在的依赖链；env_keys 必须是比 `config` 更底层的零依赖模块，任何层都能安全 `from app.env_keys import ...` 而不成环。
- **禁止** env_keys 反向 import `app.config` / `app.services`。

### 3.3 完整代码（定稿，可直接落盘）

`backend/app/env_keys.py`：

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-26 - 小欧 - 新建: 环境变量名单一真源(零依赖), 集中变量名+读取 helper+旧名映射 — 小欧-2026-11-26
"""env_keys — 环境变量名单一真源。

约束: 只 import os 与标准库 typing; 禁止 import 任何 app 内模块。
  原因: config.py 在 app.logger 导入期即被调用, 依赖链 logger→config→services→db 已存在;
  env_keys 必须比 config 更底层, 任何层都能安全引用而不成环。
"""
import os
from typing import Dict, List, Tuple

# ── 配置 / 路径 ──
CONFIG_PATH = "OMNI_CONFIG_PATH"
DATA_DIR = "OMNI_DATA_DIR"

# ── 鉴权（留：密钥不落盘 / 安全开关）──
ACCESS_TOKEN = "OMNI_ACCESS_TOKEN"
ACCESS_TOKEN_ALLOWLIST = "OMNI_ACCESS_TOKEN_ALLOWLIST"
REQUIRE_AUTH = "OMNI_REQUIRE_AUTH"

# ── 进程宿主（并：握手单串；迁：两个可选覆盖口）──
PROC_HANDSHAKE = "OMNI_PROC_HANDSHAKE"     # 内部握手, base64(json), 用户不设置
PROC_CONCURRENCY = "OMNI_PROC_CONCURRENCY" # 覆盖口, 主源 tuning.concurrency.shell_max_processes
PROC_MAX_OUTPUT_MB = "OMNI_PROC_MAX_OUTPUT_MB"   # 覆盖口, 主源 tuning.shell_fg_max_output_mb

# ── 调试开关（留：仅排障/验证）──
DEBUG_KEEP_CONSOLE = "OMNI_DEBUG_KEEP_CONSOLE"
DEBUG_SPAWN_STRICT = "OMNI_DEBUG_SPAWN_STRICT"

# ── 迁档可选覆盖口（主源在 config, env 仅部署期临时覆盖）──
ENABLE_API_DOCS = "OMNI_ENABLE_API_DOCS"                         # 主源 server.enable_api_docs
ATTACHMENTS_TRUSTED_PROXIES = "OMNI_ATTACHMENTS_TRUSTED_PROXIES" # 主源 network.attachments_trusted_proxies

# ── 旧名→新名（启动告警：仅提示, 不读取; 禁止 backward）──
DEPRECATED: Dict[str, str] = {
    "OMNIAGENT_CONFIG_PATH": CONFIG_PATH,
    "OMNIAGENT_DATA_DIR": DATA_DIR,
    "OMNIAGENT_ACCESS_TOKEN": ACCESS_TOKEN,
    "OMNIAGENT_ACCESS_TOKEN_ALLOWLIST": ACCESS_TOKEN_ALLOWLIST,
    "OMNIAGENT_REQUIRE_AUTH": REQUIRE_AUTH,
    "OMNIAGENT_ENABLE_API_DOCS": ENABLE_API_DOCS,
    "OMNI_KEEP_CONSOLE": DEBUG_KEEP_CONSOLE,
    "OMNI_SPAWN_STRICT": DEBUG_SPAWN_STRICT,
    "OMNI_PROC_HOST_PIPE": PROC_HANDSHAKE,
    "OMNI_PROC_HOST_KEY": PROC_HANDSHAKE,
    "OMNI_PROC_HOST_PARENT_PID": PROC_HANDSHAKE,
    "OMNI_PROC_HOST_LOG": PROC_HANDSHAKE,
    "OMNI_PROC_HOST_CONCURRENCY": PROC_CONCURRENCY,
    "OMNI_PROC_HOST_MAX_OUTPUT": PROC_MAX_OUTPUT_MB,
}

# ── 删档旧名→配置项（启动告警：提示改用 config, 不再读取）──
REMOVED: Dict[str, str] = {
    "AI_PROVIDER": "config.yaml 的 ai.model_ref.provider（设置页「模型」）",
    "LOG_LEVEL": "config.yaml 的 logging.level（设置页「日志级别」）",
    "CORS_ORIGINS": "config.yaml 的 network.cors_origins（设置页「允许访问的页面地址」）",
    "CHAT_RETENTION_DAYS": "config.yaml 的 system.chat_retention_days（设置页「对话历史保留天数」）",
    "OMNIAGENT_CHAT_RETENTION_DAYS": "config.yaml 的 system.chat_retention_days（设置页「对话历史保留天数」）",
}


def env_nonempty(name: str) -> bool:
    """环境变量非空且非纯空白 — 2026-09-21 小欧: env 覆盖语义统一单点。"""
    v = os.environ.get(name)
    return bool(v and v.strip())


def env_flag(name: str, default: str = "0") -> bool:
    """布尔型环境变量: 空/0/false(忽略大小写)视为关, 其余视为开。"""
    return (os.environ.get(name) or default).strip().lower() not in ("", "0", "false")


def deprecated_in_use() -> List[Tuple[str, str]]:
    """当前仍被设置的旧名→提示列表(仅供启动告警; 不参与读取)。

    覆盖两类: DEPRECATED(改名→改用新 env) 与 REMOVED(删档→改用 config 键)。
    """
    hints: List[Tuple[str, str]] = []
    for old, new in DEPRECATED.items():
        if env_nonempty(old):
            hints.append((old, f"改用 {new}"))
    for old, target in REMOVED.items():
        if env_nonempty(old):
            hints.append((old, f"已移除, 请改用 {target}"))
    return hints
```

### 3.4 读取 helper 的归属

`env_nonempty` / `env_flag` 从 `config.py` 原样下沉到 `env_keys.py`，作为唯一实现。**不新增** `get` / `int_value` 等包装：现有读取点的数值解析已是 `int()` + `try` 模式，再包一层属 YAGNI；helper 只保留已被多处复用、语义统一的两个。

下沉后，`config.py` 不再定义这两个函数，全部调用方改为 `from app.env_keys import env_nonempty` / `env_flag`。受影响调用方仅 3 处（`main.py`、`settings_service.py`、`config_helpers.py`），不含任何间接依赖。

### 3.5 旧名检测与告警

改名/删档遵循项目"禁止 backward"纪律：**不保留旧名读取分支**，旧名不再生效。但老部署若仍设着旧名，程序静默忽略会造成难排查问题，故启动时须对照 `DEPRECATED`（改名）与 `REMOVED`（删档）两表**检测并显式告警**（仅告警，不兼容读取）：

```
[env] 检测到已废弃环境变量 OMNIAGENT_DATA_DIR：改用 OMNI_DATA_DIR（旧名已不生效）
[env] 检测到已废弃环境变量 OMNI_LOG_LEVEL：已移除, 请改用 config.yaml 的 logging.level（设置页「日志级别」）（旧名已不生效）
```

## 第4章 变量分类

### 4.1 用户配置型

本章按"用途"分类，回答"这个变量是干什么的"；至于"该不该继续用 env"的删/迁/并/留四档治理，见第5章。

供部署者/运维在启动前设置，用于覆盖 `config.yaml` 或指定路径。**必须**：进 README / 打包文档的"环境变量覆盖"章节；在 `settings_registry` 有对应设置项者标注 `env_key`/`env_inject`（保证前端标签与实际生效值一致）；读取走 `env_nonempty()`/`env_flag()`。

代表：`OMNI_CONFIG_PATH`、`OMNI_DATA_DIR`、`OMNI_ACCESS_TOKEN`、`OMNI_REQUIRE_AUTH`、`OMNI_ENABLE_API_DOCS`、`OMNI_ATTACHMENTS_TRUSTED_PROXIES`（其中后三项的治理档位分别为留/迁/迁，见第5章）。

### 4.2 内部注入型

父进程拉起子进程（进程宿主）时一次性注入的握手/运行时参数，**用户不应设置、不进文档**。**必须**：用**单个变量**承载（`base64(json)` 单串），子进程入口一次解包，不再逐项平铺；与目标进程生命周期绑定（每实例重生成），不落盘、不进配置。

代表：`OMNI_PROC_HANDSHAKE`（原管道名/authkey/父PID/日志路径/并发度 5 项合并为 1）。

> 命名说明：不复用 `OMNI_PROC_HOST`。该名在 2026-11-26 曾是"本地回退开关"（已随三堂会审删除），同名会与历史残留测试、注释混淆。`OMNI_PROC_HANDSHAKE` 如实表达"握手串"，无歧义。

### 4.3 调试开关型

仅排障/验证期临时开启，生产默认关闭。**必须**归入 `OMNI_DEBUG_` 族，名字直白，代码注释写明"仅排障/验证，生产不得设置"。

代表：`OMNI_DEBUG_KEEP_CONSOLE`、`OMNI_DEBUG_SPAWN_STRICT`。

### 4.4 外部约定型（豁免）

见第1.2节。保持生态原名，不做前缀改造。

### 5.2 四档治理定义

| 档位 | 判定 | 处置 |
|---|---|---|
| **删** | `config.yaml` 与设置页**已有同一配置项**，env 是重复的第二通道（典型病灶：设置页改了不生效，因 env 覆盖） | 删除 env 读取分支，只保留 config/设置页 |
| **迁** | 目前**只有 env、`config.yaml` 无对应键**，但本质上属可落盘配置 | 新增 config 键为主源；env 降为部署期"可选覆盖口"（不进设置页 UI 的运维/安全项） |
| **并** | 一组同源、逐项平铺注入的内部参数 | 合并为单个 `base64(json)` 握手串 |
| **留** | config 无法表达或不应表达（引导路径 / 密钥 / 安全开关 / 排障开关 / 内部注入） | 保留 env，仍按 `OMNI_` 改名 |

**删与迁的分界**：`config.yaml` 已有键 = 删（去重复）；无键 = 迁（补键）。
**迁档为何保留 env**：保留覆盖口是为部署期临时覆盖（如容器/CI 一次性开启 docs 或调大输出上限），无需改配置文件即可生效。若追求 env 极简，可将迁档 4 个 env 一并删除、只留 config，此时运行时 env 由 12 降至 8（见 5.3）。

## 第6章 常量分层与收敛分析

### 6.1 结论先行

- **环境变量名**：纳入第3章的 `env_keys.py` 集中管理（本轮核心）。
- **其余常量**：项目**已有成熟的按域集中范式**，应沿用、补齐，而非推翻重来；不存在把所有常量塞进一个巨型文件的做法（那是垃圾桶，不是收敛）。
- 进程宿主域是**已收敛样板**（`app/proc/constants.py`），证明"相互制约的一组值放一处、约束写在值旁边"是有效做法，其他域照此办理。

### 6.2 现有常量文件盘点

| 文件 | 层/域 | 职责 | 规模 |
|---|---|---|---|
| `app/constants.py` | 系统层 | LLM 通信、Agent 循环、HTTP 协议、错误码（`ERR_*`）、HITL/重试参数 | 约 308 行 |
| `app/tools/tool_constants.py` | 工具层 | 工具运行参数、工具侧 HTTP 拷贝、超时表 | 约 75 KB |
| `app/proc/constants.py` | 进程域 | 进程宿主超时/接收预算/退避/熔断/流控（相互制约体系） | 约 53 行 |
| `app/services/agent/compaction_constants.py` | agent 子域 | 上下文压缩/裁剪参数 | 约 22 KB |
| `app/services/agent/media_constants.py` | agent 子域 | 媒体内联上限等 | 约 1.8 KB |

分层纪律已存在（`app/constants.py` 顶部明文规定"禁止引用 `tool_constants.py`，两层互不引用"），本次规范沿用该纪律，仅新增一个更底层的**部署契约层** `env_keys.py`。

### 6.3 收敛四原则

新增或搬迁常量时，按以下原则判定归属，避免"该集中的没集中、不该集中的乱集中"：

| 原则 | 判定 | 落点 |
|---|---|---|
| **跨模块共享 + 相互制约** | 多个文件引用、改一个牵动另一个（如 proc 超时预算链） | 对应域 `constants.py`，约束写在值旁 |
| **单域自用** | 只有本域几个文件用 | 本域 `constants.py`，不进全局 |
| **单文件一次性魔法值** | 只在一处出现且无跨模块语义 | 就地常量化即可，**不上升**（防全局文件膨胀） |
| **部署契约（环境变量名）** | 跨层共享、对外可见（部署者/前端标签依赖） | 独立 `app/env_keys.py`，零依赖最底层 |

一句话：**共享才集中，单用归域，一次性的别上升**。

### 6.4 为什么环境变量名必须集中（实证）

| 名字 | 重复出现点 | 漏改后果 |
|---|---|---|
| `AI_PROVIDER` | `config.py:155`、`settings_registry.py:268`、`model_service.py:379`、`config_helpers.py:394` | 只改读取点不改 registry → 页面仍标"来自环境变量"，实际已不生效 |
| `OMNIAGENT_ACCESS_TOKEN` | `deps.py:47`（常量）、`config.py:67`（注入表）、`settings_registry.py:480`（env_key） | 改一处漏一处 → 口令注入/来源标记与实际鉴权分叉 |
| `OMNIAGENT_ACCESS_TOKEN_ALLOWLIST` | `deps.py:79`、`config.py:68`、`settings_registry.py:484` | 同上，白名单静默失效 |

这类"同一名字多处字面量"就是必须集中的直接理由；集中后每个名字只存在一次。

### 6.5 收敛范围与优先级（四档）

| 治理档 | 范围 | 处置 | 落点 |
|---|---|---|---|
| **删**（4） | `AI_PROVIDER` / `LOG_LEVEL` / `CORS_ORIGINS` / `CHAT_RETENTION_DAYS` | 删 env 分支，只留 config/设置页 | `config.py` / `main.py` / `model_service.py` / `config_helpers.py` / `settings_registry.py` |

### 7.3 并档：进程宿主握手 4 → 1 串（另 2 项迁 config）

旧名 `OMNI_PROC_HOST_CONCURRENCY` / `OMNI_PROC_HOST_MAX_OUTPUT` 不再生效（进 `DEPRECATED` 告警）。
