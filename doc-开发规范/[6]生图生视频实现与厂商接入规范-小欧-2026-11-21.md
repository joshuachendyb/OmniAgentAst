## 一、定位与真源文件

### 1.1 这份文档解决什么

对话里的「生成图片」「生成视频」两个工具，从模型发起调用到厂商出片，中间要过四层，每层各管一件事。接一个新厂商时该改哪里、不该改哪里、改完怎么验，全部由这张分层决定。

本规范同时是**实现说明**与**接入规范**：描述现状（代码实际怎么跑）与约束（新厂商接入必须遵守什么）。

### 1.2 源码地图

| 层 | 文件 | 职责 | 越层禁令 |
|---|---|---|---|
| 工具层 | `app/tools/media/generate_image.py`<br>`app/tools/media/generate_video.py` | 收 LLM 入参、取回调、把回调结果翻译成 `{data, llm_data, other_data}` 三段、判定成败 | **零 HTTP**。工具层不 import httpx，不碰厂商协议，不知道 provider 是谁 |
| 工具注册 | `app/tools/media/media_register.py`<br>`app/tools/media/media_schema.py` | 工具描述、入参 Pydantic 模型、示例 | 描述必须与实现口径一致（产物由卡片呈现，回复不贴 URL） |
| 编排层 | `app/services/agent/media_generate.py` | 按模型名定位 provider 与凭据、图源归一（data URI / 公网化）、调引擎、b64 落盘为附件 | 不另开生成 HTTP 出口，只调引擎 |
| 引擎层 | `app/services/generation/generation_client.py` | 生成端点唯一 HTTP 出口：生图同步单请求、生视频提交+轮询；`settled` 三态归因；`out` 出参与 `meta` 收敛 | 不写任何 provider 分支（方言归 adapter） |
| 方言层 | `app/llm/adapters/base.py`<br>`app/llm/adapters/agnes.py`<br>`app/llm/adapters/sensenova.py` | 请求体方言翻译、响应解析、鉴权头 | 只做「与通用实现不同」的那部分，通用部分不覆写 |
| 辅助 | `app/services/generation/public_image.py` | 本地图 → 临时图床公网直链（i2v 参考图用） | 失败返回空串，不抛异常 |
| 字段解析 | `app/services/generation/vendor_spec.py` | 厂商响应字段 → 标准规格与落点的唯一真源 | 新增厂商只往别名表加键名，不动工具与文案 |
| 零散常量 | `app/tools/tool_constants.py` | 默认模型、模型话术、四个生成错误码、重试配置 | 工具内不写默认模型字面量 |

### 1.3 一句话链路

```
LLM 调 generate_image(prompt, model, ...)
  → 工具层取上下文里的生成回调（tool_executor 注入，闭包带 session_id）
  → 编排层按 model 名找 provider/api_base/api_key，图源归一
  → 引擎层 POST {api_base}/images/generations（adapter 翻译请求体）
  → 厂商返回 → adapter 解析 → 引擎把产物写 out，其余字段收敛进 out["meta"]
  → 编排层判是否要把 b64 落盘，回 9 字段结果
  → 工具层按 settled / 有无产物 判三态，填 data/llm_data/other_data
```

## 二、一次生成请求的完整链路

### 2.1 回调是怎么到工具层的

工具层拿不到 provider 配置，也不能自己发请求。它通过 `app/tools/context.py` 的 `ContextVar` 拿一个可调用对象：

```python
generate_callback = get_current_generate_callback()   # 可能为 None
```

注入方是 `app/services/agent/tool_executor.py`：每次执行工具前建闭包并 set，`finally` 里 reset。

```python
_sid = str((getattr(agent, "_start_meta", None) or {}).get("session_id") or "")

async def _invoke_generate(kind: str, model: str, prompt: str, **kwargs):
    return await invoke_generate(kind, model, prompt, session_id=_sid, **kwargs)

_generate_token = set_current_generate_callback(_invoke_generate)
try:
    ...执行工具...
finally:
    reset_current_generate_callback(_generate_token)
```

三个要点：

- **`session_id` 是这个闭包带进去的**，工具层不传。b64 产物落盘到哪个会话的附件目录，取决于它。
- **回调为 None 是合法状态**（比如未经 agent 执行、单测直调工具）。此时工具必须回 `ERR_GENERATE_NO_CHANNEL`，不能抛异常。
- **reset 在 finally**，上下文不泄漏到下一个工具。

### 2.2 工具层调用回调的形状

两个工具都按「位置参数 + 关键字参数」调：

```python
# 生图
result = await generate_callback("image", effective_model, prompt, image=image, **cb_kwargs)
# 生视频
result = await generate_callback("video", effective_model, prompt, **kwargs)
```

前三个位置参数固定是 `kind / model / prompt`。可选参数只在**非空**时才放进 kwargs（`if size:` / `if val is not None:`），未给的不下发，由编排层走默认——这样旧调用与探测腿零影响。

### 2.3 各层边界为什么这么切

- **工具层零 HTTP**：厂商协议差异全在 adapter，工具层若自己发请求，每接一家就要改工具。
- **编排层的存在意义**：它需要 `session_id` 和 `attachments` 能力（落盘），而 `services/generation` 是纯协议层不该依赖附件域；`tool_executor` 消费方在 agent 层，故回调实现随用方放 `services/agent`。
- **引擎层协议无关**：`generation_client` 里没有 `if provider == "agnes"` 这种分支，方言翻译下沉到 adapter 的钩子。

## 三、工具层契约

### 3.1 入参

**`generate_image(prompt, model=None, image=None, images=None, size=None, ratio=None, return_base64=False, response_format=None)`**

| 参数 | 语义 | 备注 |
|---|---|---|
| `prompt` | 图片内容描述 | 必填，schema `min_length=1` |
| `model` | 生成图像模型名 | 空则取 `MEDIA_DEFAULT_IMAGE_MODEL`（`agnes-image-2.1-flash`） |
| `image` | 单张参考图（i2i） | 四种来源：本地路径 / attachment_id（32 位 hex）/ 公网 URL / data URI |
| `images` | 多图合成参考图列表 | 与 `image` 同时给时合并；后端公网化 |
| `size` | 尺寸档位 1K/2K/3K/4K | 各家翻译不同（见 6.4） |
| `ratio` | 宽高比 | 8 种：1:1/3:4/4:3/16:9/9:16/2:3/3:2/21:9 |
| `return_base64` | 要求产物以 b64 返回 | 产物落盘为会话附件，不塞进回复 |
| `response_format` | `url` 或 `b64_json` | 一般无需显式设置 |

**`generate_video(prompt, model=None, mode="t2v", image=None, images=None, first_frame=None, last_frame=None, audios=None, videos=None, seconds=None, size=None, aspect_ratio=None, seed=None, timeout=660)`**

| 参数 | 语义 | 备注 |
|---|---|---|
| `mode` | `t2v`/`text`、`keyframe`、`i2v`/`reference` | 工具层支持别名，编排层映射成端点枚举（见 4.3） |
| `image` | 单图参考（兼容旧 i2v） | 插到 `images` 首位，去重 |
| `images` / `first_frame` / `last_frame` | 图片类素材 | 本地路径/attachment_id/data URI 由后端公网化 |
| `audios` / `videos` | 音频 URL 列表 / 视频对象列表 | **原样透传**，本地文件不公网化（见 10.1） |
| `seconds` / `size` / `aspect_ratio` / `seed` | 通用参数 | 不传走厂商默认 |
| `timeout` | 等待上限秒（120~1200，默认 660） | 映射到**轮询总时长**，不是单个 HTTP 请求超时 |

### 3.2 出参三段

工具统一返回 `build_success / build_warning / build_error` 构造的三段结构。

**`data`——本次执行的产物指针，只有两种形态**：

```jsonc
{"url": "https://.../output.png", "type": "image"}                       // 厂商给公网 URL
{"file_path": "E:\\...\\attachments\\x.png", "attachment_id": "...", "type": "image"}  // 只有 b64，已落盘
{}                                                                       // 失败
```

`data` 里**没有 b64、没有入参回显**。入参在 `llm_data.action.params`。

**`llm_data`——模型看到的东西**：

```jsonc
{
  "summary": "生成图像，成功：模型 agnes-image-2.1-flash，1024x1024，png 格式",
  "action": {
    "tool": "generate_image",
    "tool_zh": "生成图像",
    "params": { "prompt": "...", "model": "...", "size": "2K" },
    "artifacts": [{ "name": "x.png", "path": "...", "type": "image" }]
  },
  "status": { "exec_code": "success", "message": "成功", "code": "", "detail": "", "hint": "" },
  "duration_ms": 15288,
  "metrics": { "model": {"value": "...", "text": "..."} }
}
```

- `duration_ms` 是**工具墙钟**（含排队、轮询粒度）；厂商侧用时另在 summary 的「用时」里，两者互补。
- `status` 五字段齐全，`exec_code` 只取 `success`/`warning`/`error` 三种；`message` 由调用处写死，不在 builder 里按 code 查表（避免非法 exec_code 崩）。
- `metrics` 的值统一 `{value, text}` 形——前端工具行标签只认 `text`/`value`，裸标量会渲染成空。

**`other_data`——只装厂商返回的 token 用量数字**：

```jsonc
{"usage": {"input_tokens": 376, "output_tokens": 3969, "total_tokens": 4345, "images_count": 1}}   // 有 usage
{}                                                                                                  // 无 usage
```

键名原样保留，值只取数字（`int`/`float`，排除 `bool`）。厂商响应其余内容不落库，详见第七章。

### 3.3 三态与错误码

工具层的成败不是「引擎说 ok 就算成功」，而是按**有没有交付产物**判：

```python
if not result.get("ok"):
    if result.get("settled") is True:   → error   + ERR_GENERATE_REJECTED
    else:                                → warning + ERR_GENERATE_INCOMPLETE
if not url and not file_path:
    if result.get("b64"):                → error   + ERR_GENERATE_PERSIST_FAILED
    else:                                → error   + ERR_GENERATE_REJECTED
→ 否则 success
```

| 错误码 | 触发 | exec_code | 语义 |
|---|---|---|---|
| `ERR_GENERATE_NO_CHANNEL` | 生成回调未注入 | error | 通道没配好，检查设置页 |
| `ERR_GENERATE_REJECTED` | 厂商确定拒绝（模型不存在/参数非法/鉴权失败/no_output），或 ok 但什么都没给 | error | 换模型或查配置，重试无益 |
| `ERR_GENERATE_PERSIST_FAILED` | 厂商已生成 b64，但落盘为附件失败 | error | 本地产物丢了，重试或查磁盘权限 |
| `ERR_GENERATE_INCOMPLETE` | 未定：队列满、轮询超时、轮询非 200、网络错 | warning | 可稍后重试，**不可据此判模型无能** |

**铁律**：没交付产物就不是成功。warning 只留给「未定」，不留给「确定失败」。

### 3.4 summary 骨架

```
<动作>，<结果>：<主体><规格段>
```

| 模态 | 实例 |
|---|---|
| 图像成功 | `生成图像，成功：模型 agnes-image-2.1-flash，1024x1024，png 格式，用时 7 秒` |
| 视频成功 | `生成视频，成功：模型 agnes-video-2.5-flash，5 秒 720P（standard），用时 461 秒` |
| 失败 | `生成图像，失败：<厂商 reason 截断 120 字>` |
| 警告 | `生成视频，警告：<厂商 reason 截断 120 字>` |

成功 summary **不复述产物指针**：URL 或本地路径已经在 `data` 里，summary 再说一遍只是噪音。因此公网形态与本地落盘形态的成功 summary 完全一致。

规格段由 `vendor_spec` 拼，映射不到就整段缺席（不猜不编造），详见第七章。

### 3.5 artifacts 声明

产物清单挂 `llm_data.action.artifacts`（`with_artifacts`），供任务终态的「本会话产物」抽屉与前端卡片使用。

| 产物形态 | 条目 |
|---|---|
| 公网 URL | `artifact_from_url(url, kind)` → `{name}` 取 URL 路径末段的真实后缀（签名查询串不进名字），`path` 恒为原 URL 一字不改 |
| 本地附件 | `{"name": os.path.basename(file_path), "path": file_path, "type": kind}` |

每次调用只声明**一个**产物条目（一次生成一张图/一段视频）。

### 3.6 工具级不重试

`tool_constants.TOOL_RETRY_CONFIG` 里两个工具都是 `{"max_retries": 0}`——生成端点计费，重试等于重复扣费。失败信息直接回给 LLM 决策。

## 四、编排层 `invoke_generate`

### 4.1 provider 定位与凭据

```python
provider, api_base, api_key = _provider_credentials(model)
```

顺序：

1. `ai.model_ref.provider` 指向的当前 provider **优先**——同一个模型名可能被多个 provider 声明，不按字典序瞎取第一个；
2. 其余 provider 按配置顺序遍历；
3. 都不命中 → `(None, "", "")` → 回 `ok=False, settled=True`（**确定失败**：换模型或改配置才有出路，不能回「稍后重试」）。

凭据取值：`os.environ["{PROVIDER大写}_API_KEY"]` 优先，其次 `ai.<provider>.api_key`。鉴权头由 `get_provider_adapter(provider).static_headers(api_key)` 生成（空 key 不带 `Authorization`）。

### 4.2 图源归一（两层策略不同）

| 场景 | 处理 | 原因 |
|---|---|---|
| 生图 i2i 单图 | 本地路径/attachment_id/data URI → **data URI**；公网 URL 原样 | 实测 agnes / sensenova 的 i2i `image` 参数接受标准 data URI |
| 生图多图合成 | 每张都**公网化** | sensenova 多图只吃公网 URL |
| 生视频 `images`/`first_frame`/`last_frame` | 每张都**公网化** | 厂商侧要直连 GET，实测 data URI 被拒（`source_unreachable`） |
| `audios`/`videos` | 原样透传 | 已是公网 URL/对象 |

读取口 `_read_image_source` 支持三种源，返回 `(bytes, mime)`；读不出返回 `None`，调用方**降级为原样透传**（让厂商拒绝并记因），不中断流程。32 位 hex 走 `attachment_service.get_attachment` 取 `stored_path`。

公网化失败时 `upload_image` 返回空串，`_publicize_image_source` 退回原串——同样是「交给厂商判」。

### 4.3 `mode` 别名映射（唯一映射点）

```python
alias = {"t2v": VIDEO_MODE_T2V, "i2v": VIDEO_MODE_I2V}
endpoint_mode = alias.get(mode or "", mode or VIDEO_MODE_T2V)
```

| 工具侧 `mode` | 端点枚举 |
|---|---|
| `t2v` / `text` | `text` |
| `i2v` / `reference` | `reference` |
| `keyframe` | `keyframe`（直通） |

工具侧保留 `t2v`/`i2v` 是为了兼容既有语义；厂商文档的枚举是 `text`/`keyframe`/`reference`，翻译只在这一处。

### 4.4 b64 落盘

只在 **`ok=True` 且没有 url 且 b64 非空** 时触发（有 url 时 url 优先，b64 丢弃）。

`_save_b64_attachment(b64, session_id, kind, stem)`：

| 环节 | 处理 |
|---|---|
| 解码 | 补 padding（`b64 + "=" * (-len(b64) % 4)`）+ `validate=False`；解不出 → **直接 None，不重试**（确定性失败） |
| mime 判定 | `_sniff_media_mime` 按字节魔数：PNG / JPEG / GIF87a·GIF89a / WebM / WebP / MP4（`ftyp`）/ MOV（`ftyp`+`qt  `）；认不出按 kind 默认 `image/png` / `video/mp4` |
| 落盘 | `attachment_service.save_generated_bytes(session_id, stem, raw, mime)`，系统产出专用写盘口：不校验会话存在性、不计配额、不设单文件上限 |
| 重试 | 写盘/登记失败按 `0.1s × 尝试序号` 线性退避，共 3 次（杀软/索引器占锁属瞬时故障）；全败返回 None |
| 去重 | `save_generated_bytes` 内按 `(session_id, sha256)` 查重，同内容复用旧行并删本次副本 |
| 返回 | `{attachment_id, file_path, name}`，工具据此填 `data` 与 artifacts |

落盘全在 `asyncio.to_thread` 里执行，不阻塞事件循环。

### 4.5 出参固定 9 字段

```jsonc
{
  "ok": bool, "settled": bool,
  "url": "", "b64": "", "file_path": "", "attachment_id": "",
  "reason": "",            // 取证串（已截短），失败时进 llm_data.status.detail
  "meta": {},              // 厂商响应剔产物本体后累积合并
  "vendor_duration_ms": 0  // 厂商侧用时，缺失为 0
}
```

任何异常都收口成 `{"ok": False, "settled": False, "reason": "生成异常: ..."}`，从不抛给工具层——一轮对话不因生成失败而崩。

## 五、引擎层 `generation_client`

### 5.1 端点与常量

| 常量 | 值 | 用途 |
|---|---|---|
| `IMAGE_PATH` | `/images/generations` | 生图端点（t2i/i2i/多图同端点） |
| `VIDEO_PATH` | `/videos` | 生视频提交端点；轮询 `GET {base}/videos/{task_id}` |
| `REJECT_STATUS` | `{400, 415, 422}` | 只有这三个算「厂商确定不收」 |
| `VIDEO_POLL_INTERVAL` | `5.0s` | 轮询间隔 |
| `VIDEO_POLL_TIMEOUT` | `600s` | 轮询默认上限（工具 `timeout` 可覆盖） |
| `VIDEO_QUEUE_RETRIES` / `VIDEO_QUEUE_GAP` | `3` / `30s` | 队列满时提交重试 |
| `VIDEO_DONE` | `{completed, succeeded, success}` | 完成态 |
| `VIDEO_FAILED` | `{failed, error}` | 失败态 |

签名统一 `Tuple[bool, str, bool]` = `(产物成功?, evidence, settled?)`。

### 5.2 生图：同步单请求

```
body = {model, prompt} + adapter.prepare_image_body(...)
POST {api_base}/images/generations      # httpx.AsyncClient(timeout=120 默认)
  ├─ 网络异常     → (False, "network_error: ...", False)
  ├─ 非 200       → _put_meta(_resp_meta(resp))
  │                 ├─ 图源不可达短语命中 → (False, "source_unreachable: ...", False)
  │                 └─ 否则              → (False, "http_N: ...", N in REJECT_STATUS)
  ├─ JSON 解析失败 → _put_meta(_resp_meta(resp)); (False, "bad_json", False)
  └─ 200
      ├─ adapter.parse_image_result(data) 优先，否则 data[0].url / data[0].b64_json
      ├─ 有 url 或 b64 → out.update(url=, b64=); _put_meta(data); (True, ..., True)
      └─ 都没有        → _put_meta(data); (False, "no_output", True)
```

参考图合并：`images` 在前，`image` 若不在其中则插到首位，去重后交给 adapter；单张给字符串、多张给数组（基类行为），sensenova 强行要数组。

### 5.3 生视频：提交 + 轮询

```
body = {model, prompt, mode} + adapter.prepare_video_body(...)
for attempt in 1..3:
    POST {api_base}/videos
    if 响应体不含 "video_queue_full" or 是第 3 次: break
    sleep 30s
├─ 非 200 → _put_meta(_resp_meta)
│     ├─ source_unreachable → (False, ..., False)
│     ├─ video_queue_full  → (False, "queue_full: ...", False)
│     ├─ mode 无效/不能为空/"不能包含" → (False, "protocol_drift: ...", False)
│     └─ 否则 → (False, "http_N: ...", N in REJECT_STATUS)
├─ 取 task_id（task_id / id / video_id）失败 → _put_meta; (False, "no_task_id", False)
├─ _put_meta(提交响应)          # 提交即落档，轮询超时也能追到任务
└─ 轮询至 deadline（poll_timeout）
      ├─ GET 失败/非 200 → _put_meta(_resp_meta(poll)); (False, "poll_http_N", False)
      ├─ status ∈ DONE   → url = adapter.parse_video_url(preserve_case=True) 或启发式
      │                    ├─ 有 url → out["url"]=原始大小写; _put_meta(detail); (True, ..., True)
      │                    └─ 无 url → _put_meta(detail); (False, "no_output_field", False)
      ├─ status ∈ FAILED → _put_meta(detail); (False, "task_failed: ..." / "source_unreachable: ...", False)
      └─ 超时            → (False, "poll_timeout: <最后状态>", False)
```

**产物 URL 保留原始大小写**：签名参数大小写敏感，取证串（evidence）用 `lower()` 仅作人读，`out["url"]` 用原串供下载。

**状态/原因/URL 三段解析都先问 adapter**，adapter 返回 `None` 才落引擎启发式：

- 状态：`status`/`state`/`task_status`，再递归 `data.*`，取不到记 `unknown`；
- 失败原因：`error`/`message`/`fail_reason`/`failure_reason`/`reason`/`error_message`，值为对象时取 `message`/`msg`/`code`；
- 产物地址：先找键名含 `video` 的 http 串，再退任意 `.mp4` 直链（任务响应常同时带封面图/尾帧图，只按 `url` 取值会拿错）。

### 5.4 `settled` 三态判定总表

`settled=True` 表示「结论确定」，工具据此判 error；`settled=False` 表示「未定」，工具判 warning。

| 情形 | ok | settled | 工具侧 |
|---|---|---|---|
| 200 且有产物 | True | True | success |
| 200 但无产物（`no_output`） | False | True | error + REJECTED |
| 400 / 415 / 422 | False | True | error + REJECTED |
| 401 / 403 / 429 / 5xx | False | False | warning |
| 网络异常 | False | False | warning |
| JSON 解析失败（`bad_json`） | False | False | warning |
| 图源不可达（`source_unreachable`） | False | False | warning |
| 队列已满（`queue_full`） | False | False | warning |
| 无 `task_id` | False | False | warning |
| 轮询非 200 | False | False | warning |
| 轮询超时 | False | False | warning |
| 任务 `failed` / `error` | False | False | warning |
| 终态无产物地址（`no_output_field`） | False | False | warning |
| `mode` 协议漂移（`protocol_drift`） | False | False | warning |
| provider 未配置 / 未知 kind | False | True | error |
| 编排层未捕获异常 | False | False | warning |

判据背后的一条原则：**只有「厂商明确说着不要」才算确定拒绝**。鉴权、限流、排队、超时、厂商侧资源失败，都不构成「模型没有生成能力」的证据——这条同时决定了设置页探测结论的可信度。

### 5.5 `out` 出参与 meta 收敛

`out` 是可选字典，探测腿不传则三元组行为完全不变。

| 函数 | 作用 |
|---|---|
| `_prune_meta(node)` | 递归剔产物本体与空壳。剔除条件：①键名为 `b64_json`/`url`/`image_url`/`video_url`/`image`/`mask` **且值为字符串**；②键名含 `b64` 或 `base64` 且值为字符串；③任意超过 **8192 字符**的字符串。空 dict/list 整体丢弃（返回 `_META_EMPTY` 哨兵）。结构化 `image`/`mask` 元数据（值为 dict）照常保留，其内部 url 再被剔 |
| `_put_meta(out, data)` | 把已收敛的 dict **累积合并**进 `out["meta"]`，后者覆盖同名键。`out=None` 直接返回 |
| `_resp_meta(resp)` | 非 200 响应 → meta：能解析成 JSON 对象就原样用（失败态的 `code`/`message`/`request_id` 是一手排查信息），解析不出退 `{status_code, body[:2000]}` |

累积合并的意义：视频提交阶段拿到的 `task_id`/`created_at`，不会因为后续轮询响应缺这两项而被抹掉。

**b64 与产物 URL 只走 `out`**，不进 `meta`：`meta` 是给「规格与排查信息」的通道，产物本体已经在 `out["url"]`/`out["b64"]` 里，再存一份等于把 MB 级串翻倍。

### 5.6 超时语义

| 参数 | 含义 | 默认 |
|---|---|---|
| 生图 `timeout` | httpx 单请求超时 | 120s（工具不传） |
| 生视频 `timeout` | httpx 单请求超时 | 120s（固定） |
| 生视频 `poll_timeout` | 轮询总时长 | 600s（工具 `timeout=660` 覆盖） |

工具 schema 宣称的 `timeout` 是「等待上限」，因此映射到 `poll_timeout` 而不是单请求超时——否则排队 4 分钟的任务在第一个请求上就超时了。

## 六、厂商方言层 `adapter`

### 6.1 何时必须建 adapter

判定只有一条：**该方法/字段与基类通用实现不同**。

- 协议完全通用（OpenAI Images/Videos 兼容，字段同名）→ **不建 adapter**，基类即实现；
- 请求体字段不同 / 响应结构不同 / 鉴权头不同 → 建 adapter，**只覆写有差异的钩子**。

反例：只是调通用参数（`seconds`/`size`/`seed`）的厂商，无需建 adapter。

### 6.2 八个钩子

**请求方言（4 个）**

| 钩子 | 默认行为 | 何时覆写 |
|---|---|---|
| `static_headers(api_key)` | `{"Authorization": "Bearer ..."}`，空 key 返回 `{}` | 鉴权方式非 Bearer |
| `prepare_image_body(body, *, size, ratio, image_refs, return_base64, response_format)` | `size` 原样、`image` 单串/多数组、`response_format` 顶层 | size 协议不同 / 有厂商特有字段 |
| `prepare_video_body(body, *, first_frame, last_frame, images, audios, videos, seconds, size, aspect_ratio, seed)` | 字段同名直传，`None` 不写 | 字段名或结构不同 |
| `per_request_headers()` / `ensure_gate_body(body)` / `endpoint_for(model)` | 空 / 原样 / `/chat/completions` | 与生成链路无关（chat 专用） |

**响应方言（4 个）**

| 钩子 | 返回 `None` 的含义 |
|---|---|
| `parse_image_result(data)` | 用引擎通用 `data[0].url` / `data[0].b64_json` |
| `parse_video_status(data)` | 用引擎启发式（`status`/`state`/`task_status` 递归） |
| `parse_video_reason(data)` | 用引擎启发式（`error`/`message`/`fail_reason`…） |
| `parse_video_url(data, preserve_case=False)` | 用引擎启发式（键名含 `video` → `.mp4` 递归） |

**返回 `None` 即回退**，所以新厂商只写自己那一个钩子，其余继承。

### 6.3 注册

```python
# app/llm/adapters/__init__.py
_ADAPTERS: Dict[str, ProviderAdapter] = {
    "ZenFree": OpencodeZenAdapter(),
    "agnes": AgnesAdapter(),
    "sensenova": SensenovaAdapter(),
}
```

键名大小写敏感，**必须与 `config.yaml` 的 provider 键名一致**。未注册的 provider 落入 `_DEFAULT_ADAPTER`（通用基类），并按名只记一次 INFO——未适配厂商是常态，不是错误。

### 6.4 现有两家方言对照

| 差异点 | 通用/基类 | agnes | sensenova |
|---|---|---|---|
| 生图 `size` | 原样透传 | 档位 `1K`~`4K` + `ratio` | 档位×比例 → `WIDTHxHEIGHT`（32 的倍数，钳制到 4096） |
| 生图 `ratio` | 无此字段 | 顶层 `ratio` | 不下发（比例已隐含在尺寸里） |
| 生图 `image` | 单串/多数组 | 单串/多数组 | **只认数组**（字符串会 `RemoteProtocolError`） |
| `return_base64` | 不下发 | 顶层 `return_base64: true` | 忽略（非其字段） |
| `response_format` | 顶层 | 放 `extra_body` | 放 `extra_body` |
| 视频方言 | 字段同名直传 | 同通用 | 同通用 |

sensenova 的档位→像素表是 4 档 × 8 比例，越界钳制到 4096 并按 32 取整——这些数字是厂商硬性要求，改动前先对文档。

### 6.5 一处必须知道的硬限制

**端点路径是模块常量，adapter 没有端点钩子**。`IMAGE_PATH = "/images/generations"`、`VIDEO_PATH = "/videos"` 写死在引擎里。若新厂商端点路径不同（如 `/v1/images/generate`、`/videos/create`），仅加 adapter 解决不了，必须改引擎常量或新增端点钩子。

这是刻意的取舍：接入时先确认端点是否兼容，不兼容就要么改引擎（一次性），要么不接（避免为一家厂商引入端点注册表这种过度设计）。

## 七、厂商响应字段解析与落点

`vendor_spec.py` 是唯一真源。工具层不解析厂商字段，只调一个函数：

```python
metrics, spec, other, model_echo = build_vendor_fields(kind, result, effective_model)
```

### 7.1 标准规格别名表

按候选顺序取**首个非空标量**：空串、`0`、`0.0`、`bool` 都算未命中。

| 模态 | 标准键 | 厂商候选键名 |
|---|---|---|
| image | `size` | `size` / `resolution` / `image_size` |
| image | `format` | `output_format` / `format` / `image_format` / `mime_type`（命中后取 `/` 后面的子类型） |
| video | `seconds` | `seconds` / `duration` / `video_seconds` |
| video | `size` | `size` / `resolution` / `video_size` |
| video | `quality` | `quality` / `quality_level` |

取值视图：**顶层优先，`data[0]` 兜底**（部分厂商把参数放在产物项里）。

### 7.2 用时计算

```python
start ∈ {created_at, created, created_time, started_at}
end   ∈ {completed_at, completed, finished_at, done_at}
用时(ms) = end - start
```

- 缺任一端 → 0（不显示），**不用墙钟顶替**；
- `end < start` → 0（倒挂视为脏数据）；
- 起点 ≥ 10^11（13 位毫秒时间戳）→ 差值即毫秒，不再乘 1000；否则按秒差 × 1000。

拼句形态：`，用时 N 秒`（`duration_ms // 1000`）。

### 7.3 落点分工

| 落点 | 装什么 | 是否进模型观察 |
|---|---|---|
| `llm_data.summary` | 结论 + 规格段 | 是 |
| `llm_data.metrics` | `model`（厂商回显优先）+ 标准规格 + `total_tokens`/`output_tokens` + `revised_prompt`/`error_code`/`request_id`，**失败态另加 `task_id`** | 是，渲染为「统计:」行 |
| `other_data.usage` | **只装厂商返回的 token 用量数字**，原样键名；无 usage 则 `{}` | 否，只落库 |

有价值标量的别名：

| metrics 键 | 厂商候选键名 | 为什么留 |
|---|---|---|
| `revised_prompt` | `revised_prompt` | 厂商改写的提示词，说明实际生成了什么 |
| `error_code` | `code` / `error_code` | 失败态一手信息 |
| `request_id` | `request_id` / `trace_id` | 厂商侧追单凭据 |
| `task_id`（仅失败态） | `task_id` / `video_id` / `id` | 成功时产物已在手，只有失败才需要追单 |

### 7.4 不落库的字段

`created` / `completed_at` / `progress` / `status` / `input_*` / 厂商响应原文**用完即弃**。这些是过程量：产物已交到用户手里，留着只增长库。排查要的一手信息（错误码、request id、失败态任务号）已在 metrics。

### 7.5 新厂商只加别名

新厂商字段名不同，**只往对应别名元组里加名字**，工具、文案、前端零改动：

```python
_SPEC_ALIASES["video"]["seconds"] = ("seconds", "duration", "video_seconds", "clip_length")
```

反过来，若想给新厂商加一个新的「标准规格」，就要同步改 `build_vendor_spec` 的拼句逻辑与前端标签——这是有成本的动作，先问是否真的需要。

## 八、设置页生成验证腿

### 8.1 闸门

只在该模型 `model_meta.<model>.output_modalities` 声明了 `image` 或 `video` 时执行（与设置页按钮的显示条件同口径）。未声明则 400：该模型没有生成验证腿。

### 8.2 四枪与跳过规则

| 腿 | 生图 | 生视频 |
|---|---|---|
| 第一枪（文生） | `PROBE_PROMPT` = "一个红色圆点，白色背景" | `PROBE_VIDEO_PROMPT` = "一个红色圆点在白色背景上缓慢移动" |
| 第二枪（图生） | `PROBE_I2I_PROMPT` = "把图片主色调改为蓝色"，图源 `PROBE_IMAGE_URL` | `PROBE_VIDEO_I2V_PROMPT` = "让画面缓慢推近"，`mode=reference` |

- **第一枪未取证或未成功，第二枪记 `skipped`**，不打第二枪（避免为一次失败付两次费）。
- 每条腿落 `{state, ms, evidence, at}`，`state ∈ ok / none / unverified / skipped`（对应 ok=True / settled=True 失败 / settled=False / 跳过）。
- 图/视频两组**分组落库**到 `media.generate.{image,video}`：一组未取证不连坐另一组（视频排队超时不影响图腿的结论）。

### 8.3 与业务腿的关系

探测腿与业务腿**共用同一个引擎函数**，区别有三点：

1. 探测腿不传 `out`——不取产物、不落 meta；
2. 请求体与响应解析用**基类** adapter（`adapter` 不传时 `ProviderAdapter()`），即探测走「通用协议兼容性」；
3. 鉴权头仍用该 provider 的 adapter（`get_provider_adapter(name).static_headers(api_key)`），所以鉴权差异探测腿能覆盖到，方言差异覆盖不到。

因此**探测通过不等于业务一定通**：请求方言或响应解析写错时，探测可能过、业务挂。接入新厂商后必须再跑一次真机对话生成。

## 九、新厂商接入 SOP

### 9.1 先分档

| 档 | 判据 | 动作 |
|---|---|---|
| **A** | 端点路径兼容，且请求/响应字段与通用一致 | 只改配置，不改代码 |
| **B** | 端点路径兼容，但请求体或响应结构有差异 | 加一个 adapter 文件 + 注册一行 |
| **C** | 生图也走异步任务（提交+轮询），或端点路径不兼容 | 需扩引擎，非本规范覆盖范围 |

C 档的现状：引擎的 `generate_image` 是同步单请求，**没有** submit/poll 分支。接入这类厂商（如通义万相）必须先在引擎里加通用任务分支（可复用视频的轮询骨架），不要在 adapter 里伪造同步——那会把轮询塞进方言层，破坏分层。

### 9.2 A 档：只改配置

```yaml
ai:
  <provider>:
    api_base: https://api.example.com/v1
    api_key: <key>                 # 生产建议走环境变量 <PROVIDER大写>_API_KEY
    models:
      - <image-model>
      - <video-model>
    timeout: 120
    model_meta:
      <image-model>:
        input_modalities: [text]
        output_modalities: [image]
      <video-model>:
        input_modalities: [text]
        output_modalities: [video]
```

`output_modalities` 是设置页生成验证腿的闸门，漏写就没有验证入口。

### 9.3 B 档：加 adapter

1. 新建 `app/llm/adapters/<provider>.py`：

```python
class ExampleAdapter(ProviderAdapter):
    @staticmethod
    def prepare_image_body(body, *, size=None, ratio=None, image_refs=None,
                           return_base64=False, response_format=None):
        # 只写与基类不同的部分；未覆盖的字段不会自动出现，需要自己补
        ...
        return body

    @staticmethod
    def parse_image_result(data):
        # 结构不同才覆写；返回 (url, b64_json)
        return None
```

2. 在 `adapters/__init__.py` 的 `_ADAPTERS` 加一行，**键名与 config 的 provider 键一致**。
3. `generation_client` 与工具层**零改动**（这是本分层存在的理由）。

### 9.4 接入检查清单

| # | 检查项 | 判据 |
|---|---|---|
| 1 | provider 在 `config.yaml` 的 `ai` 下，`api_base` 正确 | 能拼出 `{api_base}/images/generations` |
| 2 | 模型名在 `models` 列表里 | 否则编排层报「未找到 provider/api_base」 |
| 3 | `model_meta.<model>.output_modalities` 声明正确 | 否则设置页无验证入口 |
| 4 | 端点路径兼容 | 不兼容属 C 档（见 6.5） |
| 5 | 鉴权头对得上 | 非 Bearer 要覆写 `static_headers` |
| 6 | 请求方言钩子覆写完整 | 该有的字段真的发出去了 |
| 7 | 响应解析钩子正确 | url / b64 取到；视频状态、失败原因、产物 URL 取到 |
| 8 | 产物形态确认 | 回 URL 还是只回 b64？只回 b64 会走附件落盘链路 |
| 9 | 规格字段是否命中 | 不命中就是 summary 无规格段（可接受，不许编造） |
| 10 | 错误码归因是否合理 | 该厂商的「参数非法」是否真是 400/415/422；若是别的码，要评估是否该进 `REJECT_STATUS` |
| 11 | 设置页生成验证四枪 | 图腿 t2i/i2i、视频腿 t2v/i2v 都过 |
| 12 | 真机跑一次对话生成 | 确认 data / summary / metrics / other_data 符合本规范 |

## 十、已知边界与坑

### 10.1 能力边界（诚实说明）

| 边界 | 现状 | 影响 |
|---|---|---|
| 生图异步任务 | 不支持 | C 档厂商接不了，需扩引擎 |
| 端点路径可配 | 不支持（模块常量） | 路径不同的厂商接不了 |
| `audios` / `videos` 本地文件公网化 | 不处理，原样透传 | 只有公网 URL 可用 |
| 每次调用产物数量 | 1 个 | 多图返回只取 `data[0]` |
| 视频「任务 failed」归因 | 记未定（warning） | 厂商侧资源/素材问题不判模型无能；这类失败重试可能仍失败，LLM 需自行判断 |
| 厂商文档行为与实测不符 | 以实测为准，注释记下 | 例如某模型标称支持视频参考、实测拒绝 |

### 10.2 常见坑

| # | 坑 | 处置 |
|---|---|---|
| 1 | 把 401/429/5xx 当「模型不支持」 | 只有 400/415/422 算确定拒绝 |
| 2 | 队列满直接报失败 | 提交重试 3 次、间隔 30s，仍满才记未定 |
| 3 | 视频 URL 被 `lower()` 后回放 | 签名参数大小写敏感，下载用原串，取证才用 lower |
| 4 | b64 缺 padding 或带换行 | 补 `=` + `validate=False` |
| 5 | 按 kind 硬编码产物后缀 | 按字节魔数嗅探，jpeg/webp 才不会被存成 .png |
| 6 | 同名模型跨 provider 取错 | `ai.model_ref.provider` 优先，再遍历 |
| 7 | i2v 传 data URI | 厂商拒（`source_unreachable`），必须公网化 |
| 8 | b64 塞进 data / llm_data / other_data | 只走内存交接，落盘后 data 只放 `file_path` + `attachment_id` |
| 9 | 图床不可达时中断流程 | 降级为原样透传，让厂商拒绝并记因 |
| 10 | 工具层重复提交 | `max_retries=0`，生成端点计费 |
| 11 | 用墙钟当厂商用时 | 厂商时间戳两端齐才算，缺一端不显示 |
| 12 | metrics 塞裸标量 | 统一 `{value, text}`，否则前端标签空白 |

### 11.3 前端呈现

产物由 `frontend/src/features/chat/components/pipeline/GenerationResultCard.tsx` 渲染，数据只取后端 `data`：

| data 形态 | 呈现 |
|---|---|
| `{url, type}` 且是视频 | `<video controls>` 播放器 + 「查看 / 下载」外链 |
| `{url, type}` 且是图片 | `<img loading="lazy">` 缩略图 |
| `{file_path, type}` | `PathLink` 深链（本地路径不能用 markdown `![]`，会 401） |

文字信息（工具名、浮层参数、状态、耗时、结果摘要）由 `ToolCallLine` 统一呈现，本卡片只做「产物呈现」这一差异点。因此工具描述里明确要求 LLM：成功后在回复里只说一句已生成，**不要粘贴 URL、不要写 markdown 图片或链接**。
