## 一、功能定位

### 1.1 什么是会话产物

会话产物是 **AI 在本会话中产出（写/生成/下载）的文件、目录、公网资源**的清单。它回答一个问题："这次对话里，AI 到底给我造出了哪些东西？"

它不是附件台账（上传/存为附件的文件在 `attachments` 表），也不是文件足迹（Agent 读/写/改过的所有文件，含只读文件）——产物只算**产出型工具**的交付物。三者数据源各自独立。

### 1.2 前端展示位置

产物最终出现在两处界面（详见第六章）：

| 位置 | 说明 | 数据源 |
|---|---|---|
| 输入框旁「文件/附件」抽屉的「本会话产物」分区 | 列出本会话全部任务产出的文件 | `GET /sessions/{id}/artifacts` |
| 右侧任务结束统计块（StaticStatsBlock）的产出物列表 | 单个任务结束后的产出物 | DB `detail.artifacts` 优先，SSE `finalStats.artifacts` 兜底 |

### 1.3 文件抽屉与「本会话产物」栏

用户点输入框旁的「附件」按钮弹出的面板，就是前端的 `FileDrawer`（文件抽屉）——它是全系统唯一的「附件」入口面板。产物不在独立界面，而是这个抽屉左栏的一个来源标签「本会话产物」。左栏各标签的来源与数据源对照如下：

| 左栏标签 | 内容 | 数据源 |
|---|---|---|
| 本会话附件 | 本次对话上传、导入或存为附件的文件 | `attachments` 表 |
| **本会话产物** | 本次对话中 AI 任务产出的文件（本文档主题） | `chat_tasks.artifacts` |
| 他会话附件 | 近 30 天在其它对话发送过的附件 | `attachments` 表 |
| 项目文件 | 项目目录树中的文件 | 文件树 API |
| 后端电脑 | 后端所在机器的文件（导入） | 本地文件 API |
| 收藏 / 合集 | 星标附件及附件合集 | `attachments` 表 |

「本会话产物」栏与「本会话附件」栏虽在同一抽屉，数据源完全不同：前者读 `chat_tasks.artifacts`（任务产出物），后者读 `attachments`（附件台账副本）。产物走引用模式从不落 `attachments` 表，所以两栏不会重复；产物若被"存为附件"，副本会归到「本会话附件」栏，原产物行仍留在「本会话产物」栏并经 `source_path` 过滤后不重复列出。

**口径差异（易混淆，务必区分）**：同是"产物"，两处展示的范围不同——

| 展示处 | 范围 | 说明 |
|---|---|---|
| 抽屉「本会话产物」栏 | **本会话全部任务**汇总 | 后端 `list_session_task_artifacts` 查该 `session_id` 下所有任务的 `chat_tasks.artifacts`，跨任务倒序、同一资源多任务只列一次（保留最新任务） |
| 右侧终态统计块 | **单个任务**快照 | 取该任务结束时的 `detail.artifacts`（`chat_tasks.artifacts` 的单任务行，SSE `finalStats.artifacts` 兜底） |

产物若被多任务反复产出，抽屉里只列一条（最新任务），而各任务自己的统计块仍各自显示——这是"汇总视图"与"单任务快照"的区别，不是数据不一致。

### 1.4 唯一真源

`chat_tasks.artifacts` 是「AI 产出的」唯一真源。工作区内产物走引用模式，从不落 `attachments` 表——用附件台账判据取产物清单恒为空，故有独立读口。

## 二、数据契约（五字段）

任何来源、任何环节的条目，都只用这一份字段定义。唯一实现：`backend/app/utils/artifacts.py`。

### 2.1 字段定义

| 字段 | 类型 | 由谁产生 | 取值域 | 说明 |
|---|---|---|---|---|
| `tool_name` | str | 收集器注入 | 工具名 | 生产者不填；收集器拷贝条目时写入，保证可追溯到产出它的工具 |
| `name` | str | 规范化 | 非空 | 展示名。本地取 `basename`；目录取目录名；URL 取末段文件名（URL 解码、去 query/fragment） |
| `path` | str | 生产者 | 本地绝对路径 或 `http(s)://` URL | 唯一地址字段，不再有第二种解释 |
| `form` | str | 规范化 | `file` / `dir` / `url` | 唯一形态字段。下游所有"怎么打开、怎么判存在"都只看它 |
| `type` | str | 规范化 | 小写无点扩展名 / `dir` / 媒体类别 / `file` / `url` | 唯一类型字段，仅用于展示分类 |

### 2.2 判定规则（每类只有一个实现）

| 判定 | 规则 | 唯一实现函数 |
|---|---|---|
| `form` | 条目已带合法 `form` → 信任，不重新探测磁盘；缺失 → URL 前缀判 `url`；`isdir` 判 `dir`；其余 `file` | `normalize_artifact` |
| `type` | 有扩展名 → 扩展名（小写无点）；目录 → `dir`；URL 认不出后缀 → 声明方给的媒体类别（`image`/`video`/…）；类别也缺 → `url`；本地无扩展名 → `file` | `normalize_artifact` |
| 去重键 | `url`：`scheme://host/path`（去 query 与 fragment，签名参数不影响"是否同一资源"）；`file`/`dir`：`normcase(abspath(path))` | `artifact_dedup_key` |
| 存在性 | `url` 恒 `True`（远程资源不做网络探测，避免读一次抽屉打一串外网请求）；`dir` 用 `isdir`；`file` 用 `isfile` | `artifact_exists` |
| 可引用 | 只有 `form == "file"` 且位于项目根内才给 `rel_path`；`dir` 与 `url` 的 `rel_path` 恒 `None` | `list_session_task_artifacts` |

### 2.3 两条关键取舍

1. **信任已有 `form`，不按磁盘现状重判**。产物声明时形态是确定的；若读口按磁盘重判，文件被删会把 `dir` 误降成 `file`。信任存量字段才能保证历史数据稳定、`normalize` 幂等（`normalize(normalize(x)) == normalize(x)`）。
2. **`type` 的兜底是单条规则，不是多套含义**。旧实现的问题是三个生产者各自发明含义；现在由同一函数按同一规则产出，调用方不参与决策。

### 2.4 三级记录的分工

三级记录不是重复存储，是三个不同粒度：

| 层级 | 位置 | 粒度 | 生命周期 | 消费方 |
|---|---|---|---|---|
| 单次调用证据 | `result["other_data"]["artifacts"]` | 一次工具调用声明了什么 | 随执行存在，不单独持久化 | `agent_telemetry` 收集器 |
| 任务终态 | `FinalStatsStep.artifacts` / `chat_tasks.artifacts` | 整个任务合并去重后的清单 | 持久化，单一真源 | 任务详情、终态统计块 |
| 会话视图 | `list_session_task_artifacts` 返回值 | 跨任务去重倒序 | 每次请求实时计算 | 前端「本会话产物」抽屉 |

单次调用层与终态层不是重复：同一文件被 `write` 和 `edit` 各声明一次，是两次真实产出（原始证据）；任务级去重后只列一次（终态结果）。粒度不同、用途不同。

## 三、唯一契约模块

`backend/app/utils/artifacts.py`，全局层，纯标准库依赖（`os`/`logging`/`urllib.parse`），不 import 任何业务模块，避免反向依赖。`MAX_ARTIFACTS = 50` 上限常量只在此定义。

### 3.1 九个函数

| 函数 | 职责 | 调用方 |
|---|---|---|
| `normalize_artifact(raw)` | 任意条目 → 五字段标准条目；不可成立返回 `None` | 全部 |
| `artifact_from_file(path, name="")` | 本地文件/目录 → 标准条目（`form` 按磁盘实况） | 16 个本地产出工具 |
| `artifact_from_url(url, kind="")` | 公网 URL → 标准条目（`name` 取末段文件名，`type` 取后缀，认不出用 `kind`） | 2 个媒体工具 |
| `artifact_dedup_key(item)` | 去重键（形态 + 去签名资源地址） | 收集器、读口 |
| `artifact_exists(item)` | 形态化存在性判定 | 读口 |
| `merge_artifacts(existing, new_items)` | 规范化 + 合并去重（后到覆盖先到）+ 保留最新 50 条，超限告警 | 收集器、声明入口、读口 |
| `declare_artifacts(other_data, items)` | 声明入口（基座），追加语义，不改入参 | 2 个媒体工具 |
| `declare_artifact_file(other_data, path)` | 声明入口（便捷），由本地路径声明单个产物 | 16 个本地产出工具 |
| `read_declared_artifacts(result)` | 读取口：从工具返回体取已声明产物并规范化 | 收集器 |

### 3.2 声明入口的调用形态

本地文件产物（最常用）：

```python
other: Dict[str, Any] = {}
llm_data = _build_xxx_llm_data(...)
other = declare_artifact_file(other, str(path))
return build_success(data=data, llm_data=llm_data, other_data=other)
```

公网 URL 产物（生图/生视频）：

```python
other = declare_artifacts(other, [artifact_from_url(url, "image")])
return build_success(data=result_data, llm_data=llm_data, other_data=other)
```

落盘媒体产物：不再手搓 `{"name":..., "path":..., "type":...}` 条目，一律走 `declare_artifact_file`，`type` 自动取扩展名、`form` 自动判 `file`。

## 四、后端实现链路

### 4.1 产出工具声明

产出型工具在返回成功/警告时，把产物挂到 `other_data["artifacts"]`。统一模式：**函数入口建 `other` 局部 dict → 声明函数返回值接收 → `build_*` 传 `other_data`**，业务逻辑零改动。落盘产物只在确实落盘后才声明（`save_to` 未指定时不塞空清单）。

| 工具文件 | 声明入口 | 工具文件 | 声明入口 |
|---|---|---|---|
| `dataanalysis/generate_chart.py` | `declare_artifact_file` | `file/extract_archive.py` | `declare_artifact_file`（目录自动 `form="dir"`） |
| `desktop/screen_capture.py` | `declare_artifact_file` | `file/move_file.py` | `declare_artifact_file` |
| `document/write_docx.py` | `declare_artifact_file` | `file/rename_file.py` | `declare_artifact_file` |
| `document/write_pdf.py` | `declare_artifact_file` | `file/write_text_file.py` | `declare_artifact_file` |
| `document/write_pptx.py` | `declare_artifact_file` | `media/generate_image.py` | URL → `declare_artifacts`+`artifact_from_url`；本地 → `declare_artifact_file` |
| `document/write_xlsx.py` | `declare_artifact_file` | `media/generate_video.py` | 同上 |
| `file/compress_files.py` | `declare_artifact_file` | `network/download_file.py` | `declare_artifact_file` |
| `file/copy_file.py` | `declare_artifact_file` | `network/fetch_webpage.py` | `declare_artifact_file`（warning 分支同样声明） |
| `file/edit_text_file.py` | `declare_artifact_file` | | |

### 4.2 遥测收集（`agent_telemetry.py`）

`TaskTelemetry.collect_and_report` 遍历批次结果：

- 来源：`read_declared_artifacts(result)`，只读 `other_data["artifacts"]`；
- 条件：仅 `exec_code ∈ {success, warning}` 收集，失败态即便误声明也不进清单；
- 注入 `tool_name`：拷贝条目后写入（`dict(a, tool_name=...)`），绝不原地改写工具返回体；
- 合并：`on_tool_call` 内走 `merge_artifacts` 统一去重与上限。

`build_final_stats_step` 只消费 `self._artifacts`，不再持有收集细节。

### 4.3 落库

`agent_runner` 任务终态取 `telemetry._artifacts`，经 `db_ops.update_task(..., artifacts=...)` 写入 `chat_tasks.artifacts`。条目已是五字段结构，落库结构即终态结构。

### 4.4 读口（`storage.list_session_task_artifacts`）

读 `chat_tasks.artifacts` 真源，任务时间倒序、跨任务去重：

| 处理 | 实现 |
|---|---|
| 条目规范化 | `normalize_artifact(it)`，`None` 跳过（兼容历史四字段数据） |
| 去重 | `artifact_dedup_key`（同一资源多任务反复产出只列一次，保留最新任务） |
| `rel_path` | 仅 `form == "file"` 调 `browse.root_relative`；`dir`/`url` 恒 `None` |
| `exists` | `artifact_exists(item)` |
| 返回字段 | `task_id/task_created_at/name/path/form/rel_path/type/tool_name/exists` |

历史数据缺 `form` 时按地址推断（URL → `url`；`isdir` → `dir`；其余 `file`），落库结构与新条目一致，无需数据迁移。

### 4.5 API

`GET /sessions/{session_id}/artifacts`（`backend/app/api/v1/sessions.py`）：返回 `{session_id, total, artifacts}`。

## 五、前端实现

### 5.1 类型定义

后端五字段契约在前端四处对齐：`session.api.ts` 的 `SessionArtifactItem`（`form` 必填）、`sse.ts` 的 `FinalStatsFrame.artifacts`、`execution.ts` 的 `ExecutionStep.artifacts`、`task.api.ts` 的 `TaskArtifact`（后三处 `form` 可选，缺省视为 `file` 以兼容老数据）。

### 5.2 形态分派（FileDrawer「本会话产物」）

前端不做任何形态推断：`form` 由后端给，前端只按它分派（前端薄、后端厚）。

| form | 行显示 | 点击行为 | 失效判定 |
|---|---|---|---|
| `url` | meta「远程产物」，类型标签显示 `type` | `window.open(path, '_blank', 'noopener,noreferrer')` | 不判失效（远程资源不探测） |
| `dir` | meta「目录产物」 | 有 Router 走 SPA 跳 `buildExternalDeepLink(path)`，无 Router 整页跳 | `!exists` 时提示"目录已不存在" |
| `file` | meta「可引用」/「在项目根外」 | 根内有 `rel_path` 加入本轮引用；根外"存为附件"复制固化 | `!exists` 时提示"文件已不存在" |

目录跳转复用 `utils/projectPath.ts` 导出的 `buildExternalDeepLink`（深链 `/files?ext=1&path=<abs>`）。

### 5.3 终态统计块（StaticStatsBlock）

产出物列表：数据源 `detail.artifacts` 优先、`finalStats.artifacts` 兜底；非本地文件补形态标签（`远程 ·` / `目录 ·`），`type` 直接显示，与抽屉口径一致；路径走 `PathLink` 深链，行级"存为附件"不锁整块。

### 5.4 回归红线（前端）

- 根内文件产物可加入本轮，根外产物可存为附件；
- 已存为附件的产物在「本会话产物」中不重复列出（`source_path` 过滤）；
- 同一文件被多任务反复产出只列一次，保留最新任务；
- 终态统计块与抽屉条数口径一致。

## 六、新增一个产出工具的步骤

1. 在工具函数入口加 `other: Dict[str, Any] = {}`；
2. 落盘成功后调用 `other = declare_artifact_file(other, str(path))`（URL 产物用 `declare_artifacts(other, [artifact_from_url(url, kind)])`）；
3. `build_success/build_warning` 传 `other_data=other`；
4. 确认 warning 分支（文件已落盘但有告警）同样声明；
5. 在 `FUNCTIONS.md` §1.23 核对入口用法，无需新增登记（复用已有九函数）；
6. 在文件头部编辑历史追加"日期 + 署名 + 改动目的"，禁止删历史行。

约束：不要手搓条目 dict（`form`/`type` 判错会让抽屉把远程资源与目录当本地文件判"已不存在"）；不要新增第二份产物存储。

## 七、验证清单

### 7.1 契约级（`app/utils/artifacts.py`）

| 编号 | 验证项 | 通过标准 |
|---|---|---|
| V1 | `normalize_artifact` 幂等 | `normalize(normalize(x)) == normalize(x)`，file/dir/url 三类均成立 |
| V2 | `form` 判定 | URL → `url`；存在目录 → `dir`；存在文件 → `file`；已带 `form` 原样保留 |
| V3 | `type` 判定 | `报告.docx` → `docx`；目录 → `dir`；`https://x/a.webp?sig=1` → `webp`；`https://x/gen?id=1`+`kind="image"` → `image` |
| V4 | 去重键 | 同 URL 不同 query 同键；同路径不同大小写（Windows）同键；`file` 与 `dir` 同路径不同键 |
| V5 | 合并追加 | 两次调用条目累加，同键后到覆盖先到，不丢前一批 |
| V6 | 上限 | 51 条输入 → 50 条，保留最新 50，`logger.warning` 被触发 |
| V7 | URL 命名 | 不同文件名 URL → 不同 `name`；同名 URL 不同 query → 同一 `name` 且合并为一条 |
| V8 | 读取口 | 非 dict 返回体 → `[]`；`other_data` 缺失 → `[]`；合法清单 → 规范化列表 |

### 7.2 链路级

| 编号 | 验证项 | 通过标准 |
|---|---|---|
| V9 | 声明不污染 `llm_data` | 工具执行后 `llm_data.action` 无 `artifacts` 键 |
| V10 | 生产者数据不被改写 | `collect_and_report` 后工具返回体条目无 `tool_name` 键 |
| V11 | 收集条件 | `error` 态声明产物不收集；`success`/`warning` 收集 |
| V12 | 两层一致 | `telemetry._artifacts` 与 `list_session_task_artifacts` 条数一致 |

## 八、硬约束

实现与扩展必须遵守以下约束（由 SRP/DRY/KISS/SLAP/YAGNI/禁止 backward 等规范推导）：

1. **唯一落点**：清单只在 `other_data["artifacts"]`，不在 `llm_data.action`（`action` 是动作描述，塞清单属职责混用）。
2. **唯一契约**：字段定义只在 `app/utils/artifacts.py`，声明端/收集端/落库/读口/前端不得各自解释字段。
3. **唯一判定**：形态、类型、存在性、去重键各只有一个函数实现，禁止多处各写一遍。
4. **无兼容层**：旧入口（`with_artifacts`/`with_artifact_file`/`artifact_from_url`/`extract_ext`）已删除，不留别名、不双写、不双读。
5. **单层职责**：声明端只声明、收集端只收集、读口只读；任一层不做其他层的判断。
6. **不改生产者数据**：收集器只拷贝后加工，绝不原地改写工具返回体。
7. **有界且可见**：条目上限 50，超限丢最早、保留最新并写 warning。
8. **复用优先**：新产出工具复用九函数，新增通用能力放 `app/utils/` 并登记 `FUNCTIONS.md`。

## 九、与文件足迹的区别

产物与文件足迹常被混淆，二者是独立链路：

| 维度 | 会话产物（本文档） | 文件足迹 |
|---|---|---|
| 真源 | `chat_tasks.artifacts` | `chat_task_steps.step_json` 的 `action.tools[].params.path` |
| 后端读口 | `storage.list_session_task_artifacts` | `browse_service.recent_files` |
| 前端 API | `/sessions/{id}/artifacts` | `/files/recent-files` |
| 前端展示 | 「本会话产物」抽屉、终态统计块 | 「文件足迹」面板、文件树 `●`、推荐行 |
| 语义 | AI **产出**（写/生成/下载），只算产出型工具 | Agent **动过**（读/写/改全部），`ops` 记工具名 |

## 十、结论

1. 会话产物功能以 `chat_tasks.artifacts` 为唯一真源，五字段契约收敛在 `app/utils/artifacts.py`，前后端只按契约消费。
2. 缺口不在个别 bug，而在条目缺"形态"维度——补齐 `form` 并把判定收敛到单函数后，URL/目录产物不再被当本地文件判失效。
3. 落点从 `llm_data.action` 迁到 `other_data`，无兼容层、无数据迁移；新增产出工具只需复用声明入口三步即可接入。
