用\"Self-Attention\"取代 RNN 的时序递归，允许模型并行处理任意长序列，并显式建模每对 token 之间的加权依赖，是模型规模化（scaling）的物理前提。\n\n### 3.2 预训练—微调—对齐三阶段范式\n\n1. **预训练（Pre-training）**：在万亿 token 的公开语料上用自回归（预测下一个 多模态与大模型对齐\n\n多模态大模型不再把视觉、听觉、文本作为分离模块，而是在预训练阶段就共同嵌入同一表示空间（GPT-4o、Gemini、Claude 3 都是原生多模态）。这让 Agent 能\"看屏幕、听指令、读文档、写字典\"——是 Claude Computer Use、ChatGPT Agent 得以实现的技术前提。\n\n### 3.4 长上下文与检索增强（RAG）\n\n- **长上下文**：从 GPT-3（4K）→ GPT-4 Turbo（128K）→ Gemini 1.5 Pro（2M）→ GPT-5.5（1M+ 默认）；2024-2026 是\"上下文窗口\"最激烈的赛道。\n- **RAG**：把外部知识库向量化后注入上下文，让 Agent 访问企业私有数据。RAG + 长上下文互补：RAG 管\"广度\"，长上下文管\"深度\"。\n\n### 3.5 推理模型与思维链\n\no1/o3、DeepSeek R1、Gemini 3.1 Pro 都证明：把 RL 奖励信号设计为\"过程正确性\"而非\"结果正确性\"，模型会自发展现出\"内部推演—反思—修正\"的行为，这在数学、代码、ARC-AGI 等推理任务上带来数量级提升。\n\n### 3.6 Agent 原理：感知—规划—行动—记忆四要素\n\n- **感知**：多模态输入（文本、图像、屏幕、音频、传感器）。\n- **规划**：任务分解（Chain-of-Thought / Tree-of-Thought / 显式 Planner）。\n- **行动**：Function Calling + MCP 工具调用 + Computer Use。\n- **记忆**：短期上下文 + 长期向量库 + Claude Agent SDK 的 \"Dreaming\" 记忆。\n\n---\n\n## 第四部分 量子计算：AI 的下一个物理杠杆\n\n（本节是应用户要求补充的独立章节，详细版见报告 03。）\n\n### 4.1 量子计算的原理简说\n\n- 经典比特是 0 或 1；量子比特（qubit）在测量前处于 α|0⟩+β|1⟩ 的叠加态。\n- n 个 qubit 可同时表示 2^n 个状态的叠加，通过**量子纠缠**让状态之间存在强相关性，从而在某些问题（因式分解、量子模拟、优化）上实现指数级加速。\n- 三大硬件路线：**超导（IBM、Google）**、**离子阱（IonQ、Quantinuum）**、**光量子（PsiQuantum）**。\n\n### 4.2 2021-2026 关键里程碑\n\n- **2021**：IBM Eagle 127 量子比特（首个破百的通用量子处理器）；Google Sycamore 后续优化。\n- **2022**：IBM Osprey 433 量子比特；微软推出 Majorana 1 拓扑量子比特路线（2025）。\n- **2023-12**：IBM **Condor** 1121 量子比特（首个破千）；同期发布 **Heron** 处理器（可调耦合器、错误率降低 5 倍）与 **IBM Quantum System Two**（3 颗 Heron 模块化组网），IBM 给出到 2029 年 **Starling**（首个容错量子计算机）路线图。\n- **2024-06**：IBM QDC 大会宣布 Heron R2 可运行 5000 个两量子比特门电路，兑现了 2022 年\"100×100 挑战\"。\n- **2024-12**：Google 发布 **Willow** 芯片（105 qubit），首次实现\"逻辑量子比特随物理 qubit 数增加而指数级降错\"，被 Scientific American 称为量子纠错的关键突破；Google 论文（Newman & Satzinger, Google Quantum AI Blog, 2024-12-09）明确：\"Willow 是第一个让纠错 qubit 随规模指数级变好的处理器。\"\n- **2025**：Quantinuum / Google DeepMind 合作推动 **Generative Quantum AI (Gen QAI)**，用经典 AI 训练于量子生成的数据；IBM 提前完成 Starling 实时纠错解码器的原型。\n- **2026**：IBM 宣布 2026 年将展示量子优势候选算法；arXiv 综述（arXiv:2505.23860、2607.00365）指出\"AI 与量子信息已进入双向互哺阶段\"。\n\n### 4.3 量子×AI：双向价值\n\n- **Quantum for AI（Q4AI）**：量子机器学习（QML）、量子优化、量子退火用于超大规模聚类、组合优化、材料分子模拟。目前处于\"量子弱优势\"（quantum weak advantage）阶段——2025 年 arXiv:2505.24765 明确指出\"实用量子优势在监督学习中仍然有限，主要限于合成基准\"。\n- **AI for Quantum（A4Q）**：用 AI 做量子比特校准、错误解码（Google Willow 的解码器就是 AI 驱动）、门电路优化、材料设计（微软 Majorana 材料的发现就依赖 AI）。这是目前更成熟也更快见效的方向。\n\n### 4.4 对行业的意义\n\n- **制药/材料**：量子模拟可以在原理上解决今天经典机无法精确计算的分子哈密顿量，是\"AI 制药 + 量子模拟\"融合的最大机会。\n- **加密/安全**：Shor 算法威胁 RSA/NIST 椭圆曲线，2016 年 NIST 已启动 PQC 标准化（2024 年 8 月发布 FIPS 203/204/205），\"后量子密码迁移\"是当下最紧迫的工程任务。\n- 自己决定。\n- **优点**：实现极简、可解释、与 Function Calling 天然契合。\n- **缺点**：每一步都要调 LLM，长任务慢且贵；容易陷入循环。\n- **2026 现状**：仍是绝大多数 SaaS 内嵌 Agent（客服、Copilot、RAG Agent）的默认骨架。Future AGI（2026-03）与 Vahe Sahakyan（Towards AI, 2026-03-03）都把它列为\"入门第一范式\"。\n\n### 2.2 Reflexion / Self-Reflection——2023-10 起\n\n- **提出**：Shinn et al., 2023-10（arXiv:2303.11366）。\n- **控制流**：在 ReAct 外层加一层\"语言强化\"——失败时把失败原因写入 Episodic Memory，下一次尝试时读回来当条件。\n- **贡献**：第一次把\"记忆\"变成显式一等公民；对数学/代码/推理任务的准确率提升 10-20%。\n- **2026 现状**：被 Claude Agent SDK 的 \"Dreaming\" 记忆吸收，成为长时程 Agent 的标配。\n\n### 2.3 Plan-and-Execute / Plan-then-Execute——2023 至今\n\n- **提出**：LangChain 团队 2023-12 正式发布三个 Plan-and-Execute 变体（LangGraph 官方博文），包括 LLMCompiler、ReWOO（Reasoning WithOut Observation）。\n- **控制流**：先用一个强模型（Planner）产出完整计划 → 再让执行器（可以是更小的模型或确定性代码）按步骤执行，只在必要时回调 Planner。\n- **与 ReAct 的差异**：\n  - 更快：执行器不需要每步都问大模型，减少 60-80% 的 LLM 调用。\n  - 更省：可用小模型执行 + 大模型规划的组合。\n  - 更易审计：计划显式暴露，可以做 human-in-the-loop 审查。\n- **2026 Tree-of-Thought（ToT）与 Tree-of-Action——2023-2024\n\n- **提出**：Yao et al., 2023-05（ToT, arXiv:2305.10601）。\n- **控制流**：把 CoT 的线性扩展成树——每一步产生多个候选分支，用评分函数剪枝，最终回溯到最优解。\n- **场景**：数学、创意写作、代码调试。\n- **2026 **控制流**：一次全局规划（Goal Plan）+ 每步子计划（Sub-plan）+ 局部执行（Local Act）。\n- **动机**：ReAct 在复杂任务上\"想一步做一步\"，容易走偏；Plan-and-Execute 又过于刚性。GoalAct 试图把两者折中：全局有目标感，局部能自适应。\n- **2026 现状**：GPT-5.5 官方演示中\"1000+
