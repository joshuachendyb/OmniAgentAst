## 一、问题根因

### 1.1 现状全景（两套 Task ID 并存）

本系统在一次用户消息响应中，存在**两套独立生成、格式不同、无映射关系的 Task ID**：

| 编号 | 生成点（文件:行） | 当前值 | 用途 | 使用者 |
|------|------|------|------|--------|
| **A 号** | `openai.py:181` `str(uuid.uuid4())` | `5938890e-xxxx-xxxx-xxxxxxxxxxxx`（裸 UUID4，36 位带连字符） | SSE task_id、`agent_streams`/`running_tasks` 的 key、`_current_task_id`（工具打标）、前端 start 事件拿到的号 | SSE 流控制、pause/cancel/reconnect、工具日志 |
| **B 号** | `task_db.py:38` `f"task-{uuid4().hex}"` | `task-a1b2c3d4...`（前缀 task-，32 位无连字符） | `_tracked_task_id`、DB `tasks`/`operations` 表的关联键 | TaskTracker DB 持久化、step_emitter 注入事件 |
| **C 号** | `health.py:118` `str(_uuid.uuid4())` | 裸 UUID4 | `_api_task_id` 供 API 工具直执行打标 | 工具日志（独立入口，不进入主链路） |

### 1.2 核心病根（实锤）

```
openapi.py:181  → UUID4 → agent_streams[UUID4]、running_tasks[UUID4]、_current_task_id=UUID4
                    ↓ 传入 UniversalAgent(task_id=UUID4) → self.task_id = UUID4
base_agent.py:73  → tracker.create_task() → task_db.py:38 内部独立生成 task-{hex}
                    ↓
                    _tracked_task_id = task-{hex}  ─── step_emitter 注入的也是 task-{hex}
```

同一次响应里，`openai.py:181` 生成的 **A 号**（UUID4）与 `task_db.py:38` 内部生成的 **B 号**（task-hex）**无任何映射、各自独立**。

**后果**：前端从 start 事件拿到 UUID4 去 pause/cancel/reconnect（走 `running_tasks`，一致），但**查不到** TaskTracker DB 里的 task-hex 状态——前端拿到的号不能查/控持久化状态。

## 二、10 大规范违反点审校

| 规范 | 现状违反点 | 整改方向（定稿） |
|------|-----------|------------------|
| **SRP** 单一职责 | "生成任务标识"散落在 openai.py / base_agent.py / task_db.py / health.py 四处 | `generate_task_id()` 单点定义于 `openai.py`（唯一调用点）；tracker 不再自编号 |
| **DRY** 不重复 | task 级 ID 两处独立生成、格式不一 | 单一 `openai.py:181` 生成，全链路透传同一值 |
| **KISS-DIRECT** 简单直接 | 两套 ID + 无映射，链路绕、认知重 | 全链路同一 `task-{hex}` 贯穿，无别名、无分支 |
| **SLAP** 同抽象层 | SSE 流层（传输）与 TaskTracker 层（生命周期）在同一响应上用不同 ID | 统一 ID 消除层级混 |
| **YAGNI** 不过度 | 不需要两套；且 `_tracked_task_id` 是恒等于 `task_id` 的冗余属性 | 去双轨 + **彻底删除 `_tracked_task_id`** |
| **复用优先** | ID 生成未登记、未复用 | `generate_task_id()` 单调用点，**本地定义于 `openai.py`**（不外泄跨模块、不入 FUNCTIONS.md，避免为单点调用过度抽象） |
| **禁止 backward** | 旧生成路径残留 | `create_task` 必填 `task_id`、无 `or generate_task_id()` 兜底、无返回；不留兼容分支 |
| **OCP** 开闭 | 无稳定接口 | 统一后改格式只改 `openai.py` 一处 `generate_task_id` |
| **LSP/ISP** | 不适用（无继承） | — |
| **消除冗余（YAGNI 再确认）** | `_tracked_task_id` 与 `task_id` 恒等，多存一份 | 三处引用（`base_agent`/`step_emitter`/`initialize_run_state`）全部改用 `agent.task_id` |

```
  │                  └─ reconnect(A号) → agent_streams[A号] ✓
  │
  ├─ UniversalAgent(task_id=A号) → self.task_id = A号
  │   └─ create_task() → task_db.py:38 内部生成 B号 "task-a1b2c3..."
  │       └─ _tracked_task_id = B号
  │           ├─ DB tasks 表 task_id = B号  ← 前端拿不到这个号！
  │           └─ step_emitter 注入事件 task_id = B号
  │
  └─ run_agent_in_background(agent, A号)
      └─ run_react_cycle(task_id=A号)  ← 用的 A号
```

**问题**：前端拿 A 号不能查 TaskTracker DB（DB 用 B 号），两种事件（start/step）混着两个不同 ID，console 打印两种格式。

### 5.2 改动后（统一—单一 ID `task-{hex}`）

```
用户发消息
  │
  ▼
openai.py:181  task_id = generate_task_id()   → 统一号 "task-a1b2c3d4e5f6..."
  │
  ├─ _current_task_id.set(统一号)
  ├─ agent_streams[统一号]、running_tasks[统一号]
  ├─ register_task(统一号)
  ├─ step_start → SSE start event task_id = 统一号
  │                  前端从 start 拿到 统一号
  │                  ├─ pause(统一号) → running_tasks[统一号] ✓
  │                  ├─ cancel(统一号) → running_tasks[统一号] ✓
  │                  └─ reconnect(统一号) → agent_streams[统一号] ✓
  │
  ├─ UniversalAgent(task_id=统一号) → self.task_id = 统一号
  │   └─ create_task(task_id=self.task_id) → DB tasks 表直接写入统一号  ← ！！！
  │       ├─ DB tasks 表 task_id = 统一号  ← 前端能查到了！
  │       └─ step_emitter 直读 self.agent.task_id = 统一号（_tracked_task_id 已删除）
  │
  └─ run_agent_in_background(agent, 统一号)
      └─ run_react_cycle(task_id=统一号)
```

**改变**：
- `openai.py:181` 统一生成 `task-{hex}`，与历史 `tasks` 表、与 `op-{hex}` 操作 ID 同构。
- `create_task` 接收传入的 `task_id`，不再内部独立生成。
- `_tracked_task_id` 彻底删除，`step_emitter`/`initialize_run_state` 直接读 `agent.task_id`，与 SSE task_id、running_tasks、agent_streams、DB 全部相同。
