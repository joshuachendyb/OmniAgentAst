## 一、背景与问题

### 1.1 问题描述

LLM 在推理过程中可能陷入"卡顿循环"——反复生成相同的 reasoning 文本。当前 `_dedup_repeat` 函数使用 **固定 200 字 chunk** 检测重复：

```python
DUP_CHUNK = 200  # 固定步长
chunks = [content[i:i+step] for i in range(0, len(content)-step+1, step)]
```

### 1.2 已知缺陷

从真实 prompt 日志数据中发现：

| 问题 | 样本 | 数据 | 根因 |
|------|------|------|------|
| A-B 交替重复无法检测 | prompt_999481#33375 | 29863 字, 68 次重复, **去重 0%** | 200 字 chunk 不匹配 312+123 交替模式 |
| 非 200 倍数块无法检测 | prompt_999481 全部 4 个条目 | 531 字块重复, **去重 0%** | 531 mod 200 = 131, chunk 偏移 |
| 中等重复效果差 | prompt_999507#66400 | 29943 字, 仅 **62.5%** 去重 | chunk 偏移导致检测延迟 |
| 简单重复效果良好 | prompt_999099#131917 | 149997 字, **88.0%** | 块大小对齐 |
| 简单重复效果良好 | prompt_999235#66807 | 145581 字, **99.0%** | 块大小对齐 |

**核心矛盾**: 固定 200 字步长只能检测"块长度是 200 倍数"的简单重复，对真实世界的非对齐重复模式（A-B 交替、非 200 倍数块）失效。

## 三、测试方法详述

### 3.1 方法 1: 当前算法（基线）

固定 200 字 chunk 切块，找第一个出现的重复 chunk。

```python
step = 200
chunks = [content[i:i+step] for i in range(0, len(content)-step+1, step)]
seen = {}
for idx, ch in enumerate(chunks):
    if ch in seen:
        second_pos = idx * step
        break
    seen[ch] = idx
```

### 3.2 方法 2: 句子频率 (min_repeat=3)

按句号(`。`)或换行(`\n`)分割为句子，统计频率，出现 ≥3 次的句子保留首次出现，后续跳过。

```python
parts = re.split(r'(?<=[。\n])', content)
counter = Counter(parts)
repeated = {s for s, cnt in counter.items() if cnt >= min_repeat}
# 保留首次出现的重复句子，跳过后续重复
```

### 3.3 方法 3: 句子频率 (min_repeat=5)

同方法 2，但阈值提高到 5。

### 3.4 方法 4: 多步长 chunk

尝试 6 种步长 (100/150/200/300/400/500)，取压缩率最高的结果。

### 3.5 方法 5: 关键词间距

找 "让我尝试使用fetchpage" 关键词的出现间距，用最常见间距作为步长检测重复。

### 3.6 方法 6: n-gram 窗口 (50 字, min_repeat=5)

50 字 n-gram 滑动窗口（步长 10），出现 ≥5 次的片段标记为重复。

### 3.7 方法 7: n-gram 窗口 (30 字, min_repeat=7)

同方法 6，但窗口 30 字，阈值提高到 7。

### 3.8 方法 8: 组合 — 句子 + 多步长

先句子频率，未触发则多步长。

### 3.9 方法 9: 组合 — 关键词 + 句子

先关键词间距，未触发则句子频率。

### 3.10 方法 10: 三层 — 关键词 → 句子 → n-gram

按顺序尝试关键词间距、句子频率、n-gram，任一触发即返回。

### 4.2 方法汇总

| 方法 | 命中率 | 平均压缩率 | 最大耗时 | 结论 |
|------|-------|-----------|---------|------|
| 当前算法(200字chunk) | 6/10 | 50.7% | 0.5ms | A-B交替完全失效, 非200倍数块部分失效 |
| **句子频率(min=3)** | **10/10** | **98.4%** | **5.8ms** | **最佳单一方法** |

| 关键词间距 | 3/10 | 29.1% | 0.6ms | 有特定关键词才有效, 不可靠 |
| n-gram(50字,min=5) | 10/10 | 99.0% | 3.6ms | 压缩率高但可能过度 |

| 组合:句子+多步长 | 10/10 | 98.4% | 6.6ms | 无增益, 同句子频率 |
| 组合:关键词+句子 | 10/10 | 97.9% | 6.3ms | 关键词拖后腿 |
| 三层:关键词→句子→ngram | 10/10 | 97.9% | 7.6ms | 无增益 |

### 4.3 关键结论

1. **句子频率(min=3) 是最佳单一方法** — 100% 命中, 98.4% 平均压缩, 5.8ms
2. **关键词间距假设错误** — 只有 3/10 命中率, 仅在关键词精确出现时才有效
3. **组合没有增益** — 句子频率单独已经 100% 命中, 加其他层反而拖后腿
4. **n-gram 压缩过度** — 99.0% 会去掉更多有用内容 (如 999481#33375: 135 字 vs 句子频率 565 字)
5. **min_repeat=3 和 5 效果一致** — 数据中重复程度极高, 两者无差异

对 14 种边缘场景测试了句子频率方法的 3 个版本：

| 短重复(<500字) | 300 | OK(too_short) | OK(too_short) | OK(too_short) |

| 无标点内容(7200字) | 7200 | OK(too_few_parts) | OK(too_few_parts) | OK(too_few_parts) |

| 相似但不同句子 | 222 | OK(too_short) | OK(too_short) | OK(too_short) |

| 超长代码(100函数) | 2980 | OK | OK | OK |
| 超长散文(重复段落) | 4500 | **90.0%** 正确 | **90.0%** 正确 | **90.0%** 正确 |
| 多章节内容(无重复) | 383 | OK(too_short) | OK(too_short) | OK(too_short) |

### 5.2 重要发现

**v1(基础版) 在长报表上触发假阳性 (93.8%)**：
- markdown 表行被按 `\n` 分割为句子，数据行完全相同（如 "| 智能客服系统 | 张三 | 80% | 进行中 |\n" 出现 20 次）
- 句子频率方法将其标记为重复并压缩，导致结构化数据丢失

**v2(排除表行) 完美解决**：
- 对以 `|` 开头的句子不标记为重复
- 报表数据保持完整 (2876→2876, 0% 压缩)
- 真实重复样本仍被正确检测 (与 v1 一致)

**保护机制有效性**：
- `REPEAT_CHECK_MIN_LEN=500`: 所有 <500 字的内容均被跳过
- 无标点内容: `too_few_parts` 保护（无句号/换行时不触发）
- `DUP_RATIO=0.5`: 即使少数句子被标记为重复，占比不足 50% 时不截断

## 六、最终推荐方案

### 6.1 选型决策

| 维度 | 决策 | 理由 |
|------|------|------|
| 核心算法 | **句子频率(v2)** | 100%命中, 98.4%压缩, 5.8ms |
| min_repeat | **3** | 防误伤, 3次相同的句子才标记 |
| 表行保护 | **排除行首为 `|` 的句子** | 防止结构化报表假阳性 |
| 保留 DUP_RATIO | **0.5** | 继续作为保守阈值 |
| 保留 REPEAT_CHECK_MIN_LEN | **500** | 短内容保护 |
| 删除 DUP_CHUNK | **是** | 不再需要固定步长 |

### 6.2 为什么不是组合方案

实测数据显示**句子频率单独已经最优**：
- 组合方案"句子+多步长" = 98.4%（同句子频率）
- 组合方案"关键词+句子" = 97.9%（关键词拖后腿）
- 三层"关键词→句子→ngram" = 97.9%（同关键词+句子）

### 6.3 为什么不是 n-gram

n-gram 压缩率略高 (99.0% vs 98.4%), 但：
- 压缩更激进: 999481#33375 保留 135 字 vs 句子频率保留 565 字（有用内容更多）
- 实现更复杂: 需要 O(N) 哈希表, 参数较多
- 无法区分表行

### 6.4 参数配置

```python
# 最终参数配置
REPEAT_CHECK_MIN_LEN = 500    # 保留: 短内容不检测
SENTENCE_MIN_REPEAT = 3       # 新增: 同一句出现≥3次标记为重复
DUP_RATIO = 0.5               # 保留: 重复占比过半才截断
# DUP_CHUNK = 200             # 删除: 不再需要固定步长
```

## 七、实施计划

### 7.1 改造 `_dedup_repeat` 函数

将现有函数替换为句子频率方法(v2)：

```python
def _dedup_repeat(content: str) -> str:
    """基于句子频率的重复检测与去重
    原理: 按句号/换行分割为句子, 统计频率, 
    出现 ≥SENTENCE_MIN_REPEAT 次的句子保留首次出现, 后续跳过
    防误伤: 排除markdown表行(行首为|), 重复占比>50%才截断"""
    if len(content) < REPEAT_CHECK_MIN_LEN:
        return content
    # 按句号/换行分句
    parts = re.split(r'(?<=[。\n])', content)
    parts = [p for p in parts if len(p.strip()) > 0]
    if len(parts) < 10:
        return content
    # 统计句子频率(排除表行)
    counter = Counter(parts)
    repeated = {s for s, cnt in counter.items()
                if cnt >= SENTENCE_MIN_REPEAT
                and not s.strip().startswith('|')}
    if not repeated:
        return content
    # 去重
    result = []
    seen = set()
    for p in parts:
        if p in repeated and p in seen:
            continue
        if p in repeated:
            seen.add(p)
        result.append(p)
    deduped = "".join(result)
    # 保守阈值
    if len(deduped) >= len(content):
        return content
    if 1 - len(deduped) / len(content) < DUP_RATIO:
        return content
    return deduped
```
