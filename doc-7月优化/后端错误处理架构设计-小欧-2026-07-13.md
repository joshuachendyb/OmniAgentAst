## 一、先说结论：系统处理错误分两大类

整个系统里所有出错情况，按"任务停不停"分成两大类，互不重叠，各自独立路径：

### 1.1 核心分类架构

```
错误处理架构
├── 系统层次错误 (System Errors)          —— 任务停
│   ├── LLM调用/分类层错误（5种，全部正确）
│   ├── ReAct循环层错误（11种，全部正确）
│   ├── 安全检查层错误（3种，全部正确）
│   └── 基础设施层错误（2种，全部正确）
│
└── 工具层次错误 (Tool Errors)            —— 任务不停
    ├── 前置校验错误（4种，全部正确）
    ├── 执行重试错误（3种，全部正确）
    └── 执行段错误（1种，全部正确）
```

```
系统类错误（任务停）：LLM调用/分类层 + ReAct循环层 + 安全检查层 + 基础设施层
├── 特征：Agent循环中断，设FAILED/CANCELLED/RETRYING
├── 分类机制：SystemErrorClassifier(app/services/llm/error_classifier.py) + _is_recoverable_error(react_cycle.py:42)
└── 位置：llm_stream → _process_single_step → _dispatch_handler → handle_react_error → run_react_cycle

工具层错误（任务不停车）：前置校验 + 执行重试 + 执行段
├── 特征：Agent循环继续，错误作为ObservationStep喂回给LLM
├── 分类机制：ToolErrorClassifier(app/tools/tool_error_classifier.py)
└── 位置：action_handler → tool_executor → tool_retry_engine
```

### 1.2 第一类：系统层次的错误（任务会停）

比方说：
- 调AI大模型的时候网络断了
- AI大模型返回的数据格式完全不对
- 安全检查认定某个操作有风险，不让执行
- 用户点了"取消"

遇到这类错误，**任务直接终止**，系统告诉用户"任务失败了，原因是XXX"。

> 简单理解：**系统自己出了问题，任务没法继续了。**

### 1.3 第二类：工具层次的错误（任务不停）

定义：发生在工具执行过程中的错误。每个工具独立处理，自带重试机制，不炸到系统层。

LLM说"要用工具X"→ 系统去执行工具X → 工具执行有问题 → 但问题不扩散到系统层→ 包装成ObservationStep喂回给LLM → LLM自己决定：重试、换工具、回答

比方说：
- AI说要调一个工具，但这个工具的名字系统里找不到
- AI调工具时给的参数不对
- AI漏了必填的参数
- 调工具时出错了（比如网络超时），重试了几次还是不行

遇到这类错误，**任务不终止**。系统把"工具执行出错了"这个信息包装好，喂回给AI大模型。AI大模型自己决定下一步怎么办：
- 重试一次这个工具
- 换别的工具试试
- 直接回答用户"这个事我办不了"

> 简单理解：**工具执行不顺利，但AI自己会想办法，任务还能继续。**

### 1.4 两类错误的核心区别

| 特性 | 系统层次错误 | 工具层次错误 |
|------|------------|-------------|
| 循环是否中断 | 是，直接break | 否，LLM看到错误结果后自行决定 |
| 前端看到什么 | ErrorStep（FAILED终态）/ MetaStep(cancelled) | ObservationStep（error状态） |
| Agent状态 | FAILED / RETRYING / CANCELLED | 保持THINKING，循环继续 |
| 能否恢复 | 一部分可以（RETRYING，由SystemErrorClassifier判定） | 可以，LLM重试或换工具 |
| 谁创建Step | ErrorStep（FAILED终态）/ MetaStep(cancelled)（COMPLETED 才用 FinalStep） | ObservationStep |
| 错误码来源 | SystemErrorClassifier 分类出的系统类别；工具层为 `app/tools/tool_constants.py` 中的 `ERR_xxx` | `app/tools/tool_constants.py` 中的 `ERR_xxx` |

| 核心区别 | 系统层次错误 | 工具层次错误 |
|---------|------------|-------------|
| **任务停不停** | **停** | **不停** |
| **用户看到什么** | "任务失败，原因是..." | AI自己处理，用户可能看到AI说"我重试一下"或者"办不了" |
| **谁来决定下一步** | 系统自己决定（终止/重试整轮） | AI自己决定（重试/换工具/放弃） |

> 注：v2.1 中的 `RETRYABLE_ERROR` 状态枚举已不存在，当前用 `AgentStatus.RETRYING`（可重试，重试超限转 `FAILED`）。

> 注（终态 Step 统一约定 v3.2/v3.3，2026-07-13 小欧，已落地）：`FinalStep` 仅用于 COMPLETED；**FAILED 终态仅用 `ErrorStep`（删 recoverable、不再补发空 FinalStep）**；**CANCELLED 终态用 `MetaStep(type="cancelled")`（不再发 FinalStep）**；**RETRYING 仅系统/LLM 重试用 `MetaStep(type="retrying")`，工具重试隐蔽前端不可见**；**SUSPENDED/HITL 用 `MetaStep(type="paused", confirm_id=...)`**。删除旧的 `incident`/`authorization_required` 裸 SSE 表示与 `recoverable` 布尔；DB `chat_messages` 新增 `status` 列（completed/failed/cancelled/paused），并有一次性幂等迁移脚本回填旧数据。详见《终态 Step 统一约定设计方案-小欧-2026-07-13.md》。

### 2.5 关于blocked/user_rejected/invalid_action的分类说明

`check_safety_and_confirm`（`action_handler.py:53`）在 action_handler 里，但它中断了循环（推断 `FAILED`）。它不是 Tool 执行本身的错误，而是安全检查基础设施阻止了 Tool 执行。

所以正确的分类应该是：
- 18号 blocked → 系统层次（中断循环，推断 `FAILED`）
- 19号 user_rejected → 系统层次（中断循环，推断 `FAILED`）
- 20号 invalid_action → 系统层次（中断循环，推断 `FAILED`）

### 2.6 系统层次错误处理架构图

```
call_llm_with_fallback()
    │
    ├── 正常响应 (response type ──── limit / no error)
    │   ├── "action" ──→ _dispatch_handler ──→ handle_action()
    │   └── "answer" ──→ _dispatch_handler ──→ handle_answer() → COMPLETED
    │
    └── 错误响应 (error type)
        └── _dispatch_handler ──→ handle_react_error() → FAILED / RETRYING
                                       │
                                       ├── SystemErrorClassifier 分类(circuit_open/server/unknown/empty_response/idle_timeout)
                                       ├── _is_recoverable_error 判定是否可重试
                                       ├── ErrorStep(error_type, error_message)
                                       ├── add_assistant_message(content)
                                       ├── agent.set_failed(content) 或 agent.set_status(RETRYING)
                                       └── FinalStep(response=content)
```

## 三、工具层次的错误（共8条，都有对）

### 3.1 核心思想

AI说"我要用工具X"→ 系统去执行工具X → **工具执行有问题**

但**问题不传到系统层**，而是：
1. 把错误包装成**结构化的结果**
2. 通过"观察步骤"喂给AI
3. AI自己决定下一步
