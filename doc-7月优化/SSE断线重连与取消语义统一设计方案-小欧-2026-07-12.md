# SSE 断线重连与取消语义统一设计方案

**版本**: v1.0
**创建时间**: 2026-07-12 23:41:24
**作者**: 小欧
**适用范围**: OmniAgentAs-desk 后端 `services/chat` + `services/task` + `services/agent`，前端 `utils/sse.ts` + 任务控制 Hook

---

## 一、背景与问题

### 1.1 当前架构缺陷

当前 SSE 流式输出中，agent 的执行（ `agent.run_react_cycle()` ）直接运行在 HTTP 请求处理器 `generate()` 协程内。带来的问题：

1. **断线即终止**：前端 SSE 连接断开时，FastAPI 取消 `generate()` 协程，导致 `run_react_cycle` 被取消，后端 agent 一并死亡。用户网络闪断后，整个任务丢失。
2. **取消语义不一致**：状态枚举 `AgentStatus.CANCELLED` 值正确，但 SSE 事件 `type`、DB `end_type` 却使用字面量 `"interrupted"`，前后端对终态事件的判断口径不统一。
3. **取消来源单一**：只考虑了"用户点取消"，没有覆盖"前端断线重连 3 次失败"这一取消来源。
4. **旧 cleanup bug**： `openai.py` 的 `finally` 在断线时也会调用 `task_cleanup`，会误删仍在运行的任务。

### 1.2 用户诉求（北京老陈 2026-07-12）

- 前端 SSE 瞬时断开再恢复 → **不能武断算取消**
- 前端应尝试重连后端 **3 次**，3 次都不成功才可以置为取消
- 前端 SSE 连接与后端调 LLM 的 HTTP 连接是**两个独立空间**，必须分开设计
- 修改必须准确、说清每个改动解决什么问题，且功能不退化

---

## 二、设计目标与不可退化的子系统

### 2.1 设计目标

将 agent 执行与 SSE 传输**解耦**：agent 在独立后台任务运行，SSE 只从事件缓冲按 `seq` 偏移读取；前端断线不影响 agent，重连读取同一缓冲，3 次重连失败才取消。

### 2.2 不可退化的能力（逐项保护）

| 编号 | 能力 | 当前实现 |
|------|------|---------|
| R1 | 用户点"取消" → CANCELLED | `cancel_task` → `set_cancelled` → `ai_service.cancel()` |
| R2 | 用户"暂停/恢复" | `task_pause_check_and_yield` |
| R3 | HITL 人工确认 | `resolve_confirmation` 端点 |
| R4 | 执行步骤持久化 DB | `save_execution_steps_to_db` |
| R5 | `task_cleanup` 生命周期清理 | `openai.py` finally |
| R6 | prompt_logger 记录 | `openai.py` 起止 + `stream.py` 每步 |
| R7 | pytest E2E 超时保护 | marker 恢复机制（不受影响） |

## 三、架构前后对比

### 3.1 当前架构（缺陷）

```
StreamingResponse(generate())
  generate():
    register_task(task_id)
    async for ev in agent.run_react_cycle():   ← handler 内
        yield sse(ev)
    except CancelledError → set_cancelled       ← 断线即触发
    except Exception     → set_failed
    finally: save DB, task_cleanup
```

### 3.2 新架构（解耦）

```
POST /chat/stream
  generate():
    task_id = uuid(); 建 StreamBuffer → agent_streams[task_id]
    register_task(task_id)                          ← running_tasks（控制态）
    asyncio.create_task(run_agent_in_background(...))   ← 独立后台生产者
    async for sse in _stream_with_control(buffer, after_seq=0):  ← 纯消费者
        yield sse

GET  /chat/stream/{task_id}?after_seq=N             ← 重连入口
  async for sse in _stream_with_control(buffer, after_seq=N):
        yield sse

run_agent_in_background():   ← 生产者，与连接无关
    async for ev in agent.run_react_cycle():
        buffer.append(ev)        ← event_log（append-only）+ notify
    except CancelledError → append(cancelled step); set_cancelled
    except Exception     → append(error step); set_failed
    finally: save DB; task_cleanup; buffer.done.set()
```

### 3.3 核心数据结构（新增 `agent_streams` 独立于 `running_tasks`）

```python
# services/task/task_state.py
agent_streams: dict[str, "StreamBuffer"] = {}

@dataclass
class StreamBuffer:
    event_log: List[Dict] = field(default_factory=list)  # append-only，每条含 seq
    cond: asyncio.Condition                              # 新事件唤醒消费者
    done: asyncio.Event                                  # 生产者结束信号
    max_step: int = 0
```

**为什么分离（SRP）**： `running_tasks` 是控制态（cancelled/paused/agent）， `cleanup_task` 会在任务完成时删除它； `agent_streams` 是流态（事件回放），必须保留到重连窗口结束。两者生命周期不同，必须拆开，否则重连时 `running_tasks` 已删 → 找不到缓冲。

## 四、完整修改清单

### 4.1 M1 `services/task/task_state.py` — 新增 `agent_streams` + `StreamBuffer`

- **位置**：文件末尾（`__all__` 之前）
- **改前**：无
- **改后**：新增 `agent_streams` dict + `StreamBuffer` dataclass + `create_stream_buffer(task_id)` / `get_stream_buffer(task_id)` / `reclaim_stream_buffer(task_id)` 三个小函数
- **解决问题**：为断线重连提供持久化事件缓冲，与 `running_tasks` 控制态解耦
- **标准**：SRP（流态独立）、KISS-DIRECT（dataclass 直白）、复用（沿用 `running_tasks` 同款 dict 模式）

### 4.2 M2 新建 `services/agent/agent_runner.py` — 生产者

- **位置**：新文件
- **内容**： `run_agent_in_background(agent, task_id, last_message, context, next_step, session_id, stream_state, start_time)`
  - 原 `stream.py` 的 agent 创建、 `_stop_check` 注入、 `_load_previous_messages`、run 循环、异常分支、**finally（save DB + `_log_task_end` + `task_cleanup`）** 全部原样迁移
  - `except CancelledError` 分支：保留 `MetaStep(type="cancelled", message="任务已被取消")` + `FinalStep` + `set_cancelled(agent)`
  - `except Exception` 分支：保留 `ErrorStep` + `FinalStep` + `set_failed`
  - 每个事件经 `buffer.append()` 写入 `event_log` 并 `cond.notify_all()`；结束时 `buffer.done.set()`
- **解决问题**：agent 不再绑死 HTTP handler，断线不影响执行
- **标准**：SRP（生产者单一职责）、DRY（复用 `run_react_cycle`/`save_execution_steps_to_db`/`_log_task_end`）、禁止 backward（不保留旧 `run_sse_stream`）

### 4.3 M3 `services/chat/stream.py` — 删除 `run_sse_stream`，新增纯消费者 `stream_reader`

- **位置**： `stream.py` 全文重写，保留 `_log_task_end`/`_yield_error_sse`/`_parse_*`/`_load_previous_messages`
- **改前**： `run_sse_stream()`（含 agent 创建 + run 循环 + 异常 + finally）
- **改后**：
  ```python
  async def stream_reader(buffer, task_id, after_seq=0):
      offset = after_seq
      while True:
          async with buffer.cond:
              while offset < len(buffer.event_log):
                  yield format_agent_sse(buffer.event_log[offset])
                  offset += 1
              if buffer.done.is_set():
                  return
              await buffer.cond.wait()
  ```
  并在 `openai.py` 的 reader 外层包 pause/cancel 注入（见 M5）
- **解决问题**：SSE 只做"读缓冲→转发"，断线即返回、不碰 agent；重连复用同一函数
- **标准**：SRP、KISS-DIRECT（无抽象）、DRY（首次/重连共用 `stream_reader`）

### 4.5 M5 `api/v1/chat/openai.py` — 拆 `generate()`，新增重连端点

- **位置**： `openai.py:148-263`
- **改前**： `generate()` 内联调用 `run_sse_stream(...)` 并包 pause/cancel 注入 + 末尾 `task_cleanup`
- **改后**：
  ```python
  @router.post("/chat/stream")
  async def chat_stream(request):
      task_id = str(uuid.uuid4())
      buffer = create_stream_buffer(task_id)
      await register_task(task_id, ai_service)
      asyncio.create_task(run_agent_in_background(agent, task_id, user_input, context, next_step, session_id, state, _task_start_time))
      return StreamingResponse(_stream_with_control(buffer, task_id, next_step, session_id))

  @router.get("/chat/stream/{task_id}")
  async def chat_stream_reconnect(task_id, session_id=None, after_seq: int = 0):
      buffer = get_stream_buffer(task_id)
      if not buffer:
          return PlainTextResponse(error_sse("任务不存在或已结束"), media_type="text/event-stream")
      return StreamingResponse(_stream_with_control(buffer, task_id, next_step, session_id, after_seq))
  ```
  抽出 `_stream_with_control(buffer, task_id, next_step, session_id, after_seq=0)` 包装 `stream_reader` + pause/cancel 注入； `finally` 仅做 prompt_logger 起止，**不再调用 `task_cleanup`**（已由 M2 生产者负责）
- **解决问题**：提供"首次启动"与"重连读取同一缓冲"两条 HTTP 路径；消除旧 bug（断线即 cleanup 在跑的 agent）
- **标准**：SRP、DRY（`_stream_with_control` 被两端点共用）、禁止 backward（删除 `run_sse_stream` 旧调用）

  const tid = reconnectAttemptsRef.current > 0 ? serverTaskIdRef.current : null;

## 五、回归风险矩阵

| 子系统 | 当前行为 | 新方案如何保持 | 风险 |
|--------|---------|---------------|------|
| 用户取消 | `cancel_task`→`set_cancelled`→`_cancelled`→react_cycle 停→`set_cancelled` | 完全保留；生产者 `except CancelledError` 补发 cancelled 终态 | 低 |
| 暂停/恢复 | `task_pause_check_and_yield` 在 `generate()` 内注入 | 抽到 `_stream_with_control`，首次+重连共用 | 低 |
| HITL 确认 | `resolve_confirmation` 独立端点，agent 内 await | 生产者内 `run_react_cycle` 不变 | 无 |
| DB 持久化 | `stream.py` finally `save_execution_steps_to_db` | 原样迁入 M2 生产者 finally | 低 |
| task_cleanup | `openai.py` finally 调 `task_cleanup` | 移到 M2 生产者 finally；修复旧 bug：断线时不再误删在跑的 task | 中（需确认时机） |
| prompt_logger | `openai.py` 起/止 + `stream.py` 每步 `log_step_yield` | 起/止留 `openai.py`；每步 `log_step_yield` 迁入 M2 `_append` | 低 |
| pytest 超时 | pytest-timeout 杀进程，marker 恢复 | 本方案不改 pytest 机制；E2E 仍走真实后端 | 无 |
| 重连重复事件 | 旧：重连重发整条消息（双 agent） | 新： `after_seq` 续传 + `event_log` append-only，无重复 | 低 |
| 空闲超时误判 | 前端 60s 无数据→误判断线→重连 | 新：误判重连只是开新 GET 读同缓冲，旧连接断开不影响 agent；事件不丢 | 低 |
