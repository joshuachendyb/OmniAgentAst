## 一、设计铁律（北京老陈硬约束）

1. **一个概念 = 一种表示**，绝不允许两套表示并存（双表示 = 屎）。
2. **名称必须准确无误、名副其实**，禁止不伦不类（如"取消语义却用 Interrupt 命名"）。
3. **禁止靠布尔 flag 区分概念**（如 recoverable 布尔 = 屎）。终止与否由"有无 FINAL 表示"判定，不由 flag。
4. **三种信号必须用 TYPE 区分**，不得共用 ErrorStep 再用 flag 暗示"其实还要重试/已暂停"：
   - 真·停下 = `ErrorStep`（error=true）
   - 重试中 = `MetaStep(type="retrying", ...)`（纯通知，非 error）
   - 暂停中 = `MetaStep(type="paused", ...)`（纯通知，非 error）
5. **禁止用裸 SSE dict 当生命周期信号**（如 `{"type":"incident","incident_value":"cancelled"}`）；统一走 `MetaStep`，经由 `build_step_dict` 产出。
6. **不改功能逻辑、功能不退化**：用户取消 / 暂停恢复 / HITL / DB 持久化 / task_cleanup / prompt_logger 全部保留。
7. **前端重设计不迁就旧屎**：组件按新 TYPE 直接渲染，不再为旧 incident 特殊分支。
8. **遵守编码 10 法**：SRP / DRY / KISS-DIRECT / SLAP / YAGNI / 禁止 backward / OCP / LSP / ISP / 复用优先。
9. **设计文档先写，再按设计落地**；实现前先查 `backend/FUNCTIONS.md` 确认无复用。
10. **严禁提交测试代码**（`tests/` 目录），本次不涉及实现提交。

## 二、统一模型（5 种终态/生命周期概念）

| 概念 | 统一表示 | 含义 | 是否真终止 |
|------|----------|------|-----------|
| COMPLETED | `FinalStep` | 正常完成，带 `content` | 是（FINAL） |
| FAILED | `ErrorStep`(error=true) | 真失败，停下来 | 是（FINAL） |
| CANCELLED | `MetaStep(type="cancelled")` | 用户取消 | 是（FINAL） |
| RETRYING | `MetaStep(type="retrying", message, data={attempt?, max_retries?})` | **仅系统/LLM/agent 重试**上报（纯通知） | 否（中间态） |
| （工具重试） | **不发出任何 step** | 工具重试隐蔽，前端不可见，仅后端 `tool_retry_engine` 内部重试 | 否（内部） |
| SUSPENDED | `MetaStep(type="paused", data={confirm_id?, tool_name?, params?, safety_level?})` | 等待 HITL / 用户暂停（纯通知） | 否（中间态） |

**生命周期统一经由 `MetaStep`**：
- 用户取消（最终）→ `MetaStep(type="cancelled")` — 已存在
- HITL 授权请求 → `MetaStep(type="paused", confirm_id=..., tool_name=..., params=..., safety_level=...)` — 由 `authorization_required` 改造
- 用户暂停 → `MetaStep(type="paused", data={...})` — 由裸 incident dict 改造
- **系统/LLM 重试** → `MetaStep(type="retrying", ...)` — 由 `ErrorStep(recoverable=True)` 改造；空内容重试（answer_handler）同属系统重试，一并上报
- **工具重试** → **隐蔽，不发出任何 step**；仅后端 `tool_retry_engine` 内部重试，前端不可见（绝不走 `MetaStep(retrying)`，旧 `ChunkStep` 重试提示直接删除）

**删除**：
- `ErrorStep.recoverable` 字段及 `_extra_fields`/`recoverable` property（连根）
- 工具重试用 `ChunkStep` 的写法（**彻底删除，隐蔽不发出任何 step**）
- HITL/用户暂停用裸 `{"type":"incident",...}` 的写法（改 `MetaStep(paused)`）

**不改名**：`ErrorStep` 保留原名（RETRYING 已移出，不再有歧义），不改为 `FailedStep`。

> **命名说明（透明，非变更）**：用户取消（task_runtime）与系统强制终止（截断/最大步数/无终态，react_cycle L249/L296/L337）在 wire 上统一用 `type="cancelled"`，靠 `content` 精确描述原因（"响应过长已截断"/"已达最大步数"/"未产出终态"等）。语义上"cancelled"偏用户取消，系统终止严格应另立 `type`；但 v2.0 已按"统一终态表示"定稿且老陈认可，故保持。后续如需严格区分可另增 `type="terminated"`（OCP 友好，扩展 MetaStep.type 即可，不动既有类）。

## 三、10 大原则符合性自检（逐条）

| # | 原则 | 本设计符合性 | 说明 / 修正 |
|---|------|------------|------------|
| 1 | SRP 单一职责 | ✅ | 每类只表一种语义：`ErrorStep`=错误、`MetaStep`=生命周期、`FinalStep`=答案 |
| 2 | DRY 不重复 | ✅ | 复用既有 `MetaStep`/`_emit_step_sse`/`extract_metadata_from_steps`；`status` 映射分两级且各一处：`_m`(AgentStatus→end_type) 与 `_STATUS_MAP`(end_type→storage)，轴不同不重复；`build_step_dict` 仅扩展 `data` 参数不复制逻辑 |
| 3 | KISS-DIRECT 简单直接 | ✅ | 每概念单一表示，直接按 `type` 分派，无中间注册表、无 flag 绕弯 |
| 4 | SLAP 同一抽象层 | ✅ | handler 产 step → runner 收尾 → storage 落库，层级清晰不混搭 |
| 5 | YAGNI 不过度 | ✅ | `status` 列与迁移均为用户明确要求或数据兼容所必需；v3.2 已撤掉 `exit_with_error` 多余的 `details` 参数（无调用方），无多余抽象 |
| 6 | **禁止 backward** | **✅（v3.0 修正）** | **v2.0 在组件保留 `incident` 渲染分支 = 新旧混杂，违反本原则。v3.0 改为：加一次性迁移把旧 `incident` 步骤改写为新 `MetaStep` 类型 + 落 `status` 列，组件彻底删除 `incident` 分支，渲染只走新 `type`，无新旧并存** |
| 7 | OCP 开闭 | ✅ | 新增 retrying/paused 无需新建 step 类，扩展 `MetaStep.type` 即可，对既有 step 类封闭 |
| 8 | LSP 里氏替换 | ✅ | `MetaStep` 无子类改写契约；`ErrorStep`/`FinalStep` 为兄弟类，无继承替换风险 |
| 9 | ISP 接口隔离 | ✅ | `MetaStep.data` 仅承载该类型所需的 `confirm_id`/`tool_name` 等可选字段，不强制所有事件具备全部字段 |
| 10 | 复用优先 | ✅ | 复用既有 `MetaStep`/`create_timestamp`；新增 `derive_status_from_steps` 前须查 `FUNCTIONS.md` 确认无复用再建并登记 |

> **关于"禁止 backward"的再说明**：本原则针对"代码新旧混杂"。持久化在 DB 的历史行属**数据兼容**，不以"保留旧渲染分支"方式迁就，而以"一次性迁移改写历史数据"方式解决，迁移后代码路径单一，符合"禁止 backward"。
