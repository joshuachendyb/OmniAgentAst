## 一、新增的安全配置项目

组名进键名前缀，三组 —— `security.system.` / `security.hitl.` / `security.trust.`。

### 1.1 安全/系统组（硬拦类：要不要拦）

| # | 变量名 | 类型 | 默认 | 中文标签 |
|---|---|---|---|---|
| 1 | `security.system.enabled` | bool | true | 安全模块启用 |
| 2 | `security.system.forbidden_system_path_block` | bool | true | 禁区系统目录拦截 |
| 3 | `security.system.forbidden_non_system_path_block` | bool | true | 禁区非系统目录拦截 |
| 4 | `security.system.out_of_scope_path_block` | bool | true | 白名单外路径拦截 |
| 5 | `security.system.shell_danger_block` | bool | true | bash 危险命令拦截 |

### 1.1.1 各开关配置含义

- `security.system.enabled`：**总闸**。开启＝安全模块正常检测；关闭＝全部安全判据（含系统组硬拦、HITL 确认）一律直接通过。实现为折入唯一读取原子 `safety_switch`（见 2.1.2）—— 关闭时任何经 `safety_switch` 读取的开关都返回 False，故**执行层直调**（`execute_shell_command` 直调 `check_shell_danger_command`、`delete_file` 直调 `guard_forbidden_delete`）也同样被放行，不靠逐处补读。
- `security.system.forbidden_system_path_block`：对**禁区的系统目录**（磁盘根、系统敏感文件/目录、系统保护目录；硬拦，永不可放行）是否检测；关闭＝不检测，直接通过。
- `security.system.forbidden_non_system_path_block`：对**禁区的非系统目录**（删除硬拦；写入需确认后可放行）是否检测拦截；关闭＝不拦截，直接通过。
- `security.system.out_of_scope_path_block`：对**白名单外的路径**（逐次确认；递归删除直接拒绝）是否检测拦截；关闭＝不再逐次确认（递归删除等硬拦不受影响）。
- `security.system.shell_danger_block`：对 shell 危险命令是否检测；关闭＝不检测，直接通过。
- 中风险 shell 命令不单列系统组开关，统一由 1.2 的 `security.hitl.shell_path_confirm` 管辖（见 1.2 第 4 项说明）。

### 1.2 安全/HITL人工确认组（确认类：要不要问）

| # | 变量名 | 类型 | 默认 | 中文标签 |
|---|---|---|---|---|
| 1 | `security.hitl.write_confirm` | bool | true | 写操作确认 |
| 2 | `security.hitl.delete_confirm` | bool | true | 删除操作确认 |
| 3 | `security.hitl.dual_path_confirm` | bool | true | 双路径操作确认 |
| 4 | `security.hitl.shell_path_confirm` | bool | true | shell 命令确认 |

- `security.hitl.write_confirm`：对写工具的授权请求是否确认；关闭＝跳过确认，直接放行（危险写入硬拦不受影响）。
- `security.hitl.delete_confirm`：对删除工具的授权请求是否确认；关闭＝跳过确认，直接放行（递归删根集外目录的硬拦不受影响）。
- `security.hitl.dual_path_confirm`：对 copy/move 等双路径工具的授权请求是否确认；关闭＝跳过确认，直接放行。
- `security.hitl.shell_path_confirm`：对 shell 中风险命令与命令内路径授权是否确认；关闭＝跳过确认，直接放行（bash 危险命令硬拦不受影响）。

> 现有 `security.hitl.enabled`（人工确认总开关）保持不变，不在本次新增列表内；1.2 四项为在其之下细分的按线确认开关。

> 第 4 项管辖范围：中风险命令确认（`shell_command_risk`）+ 命令内路径权限确认（`shell_path_check`）。**bash 危险命令不受本项控制** —— 它是硬拦不是确认，由 `security.system.shell_danger_block` 单独管辖。
> 键名统一：本项全文（含 registry、2.0 表、正文）一律用 `security.hitl.shell_path_confirm`。

### 1.3 待定项

`classify_forbidden_path` 的 `non_system` 档实际含两类：代码目录自身及内部子级，**以及允许根集自身及其上级祖先**（`is_allowed_root_itself`，父级不拦）。1.1 的「禁区非系统目录拦截」只对得上第一类，第二类归属待定：单列第 5 个开关 / 并入禁区非系统目录拦截（键名与标签须改）/ 并入禁区系统目录拦截。

## 二、实现方法 — 后端代码的修改要点

### 2.0 读取点/使用点的总体原则（v1.6 审计 / v2.1 收敛到最早分支点）

三条铁律：

1. **确认类开关只在总闸 `check_before_execute` 入口读一次**，按"入口线"决定各确认产地是否抑制；深层各线模块**一律不读确认开关**。
   - 病根（改前散读）：`write_path_check.write_permission`（被直写/dual/shell 三线复用）、`delete_path_check.delete_permission/check_delete_risk`（同样三线复用）被塞入确认开关 → 同一操作被"本线开关 + dual/shell 开关"同时管，叠加污染、语义不可预期。上收到总闸单点即根治。
   - **读取最早、应用不早于产物**：开关在门首一次读（最早读取），但抑制只能在`blocked` 判完之后施加 —— 三线 `blocked` 硬拦无条件先判，把开关提到产物前会跳过硬拦 = 退化，禁止。
2. **拦截类开关留在唯一能区分子判据的地方**：`forbidden_system_path_block`/`forbidden_non_system_path_block` 必须在 `classify_forbidden_path` 各判据分支（`SafetyLevel` 只有一个统一标签 `path_forbidden`，总闸处无法区分"磁盘根/系统目录"与"代码目录/允许根自身"）；`shell_danger_block` 在 `check_shell_danger_command` 入口（两个调用方——safety_gate 与执行层 `execute_shell_command` 直调——的唯一公共点）。
3. **总闸 `system.enabled` 折入唯一读取原子 `safety_switch`**（v2.1）：任何开关经 `safety_switch` 读取，总闸关闭即返回 `False`。这样每个判据在**自己入口**（最早点）即 honor，且执行层直调（不经 `check_before_execute`，如 `execute_shell_command` 直调 `check_shell_danger_command`、`delete_file` 直调 `guard_forbidden_delete`）一并生效，无需逐处补读（DRY）。

关闭语义：
- 拦截类关闭 = **跳过该判据**（不硬拦、不转确认）；若该路径还被其它**启用**的判据命中则照常拦，全不命中才放行。
- 确认类关闭 = 该线本轮确认**全部抑制**（`needs_confirm=False`，直接放行）；`blocked` 硬拦不受影响。

#### 2.1.2 `safety_switch.py`（新建）—— 公用读取原子

**病根**：v1.5 之前各模块各造私有 `_block_on` / `_confirm_on`（≥5 份同逻辑副本），违反公用函数规范（DRY）。

**改后**（安全层唯一读取原子）：

```python
def safety_switch(key: str, default: bool = True) -> bool:
    """安全开关读取原子(唯一) — 缺键 / 读异常一律按 default(开, fail-closed)。
    总闸 security.system.enabled 关闭 → 一律返回 False(整个安全层放行);
    各线一律复用本函数, 不再各造 _block_on / _confirm_on 私有副本(DRY)。"""
    try:
        from app.config import get_config
        _cfg = get_config()
        if not bool(_cfg.get("security.system.enabled", True)):
            return False
        return bool(_cfg.get(key, default))
    except Exception:
        return default
```

**要点**
- **总闸折入此处**：任何经 `safety_switch` 读取的开关，总闸关闭即返回 False —— 执行层直调（不经 `check_before_execute`）读取的开关也随总闸关闭而放行，无需逐处补读（v2.1）
- `get_config()` 内部带 mtime 缓存，循环内反复调用不读盘，无性能问题
- fail-safe 默认"开"：读不到配置时按"该检测/确认生效"处理，不因读配置失败而放行

**改后**（门首总闸 → 入口一次读四开关 → 各产地按结果自带的 `auth_line` 盖章）：

```python
def check_before_execute(self, tool_name, params=None, pool_pids=None) -> SafetyResult:
    # 总闸: security.system.enabled 关闭即整个安全层放行
    if not safety_switch("security.system.enabled"):
        return SafetyResult.pass_result()
    _bypass = _is_hitl_bypass()
    # 确认类开关唯一读取点: 入口读一次, 各确认产地按结果自带的 auth_line 盖章
    _cfm = {
        "write":  safety_switch("security.hitl.write_confirm"),
        "delete": safety_switch("security.hitl.delete_confirm"),
        "dual":   safety_switch("security.hitl.dual_path_confirm"),
        "shell":  safety_switch("security.hitl.shell_path_confirm"),
    }
    _oos = safety_switch("security.system.out_of_scope_path_block")   # 白名单外确认开关(系统组)
    _OOS_LEVELS = (SafetyLevel.WRITE_OUT_OF_SCOPE, SafetyLevel.DELETE_OUT_OF_SCOPE)
    ...
    # [4-1] 中风险(仅 bash 线): 该线确认关闭 → 不产出, 继续走路径判定
    if _medium is not None and _cfm["shell"]:
        _medium.sandbox_required = True
        _medium.auto_confirm = _bypass
        return _medium
    ...
    # [4-2] 权限三线: blocked 原样返回(硬拦不受确认开关影响); needs_confirm 授权请求按本线开关收敛
    known_risk = self._check_known_risks(tool_name, params or {})
    if known_risk is not None:
        if known_risk.blocked:
            return known_risk
        # 线身份取自结果自带的 auth_line(由产物线置位), 不在门首按工具名重推
        if not _cfm.get(known_risk.auth_line, True):
            return SafetyResult.pass_result()
        # 白名单外确认关闭 → 直接放行(递归删除等拒执是 blocked, 已在上方返回)
        if known_risk.safety_level in _OOS_LEVELS and not _oos:
            return SafetyResult.pass_result()
        known_risk.auto_confirm = _bypass
        known_risk.sandbox_required = known_risk.needs_confirm
        return known_risk
    ...
    # 尾部工具级确认(无路径线, auth_line 为空): 不受线开关管, 仅 hitl.enabled 管
    needs_confirm, _shell_msg = self._get_needs_confirmation(tool_meta, params or {})
    return SafetyResult(needs_confirm=needs_confirm, blocked=False,
                        message=_shell_msg or "",
                        auto_confirm=needs_confirm and _bypass,
                        safety_level=confirm_level_for(tool_name, params) if needs_confirm else "",
                        sandbox_required=needs_confirm)
```

**要点**
- 总闸只在**安全层总入口**短路一次；四确认开关 + 白名单外开关也只在**这里**读一次 —— 不在每个判定点各判一次（避免 N 处开关判 N 次、且改漏）
- 门首总闸短路覆盖 **agent 路径**（`check_before_execute` 的唯一调用方是 `safety_gate`）；**执行层直调**由 `safety_switch` 折入的总闸覆盖（见 2.1.2），两条路径都随 `system.enabled` 关闭而放行
- 线身份**不在门首按工具名重推**：三线产物各自置 `auth_line`（write/delete/dual），shell 通道置 `shell`，门首 `_cfm.get(auth_line, True)` 直接消费；`bash` 线的中风险走 `_cfm["shell"]`（命令层，非路径线）
- 白名单外开关（`security.system.out_of_scope_path_block`，系统组）：仅对 `safety_level` 属 `_OOS_LEVELS` 的授权请求生效，关闭即放行；递归删除的拒执是 `blocked`，不受本项影响
- 中风险产地：`shell` 线确认关闭时**不 return**，继续走路径判定（路径判定同受 `shell` 开关抑制）；若路径另有 `blocked` 硬拦照常返回
- `known_risk` 产地：`blocked` 硬拦不受开关影响；仅 `needs_confirm` 授权请求在开关关闭时收敛为 `pass_result()`
- 尾部：`execute_sql`/`registry_*` 等无路径线的工具 `auth_line` 为空 → `_cfm.get("", True)=True`，行为与今日一致（仅受 `hitl.enabled` 管）
- 关闭时返回 `pass_result()`（`blocked=False, needs_confirm=False`，**不带 safety_level**），与「放行无分类」口径一致

#### 2.1.4 `path_classify_category.py` —— 服务 `security.system.forbidden_system_path_block` 与 `security.system.forbidden_non_system_path_block`

**改前**（`classify_forbidden_path`，磁盘根 / 系统禁区 / 系统保护目录 / 代码目录 四处直接 `return`）：

```python
if is_disk_root(file_path):
    return "system", f"禁止访问磁盘根目录: {file_path}"
...
if is_code_root_path(file_path):
    return "non_system", f"路径位于代码目录(含其内部子级): {file_path}"
```

**改后**（命中禁用判据 = 跳过该判据；若其它启用判据仍命中则照常拦，全不命中才放行）：

```python
_disabled_hit = False   # 命中"已关闭"的判据标记

if is_disk_root(file_path):
    if safety_switch("security.system.forbidden_system_path_block"):
        return "system", f"禁止访问磁盘根目录: {file_path}"
    _disabled_hit = True

if os.name == 'nt':
    ...
    if is_system_protected_path(file_path, mode):
        if safety_switch("security.system.forbidden_system_path_block"):
            return "system", f"路径位于系统保护目录,禁止操作: {file_path}"
        _disabled_hit = True

if is_code_root_path(file_path):
    if safety_switch("security.system.forbidden_non_system_path_block"):
        return "non_system", f"路径位于代码目录(含其内部子级): {file_path}"
    _disabled_hit = True

...  # 其余启用判据照常 return

if _disabled_hit:
    return "allow", None   # 命中的判据被关闭 → 该路径直接放行(不再进白名单授权确认)
return None, None
```

三条线调用方（`write_path_check.validate_write` / `delete_path_check` / `read_path_check`）新增一档映射：

```python
category, msg = classify_forbidden_path(file_path, MODE)
if category == "allow":          # 命中已关闭的判据 → 直接放行
    return True, None, None
if category: ...
```

**要点**
- 开关挂在**各判据分支的 `return` 之前**，不是挂在 `classify_forbidden_path` 入口 —— 挂入口一刀切会把 `system` 与 `non_system` 一起关掉，两个独立开关就退化成一个
- `forbidden_system_path_block` 覆盖**三处**系统类判据：磁盘根、系统禁区敏感文件/目录、`is_system_protected_path`——三处一律「开关开→`return`；开关关→置 `_disabled_hit`」，即命中任一被关闭的系统判据都算放行候选（不得只处理磁盘根一处）
- `forbidden_non_system_path_block` 覆盖代码目录判据；**关闭后该路径直接放行**（新增 `"allow"` 类别，三线映射为放行）—— 不再降级为白名单授权确认
- `_disabled_hit` 保证"关闭判据"不误放行其它**启用**判据该拦的路径（其余判据仍先判、先拦）
- 配置读取异常时 `safety_switch` 按「开」处理，不因读不到配置而降级放行
- 两开关经 `safety_switch` 读取，**总闸 `system.enabled` 关闭时随之返回 False**（跟随总闸放行）—— 每个判据在自己入口即 honor，覆盖执行层直调（见 2.1.2）
- **删线硬拦必须同源**：`guard_forbidden_delete` 现直接自持同一批判据，会绕过这两开关；改其消费 `classify_forbidden_path`（见 2.1.7），开关才覆盖删线

#### 2.1.5 `shell_danger_command.py` —— 服务 `security.system.shell_danger_block`

**改前**（`check_shell_danger_command`，命中 HIGH 规则即返回 `blocked=True`）：

```python
def check_shell_danger_command(command: str, shell_type: str = "ps7") -> Optional[SafetyResult]:
    ...
    for pattern_str, desc, level, st_tag in SHELL_DANGER_PATTERNS:

```

**改后**：

```python
def check_shell_danger_command(command: str, shell_type: str = "ps7") -> Optional[SafetyResult]:
    if not safety_switch("security.system.shell_danger_block"):
        return None          # ← 关闭拦截: 直接不进规则循环, 按「未命中」返回
    ...
```

**要点**
- 关闭时在**函数入口**返回 `None`，不进入规则循环 —— 该函数契约就是「`None` = 未命中」，返回 `None` 才能让调用方落到 `check_shell_risk_command`（中风险，由 `security.hitl.shell_path_confirm` 管）与路径判定（各自开关管）
- 本开关属**系统组（硬拦）**，与 `security.hitl.shell_path_confirm`（确认类）是两件事，互不影响：关掉本项只是不再拒绝 HIGH 命中，中风险确认仍照常弹窗
- 经 `safety_switch` 读取，**总闸 `system.enabled` 关闭时随之返回 False**；此处函数入口是 safety_gate 与执行层直调（`execute_shell_command` 直调本函数）的**唯一公共点**，故为最早且全覆盖的挂点

#### 2.1.6 `safety_result.py` + 三线/shell 通道产物 —— 线身份随结果传递（`auth_line`）

**改后**（`SafetyResult` 增一个字段）：

```python
@dataclass
class SafetyResult:
    ...
    auth_line: str = ""   # 确认产物的入口线: "write" / "delete" / "dual" / "shell"; 空 = 无路径线
```

四个确认产物口置位：

```python
# write_path_check.check_write_permission:       确认产物置 auth_line="write"
# delete_path_check.check_delete_permission:     确认产物置 auth_line="delete"
# dual_path_check.check_dual_permission:         确认产物置 auth_line="dual"
# shell_path_check.check_shell_permission:       确认产物置 auth_line="shell"
```

**要点**
- 线身份由**产物自己**给出（它本就是按线分派出来的），门首 `_cfm.get(auth_line, True)` 直接消费 —— 不再"门首按工具名重推 + 路由按集合分派"两份真相
- **shell 通道必须在 shell 层置线（v2.1）**：`shell_path_check` 的确认产物内部走 `write_permission`/`delete_permission`（**非**工具级 `check_*_permission`），若不置线会被标成 write/delete，`shell_path_confirm` 永远管不到、反被 write/delete 开关误管。故其确认产物在 shell 通道（最早能确定"这是 shell"的分支）统一置 `auth_line="shell"`
- 只置字段、不读开关：深层模块"只产确认事实"的单一职责不变

#### 2.1.7 `delete_path_check.py` —— 删线判据改单一源（两开关才覆盖删线）

**改前**：`guard_forbidden_delete` 直接调 `is_system_protected_path` / `is_disk_root` / `is_code_root_path` / `is_allowed_root_itself`，与 `classify_forbidden_path` **各持一份同款判据**。

**改后**：`guard_forbidden_delete` 改消费 `classify_forbidden_path` 的 `category`（`system` / `non_system` / `allow` / `None`），判据只此一份。

**要点**
