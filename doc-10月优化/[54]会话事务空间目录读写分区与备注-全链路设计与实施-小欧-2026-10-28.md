## 一、需求定义

### 1.1 总览：三个能力，一个面板

本次改造为会话事务空间面板带来三个核心能力：

| 能力 | 现状 | 改造后 |
|---|---|---|
| **新增目录** | ✅ 有（仅 path） | ✅ 增强（path + role + memo 三字段同时填） |
| **删除目录** | ✅ 有 | ✅ 不变 |
| **编辑目录** | ❌ 无 | ✅ **新增**：行内编辑，支持改 path、role、memo 三个字段 |

> 当前面板只有"输入框 + 添加按钮"和"每行一个删除按钮"。用户添加目录后想改 role 或 memo，只能删掉重新加。本次改造让每条目录支持原地编辑——点编辑按钮后该行切换为输入态，三字段全可改，保存即回写。

### 1.2 为什么是 role + memo 两个字段

| 字段 | 定位 | 解决什么 | 是否注入 prompt |
|---|---|---|---|
| **role** | 读写分区引导（结构化的三档语义） | 让 LLM 快速判断"这目录是拿来读的、拿来写的、还是主战场" | ✅ 注入为 `[读取工作区]/[读写工作区]/[写工作区]` 标注 |
| **memo** | 自由文本备注（非结构化的补充说明） | 表达 role 三档无法覆盖的具体信息，如"后端源码，别碰 legacy 目录"、"报告按 YYYYMMDD 命名" | ✅ 注入为行尾备注 |

**两者互补不重叠**：
- role 是**枚举化的粗粒度分类**（可快速筛选/着色/统计）
- memo 是**自由文本的细粒度补充**（role 装不下的具体约束、命名规约、注意事项）

> **为什么不用 alias**：alias 只是"短名标识"，与 role 承担的"读写语义"重叠 80%，且不携带任何可供 LLM 行动的信息。role + memo 组合的信息密度显著高于 alias，且直接作用于 prompt → LLM 行为，价值闭环完整。

### 1.3 role 的本质：引导标注，不是权限约束

**关键前提（必须在实现中守住）**：

- 本系统**没有"只读区域"设置** —— 路径是否可写一律由安全矩阵（`write_path_check` / `path_dir_lists` / `delete_path_check`）与确认层统一裁决
- role 是**纯 prompt 引导词**，让 LLM 自己理解"这个目录大概干嘛的"
- role **不影响**：安全判定、快照白名单、禁区判定、读写权限
- 即使 role=读取工作区 的目录，LLM 若发起写操作，安全矩阵照样按规则裁决（该放行就放行，该拦就拦）
- role 的效力边界：**只在 LLM 的语义理解层**，不在执行层

### 1.4 三档预设 + 自由输入

| role 预设值 | 语义 | LLM 行为引导 | badge 颜色 |
|---|---|---|---|
| **读取工作区** | 主要用来查阅参考 | 此目录以读取为主，写操作需谨慎 | 绿 |
| **读写工作区**（默认） | 默认可读写工作区 | 正常工作目录，按任务需要读写 | 蓝 |
| **写工作区** | 产物/报告输出目标 | 产物、报告、中间文件**优先**写这里 | 橙 |
| 自定义值 | 用户自由输入（如"构建产物"/"日志区"/"源码查阅"） | 按值本身的字面语义理解 | 灰 |

**role 为 TEXT 非 ENUM**：允许自由输入，识别不了的走灰色 badge + 默认引导，不报错不拦截。

### 1.5 自定义 role 值跨会话共享（localStorage）

用户在面板里自定义输入过的新 role 值（不在三档预设内），通过浏览器 `localStorage` 持久化，后续所有会话的 AutoComplete 下拉都能看到，避免重复手打。新增和编辑时都会触发持久化。

| 项 | 设计 | 理由 |
|---|---|---|
| 存储位置 | `localStorage["ws_custom_roles"]` = JSON 数组 | 浏览器本地，零后端改动 |
| 存储时机 | `addEntry` / `saveEdit` 时，若 role 值不在三档预设内，自动追加 | 无感知，用户不需要额外操作 |
| 去重 | 加入前检查数组中是否已有该值 | 避免重复项 |
| 上限 | 最多保留 16 条自定义值 | 防无限膨胀；超出按 FIFO 淘汰最旧的 |
| 跨会话 | ✅ 同浏览器所有会话共享 | 这是"个人习惯标签"，非团队规范 |
| 跨机器 | ❌ 不同浏览器/机器不共享 | YAGNI —— 没有多机器同步需求 |

**实现**（前端 ~15 行，仅 `SessionWorkspacePanel.tsx` 内）：

```typescript
const WS_ROLE_PRESETS = ['读取工作区', '读写工作区', '写工作区'];
const CUSTOM_ROLES_KEY = 'ws_custom_roles';
const MAX_CUSTOM_ROLES = 16;

function loadCustomRoles(): string[] {
  try {
    const raw = localStorage.getItem(CUSTOM_ROLES_KEY);
    return raw ? JSON.parse(raw) : [];
  } catch { return []; }
}

function saveCustomRole(role: string): void {
  if (WS_ROLE_PRESETS.includes(role)) return;   // 预设值不存
  const list = loadCustomRoles();
  if (list.includes(role)) return;               // 已有不存
  list.push(role);
  if (list.length > MAX_CUSTOM_ROLES) list.shift();   // FIFO 淘汰
  try { localStorage.setItem(CUSTOM_ROLES_KEY, JSON.stringify(list)); } catch {}
}
```

AutoComplete 的 options 合并预设 + 自定义：

```typescript
const roleOptions = useMemo(() => {
  const customs = loadCustomRoles();
  return [...WS_ROLE_PRESETS, ...customs]
    .filter((v, i, arr) => arr.indexOf(v) === i)   // 去重
    .map(v => ({ value: v }));
}, []);
```

### 1.6 memo 设计约束

| 项 | 取值 | 理由 |
|---|---|---|
| 类型 | `TEXT DEFAULT NULL` | 可选字段，NULL = 无备注 |
| 最大长度 | 256 字符 | 足够写一两句具体约束；防长串污染 prompt |
| 是否必填 | 否 | 不破坏现有流程；YAGNI |
| 是否唯一 | 否 | 备注内容可重复 |
| 换行 | 不允许 | 单行注入，避免破坏 prompt 行结构（前端换行符 → 空格） |
| 参与安全判定 | **否** | 纯 prompt 文本，不做任何路径校验 |

### 1.7 行内编辑设计

面板的每条目录行支持"展示态 ↔ 编辑态"切换，三字段（path、role、memo）全可改。

| 项 | 设计 | 理由 |
|---|---|---|
| 触发方式 | 展示态行内 ✏️ 编辑按钮 | 与 🗑 删除按钮并排，操作入口一致 |
| 编辑范围 | path + role + memo 三个字段全可改 | 用户可能填错路径、想换分区、想补备注 |
| path 可改的原理 | PATCH 写库是 DELETE 全删 → INSERT 全量，改 path = 改数组元素，不存在 UNIQUE 冲突 | 不需要单独的 UPDATE 某行 |
| 同一时间只编辑一行 | `editingIndex` 单值，点新行编辑自动退出旧行 | 避免多行同时编辑的 state 混乱 |
| 编辑不立即 PATCH | 改的是本地 `entries` state，点"确定"才统一提交 | 与 add/delete 一致（都是改 state → 确定时一次性 PATCH） |
| 编辑保存时校验 path | `isAbsolute` 检查，与 addEntry 同校验规则 | 保证数据一致 |
| role AutoComplete 复用 | 编辑态和新增区共享 `roleOptions` | DRY |
| 自定义 role 持久化 | `saveEdit` 里调 `saveCustomRole(r)` | 与 addEntry 同逻辑 |
| 回车保存 | path Input 和 memo Input 都绑 `onPressEnter={saveEdit}` | 快捷操作 |
| 取消编辑 | 点"取消"按钮丢弃修改回到展示态 | 不影响 state |

**改动 1 — `get_session_workspaces`（L54）**：SELECT 加两列

```python
def get_session_workspaces(conn, session_id: str) -> list:
    """读该会话使用的全部目录行（含 role/memo）。ORDER BY rowid = 加入顺序。"""
    return conn.execute(
        "SELECT path, role, memo FROM chat_session_workspaces "
        "WHERE session_id = ? ORDER BY rowid",
        (session_id,),
    ).fetchall()
```

**改动 2 — 新增 `_normalize_ws_meta`（role/memo 归一化单一真源）**

```python
def _normalize_ws_meta(role, memo) -> tuple[str, Optional[str]]:
    """role/memo 归一化唯一源：trim → 空归默认 → 超长截断 → memo 换行转空格。

    role 是引导标注不是权限开关，故非法值一律**放行**（不 reject），
    只做长度与空白处理 —— 拒单会让整条 PATCH 失败，代价远大于收益。
    memo 禁换行：注入时按行拼接，换行会破坏 <会话工作目录> 块结构。"""
    _r = (role or "").strip()[:MAX_ROLE_CHARS] or DEFAULT_ROLE
    _m = (memo or "").strip().replace("\r", " ").replace("\n", " ")[:MAX_MEMO_CHARS]
    return _r, (_m or None)
```

**改动 3 — `_ws_apply`（L113）**：入参改为 `(path, role, memo)` 三元组

```python
def _ws_apply(conn, session_id: str, entries: list[tuple[str, str, Optional[str]]]) -> None:
    """覆盖写 —— PATCH 的唯一写库实现（懒建占行不走这里）。
    DELETE 全删 → executemany INSERT(path, role, memo)。
    全删全插天然支持编辑：前端改了某条 path/role/memo 后整批提交，
    后端不需要区分"新增/修改/删除"——全量覆盖即可。"""
    conn.execute("DELETE FROM chat_session_workspaces WHERE session_id = ?", (session_id,))
    if not entries:
        return
    conn.executemany(
        "INSERT INTO chat_session_workspaces(session_id, path, role, memo) VALUES (?, ?, ?, ?)",
        [(session_id, p, r, m) for p, r, m in entries])
```

**改动 4 — `set_session_workspaces`（L124）**：入参兼容 `list[str]` / `list[dict]`

```python
def set_session_workspaces(conn, session_id: str, raw_items) -> list[dict]:
    """PATCH 唯一写入口：数量先拦 → 归一化 → 去重 → 预检 → 写库。
    返回被拒清单；非空即调用方返 422，空即 200。

    入参兼容两形态（旧前端/脚本不炸）：
      list[str]  → 视为 (path, 默认role, 无memo)
      list[dict] → {"path": ..., "role": ..., "memo": ...}
    role/memo **不参与预检**（不是路径，与安全判定无关）。
    前端编辑（改 path/role/memo）后整批提交，本函数不区分新增/编辑——全量覆盖。"""
    # 兼容旧形态
    if raw_items and isinstance(raw_items[0], str):
        raw_items = [{"path": p} for p in raw_items]
    if len(raw_items) > MAX_WORKSPACES:
        return [{"path": f"({len(raw_items)} 条)", "reason": f"目录数超上限({MAX_WORKSPACES})"}]

    entries, rejected, _seen = [], [], set()
    for it in raw_items:
        _p = it.get("path", "")
        try:
            _n = _normalize_ws_path(_p)
        except (OSError, ValueError) as _e:
            rejected.append({"path": _p, "reason": f"路径非法: {type(_e).__name__}: {_e}"})
            continue
        _k = _n.casefold()
        if _k in _seen:                      # 去重(大小写不敏感)，存值保大小写
            continue
        _seen.add(_k)
        _role, _memo = _normalize_ws_meta(it.get("role"), it.get("memo"))
        entries.append((_n, _role, _memo))
    if rejected:
        return rejected                      # 归一化失败即整单 422，不再写库

    rejected = _ws_precheck([p for p, _r, _m in entries])
    if rejected:
        return rejected

    _ws_apply(conn, session_id, entries)
    logger.info(f"[workspace] 会话使用目录已更新: session={session_id} 数量={len(entries)}")
    return []
```

**改动 5 — `classify_workspace_rows`（L157）**：返回值升级为三元组列表

```python
def classify_workspace_rows(rows) -> tuple[list, list]:
    """行 → (有效条目集, 不可用清单)：**会话目录过滤唯一真源**。

    返回值变更：effective 由 list[str] 升级为 list[tuple[str, str, Optional[str]]]
    = [(path, role, memo)]。role/memo 只**透传**，不参与任何裁决 ——
    归一化/禁区/宽根/存在性判定全部只看 path，安全语义零变化。"""
    effective, unusable = [], []
    for r in rows:
        try:
            p = _normalize_ws_path(r["path"])
        except (OSError, ValueError) as _e:
            unusable.append({"path": r["path"], "reason": f"路径非法({type(_e).__name__})",
                             "kind": "illegal"})
            continue
        reason = _ws_deny_reason(p)          # 禁区判定先行，全套判据
        if reason:
            unusable.append({"path": p, "reason": reason, "kind": "denied"})
            continue
        if not Path(p).is_dir():             # 必须是目录：不存在/是文件都不收
            unusable.append({"path": p, "reason": "不是目录或不存在", "kind": "missing"})
            continue
        _role, _memo = _normalize_ws_meta(r["role"] if "role" in r.keys() else None,
                                          r["memo"] if "memo" in r.keys() else None)
        effective.append((p, _role, _memo))
    return effective, unusable
```

> **注意 `r["role"]` 安全取值**：`_ensure_column` 补列后老库 Row 对象自动含 role/memo 列；但 classify 也可能被其他来源的 rows 调用，故用 `r.keys()` 检查列存在性，缺失时走默认值。

```typescript
const WS_ROLE_PRESETS = ['读取工作区', '读写工作区', '写工作区'] as const;

/** 自定义 role localStorage 管理（新增和编辑共用） */
const CUSTOM_ROLES_KEY = 'ws_custom_roles';
const MAX_CUSTOM_ROLES = 16;

function loadCustomRoles(): string[] {
  try {
    const raw = localStorage.getItem(CUSTOM_ROLES_KEY);
    return raw ? JSON.parse(raw) : [];
  } catch { return []; }
}

function saveCustomRole(role: string): void {
  if (WS_ROLE_PRESETS.includes(role as any)) return;   // 预设值不存
  const list = loadCustomRoles();
  if (list.includes(role)) return;                       // 已有不存
  list.push(role);
  if (list.length > MAX_CUSTOM_ROLES) list.shift();      // FIFO 淘汰
  try { localStorage.setItem(CUSTOM_ROLES_KEY, JSON.stringify(list)); } catch {}
}
```

## 五、数据库迁移策略

**使用现有 `_ensure_column` 机制**（幂等，老库安全）：

```python
# db_initializer.py 迁移区追加两条
_ensure_column(conn, "chat_session_workspaces", "role", "TEXT DEFAULT '读写工作区'")
_ensure_column(conn, "chat_session_workspaces", "memo", "TEXT DEFAULT NULL")
```

| 场景 | 结果 |
|---|---|
| **老库** | role 列自动填 `'读写工作区'`，memo 列 `NULL` → 旧行行为与现状完全一致 |
| **新库** | 建表语句直接含两列，默认值同上 |
| **UNIQUE** | `UNIQUE(session_id, path)` 不变，role/memo 允许任意重复 |
| **回滚** | 两列均有默认值/NULL，删列不丢业务数据（只丢标注） |
| **性能** | 每行多两列短文本，64 行上限下可忽略 |

## 七、风险与注意事项

| # | 风险 | 处置 |
|---|---|---|
| 1 | **旧前端 + 新后端** | `set_session_workspaces` 兼容 `list[str]`（自动补 `role='读写工作区', memo=None`）→ 不炸 |
| 2 | **新前端 + 旧后端** | 前端多传 role/memo，旧后端 Pydantic `list[str]` 对 dict 元素校验失败 → **必须先后端后前端上线**（同一版本内一起发） |
| 3 | **role 被误当权限** | prompt 首行明示"引导参考，不改变可写性判定"；文档与代码注释双处说明；安全矩阵零改动 |
| 4 | **role/memo 污染安全判定** | `all_paths` 只由 `e.path` 构成；`_ws_deny_reason` 等判据不接收 role/memo → 结构上不可能污染 |
| 5 | **memo 换行破坏 prompt 行结构** | `_normalize_ws_meta` 统一把 `\r\n` 转空格；前端 Input 本身单行 |
| 6 | **超长 memo 撑爆 prompt** | 后端截断 256 + 前端 `maxLength={256}` 双保险 |
| 7 | **role 自由输入乱填** | 不校验不拒单（拒单代价 > 收益），非预设值走灰色 badge，LLM 按字面理解 |
| 8 | **自定义 role localStorage 丢失** | 浏览器清缓存/换机器会丢失自定义 role 列表。**但库里的 role 值不丢**（存在 DB），只是 AutoComplete 下拉不再提示 → 用户重新输入即可 |
| 9 | **`_drop_nested` 丢子目录标注** | 父目录在快照里时子目录被去嵌套 → 子目录 role/memo 不进 prompt。**面板读库直显不受影响**（面板不走快照），仅 prompt 展示不全；如需保留可在 build 前按 role 分组，但属过度设计（YAGNI），先按现状 |
| 10 | **UNIQUE 约束** | 仍 `UNIQUE(session_id, path)`，role/memo 不参与 → 同路径只有一行，改 role/memo 走覆盖写 |
| 11 | **classify 返回值类型变更** | `effective` 从 `list[str]` → `list[tuple,str,Optional[str]]]`，调用方仅 `_load_workspaces_conn` 与 `reconcile` 两处，已同步改造；`_ws_precheck` 调用处已改为 `[p for p, _r, _m in entries]` |
| 12 | **classify 中 `r["role"]` 安全取值** | `_ensure_column` 补列后 Row 自动含新列；但 classify 可能被其他来源 rows 调用，故用 `r.keys()` 检查列存在性，缺失时走 `DEFAULT_ROLE` |
| 13 | **编辑 path 后与已有条目重复** | `saveEdit` 不做前端去重（与 addEntry 不同），因为后端 `set_session_workspaces` 的 casefold 去重会自动合并。但用户可能不感知合并 → 可选：`saveEdit` 前检查重复并提示。先按后端兜底（KISS），有反馈再加前端提示 |
| 14 | **编辑中途切换到另一行编辑** | `editingIndex` 单值，点新行 `startEdit` 自动覆盖旧值 → 旧行编辑内容丢失。设计如此（同时只编辑一行），与"取消 = 丢弃"语义一致 |
| 15 | **编辑 path 改成非法路径** | `saveEdit` 做 `isAbsolute` 校验，失败时 `setEditErr` 提示，不退出编辑态 → 用户可修正后重试 |

## 十、三堂会审自检（设计阶段）

### 10.1 合规检查（10 大规范）

| 规范 | 自检 |
|---|---|
| **SRP** | `_normalize_ws_meta` 只管 role/memo 归一化；`_ws_deny_reason` 只管准入判据；`loadCustomRoles`/`saveCustomRole` 只管 localStorage；`startEdit`/`saveEdit`/`cancelEdit` 只管编辑态切换；职责不混 |
| **DRY** | role/memo 归一化抽 `_normalize_ws_meta` 单一真源；localStorage 工具函数单一出口；`roleOptions` 新增区和编辑区共享；`saveCustomRole` 在 addEntry 和 saveEdit 两处复用 |
| **KISS-DIRECT** | 不做 role 枚举类、不做 registry、不做 validator 链；编辑态直接切分支渲染，不抽 EditableRow 组件（YAGNI——只有一个使用点）；localStorage 直接 JSON.stringify |
| **SLAP** | service 层不碰 prompt 拼接；orchestrator 不碰 DB 写库；localStorage 逻辑在组件内不外泄；编辑态逻辑在组件内不外泄 |
| **YAGNI** | 不做 role 国际化、不做 memo 富文本、不做跨机器同步、不做自定义 role 管理 UI、不抽 EditableRow 组件 |
| **禁止 backward** | ❗例外说明：`list[str]` 兼容是**跨版本接口兼容**（前端可能滞后部署），不是代码内部新旧逻辑并存 —— 属必要兼容层，非 backward 违规 |
| **OCP** | role 为 TEXT 而非 ENUM，新增自定义值零代码改动；localStorage 自定义列表动态扩展不改预设常量；编辑能力复用 PATCH 全量覆盖，不改后端接口 |
| **LSP** | `WorkspaceEntry` 新增字段有默认值，不破坏既有构造点 |
| **ISP** | `WorkspaceItem`（API）与 `WorkspaceEntry`（快照）职责分离，未合并 |
| **复用优先** | 复用既有 `_normalize_ws_path` / `_ws_precheck` / `classify_workspace_rows` / PATCH 全量覆盖，未重造；`roleOptions` / `saveCustomRole` 新增和编辑共用 |

### 10.2 合理检查

- **数据流单向**：DB → service → snapshot → prompt，无回环
- **编辑数据流单向**：`startEdit`（灌入 state）→ 用户改 → `saveEdit`（回写 entries）→ confirm → PATCH → DB，无回环
- **localStorage 数据流单向**：`addEntry`/`saveEdit` → `saveCustomRole` → localStorage → 下次渲染 `loadCustomRoles` → options，无回环
- **无透传层**：`_normalize_ws_meta` 有实质逻辑（trim + 默认 + 截断 + 换行处理），非纯透传
- **异常边界集中**：`_ws_deny_reason` 的 fail-closed 保持不动；role/memo 归一化不抛异常（截断兜底）；localStorage 全 try-catch（隐私模式/配额满不炸）；编辑 path 校验失败不退出编辑态（用户可修正）

### 10.3 关联检查（功能退化风险）

| 链路 | 是否退化 | 说明 |
|---|---|---|
| 安全判定（写/删/读三线） | ❌ 不退化 | `all_paths` 构造逻辑未动 |
| 禁区清理（reconcile） | ❌ 不退化 | 仍按 `u["path"]` 操作 |
| 缺目录自动建（reconcile） | ❌ 不退化 | 逻辑分支未动 |
| 默认目录创建 | ❌ 不退化 | 仅多传 `DEFAULT_ROLE`，路径生成不变 |
| 面板增删改 | ✅ 增强 | 从"增+删"升级为"增+删+改"三态完整 + role/memo 双字段 + 自定义 role 跨会话记忆 |
| 旧版前端调用 | ❌ 不退化 | `list[str]` 兼容层 |
| AutoComplete 选项 | ✅ 增强 | 原来无 AutoComplete，现在预设 + 自定义值 |
| PATCH 接口语义 | ❌ 不退化 | 仍是全量覆盖，编辑只是前端能力增强，后端零增量 |
