## 零、本篇的数据来源与口径

**先量后画**：所有表格均由探针脚本调用**生产函数**实测得出。**v2.0 的数据全部为订正后重测**，v1.x 基于 `is_default` 分档的结论已作废。

| 列 | 取自哪个生产函数 | 含义 |
|---|---|---|
| 禁区判据 | `path_safe_check._is_forbidden_path(p)` | 非空 category 即"永不使用" |

## 一、三层"域"速查（全文词汇表）

同一目录会同时出现在不同"域"里，各域成员不同、后果不同 —— 这是全文最容易看错的地方：

| 域 | 生产函数 | 成员 | 家目录在里面？ | 命中后能得到什么 |
|---|---|---|:--:|---|
| **写白名单** | `path_safe_check.get_default_allowed_paths()` | 家目录 + `\tmp` + `\var\tmp` + **项目根 + 配置授权目录 + 会话使用目录** | ✅ 在 | 写入免 `temp_auth` 弹窗 |
| **删除允许根** | `safety.delete_safety._get_allowed_roots()` | **项目根 + 配置授权目录 + 会话使用目录** | ❌ 不在 | 该根**内**的文件可删 |
| **根自身保护** | `file.delete_file._guard_forbidden_delete()` | 项目根 + 配置授权目录 + **会话使用目录（全部）** | ❌ 不在 | 这些根**本身及更上层**删不掉 |

> **v2.0 关键变化**：会话使用目录**不再分档**。系统自动建的与用户手动加的，**都**进删除允许根、**都**受根硬拦 —— 行为完全一致（v1.x 的 `is_default` 分档已删除）。

     │                  │    （改代码的地方，AI 永远不能写）            │

     │                  │  项目根（全局配置）                ✅ 可写    │  ← 工具工作区基准

## 三、裁决链（谁先说话）

```
一次写入请求
   │
   ├─① _is_forbidden_path ──────── 盘根/系统目录/代码库根 → 拒，永不使用
   ├─② 路径穿越检查 ────────────── 含 .. 或 realpath 跳出 → 拒
   ├─③ 系统保护目录 ────────────── C:\Windows\ / Program Files / ProgramData → 拒
   ├─④ 白名单匹配 ──────────────── 家目录 / 项目根 / 配置授权目录 / **会话使用目录**
   │                              → 命中即放行（并集，不是交集）
   └─⑤ 白名单外 ──────────────────→ temp_auth 临时授权弹窗
                                    ★ 会话目录 = 提前把⑤变成④，免掉弹窗

一次删除请求（额外的两套域，与写相互独立）
   ├─ _guard_forbidden_delete ── 盘根/系统目录/受保护根自身 → 硬拦
   └─ _get_allowed_roots ─────── 项目根 + 配置授权目录 + **会话使用目录** → 根内文件可删
```

**会话目录进入会话时的自检**（第三套，不在上面两套里）：

```
进入会话 → 取列表 → 空则造默认目录
  逐条: 存在 → 直接用
        落入禁区 → DELETE 该行（只删库，不删磁盘目录）
        不存在 → mkdir 建立
```

## 四、单个路径的裁决（v2.0 重测）

### 4.1 无会话目录时

| 候选路径 | 禁区判据 | 写入 | category | 在删除允许根 | 删根被硬拦 | 可作会话目录 |
|---|:--:|:--:|---|:--:|:--:|:--:|
| 盘根 `E:\` | ⛔拦 | ❌ | system | 否 | ⛔硬拦 | **否** |
| 用户目录 `C:\Users` | 过 | ❌ | system | 否 | ⛔硬拦 | **否**（宽根） |
| 家目录 `C:\Users\chend` | 过 | ✅ | – | 否 | ⛔硬拦 | **否**（宽根） |
| 代码库根 | ⛔拦 | ❌ | non_system | 否 | 过 | **否** |
| 项目根 | 过 | ✅ | – | ✅ | ⛔硬拦 | 是 |
| 系统目录 `C:\Windows` | ⛔拦 | ❌ | system | 否 | ⛔硬拦 | **否** |
| `C:\Program Files\App` | 过 | ❌ | **system** | 否 | ⛔硬拦 | **否**（靠第③闸） |

### 4.2 会话已有 2 个使用目录后（系统建的 + 用户加的）

| 候选路径 | 禁区判据 | 写入 | 在删除允许根 | 删根被硬拦 | 说明 |
|---|:--:|:--:|:--:|:--:|---|
| **会话目录（系统建）** | 过 | ✅ | ✅ | ⛔**硬拦** | 与用户加的**行为完全相同** |
| **会话目录（用户加）** | 过 | ✅ | ✅ | ⛔**硬拦** | 与系统建的**行为完全相同** |
| 家目录 | 过 | ✅ | 否 | ⛔**硬拦** | 授权它家下面的目录后，家目录自己也不能删 ← 宽根危害 |
| 项目根 | 过 | ✅ | ✅ | ⛔硬拦 | 未受影响（保护仍在） |

> **v2.0 与 v1.x 的差别**：v1.x 里"系统建的默认目录"不进根硬拦（可删），"用户加的"进。v2.0 **取消这个分档** —— 两者一律受硬拦，也一律进删除允许根。

**实测原始值（v2.0 重测）**：

```
全局白名单 = [家目录, \tmp, \var\tmp, 项目根, 会话目录A, 会话目录B]
删除允许根 = [项目根, 会话目录A, 会话目录B]     ← 家目录不在
两个会话目录 A/B：写入 PASS，在删除允许根 YES，删根硬拦 BLOCK  ← 完全一致
```

## 五、三个目录的组合关系（v2.0 结论不变，数据沿用 v1.1）

### 5.1 决策函数

```
写权限：
  if 命中禁区/路径穿越/系统保护目录        → 拒
  elif 命中【项目根 OR 配置授权目录 OR 会话目录】 → 放行   ★ 纯并集，无优先级
  else                                     → temp_auth 临时授权弹窗

删除权限：独立两域，不从写域推导
  允许根内文件可删 = 项目根 + 配置授权目录 + 会话目录
  根自身/更上层硬拦 = 上述三者（v2.0 不再按 is_default 分档）
```

### 5.2 8 种组合（项目根 / 配置授权目录 / 会话目录）

| # | 组合 | X 落在 | 写入 | 在删除允许根 |
|---|---|---|:--:|:--:|
| 1 | **三个都不在** | `E:\nowhere\x` | ❌ **拒** | 否 |
| 2 | 只在**项目根** | `E:\test_dir\x` | ✅ | 是 |
| 3 | 只在**配置授权目录** | `E:\auth_dir\x` | ✅ | 是 |
| 4 | 只在**会话目录** | `E:\ws_dir\x` | ✅ | 是 |
| 5 | 项目根 + 配置授权 | `E:\test_dir\x` | ✅ | 是 |
| 6 | 项目根 + 会话目录（嵌套） | `E:\test_dir\ws\x` | ✅ | 是 |
| 7 | 配置授权 + 会话目录（嵌套） | `E:\auth_dir\ws\x` | ✅ | 是 |
| 8 | **三者全含**（嵌套） | `E:\test_dir\ws\x` | ✅ | 是 |

### 5.3 从表中读出的三条结论

1. **组合之间在"写权限"上没有区别** —— 8 行里只有第 1 行被拒。三个目录**互不影响、不需要同时包含**，决策只问一句：*"X 是否在任意一个之下？"*
2. **"包含"是前缀包含，嵌套不叠加权限** —— 跨源父子（配置授权目录 vs 会话目录）会同时出现在白名单里，但写入结论与单根时完全相同；v2.1 同一快照内父子已归一（`_drop_nested`），只留顶层。
3. **白名单与删除根都不去重** —— 配置授权目录恰等于项目根时，`E:\test_dir` 会出现两次。功能无影响，属可优化项。

## 六、关系规则（v2.0 订正后）

| # | 规则 | 实测证据 |
|---|---|---|
| **1** | **并集，不是交集** —— 会话目录是"额外加的"，**从不收窄**任何东西 | §5.2：8 种组合里 7 种结论相同，只有"三个都不在"被拒 |
| **2** | **写域和删域是两套独立域** | 见 §一 速查表；会话目录：写=放行、删根=硬拦、删根内文件=可删，三个结论互不推导 |
| **3** | **~~默认目录 vs 手动目录分档~~ → v2.0 取消分档** | §4.2：系统建的与用户加的**行为完全相同**（`is_default` 已删除） |
| **4** | **项目根 ⊂ 全局白名单** | 默认会话目录若写在项目根下，**不带来任何新权限**；其价值是"按会话隔离产物" |
| **5** | **"包含"是前缀包含，嵌套不叠加权限** | §5.2 组合⑥⑦⑧ |
| **6** | **白名单与删除根：异源不去重，会话内嵌套归一** | §5.2 组合⑤⑧（配置授权目录恰等于项目根时仍出现两次，分属两源）；v2.1 快照 `build()` 加 `_drop_nested` —— 同一快照内父子只留顶层（前缀匹配下子项恒冗余），故组合⑥⑦⑧的会话目录侧不再堆叠 |
| **7** | **会话目录不是"授权目录"** | 授权目录归全局 config 管；会话目录只是**会话级的工作范围**，两者不纠缠 |

## 七、这张图暴露的 3 件事

1. **会话目录的真实价值是"按会话隔离产物"** —— 它躺在项目根下时，项目根本来就可写（§5.2 组合②佐证），**不带来新权限**；价值在于防止不同会话的产物混在一起。此点已登记在 `[16]`。

2. **会话使用目录的真正用武之地是"全局白名单之外的目录"** —— §5.2 组合③/④ 显示：配置授权目录与会话目录的作用完全对等，**区别只在于一个是全局长期、一个是会话级长期**。

3. **宽根（家目录）必须禁** —— 授权它会把删除允许范围放大到整个用户目录（§4.2 第 3 行：家目录自己都不能删），故 `workspace_service._is_broad_root` 拦住。
