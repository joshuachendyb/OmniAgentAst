## 一、用户三点决策（已拍板）

| # | 决策点 | 用户决策 | 影响 |
|---|---|---|---|
| 1 | 默认目录是否始终创建 | **始终创建**（无论是否先添加目录） | 解决"先添加目录则不建默认"的不一致缺陷 |

## 二、最终方案（方案 D：始终创建 + is_default 标志 + 项目根感知）

### 2.1 表结构变更

**`chat_session_workspaces` 表加列**（`db_initializer.py` **L224-230** 建表 + **L254** 幂等补列）：

```sql
is_default INTEGER DEFAULT 0   -- 是否本会话默认工作区（= 系统自动创建的隔离区），0=普通用户目录，1=默认
```

- **存量数据（2026-10-31 修订）**：老系统每个会话自动建一个默认目录 `<项目根>\<YYYYMMDD-HHMMSS>-<会话ID前4位>`，目录名**内嵌会话ID前4位** → `_backfill_ws_default_legacy` 据此精确识别并置 `is_default=1`（一次性门控，`db_initializer.py`）。未命中（纯用户目录 / 老目录已被系统外删除）保持 `is_default=0`，交首次 `reconcile` 按规则2 补建。
  > 原 v1-v3 定稿"全部置 0、首次 reconcile 补建"已撤销：那会给每个老会话再建一个新时间戳目录，把老默认目录降成普通行、历史产物被拆散（2026-10-31 北京老陈令）。
- **系统内部不可删默认条目（2026-10-31 新增）**：默认行在面板**不渲染删除按钮**；删除只能系统外（资源管理器）手动删目录，下次任务 `reconcile` 按规则2 重建。列表条目系统内不可删。
- **UNIQUE 约束**：保持 `UNIQUE(session_id, path)` 不变（is_default 不参与唯一键）
- **语义**：`is_default=1` 的行 = 本会话自动创建的默认隔离区，供其他应用识别；同一会话**至多一条** `is_default=1`（reconcile 保证）

> 注：`is_default` 是**业务标志**（识别默认工作区），**不参与安全判定**，与 role/memo 一样只做标注。安全矩阵零改动。

### 2.2 核心逻辑（`reconcile_session_workspaces` 重写）

```python
def reconcile_session_workspaces(conn, session_id: str) -> list[tuple[str, str, Optional[str], bool]]:
    """进入会话·建立一条规则（唯一真源）：默认工作区始终创建 → 逐条裁决 →
    禁区行清库 / 不存在则建目录 / 可用则留 → 返回有效条目集。

    v2 定稿逻辑（[54]改动7 / [55]方案D）：默认工作区始终存在（先添加目录也创建）；
    删除后下次重建；项目根改变后在新根重建。返回 [(path, role, memo, is_default)] 四元组。
    ⚠ 只删数据库行，**绝不删除磁盘目录**。"""
    rows = get_session_workspaces(conn, session_id)   # 现含 role/memo/is_default 列
    current_root = get_config().get_project_root()     # 当前配置的项目根

    # ── 判断是否需要创建/重建默认工作区 ──
    # 需要创建的条件（任一）：
    #   a) 会话无任何 is_default=1 的行（首次，或用户删除了默认目录）
    #   b) 默认目录不在当前项目根下（项目根改变了）
    need_new_default = True
    for r in rows:
        if r.get("is_default") and Path(r["path"]).parent == Path(current_root):
            need_new_default = False          # 默认工作区存在且在正确位置
            break

    if need_new_default:
        d = _build_default_workspace_dir(session_id)   # 读当前根，天然建在新根下
        if d:
            try:
                # 旧默认目录降为普通目录（保留历史产物，用户可自行处置）
                conn.execute(
                    "UPDATE chat_session_workspaces SET is_default=0 "
                    "WHERE session_id = ? AND is_default = 1", (session_id,))
                # 新默认工作区登记（role=读写工作区，memo=本会话事务空间默认读写区域，is_default=1）
                conn.execute(
                    "INSERT OR IGNORE INTO chat_session_workspaces(session_id, path, role, memo, is_default) "
                    "VALUES (?, ?, ?, ?, 1)",
                    (session_id, _normalize_ws_path(d), DEFAULT_ROLE, DEFAULT_MEMO))
            except Exception as _e:
                logger.warning(f"[chat] 默认目录登记失败（降级走项目根）: {_e}")
        rows = get_session_workspaces(conn, session_id)

    _effective, unusable = classify_workspace_rows(rows)
    for u in unusable:
        if u["kind"] != "denied":
            continue                             # 脏行/缺目录：本轮跳过，下次再看
        try:                                     # 禁区行：从表里清掉（只删库行）
            conn.execute(
                "DELETE FROM chat_session_workspaces WHERE session_id = ? AND path = ?",
                (session_id, u["path"]))
        except Exception as _de:                 # 订正：失败就只报失败，
            logger.warning(f"[chat] 禁区目录清理失败(本轮仍不放行): {u['path']} - {_de}")
            continue                             #   不再无条件打"已清理"
        logger.warning(f"[chat] 会话目录已落入禁区, 已从列表清理: {u['path']}")

    for u in unusable:                           # 缺目录：建出来（禁区/脏行不建）
        if u["kind"] != "missing":
            continue
        try:
            Path(u["path"]).mkdir(parents=True, exist_ok=True)
            logger.info(f"[chat] 会话目录不存在, 已自动建立: {u['path']}")
        except Exception as _e:
            logger.warning(f"[chat] 会话目录建立失败(本轮不生效, 下次再试): {u['path']} - {_e}")

    return _load_workspaces_conn(conn, session_id)   # 重读重判：刚建好的目录本轮即生效
```

### 2.3 行为矩阵（方案 D 全场景验证）

| 场景 | 行为 | 正确性 |
|---|---|---|
| 新会话，直接发任务 | 创建默认工作区（`is_default=1`） | ✅ 与现状一致 |
| 新会话，**先添加目录**再发任务 | **仍创建默认工作区**（与用户目录并存） | ✅ 解决不一致 |

| 项目根多次改变 | 每次变化在新根重建；旧默认目录逐次降为普通 | ✅ 历史不回溯 |
| 用户先添加目录 + 项目根改变 | 默认工作区仍在新根重建（用户目录不动） | ✅ |

### 2.5 其他应用如何消费 `is_default`

其他应用（如文件页"设为会话工作目录"、历史页 workspaceMap）读取 `is_default=1` 的行即可识别"本会话默认工作区"，无需再依赖路径模式猜测（如判断是否含时间戳前缀）。

```python
def get_session_default_workspace(conn, session_id: str) -> Optional[str]:
    """其他应用消费口：返回本会话默认工作区路径（is_default=1），无则 None。"""
    row = conn.execute(
        "SELECT path FROM chat_session_workspaces "
        "WHERE session_id = ? AND is_default = 1 LIMIT 1", (session_id,)).fetchone()
    return row["path"] if row else None
```

> **代码位置**：`workspace_service.py` **L293**（在 `session_exists` L292 之后追加，文件末尾）。

## 三、三堂会审自检（方案 D）

### 3.1 合规检查（10 大规范）

| 规范 | 自检 |
|---|---|
| **SRP** | `is_default` 只管"是否默认工作区"标志；`_build_default_workspace_dir` 只管路径生成；`reconcile` 只管编排；`get_session_default_workspace` 只管消费读取；职责不混 |
| **DRY** | 默认工作区创建收敛在 `reconcile` 一处；`_build_default_workspace_dir` 单一真源；`get_session_default_workspace` 单一消费口 |
| **KISS-DIRECT** | 不用物理搬目录迁移；`need_new_default` 布尔判断直线；`is_default` 单列够用；存量识别仅一处正则（目录名前缀），无目录扫描 |
| **SLAP** | `reconcile` 不碰 prompt 拼接；`get_session_default_workspace` 独立函数不内联 |
| **YAGNI** | 不做物理迁移（旧目录保留降级，不搬文件）；不做多默认工作区（同一会话至多一条 is_default=1）；不做 is_default 的复杂状态机 |
| **禁止 backward** | 存量老默认目录**识别置 1**（`_backfill_ws_default_legacy`，目录名前缀识别，一次性门控，行为兼容）；不删旧逻辑 |
| **OCP** | 项目根变化天然支持（`get_project_root` 读当前根）；新增消费口不破坏既有 |
| **LSP** | 无继承体系 |
| **ISP** | 无多实现 |
| **复用优先** | 复用既有 `_build_default_workspace_dir` / `_normalize_ws_path` / `classify_workspace_rows` / `INSERT OR IGNORE`，未重造 |

### 3.2 合理检查

- **行为一致性**：先添加目录与先发任务，最终都创建默认工作区（决策1）→ 消除不一致缺陷
- **删除可重建（系统外删目录）**：默认行对应目录在系统外被删（行仍在）→ `reconcile` `missing` 分支 mkdir 重建；默认行被删（仅 API 程序化）→ 下次 reconcile 判定"无默认"→ 重建（决策2）。**系统内部面板不提供删除入口**（2026-10-31 令）。规则2 因此有两条互斥触发路径：DB 行删除 ↔ 磁盘目录删除，分别由 reconcile 的不同分支处理，语义对称。
- **项目根感知**：`need_new_default` 比较 `Path(默认目录).parent == Path(当前根)`，项目根改变自动触发重建（决策3）
- **数据流单向**：`is_default` 0→1 单向（UPDATE 降级 / INSERT 置 1）；无回环
- **异常边界**：`_build_default_workspace_dir` 返回 None 时降级（不建默认，走用户目录）；UPDATE/INSERT 失败不阻断主流程（try-catch）

### 3.3 关联检查（功能退化风险）
