## 一、术语与概念统一

> **全系统（前后端代码、日志、注释、UI 文案、文档）一律按本章口径表述**，禁止再用历史名词。

### 1.1 三个概念的边界

| 概念 | 性质 | 定义 | 用法约定 |
|---|---|---|---|
| **会话（Session）** | 逻辑实体 | DB `chat_sessions` 里的一行记录：标题、历史消息、状态等元数据 | 只说"会话"，**绝不指目录** |
| **会话工作区（Session Workspace）** | 物理实体 | 该会话在文件系统上对应的事务落盘目录（一行 = 一个目录） | 日常表述、代码注释、UI 统一用简称"会话工作区" |
| **会话工作区目录（Session Workspace Directory）** | 物理实体（全称） | 同上的完整名称 | 仅用于架构图、DDL、严谨技术描述 |

### 1.2 历史名词替换清单（强制）

| 历史名词 | 处置 | 替代为 |
|---|---|---|
| **事务空间目录** | ❌ 废弃 | 会话工作区 |
| **工作区目录** | ❌ 废弃（本系统会话语境内） | 会话工作区 |
| **会话目录** | ❌ 废弃 | 会话工作区 |
| **会话事务空间**（UI 面板标题/输入框下方文案） | ❌ 废弃 | **事务工作区** |
| **事务工作区**（UI 文案） | ✅ 保留 | 与"会话工作区"**等义**；界面用"事务工作区"，技术层用"会话工作区" |
| **role**（字段名） | ❌ 废弃 | **workspace_property** |
| **读写分区**（字段语义描述） | ❌ 废弃 | **工作区属性** |

> **等义声明**：UI 上的「事务工作区」＝ 技术层的「会话工作区」，二者指同一实体，只是表述场景不同。UI 用短词更顺口，代码/日志用全称更严谨。

### 1.3 workspace_property 的本质：纯文字标签，不涉及任何权限

**关键前提（实现中必须守住）**：

- `workspace_property` 是**给人看、给 LLM 看的文字标签**，用于描述"这个目录大概是干什么的"
- 它**不参与、不影响**：安全判定（`write_path_check` / `path_dir_lists` / `delete_path_check`）、确认层、快照白名单、禁区判定、读写授权
- 本系统**没有"只读区域"设置** —— 路径是否可写一律由安全矩阵统一裁决
- 即使属性是 `read_only`（读取工作区）的目录，LLM 发起写操作时安全矩阵照样按规则裁决（该放行就放行，该拦就拦）
- 属性的效力边界：**只在 UI 展示层 + LLM 语义理解层**，不在执行层

> 因此 `workspace_property` 与 `is_default`、`memo` 三者**同属"标注类字段"**：只做展示与提示，不进入 `all_paths`，不参与任何安全链路。

## 二、需求定义

### 2.1 总览：四个能力，一个面板

| 能力 | 现状 | 改造后 |
|---|---|---|
| **新增目录** | ✅ 有（仅 path） | ✅ 增强（path + workspace_property + memo 三字段同时填） |
| **删除目录** | ✅ 有 | ✅ 不变 |
| **编辑目录** | ❌ 无 | ✅ **新增**：行内编辑，支持改 path、workspace_property、memo 三个字段 |
| **默认工作区** | ⚠️ 仅"无目录才创建"，先添加目录则不建 | ✅ **重构**：始终创建 + `is_default` 标志 + 项目根感知 + 删除后重建 |

> 当前面板只有"输入框 + 添加按钮"和"每行一个删除按钮"。用户添加目录后想改属性或备注，只能删掉重新加。本次改造让每条目录支持原地编辑——点编辑按钮后该行切换为输入态，三字段全可改，保存即回写。

### 2.2 为什么是 workspace_property + memo 两个字段

| 字段 | 定位 | 解决什么 | 是否注入 prompt |
|---|---|---|---|
| **workspace_property** | 工作区属性（结构化的三档语义 + 自定义） | 让 LLM 快速判断"这目录是拿来读的、拿来写的、还是主战场" | ✅ 注入为 `[读取工作区]`/`[读写工作区]`/`[写工作区]` 标签 |
| **memo** | 自由文本备注（非结构化的补充说明） | 表达属性三档无法覆盖的具体信息，如"后端源码，别碰 legacy 目录"、"报告按 YYYYMMDD 命名" | ✅ 注入为行尾备注 |

**两者互补不重叠**：

- workspace_property 是**枚举化的粗粒度分类**（可快速筛选/着色/统计）
- memo 是**自由文本的细粒度补充**（属性装不下的具体约束、命名规约、注意事项）

### 2.3 三档预设 + 自由输入

**存储采用"机器值 + 中文标签"双层**：库里存机器值（稳定、可换标签不迁数据），UI 与 prompt 用中文标签（人读、LLM 读）。

| 机器值（存库） | 中文标签（展示/注入） | 语义 | LLM 行为引导 | Tag 颜色 |
|---|---|---|---|---|
| `read_only` | **读取工作区** | 主要用来查阅参考 | 此目录以读取为主，写操作需谨慎 | 绿 |
| `read_write`（**默认**） | **读写工作区** | 默认可读写工作区 | 正常工作目录，按任务需要读写 | 蓝 |
| `write` | **写工作区** | 产物/报告输出目标 | 产物、报告、中间文件**优先**写这里 | 橙 |
| 自定义文本（原样存） | 同原文（如"构建产物"/"日志区"） | 用户自由输入 | 按值本身的字面语义理解 | 灰 |

**字段为 TEXT 非 ENUM**：允许自由输入，识别不了的走灰色 Tag + 默认引导，**不报错不拦截**（拒单代价远大于收益）。

### 2.4 兜底规则（唯一真源）

> 兜底规则：**`workspace_property` 缺失一律回落 `read_write`，展示「读写工作区」**。这只是文字标签，不涉及权限/授权。

| 场景 | 存储值 | 展示/注入标签 |
|---|---|---|
| 新建会话 / 新增目录未填属性 | `read_write` | 读写工作区 |
| 历史数据（列为 NULL / 空串 / 全空白） | `read_write` | 读写工作区 |
| 传入了中文标签（如 `读写工作区`） | 归一为 `read_write` | 读写工作区 |
| 传入了未知/非法值（如乱码、超长） | 原样保留（自定义语义） | 原样展示 |
| 列不存在（旧库未迁移 / 外部 rows） | `read_write` | 读写工作区 |

**归一化唯一入口**（入库：后端 `ws_prop_value` / 前端 `propValue`；展示：后端 `ws_prop_label` / 前端 `propLabel`），任何取属性的地方都必须走它，禁止直接读原始字段。

### 2.5 自定义属性值跨会话共享（localStorage）

用户在面板里自定义输入过的新属性值（不在三档预设内），通过浏览器 `localStorage` 持久化，后续所有会话的 AutoComplete 下拉都能看到，避免重复手打。新增和编辑时都会触发持久化。

| 项 | 设计 | 理由 |
|---|---|---|
| 存储位置 | `localStorage["ws_custom_props"]` = JSON 数组 | 浏览器本地，零后端改动 |
| 存储时机 | `addEntry` / `saveEdit` 时，若属性值不在三档预设内，自动追加 | 无感知，用户不需要额外操作 |
| 去重 | 加入前检查数组中是否已有该值 | 避免重复项 |
| 上限 | 最多保留 16 条自定义值 | 防无限膨胀；超出按 FIFO 淘汰最旧的 |
| 跨会话 | ✅ 同浏览器所有会话共享 | 这是"个人习惯标签"，非团队规范 |
| 跨机器 | ❌ 不同浏览器/机器不共享 | YAGNI —— 没有多机器同步需求 |

### 2.6 memo 设计约束

| 项 | 取值 | 理由 |
|---|---|---|
| 类型 | `TEXT DEFAULT NULL` | 可选字段，NULL = 无备注 |
| 最大长度 | 256 字符 | 足够写一两句具体约束；防长串污染 prompt |
| 是否必填 | 否 | 不破坏现有流程；YAGNI |
| 是否唯一 | 否 | 备注内容可重复 |
| 换行 | 不允许 | 单行注入，避免破坏 prompt 行结构（前端换行符 → 空格） |
| 参与安全判定 | **否** | 纯 prompt 文本，不做任何路径校验 |

### 2.7 行内编辑设计

面板的每条目录行支持"展示态 ↔ 编辑态"切换，三字段（path、workspace_property、memo）全可改。

| 项 | 设计 | 理由 |
|---|---|---|
| 触发方式 | 展示态行内 ✏️ 编辑按钮 | 与 🗑 删除按钮并排，操作入口一致 |
| 编辑范围 | path + workspace_property + memo 三个字段全可改 | 用户可能填错路径、想换属性、想补备注 |
| path 可改的原理 | PATCH 写库是 DELETE 全删 → INSERT 全量，改 path = 改数组元素，不存在 UNIQUE 冲突 | 不需要单独的 UPDATE 某行 |
| 同一时间只编辑一行 | `editingIndex` 单值，点新行编辑自动退出旧行 | 避免多行同时编辑的 state 混乱 |
| 编辑不立即 PATCH | 改的是本地 `entries` state，点"确定"才统一提交 | 与 add/delete 一致（都是改 state → 确定时一次性 PATCH） |
| 编辑保存时校验 path | `isAbsolute` 检查，与 addEntry 同校验规则 | 保证数据一致 |
| 属性 AutoComplete 复用 | 编辑态和新增区共享 `propOptions` | DRY |
| 自定义属性持久化 | `saveEdit` 里调 `saveCustomProp(p)` | 与 addEntry 同逻辑 |
| 回车保存 | path Input 和 memo Input 都绑 `onPressEnter={saveEdit}` | 快捷操作 |
| 取消编辑 | 点"取消"按钮丢弃修改回到展示态 | 不影响 state |

### 2.8 创建时机与默认工作区

#### 2.8.1 默认工作区的定位与三条硬规则

默认工作区（`is_default=1`）＝ 系统为本会话自动创建的隔离落盘区，语义是"本会话临时/中间文件的默认落点"。

| # | 规则 | 具体行为 |
|---|---|---|
| 1 | **始终创建** | 无论用户是否已先添加目录，默认工作区都必须存在（消除"先添加目录则不建默认"的不一致） |
| 2 | **删除后可重建** | 用户删掉默认工作区（DB 行或磁盘目录）后不防重建，下次建任务时重建；`is_default` 列标识"哪条是本会话默认工作区"，供其他应用识别，不靠路径模式猜测 |
| 3 | **跟随项目根** | 项目根改变后，老会话的新任务在新项目根下重建默认工作区；旧默认目录降为普通目录，历史产物保留不搬移 |

#### 2.8.2 创建时机

| 对象 | 创建时机 | 说明 |
|---|---|---|
| **默认工作区**（`is_default=1`） | **始终创建**：每次"创建新 Task 并绑定该会话"时由 `reconcile_session_workspaces` 确保存在 | 无则建、删则重建、项目根变则在新根重建 |
| **用户添加的目录行** | **懒加载**：不提前创建；同样在"创建新 Task 并绑定该会话"时才 `mkdir` | 避免纯浏览产生空目录 |
| **面板 GET（打开面板/切会话/看历史）** | **不创建任何目录** | 纯读 + 只做 `classify_workspace_rows` 判定，绝不落盘 |

**为什么触发点选"创建新 Task 并绑定该会话"**：

1. **语义最准** —— 会话工作区是"任务的事务落盘范围"，任务不创建就不需要它
2. **覆盖"删除后下次创建"** —— 用户删了磁盘目录，下次建任务时 `classify` 判为 `missing` → 立即重建，语义自然
3. **零冗余** —— 纯浏览、纯看历史、纯切会话都不会在磁盘上留下空目录
4. **与现有代码天然吻合** —— `_ensure_and_load_workspaces`（`stream_orchestrator.py` L354）就在任务启动路径上调用 `reconcile_session_workspaces`，无需新增触发点

**落地约束（实现必须守住）**：

- 创建目录的唯一位置 = `reconcile_session_workspaces`（`workspace_service.py` L211）。**禁止在其他地方新增 `mkdir`**
- `GET /sessions/{id}/workspaces`（`sessions.py` L133）**只调 `classify_workspace_rows`，不调 `reconcile`** —— 保持"面板只读不落盘"
- 幂等：`mkdir(parents=True, exist_ok=True)`，并发多请求同时建也不报错
- 可观测：登记默认工作区时打 `info` 日志（`session_id` / `path` / `is_default`）；清理与建目录沿用既有 `warning` / `info` 日志

#### 2.8.3 核心逻辑（`reconcile_session_workspaces` 重写）

```python
def reconcile_session_workspaces(conn, session_id: str) -> list[tuple[str, str, Optional[str], bool]]:
    """创建新 Task 并绑定该会话时的唯一落盘入口。

    默认工作区始终存在（先添加目录也建）→ 逐条裁决（禁区行清库 / 缺目录则建 / 可用则留）
    → 返回有效条目集。用户目录同样在此懒建（面板 GET 不建，只此处建）。
    返回 [(path, workspace_property, memo, is_default)] 四元组。

    ⚠ 只删数据库行，绝不删除磁盘目录。"""
    rows = get_session_workspaces(conn, session_id)      # 含 workspace_property/memo/is_default
    current_root = get_config().get_project_root()       # 当前配置的项目根

    # ── 默认工作区是否需创建/重建 ──
    # 需要（任一）：a) 无任何 is_default=1 行（首次，或用户删了默认行）
    #               b) 默认行不在当前项目根下（项目根变了）
    need_new_default = True
    for r in rows:
        if r["is_default"] and Path(r["path"]).parent == Path(current_root):
            need_new_default = False
            break

    if need_new_default:
        d = _build_default_workspace_dir(session_id)     # 读当前根，天然建在新根下
        if d:
            try:
                _p = _normalize_ws_path(d)
                # 先登记/升级新默认（同路径已存在则原地置 1），再降级其余默认行 ——
                # 顺序不可颠倒：先降后插一旦插入失败，会话将没有任何默认工作区
                conn.execute(
                    "INSERT INTO chat_session_workspaces"
                    "(session_id, path, workspace_property, memo, is_default) "
                    "VALUES (?, ?, ?, ?, 1) "
                    "ON CONFLICT(session_id, path) DO UPDATE SET "
                    "workspace_property = excluded.workspace_property, "
                    "memo = excluded.memo, is_default = 1",
                    (session_id, _p, DEFAULT_WS_PROP, DEFAULT_MEMO))
                # 旧默认目录降为普通目录（保留历史产物，用户可自行处置）
                conn.execute(
                    "UPDATE chat_session_workspaces SET is_default = 0 "
                    "WHERE session_id = ? AND is_default = 1 AND path <> ?",
                    (session_id, _p))
                logger.info(f"[chat] 默认工作区已就绪: session={session_id} path={_p}")
            except Exception as _e:
                logger.warning(f"[chat] 默认工作区登记失败（本轮无默认区，下次再试）: {_e}")
        rows = get_session_workspaces(conn, session_id)

    _, unusable = classify_workspace_rows(rows)
    for u in unusable:
        if u["kind"] != "denied":
            continue                                     # 脏行/缺目录：本轮跳过，下次再看
        try:                                             # 禁区行：从表里清掉（只删库行）
            conn.execute(
                "DELETE FROM chat_session_workspaces WHERE session_id = ? AND path = ?",
                (session_id, u["path"]))
        except Exception as _de:
            logger.warning(f"[chat] 禁区目录清理失败(本轮仍不放行): {u['path']} - {_de}")
            continue
        logger.warning(f"[chat] 会话工作区已落入禁区, 已从列表清理: {u['path']}")

    for u in unusable:                                   # 缺目录：建出来（禁区/脏行不建）
        if u["kind"] != "missing":
            continue
        try:
            Path(u["path"]).mkdir(parents=True, exist_ok=True)
            logger.info(f"[chat] 会话工作区目录不存在, 已自动建立: {u['path']}")
        except Exception as _e:
            logger.warning(f"[chat] 会话工作区目录建立失败(本轮不生效, 下次再试): {u['path']} - {_e}")

    return _load_workspaces_conn(conn, session_id)       # 重读重判：刚建好的目录本轮即生效
```

#### 2.8.4 行为矩阵（全场景验证）

| 场景 | 行为 | 正确性 |
|---|---|---|
| 新会话，直接发任务 | 建任务时创建默认工作区（`is_default=1`） | ✅ 与现状一致 |
| 新会话，**先添加目录**再发任务 | **仍创建默认工作区**（与用户目录并存） | ✅ 解决不一致 |
| 用户删除默认工作区（DB 行） | `is_default=1` 行没了 → 下次建任务**重建**（新时间戳） | ✅ 规则 2 |
| 用户删除默认工作区（磁盘目录） | `classify` 判 `missing` → 下次建任务**原地重建**（同路径） | ✅ 规则 2 |
| 用户删除用户目录（磁盘） | 同上，下次建任务原地重建 | ✅ 懒加载 |
| 项目根 `E:\test_dir` → `E:\new_root` | 检测默认目录不在新根下 → **在新根重建**（旧默认降为普通，历史产物保留） | ✅ 规则 3 |
| 项目根多次改变 | 每次变化在新根重建；旧默认逐次降为普通 | ✅ 历史不回溯 |
| 用户先添加目录 + 项目根改变 | 默认工作区仍在新根重建（用户目录不动） | ✅ |
| **打开面板 / 切会话 / 看历史** | **不创建任何目录**（GET 只读） | ✅ 懒加载 |

#### 2.8.5 其他应用如何消费 `is_default`

其他应用（如文件页"设为会话工作区"、历史页 workspaceMap）读取 `is_default=1` 的行即可识别"本会话默认工作区"，无需再依赖路径模式猜测（如判断是否含时间戳前缀）。

```python
def get_session_default_workspace(conn, session_id: str) -> Optional[str]:
    """其他应用消费口：返回本会话默认工作区路径（is_default=1），无则 None。"""
    row = conn.execute(
        "SELECT path FROM chat_session_workspaces "
        "WHERE session_id = ? AND is_default = 1 LIMIT 1", (session_id,)).fetchone()
    return row["path"] if row else None
```

```python
    """覆盖写 —— PATCH 的唯一写库实现（懒建占行不走这里）。

    DELETE 全删 → executemany INSERT(path, workspace_property, memo, is_default)。
    全删全插天然支持编辑：前端改了某条 path/属性/memo 后整批提交，
    后端不需要区分"新增/修改/删除"——全量覆盖即可。

    ⚠ is_default 由系统维护，前端 PATCH 无权携带：写库前先读旧默认行，
    覆盖时按 path（大小写不敏感）原样继承。否则用户每点一次「确定」都会把
    默认标志抹成 0，下次建任务再建一个新时间戳目录，历史产物被拆散。"""
    _old_defaults = {
        r["path"].casefold()
        for r in conn.execute(
            "SELECT path FROM chat_session_workspaces "
            "WHERE session_id = ? AND is_default = 1", (session_id,)).fetchall()
    }
    conn.execute("DELETE FROM chat_session_workspaces WHERE session_id = ?", (session_id,))
    if not entries:
        return
    conn.executemany(
        "INSERT INTO chat_session_workspaces"
        "(session_id, path, workspace_property, memo, is_default) "
        "VALUES (?, ?, ?, ?, ?)",
        [(session_id, p, r, m, 1 if p.casefold() in _old_defaults else 0)
         for p, r, m in entries])
```

```python
def set_session_workspaces(conn, session_id: str, raw_items) -> list[dict]:
    """PATCH 唯一写入口：数量先拦 → 归一化 → 去重 → 预检 → 写库。
    返回被拒清单；非空即调用方返 422，空即 200。

    入参兼容两形态（旧前端/脚本不炸）：
      list[str]  → 视为 (path, 默认属性, 无memo)
      list[dict] → {"path": ..., "workspace_property": ..., "memo": ...}
    属性/memo **不参与预检**（不是路径，与安全判定无关）。
    前端编辑（改 path/属性/memo）后整批提交，本函数不区分新增/编辑——全量覆盖。"""
    if raw_items and isinstance(raw_items[0], str):
        raw_items = [{"path": p} for p in raw_items]
    if len(raw_items) > MAX_WORKSPACES:
        return [{"path": f"({len(raw_items)} 条)", "reason": f"目录数超上限({MAX_WORKSPACES})"}]

    entries, rejected, _seen = [], [], set()
    for it in raw_items:
        _p = it.get("path", "")
        try:
            _n = _normalize_ws_path(_p)
        except (OSError, ValueError) as _e:
            rejected.append({"path": _p, "reason": f"路径非法: {type(_e).__name__}: {_e}"})
            continue
        _k = _n.casefold()
        if _k in _seen:                      # 去重(大小写不敏感)，存值保大小写
            continue
        _seen.add(_k)
        _prop, _memo = _normalize_ws_meta(it.get("workspace_property"), it.get("memo"))
        entries.append((_n, _prop, _memo))
    if rejected:
        return rejected                      # 归一化失败即整单 422，不再写库

    rejected = _ws_precheck([p for p, _r, _m in entries])
    if rejected:
        return rejected

    _ws_apply(conn, session_id, entries)
    logger.info(f"[workspace] 会话工作区已更新: session={session_id} 数量={len(entries)}")
    return []
```

```python
def classify_workspace_rows(rows) -> tuple[list, list]:
    """行 → (有效条目集, 不可用清单)：**会话工作区过滤唯一真源**。

    返回值变更：effective 由 list[str] 升级为 list[tuple[str, str, Optional[str], bool]]

    ⚠ 本函数只判定不落盘：面板 GET 走这里，因此打开面板永不创建目录。"""

    for r in rows:
        try:
            p = _normalize_ws_path(r["path"])
        except (OSError, ValueError) as _e:
            unusable.append({"path": r["path"], "reason": f"路径非法({type(_e).__name__})",
                             "kind": "illegal"})
            continue

            r["workspace_property"] if "workspace_property" in _keys else None,
            r["memo"] if "memo" in _keys else None)
        _is_def = bool(r["is_default"]) if "is_default" in _keys else False
```

```python
        return user_input

    _lines = []
    for e in sorted(snap.entries, key=lambda x: x.path):
        _line = f"  - {e.path}    [{ws_prop_label(e.workspace_property)}]"
        if e.memo:
            _line += f"  {e.memo}"
        if e.is_default:
            _line += "  (默认工作区)"
        _lines.append(_line)
    lines = "\n".join(_lines)

    _has_write = any(e.workspace_property == WS_PROP_WRITE for e in snap.entries)
    _tail = ("要求你临时/中间文件优先写入[写工作区]目录."
             if _has_write else
             "要求你临时/中间文件优先写入会话工作区.")

    return (
        f"{user_input}\n\n<会话工作目录>\n"
        f"本次任务会话工作区及属性标注（引导参考，不改变可写性判定）：\n{lines}\n"
        f"{_tail}\n"
        "</会话工作目录>\n"
    )
```

> `ws_prop_label` / `WS_PROP_WRITE` 从 `workspace_service` 导入（与 B.1 同源，DRY）。

## 六、数据库迁移策略

**使用现有 `_ensure_column` 机制**（幂等，老库安全）：

```python
# db_initializer.py 迁移区追加三条
_ensure_column(conn, "chat_session_workspaces", "workspace_property", "TEXT DEFAULT 'read_write'")
_ensure_column(conn, "chat_session_workspaces", "memo", "TEXT DEFAULT NULL")
_ensure_column(conn, "chat_session_workspaces", "is_default", "INTEGER DEFAULT 0")
```

| 场景 | 结果 |
|---|---|
| **老库** | `workspace_property` 自动填 `'read_write'`，`memo` 列 `NULL`，`is_default` 列 `0` → 旧行行为与现状完全一致（展示为"读写工作区"） |
| **新库** | 建表语句直接含三列，默认值同上 |
| **UNIQUE** | `UNIQUE(session_id, path)` 不变，三个标注字段允许任意重复 |
| **回滚** | 三列均有默认值/NULL，删列不丢业务数据（只丢标注） |
| **性能** | 每行多三列短文本，64 行上限下可忽略 |
| **是否需要数据迁移脚本** | **不需要** —— 运行时 `ws_prop_value` 兜底已覆盖 NULL/空/非法，无需批量 UPDATE 历史行 |

## 八、风险与注意事项

| # | 风险 | 处置 |
|---|---|---|
| 1 | **旧前端 + 新后端** | `WorkspaceUpdate` 联合类型放行 `list[str]`，service 归一为默认属性 + 无 memo → 不炸 |
| 2 | **新前端 + 旧后端** | 旧 DTO 是 `list[str]`，对 dict 元素直接 422 → **必须后端先上线、前端后上线**（同一版本内先后发） |
| 3 | **属性被误当权限** | prompt 首行明示"引导参考，不改变可写性判定"；文档与代码注释双处说明；安全矩阵零改动 |
| 4 | **标注字段污染安全判定** | `all_paths` 只由 `e.path` 构成；`_ws_deny_reason` 等判据不接收标注字段 → 结构上不可能污染 |
| 5 | **memo 换行破坏 prompt 行结构** | `_normalize_ws_meta` 统一把 `\r\n` 转空格；前端 Input 本身单行 |
| 6 | **超长 memo 撑爆 prompt** | 后端截断 256 + 前端 `maxLength={256}` 双保险 |
| 7 | **属性自由输入乱填** | 不校验不拒单（拒单代价 > 收益），非预设值走灰色 Tag，LLM 按字面理解 |
| 8 | **自定义属性 localStorage 丢失** | 浏览器清缓存/换机器会丢失下拉候选。**但库里的值不丢**（存在 DB），用户重新输入即可 |
| 9 | **父子目录在 prompt 中重复出现** | 注入遍历 `snap.entries`（全量行），`_drop_nested` 只作用于 `all_paths`（用于空判定与安全保护根）→ 父子目录同时配置时两行都进 prompt，语义冗余但不影响裁决；按现状保留 |
| 10 | **UNIQUE 约束** | 仍 `UNIQUE(session_id, path)`，标注字段不参与 → 同路径只有一行，改标注走覆盖写 |
| 11 | **classify 返回值类型变更** | `effective` 从 `list[str]` → `list[tuple[str, str, Optional[str], bool]]`，调用方仅 `_load_workspaces_conn` / `reconcile` / GET 端点三处，已同步改造 |
| 12 | **classify 中列缺失** | 用 `r.keys()` 检查列存在性，缺失时走 `DEFAULT_WS_PROP` / `None` / `False` |
| 13 | **编辑 path 后与已有条目重复** | `saveEdit` 不做前端去重，后端 `casefold` 去重会自动合并；用户可能不感知合并 → 先按后端兜底（KISS） |
| 14 | **编辑中途切换到另一行编辑** | `editingIndex` 单值，点新行 `startEdit` 自动覆盖旧值 → 旧行编辑内容丢失。设计如此（同时只编辑一行） |
| 15 | **编辑 path 改成非法路径** | `saveEdit` 做 `isAbsolute` 校验，失败时 `setEditErr` 提示，不退出编辑态 |
| 16 | **PATCH 抹掉默认标志** | `_ws_apply` 覆盖写时按 path 继承旧行的 `is_default`，前端无权携带该字段 → 用户改属性/备注不会让默认区丢失。用户**显式删掉**默认行、或把默认行 path 改成别的目录（等价于删除），下次建任务由 reconcile 重建 |
| 17 | **is_default 不参与安全判定** | `all_paths` 只由 `e.path` 构成；is_default 不传给判据 → 结构上不可能污染 |
| 18 | **面板 GET 误建目录** | GET 端点只调 `classify_workspace_rows`，**禁止调 `reconcile`**；实现时须确认"GET 路径无 mkdir" |
| 19 | **属性机器值/中文标签混存** | `ws_prop_value` 唯一归一化入口：中文标签归一为机器值，自定义文本原样；所有读取点必须走它，禁止直读原始字段 |
