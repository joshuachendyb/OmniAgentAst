## 一、术语与概念统一

> **全系统（前后端代码、日志、注释、UI 文案、文档）一律按本章口径表述**，禁止再用历史名词。

### 1.1 三个概念的边界

| 概念 | 性质 | 定义 | 用法约定 |
|---|---|---|---|
| **会话（Session）** | 逻辑实体 | DB `chat_sessions` 里的一行记录：标题、历史消息、状态等元数据 | 只说"会话"，**绝不指目录**；技术词=会话 ≡ 日常用语=**事项（matter）** |
| **会话工作区（Session Workspace）** | 物理实体 | 该会话在文件系统上对应的事务落盘目录（一行 = 一个目录） | 技术层/代码注释/日志用"会话工作区"；**界面 UI 用"事项工作区"** |
| **会话工作区目录（Session Workspace Directory）** | 物理实体（全称） | 同上的完整名称 | 架构图/DDL/严谨技术描述用"会话工作区目录"；**界面 UI 用"事项目录"** |

> **口径（用户拍板 2026-10-30）**：技术词"会话"（Session）≡ 日常用语"事项"（matter）。界面 UI 一律用"**事项工作区**/ **事项目录**"；技术层（代码注释/日志/DDL）用"会话工作区/会话工作区目录"。**界面 UI 用"事项"、技术层用"会话"，二者指同一实体。**

### 1.2 历史名词替换清单（强制）

| 历史名词 | 处置 | 替代为 |
|---|---|---|
| **事务空间目录** | ❌ 废弃 | 会话工作区 |
| **工作区目录** | ❌ 废弃（本系统会话语境内） | 会话工作区 |
| **会话目录** | ❌ 废弃 | 会话工作区 |
| **会话事务空间**（UI 面板标题/输入框下方文案） | ❌ 废弃 | **事项工作区**（界面）；技术层"会话工作区" |
| **事务工作区**（UI 文案） | ❌ 废弃 | **事项工作区**（界面）；技术层"会话工作区" |
| **会话工作区**（UI 界面词汇） | ❌ 废弃 | **事项工作区**（界面）；技术层保留"会话工作区" |
| **会话工作区目录**（UI 界面词汇） | ❌ 废弃 | **事项目录**（界面）；技术层保留"会话工作区目录" |
| **会话**（日常用语） | ❌ 废弃 | **事项（matter）**（技术词仍用 Session/会话） |
| **role**（字段名） | ❌ 废弃 | **workspace_property** |
| **读写分区**（字段语义描述） | ❌ 废弃 | **工作区属性** |

> **等义声明**：UI 上的「事项工作区」＝ 技术层的「会话工作区」＝ 原「事务工作区」，三者指同一实体，只是表述场景不同。界面 UI 用"事项"（日常用语），代码/日志用"会话"（技术词），技术词"会话" ≡ 日常用语"事项（matter）"。

### 1.3 workspace_property 的本质：纯文字标签，不涉及任何权限

**关键前提（实现中必须守住）**：

- `workspace_property` 是**给人看、给 LLM 看的文字标签**，用于描述"这个目录大概是干什么的"
- 它**不参与、不影响**：安全判定（`write_path_check` / `path_dir_lists` / `delete_path_check`）、确认层、快照白名单、禁区判定、读写授权
- 本系统**没有"只读区域"设置** —— 路径是否可写一律由安全矩阵统一裁决
- 即使属性是 `read_only`（读取工作区）的目录，LLM 发起写操作时安全矩阵照样按规则裁决（该放行就放行，该拦就拦）
- 属性的效力边界：**只在 UI 展示层 + LLM 语义理解层**，不在执行层

> 因此 `workspace_property` 与 `is_default`、`memo` 三者**同属"标注类字段"**：只做展示与提示，不进入 `all_paths`，不参与任何安全链路。

## 二、需求定义

### 2.1 总览：四个能力，一个面板

| 能力 | 现状 | 改造后 |
|---|---|---|
| **新增目录** | ✅ 有（仅 path） | ✅ 增强（path + workspace_property + memo 三字段同时填） |
| **删除目录** | ✅ 有 | ✅ 不变 |
| **编辑目录** | ❌ 无 | ✅ **新增**：行内编辑，支持改 path、workspace_property、memo 三个字段 |
| **默认工作区** | ⚠️ 仅"无目录才创建"，先添加目录则不建 | ✅ **重构**：始终创建 + `is_default` 标志 + 项目根感知 + 删除后重建 |

> 当前面板只有"输入框 + 添加按钮"和"每行一个删除按钮"。用户添加目录后想改属性或备注，只能删掉重新加。本次改造让每条目录支持原地编辑——点编辑按钮后该行切换为输入态，三字段全可改，保存即回写。

### 2.2 为什么是 workspace_property + memo 两个字段

| 字段 | 定位 | 解决什么 | 是否注入 prompt |
|---|---|---|---|
| **workspace_property** | 工作区属性（结构化的三档语义 + 自定义） | 让 LLM 快速判断"这目录是拿来读的、拿来写的、还是主战场" | ✅ 注入为 `[读取工作区]`/`[读写工作区]`/`[写工作区]` 标签 |
| **memo** | 自由文本备注（非结构化的补充说明） | 表达属性三档无法覆盖的具体信息，如"后端源码，别碰 legacy 目录"、"报告按 YYYYMMDD 命名" | ✅ 注入为行尾备注 |

**两者互补不重叠**：

- workspace_property 是**枚举化的粗粒度分类**（可快速筛选/着色/统计）
- memo 是**自由文本的细粒度补充**（属性装不下的具体约束、命名规约、注意事项）

### 2.3 三档预设 + 自由输入

**存储采用"机器值 + 中文标签"双层**：库里存机器值（稳定、可换标签不迁数据），UI 与 prompt 用中文标签（人读、LLM 读）。

| 机器值（存库） | 中文标签（展示/注入） | 语义 | LLM 行为引导 | Tag 颜色 |
|---|---|---|---|---|
| `read_only` | **读取工作区** | 主要用来查阅参考 | 此目录以读取为主，写操作需谨慎 | 绿 |
| `read_write`（**默认**） | **读写工作区** | 默认可读写工作区 | 正常工作目录，按任务需要读写 | 蓝 |
| `write` | **写工作区** | 产物/报告输出目标 | 产物、报告、中间文件**优先**写这里 | 橙 |
| 自定义文本（原样存） | 同原文（如"构建产物"/"日志区"） | 用户自由输入 | 按值本身的字面语义理解 | 灰 |

**字段为 TEXT 非 ENUM**：允许自由输入，识别不了的走灰色 Tag + 默认引导，**不报错不拦截**（拒单代价远大于收益）。

### 2.4 兜底规则（唯一真源）

> 兜底规则：**`workspace_property` 缺失一律回落 `read_write`，展示「读写工作区」**。这只是文字标签，不涉及权限/授权。

| 场景 | 存储值 | 展示/注入标签 |
|---|---|---|
| 新建会话 / 新增目录未填属性 | `read_write` | 读写工作区 |
| 历史数据（列为 NULL / 空串 / 全空白） | `read_write` | 读写工作区 |
| 传入了中文标签（如 `读写工作区`） | 归一为 `read_write` | 读写工作区 |
| 传入了未知/非法值（如乱码、超长） | 原样保留（自定义语义） | 原样展示 |
| 列不存在（旧库未迁移 / 外部 rows） | `read_write` | 读写工作区 |

**归一化唯一入口**（入库：后端 `ws_prop_value` / 前端 `propValue`；展示：后端 `ws_prop_label` / 前端 `propLabel`），任何取属性的地方都必须走它，禁止直接读原始字段。

### 2.5 自定义属性值跨会话共享（localStorage）

用户在面板里自定义输入过的新属性值（不在三档预设内），通过浏览器 `localStorage` 持久化，后续所有会话的 AutoComplete 下拉都能看到，避免重复手打。新增和编辑时都会触发持久化。

| 项 | 设计 | 理由 |
|---|---|---|
| 存储位置 | `localStorage["ws_custom_props"]` = JSON 数组 | 浏览器本地，零后端改动 |
| 存储时机 | `addEntry` / `saveEdit` 时，若属性值不在三档预设内，自动追加 | 无感知，用户不需要额外操作 |
| 去重 | 加入前检查数组中是否已有该值 | 避免重复项 |
| 上限 | 最多保留 16 条自定义值 | 防无限膨胀；超出按 FIFO 淘汰最旧的 |
| 跨会话 | ✅ 同浏览器所有会话共享 | 这是"个人习惯标签"，非团队规范 |
| 跨机器 | ❌ 不同浏览器/机器不共享 | YAGNI —— 没有多机器同步需求 |

### 2.6 memo 设计约束

| 项 | 取值 | 理由 |
|---|---|---|
| 类型 | `TEXT DEFAULT NULL` | 可选字段，NULL = 无备注 |
| 最大长度 | 256 字符 | 足够写一两句具体约束；防长串污染 prompt |
| 是否必填 | 否 | 不破坏现有流程；YAGNI |
| 是否唯一 | 否 | 备注内容可重复 |
| 换行 | 不允许 | 单行注入，避免破坏 prompt 行结构（前端换行符 → 空格） |
| 参与安全判定 | **否** | 纯 prompt 文本，不做任何路径校验 |

### 2.7 行内编辑设计

面板的每条目录行支持"展示态 ↔ 编辑态"切换，三字段（path、workspace_property、memo）全可改。

| 项 | 设计 | 理由 |
|---|---|---|
| 触发方式 | 展示态行内 ✏️ 编辑按钮 | 与 🗑 删除按钮并排，操作入口一致 |
| 编辑范围 | path + workspace_property + memo 三个字段全可改 | 用户可能填错路径、想换属性、想补备注 |
| path 可改的原理 | PATCH 写库是 DELETE 全删 → INSERT 全量，改 path = 改数组元素，不存在 UNIQUE 冲突 | 不需要单独的 UPDATE 某行 |
| 同一时间只编辑一行 | `editingIndex` 单值，点新行编辑自动退出旧行 | 避免多行同时编辑的 state 混乱 |
| 编辑不立即 PATCH | 改的是本地 `entries` state，点"确定"才统一提交 | 与 add/delete 一致（都是改 state → 确定时一次性 PATCH） |
| 编辑保存时校验 path | `isAbsolute` 检查，与 addEntry 同校验规则 | 保证数据一致 |
| 属性 AutoComplete 复用 | 编辑态和新增区共享 `propOptions` | DRY |
| 自定义属性持久化 | `saveEdit` 里调 `saveCustomProp(p)` | 与 addEntry 同逻辑 |
| 回车保存 | path Input 和 memo Input 都绑 `onPressEnter={saveEdit}` | 快捷操作 |
| 取消编辑 | 点"取消"按钮丢弃修改回到展示态 | 不影响 state |

### 2.8 创建时机与默认工作区

#### 2.8.1 默认工作区的定位与三条硬规则

默认工作区（`is_default=1`）＝ 系统为本会话自动创建的隔离落盘区，语义是"本会话临时/中间文件的默认落点"。

| # | 规则 | 具体行为 |
|---|---|---|
| 1 | **始终创建** | 无论用户是否已先添加目录，默认工作区都必须存在（消除"先添加目录则不建默认"的不一致） |
| 2 | **删除后可重建** | ① DB 行被删（程序化 PATCH/前端清空）→ 下次建任务 `reconcile` 判"无默认"→ 重建；② **系统外删目录**（资源管理器手动删）→ 行仍在、下次 `reconcile` `missing` 分支 mkdir 重建。**系统内部面板不提供删除入口**（2026-10-31 令）；`is_default` 列标识"哪条是本会话默认工作区"，供其他应用识别，不靠路径模式猜测 |
| 3 | **跟随项目根** | 项目根改变后，老会话的新任务在新项目根下重建默认工作区；旧默认目录降为普通目录，历史产物保留不搬移 |

#### 2.8.2 创建时机

| 对象 | 创建时机 | 说明 |
|---|---|---|
| **默认工作区**（`is_default=1`） | **始终创建**：每次"创建新 Task 并绑定该会话"时由 `reconcile_session_workspaces` 确保存在 | 无则建、删则重建、项目根变则在新根重建 |
| **用户添加的目录行** | **懒加载**：不提前创建；同样在"创建新 Task 并绑定该会话"时才 `mkdir` | 避免纯浏览产生空目录 |
| **面板 GET（打开面板/切会话/看历史）** | **不创建任何目录** | 纯读 + 只做 `classify_workspace_rows` 判定，绝不落盘 |

**为什么触发点选"创建新 Task 并绑定该会话"**：

1. **语义最准** —— 会话工作区是"任务的事务落盘范围"，任务不创建就不需要它
2. **覆盖"删除后下次创建"** —— 用户删了磁盘目录，下次建任务时 `classify` 判为 `missing` → 立即重建，语义自然
3. **零冗余** —— 纯浏览、纯看历史、纯切会话都不会在磁盘上留下空目录
4. **与现有代码天然吻合** —— `_ensure_and_load_workspaces`（`stream_orchestrator.py` L391）就在任务启动路径上调用 `reconcile_session_workspaces`，无需新增触发点

**落地约束（实现必须守住）**：

- 创建目录的唯一位置 = `reconcile_session_workspaces`（`workspace_service.py` L211）。**禁止在其他地方新增 `mkdir`**
- `GET /sessions/{id}/workspaces`（`sessions.py` L133）**只调 `classify_workspace_rows`，不调 `reconcile`** —— 保持"面板只读不落盘"
- 幂等：`mkdir(parents=True, exist_ok=True)`，并发多请求同时建也不报错
- 可观测：登记默认工作区时打 `info` 日志（`session_id` / `path` / `is_default`）；清理与建目录沿用既有 `warning` / `info` 日志

#### 2.8.3 核心逻辑（`reconcile_session_workspaces` 重写）

```python
def reconcile_session_workspaces(conn, session_id: str) -> list[tuple[str, str, Optional[str], bool]]:
    """创建新 Task 并绑定该会话时的唯一落盘入口。

    默认工作区始终存在（先添加目录也建）→ 逐条裁决（禁区行清库 / 缺目录则建 / 可用则留）
    → 返回有效条目集。用户目录同样在此懒建（面板 GET 不建，只此处建）。
    返回 [(path, workspace_property, memo, is_default)] 四元组。

    ⚠ 只删数据库行，绝不删除磁盘目录。"""
    rows = get_session_workspaces(conn, session_id)      # 含 workspace_property/memo/is_default
    current_root = get_config().get_project_root()       # 当前配置的项目根

    # ── 默认工作区是否需创建/重建 ──
    # 需要（任一）：a) 无任何 is_default=1 行（首次，或用户删了默认行）
    #               b) 默认行不在当前项目根下（项目根变了）
    need_new_default = True
    for r in rows:
        if r["is_default"] and Path(r["path"]).parent == Path(current_root):
            need_new_default = False
            break

    if need_new_default:
        d = _build_default_workspace_dir(session_id)     # 读当前根，天然建在新根下
        if d:
            try:
                _p = _normalize_ws_path(d)
                # 先登记/升级新默认（同路径已存在则原地置 1），再降级其余默认行 ——
                # 顺序不可颠倒：先降后插一旦插入失败，会话将没有任何默认工作区
                conn.execute(
                    "INSERT INTO chat_session_workspaces"
                    "(session_id, path, workspace_property, memo, is_default) "
                    "VALUES (?, ?, ?, ?, 1) "
                    "ON CONFLICT(session_id, path) DO UPDATE SET "
                    "workspace_property = excluded.workspace_property, "
                    "memo = excluded.memo, is_default = 1",
                    (session_id, _p, DEFAULT_WS_PROP, DEFAULT_MEMO))
                # 旧默认目录降为普通目录（保留历史产物，用户可自行处置）
                conn.execute(
                    "UPDATE chat_session_workspaces SET is_default = 0 "
                    "WHERE session_id = ? AND is_default = 1 AND path <> ?",
                    (session_id, _p))
                logger.info(f"[chat] 默认工作区已就绪: session={session_id} path={_p}")
            except Exception as _e:
                logger.warning(f"[chat] 默认工作区登记失败（本轮无默认区，下次再试）: {_e}")
        rows = get_session_workspaces(conn, session_id)

    _, unusable = classify_workspace_rows(rows)
    for u in unusable:
        if u["kind"] != "denied":
            continue                                     # 脏行/缺目录：本轮跳过，下次再看
        try:                                             # 禁区行：从表里清掉（只删库行）
            conn.execute(
                "DELETE FROM chat_session_workspaces WHERE session_id = ? AND path = ?",
                (session_id, u["path"]))
        except Exception as _de:
            logger.warning(f"[chat] 禁区目录清理失败(本轮仍不放行): {u['path']} - {_de}")
            continue
        logger.warning(f"[chat] 会话工作区已落入禁区, 已从列表清理: {u['path']}")

    for u in unusable:                                   # 缺目录：建出来（禁区/脏行不建）
        if u["kind"] != "missing":
            continue
        try:
            Path(u["path"]).mkdir(parents=True, exist_ok=True)
            logger.info(f"[chat] 会话工作区目录不存在, 已自动建立: {u['path']}")
        except Exception as _e:
            logger.warning(f"[chat] 会话工作区目录建立失败(本轮不生效, 下次再试): {u['path']} - {_e}")

    return _load_workspaces_conn(conn, session_id)       # 重读重判：刚建好的目录本轮即生效
```

#### 2.8.4 行为矩阵（全场景验证）

| 场景 | 行为 | 正确性 |
|---|---|---|
| 新会话，直接发任务 | 建任务时创建默认工作区（`is_default=1`） | ✅ 与现状一致 |
| 新会话，**先添加目录**再发任务 | **仍创建默认工作区**（与用户目录并存） | ✅ 解决不一致 |
| 用户删除默认工作区（DB 行） | `is_default=1` 行没了 → 下次建任务**重建**（新时间戳） | ✅ 规则 2 |
| 用户删除默认工作区（磁盘目录） | `classify` 判 `missing` → 下次建任务**原地重建**（同路径） | ✅ 规则 2 |
| 用户删除用户目录（磁盘） | 同上，下次建任务原地重建 | ✅ 懒加载 |
| 项目根 `E:\test_dir` → `E:\new_root` | 检测默认目录不在新根下 → **在新根重建**（旧默认降为普通，历史产物保留） | ✅ 规则 3 |
| 项目根多次改变 | 每次变化在新根重建；旧默认逐次降为普通 | ✅ 历史不回溯 |
| 用户先添加目录 + 项目根改变 | 默认工作区仍在新根重建（用户目录不动） | ✅ |
| **打开面板 / 切会话 / 看历史** | **不创建任何目录**（GET 只读） | ✅ 懒加载 |

#### 2.8.5 其他应用如何消费 `is_default`

其他应用（如历史页 workspaceMap）直接从 `GET /sessions/{id}/workspaces` 的每条记录读 `is_default`（GET 已返回四字段），即可识别"本会话默认工作区"，无需再依赖路径模式猜测（如判断是否含时间戳前缀）。

**不新增后端专用取数函数**：GET 已是唯一读口，再加一个"只查默认行"的函数没有调用方，违反 YAGNI；历史页在默认工作区行显示「默认」Tag（见 §I）。

> **语义约束**：同一会话**至多一条** `is_default=1`（由 reconcile 的「先登记新默认 → 再降级其余默认行」顺序保证）。

```python
    """覆盖写 —— PATCH 的唯一写库实现（懒建占行不走这里）。

    DELETE 全删 → executemany INSERT(path, workspace_property, memo, is_default)。
    全删全插天然支持编辑：前端改了某条 path/属性/memo 后整批提交，
    后端不需要区分"新增/修改/删除"——全量覆盖即可。

    ⚠ is_default 由系统维护，前端 PATCH 无权携带：写库前先读旧默认行，
    覆盖时按 path（大小写不敏感）原样继承。否则用户每点一次「确定」都会把
    默认标志抹成 0，下次建任务再建一个新时间戳目录，历史产物被拆散。"""
    _old_defaults = {
        r["path"].casefold()
        for r in conn.execute(
            "SELECT path FROM chat_session_workspaces "
            "WHERE session_id = ? AND is_default = 1", (session_id,)).fetchall()
    }
    conn.execute("DELETE FROM chat_session_workspaces WHERE session_id = ?", (session_id,))
    if not entries:
        return
    conn.executemany(
        "INSERT INTO chat_session_workspaces"
        "(session_id, path, workspace_property, memo, is_default) "
        "VALUES (?, ?, ?, ?, ?)",
        [(session_id, p, r, m, 1 if p.casefold() in _old_defaults else 0)
         for p, r, m in entries])
```

```python
    返回被拒清单；非空即调用方返 422，空即 200。

        return [{"path": f"({len(items)} 条)", "reason": f"目录数超上限({MAX_WORKSPACES})"}]

        try:
```

| 不变量 | 现状实现 | 本次要求 |
|---|---|---|
| 关闭不被网络绑定 | `confirm()` 同步执行 `void workspaceStore.commit(...)` + `onClose()` | 保持；禁止加 `saving` / `confirmLoading` / await |
| 未就绪禁止覆盖写 | `loadState !== 'ready'` → 「确定」禁用，`confirm()` 再拦一次 | 保持 |
| 迟到 GET 不覆盖草稿 | `dirtyRef.current` | 保持；增 / 删 / 改 / 清空都要置 `true` |
| 关闭 / 切会话作废在飞请求 | `loadSeqRef.current` | 保持 |
| 422 留痕跨关闭 | `workspaceStore.notice`（组件用 `useSyncExternalStore` 读） | 保持；组件内不再自建 `rejected` state |
| 删空二次确认 | `remove()` 按"删空后果"确认，`Modal.confirm` 在 updater 外 | 保持（StrictMode 双调用 updater，放里面会弹两次） |
| 列表加载失败降级 | `loadState='failed'` + `handleError`，不显示成"空列表可写" | 保持 |

#### H.2 草稿类型与纯函数

```typescript
/** 面板内部草稿：path + 属性 + memo + 默认标志（is_default 只读展示，PATCH 不携带） */
type WsDraft = {
  path: string;
  workspace_property: string;
  memo: string;
  is_default: boolean;
};

/** 属性三档预设：机器值 + 中文标签 */
const WS_PROP_PRESETS = [
  { value: 'read_only', label: '读取工作区' },
  { value: 'read_write', label: '读写工作区' },
  { value: 'write', label: '写工作区' },
] as const;
const DEFAULT_WS_PROP = 'read_write';
const CUSTOM_PROPS_KEY = 'ws_custom_props';
const MAX_CUSTOM_PROPS = 16;

/** 属性 Tag 颜色：预设三档 + 自定义灰 */
const PROP_COLORS: Record<string, string> = {
  read_only: 'green',
  read_write: 'blue',
  write: 'orange',
};

/** 属性展示唯一源：机器值 → 中文标签；自定义原样；缺失 → 读写工作区 */
function propLabel(raw?: string | null): string {
  const v = (raw || '').trim();
  if (!v) return '读写工作区';
  const hit = WS_PROP_PRESETS.find((p) => p.value === v || p.label === v);
  return hit ? hit.label : v;
}

/** 属性入库唯一源：缺失/空 → read_write；中文标签 → 机器值；自定义原样 */
function propValue(raw?: string | null): string {
  const v = (raw || '').trim();
  if (!v) return DEFAULT_WS_PROP;
  if (WS_PROP_PRESETS.some((p) => p.value === v)) return v;
  const byLabel = WS_PROP_PRESETS.find((p) => p.label === v);
  return byLabel ? byLabel.value : v;
}

/** 读自定义属性列表（localStorage，失败降级空数组） */
function loadCustomProps(): string[] {
  try {
    const raw = localStorage.getItem(CUSTOM_PROPS_KEY);
    return raw ? JSON.parse(raw) : [];
  } catch {
    return [];
  }
}

/** 存自定义属性（预设不存、已有不存、FIFO 淘汰、失败静默） */
function saveCustomProp(prop: string): void {
  if (WS_PROP_PRESETS.some((p) => p.value === prop || p.label === prop)) return;
  const list = loadCustomProps();
  if (list.includes(prop)) return;
  list.push(prop);
  if (list.length > MAX_CUSTOM_PROPS) list.shift();
  try {
    localStorage.setItem(CUSTOM_PROPS_KEY, JSON.stringify(list));
  } catch {
    /* 隐私模式/配额满：静默降级，不影响主流程 */
  }
}
```

> 属性是**文字标签**，不参与任何权限判定（§1.3）；`propLabel` / `propValue` 是面板内唯一展示/入库入口，禁止在 JSX 里散写映射。

#### H.3 store 契约增量（`services/sessionWorkspaceStore.ts`）

```typescript
/** 提交载荷：只有三个可写字段；is_default 由后端 reconcile / _ws_apply 维护 */
export type WorkspacePatchItem = Pick<
  WorkspaceEntry,
  'path' | 'workspace_property' | 'memo'
>;

const commit = async (
  sessionId: string,
  items: WorkspacePatchItem[]
): Promise<void> => {
  const seq = ++commitSeq;
  try {
    await sessionApi.patchWorkspaces(sessionId, items);
    if (seq !== commitSeq || state.sessionId !== sessionId) return;
    setState({
      sessionId,
      // 成功即以请求列表为权威落位：三字段原样保留，禁止退化成 { path }
      list: items.map((i) => ({ ...i })),
      notice: [],
    });
  } catch (e: unknown) {
    if (seq !== commitSeq) return;
    const rejected = rejectionsOf(e);
    if (rejected.length) {
      if (state.sessionId === sessionId) {
        setState({ ...state, notice: rejected });
      }
      rejected.forEach((x) =>
        showMessage(ErrorType.WORKSPACE_REJECTED, `${x.path}：${x.reason}`)
      );
    } else {
      handleError(e);
    }
    await reconcile(sessionId);
  }
};
```

`reconcile` / `loadSession` / `subscribe` 均**不改**：GET 已返回四字段，`list` 类型随 `WorkspaceEntry` 自动升级。

```typescript
const [inputErr, setInputErr] = useState('');
```

#### H.5 新增 / 编辑 / 删除 / 确定

编辑态用 **path 作标识**（`editingPath: string | null`），不用下标：`dataSource` 同时混有可用项与不可用项，下标在渲染期易错位；path 在列表内唯一。

```typescript
const [editingPath, setEditingPath] = useState<string | null>(null);
const [editPath, setEditPath] = useState('');
const [editProp, setEditProp] = useState(DEFAULT_WS_PROP);
const [editMemo, setEditMemo] = useState('');
const [editErr, setEditErr] = useState('');

/** 新增（同路径覆盖属性/memo，不产生重复行） */
const addEntry = () => {
  const v = input.trim();
  if (!v || !isAbsolute(v)) {
    setInputErr('请输入绝对路径');
    return;
  }
  const p = propValue(propInput);
  const m = memoInput.trim();
  saveCustomProp(p);
  dirtyRef.current = true;
  setEntries((es) =>
    es.some((e) => e.path.toLowerCase() === v.toLowerCase())
      ? es.map((e) =>
          e.path.toLowerCase() === v.toLowerCase()
            ? { ...e, workspace_property: p, memo: m }
            : e
        )
      : [...es, { path: v, workspace_property: p, memo: m, is_default: false }]
  );
  setInput('');
  setPropInput(DEFAULT_WS_PROP);
  setMemoInput('');
  setInputErr('');
};

/** 进入编辑态 */
const startEdit = (e: WsDraft) => {
  setEditingPath(e.path);
  setEditPath(e.path);
  setEditProp(e.workspace_property);
  setEditMemo(e.memo);
  setEditErr('');
};

/** 保存编辑：绝对路径 + 同列表去重（改到别的行已占用的路径必须拦住） */
const saveEdit = () => {
  if (!editingPath) return;
  const v = editPath.trim();
  if (!v || !isAbsolute(v)) {
    setEditErr('请输入绝对路径');
    return;
  }
  const clash = entries.some(
    (e) => e.path !== editingPath && e.path.toLowerCase() === v.toLowerCase()
  );
  if (clash) {
    setEditErr('该目录已在列表中');
    return;
  }
  const p = propValue(editProp);
  saveCustomProp(p);
  dirtyRef.current = true;
  setEntries((es) =>
    es.map((e) =>
      e.path === editingPath
        ? { ...e, path: v, workspace_property: p, memo: editMemo.trim() }
        : e
    )
  );
  setEditingPath(null);
};

const cancelEdit = () => setEditingPath(null);

/** 删除（删空二次确认，确认框在 updater 外） */
const remove = (path: string) => {
  /* 默认工作区系统内不可删：目录只能系统外（资源管理器）手动删，
     下次建任务 reconcile 按规则2 重建。面板不渲染默认行删除按钮，
     此处防御兜底（UI 与业务逻辑双重保障）。 */
  const target = entries.find((e) => e.path === path);
  if (target?.is_default) return;
  const willEmpty = entries.length === 1 && entries[0].path === path;
  if (willEmpty) {
    Modal.confirm({
      title: '清空目录列表？',
      content: '清空后本会话暂时没有使用目录，下一条消息会重新生成一个默认工作区。磁盘目录不会被删除。',
      okText: '清空',
      cancelText: '取消',
      onOk: () => {
        dirtyRef.current = true;
        setEntries([]);
        setEditingPath(null);
      },
    });
    return;
  }
  dirtyRef.current = true;
  setEntries((es) => es.filter((e) => e.path !== path));
  if (editingPath === path) setEditingPath(null);
};

/** 确定 → 本地立即关闭 + 后台提交（不可 await） */
const confirm = () => {
  if (loadState !== 'ready') return;
  void workspaceStore.commit(
    sessionId,
    entries.map((e) => ({
      path: e.path,
      workspace_property: propValue(e.workspace_property),
      memo: e.memo.trim() || null,
    }))
  );
  onClose();
};
```

## 六、数据库迁移策略

**使用现有 `_ensure_column` 机制**（幂等，老库安全）：

```python
# db_initializer.py 迁移区追加三条
_ensure_column(conn, "chat_session_workspaces", "workspace_property", "TEXT DEFAULT 'read_write'")
_ensure_column(conn, "chat_session_workspaces", "memo", "TEXT DEFAULT NULL")
_ensure_column(conn, "chat_session_workspaces", "is_default", "INTEGER DEFAULT 0")
```

| 场景 | 结果 |
|---|---|
| **老库** | `workspace_property` 自动填 `'read_write'`，`memo` 列 `NULL`，`is_default` 列 `0` → 旧行行为与现状完全一致（展示为"读写工作区"） |

| **UNIQUE** | `UNIQUE(session_id, path)` 不变，三个标注字段允许任意重复 |

>

**S1 DB 迁移（A）**

2. **禁止**在面板里再做一次属性归一（统一走 `propValue`；后端统一走 `_normalize_ws_meta`）。

4. **禁止**新增没有确定调用方的只读接口或工具函数（YAGNI）。
5. 新增公用函数前先查 `backend/FUNCTIONS.md`；新增后必须登记（复用优先）。
6. 前端提交前跑 `npm run check:full`（含 `typecheck:e2e`），后端跑相关 pytest。
