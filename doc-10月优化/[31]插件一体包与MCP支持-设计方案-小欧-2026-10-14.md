## 一、目标

### 1.1 要做成的样子

1. **插件一体包**：一个插件目录 = `skills/` + `tools/` + `mcp.json` + `ui/` + `hooks/`，
   一次安装整包生效（对标 Claude 插件，多一维 UI）。
2. **插件市场**：本地目录/ git 仓库即市场（`marketplace.json`），设置页可浏览、
   安装、开关、卸载；安装前有"装什么 + 花多少上下文"的审查窗。
3. **三级作用域**：user（全局）/ project（按会话工作目录生效，本系统独家）/ session（当次）。
4. **Skills 渐进加载**：`SKILL.md` 元数据常驻索引、body 按需取；每个插件标上下文开销。
5. **MCP client**：连外部 MCP server（先 stdio），远端工具在本地 Agent 侧零感知可用。
6. **MCP Apps host**：带 `_meta.ui` 界面的工具，在对话里渲染沙箱卡片，不支持则降级纯文本。

### 1.2 非目标（本期不做）

- 不做 MCP server 端（把自家工具暴露出去）：谁来连不成立，YAGNI。
- 不做 Streamable HTTP 传输与 OAuth：P4 再说，P2 只做 stdio。
- 不做中心化商店/付费/账号体系：市场就是目录 + git。
- 不升级 `httpx`（锁死，见第五章）。

## 二、前沿研究分析

> 核查时间：2026-10-14；来源：Claude Code 官方插件文档、MCP SEP-1865（2026-01-26 稳定版）
> 及 modelcontextprotocol/ext-apps 官方库。结论：**工具的终点不是文字，是界面；
> 插件的形态不是单点功能，是一体包；上下文的形态不是全量灌，是渐进披露。**

### 2.1 Claude Code 插件体系（一体包 + 市场 + 作用域）

- 插件 = 目录：`plugin.json` 清单 + `skills/`（`SKILL.md`）+ `agents/` + `hooks/`（`hooks.json`，
  工具调用前后等生命周期点）+ `.mcp.json` + `output-styles` + `bin/`。
  **几个异构东西打成一包、一次安装，是插件区别于"装一个工具"的本质。**
- 市场 = `marketplace.json` 目录（git/本地路径均可），安装/更新/禁用/卸载全套，
  支持 auto-update；`strict` 模式区分"清单权威还是市场权威"。
- 三级作用域：user（`~/.claude/settings.json`）/ project（`./.claude/settings.json`，
  可提交，协作者各装一次）/ local（本机本仓）。**project 级可提交、协作者同享**，
  是团队分发的关键。
- 信任：安装前面板明示"Will install"（装 commands/agents/skills/hooks/MCP 各几项）+
  上下文开销估算（每轮多少 token）+ 安全审查提示（插件以用户权限跑代码）。
- Skills 目录自动发现（`~/.claude/skills/` 下有目录即加载，免安装）——
  **低摩擦是生态转起来的前提**。

### 2.2 MCP Apps（SEP-1865，官方第一个扩展，2026-01-26 稳定）

- 工具用 `_meta.ui.resourceUri` 声明 `ui://` 界面；host 取回渲染**沙箱 iframe**，
  双向 postMessage（JSON-RPC）；**不支持的 host 自动降级回纯文本**（向后兼容写进协议）。
- 可见性模型：`visibility: ["model", "app"]`——给模型的和给界面的可以不是同一批工具。
- 安全模型：强制沙箱 + 通信可审计 + CSP 声明（默认不许对外联网）+ 用户 consent。
- 已支持：Claude（网/桌）、ChatGPT、Goose、VS Code。OpenAI Apps SDK 与 MCP-UI 是先驱，
  现收敛为同一标准。**例证：Excalidraw 级交互（画布/表单/看板/视频）直接长在对话里。**
- 对我们的含义：MCP = 能力接入层，**MCP Apps = 体验分水岭**。只接前者是接线工，
  接上后者才是房东——而界面只能长在富客户端里，终端玩家天生进不来。

### 2.3 渐进式上下文（Skills 的实质）

- `SKILL.md` = frontmatter（名/描述/开销）+ 正文（用时加载）。元数据常驻索引，
  body 按需取：**上下文从"全量灌"变成"按需披露"，插件再多也不撑爆窗口**。
- 映射到本系统：`searchtool` 的 BM25 索引（名 + 描述 + 分类）就是现成的披露底座，
  差的是 SKILL.md 这一路索引源和开销计量（M11 字符数那套肌肉记忆直接放大）。

### 2.4 给本系统的四条启示

1. 插件必须是**一体包**（skills/tools/mcp/ui/hooks），单点工具不配叫插件。
2. 市场必须**无服务器**（目录 + git 即可），先让生态转起来。
3. 作用域必须绑到**工作区**（[15]/[16] 才给得了的东西，别家没有）。
4. 工具必须能**长出界面**（MCP Apps host），这是富客户端的代差，不做等于把长板锯了。

## 三、本地系统实际情况分析

> 全部实测（2026-10-14），行号为当时本地最新代码。

### 3.1 工具系统：已经是"准插件"形态

- `ToolRegistry` 单例 + `register_tool` 装饰器（`backend/app/tools/registry.py:123,343`），
  注册字段含 `input_schema`（支持**直传 JSON Schema**，不用包 Pydantic 模型——
  MCP 远端 schema 直灌的口子是现成的）、`expose_to_llm`、`needs_confirmation`、
  `check_fn`、`dependencies`（运行时 pip 安装）。
- 分类懒加载：`CATEGORY_MODULES` → `{cat}_tools.py`（实现）+ `{cat}_register.py`（注册），
  `_import_and_register` + `ensure_tools_registered()`（:398-437，失败重试 3 次）。
- `ToolCategory` 枚举是 OCP 开口（`tool_types.py:24`，注释"新增分类只需在此文件添加"）；
  `ToolMetadata` 是 dataclass，加可选字段零影响旧代码。
- 执行链：`handle_action` → `get_implementation` → 调实现，Agent 侧只认注册表，
  **新来源的工具只要进注册表，Agent 零感知**（MCP 薄包装的立足点）。
- 发现：`searchtool`（`fundamental/tool_search.py`）BM25 索引名 + 描述 + 分类（含中文名），
  分类懒加载（没搜到的类 bodies 不进内存）——渐进披露的半成品。

### 3.2 安全链：全部可复用，不新造

- `needs_confirmation` / `check_fn`（注册期二元安全）、`validate_path`（路径三界）、
  trust（`trust.py`）、HITL 网关（人工裁决）——插件/远端工具直接继承，
  **外部来源一律默认 `needs_confirmation=True`**（fail-closed）。
- [28]第六章结论：模型输出/外部内容属不可信输入，渲染侧标边界——MCP 远端结果与
  MCP Apps iframe 通信同理（后者再加沙箱 + 可审计，抄 SEP-1865 安全模型）。

### 3.3 MCP 现状：实质为零

- 全仓 "MCP" 仅两处：`search_web.py` 调 parallel/exa 的 HTTP 搜索接口
  （借名，非协议）、`agent_telemetry.py` 一句"未来插件"注释。无 client、无 server、无配置。
- **官方 `mcp` SDK 装不得**（实测 PyPI：v2 要 `httpx2>=2.5` + `sse-starlette` +
  `starlette>=0.27` + `anyio>=4.9` 等十几个包）。本项目 `httpx==0.26.0` +
  `httpcore==1.0.1` 锁死（0.28.1 断 TLS，见 AGENTS.md）。**结论：手写最小客户端，
  只用 stdlib + 现有 httpx。**

### 3.4 前端渲染面：MCP Apps host 已就位约八成

- `MarkdownSlot`（统一入口，`MD_IMPL` 开关）+ `rehype-sanitize` 净化 + Suspense、
  `FileRefChip`（工具结果 → 可点卡片，[28] 4.2.8/4.4.13-14）、`ToolResultRenderer`、
  `markdown-text-fence` 回归传统——**缺的只是一层**：认 `_meta.ui` →
  `resources/read` 取 `ui://` → 沙箱 iframe → 降级走现有纯文本。
- 设置页有现成形态可抄：`ModelLibraryTab`（一键安装/开关/计数）、
  `SessionWorkspacePanel`（422 如实呈现），插件市场页照此长相做。
- 反面：`App.tsx:92` 的 `path="*"` 兜底吞路由（[28] 4.2.4 实证），新页面必手测直达。

### 3.5 配置与依赖现状

- `config.yaml` 经 `get_config_path()` 读写（测试隔离铁律见 AGENTS.md），
  加 `plugins:` / `mcp_servers:` 两段是纯加法。
- Python 3.13（`E:\Appsw\python31311\`），`anyio` 在（stdio 子进程协程够用），
  `mcp` 包不在。Windows-only：MCP stdio 起子进程走 `.cmd`/`.exe`，命令写法按 Windows 约定。

## 四、实施策略和概要方案

> 原则：**地基一个不拆，全是加法**（见第五章对照表）。顺序 P1→P4，前一步是后一步的地基。

### 4.1 P1 插件包 + 本地市场 + Skills 渐进（地基，先让生态转起来）

**插件包格式**（目录即插件，对标 Claude 并多一维 `ui/`）：

```
my-plugin/
  plugin.json            # 名/版本/描述/作者 + 各部件路径（缺省按默认位置扫，可省略）
  skills/<name>/SKILL.md # frontmatter：name/description/cost（字符数≈token×0.3，沿 M11 口径）
  tools/*.py             # 调现成 register_tool，category=PLUGIN（新增枚举成员）
  mcp.json               # 本插件自带的 MCP servers（P2 消费，见 4.3）
  ui/*.tsx               # 插件卡片（注册进 ToolResultRenderer 映射，见 4.4）
  hooks/hooks.json       # 事件→动作（工具调用前后/会话起止/compaction；动作为 shell 命令或 py 函数）
```

**市场**：`marketplace.json`（名/owner/plugins[]：名/source/版本/描述），source 支持
本地路径（先）与 git（后）；`strict` 抄 Claude（清单权威 vs 市场权威，默认清单）。
安装 = 拷目录 + 登记 + 校验（JSON schema + 「Will install」清单 + 上下文开销）；
禁用 ≠ 卸载（开关独立）。

**三级作用域**：user（全局配置）/ project（写进会话工作区配置，随 [15]/[16] 走，
协作者各装一次即同享——**本系统独家**）/ session（当次有效）。

**Skills 渐进**：searchtool 索引加两路（SKILL.md frontmatter、插件元数据），
body 按需读文件；插件管理页每插件标开销（字符数，沿 M11）；
上下文预算超限只告警不硬拦（v3.4 裁定风格：告知不限制）。

**文件清单（P1）**：`app/tools/plugin/`（manifest 解析 + 加载器，复用
`_import_and_register` 路径）/ `ToolCategory.PLUGIN` + `ToolMetadata.source`
（1 枚举成员 + 1 可选字段）/ searchtool 加索引源 / `config.yaml` 加 `plugins:` 段 /
前端插件市场页（抄 ModelLibraryTab 形态）/ 单测（manifest 非法/越权路径/卸载残留）。

### 4.2 P2 MCP stdio client（只 client，只 stdio，只 tools）

- 传输只做 **stdio**：`subprocess` 起子进程，stdin/stdout 走 JSON-RPC
  （initialize → tools/list → tools/call + notifications），**零新依赖**，
  与 httpx 锁无交集。Windows 命令写法注意 `.cmd` 解析。
- 形态：**一个 MCP server = 一个虚拟分类**。连上后调 `tools/list`，
  每个远端 tool 在本地注册一个薄包装：`input_schema` 用远端原样 JSON Schema 直灌
  （`register()` 天生支持），`implementation` 是调 `tools/call` 的闭包，
  `category=PLUGIN` + `source=mcp:<server>` + `needs_confirmation=True`（默认）。
- 三道关全走现成路：发现进 searchtool（描述前缀 server 名，**不动 BM25 本体**）；
  执行走 `handle_action`（Agent 零感知）；结果标不可信进 observation（[28]第六章同款）。
- 配置：`config.yaml` 加 `mcp_servers:`（name/command/args/env/enabled），
  连接失败降级（该 server 工具置灰 + 日志，不阻断别的分类）。
- **子进程铁律**（shell 卡死案教训）：`to_thread` 卸载 + 启动/调用双超时 + 超时 kill，
  僵死进程不得拖住事件循环，验收必含杀进程演练。

### 4.3 P3 MCP Apps host（体验分水岭）

- 落点（按 [28] 4.4.13-14 的三挂载位接着做）：渲染链识别 `_meta.ui.resourceUri` →
  `resources/read` 取 `ui://` → 沙箱 iframe（`sandbox` + CSP，默认禁对外联网，
  通信走 postMessage JSON-RPC，可审计日志）→ 不支持/取失败**降级走现有纯文本**
  （协议自带向后兼容，[28] v4.9 的href 放行实测是同一类"先实测再上线"纪律）。
- `visibility` 照抄（`["model","app"]`）：只给界面的工具不进 Agent 工具列表。
- 验收：官方示例（threejs/map/pdf/system-monitor 四类 server 形态各一）+ 
  恶意 HTML（`javascript:`/外链）被拦的对照组（沿 [28] v4.9 对照组传统）。

### 4.4 P4 Streamable HTTP + OAuth + git 市场（条件成熟再烧）

- 前提：P1–P3 验证"有人用"。HTTP 传输手写 SSE（`httpx==0.26.0` 的 `aiter_lines`
  可用，不升级锁）；OAuth 走桌面浏览器回环（desktop 天然有）。
- git 市场分发 + auto-update（抄 Claude 的 update 语义：只更磁盘版，不动运行中会话）。

## 五、研究中发现的基础问题以及解决方法

### 5.0 先说结论：下表四条，没有一条是当前系统的缺陷，没有一条需要优先"修复"

> 立此节的唯一目的，是防止后人把**约束**当**缺陷**修——尤其是第 1 条：
> 谁以"支持 MCP"为名升级 `httpx`，谁就亲手制造一个 TLS 全断的 P0。
> 四条的性质各不相同：一条是立死的约束，一条是已治理的风险，
> 一条是作用域决策，一条是现成姿态。**对策全是"遵守/复用"，没有"修复"。**

| # | 条目 | 是当前缺陷吗 | 要优先处理吗 | 正确做法 |
|---|---|---|---|---|
| 1 | httpx 锁（0.26.0，官方 MCP SDK 装不得） | **不是**。锁是故意打的：0.28.1 断 TLS 是实测结论（AGENTS.md），锁本身就是修复的结果 | **不修，永远不升级**。任何"为 MCP 升级 httpx"的方案直接否决 | P2 只做 stdio（零依赖，与锁无交集）；P4 手写 SSE + 浏览器回环 OAuth，全程绕开锁 |
| 2 | 子进程僵死风险 | **曾经是，已治理**（shell 卡死案，见 [7]；治理 = `to_thread` 卸载 + 超时 kill，见 AGENTS.md） | 不新立项；MCP stdio 落码时**复用**该治理并把杀进程演练写进验收 | 若审计发现治理有漏项，单独立项补，不归本设计管 |
| 3 | 只做 client 不做 server | **不是**。"谁来连我们"不成立，不做是 YAGNI 决策，不是缺口 | 不做 |
| 4 | 默认不可信 | **不是**。`needs_confirmation` + HITL + 不可信标记是**现成姿态**，不是待补的洞 | 往新表面延伸：远端工具默认 `needs_confirmation=True`，iframe 强制沙箱 + 可审计 |

### 5.1 仍然算数的（照旧执行）

| # | 问题 | 解决方法（不变） |
|---|---|---|
| 1 | 官方 `mcp` SDK 与 httpx 锁冲突（v2 要 httpx2/sse-starlette 等十几个包） | 手写最小客户端；P2 只做 stdio（零依赖），与锁无交集 |
| 2 | MCP stdio = 常驻子进程，有僵死风险 | `to_thread` 卸载 + 双超时 + 超时 kill；杀进程演练进验收 |
| 3 | 只做 client 不做 server | YAGNI 照砍（MCP Apps host 也是 client 侧） |
| 4 | 外部来源默认不可信 | `needs_confirmation=True` + HITL + 结果标不可信；iframe 强制沙箱 + 可审计 |

### 5.2 要升级的（加法，不拆地基）

| # | 部位 | 升级内容 | 为什么不动本体 |
|---|---|---|---|
| 5 | `ToolCategory` | 加 `PLUGIN` 成员 | 枚举 OCP 开口就是干这个的 |
| 6 | `ToolMetadata` | 加 `source` + `ui_meta` 两个可选字段 | dataclass 加字段，旧代码零影响 |
| 7 | searchtool | 索引入口加 SKILL.md 与插件元数据两路 | 只加索引源，不动 BM25（上一版"零改动"说大了，收回） |
| 8 | `config.yaml` | 加 `plugins:` + `mcp_servers:` 两段 | 纯加法，走 `get_config_path()` |
| 9 | observation | 远端结果标不可信 marker | 一小段，[28]第六章同款 |

### 5.3 上一版缺的（本版补上，主体）

| # | 缺项 | 补法 |
|---|---|---|
| 10 | 没有 UI 维（插件长不出界面） | `ui/` 部件 + MCP Apps host（4.3），富客户端代差是主攻方向 |
| 11 | 没有市场与分发 | `marketplace.json` + 设置页市场（抄 ModelLibraryTab 形态） |
| 12 | 没有作用域 | user/project/session，project 绑工作区（[15]/[16]）是独家 |
| 13 | 没有上下文账 | Skills 渐进 + 插件开销计量（M11 口径放大） |
| 14 | Streamable HTTP 没说怎么绕锁 | P4 手写 SSE + 浏览器回环 OAuth，锁不升级 |

**一句话结论：地基（registry 单例、装饰器、`handle_action` 执行链、HITL、
searchtool 本体、httpx 版本）一个不用动；上一版的四个硬约束全部保留；
新增的全是加法；真正的增量在 UI、市场、作用域三处——那也是创新所在。**
