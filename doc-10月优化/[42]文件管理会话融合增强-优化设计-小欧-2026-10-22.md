## 一、背景与目标

### 2.2 三项重点不足深挖

#### 2.2.1 BR1 台账不落盘（不足 #1/#2）

**台账是什么**：一份"引用流水账"，每条记 `label / path / lineRange / taskId / ts`，供"回上一轮引用"功能回头找文件。铁律是**只存路径不存正文** —— 正文当轮即弃（M1 分层），路径长期有效。

**现状**：

```
写入  pushSentRefs(sessionId, taskId, refs)   chatStreamStore.ts:809
读取  getSentRefLedger(sessionId, taskId)      chatStreamStore.ts:827
渲染  ↩ 本轮引用：a.md L12-20                   TaskListPanel.tsx:565-584
落盘  ✗ 无 —— toBackupOf() 未含该字段          chatStreamStore.ts:446-472
```

**后果矩阵**：

| 使用场景 | 台账 | 用户感受 |
|---|---|---|
| 不刷新，连续使用 | ✅ 在 | 正常 |
| **F5 刷新** | ❌ 丢 | "刚才引用的那个文件呢？" → 功能像是坏了 |
| **崩溃 / 关标签页重进** | ❌ 丢 | 同上 |
| 换会话再切回 | ❌ 丢（内存条目被 evict） | 同上 |

**根因**：台账被当成"运行时临时态"存在 `ChatStreamSession` 上，而**会话备份链 `toBackupOf()` 是逐字段手工列举**的 —— 没被列举的字段就永远不落盘。这是"手工列举式备份"的结构性缺口（该文件 2026-09-30 已因同类问题修过一次：`heartbeatTs` 漏抄被静默丢弃）。

**为什么必须修**：`restore()`（`:1216-1265`）用的是**展开式**恢复（`Object.assign(d, rest, {...})`），所以只要把台账加进备份类型 + `toBackupOf()`，**恢复侧零改动**。这是一处加字段的活，不是重构。

#### 2.2.2 产出物路径是死文本（不足 #3）

**现状**：`StaticStatsBlock.tsx:334-372` 把 `artifacts` 逐条渲染，第 5 列是路径：

```tsx
<span style={{ color: Colors.TEXT.PRIMARY, fontFamily: FontFamily.MONO, ... }}>
  {a.path}          // ← 纯文本，不可点
</span>
```

**讽刺之处**：同一份产物路径，**在 Agent 的答复正文里已经能自动转成可点卡片**（文档[28] v5.19 的 J5 裸路径识别，`FileRefChip.tsx:278-299`）；**在产出物列表里却是死的**。最确定的路径反而最不可点。

**修完之后的用户路径**：

```
右栏「产出物」第 2 条  E:\test_dir\out\report.md
   └─ 点击 → /files?path=out/report.md → 树逐级展开 → 右侧预览定位
             └─ 预览区「引用到对话」→ 输入框 token → 发给 Agent
```

一条龙闭环，从"手抄路径"降到"点两下"。

#### 2.2.3 文档对 J4 的结论已过期（不足 #4）

文档[28] M2（`:211`）写：「`chat_tasks.artifacts` 列**全库零 UPDATE 写入** → J4 移出本期」。**实码已不成立**：

```
agent_runner.py:811   artifacts=getattr(agent.telemetry, "_artifacts", None)
storage.py:414-425    ("artifacts", artifacts) → safe_json_dumps → UPDATE chat_tasks
storage.py:993        get_task_detail 反序列化回 list
task.api.ts:138       TaskDetail.artifacts: TaskArtifact[] | null
```

即：**产出物数据早已在库里、早已下发到前端**，只剩"渲染成死文本"这一处没接。

### 3.2 体验增强效果（Before / After 场景剧本）

> 只写用户能看见的变化；技术细节见第四章。

#### 剧本 A：长会话后引用过的文件，想再给 Agent 一次

| | 现状（Before） | 优化后（After） |
|---|---|---|
| 路径一 | 刷新页面 → `↩ 本轮引用` 行消失 → 只能凭记忆去文件页翻 | 刷新页面 → 行仍在 → 点 chip → **现场重读最新文件** → token 落定 |
| 路径二 | 换会话回来 → 台账已丢 | 打开「引用历史」抽屉 → 看到过去 3 个会话引用过的文件 → 搜索 → 一键再引用 |
| 关键点 | 台账"活不过一次刷新" | **引用记忆跨会话、跨刷新**（只存路径，实时重读，永不过期） |

#### 剧本 B：Agent 刚给我生成了一份报告

| | 现状（Before） | 优化后（After） |
|---|---|---|
| 找文件 | 右栏「产出物」显示路径 → **用眼睛抄下来** → 切文件页 → 粘贴搜索 | 右栏「产出物」路径**本身就是链接** → 点 → 文件页已展开定位 → 「引用到对话」→ 发回 Agent |
| 二次加工 | 想改报告再让 Agent 改 → 复制路径 → @ 补全里找 | 深链直达 → 选中要改的行 → 引用（带行号）→ 精确告诉 Agent"改这三行" |

#### 剧本 C：Agent 会不会动我的文件？

| | 现状（Before） | 优化后（After） |
|---|---|---|
| 判断依据 | 树上 `●` = "动过" —— 读和写**分不清** | `●`=读过、`✎`=**被改写过**；改写过的用醒目色 + 提示 |
| 风险感知 | 不知道自己辛苦写的文件被覆盖了 | 一眼看出"这三个文件被改过"，点开对比 |
| 附加 | — | 会话页的工作目录**可点直达文件页**，不用手抄 |

#### 剧本 D：让 Agent 一次看一组文件

| | 现状（Before） | 优化后（After） |
|---|---|---|
| 多文件 | 逐个 @ 补全引用 → token 栏爆炸 → Agent 收到 N 段散块，看不出相互关系 | 多选 5 个 → 「作为一组引用」→ **一个 token** → 正文含文件清单 + 各文件内容 → Agent 看得出"这批文件是一套 / 是两个版本" |
| 成本 | — | 零新增后端端点（并发调 `/files/read`，包内无 path → 后端 `sanitize_refs` 放行、`_render_refs_block` 以 label 作锚） |

### 4.2 实施顺序与门禁

| 阶段 | 内容 | 依赖 | 过线门禁 |
|---|---|---|---|
| **一阶段** | O7.1（失败缓存）→ O1（台账落盘+响应式）→ O3（产出物可点） | 无 | `npm run check:full` 绿；刷新后台账仍在；产出物路径可点且根外路径退化为纯文本 |
| **二阶段** | O4（双标记）→ O5（反链 + 禁区提示） | 一阶段（共用 `fileOps.ts` / `FilePathLink.tsx`） | 树 `✎` 只标改写过的；工作区目录可点；`code_root_blocked` 提示可见 |
| **三阶段** | O2（引用历史面板） | 一阶段（台账已落盘） | 跨会话可见、可搜索、再引用内容为最新盘面 |
| **四阶段** | O6（上下文包） | 二阶段（多选 UI 已存在） | 5 文件打包成一个 token；Agent 侧渲染为一段引用块；超阈值有提示 |
| **贯穿** | O7.2（补 T9-g）→ O7.3（文档[28] 回写） | 各阶段同步 | 红线取证：改坏 → 变红 → 还原 |

**贯穿铁律**：① 每条契约用例"改坏→红→还原"证据入库；② 每阶段 `npm run check:full`（**注意 `check` 不含任何 typecheck**）；③ 本轮新增的测试文件按 AGENTS 规矩**不提交**，以文档[28] 已有的"本地测试 + 红线取证"方式留证。

### 4.3 明确不做（YAGNI，防蔓延）

| 项 | 不做的理由 |
|---|---|
| 新增 `GET /files/read-batch` 批量读取端点 | O6 用前端 `Promise.all` 并发调 `/files/read` 即可；端点无必要（文档[28] §5.9.3 #5 维持备案） |
| 新增 `GET /files/session-trail` 会话级 steps 聚合端点 | 无真实需求（文档[28] §5.9.3 #4 维持备案） |
| 会话级产出物聚合端点 | **不做**：单任务 `detail.artifacts` 已足够（用户看的是"这轮产出"）；真需要时再加，届时再说 —— 避免"为以后可能用得上"新开端点 |

### 5.2 O7.1：recent-files 失败不再永久缓存空（地基小修）

**问题**：现实现把失败吞成空数组后**照样 `cache.set`**（`useRecentFiles.ts:33-42`）→ 一次网络抖动后，足迹面板与树上 `●` 集体空态，直到用户手动刷新（该 hook 无自动失效）。

import React, { useMemo, useState } from 'react';

            >
              <FileOutlined style={{ color: Colors.PRIMARY }} />
              <Tooltip title={e.path}>
                <span
                  style={{
                    flex: 1,
                    minWidth: 0,
                    overflow: 'hidden',
                    textOverflow: 'ellipsis',
                    whiteSpace: 'nowrap',

                    color: Colors.TEXT.PRIMARY,

                >
                  {e.label}
                </span>
              </Tooltip>

                type="button"
                onClick={() => void reuse(e.path)}
                aria-label={`引用 ${e.label}`}
                title="引用到对话"
