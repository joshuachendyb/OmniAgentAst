## 一、当前的目录构建和使用现状分析

### 1.1 判据散落在代码里，判定与数据分离

**"哪些目录算禁区、哪些算白名单"这批数据没有以清单形式存在**，而是硬编码成一段段判据代码分布在多个函数中。后果有四个：

1. **无法审计** —— 想知道"到底哪些目录被禁了"必须逐函数读代码；
2. **无法配置** —— 临时放开某个目录必须改代码发版；
3. **同一语义多处实现** —— "路径是否落在某根之下"在 `check_whitelist` 与 `is_allowed_root_itself` 中各有一份写法不同的实现；
4. **新增一类目录要改多处** —— 判据函数、取值函数、判定分支都要动。

### 1.2 禁区判据（代码内硬编码）

统一入口 `path_classify_category.classify_forbidden_path(file_path, mode)`，返回 `(category, msg)`，`category ∈ {"system", "non_system", None}`。内部按序执行：

| 序 | 判据 | 实现位置 | 语义 | 产出类别 |
|---|---|---|---|---|
| 1 | 磁盘根（任意盘符） | `is_disk_root` | splitdrive 后剩余为空 | system |
| 2 | 系统敏感文件（Windows 相对精确） | `FORBIDDEN_PATHS_WINDOWS_REL_EXACT` | 与 `{系统盘}+项` 精确相等 | system |
| 3 | 系统敏感目录（Windows 相对前缀） | `FORBIDDEN_PATHS_WINDOWS_REL_PREFIX` | 以 `{系统盘}+项` 开头 | system |
| 4 | 系统保护目录名 | `is_system_protected_path` | 根下**第一层目录名**命中 `SYSTEM_PROTECTED_DIR_NAMES`（windows / program files / program files (x86) / programdata / boot / recovery / winnt / system32 / system） | system |
| 5 | 代码目录 | `is_code_root_path` | 落在 `get_code_root()` 自身及其子级 | non_system |
| 6 | 允许根自身及其上级 | `is_allowed_root_itself` | 等于某允许根，或等于其祖先目录 | non_system |

Linux 侧 `FORBIDDEN_PATHS_EXACT` / `FORBIDDEN_PATHS_PREFIX`（`/etc/shadow`、`/etc/sudoers`、`/proc`、`/sys`）在判据 5/6 之后执行，产出 system。

判据 4 有一处耦合：`is_system_protected_path` 按 `mode` 过滤（`read` 不拦），判据函数内部混入了操作线策略。

### 1.3 允许范围：三条互不相干的路径各取一次

同一份"允许范围"在系统里有三个独立取值口：

```
路径 A · 白名单取值壳
  path_check_common.resolve_allowed_paths(allowed_paths)
    └─ allowed_paths 为 None → path_env.get_default_allowed_paths()
         = 用户目录 + 系统临时目录 + get_allowed_roots(会话工作区)
    └─ path_check_common.check_whitelist(file_path, allowed_paths)

路径 B · 禁区判据 6
  path_classify_category.is_allowed_root_itself(file_path)
    └─ get_allowed_roots(session_workspace_paths())       # 现场再取一次
    └─ 判"等于根 或 等于根的祖先"

路径 C · 删线独立判定
  delete_path_check.check_delete_permission(:154)
    └─ allowed_roots = get_allowed_roots(session_workspace_paths())   # 第三次再取
    └─ inside_proj = any(p == root or root in p.parents ...)
```

**三条路径的集合定义还不一致**：路径 A 含用户目录与临时目录，路径 B/C 只含项目根 + 授权目录 + 会话工作区。

### 1.4 判据到结果的三线策略矩阵（现状）

| category | 读 | 写 | 删 |
|---|---|---|---|
| `system` | 放行 | blocked 不授权 | blocked 不授权 |
| `non_system` | 放行 | 确认 + auth_path | blocked 不授权 |
| `None` + 不在白名单 | 放行 | 确认 + auth_path | 确认 + auth_path |
| `None` + 在白名单 | 放行 | 放行 | 放行 |
| 路径含 `..` | blocked | blocked | blocked |
| 异常 | blocked | blocked | blocked |

> 读线一律放行，与 `delete_path_check.py` 文件头的权限总表一致。

### 1.5 没有统一构建时机，且存在重复构建

- `classify_forbidden_path` 被调时内部实时调 `get_code_root()`、`get_allowed_roots(session_workspace_paths())`；
- 白名单侧被调时实时调 `get_default_allowed_paths()`，而它**内部又调一次** `get_allowed_roots(...)`；
- 执行层 `delete_file._guard_forbidden_delete` 再走一遍 `classify_forbidden_path`。

一次任务内同一批根被取 N 遍。**没有单一构建时机，就没有单一数据源，也就没有一致性保证。**

### 1.6 无目录范围落库记录

`chat_tasks` 现有列无目录范围字段。事后排查"这个路径为什么被拦"只能翻代码与当前配置，**无法还原任务执行当时的目录范围**。

## 二、目录数组清单归一化需求要点

### 2.1 需求要点

1. **分类口径**：目录归两类 —— 禁区（分系统、非系统两档）与白名单；
2. **数据形态**：三类名单全部一维数组；每项是构建期展开完成的**完整目录路径**（严禁半截路径）；第二字段是 `label`；
3. **一个结构**统一存放三类数组；
4. **构建时机**：在**安全模块入口 `check_before_execute`**（一个 loop = 一次工具执行前的安全检查）开头构建一次，本次 loop 内严禁二次构建；
5. **根即名单项**：对任一待判路径，根里还是根外完全依据这份名单判定；
6. **原样落库**：构建好的清单原样存入 task 表，供事后回溯；
7. **全系统收口**：散落各处的"取目录"函数全部汇集到 build；只服务目录判定的取值函数直接删除。

### 2.2 七条硬要求

| 要求 | 验收标准 |
|---|---|
| **单一数据源** | 判定函数内不再出现硬编码目录常量 |
| **单一构建时机** | 一次 loop（一次 `check_before_execute`）内 `build_directory_lists()` 调用次数恒为 1 |
| **路径完整性** | 名单中不存在任何相对项、半截项、待拼接项 |
| **根里根外单一判定** | 只存在 `locate` 一个实现 |
| **命名唯一** | 实施后 §1.8.1 的作废名零命中 |
| **无跨 loop 全局态** | 名单按 loop 作用域传递 |
| **原样可落库** | 落库 JSON 三个数组齐全，无裁剪 |

### 2.3 明确不做

- **不做跨 loop 名单缓存**（每 loop 重建是需求要求，不是缺陷）；
- **不把名单内容做成配置项**（是否可配后续单独评估，接口已按 §3.3.1.1 预留）；
- 非目录类安全开关（`security.system.*` / `security.hitl.*` 九项 + 五项工具线开关）不在本章范围，**全部见第五章**。

## 三、优化方案

### 3.1 思路

把"哪些目录是什么性质"从代码里抽出来，变成**在安全模块入口每个 loop 构建一次的目录数组**；判定侧退化为**只查这份名单**。

```
现状：判定函数 = 判据代码 + 常量 + 关系推断    取值散落三条路径, 集合定义还不一致
优化：build_directory_lists()  全系统唯一目录取值口, 在 check_before_execute 构建一次
      locate()                全系统唯一的根里/根外判定, 取最深命中
      classify_scope()        五档归属判定链
      判定函数                 只读名单, 无常量、无推断、无独立取值
      构建结果                 原样序列化落库
```

### 3.2 名单结构

```python
@dataclass(frozen=True)
class DirRule:
    path: Path    # 构建期展开完成的完整路径
    label: str    # 语义标签, 供日志与提示消息

@dataclass(frozen=True)
class DirectoryLists:
    forbidden_system_path: List[DirRule]
    forbidden_non_system_path: List[DirRule]
    whitelist_path: List[DirRule]
```

三个一维数组，类型统一，判定侧用同一套函数遍历。**只有两个字段** —— 覆盖范围不靠字段表达，靠"命中自身"与"命中最深条目"在判定时算出来。

### 3.3 名单内容

#### 3.3.1 `forbidden_system_path` —— 常量清单，跨平台

`forbidden_system_path` 是 `DirectoryLists` 上的**一个字段（变量），类型是 `List[DirRule]`**，与另外两个名单同构。它的内容由**模块级常量清单**产出，与 Windows / Linux 平台无关 —— 平台差异只体现在"怎么拼根"，不体现在名单结构。

**常量清单（内置基线，代码单一真源）**：

```python
# 磁盘根: 只判自身, 由平台决定挂哪个根
DISK_ROOT_LABEL = "磁盘根目录"

# 系统保护目录名: 与盘符/挂载点无关的纯名字, 构建期才拼成完整路径
SYSTEM_PROTECTED_DIR_NAMES = (
    "windows", "program files", "program files (x86)",
    "programdata", "boot", "recovery", "winnt", "system32", "system",   # Windows
)

# 跨平台系统禁区: 全路径原样入名单(文件精确 / 目录含下级)
FORBIDDEN_SYSTEM_EXACT = (          # 文件, 仅自身
    "/etc/shadow", "/etc/sudoers",
)
FORBIDDEN_SYSTEM_PREFIX = (         # 目录, 自身 + 下级
    "/proc", "/sys",
)
```

**构建规则**（`_build_forbidden_system_path()`）：

1. 加磁盘根 —— Windows 取 `get_system_drive() + "\\"`，Linux 取 `"/"`；label 一律 `磁盘根目录`，**只判自身**；
2. 遍历 `SYSTEM_PROTECTED_DIR_NAMES`，拼成 `{根}{名字}`（Windows 得 `C:\Windows`，Linux 得 `/windows`）；
3. **若该路径在已加入条目的下级之下，跳过不加入**（例如把某条配置成根下的子目录时）；
4. `FORBIDDEN_SYSTEM_EXACT` / `FORBIDDEN_SYSTEM_PREFIX` 原样入名单；
5. **不展开任何下级文件与目录**（`C:\Windows\WinSxS`、`C:\Windows\System32\config` 及 5 个 hive 文件均不加入，命中 `C:\Windows` 即可）。

**Windows 上的产出（10 条）**：

| 路径 | label | 匹配 |
|---|---|---|
| `C:\` | 磁盘根目录 | **仅自身** |
| `C:\Windows` | 系统保护目录 | 自身 + 下级 |
| `C:\Program Files` | 系统保护目录 | 自身 + 下级 |
| `C:\Program Files (x86)` | 系统保护目录 | 自身 + 下级 |
| `C:\ProgramData` | 系统保护目录 | 自身 + 下级 |
| `C:\Boot` | 系统保护目录 | 自身 + 下级 |
| `C:\Recovery` | 系统保护目录 | 自身 + 下级 |
| `C:\Winnt` | 系统保护目录 | 自身 + 下级 |
| `C:\System32` | 系统保护目录 | 自身 + 下级 |
| `C:\System` | 系统保护目录 | 自身 + 下级 |

> **`C:\System32` 必须单列，不能因为"它是系统目录"就省掉**：它与 `C:\Windows` **平级**（真正被 `C:\Windows` 覆盖的是 `C:\Windows\System32`），`_is_under()` 判它不在 `C:\Windows` 之下，因此构建时会被正常加入。现状 `is_system_protected_path` 按"根下第一层目录名"匹配，`C:\System32` 的第一层就是 `System32`，**现状确实拦它** —— 省掉这条是安全倒退。

只有 **C 盘进系统禁区**，`D:\` / `F:\` 等其他盘符不进（常量里根本不枚举盘符，只有一个"当前系统盘根"），走白名单外。

**Linux 上的产出**：`/`（磁盘根，仅自身）+ 4 条跨平台禁区 + 9 个拼在 `/` 下的系统目录名（多数不存在，`_complete()` 自动丢弃）。同一套代码、同一份名单结构，零平台分支。

#### 3.3.1.1 配置化接口预留（本期只落常量，机制先留好）

名单**当前的唯一来源是上面那几行模块级常量**。为后续"设置页可改"预留三点，**本期不实现配置读写**，只保证将来接上时不需要改结构：

| 预留点 | 做法 | 本期状态 |
|---|---|---|
| **来源可替换** | `_build_forbidden_system_path()` 只依赖 `SYSTEM_PROTECTED_DIR_NAMES` / `FORBIDDEN_SYSTEM_EXACT` / `FORBIDDEN_SYSTEM_PREFIX` 三个常量，**不硬编码任何具体路径**；将来加一层 `_configured_forbidden_extra()` 返回用户配置项，在第 2 步之后并入即可 | 常量直供 |
| **结构不变** | 用户配置进来后仍是 `DirRule(path, label)`，判定侧 `locate` / `classify_scope` / `PERMISSION` **零改动** | 已就位 |
| **默认不落盘** | 配置化时默认策略应与常量一致（空配置 = 用内置），避免"配置缺失=安全裸奔" | 待实现 |

三条名单的**配置化路径完全对称**：将来加 `_configured_forbidden_non_system_extra()` / `_configured_whitelist_extra()`，各自在同名 `_build_*` 的最后并入即可。

#### 3.3.2 `forbidden_non_system_path`

| 路径 | label | 匹配 |
|---|---|---|
| `get_code_root()` | 代码目录(含其内部子目录) | 自身 + 下级 |
| 各允许根自身（项目根 / 授权目录；**不含会话工作区**） | 允许根自身 | **仅自身** |
| 用户级自启动目录 | 用户自启动目录 | 自身 + 下级 |

> 会话工作区是任务当次的工作目录根，任务要创建它并在其中写文件；把它挂进禁区"仅自身"会让"创建/写会话目录自身"被判需授权（2026-10-20 实测弹窗超时挂死）。其自身可写性由白名单"自身"档（PASS）承载。

#### 3.3.3 `whitelist_path`

| 路径 | label | 匹配 |
|---|---|---|
| `Path.home()` | 用户目录 | 自身 + 下级 |
| 系统临时目录 | 系统临时目录 | 自身 + 下级 |
| 项目根 | 项目根 | 自身 + 下级 |
| 授权目录 | 授权目录 | 自身 + 下级 |
| 会话工作区 | 会话工作区 | 自身 + 下级 |

label 按**真实来源**区分（项目根 / 授权目录 / 会话工作区），三种来源权限语义不同，混写成一个标签等于审计失真。

**白名单是全系统唯一的允许范围**，读、写、删三条线全部以它为准。

### 3.4 归属判定链与权限矩阵

**归属只有一条链，按序走完即定，无第四种情况**：

| 顺序 | 判据 | 归属 |
|---|---|---|
| 1 | 命中 `forbidden_system_path` | **禁区·系统** |
| 2 | 命中 `forbidden_non_system_path` | **禁区·非系统**（禁区优先，到此定案） |
| 3 | 命中 `whitelist_path` 且路径等于条目 | **白名单·自身** |
| 4 | 命中 `whitelist_path` 且路径在条目之下 | **白名单·下级** |
| 5 | 以上均不命中 | **白名单外** |

**权限矩阵（读 / 写 / 删 / 递归删）**：

| 归属 | 读 | 写 | 删 | 递归删 |
|---|---|---|---|---|
| 禁区·系统 | 放行 | 拒绝 | 拒绝 | 拒绝 |
| 禁区·非系统 | 放行 | 确认 | 拒绝 | 拒绝 |
| 白名单·自身 | 放行 | 放行 | 拒绝 | 拒绝 |
| 白名单·下级 | 放行 | 放行 | 放行 | 放行 |
| 白名单外 | 放行 | 确认 | 确认 | 拒绝 |

**父级目录与兄弟目录没有特殊地位**，一律按上面的链走。例：允许根 `F:\proj`、代码根 `F:\OmniAgentAs-repair`

| 路径 | 归属 |
|---|---|
| `F:\proj` | 禁区·非系统（允许根自身） |
| `F:\proj\src\a.py` | 白名单·下级（允许根在禁区名单中**仅判自身**，子级不命中禁区；项目根在白名单中含子级，故落白名单·下级） |
| `F:\`（父级） | 白名单外 |
| `F:\other`（兄弟） | 白名单外 |
| `F:\OmniAgentAs-repair\src` | 禁区·非系统 |
| `F:\其他项目\` | 白名单外 |

**唯一例外**：兄弟目录若被用户**单独授权**（列入 `workspace.allowed_dirs`），它本身就是允许根 → 命中第 2 步。这是显式授权，不是自动放大。

**空名单语义**：禁区名单为空则该类不拦；`whitelist_path` 为空则全部落"白名单外"（**不静默放行**）。

### 3.5 构建时机与传递

**loop = 安全模块的入口 `check_before_execute`（`path_tool_safety_checker.py`）。** 每次工具执行走一次安全总闸，就是一个 loop。

**硬规则：一个 loop 内 `build_directory_lists()` 只调用一次。** 任务运行期间代码根、授权目录、会话工作区、系统盘都是确定的，不存在中途变化。

```
安全模块入口 check_before_execute  ← 一个 loop = 一次工具执行前的安全检查
    │
    ├─ dl = build_directory_lists()      ← 唯一构建点
    ├─ current_directory_lists.set(dl)   ← 挂到当前 loop 上下文
    ├─ save_path_scope_snapshot(...)     ← 原样落库(同一份 dl)
    │
    └─ ↓ 本次 loop 内所有判定读同一份，全链路零重复构建
       ├─ path_legality_router ──┬─ read_path_check      ┐
       │                          ├─ write_path_check     ├─ 均无需改签名,
       │                          ├─ delete_path_check    │  经 ContextVar
       │                          └─ dual_path_check      ┘  自动可见名单
       ├─ shell_path_check
       └─ delete_path_check.guard_forbidden_delete  ← 执行层直调(§4.14-C: 此路径可能无 loop 上下文)
```

用 `ContextVar` 而非普通全局变量或逐层传参：普通全局在并发时 A 任务会读到 B 任务的名单；逐层传参要改 7 个文件签名，而执行层 `tools` 侧根本不在这条调用链上、参数传不过去。

**兜底语义**：读不到名单时抛异常按 fail-closed 阻断，不静默放行、也不重建 —— 确保二次构建在代码层面不可能发生。

### 3.6 原样落库

`DirectoryLists` 同一份结构，运行期供判定、落库供回溯，不另建落库专用结构。

| 项 | 设计 |
|---|---|
| 目标表 | `chat_tasks`（名单随 loop 失效，`chat_sessions` 跨 task 复用会与"每 loop 最新"冲突） |
| 列名 | `path_scope_snapshot` |
| 类型 | `TEXT`（与 `process_events` / `task_summary` 同为 JSON 字符串列） |
| 迁移 | `CREATE TABLE` 内建 + `_ensure_column` 兜底（与 `task_summary` 同源的双保险） |
| 时机 | 与构建点同一处，构建后立即写一次；同 task 多 loop 覆盖同一列，保留最后一次 |

```json
{
  "built_at": "2026-10-19T16:42:05+08:00",
  "forbidden_system_path": [
    {"path": "C:\\", "label": "磁盘根目录"},
    {"path": "C:\\Windows", "label": "系统保护目录"}
  ],
  "forbidden_non_system_path": [
    {"path": "F:\\OmniAgentAs-doc40-ws", "label": "代码目录(含其内部子目录)"},
    {"path": "F:\\OmniAgentAs-doc40-ws\\backend", "label": "允许根自身"}
```

**全量原样入库，不裁剪、不设阈值。** 三条名单合计约 20 条 × 100 字节 ≈ 2 KB，`TEXT` 列无压力。

| 情形 | 处理 |
|---|---|
| 序列化或写库抛异常 | 记 warning，不阻断判定（`ContextVar` 已挂好，判定照常） |
| `task_id` 缺失（`/tool/execute` 直调无任务行） | 跳过落库，不报错 |
| UPDATE 命中 0 行 | 记 debug 日志 |

```python
def _get_system_drive() -> str:
    """动态获取真实系统盘符(三级探测, 全失败回落 C:)"""
    for var in ("SystemRoot", "WINDIR"):
        root = os.environ.get(var)
        if root:
            drive, _ = os.path.splitdrive(root)
            if drive:
                return drive
    sdrive = os.environ.get("SystemDrive", "")
    if sdrive:
        return sdrive.rstrip("\\/")
    if os.name == "nt":
        for c in "CDEFGHIJKLMNOPQRSTUVWXYZ":
            if os.path.isdir(f"{c}:\\Windows"):
                return f"{c}:"
    return "C:"


def _system_temp_dir() -> Path:
    """系统临时目录(Windows 取 TEMP/TMP, 其他平台回落 /tmp)"""
    if os.name == "nt":
        temp = os.environ.get("TEMP") or os.environ.get("TMP")
        if temp:
            return Path(temp)
    return Path("/tmp")


# ────────────────── 路径格式化(全系统唯一实现) ──────────────────

#: Windows 扩展长度前缀
_EXT_PREFIX = "\\\\?\\"


def strip_windows_prefix(raw: str) -> str:
    """剥离 Windows 扩展长度前缀 \\?\\ — 小欧 2026-10-19

    两种来源都只此一处剥离:  LLM 直给的 `\\\\?\\C:\\x`;
     Windows `os.path.realpath` 对尾空格/超长路径**自产**的 `\\\\?\\`。
    UNC 分支还原: `\\\\?\\UNC\\srv\\share` -> `\\\\srv\\share`(其余 `\\\\?\\X` -> `X`)。
    """
    if raw.startswith(_EXT_PREFIX):
        rest = raw[len(_EXT_PREFIX):]
        if rest[:4].lower() == "unc\\":
            return "\\\\" + rest[4:]
        return rest
    return raw


def format_path(file_path: str, require_absolute: bool = False) -> str:
    """路径格式化唯一实现(全系统唯一真源) — 小欧 2026-10-19

    口径(顺序固定): 剥入参 `\\\\?\\` → expanduser → realpath(解 symlink / `..` / 8.3 短名 /
    正斜杠)→ **再剥** realpath 自产的 `\\\\?\\` → 折叠重复分隔符 → 去尾部分隔符(盘根 `X:\\` 保留)
    → 盘符统一大写(Windows)。

    名单构建 _complete / 查询 classify_path / 安全模块入口(工具 path/dest 值)三处共用本函数 ——
    保证"名单里是什么格式, 工具参数就是什么格式"; 两边若各写一遍 realpath, 口径一改即分裂。

    require_absolute=True: expanduser 后先判绝对性, 相对路径直接抛 ValueError(不在 realpath 前
    按 cwd 猜基准)。仅供名单构建使用 —— 名单条目必须"绝对且真实", 相对路径入名单等于把名单
    锚到构建时的 cwd, 换进程/换目录即错位。工具参数侧保持 False(相对路径仍按 cwd 解析, 不误拦)。
    """
    _raw = str(file_path).strip()                     # 2026-10-20 小欧 - FIX: 首尾空白不归一会把相对路径挂错基准
    if _raw in ("", ".", ".."):                       # 2026-10-20 小欧 - FIX: 无绝对语义, realpath 会解析成 cwd 泄漏
        raise ValueError(f"路径无绝对语义: {file_path!r}")
    p = strip_windows_prefix(_raw)
    # 2026-10-20 小欧 - FIX: 盘符段外的冒号(NTFS ADS)交 realpath 会被毁成 `x:ads`(实测),
    #   改走 abspath 保留原样, 由安全线按真实拼写裁决
    _drive = ntpath.splitdrive(p)[0]
    _skip_realpath = (":" in p[len(_drive):]) if _drive else (":" in p)
    p = os.path.expanduser(p)
    # 2026-10-20 小欧 - 绝对性守卫放进唯一格式化链, 避免 _complete 重复 expanduser/isabs
    if require_absolute and not os.path.isabs(p):
        raise ValueError(f"路径无绝对语义(相对路径不入名单): {file_path!r}")
    try:
        p = os.path.abspath(p) if _skip_realpath else os.path.realpath(p)
    except (ValueError, OSError):
        p = os.path.abspath(p)
    p = strip_windows_prefix(p)
    p = os.path.normpath(p) if p else p          # 折叠重复分隔符 / 统一分隔符
    if len(p) > 1:
        stripped = p.rstrip("\\/")
        # 盘根 `C:\\` 去尾后成 `C:`, 需还原; 其余一律去尾部分隔符
        p = (stripped + os.sep) if stripped.endswith(":") else (stripped or p)
    if os.name == "nt" and len(p) > 1 and p[1] == ":":
        p = p[0].upper() + p[1:]                 # 盘符统一大写
    return p


def _complete(path) -> Optional[Path]:
    """展开为完整真实路径; 失败返回 None(该项跳过, 不留半截路径)

    名单完整性的唯一守门点: 任何进入名单的路径都必须经此展开为绝对真实路径。
    格式化与"绝对性"两项检查全部走 format_path(require_absolute=True), 本函数不再
    自行 expanduser/isabs 预判, 保证全系统只有一条解析链 — 小欧-2026-10-20
    """
    try:
        return Path(format_path(path, require_absolute=True))
    except (ValueError, OSError, TypeError):
        return None


def _is_under(child: Path, parent: Path) -> bool:
    """child 是否在 parent 之下(不含相等)

    2026-10-20 05:27 小欧 - FIX: 原先安全性依赖"两侧都过 format_path"的调用纪律
    (字符串前缀匹配不校验输入), 新增消费点直送 raw 即整套失效; 现层内自证——两侧先
    normcase(统一大小写/分隔符)+normpath(消冗余拼写)再做前缀比较, 约定升级为函数级保证
    (不引入 realpath, 判定热路径零 IO 开销)。
    """
    _c = os.path.normcase(os.path.normpath(str(child))).rstrip("\\/")
    _p = os.path.normcase(os.path.normpath(str(parent))).rstrip("\\/")
    # 2026-10-20 小欧 - 平台根("/")归一后为空串, 空串 + os.sep 会退化为"任意绝对路径",
    #   这里显式按"在平台根之下"处理, 避免空串前缀造成误命中 — 小欧-2026-10-20
    if not _p:
        return _c.startswith(os.sep)
    return _c.startswith(_p + os.sep)


def _collect_white_list_scope_entries(include_session: bool) -> List[Tuple[str, str]]:
    """收集"路径作用域条目" [(原始路径, 来源标签)] — 小欧 2026-10-20

    返回带来源标签的条目(非纯根路径集合), 原始串交调用方 _complete 统一格式化。

      会话工作区是任务当次的工作目录根, 任务要创建它并在其中写文件; 把它挂进禁区
      "仅自身"会让"创建/写会话目录自身"被判需授权(2026-10-20 实测弹窗超时挂死)。
      其自身可写性由白名单"自身"档(PASS)承载。
    fail-closed: 读取异常即抛 RuntimeError, 不用空列表静默降级
    标签必须是真实来源(项目根 / 授权目录 / 会话工作区), 供白名单落库与日志区分 ——
      三种来源权限语义不同, 混写成一个标签等于审计失真。

    try:
        cfg = get_config()

def _platform_root() -> str:
    """平台根: Windows 取系统盘符根, Linux 取 /

    名单里只挂**当前平台的根** —— 其它盘符(D:/F:/E: ...)不进禁区, 走白名单外。
    """
    return (_get_system_drive() + "\\") if os.name == "nt" else "/"


def _build_forbidden_system_path() -> List[DirRule]:
    """构建禁区·系统一维数组 —— 来源是模块级常量清单, 跨平台同一套代码

    构建规则:
      (1) 磁盘根 —— label 磁盘根目录, 判定时只判自身(否则整盘命中)
      (2) 系统保护目录名 -> 拼在平台根下; 下级候选跳过(不下级)
      (3) 跨平台系统禁区: 文件精确 / 目录含下级
    将来接配置化时, 在 (3) 之后并入 _configured_forbidden_extra() 即可, 结构不变。
    """
    rules: List[DirRule] = []
    plat_root = _platform_root()

    # (1) 平台根 —— 只判自身
    root = _complete(plat_root)
    if root is not None:
        rules.append(DirRule(root, _DISK_ROOT_LABEL, self_only=True))

    # (2) 系统保护目录 —— 自身+下级; 下级候选跳过
    #   2026-10-20 小欧 - 跳过条件改用结构字段 self_only(原靠 label != 磁盘根目录)
    for name in SYSTEM_PROTECTED_DIR_NAMES:
        p = _complete(os.path.join(plat_root, name))
        if p is None:
            continue
        if any(_is_under(p, r.path) for r in rules if not r.self_only):
            continue                                   # 在已加入条目的下级之下 -> 不加入
        rules.append(DirRule(p, "系统保护目录"))

    # (3) 跨平台系统禁区(文件精确 / 目录含下级)
    for item in FORBIDDEN_SYSTEM_EXACT:
        p = _complete(item)
        if p is not None:
            rules.append(DirRule(p, "系统禁区(精确)"))
    for item in FORBIDDEN_SYSTEM_PREFIX:
        p = _complete(item.rstrip("/"))
        if p is not None:
            rules.append(DirRule(p, "系统禁区(前缀)"))

    return rules


def _build_forbidden_non_system_path() -> List[DirRule]:
    """构建禁区·非系统一维数组: 代码目录(自身+下级) + 允许根自身(仅自身)

    2026-10-20 小欧 - 允许根自身集只用 项目根+授权目录(不含会话工作区): 会话目录需被任务
      创建/写入, 其可写性由白名单自身档承载; 构建异常上抛, 由安全入口单点转 blocked。
    """
    rules: List[DirRule] = []
    code_root = get_code_root()
    full = _complete(code_root) if code_root else None
    if full is not None:
        rules.append(DirRule(full, "代码目录(含其内部子目录)"))
    for r, _source in _collect_white_list_scope_entries(include_session=False):
        full = _complete(r)
        if full is not None:
            rules.append(DirRule(full, _ALLOWED_ROOT_SELF_LABEL, self_only=True))
    # 2026-10-20 05:27 小欧 - FIX: 用户级自启动挂入(含下级——启动项文件在目录内, 仅自身堵不住);
    #   全局级(All Users)Startup 在 ProgramData 系统保护目录下级, 已被禁区·系统覆盖, 不重复挂
    _startup = _complete(str(Path.home() / "AppData/Roaming/Microsoft/Windows/Start Menu/Programs/Startup"))
    if _startup is not None:
        rules.append(DirRule(_startup, _STARTUP_LABEL))
    return rules


def _build_whitelist_path() -> List[DirRule]:
    """构建白名单一维数组 = 全系统唯一允许范围(自身+下级)

    2026-10-20 小欧 - 构建异常上抛, 不留残缺白名单, 由安全入口单点转 blocked。
    """
    rules: List[DirRule] = []
    for raw, label in ((Path.home(), "用户目录"), (_system_temp_dir(), "系统临时目录")):
        full = _complete(raw)
        if full is not None:
            rules.append(DirRule(full, label))
    for r, source in _collect_white_list_scope_entries(include_session=True):
        full = _complete(r)
        if full is not None:
            rules.append(DirRule(full, source))     # 标签=真实来源(项目根/授权目录/会话工作区)
    return rules


def _build_directory_lists() -> DirectoryLists:
    """构建本 loop 的目录名单(唯一构建口 / 全系统唯一目录取值口)

    调用点唯一: 安全模块入口 check_before_execute 开头(一个 loop = 一次安全检查), 每 loop 一次。
    构建后必须由调用方 _current_directory_lists.set(dl) 挂到本 loop 上下文。
    loop 内严禁二次调用 —— 任何"就近再取一次目录"都应改从名单读。
    """
    return DirectoryLists(
        forbidden_system_path=tuple(_build_forbidden_system_path()),
        forbidden_non_system_path=tuple(_build_forbidden_non_system_path()),
        whitelist_path=tuple(_build_whitelist_path()),
    )


def _current_or_build() -> DirectoryLists:
    """取当前 loop 名单; 无 loop 上下文(执行层直调)时就地构建一次返回

    用于 delete_file / temp_auth 这类"无任务上下文直调"的执行层路径: 该路径从未经过
    check_before_execute, ContextVar 必然为空。此种临时构建**不写回 ContextVar** ——
    写回会在无作用域时残留, 使紧随其后的 loop 作用域(见 directory_lists_scope 的
    "已存在即复用")误用这份来时不明的旧名单(跨 loop 污染); 直调点各自量小, 现算即用。
    """
    dl = _current_directory_lists.get()
    if dl is not None:
        return dl
    return _build_directory_lists()


@contextmanager
def directory_lists_scope(task_id: Optional[str] = None):
    """目录名单作用域 — **一个安全模块 loop = 一次本上下文** — 小欧 2026-10-19

    进入时: **构建一次目录名单(构建点唯一) → 立刻原样落库 → 挂进 ContextVar**;
    退出时自动还原。

    **为什么落库放在这里(生成的那一刻), 而不是调用方拿到之后再存**:
      · 快照的意义就是"这次判定用的到底是哪份名单"。名单**刚生成**是唯一无歧义的时刻 ——
        出了作用域名单就没了, 再去取只能靠 ContextVar 残留, 取不到就是"来路不明"。
      · 原设计把落库放在调用方(总闸返回之后), 一旦有人绕过编排层直接调判定层,
        快照就漏记 —— 而漏记的恰恰是最该被审计的场景。
      · 放在这里 = **带 task_id 时构建一次即落一次账**, 调用方无从遗漏, 也无须记得调
        (无 task_id 的执行层直调见下 Args: 该情形只构建不落库)。

    **可嵌套**: 已在作用域内时直接复用现有名单, **不二次构建、不重复落库** ——
    所以"每 loop 只构建一次"由本上下文管理器在结构上保证, 调用方无从违反。

    Args:
        task_id: 任务 id, 供快照落库定位 chat_tasks 行; 为空(None)则只构建不落库 ——
            执行层无任务上下文的直调(temp_auth / delete_file)走惰性构建, 不经过本管理器,
            故正常情况下这里总能拿到 task_id。

    用法:
        with directory_lists_scope(task_id=agent.task_id):
            ...  # 本 loop 内所有路径判定复用同一份名单
    """
    existing = _current_directory_lists.get()
    if existing is not None:
        yield existing                      # 已在 loop 内 → 复用, 不二次构建不重复落库
        return
    dl = _build_directory_lists()
    _save_snapshot(task_id, dl)             # 生成即刻落库
    token = _current_directory_lists.set(dl)
    try:
        yield dl
    finally:
        _current_directory_lists.reset(token)   # 必须还原: 不还原会顺着 asyncio task 上下文外泄


#: 各任务最近一次已落库的名单内容键(不含 built_at)。用于跳过"内容未变"的重复 UPDATE ——
#: 名单作用域每个工具调用开一次, 同一任务内名单通常不变, 每次 action 都 UPDATE 属写放大。
#: 上限保护: 超出即整体清空(只影响能否跳过写, 不影响正确性)。
_snapshot_keys: dict = {}
_SNAPSHOT_KEYS_MAX = 512


def _save_snapshot(task_id: Optional[str], dl: DirectoryLists) -> bool:
    """把刚生成的名单原样落库(审计辅助) — 小欧 2026-10-19

    Args:
        task_id: 任务 id; 为空只构建不落库
        dl: 本次判定实际使用的名单(与判定对象同一份, 保证快照=判定口径)

    失败只记 warning 不抛: 落库是审计辅助, 不得因它阻断工具执行。
    惰性导入 app.db: 只在真正落库时才引入, 且避免本模块在安全层导入期就把 db 拉进来。
    (app.db 不依赖 app.safety, 无循环依赖。)

    2026-10-20 小欧 - 内容(三数组, 不含 built_at)未变则跳过 UPDATE, 避免每 action 重复写;
      变更即写, 仍保证每任务保留最新一份完整名单。
    """
    if not task_id:
        return False
    key = (dl.forbidden_system_path, dl.forbidden_non_system_path, dl.whitelist_path)
    if _snapshot_keys.get(task_id) == key:
        return False                                  # 内容未变, 不重复写
    try:
        from app.db.task_scope_queries import save_path_scope_snapshot
        ok = save_path_scope_snapshot(task_id, _to_snapshot_json(dl))
        if ok:
            if len(_snapshot_keys) >= _SNAPSHOT_KEYS_MAX:
                _snapshot_keys.clear()
            _snapshot_keys[task_id] = key
        return ok
    except Exception as e:
        logger.warning(f"[path_dir_lists] 目录名单快照落库失败(不影响执行): {e}")
        return False


# ────────────────── 归属判定(全系统唯一) ──────────────────

def _locate(rules: Sequence[DirRule], real_path: Path) -> Tuple[bool, Optional[DirRule], bool]:
    """在一维名单中定位路径, 取最深命中项 — 小欧 2026-10-19 / 2026-10-20

    Returns:
        (hit, rule, is_self) — 自身命中 True; 下级命中 False; 未命中 (False, None, False)
    规则: 自身命中立即定案; self_only=True 的条目只判自身; 多条命中取 path 最深。
    2026-10-20 小欧 - "包含"统一走 _is_under(单一实现), 返回 is_self 免调用方二次比较。
    """
    best: Optional[DirRule] = None
    # 归一为 Path: 误传 str 时 Path 比较恒不相等(自身档静默失效), 此处统一收口 — 小欧-2026-10-20
    rp = Path(real_path)
    for rule in rules:
        if rp == rule.path:
            return True, rule, True                    # 自身命中, 最深, 立即定案
        if rule.self_only:
            continue                                   # 仅自身类条目(盘根/允许根)不向下匹配
        if _is_under(rp, rule.path):
            if best is None or len(rule.path.parts) > len(best.path.parts):
                best = rule                            # 取最深命中
    return (best is not None), best, False


def _classify_scope(dl: DirectoryLists, real_path: Path) -> Tuple[str, Optional[DirRule]]:
    """归属判定链(顺序不可换): 禁区·系统 → 禁区·非系统 → 白名单·自身 → 白名单·下级 → 白名单外"""
    hit, rule, _is_self = _locate(dl.forbidden_system_path, real_path)
    if hit:
        return SCOPE_FORBIDDEN_SYSTEM, rule

    hit, rule, _is_self = _locate(dl.forbidden_non_system_path, real_path)
    if hit:
        return SCOPE_FORBIDDEN_NON_SYSTEM, rule   # 禁区优先, 到此定案

    hit, rule, is_self = _locate(dl.whitelist_path, real_path)
    if hit:
        return (SCOPE_WHITELIST_SELF if is_self else SCOPE_WHITELIST_SUB), rule

    return SCOPE_OUTSIDE, None


def permission_of(scope: str, line: int) -> str:
    """查权限矩阵: 返回 PASS / CONFIRM / DENY"""
    return PERMISSION[scope][line]


def classify_path(file_path: str) -> Tuple[str, Optional[DirRule]]:
    """格式化 + 归属判定 — **全系统唯一的"路径 → 五档归属"入口** — 小欧 2026-10-19

    Args:
        file_path: 原始路径(可含 ~、相对段、symlink)

    Returns:
        (scope, rule) — scope 为五档之一; rule 为命中的名单条目(白名单外为 None)

    格式化口径见 `format_path`(只此一处); 判定链顺序不变(禁区优先, 见 classify_scope)。

    作用域语义(调用方必读):
      在 directory_lists_scope 内 → 用本 loop 唯一名单; 作用域外直调 → 就地临时构建, 不写回
      ContextVar(防跨 loop 污染)。两种路径判定口径相同。构建失败 fail-closed 抛异常, 执行层
      各调用点已包 try, 按"判不出即拒绝"处理。
    """
    return _classify_scope(_current_or_build(), Path(format_path(file_path)))


def _to_snapshot_json(dl: DirectoryLists) -> str:
    """把目录清单原样序列化为 JSON(全量, 不裁剪)"""
    def dump(rules: Sequence[DirRule]) -> list:
        return [{"path": str(r.path), "label": r.label} for r in rules]

    return json.dumps({
        "built_at": datetime.now().astimezone().isoformat(timespec="seconds"),
        "forbidden_system_path": dump(dl.forbidden_system_path),
        "forbidden_non_system_path": dump(dl.forbidden_non_system_path),
        "whitelist_path": dump(dl.whitelist_path),
    }, ensure_ascii=False)
```

### 4.5.1 目录名单作用域：`directory_lists_scope`

**设计（v1.17 原稿）**：暴露 `build_directory_lists` / `get_directory_lists` /
`get_or_build_directory_lists` 三个取值口 + 一个 `current_directory_lists` ContextVar，
由调用方自己管"什么时候建、什么时候还原"。

**落地修正（v1.19，北京老陈批注"路径提供就是目录，为什么还要这些函数"）**：
这个设计**把"清单"当成了需要到处传递的运行时状态**，于是长出了 3 个取值口 + 1 个外露的
ContextVar。但清单的本质是**数据**，外部真正需要的能力只有三件：

1. 判一个路径属于哪一档 —— `classify_path`
2. 查某档某动作是否允许 —— `permission_of`
3. 在一个安全模块 loop 内建一次、退出自动还原 —— **1 个上下文管理器就够**

三个取值口 + 外露 ContextVar 全部多余，且有害：

- `current_directory_lists` 一旦被外部 import，**别的模块就能绕过 loop 作用域直接拿到/改名单**，
  "每 loop 一次"的约束形同虚设；
- `get_directory_lists`（严格口）与 `get_or_build_directory_lists`（宽松口）并存，
  调用方必须先搞清自己在不在 loop 里 —— 这个判断**没有任何业务含义**，纯属实现细节泄漏。

**修法**：ContextVar 与构建/取值全部收进模块私有，外部只看到一个上下文管理器：

```python
@contextmanager
def directory_lists_scope(task_id: Optional[str] = None):
    """目录名单作用域 — 一个安全模块 loop = 一次本上下文"""
    existing = _current_directory_lists.get()
    if existing is not None:
        yield existing                      # 已在 loop 内 → 复用, 不二次构建不重复落库
        return
    dl = _build_directory_lists()
    _save_snapshot(task_id, dl)             # ← 生成的那一刻就落库
    token = _current_directory_lists.set(dl)
    try:
        yield dl
    finally:
        _current_directory_lists.reset(token)


def _save_snapshot(task_id, dl) -> bool:
    """把刚生成的名单原样落库; 失败只记 warning 不抛"""
```

**可嵌套是结构上的关键**：外层（`safety_gate`）已开作用域时，内层（`check_before_execute`）
直接复用现有名单，**不二次构建**。所以"每 loop 只构建一次"由上下文管理器在**结构上**保证，
调用方无论怎么写都破坏不了 —— 这比"靠注释规定调用方别重复构建"强得多。

| v1.17 设计 | v1.19 落地 | 外部可见性 |
|---|---|---|
| `build_directory_lists()` | `_build_directory_lists()` | 模块私有 |
| `get_directory_lists()`（严格） | `_get_current_lists()` | 模块私有（**无人使用，已删**） |
| `get_or_build_directory_lists()`（宽松） | `_current_or_build()` | 模块私有（只被 `classify_path` 调用） |
| `current_directory_lists`（ContextVar） | `_current_directory_lists` | 模块私有 |
| `to_snapshot_json(dl)` | `_to_snapshot_json(dl)` | 模块私有 |
| —（新增） | **`directory_lists_scope(task_id=None)`** | 公开，唯一作用域入口；生成即落库 |

> **落库放在"生成的那一刻"，不放调用方**（北京老陈裁定，v1.20）：
> 快照的意义就是"这次判定用的到底是哪份名单"，而**名单刚生成是唯一无歧义的时刻**。
> 放在调用方有三个坏处：① 出了作用域名单就没了，再取只能靠 ContextVar 残留，取不到就是"来路不明"；
> ② 谁绕过编排层直调判定层就**漏记**，而漏记的恰恰是最该被审计的场景；
> ③ 调用方多一次显式调用，就多一次"忘了调"的机会。
> 放进作用域管理器 = **构建一次必落一次账**，调用方无从遗漏。
>
> 同时**修正 §4.8 的错误论据**：v1.19 曾写"安全层不该碰持久化（落库是编排层的事）"——
> **这是错的**。实测 `app/safety` 已有 6 个模块直接 `import app.db`
> （`trust.py` / `operation_record.py` / `operation_backup_rollback.py` /
> `operation_maintenance.py` / `safety/__init__.py`），且 `app/db` 从不 import `app/safety`
> （无循环依赖）。拿一条自己都不遵守的规矩去否决更合理的方案，是拿规矩挡事实。

### 4.5.2 路径格式化的单一真源：`format_path` / `classify_path`

| `delete_path_check.guard_forbidden_delete` | `Path(...).resolve()` |
| `dual_path_check` | 同上 |
| `shell_path_check` | 同上 |
| `temp_auth` | 同上 |

**为什么这是真问题（不是洁癖）**：格式化口径一改（比如以后要加 `\` → `/` 归一、或加 UNC 路径处理），
要改 7 处；漏改 1 处就是**同一路径在两条线上判出不同归属** —— 而"同一条路径在读线放行、删线拒绝"
这种不一致是最难查的一类安全 bug。delete 线算两遍 realpath 还白费一次文件系统调用。

**修法**：`path_dir_lists` 出两个口，格式化与判定重新成对封装：

```python
def format_path(file_path: str, require_absolute: bool = False) -> str:
    """路径格式化 — 全系统唯一真源（剥 \\?\ → expanduser → realpath → 折叠/去尾 → 盘符大写）
    require_absolute=True: 名单构建用, 相对路径直接抛 ValueError(不锚到 cwd)"""

def classify_path(file_path: str) -> Tuple[str, Optional[DirRule]]:
    """格式化 + 归属判定 — 全系统唯一的『路径 → 五档归属』入口"""
    return _classify_scope(_current_or_build(), Path(format_path(file_path)))
```

7 个调用点全部改调 `classify_path`（`delete_path_check.validate_delete` 另需判"是不是目录"，
调 `format_path(file_path)` 后 `Path(...).is_dir()`）。**格式化代码回到 1 处**。

> **这是"删适配壳"的连带代价，必须补回来才算做完**。删掉 `classify_forbidden_path` 换来了
> "判定入口只有一处"，但同时丢掉了"归一化只有一处"。前者是收益，后者是负债 ——
> 只看收益就把负债忘了，是典型的片面优化。**判据层收口时，要连着把"判据的前半段"一起收口。**

> **v1.17 修正（落地核查发现的真 bug）**：初稿写的是
> `self._check_before_execute(tool_name, params, pool_pids, _bypass, tool_meta)` ——
> 即**把 `tool_meta` 当形参从外层传进来**。但 `tool_meta = tool_registry.get_tool(tool_name)`
> 这行在**内层**（原函数体第一段就查工具元数据），外层根本没有这个名字 →
> 外层引用 `tool_meta` 直接 **NameError**，**每一次工具执行都崩**。
>
> 这个 bug 编译期不报错、`from app.main import app` 也不报错、pytest 更测不到
> （本工作区 `tests/` 被 `.gitignore` 排除，只有 2 个不碰安全总闸的用例）——
> 是靠"手工调一次 `check_before_execute`"才暴露的。**教训：安全总闸这种全局入口，
> 改完必须手工调一次，不能只靠编译和单测。**
>
> 正确切法：**`_bypass` 在外层算**（`security.hitl.enabled` 是门首唯一读取点），
> **`tool_meta` 在内层查**（它属于判定主体的一部分），外层**不传** `tool_meta`。
>
> 补充纪律：**拆函数时，形参只传"外层已经算出来、且内层不会再自己算"的量**；
> 内层自己会算的量一律在内层算 —— 传过去就成了未定义名。

**两条硬约束：**

1. **必须用上下文管理器**，不能用裸 `ContextVar.set()`。`ContextVar` 会随 asyncio task
   上下文复制，不还原会让本次执行构建的名单活到下一次执行去——而"每 loop 一次"的前提是
   每 loop 都重新建。`directory_lists_scope()` 的 `finally` 覆盖整个判定主体。
2. **函数拆两层**是为了让作用域覆盖整个判定主体（含中段 `return _danger` /
   `return self._settle_confirm(...)` 那些提前返回的分支）。

**v1.19 简化**：原设计在外层手写 `token = ...set(...) / try / finally: reset(token)`。
现在这段逻辑已收进 `directory_lists_scope()`，**外层只剩一行 `with`** —— 构建点、还原时机、
嵌套复用三件事全在管理器里，调用方无从写错。

#### C. 落地阻断点（已裁定并解决，见本节末）

`delete_file.py:276-282` 实测代码：

```python
if _current_task_id.get() is None:                      # 无任务上下文(Agent/API 直调)
    from app.safety.delete_path_check import guard_forbidden_delete
    _reason = guard_forbidden_delete(source)              # ← 此时从未经过 check_before_execute
```

**这条路径上 `current_directory_lists` 为空**，而 `get_directory_lists()` 的设计是"读不到就抛 RuntimeError（fail-closed）"。结果：**无任务上下文的删除调用会被自己的安全守卫崩掉**（变成 500 而非安全拒绝）。

"每 loop 只构建一次"这条硬规则约束的是 **loop 内**；此处**不在任何 loop 内**，因此有三种解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **① 就地构建** | `guard_forbidden_delete` 检测到 ContextVar 为空时**就地构建一次**用完即弃 | 不违反 loop 内规则；但"构建点唯一"的表述需放宽为"loop 内唯一，loop 外按需" |
| **② 提前构建** | `delete_file.py` 在调用守卫前先 `build_directory_lists()` 并 set | 改动扩散到 tools 层，且同样要清 ContextVar |
| **③ 缓存兜底** | `get_directory_lists()` 为空时构建并写入 ContextVar | 变成隐式全局缓存，违背设计初衷，且并发下有串味风险 |

**已裁定并落地（v1.16，北京老陈裁定）**：取 **①**，但实现落在 `path_dir_lists` 侧而非调用方 —— 新增 `get_or_build_directory_lists()`：先读 ContextVar，读不到就**当场构建一次**并写回。调用方（`guard_forbidden_delete` / 三线 `validate_*` / `dual_path_check` / `shell_path_check` / `temp_auth`）统一改用这个口，**`delete_file.py` 保持零改动**。

为什么不选 ③（缓存兜底）而选 ①：③ 把构建隐式化，一旦 ContextVar 为空就静默重建一份，「本次执行用的到底是哪份名单」这个问题就没法回答了；① 至少把「没有 loop 上下文」这件事显式表达出来，且范围可控。

为什么不直接放宽 `get_directory_lists()`（严格口）：三线改用宽松口后，严格口就没有调用方了，等于名存实亡。故保留严格口给 `safety_gate` 落快照用（那行代码位置决定了它必然在 loop 内），宽松口给所有判定用。详见 §4.5.1。

## 五、安全模块开关体系

### 5.1 具体要求

> 本节是安全开关的**设计要求基线**（需求确认 2026-10-20）。以下各节须严格按本节实现，凡与本节冲突的既有表述一律以本节为准。

#### 5.1.1 配置之间互相独立

所有安全配置项**彼此独立、平行**，不存在层次、优先级、先后判定关系。每项只作用于自己负责的那一份名单或那一个判定点，关闭一项不影响其他项。

#### 5.1.2 总闸

| 配置键 | 判定位置 | 关闭时 |
|---|---|---|
| `security.system.enabled` | 安全模块**入口处首先判定** | 直接返回通过，不进入任何权限判定 |

总闸只关**权限判定**：入口之前的 `precheck_path_legality`（空路径 / `..` / 非法字符 / 存在性）与"无任务上下文直调工具"时的 `guard_forbidden_delete` 属合法性初查与执行层兜底，不受总闸控制（边界见 5.3.1）。

#### 5.1.3 三个名单开关

每个开关只关掉自己那一份名单：**关闭 = 该名单置空**；名单为空即该档不判。

| 配置键 | 关闭时 |
|---|---|
| `security.system.forbidden_system_path_block` | `forbidden_system_path` 名单置空 |
| `security.system.forbidden_non_system_path_block` | `forbidden_non_system_path` 名单置空 |
| `security.system.white_list_block` | `whitelist_path` 名单置空 |

#### 5.1.4 白名单置空后的判定

`whitelist_path` 为空时，判定链**跳过白名单档、直接返回通过档**。不得出现"名单为空 → 所有路径都属白名单外"的反向收紧（写/删确认、递归删拒绝都不允许因此产生）。

#### 5.1.5 shell 命令级开关（危险 / 风险）

两条检查彼此独立，各自的开关只关自己那一条检查，关闭时**跳过本项检查、继续后续判定**（不影响另一条检查与路径判定）：

| 配置键 | 对应检查（代码） | 关闭时 |
|---|---|---|
| `security.system.shell_danger_block` | `check_shell_danger_command_all_shells()`（危险命令，直接拒绝） | 跳过危险命令检查，继续走风险检查与路径判定 |

|---|---|

> 每项只作用于**自己那一份名单**或**自己那一个判定点**；关闭一项不影响其他项。不存在"层"、"优先级"、"先判定后判定"的关系。
>

### 5.3 逐项判定逻辑

#### 5.3.1 总闸：安全模块入口短路

- 位置：`PathToolSafetyChecker.check_before_execute` **第一行**（早于 `_is_hitl_bypass()`、早于名单构建、早于一切判定）。
- 行为：`security.system.enabled` 关 → `SafetyResult.pass_result()` 立即返回。
- 为什么在入口而不是折进各开关：折叠会让总闸的生效依赖"每个开关都被读到"，任何直接用名单或直接调判定的路径都会绕过总闸；入口短路与调用方怎么走无关。

**总闸的边界（必须写清，避免误判为"全放行"）**：

| 位置 | 是否受总闸控制 | 理由 |
|---|---|---|
| `precheck_path_legality`（`safety_gate.py:216`，在入口**之前**） | **否**，照旧拦截 | 它答的是"参数能不能构成一次执行"（空路径 / `..` / 非法字符 / 存在性），不是"允不允许动"，属前置合法性初查 |
| `check_before_execute` 起的全部权限判定（名单、五线、shell、沙箱预检、确认） | **是** | 权限判定的唯一入口 |
| `delete_file.py:278` 的 `guard_forbidden_delete` | **否** | 只在无任务上下文（工具被单独直调、安全层没跑过）时兜底；Agent / API 链路已由总闸处置 |
| `safety_gate.py:234` 的 `directory_lists_scope` | **否**，照旧建名单并落快照 | 快照是审计事实（"这一轮有哪些名单"），与"是否据此判定"分离；总闸关时快照仍在，判定不执行 |

#### 5.3.2 三个名单开关：构建时置空

三个开关**只作用于名单构建**，判定链一行不改：

| 开关 | 关闭时 |
|---|---|
| `forbidden_system_path_block` | `forbidden_system_path` 数组置为 `()` |
| `forbidden_non_system_path_block` | `forbidden_non_system_path` 数组置为 `()` |
| `white_list_block` | `whitelist_path` 数组置为 `()` |

落点唯一：`_build_directory_lists()`。判定侧（`_locate` / `_classify_scope`）不读任何开关 —— 名单为空自然不命中，不给"判定侧再读一次开关"留下第二处真相。

#### 5.3.3 白名单为空：跳过白名单档

`whitelist_path` 为空时，`_classify_scope` 在查完两个禁区名单后**直接返回通过档**（`SCOPE_WHITELIST_SUB`，四操作全 PASS），不进入"未命中 → 白名单外"的兜底。

原因：空名单若照原链路走，所有路径都会落 `SCOPE_OUTSIDE` → 写/删到处要确认、递归删一律拒绝，与"关闭白名单拦截"完全相反。

**默认值前提**：`white_list_block` 默认 `true`。正常构建下白名单必然非空（`_build_whitelist_path()` 恒含用户目录、系统临时目录、项目根，见 `path_dir_lists.py:397-406`），故该空档**实际只在开关关闭时触发**。若开关为 `true` 却拿到空名单 = 构建异常/配置异常，`_classify_scope` 须先 `logger.warning` 再走通过档，便于排障时区分"主动关闭"与"异常为空"。

#### 5.3.4 shell 危险命令 / 风险命令

两条检查各自独立、各自开关：

| 开关 | 关闭时 |
|---|---|
| `shell_danger_block` | 不调 `check_shell_danger_command_all_shells()`，直接通过 |
| `shell_risk_block` | 不调 `check_shell_risk_command_all_shells()`，直接通过 |

- 关闭只**跳过本项检查**，不影响路径判定（`_check_known_risks` 照常执行）。
- 两项互不影响：关风险不关危险时，危险命令仍直接拒绝。

#### 5.3.5 确认开关（三条确认线 + shell 路径）

| 开关 | 作用对象 | 关闭时 |
|---|---|---|
| `write_confirm` | 写线产生的确认 | `auto_confirm=True`，不问，直接放行 |
| `delete_confirm` | 删线产生的确认 | 同上 |
| `dual_path_confirm` | 双路径线产生的确认 | 同上 |
| `shell_path_confirm` | `bash` 线的路径判定 | 判定到 `bash` **跳过其整条路径判定**，返回通过（与中风险命令确认无关） |

- 前三个只免"询问"，**不改 blocked**：命中禁区仍然拒绝，与 `hitl.enabled` 的"只免问、不免拦"口径一致。
- `shell_path_confirm` 按需求方口径是"名单是 bash 就直接跳过、通过"：只落 `path_legality_router` 的 bash 分支（只认规范名 `bash`；`execute_command` 别名在入口已归一，见 `tool_facade.py:150`），**不进确认结算处、不参与 `_CONFIRM_SWITCH`**。
- **只管路径，不管命令风险**：`shell_path_confirm` 关不影响 `check_shell_risk_command_all_shells` 产生的中风险确认（那由 `shell_risk_block` 与 `hitl.enabled` 决定）。
- **已接受风险（必须留档）**：`shell_path_confirm` 关 → bash 命令内的路径判定**整条不执行**，`del C:\Windows\...`、写系统目录等不再有路径防线，仅剩 `shell_danger_block` / `shell_risk_block` 两道命令检查兜底。这是需求口径的直接后果，不是漏实现；若要"只免确认、保留拦截"，改法见 5.7 第 2 条。
- **粒度不对称（有意为之，需知晓）**：`write/delete/dual_confirm` 关只是"不问"，禁区仍拒；`shell_path_confirm` 关是"整线不判"，禁区也放行。两者同属 `*_confirm` 但语义不同，命名沿用需求口径，不做统一。
- 与 `hitl.enabled` 的边界：`hitl.enabled` 是**所有线**的确认总旁路（`_is_hitl_bypass()`，`path_tool_safety_checker.py:213-221`），除 shell_path_confirm 外的三个 `*_confirm` 是**分线**细控；两者是"或"关系（任一关即不问），三个分线开关不读取、也不改写 `hitl.enabled`，二者互不覆盖。
- 确认开关按**产出确认的那条线**取值；同一工具只可能落一条线，不存在叠加。

#### 5.3.6 既有配置项（保留现状，不改语义）

| 配置键 | 现状语义 |
|---|---|
| `security.hitl.enabled` | 人工确认总旁路：关 → 所有确认 `auto_confirm=True`（硬拦不受影响）。notice 中"删除硬防线仍生效"仅对**工具直调**成立（Agent / API 链路该防线由安全层判定） |
| `security.system.confirm_dangerous_ops` | **设置页保存设置时的二次确认**（`config_service.py:219` 回给前端），与安全拦截无关；本次不动 |

#### 5.3.7 工具线开关（不纳入本次实现）

原设计的 5 个 `security.system.{read,write,delete,dual,shell}_path_check` 与 4 个 `hitl.*_confirm` 语义重叠（都是"这条线不再问/不再查"），且其"第二层先判"的框架与 5.1.1 独立原则冲突。**本次不实现、不注册**；确需"整线跳过路径判定"时再单独立项。

### 5.6 回归口径

| 开关 | 关掉后必须看到 |
|---|---|
| `enabled` | 任意工具、任意路径直接执行，无权限判定日志（`precheck_path_legality` 与无任务直调的执行层兜底仍在，见 5.3.1 边界表） |
| `forbidden_system_path_block` | `C:\Windows\x` 读/写/删都不再因系统禁区被拦 |
| `forbidden_non_system_path_block` | 代码目录自身写不再确认、删不再拒绝 |
| `whitelist_path`（`white_list_block`） | 白名单外写不再确认、删不再要求确认；不得出现"反而更严" |
| `shell_danger_block` | `format C:` / `shutdown` 等高危命令放行；风险命令仍走确认 |
| `shell_risk_block` | 中风险命令不再弹窗；高危命令仍拒绝 |
| `write/delete/dual_confirm` | 对应线不再弹窗，硬拦仍生效 |
| `shell_path_confirm` | `bash` 命令内路径判定直接通过；危险命令拦截与中风险命令确认均不受影响 |

**组合**：任意多个开关同时关闭，效果等于各自独立效果之和；不存在先后覆盖关系。
