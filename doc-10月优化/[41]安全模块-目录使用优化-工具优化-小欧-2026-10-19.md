## 一、当前的目录构建和使用现状分析

### 1.1 判据散落在代码里，判定与数据分离

**"哪些目录算禁区、哪些算白名单"这批数据没有以清单形式存在**，而是硬编码成一段段判据代码分布在多个函数中。后果有四个：

1. **无法审计** —— 想知道"到底哪些目录被禁了"必须逐函数读代码；
2. **无法配置** —— 临时放开某个目录必须改代码发版；
3. **同一语义多处实现** —— "路径是否落在某根之下"在 `check_whitelist` 与 `is_allowed_root_itself` 中各有一份写法不同的实现；
4. **新增一类目录要改多处** —— 判据函数、取值函数、判定分支都要动。

### 1.2 禁区判据（代码内硬编码）

统一入口 `path_classify_category.classify_forbidden_path(file_path, mode)`，返回 `(category, msg)`，`category ∈ {"system", "non_system", None}`。内部按序执行：

| 序 | 判据 | 实现位置 | 语义 | 产出类别 |
|---|---|---|---|---|
| 1 | 磁盘根（任意盘符） | `is_disk_root` | splitdrive 后剩余为空 | system |
| 2 | 系统敏感文件（Windows 相对精确） | `FORBIDDEN_PATHS_WINDOWS_REL_EXACT` | 与 `{系统盘}+项` 精确相等 | system |
| 3 | 系统敏感目录（Windows 相对前缀） | `FORBIDDEN_PATHS_WINDOWS_REL_PREFIX` | 以 `{系统盘}+项` 开头 | system |
| 4 | 系统保护目录名 | `is_system_protected_path` | 根下**第一层目录名**命中 `SYSTEM_PROTECTED_DIR_NAMES`（windows / program files / program files (x86) / programdata / boot / recovery / winnt / system32 / system） | system |
| 5 | 代码目录 | `is_code_root_path` | 落在 `get_code_root()` 自身及其子级 | non_system |
| 6 | 允许根自身及其上级 | `is_allowed_root_itself` | 等于某允许根，或等于其祖先目录 | non_system |

Linux 侧 `FORBIDDEN_PATHS_EXACT` / `FORBIDDEN_PATHS_PREFIX`（`/etc/shadow`、`/etc/sudoers`、`/proc`、`/sys`）在判据 5/6 之后执行，产出 system。

判据 4 有一处耦合：`is_system_protected_path` 按 `mode` 过滤（`read` 不拦），判据函数内部混入了操作线策略。

### 1.3 允许范围：三条互不相干的路径各取一次

同一份"允许范围"在系统里有三个独立取值口：

```
路径 A · 白名单取值壳
  path_check_common.resolve_allowed_paths(allowed_paths)
    └─ allowed_paths 为 None → path_env.get_default_allowed_paths()
         = 用户目录 + 系统临时目录 + get_allowed_roots(会话工作区)
    └─ path_check_common.check_whitelist(file_path, allowed_paths)

路径 B · 禁区判据 6
  path_classify_category.is_allowed_root_itself(file_path)
    └─ get_allowed_roots(session_workspace_paths())       # 现场再取一次
    └─ 判"等于根 或 等于根的祖先"

路径 C · 删线独立判定
  delete_path_check.check_delete_permission(:154)
    └─ allowed_roots = get_allowed_roots(session_workspace_paths())   # 第三次再取
    └─ inside_proj = any(p == root or root in p.parents ...)
```

**三条路径的集合定义还不一致**：路径 A 含用户目录与临时目录，路径 B/C 只含项目根 + 授权目录 + 会话工作区。

### 1.4 判据到结果的三线策略矩阵（现状）

| category | 读 | 写 | 删 |
|---|---|---|---|
| `system` | 放行 | blocked 不授权 | blocked 不授权 |
| `non_system` | 放行 | 确认 + auth_path | blocked 不授权 |
| `None` + 不在白名单 | 放行 | 确认 + auth_path | 确认 + auth_path |
| `None` + 在白名单 | 放行 | 放行 | 放行 |
| 路径含 `..` | blocked | blocked | blocked |
| 异常 | blocked | blocked | blocked |

> 读线一律放行，与 `delete_path_check.py` 文件头的权限总表一致。

### 1.5 没有统一构建时机，且存在重复构建

- `classify_forbidden_path` 被调时内部实时调 `get_code_root()`、`get_allowed_roots(session_workspace_paths())`；
- 白名单侧被调时实时调 `get_default_allowed_paths()`，而它**内部又调一次** `get_allowed_roots(...)`；
- 执行层 `delete_file._guard_forbidden_delete` 再走一遍 `classify_forbidden_path`。

一次任务内同一批根被取 N 遍。**没有单一构建时机，就没有单一数据源，也就没有一致性保证。**

### 1.6 无目录范围落库记录

`chat_tasks` 现有列无目录范围字段。事后排查"这个路径为什么被拦"只能翻代码与当前配置，**无法还原任务执行当时的目录范围**。

## 二、目录数组清单归一化需求要点

### 2.1 需求要点

1. **分类口径**：目录归两类 —— 禁区（分系统、非系统两档）与白名单；
2. **数据形态**：三类名单全部一维数组；每项是构建期展开完成的**完整目录路径**（严禁半截路径）；第二字段是 `label`；
3. **一个结构**统一存放三类数组；
4. **构建时机**：在**安全模块入口 `check_before_execute`**（一个 loop = 一次工具执行前的安全检查）开头构建一次，本次 loop 内严禁二次构建；
5. **根即名单项**：对任一待判路径，根里还是根外完全依据这份名单判定；
6. **原样落库**：构建好的清单原样存入 task 表，供事后回溯；
7. **全系统收口**：散落各处的"取目录"函数全部汇集到 build；只服务目录判定的取值函数直接删除。

### 2.2 七条硬要求

| 要求 | 验收标准 |
|---|---|
| **单一数据源** | 判定函数内不再出现硬编码目录常量 |
| **单一构建时机** | 一次 loop（一次 `check_before_execute`）内 `build_directory_lists()` 调用次数恒为 1 |
| **路径完整性** | 名单中不存在任何相对项、半截项、待拼接项 |
| **根里根外单一判定** | 只存在 `locate` 一个实现 |
| **命名唯一** | 实施后 §1.8.1 的作废名零命中 |
| **无跨 loop 全局态** | 名单按 loop 作用域传递 |
| **原样可落库** | 落库 JSON 三个数组齐全，无裁剪 |

### 2.3 明确不做

- **不做跨 loop 名单缓存**（每 loop 重建是需求要求，不是缺陷）；
- **不把名单内容做成配置项**（是否可配后续单独评估，接口已按 §3.3.1.1 预留）；
- 非目录类安全开关（`security.system.*` / `security.hitl.*` 九项 + 五项工具线开关）不在本章范围，**全部见第五章**。

## 三、优化方案

### 3.1 思路

把"哪些目录是什么性质"从代码里抽出来，变成**在安全模块入口每个 loop 构建一次的目录数组**；判定侧退化为**只查这份名单**。

```
现状：判定函数 = 判据代码 + 常量 + 关系推断    取值散落三条路径, 集合定义还不一致
优化：build_directory_lists()  全系统唯一目录取值口, 在 check_before_execute 构建一次
      locate()                全系统唯一的根里/根外判定, 取最深命中
      classify_scope()        五档归属判定链
      判定函数                 只读名单, 无常量、无推断、无独立取值
      构建结果                 原样序列化落库
```

### 3.2 名单结构

```python
@dataclass(frozen=True)
class DirRule:
    path: Path    # 构建期展开完成的完整路径
    label: str    # 语义标签, 供日志与提示消息

@dataclass(frozen=True)
class DirectoryLists:
    forbidden_system_path: List[DirRule]
    forbidden_non_system_path: List[DirRule]
    whitelist_path: List[DirRule]
```

三个一维数组，类型统一，判定侧用同一套函数遍历。**只有两个字段** —— 覆盖范围不靠字段表达，靠"命中自身"与"命中最深条目"在判定时算出来。

### 3.3 名单内容

#### 3.3.1 `forbidden_system_path` —— 常量清单，跨平台

`forbidden_system_path` 是 `DirectoryLists` 上的**一个字段（变量），类型是 `List[DirRule]`**，与另外两个名单同构。它的内容由**模块级常量清单**产出，与 Windows / Linux 平台无关 —— 平台差异只体现在"怎么拼根"，不体现在名单结构。

**常量清单（内置基线，代码单一真源）**：

```python
# 磁盘根: 只判自身, 由平台决定挂哪个根
DISK_ROOT_LABEL = "磁盘根目录"

# 系统保护目录名: 与盘符/挂载点无关的纯名字, 构建期才拼成完整路径
SYSTEM_PROTECTED_DIR_NAMES = (
    "windows", "program files", "program files (x86)",
    "programdata", "boot", "recovery", "winnt", "system32", "system",   # Windows
)

# 跨平台系统禁区: 全路径原样入名单(文件精确 / 目录含下级)
FORBIDDEN_SYSTEM_EXACT = (          # 文件, 仅自身
    "/etc/shadow", "/etc/sudoers",
)
FORBIDDEN_SYSTEM_PREFIX = (         # 目录, 自身 + 下级
    "/proc", "/sys",
)
```

**构建规则**（`_build_forbidden_system_path()`）：

1. 加磁盘根 —— Windows 取 `get_system_drive() + "\\"`，Linux 取 `"/"`；label 一律 `磁盘根目录`，**只判自身**；
2. 遍历 `SYSTEM_PROTECTED_DIR_NAMES`，拼成 `{根}{名字}`（Windows 得 `C:\Windows`，Linux 得 `/windows`）；
3. **若该路径在已加入条目的下级之下，跳过不加入**（例如把某条配置成根下的子目录时）；
4. `FORBIDDEN_SYSTEM_EXACT` / `FORBIDDEN_SYSTEM_PREFIX` 原样入名单；
5. **不展开任何下级文件与目录**（`C:\Windows\WinSxS`、`C:\Windows\System32\config` 及 5 个 hive 文件均不加入，命中 `C:\Windows` 即可）。

**Windows 上的产出（10 条）**：

| 路径 | label | 匹配 |
|---|---|---|
| `C:\` | 磁盘根目录 | **仅自身** |
| `C:\Windows` | 系统保护目录 | 自身 + 下级 |
| `C:\Program Files` | 系统保护目录 | 自身 + 下级 |
| `C:\Program Files (x86)` | 系统保护目录 | 自身 + 下级 |
| `C:\ProgramData` | 系统保护目录 | 自身 + 下级 |
| `C:\Boot` | 系统保护目录 | 自身 + 下级 |
| `C:\Recovery` | 系统保护目录 | 自身 + 下级 |
| `C:\Winnt` | 系统保护目录 | 自身 + 下级 |
| `C:\System32` | 系统保护目录 | 自身 + 下级 |
| `C:\System` | 系统保护目录 | 自身 + 下级 |

> **`C:\System32` 必须单列，不能因为"它是系统目录"就省掉**：它与 `C:\Windows` **平级**（真正被 `C:\Windows` 覆盖的是 `C:\Windows\System32`），`_is_under()` 判它不在 `C:\Windows` 之下，因此构建时会被正常加入。现状 `is_system_protected_path` 按"根下第一层目录名"匹配，`C:\System32` 的第一层就是 `System32`，**现状确实拦它** —— 省掉这条是安全倒退。

只有 **C 盘进系统禁区**，`D:\` / `F:\` 等其他盘符不进（常量里根本不枚举盘符，只有一个"当前系统盘根"），走白名单外。

**Linux 上的产出**：`/`（磁盘根，仅自身）+ 4 条跨平台禁区 + 9 个拼在 `/` 下的系统目录名（多数不存在，`_complete()` 自动丢弃）。同一套代码、同一份名单结构，零平台分支。

#### 3.3.1.1 配置化接口预留（本期只落常量，机制先留好）

名单**当前的唯一来源是上面那几行模块级常量**。为后续"设置页可改"预留三点，**本期不实现配置读写**，只保证将来接上时不需要改结构：

| 预留点 | 做法 | 本期状态 |
|---|---|---|
| **来源可替换** | `_build_forbidden_system_path()` 只依赖 `SYSTEM_PROTECTED_DIR_NAMES` / `FORBIDDEN_SYSTEM_EXACT` / `FORBIDDEN_SYSTEM_PREFIX` 三个常量，**不硬编码任何具体路径**；将来加一层 `_configured_forbidden_extra()` 返回用户配置项，在第 2 步之后并入即可 | 常量直供 |
| **结构不变** | 用户配置进来后仍是 `DirRule(path, label)`，判定侧 `locate` / `classify_scope` / `PERMISSION` **零改动** | 已就位 |
| **默认不落盘** | 配置化时默认策略应与常量一致（空配置 = 用内置），避免"配置缺失=安全裸奔" | 待实现 |

三条名单的**配置化路径完全对称**：将来加 `_configured_forbidden_non_system_extra()` / `_configured_whitelist_extra()`，各自在同名 `_build_*` 的最后并入即可。

#### 3.3.2 `forbidden_non_system_path`

| 路径 | label | 匹配 |
|---|---|---|
| `get_code_root()` | 代码目录(含其内部子目录) | 自身 + 下级 |
| 各允许根自身（项目根 / 授权目录 / 会话工作区） | 允许根自身 | **仅自身** |

#### 3.3.3 `whitelist_path`

| 路径 | label | 匹配 |
|---|---|---|
| `Path.home()` | 用户目录 | 自身 + 下级 |
| 系统临时目录 | 系统临时目录 | 自身 + 下级 |
| 各允许根（项目根 / 授权目录 / 会话工作区） | 项目根/授权目录/会话工作区 | 自身 + 下级 |

**白名单是全系统唯一的允许范围**，读、写、删三条线全部以它为准。

### 3.4 归属判定链与权限矩阵

**归属只有一条链，按序走完即定，无第四种情况**：

| 顺序 | 判据 | 归属 |
|---|---|---|
| 1 | 命中 `forbidden_system_path` | **禁区·系统** |
| 2 | 命中 `forbidden_non_system_path` | **禁区·非系统**（禁区优先，到此定案） |
| 3 | 命中 `whitelist_path` 且路径等于条目 | **白名单·自身** |
| 4 | 命中 `whitelist_path` 且路径在条目之下 | **白名单·下级** |
| 5 | 以上均不命中 | **白名单外** |

**权限矩阵（读 / 写 / 删 / 递归删）**：

| 归属 | 读 | 写 | 删 | 递归删 |
|---|---|---|---|---|
| 禁区·系统 | 放行 | 拒绝 | 拒绝 | 拒绝 |
| 禁区·非系统 | 放行 | 确认 | 拒绝 | 拒绝 |
| 白名单·自身 | 放行 | 放行 | 拒绝 | 拒绝 |
| 白名单·下级 | 放行 | 放行 | 放行 | 放行 |
| 白名单外 | 放行 | 确认 | 确认 | 拒绝 |

**父级目录与兄弟目录没有特殊地位**，一律按上面的链走。例：允许根 `F:\proj`、代码根 `F:\OmniAgentAs-repair`

| 路径 | 归属 |
|---|---|
| `F:\proj` | 禁区·非系统（允许根自身） |
| `F:\proj\src\a.py` | 白名单·下级（允许根在禁区名单中**仅判自身**，子级不命中禁区；项目根在白名单中含子级，故落白名单·下级） |
| `F:\`（父级） | 白名单外 |
| `F:\other`（兄弟） | 白名单外 |
| `F:\OmniAgentAs-repair\src` | 禁区·非系统 |
| `F:\其他项目\` | 白名单外 |

**唯一例外**：兄弟目录若被用户**单独授权**（列入 `workspace.allowed_dirs`），它本身就是允许根 → 命中第 2 步。这是显式授权，不是自动放大。

**空名单语义**：禁区名单为空则该类不拦；`whitelist_path` 为空则全部落"白名单外"（**不静默放行**）。

### 3.5 构建时机与传递

**loop = 安全模块的入口 `check_before_execute`（`path_tool_safety_checker.py`）。** 每次工具执行走一次安全总闸，就是一个 loop。

**硬规则：一个 loop 内 `build_directory_lists()` 只调用一次。** 任务运行期间代码根、授权目录、会话工作区、系统盘都是确定的，不存在中途变化。

```
安全模块入口 check_before_execute  ← 一个 loop = 一次工具执行前的安全检查
    │
    ├─ dl = build_directory_lists()      ← 唯一构建点
    ├─ current_directory_lists.set(dl)   ← 挂到当前 loop 上下文
    ├─ save_path_scope_snapshot(...)     ← 原样落库(同一份 dl)
    │
    └─ ↓ 本次 loop 内所有判定读同一份，全链路零重复构建
       ├─ path_legality_router ──┬─ read_path_check      ┐
       │                          ├─ write_path_check     ├─ 均无需改签名,
       │                          ├─ delete_path_check    │  经 ContextVar
       │                          └─ dual_path_check      ┘  自动可见名单
       ├─ shell_path_check
       └─ delete_path_check.guard_forbidden_delete  ← 执行层直调(§4.14-C: 此路径可能无 loop 上下文)
```

用 `ContextVar` 而非普通全局变量或逐层传参：普通全局在并发时 A 任务会读到 B 任务的名单；逐层传参要改 7 个文件签名，而执行层 `tools` 侧根本不在这条调用链上、参数传不过去。

**兜底语义**：读不到名单时抛异常按 fail-closed 阻断，不静默放行、也不重建 —— 确保二次构建在代码层面不可能发生。

### 3.6 原样落库

`DirectoryLists` 同一份结构，运行期供判定、落库供回溯，不另建落库专用结构。

| 项 | 设计 |
|---|---|
| 目标表 | `chat_tasks`（名单随 loop 失效，`chat_sessions` 跨 task 复用会与"每 loop 最新"冲突） |
| 列名 | `path_scope_snapshot` |
| 类型 | `TEXT`（与 `process_events` / `task_summary` 同为 JSON 字符串列） |
| 迁移 | `CREATE TABLE` 内建 + `_ensure_column` 兜底（与 `task_summary` 同源的双保险） |
| 时机 | 与构建点同一处，构建后立即写一次；同 task 多 loop 覆盖同一列，保留最后一次 |

```json
{
  "built_at": "2026-10-19T16:42:05+08:00",
  "forbidden_system_path": [
    {"path": "C:\\", "label": "磁盘根目录"},
    {"path": "C:\\Windows", "label": "系统保护目录"}
  ],
  "forbidden_non_system_path": [
    {"path": "F:\\OmniAgentAs-doc40-ws", "label": "代码目录(含其内部子目录)"},
    {"path": "F:\\OmniAgentAs-doc40-ws\\backend", "label": "允许根自身"}
  ],
  "whitelist_path": [
    {"path": "C:\\Users\\chend", "label": "用户目录"},
    {"path": "F:\\OmniAgentAs-doc40-ws", "label": "项目根/授权目录/会话工作区"}
  ]
}
```

**全量原样入库，不裁剪、不设阈值。** 三条名单合计约 20 条 × 100 字节 ≈ 2 KB，`TEXT` 列无压力。

| 情形 | 处理 |
|---|---|
| 序列化或写库抛异常 | 记 warning，不阻断判定（`ContextVar` 已挂好，判定照常） |
| `task_id` 缺失（`/tool/execute` 直调无任务行） | 跳过落库，不报错 |
| UPDATE 命中 0 行 | 记 debug 日志 |

### 3.7 与现状的行为差异（3 处，无安全性下降）

| # | 场景 | 现状 | 本方案 | 性质 |
|---|---|---|---|---|
| 1 | 白名单条目**自身**删除 | 放行 | 拒绝 | **修 bug**（自身本就不该可删） |
| 2 | 白名单**下级**递归删除 | 确认 | 放行 | 放宽 |
| 3 | **非系统盘**盘根（`D:\`、`F:\`） | 判禁区·系统 → 写拒绝删拒绝 | 白名单外 → 写确认删确认 | 放宽 |

禁区删全线拒绝、白名单外递归拒绝两条硬底线**原样保留**。其余各格（含读线一律放行、`forbidden_system_path` 各条命中结果）与现状逐例一致 —— 20 格回归口径见 §4.13。

```python
def get_system_drive() -> str:
    """动态获取真实系统盘符(三级探测, 全失败回落 C:)"""
    for var in ("SystemRoot", "WINDIR"):
        root = os.environ.get(var)
        if root:
            drive, _ = os.path.splitdrive(root)
            if drive:
                return drive
    sdrive = os.environ.get("SystemDrive", "")
    if sdrive:
        return sdrive.rstrip("\\/")
    if os.name == "nt":
        for c in "CDEFGHIJKLMNOPQRSTUVWXYZ":
            if os.path.isdir(f"{c}:\\Windows"):
                return f"{c}:"
    return "C:"


def _system_temp_dir() -> Path:
    """系统临时目录(Windows 取 TEMP/TMP, 其他平台回落 /tmp)"""
    if os.name == "nt":
        temp = os.environ.get("TEMP") or os.environ.get("TMP")
        if temp:
            return Path(temp)
    return Path("/tmp")


# ────────────────── 取值(全部内聚在本文件) ──────────────────

def _complete(path) -> Optional[Path]:
    """展开为完整真实路径; 失败返回 None(该项跳过, 不留半截路径)

    名单完整性的唯一守门点: 任何进入名单的路径都必须经此展开为绝对真实路径。
    """
    try:
        expanded = os.path.expanduser(str(path))
        if not expanded or not os.path.isabs(expanded):
            return None
        return Path(os.path.realpath(expanded))
    except (ValueError, OSError, TypeError):
        return None


def _is_under(child: Path, parent: Path) -> bool:
    """child 是否在 parent 之下(不含相等)"""
    c = str(child).lower().rstrip("\\/")
    p = str(parent).lower().rstrip("\\/")
    return c.startswith(p + os.sep)


def _build_allowed_roots() -> List[Path]:
    """允许根原始集 = 项目根 + 授权目录 + 会话工作区

    2026-10-19 小欧: 内联原 utils/path_utils.get_allowed_roots —— 消费方全是安全判定,
    已随本次收口删除, 保留独立函数等于把同一份取值留在名单之外。
    fail-closed: 读取异常即抛 RuntimeError, 不用空列表静默降级
    (空列表会让"是否在允许根内"恒 False, 把全部路径误判为区外)。
    """
    try:
        cfg = get_config()
        roots = [Path(cfg.get_project_root()).resolve()]
        roots.extend(Path(d).resolve() for d in cfg.get_allowed_dirs())
    except Exception as e:
        raise RuntimeError(f"读取允许根失败(config): {e}") from e
    try:
        roots.extend(Path(r).resolve() for r in session_workspace_paths())
    except Exception as e:
        raise RuntimeError(f"读取会话工作区失败: {e}") from e
    return roots


def _platform_root() -> str:
    """平台根: Windows 取系统盘符根, Linux 取 /

    名单里只挂**当前平台的根** —— 其它盘符(D:/F:/E: ...)不进禁区, 走白名单外。
    """
    return (get_system_drive() + "\\") if os.name == "nt" else "/"


def _build_forbidden_system_path() -> List[DirRule]:
    """构建禁区·系统一维数组 —— 来源是模块级常量清单, 跨平台同一套代码

    构建规则:
      (1) 磁盘根 —— label 磁盘根目录, 判定时只判自身(否则整盘命中)
      (2) 系统保护目录名 -> 拼在平台根下; 下级候选跳过(不下级)
      (3) 跨平台系统禁区: 文件精确 / 目录含下级
    将来接配置化时, 在 (3) 之后并入 _configured_forbidden_extra() 即可, 结构不变。
    """
    rules: List[DirRule] = []
    plat_root = _platform_root()

    # (1) 平台根 —— 只判自身
    root = _complete(plat_root)
    if root is not None:
        rules.append(DirRule(root, DISK_ROOT_LABEL))

    # (2) 系统保护目录 —— 自身+下级; 下级候选跳过
    for name in SYSTEM_PROTECTED_DIR_NAMES:
        p = _complete(os.path.join(plat_root, name))
        if p is None:
            continue
        if any(_is_under(p, r.path) for r in rules if r.label != DISK_ROOT_LABEL):
            continue                                   # 在已加入条目的下级之下 -> 不加入
        rules.append(DirRule(p, "系统保护目录"))

    # (3) 跨平台系统禁区(文件精确 / 目录含下级)
    for item in FORBIDDEN_SYSTEM_EXACT:
        p = _complete(item)
        if p is not None:
            rules.append(DirRule(p, "系统禁区(精确)"))
    for item in FORBIDDEN_SYSTEM_PREFIX:
        p = _complete(item.rstrip("/"))
        if p is not None:
            rules.append(DirRule(p, "系统禁区(前缀)"))

    return rules


def _build_forbidden_non_system_path() -> List[DirRule]:
    """构建禁区·非系统一维数组: 代码目录(自身+下级) + 允许根自身(仅自身)"""
    rules: List[DirRule] = []
    try:
        code_root = get_code_root()
        full = _complete(code_root) if code_root else None
        if full is not None:
            rules.append(DirRule(full, "代码目录(含其内部子目录)"))
    except Exception as e:
        logger.warning(f"[path_dir_lists] 获取代码目录失败, 非系统禁区暂不含代码目录: {e}")
    try:
        for r in _build_allowed_roots():
            full = _complete(r)
            if full is not None:
                rules.append(DirRule(full, "允许根自身"))
    except Exception as e:
        logger.warning(f"[path_dir_lists] 获取允许根失败, 非系统禁区暂不含允许根: {e}")
    return rules


def _build_whitelist_path() -> List[DirRule]:
    """构建白名单一维数组 = 全系统唯一允许范围(自身+下级)"""
    rules: List[DirRule] = []
    for raw, label in ((Path.home(), "用户目录"), (_system_temp_dir(), "系统临时目录")):
        full = _complete(raw)
        if full is not None:
            rules.append(DirRule(full, label))
    try:
        for r in _build_allowed_roots():
            full = _complete(r)
            if full is not None:
                rules.append(DirRule(full, "项目根/授权目录/会话工作区"))
    except Exception as e:
        logger.warning(f"[path_dir_lists] 获取允许根失败, 白名单暂不含项目根与授权目录: {e}")
    return rules


def build_directory_lists() -> DirectoryLists:
    """构建本 loop 的目录名单(唯一构建口 / 全系统唯一目录取值口)

    调用点唯一: 安全模块入口 check_before_execute 开头(一个 loop = 一次安全检查), 每 loop 一次。
    构建后必须由调用方 current_directory_lists.set(dl) 挂到本 loop 上下文。
    loop 内严禁二次调用 —— 任何"就近再取一次目录"都应改从名单读。
    """
    return DirectoryLists(
        forbidden_system_path=_build_forbidden_system_path(),
        forbidden_non_system_path=_build_forbidden_non_system_path(),
        whitelist_path=_build_whitelist_path(),
    )


def get_directory_lists() -> DirectoryLists:
    """取当前 loop 的目录名单(全链路唯一读取口)

    读不到名单属链路缺陷(构建点缺失), 按 fail-closed 抛异常阻断,
    不静默放行, 也不就地重建。
    loop 外(无 check_before_execute 的直调路径)由调用方自行构建, 见 get_or_build_directory_lists()。
    """
    dl = current_directory_lists.get()
    if dl is None:
        raise RuntimeError(
            "[path_dir_lists] 当前上下文无目录名单: check_before_execute 未构建。构建点唯一, 严禁就地重建"
        )
    return dl


def get_or_build_directory_lists() -> DirectoryLists:
    """取当前 loop 名单; 无 loop 上下文(执行层直调)时就地构建一次

    用于 delete_file 这类"无任务上下文直调"的执行层路径: 该路径从未经过
    check_before_execute, ContextVar 必然为空。此处按需构建不违反
    "loop 内只构建一次"——它根本不在任何 loop 内。
    """
    dl = current_directory_lists.get()
    if dl is None:
        dl = build_directory_lists()
        current_directory_lists.set(dl)
    return dl


# ────────────────── 归属判定(全系统唯一) ──────────────────

def locate(rules: List[DirRule], real_path: Path):
    """在一维名单中定位路径, 取最深命中项

    Returns:
        (True, 命中项) 命中; (False, None) 未命中
    规则: 路径等于条目 -> 立即定案(自身一定最深); label 为磁盘根的条目只判自身;
          多条命中取 path 最深的一条。
    """
    rp = str(real_path).lower()
    best: Optional[DirRule] = None
    for rule in rules:
        rp_rule = str(rule.path).lower()
        if rp == rp_rule:
            return True, rule                      # 自身命中, 最深, 立即定案
        if rule.label == DISK_ROOT_LABEL:
            continue                               # 盘根只判自身, 不向下匹配
        if rp.startswith(rp_rule.rstrip("\\/") + os.sep):
            if best is None or len(rule.path.parts) > len(best.path.parts):
                best = rule                        # 取最深命中
    return (best is not None), best


def classify_scope(dl: DirectoryLists, real_path: Path) -> Tuple[str, Optional[DirRule]]:
    """归属判定链(顺序不可换): 禁区·系统 → 禁区·非系统 → 白名单·自身 → 白名单·下级 → 白名单外"""
    hit, rule = locate(dl.forbidden_system_path, real_path)
    if hit:
        return SCOPE_FORBIDDEN_SYSTEM, rule

    hit, rule = locate(dl.forbidden_non_system_path, real_path)
    if hit:
        return SCOPE_FORBIDDEN_NON_SYSTEM, rule   # 禁区优先, 到此定案

    hit, rule = locate(dl.whitelist_path, real_path)
    if hit:
        is_self = str(real_path).lower() == str(rule.path).lower()
        return (SCOPE_WHITELIST_SELF if is_self else SCOPE_WHITELIST_SUB), rule

    return SCOPE_OUTSIDE, None


def permission_of(scope: str, line: int) -> str:
    """查权限矩阵: 返回 PASS / CONFIRM / DENY"""
    return PERMISSION[scope][line]


def to_snapshot_json(dl: DirectoryLists) -> str:
    """把目录清单原样序列化为 JSON(全量, 不裁剪)"""
    def dump(rules: List[DirRule]) -> list:
        return [{"path": str(r.path), "label": r.label} for r in rules]

    return json.dumps({
        "built_at": datetime.now().astimezone().isoformat(timespec="seconds"),
        "forbidden_system_path": dump(dl.forbidden_system_path),
        "forbidden_non_system_path": dump(dl.forbidden_non_system_path),
        "whitelist_path": dump(dl.whitelist_path),
    }, ensure_ascii=False)
```

### 4.5.1 三线取名单的入口：`get_or_build_directory_lists`

`path_dir_lists` 提供两个取值口，三线**统一用后者**：

| 函数 | 语义 | 使用方 |
|---|---|---|
| `get_directory_lists()` | 只取当前 loop 那份，ContextVar 为空即抛 `RuntimeError` | `safety_gate` 落快照（必须在 loop 内） |
| `get_or_build_directory_lists()` | 取当前 loop 那份；ContextVar 为空则**当场构建一次** | 三线 `validate_*`、`guard_forbidden_delete`、`dual_path_check`、`shell_path_check`、`temp_auth` |

**为什么三线不用严格口**：实施中实测踩坑 —— `workspace_service._ws_deny_reason`（会话目录合法性
预查）与 `delete_file` 执行层守卫都**在 `check_before_execute` 之外**直调三线，若用严格口，
这两处会因"当前上下文无目录名单"而恒抛 `RuntimeError`，被各线 `except` 兜成"路径验证失败"
直接拒绝 —— 结果是**所有会话目录与所有临时授权路径全被拒**，且报错信息完全指不到真因。

`get_or_build` 不破坏"每 loop 一次"约束：loop 内 ContextVar 已由 `check_before_execute` 置入，
该函数只做一次 `.get()` 命中返回；仅在**根本没有 loop**（跨层直调）时才构建，而那时"每 loop 一次"
本就无从违反。

### 4.7 `path_tool_safety_checker.py`：每 loop 唯一构建点

```diff
@@ 文件头 §编辑历史 @@
+# 2026-10-19 小欧 - 目录数组归一化: check_before_execute 开头构建目录名单(唯一构建点),
+#   每 loop 一次, 挂 ContextVar 供本 loop 内三线复用; 判定主体拆出 _check_before_execute,
+#   finally 用 token reset 防止 ContextVar 顺着 asyncio task 上下文外泄

+from app.safety.path_dir_lists import build_directory_lists, current_directory_lists

     def check_before_execute(self, tool_name, params=None, pool_pids=None) -> SafetyResult:
```

**两条硬约束：**

1. **必须用 `token` + `reset(token)`**，不能用裸 `set()`。`ContextVar` 会随 asyncio task
   上下文复制，裸 set 不还原会让本次执行构建的名单活到下一次执行去——而"每 loop 一次"
   的前提是每 loop 都重新建。
2. **函数拆两层**是为了让 `finally` 覆盖整个判定主体（含中段 `return _danger` /
   `return self._settle_confirm(...)` 那些提前返回的分支），否则异常或提前返回都可能跳过还原。

**为什么不用"只在函数末尾还原"的省事写法**：判定主体 20 余处分支、多个提前 return，
任何漏分支的形态都会让 ContextVar 跨 loop 泄漏；`try/finally` 包裹整个主体是唯一无遗漏的形态。

#### C. 落地阻断点（已裁定并解决，见本节末）

`delete_file.py:276-282` 实测代码：

```python
if _current_task_id.get() is None:                      # 无任务上下文(Agent/API 直调)
    from app.safety.delete_path_check import guard_forbidden_delete
    _reason = guard_forbidden_delete(source)              # ← 此时从未经过 check_before_execute
```

**这条路径上 `current_directory_lists` 为空**，而 `get_directory_lists()` 的设计是"读不到就抛 RuntimeError（fail-closed）"。结果：**无任务上下文的删除调用会被自己的安全守卫崩掉**（变成 500 而非安全拒绝）。

"每 loop 只构建一次"这条硬规则约束的是 **loop 内**；此处**不在任何 loop 内**，因此有三种解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **① 就地构建** | `guard_forbidden_delete` 检测到 ContextVar 为空时**就地构建一次**用完即弃 | 不违反 loop 内规则；但"构建点唯一"的表述需放宽为"loop 内唯一，loop 外按需" |
| **② 提前构建** | `delete_file.py` 在调用守卫前先 `build_directory_lists()` 并 set | 改动扩散到 tools 层，且同样要清 ContextVar |
| **③ 缓存兜底** | `get_directory_lists()` 为空时构建并写入 ContextVar | 变成隐式全局缓存，违背设计初衷，且并发下有串味风险 |

**已裁定并落地（v1.16，北京老陈裁定）**：取 **①**，但实现落在 `path_dir_lists` 侧而非调用方 —— 新增 `get_or_build_directory_lists()`：先读 ContextVar，读不到就**当场构建一次**并写回。调用方（`guard_forbidden_delete` / 三线 `validate_*` / `dual_path_check` / `shell_path_check` / `temp_auth`）统一改用这个口，**`delete_file.py` 保持零改动**。

为什么不选 ③（缓存兜底）而选 ①：③ 把构建隐式化，一旦 ContextVar 为空就静默重建一份，「本次执行用的到底是哪份名单」这个问题就没法回答了；① 至少把「没有 loop 上下文」这件事显式表达出来，且范围可控。

为什么不直接放宽 `get_directory_lists()`（严格口）：三线改用宽松口后，严格口就没有调用方了，等于名存实亡。故保留严格口给 `safety_gate` 落快照用（那行代码位置决定了它必然在 loop 内），宽松口给所有判定用。详见 §4.5.1。

> 附带修正：§3.5 流程图把守卫写成 `delete_file._guard_forbidden_delete`，实际该函数在 **`delete_path_check.py:200`**（safety 层），`delete_file.py` 只是调用方。

#### 5.2.3 读取口：`safety_switch.py`

九个开关的**唯一读取口**，总闸折入本函数：

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-10-19 小欧 - 新建(文档[41] 落地): 安全开关唯一读取口。
#   总闸 security.system.enabled 折入本函数 —— 关闭时任何开关都返回 False(总闸一关全放行)。
#   缺键一律按"开"处理(fail-closed): 缺配置不悄悄放松安全等级。
#   无状态函数, 每次调用即时求值; get_config() 内有 mtime 缓存, 改配置下次调用即生效。
"""
safety_switch · 安全开关读取(唯一口)

小欧 2026-10-19
"""

from app.config import get_config

#: 总闸: 关闭后任何开关都返回 False
MASTER_KEY = "security.system.enabled"


def safety_switch(key: str, default: bool = True) -> bool:
    """读取一个安全开关(总闸已折入)

    Args:
        key: 配置键, 如 "security.hitl.delete_confirm"
        default: 缺键时的取值, 默认 True(缺配置不放松安全)
    Returns:
        True = 开关开(生效); False = 开关关(不生效) 或 总闸已关
    """
    cfg = get_config()
    if not cfg.get(MASTER_KEY, True):
        return False                            # 总闸关 → 一律放行
    return bool(cfg.get(key, default))


__all__ = ["MASTER_KEY", "safety_switch"]
```

#### 5.2.4 各开关的读取落点

| 开关 | 读取位置 | 关闭后的行为 |

| `forbidden_system_path_block` | `classify_scope` 查 `forbidden_system_path` 之前 | 命中系统禁区也不返回 category，等价于该名单为空 |
| `forbidden_non_system_path_block` | 同上，查 `forbidden_non_system_path` 之前 | 同上 |

| `security.system.dual_path_check` | 落在 `DUAL_PATH_TOOLS` 的 tool **直接放行** |
| `security.system.shell_path_check` | `bash` **直接放行**（路径判定层放行，不含 shell 危险命令拦截，见 §5.3.4） |

**语义对称性**：与现有 `PATH_TOOLS` 范围门完全同构 —— 范围门判的是"在不在合集内"，单线开关判的是"在不在这条线内"，命中即 `pass_result()`。

**命名**：用 `*_path_check` 后缀，与第一层的 `forbidden_*_path_block` / `white_list_block` 区分（前者是"名单档"，后者是"整条线做不做路径检查"）。

#### 5.3.3 落点：`path_legality_router` 分发处

现有分发是五路 `if`：

```python
if tool_name not in PATH_TOOLS:
    return SafetyResult.pass_result()          # 已有: 合集范围门
if tool_name in READ_PATH_TOOLS:   return read_path_check.check_read_permission(...)
if tool_name in WRITE_PATH_TOOLS:  return write_path_check.check_write_permission(...)
if tool_name in DELETE_PATH_TOOLS: return delete_path_check.check_delete_permission(...)
if tool_name in DUAL_PATH_TOOLS:  return dual_path_check.check_dual_permission(...)
if tool_name == "bash":            return shell_path_check.check_shell_permission(...)
```

**开关挂在分发处** —— 每条分支前加一道"本线是否启用"，关则返回 `pass_result()`。这是**唯一落点**：一处代码同时覆盖五线，不散落到各 `*_path_check` 内部。

#### 5.3.4 边界：开关管什么、不管什么

| | 受开关影响 | 不受开关影响 |
|---|---|---|
| `delete_path_check` 关 | 路径判定层放行（`delete` 工具的路径权限检查） | ① `security.hitl.delete_confirm`（人工确认层）② `guard_forbidden_delete` 执行层守卫 ③ shell 危险命令拦截 |
| `shell_path_check` 关 | `bash` 命令**内路径**的授权判定 | `check_shell_danger_command` 的危险命令拦截（另一条线，由 `security.system.shell_danger_block` 管） |
| 全部关 | 路径判定层整体放行 | 未注册工具拦截（`BLOCK_UNREGISTERED`）、路径含 `..` 的前置合法性初查（`path_precheck`） |

> 设计取向：开关只切**路径判定这一层**，不碰工具注册合法性、不碰执行层守卫、不碰 shell 命令级拦截。

### 5.6 开关组合回归口径

**第一层（单开关）**：

| 开关 | 关掉后的验证点 |
|---|---|
| `enabled` | 任意工具任意路径直接执行 |
| `forbidden_system_path_block` | `C:\Windows\x` 不再被拦；`C:\Program Files\y` 写放行 |
| `forbidden_non_system_path_block` | 代码目录下文件写不再确认、删不再拒绝 |
| `white_list_block` | 白名单外写不再确认；**白名单自身删仍拒绝、递归删仍拒绝** |
| `shell_danger_block` | `format C:` / `shutdown` 等高危命令放行 |
| `hitl.*_confirm` | 对应线不再弹窗 |

**第二层（单开关）**：

| 开关 | 关掉后的验证点 |
|---|---|
| `read_path_check` | `read C:\Windows\a.txt` 直接放行（其他线不受影响） |
| `write_path_check` | `write F:\x.txt` 直接放行 |
| `delete_path_check` | `delete F:\x.txt` 路径判定放行 |
| `dual_path_check` | `copy a b` 路径判定放行 |
| `shell_path_check` | `bash "cat C:\Windows\a"` 内路径授权放行；危险命令仍拦 |

**两层叠加**：先关第一层某名单开关、再关第二层对应线开关 → 线开关先判，第二层生效，行为与"只关第二层"一致。
