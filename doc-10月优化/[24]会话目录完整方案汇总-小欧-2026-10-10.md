## 1. 我的要求和逻辑说明

### 1.1 两个概念，严格分开

| 概念 | 归谁管 | 存在哪 |
|---|---|---|
| **会话使用的目录** | 本表管 | `chat_session_workspaces` |
| **授权目录** | **全局配置管** | `workspace.allowed_dirs` + `workspace.project_root`（config.yaml） |

> **`chat_session_workspaces` 表里只装"会话使用的目录"。项目根和授权目录都不许放进这张表。**

一个会话的使用目录**可以有多个**：系统自动建一个 + 用户再往列表里加。

### 1.2 建立规则（一句话）

> **有 → 直接用；没有 → 建立。**

再补一条清理：**落入禁区的目录 → 从会话目录表里清掉这一行**（只删数据库行，**绝不删磁盘目录**）。

| 情形 | 处理 |
|---|---|
| 目录存在 | 直接用，什么都不做 |
| 落入禁区 | **DELETE 该行**（库层面）+ 告警，本轮不放行 |
| 目录不存在 | 建立 |

> **判定顺序**：禁区判定必须跑在 `exists` 之前 —— 目录若已被用户删掉，先判存在就永远清不掉这条脏数据。

### 1.3 使用 = 两个地方（只有这两处）

| # | 用法 | 作用 |
|---|---|---|
| 1 | **整个列表并入写白名单** | agent 才有权限往这些目录写 |
| 2 | **整个列表追加到 user 信息尾巴** | LLM 才知道往哪写 |

**注入块格式（已定案：都用）**

```
<user 原话>

<system-reminder>
<会话工作目录>
本次任务产生的文件（文件类工具写入）**优先**写入以下目录之一：
  - <路径1>
  - <路径2>
</会话工作目录>
</system-reminder>
```

| 层 | 为什么保留 |
|---|---|
| 外层 `<system-reminder>` | 这是系统级指令，语义上就该由 system-reminder 框住 |
| 内层 `<会话工作目录>` | `[15]` 决策 29/51 定的块名与文案，**逐字保留** |

**两个都留，互不替代。**

⚠ **只拼给 LLM 那一份，落库那份存用户原文** —— 否则历史被污染。

### 1.4 三条硬约束

| 约束 | 说明 |
|---|---|
| **删会话 ≠ 删目录** | 两件事互不牵扯。删会话 = 软删会话 + 清库里的行，**磁盘目录一律不动** |
| **面板移除 = 只改列表** | 从列表移除某个条目，**不许删除磁盘目录**，目录原样留给用户自行处置 |
| **系统绝不删磁盘目录** | 全链路只有 `mkdir`，无 `rmtree`/`unlink`/`os.remove`/`rmdir`（已静态验证） |

### 1.5 两套独立状态（曾被混淆，此处钉死）

| 操作 | 改的是哪套状态 | 与另一套的关系 |
|---|---|---|
| 面板增/删**列表条目** | **列表本身**（配置动作） | 与磁盘上目录在不在**毫无关系** |
| 用户自己删**磁盘目录**（外部事件） | **物理目录** | 列表里那条**仍然在** → 进入会话时按"没有就建立"重建 |

> "从面板移除"是**移除目录的列表**，**与删除没有关系**，不许用删除/重建的语言去描述它。

### 1.6 唯一的不变式

> **列表里有的目录，进入会话时一定存在。**

### 1.7 端点语义

`PATCH /sessions/{id}/workspaces` = **改"会话使用的目录列表"**

### 1.8 复杂度要求

**不许复杂。** 需求就是 1 条建立规则 + 2 个使用点，不许派生额外分支与机制。

## 3. 要怎么修改 修改哪些文件代码

### 3.1 表结构（3 个字段，从第一性推导）

```sql
CREATE TABLE chat_session_workspaces (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT    NOT NULL,
    path       TEXT    NOT NULL COLLATE NOCASE,
    UNIQUE(session_id, path),
    FOREIGN KEY (session_id) REFERENCES chat_sessions(id) ON DELETE CASCADE
);
CREATE INDEX idx_csw_session ON chat_session_workspaces(session_id);
```

> `COLLATE NOCASE`（按本地代码实际）：Windows 大小写不敏感是"比较规则"不是"存储规则"，`C:/A` 与 `c:/a` 库级判重；存值保大小写。存量旧表由 `db_initializer` 按建表语句比对自动迁移（查无 `COLLATE` 即重建搬行）。

**为什么只要这 3 个字段**（从全局推导，不是拍脑袋）：

| 字段 | 回答什么问题 |
|---|---|
| `id` | 主键 |
| `session_id` | 这些目录属于哪个会话 |
| `path` | 目录在哪 |

**为什么这两个字段可以删**：

| 删 | 理由 |
|---|---|
| `is_default` | 唯一用途是"区分授权目录"。授权目录归全局 config 后，表里剩下的全是会话目录，**没有可区分的对象** |
| `ws_initialized` | 唯一用途是"清空后别重建"。但规则是"没有就建立" → **全新会话和已清空会话变成同一件事**，代码路径相同，这个标记没有意义 |

## 4. 实现的结果是什么样的

### 4.1 核心逻辑（最终形态）

```
【建立】进入会话（`reconcile_session_workspaces`，唯一真源）
   rows = 取本会话的目录列表
   if 空:  造默认目录 {项目根}/{YYYYMMDD-HHMMSS}-{会话标识前4位} → 写一行 → 重取
   classify 全套裁决（禁区判定先于存在判定）：
     denied（禁区/系统保护/宽根） → DELETE 该行 + 告警（只删库, 不删磁盘目录）
     missing（非目录或不存在）   → mkdir 建立，终判以重读为准
     非法行                      → 本轮跳过，不抛异常
   ★ 只有这一条规则；编排器只剩 atxn 回调壳

【使用】两处，就两处
   ① 有效列表 → 并入 get_default_allowed_paths()（写白名单）
   ② 有效列表 → 追加到 user 信息尾巴
                <system-reminder><会话工作目录>…</会话工作目录></system-reminder>
                （只拼给 LLM 那份，落库存用户原文）
```

**复杂度对比**：原 4 条分支 + 3 个特殊机制 → 现 **1 条规则 + 2 个使用点**。

### 4.2 用户视角的行为

| 场景 | 结果 |
|---|---|
| 全新会话发第一条消息 | 自动建一个会话目录，LLM 收到该目录，产物落在这里 |
| 继续对话 | 目录还在 → 直接用，无任何动作 |
| **手动删掉磁盘上的目录** | 下次进入会话**自动重建**（列表里那条还在） |
| **面板里从列表移除某条目** | 只改列表，**磁盘目录不动**，LLM 不再收到它 |
| 删会话 | 软删会话 + 清库行，**磁盘目录留着** |
| 清空列表 | 下次进入会话按"没有就建立"重建一个 |
| 禁区路径 | **从表里清掉这一行**，磁盘目录留着；GET 进 `unusable` 带原因（面板可置灰，不再混进可用列表） |

### 4.3 满足的不变式

| # | 不变式 | 保障方式 |
|---|---|---|
| 1 | 列表里有 → 一定存在 | 建立规则兜底 |
| 2 | 系统绝不删磁盘目录 | 全链路只有 `mkdir`（已静态验证） |
| 3 | 落库存用户原文 | 拼接只作用于发给 LLM 那份 |
| 4 | 会话目录 ≠ 授权目录 | 表里只有会话目录；授权走全局 config |
| 5 | 两概念不纠缠 | 各走独立取数口，不遍历对方 |
| 6 | 无多余字段 | 表只 3 字段，无 `is_default`/`ws_initialized` |

### 4.4 明确不做的事

| 不做 | 理由 |
|---|---|
| 不删磁盘目录（任何路径、任何触发） | 硬约束 §1.4 |
| 不做同名目录换名（`-2/-3`） | 用户定案"已存在直接使用" |
| 不做建失败回滚 | 行留着，下次进入会话自动补建（自愈，更简单） |
| 不做"清空后不重建"的标记 | 与"没有就建立"直接冲突 |
| 不在会话层造授权判据 | 授权归全局 config，避免重复造轮子 |
| 不让会话目录遍历/寄居在别的概念容器里 | §1.1 两概念严格分开 |
