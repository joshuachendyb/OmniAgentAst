

## 一、需求要点清单

### 1.1 背景

> **需求原点**：一次授权不再打扰、范围分档且事后可调、跨会话可继承与复制。

| 诉求 | 落地形态 |
|---|---|
| 一次授权不再打扰 | 命中即免弹 |
| 范围分档 + 事后可调 | 三域分档 + 跨域迁移 |
| 「任务」的口径 | 任务级 ＝ 本任务 **及其 link 续聊的任务链（组）**，隔离键＝链根 `chat_tasks.context_root_task_id` |
| 贯穿性约束 | ① 档位不随会话切换漂移 ② 撤销可发现 ③ 不做信任变更历史/导出 |

### 1.1.1 信任条目概念（信任管理 3 版设计）

- 信任来源：产生于系统的权限（授权/确认机制的输出）和记忆、记录。
- 授权/确认是对中风险操作的记录＝信任条目；信任是权限的一部分，是权限规则的应用变化。
- 信任条目定义：核心组＝action+path。
- 信任条目属性：
  - 生效域（生效空间）：全局/会话/任务
  - 产生组（生产者）：会话ID＋任务ID
  - 授权对象（生效对象）：会话ID＋任务ID
- 信任条目管理：
  - 记录存储信任条目
  - 变更信任条目的授权对象/生效对象
### 1.2 信任条目的产生--HTL授权弹窗
1.信任条目产生--
   1.1 目前主要的产生方法 是通过HTL授权弹窗,用户在弹窗中点击同意(包括action和path,生效域,)
   1.2 信任条目的 产生截断:核心组 action+path +生产者组(时间+会话ID+任务ID)
   1.3 在生成的时候 授权对象 就是当时点击的时候的,的启用域设置 生效域\ 授权对象:会话ID,任务ID 
   1.4 启用域  也是 输入框下的 选择项目(全局,会话和任务)

### 1.3 信任条目的需求和属性分析

 2. 信任条目的信息分组（核心组+产生组+生效域+授权对象）

 数据结构的四个信息组：
   核心组 = action + path
   产生组 = 时间 + 会话ID + 任务ID
   生效域 = 全局/会话/任务
   授权对象 = 会话ID + 任务ID

 概念说明：
   - 核心组：action 和 path 为一组。action 必有，path 可没有（bash/系统级命令无路径，只有 action）——第一期只做有 path 的情况。
   - 产生组：产生信任条目时的来源（会话ID+任务ID+时间），是辅助信息。
   - 生效域：数据库字段，3 个值（全局/会话/任务）。
   - 启用域：在输入框下面（会话底部）选择的后续会话和任务的任务条目生效域范围，决定使用哪个域的任务条目。
   - 授权对象：在会话域和任务域的任务条目下，定向指定可以使用的会话是谁、任务是谁。
     授权对象在数据标志有三种情况：无会话ID+无任务ID、有会话ID+无任务ID、无会话ID+有任务ID。
       1) 无会话ID+无任务ID：本会话包括本任务的新会话和新任务都可以使用。
       2) 会话域启用时：生效的是"信任条目的会话ID 为空 + 本会话ID"所属的信任条目。
       3) 任务域启用时：生效的是"任务ID 为空 + 本任务ID"所属的信任条目。
     特别说明：这些任务基本上是 link 任务（只有 link 任务才有长时间存在的可能），单任务生命期只有一次，任务完成了一次指定没有意义。但其信任条目可以迁移到（挪到）其他长生命期的对象（会话、link 任务、全局域）。

 生效域与启用域（均为 全局/会话/任务）：
   在数据库表中是"生效域"的概念（信任条目页面中叫做生效域）。
   在任务执行中是"启用域"，通过输入框下面的启用域（信任域）选择，3 个类型（全局、会话、任务）。

 产生 HTL 点击授权（确认）时的所属域＝当前任务执行时选择的启用域：
   1) 启用域为全局域：产生信任条目，数据库中的信任条目记录设置为全局域，授权对象会话ID和任务ID=空。
   2) 启用域为会话域：产生信任条目，数据库中的信任条目记录设置为会话域，授权对象会话ID=当前会话的ID，任务ID=空。
   3) 启用域为任务域：产生信任条目，数据库中的信任条目记录设置为任务域，授权对象会话ID=当前会话的ID，任务ID=当前任务ID。

 信任的应用对象——统一术语为授权对象（会话ID/任务ID）：
   1) 授权对象会话ID空：选择启用域为会话域时，生效域=会话且会话ID为空，含义是新会话包括新任务启用的信任条目。
   2) 授权对象任务ID空：选择启用域为任务域时，生效域=任务且任务ID为空，含义是新任务使用。

 任务开始执行时，选择使用域/启用域（在输入框下面选择，3 种：全局/会话/任务）：
   1) 选择为全局域：生效的信任条目 = 全局域的信任条目 + 会话域的（当前会话ID 的条目 + 无会话ID 的条目）。
   2) 选择为会话：生效的信任条目 = 会话域的（无会话ID 的条目 + 当前会话ID 的条目）。
   3) 选择为任务：生效的信任条目 = 任务域的（无任务ID 的条目 + 当前任务ID 的条目）。

 信任管理页面——新增的 /trust 页面，展示全部信任条目：
   1) 信任条目定义＝数据结构定义包括 4 个部分：核心组 + 产生组 + 域空间 + 授权对象。
   2) 页面排列：全局列、会话列、任务列。
      - 全局列：以全局为组，显示全局域下的所有信任条目。
      - 会话列：以会话为组，显示会话域的所有信任条目（包括无会话ID 的条目和有会话ID 的条目；有会话ID 但无信任条目的也要显示）。
      - 任务列：以任务为组，显示任务域的所有信任条目（包括无任务ID 的条目和有任务ID 的条目；有任务ID 且为 link 的任务，无信任条目的也要显示）。
   3) 信任条目的变更——只是条目的迁移：
      - 生效域改变：从全局、会话、任务之间的变化。
      - 生效的会话对象改变：在不同会话类型之间变更。
      - 生效的任务对象改变：在不同的 link 任务之间变更挪到。
      - 变更的操作方法：
        1) 在页面内部用拖拽的方法变更，即信任条目块块进行鼠标拖到，拖到到目标区域。
        2) 信任页面的核心 UI 模式是 3 列（全局、会话、任务），对应 3 个域。
        3) 这个页面的基本拖拽对象和元素就是信任条目，核心的就是 action + path 两个信息即可。
        4) 第 2 层 UI 对象是任务组，第 3 层对象是会话组。
        5) 其他的信息决定信任条目在哪个对象里面。

 信任条目的管理＝信任管理页 /trust：
   对信任条目进行所属域的改变——可以在全局、会话和任务 3 个空间进行改变。
   对信任条目生效对象的改变——可以从 A 会话改为 B 会话、从 X 任务改为 Y 任务。

 其他页面的 UI 信任的设计基本上大体没有变化。

## 二、需求要求说明

> 编写：小欧 2026-10-23 20:39:12

### 2.1 背景与目标

**需求原点**：一次授权不再打扰、范围分档且事后可调、跨会话可继承与复制。

| 目标诉求 | 落地形态 |
|---|---|
| 一次授权不再打扰 | 信任条目命中即免弹（HTL） |
| 范围分档 + 事后可调 | 全局/会话/任务三域分档，条目可跨域提升/迁移 |
| 跨会话继承 | 全局域条目全局生效；会话 A→B 导入 |
| "任务"的口径 | 任务级 = 本任务及其 link 续聊的任务链（组）；隔离键 = 链根 `chat_tasks.context_root_task_id` |

贯穿性约束：① 档位不随会话切换漂移；② 撤销可发现；③ 不做信任变更历史/导出。

### 2.2 信任条目定义

信任条目 = 中风险操作授权/确认的记录；信任是权限的一部分（权限规则的应用产物）。

条目数据结构由四组构成：

| 信息组 | 字段 | 说明 |
|---|---|---|
| 核心组 | action + path | 条目主体。action 必有；path 可缺（bash/系统级命令无路径）。一期只处理有 path 的条目 |
| 产生组 | 时间 + 会话ID + 任务ID | 条目产生时的来源（辅助信息） |
| 生效域 | 全局 / 会话 / 任务 | 数据库三值字段，决定条目归属域 |
| 授权对象 | 会话ID / 任务ID | 定向指定条目可用的会话/任务，可空 |

### 2.3 产生机制（HTL 授权弹窗）

- 产生入口：HTL 授权弹窗，用户点击"同意"生成条目；弹窗选择含 action、path 与生效域。
- 产生截断：核心组(action+path) + 产生组(时间+会话ID+任务ID)。
- 授权对象继承：生成时，授权对象取当时的"启用域"选择（会话ID、任务ID），规则见 2.4。
- 一期范围：只做有 path 的条目；无 path 的 bash/系统级命令（仅 action）不纳入。

### 2.4 生效域与启用域语义

- 生效域：数据库字段，三值 全局/会话/任务；信任条目页面中称"生效域"。
- 启用域：任务执行时输入框下方的选择项（全局/会话/任务），决定本任务使用哪些条目。

产生 HTL 授权时，条目生效域 = 当前任务执行所选的启用域，并据此设定授权对象：

| 启用域 | 条目生效域 | 授权对象·会话ID | 授权对象·任务ID |
|---|---|---|---|
| 全局 | 全局 | 空 | 空 |
| 会话 | 会话 | 当前会话ID | 空 |
| 任务 | 任务 | 当前会话ID | 当前任务ID |

### 2.5 应用矩阵（任务执行时按启用域取条目）

任务开始执行时，在输入框下方选择"使用域/启用域"（全局/会话/任务），按下表取生效的条目集合：

| 启用域 | 生效的信任条目集合 |
|---|---|
| 全局 | 全局域条目 + 会话域（当前会话ID 条目 + 无会话ID 条目） |
| 会话 | 会话域（无会话ID 条目 + 当前会话ID 条目） |
| 任务 | 任务域（无任务ID 条目 + 当前任务ID 条目） |

统一术语：条目的应用对象称"授权对象"（会话ID/任务ID）。

### 2.6 授权对象空值语义

授权对象标志共三种组合：无会话ID+无任务ID、有会话ID+无任务ID、无会话ID+有任务ID。

| 场景 | 含义 |
|---|---|
| 会话ID空 + 任务ID空 | 本会话及本任务下的新会话、新任务均可使用 |
| 会话域启用 + 会话ID空 | 生效"会话ID空"条目 + 本会话ID所属条目 |
| 任务域启用 + 任务ID空 | 生效"任务ID空"条目 + 本任务ID所属条目 |

特别说明：任务域条目主要面向 link 任务（单任务生命期仅一次，完成后指向无意义；仅 link 任务长期存在）。单任务条目可迁移到长生命期对象（会话、link 任务）及全局域。

### 2.7 信任管理页 /trust

定位：展示全部信任条目，支持域间迁移与对象变更。

**三列布局**（核心 UI 模式，对应三域）：

| 列 | 分组 | 显示内容 |
|---|---|---|
| 全局列 | 全局域 | 全局域下所有条目 |
| 会话列 | 会话 | 会话域所有条目：含"会话ID空"的新会话组（对应会话ID空条目的授权范围）+ 含具体会话ID 的会话组；空会话组也显示 |
| 任务列 | 任务 | 任务域所有条目：含"任务ID空"的新任务组（对应任务ID空条目的授权范围，新任务可为单次任务或 link 任务）+ 含具体任务ID 的任务组；空任务组也显示 |

**条目变更**（改生效域＋授权对象，**核心组 action+path 恒不变**），分两种语义：
- **生效域变更**：全局/会话/任务之间迁移（落不同列）。
- **生效对象变更**：A会话→B会话；X任务→Y任务（同列落不同组）。
- **挪动模式（两种，均支持）**：
  - **移动（move）**：条目挪到目标位置，**原位置失效**（原处不再免弹）。
  - **复制（copy）**：条目在目标位置**新增一份**，**原位置继续生效**（两边各一条，按启用域标志独立判定，无覆盖概念）。
  - 两种模式的核心组（action+path）不变；差别仅在"原位置条目是否保留"。

**变更交互（拖拽）**：
- 拖拽对象：条目块，核心信息为 action+path。
- 拖拽目标：目标区域对应的列/组（全局列/会话组/任务组）。
- 模式选择：移动/复制 二选一（默认复制，保证不悄悄收回既有授权；收紧须显式选移动）。
- UI 层级：第1层=条目块(action+path)；第2层=任务组；第3层=会话组。
- 产生组、授权对象等其他信息，决定条目落在哪个组内。

**范围约束**：本次仅变更 /trust 页；其他页面的信任相关 UI 大体保持不变。

### 2.8 贯穿约束

- 档位不随会话切换漂移：会话切换时，已选档位保持不变。
- 撤销可发现：条目的撤销（迁移/删除）在页面可被用户发现。
- 不做信任变更历史/导出：不记录变更流水，不提供导出。

## 三、需求分析（基于 §一 需求要点 + §二 需求说明梳理）

> 编写：小欧 2026-10-23 21:50:04
> 基准=47 号三域（全局/会话/任务）。45 号（10-21）的"未来域 session_future/task_future、继承链 parent/root、superseded 状态机"与 47 号三域口径冲突，**全部砍掉**，本章不复用；只保留与域数无关的底层设施（统一表、action 精确命中、路径归一、fail-closed、层界、TTL）。

### 3.1 信任条目的概念模型（三域）

**条目本质**：中风险操作授权/确认的记录，是权限的一部分。

**不变组与可变组**：

| 组 | 内容 | 可变性 |
|------|------|--------|
| **核心组**（最核心，不变） | `action`＋`path` | 不可改（改动＝另一条条目） |
| **产生组**（辅助，可有可无） | 时间＋会话ID＋任务ID | 不可改（溯源用） |
| 生效域 | 全局/会话/任务 | **可改**（变更时迁移到别的域） |
| 授权对象 | 会话ID/任务ID | 可改（换归属对象） |

> 变更只动"生效域＋授权对象"，**核心组（action+path）恒不变**。

**域只有三档，唯一归属维度**：

| 域 | 取值 | 归属标识 | 免弹范围 |
|------|------|----------|----------|
| 全局域 | `global` | 无（owner_* 置 `''`） | 所有会话所有任务 |
| 会话域 | `session` | `owner_session_id` | 本会话所有任务 |
| 任务域 | `task` | `owner_session_id` + `owner_root_task_id`（链根） | 本上下文链内 |

> **三域按启用域标志独立判定**：任务执行时按当前启用域查条目集合（见 3.3），**取用只看启用域标志，不存在"大域覆盖小域"**——选"会话"档时全局条目不在本档生效，选"全局"档时才查到全局条目。域之间无覆盖/包含关系。

### 3.2 产生机制（HTL 授权弹窗，三域）

- 产生入口：HITL 弹窗点击"同意"生成条目。
- 产生截断：核心组(action+path)＋ 产生组(时间+会话ID+任务ID)＋ 生效域（scope，由启用域决定）。
- **新条目的域 = 勾选瞬间底栏所选档位（启用域）**，按 2.4 表设定归属：

| 启用域 | 条目 scope | 归属·会话 | 归属·任务 |
|--------|-----------|----------|----------|
| 全局 | `global` | `''` | `''` |
| 会话 | `session` | 当前会话ID | `''` |
| 任务 | `task` | 当前会话ID | 当前链根ID |

> **一期范围**：只做有 path 的条目；无 path 的 bash/系统级命令（仅 action）不纳入。

### 3.3 取用机制（按启用域取条目集合）

任务执行时按当前"启用域"取生效条目，**不是恒三域全查**：

| 启用域 | 生效条目集合 |
|--------|-------------|
| 全局 | 全局域条目 + 会话域（当前会话ID 条目 + 无会话ID 条目） |
| 会话 | 会话域（无会话ID 条目 + 当前会话ID 条目） |
| 任务 | 任务域（无任务ID 条目 + 当前任务ID 条目） |

> 与 45 号"恒五域全查、档位不参与查询"相反：**47 号启用域是查询过滤器**，选"会话"档时全局条目不在本档生效。

### 3.4 信任管理页 /trust 与条目挪动（三列布局 + 空归属组 + move/copy）

本页是"条目挪动"的主战场，把**页面布局 → 空归属组 → 挪动语义**串成一体：

**① 三列布局（列＝域）**：

| 列 | 分组 | 显示内容 |
|------|------|----------|
| 全局列 | 全局（**一个组**） | 全局域下所有条目 |
| 会话列 | 会话 | 会话域全部条目：含"会话ID空"的新会话组 + 含具体会话ID 的会话组；**空会话组也显示** |
| 任务列 | 任务 | 任务域全部条目：含"任务ID空"的新任务组（新任务可为单次或 link）+ 含具体任务ID 的任务组；**空任务组也显示** |

> **所有组都是合法落点**：全局组、具体会话组、具体任务链组、⟨新会话⟩/⟨新任务⟩ 空归属组、以及暂时无条目的具体会话组/任务链组，**均可落入，组内条目也可挪走**。落点＝(列, 组)，唯一确定"域＋授权对象"。
> 空归属组不是占位符：它是**实际的新会话/新任务对象**（见 ②），条目落入即把授权对象改为空归属，**生效范围随之变成"新会话/新任务"**，语义清晰、允许操作。

**② 空归属组（同域内空授权对象）**：

| 组 | 数据标志 | 含义 |
|------|----------|------|
| 新会话组（会话列） | `scope=session` 且 `owner_session_id=''` | 本会话及本任务下的新会话、新任务均可使用 |
| 新任务组（任务列） | `scope=task` 且 `owner_root_task_id=''` | 本任务下的新任务使用 |

> 空归属组是**实际的新会话/新任务对象**，不是 UI 占位；取用时"启用域=会话"生效"会话ID空条目 + 本会话ID条目"，"启用域=任务"生效"任务ID空条目 + 本任务ID条目"。

**③ 条目挪动（拖拽，对象=条目块 action+path，落点=列+组）**：

条目变更 = 改生效域＋授权对象（**核心组 action+path 恒不变**）：
- **生效域变更**：全局/会话/任务之间迁移（落不同列）。
- **生效对象变更**：A会话→B会话、X任务→Y任务（同列落不同组）。

挪动两模式（均支持）：

| 模式 | 数据语义 | 用户可见 |
|------|----------|----------|
| 移动（move） | **删源行**，目标位置新建行（核心组不变，仅生效域/授权对象改） | 源组少一条、目标组多一条 |
| 复制（copy） | 源行**保留**，目标位置另建一条（两边各一条） | 源组仍在、目标组多一条 |

> 默认复制（不悄悄收回既有授权，收紧须显式移动）。copy 后两条各自按启用域标志独立判定，无"覆盖"概念——选哪一档，就按 3.3 查哪一档的条目集合。
> **move/copy 不走 `status` 字段**：move=直接删源行（物理删，非置 revoked）；copy=不动源行。`status` 只服务"撤销"场景（见 §3.5）。

> **单任务条目可迁移到长生命期对象**（会话/link 任务/全局域）。任务域条目主要面向 link 任务（单任务生命期一次，完成后指向无意义；仅 link 任务长期存在）。

### 3.5 数据表结构（统一表 `chat_trust`）

三域合为一张表，靠 `scope` 列区分；`owner_*` 两列承载授权对象（可空，`''` 哨兵表示该维度不适用）。**不复用 45 号继承链 4 列（parent_* / root_*）与未来域 scope 值**。

**字段总表**：

| 字段 | 类型 | 必填 | 含义 | 取值/规则 |
|------|------|------|------|----------|
| `id` | INTEGER PK | ✅ | 行唯一标识 | 自增 |
| `scope` | TEXT | ✅ | **生效域**（3 值） | `session` / `task` / `global` |
| `owner_session_id` | TEXT | ✅（可 `''`） | **授权对象·会话ID** | global 域＝`''`；session/task 域＝该会话ID；**可空**（空＝新会话组，见 3.4 ②） |
| `owner_root_task_id` | TEXT | ✅（可 `''`） | **授权对象·任务ID（链根）** | 非 task 域＝`''`；task 域＝链根 `context_root_task_id`；**可空**（空＝新任务组，见 3.4 ②） |
| `action` | TEXT | ✅ | **核心组① 动作** | `read` / `write` / `delete`（取 `tool_constants` 真源） |
| `path` | TEXT | ✅（可 `''`） | **核心组② 路径**（登记范围） | 经 `trust_scope_path` 目录收敛；`''`＝不限路径（一期无 path 条目不入库，仅保留字段） |
| `tool_name` | TEXT | ✅（可 `''`） | 溯源（非主体） | 创建时用的工具名；不参与命中判定、不入唯一键 |
| `creator_session_id` | TEXT | ✅（可 `''`） | **产生组·会话ID** | 条目产生时的会话（不可变，溯源） |
| `creator_task_id` | TEXT | ✅（可 `''`） | **产生组·任务ID** | 条目产生时的任务（不可变，溯源） |
| `created_at` | TEXT | ✅ | **产生组·时间** | 条目产生时刻；同键 UPSERT 冲突**不刷新** |
| `status` | TEXT | ✅ | 行状态 | `active`（生效）/ `revoked`（被撤销）；**只服务"撤销可发现"**（撤销=置 revoked 留库可发现，非物理删）；**move/copy 不走此字段**（move 直接删源行、copy 不动源行，见 3.4③） |
| `expires_at` | TEXT | ⭕（可 `NULL`） | 生命周期 | `NULL`＝不过期；`now + ttl_days`；同键未过期不续期 |

**唯一键**：`UNIQUE(scope, owner_session_id, owner_root_task_id, action, path)`

> 唯一键含 `scope`＋归属两列＋核心组（action+path）。**归属列可空（`''`）**正是"同域内空归属"（3.4 新会话组/新任务组）的落库表达：会话域行 `owner_session_id=''`＝新会话组条目；任务域行 `owner_root_task_id=''`＝新任务组条目。
> `tool_name` **不入键**：同一 (scope, 归属, action, path) 被不同工具触发时只更新该字段（"最后一次是谁点的"），不新增行。
> **撤销**：置 `status='revoked'`，留库可发现（非物理删，对应 §二 2.8"撤销可发现"）；物理清除交给 TTL 回收（只删 `status='revoked'` 且已到期行）。**move 不走 status**（直接物理删源行）；**copy 不动源行**。

**`chat_sessions` 补列**：

| 字段 | 类型 | 含义 |
|------|------|------|
| `trust_mode` | TEXT（可空） | 会话级档位（启用域缺省值），取值 `session`/`task`/`global`；`NULL`＝跟随配置 `trust.mode`；底栏开关随消息上送，确认落库时回写 |

> 产生时 `scope` 由"勾选瞬间的启用域"决定（3.2 表）；`owner_*` 按启用域填（全局＝全空、会话＝当前会话ID+任务空、任务＝当前会话ID+当前链根）。

### 3.7 跨会话导入（A→B）

**定位**：会话页面的快捷操作（与"复制"类似），把 **A 会话的信任条目复制到 B 会话**；导入行的会话ID 都指**授权对象的会话ID**（`owner_session_id`）。

**导入语义**：

| 项 | 口径 |
|------|------|
| 导入对象 | A 会话的**会话域**条目（`scope=session`，`owner_session_id=A`） |
| 复制方式 | 在 B 会话**新增**同核心组（action+path）的行，`owner_session_id` 改为 **B** |
| 保留 | 源行的 `created_at`、`expires_at`（不续期） |
| 不导入 | 全局域条目（本就跨会话可见）、任务域条目（绑定任务链，须先提升到会话域才能导入） |
| 去重 | 目标键（scope, owner_session_id=B, action, path）已存在则**跳过**（幂等，不覆盖 B 的既有行） |
| 撤销 | 导入行独立，撤销 B 的导入行不影响 A 的源行 |

> 导入=把 A 会话"已记住的授权"批量复制到 B 会话，使 B 会话获得同等的会话域信任面。会话ID 全程指**授权对象**（`owner_session_id`），不是产生组/创建者。

**UI 层级（§一 1.3 第 7.3.4 条）**

> 第 1 层＝**条目块**（action＋path）；第 2 层＝**任务组**；第 3 层＝**会话组**。
> 即：一个会话可含多条任务链 → **会话（3）⊃ 任务链组（2）⊃ 条目（1）**。
> 会话列以会话成组；任务列按"会话 → 任务链"两级呈现（同链条目归同一任务组，其外层是所属会话）。

**矩阵规格**

| 维度 | 定义 |
|------|------|
| 列＝域 | 全局 / 会话 / 任务 |
| 全局列 | **一个"全局"组**（§一 7.2"以全局为组"） |
| 会话列组 | ⟨新会话⟩（`owner_session_id=''`）＋ 每个具体会话一组；**无条目的会话也显示** |
| 任务列组 | ⟨新任务⟩（`owner_root_task_id=''`）＋ 每条 **link 任务链**一组；**该链无条目也显示**。单次任务生命期一次，不成组（§一 7.2 只要求 link 任务显示） |
| 组内条目 | 一条信任一张卡；「读 D:\work」与「写 D:\work」是两张卡，**不合并** |
| 组头 | 授权对象名 ＋ 条数；`当前` 标记当前会话/当前链 |
| 条目卡 | 动作徽标（读/写/删）＋ 路径（末段显示，完整路径 Tooltip）＋ 过期时间（有则显示） |
| 新增展示 | 组内/卡上**不标"覆盖/更宽"**（47 号无覆盖关系） |

**组的语义与可操作性（授权对象三组合，§2.6）**

| 组 | 数据标志 | 使用范围 | 可否作落点 |
|------|----------|----------|-----------|
| 全局组 | `scope=global`, `owner_*=空` | 启用域＝全局时，所有会话所有任务 | ✅ |
| ⟨新会话⟩ | `scope=session`, `owner_session_id=''` | 启用域＝会话或全局时，新会话（含其新任务） | ✅（实际的新会话对象） |
| ⟨具体会话⟩ | `scope=session`, `owner_session_id=X` | 启用域＝会话或全局时，会话 X | ✅（空组也可） |
| ⟨新任务⟩ | `scope=task`, `owner_root_task_id=''` | 启用域＝任务时，新任务 | ✅ |
| ⟨具体链⟩ | `scope=task`, `owner_root_task_id=Y` | 启用域＝任务时，链 Y | ✅（空组也可） |

> 空归属组不是占位：落入即把授权对象改为"新会话/新任务"，条目**从该组也可拖走**（§3.4①）。

**撤销可发现（§2.8）**：页头保留"已撤销 N 条 [查看]"入口，列出 `status='revoked'` 条目（只读、可清理）。不做变更历史、不做导出（§2.8）。

### 4.6 D · /trust 页 · 拖拽改域（move / copy）

**落点模型**

> 列＝域、组＝授权对象。落点＝(列, 组)，同时定"域"和"归属"。所有组都能落（含空组、空归属组、全局组）；**原位**（同列同组）不可落。三列之间与列内组间均可拖，无级数限制。

|------|------|----------|
