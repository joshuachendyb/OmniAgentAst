

## 一、需求要点清单

### 1.1 背景

> **需求原点**：一次授权不再打扰、范围分档且事后可调、跨会话可复制或移动。

| 诉求 | 落地形态 |
|---|---|
| 一次授权不再打扰 | 命中即免弹 |
| 范围分档 + 事后可调 | 三域分档 + 跨域迁移 |
| 「任务」的口径 | 任务级 ＝ 本任务 **及其 link 续聊的任务链（组）**，隔离键＝链根 `chat_tasks.context_root_task_id` |
| 贯穿性约束 | ① 档位不随会话切换漂移 ② 撤销可发现 ③ 不做信任变更历史/导出 |

### 1.1.1 信任条目概念（信任管理 3 版设计）

- 信任来源：产生于系统的权限（授权/确认机制的输出）和记忆、记录。
- 授权/确认是对中风险操作的记录＝信任条目；信任是权限的一部分，是权限规则的应用变化。
- 信任条目定义：核心组＝action+path。
- 信任条目属性：
  - 生效域（生效空间）：全局/会话/任务
  - 产生组（生产者）：会话ID＋任务ID
  - 授权对象（生效对象）：会话ID＋任务ID
- 信任条目管理：
  - 记录存储信任条目
  - 变更信任条目的授权对象/生效对象
### 1.2 信任条目的产生--HTL授权弹窗
1.信任条目产生--
   1.1 目前主要的产生方法 是通过HTL授权弹窗,用户在弹窗中点击同意(包括action和path,生效域,)
   1.2 信任条目的 产生截断:核心组 action+path +生产者组(时间+会话ID+任务ID)
   1.3 在生成的时候 授权对象 就是当时点击的时候的,的启用域设置 生效域\ 授权对象:会话ID,任务ID 
   1.4 启用域  也是 输入框下的 选择项目(全局,会话和任务)

### 1.3 信任条目的需求和属性分析

 2. 信任条目的信息分组（核心组+产生组+生效域+授权对象）

 数据结构的四个信息组：
   核心组 = action + path
   产生组 = 时间 + 会话ID + 任务ID
   生效域 = 全局/会话/任务
   授权对象 = 会话ID + 任务ID

 概念说明：
   - 核心组：action 和 path 为一组。action 必有，path 可没有（bash/系统级命令无路径，只有 action）——第一期只做有 path 的情况。
   - 产生组：产生信任条目时的来源（会话ID+任务ID+时间），是辅助信息。
   - 生效域：数据库字段，3 个值（全局/会话/任务）。
   - 启用域：在输入框下面（会话底部）选择的后续会话和任务的任务条目生效域范围，决定使用哪个域的任务条目。
   - 授权对象：在会话域和任务域的任务条目下，定向指定可以使用的会话是谁、任务是谁。
     授权对象在数据标志有三种情况：无会话ID+无任务ID、有会话ID+无任务ID、无会话ID+有任务ID。
       1) 无会话ID+无任务ID：本会话包括本任务的新会话和新任务都可以使用。
       2) 会话域启用时：生效的是"信任条目的会话ID 为空 + 本会话ID"所属的信任条目。
       3) 任务域启用时：生效的是"任务ID 为空 + 本任务ID"所属的信任条目。
     特别说明：这些任务基本上是 link 任务（只有 link 任务才有长时间存在的可能），单任务生命期只有一次，任务完成了一次指定没有意义。但其信任条目可以迁移到（挪到）其他长生命期的对象（会话、link 任务、全局域）。

 生效域与启用域（均为 全局/会话/任务）：
   在数据库表中是"生效域"的概念（信任条目页面中叫做生效域）。
   在任务执行中是"启用域"，通过输入框下面的启用域（信任域）选择，3 个类型（全局、会话、任务）。

 产生 HTL 点击授权（确认）时的所属域＝当前任务执行时选择的启用域：
   1) 启用域为全局域：产生信任条目，数据库中的信任条目记录设置为全局域，授权对象会话ID和任务ID=空。
   2) 启用域为会话域：产生信任条目，数据库中的信任条目记录设置为会话域，授权对象会话ID=当前会话的ID，任务ID=空。
   3) 启用域为任务域：产生信任条目，数据库中的信任条目记录设置为任务域，授权对象会话ID=当前会话的ID，任务ID=当前任务ID。

 信任的应用对象——统一术语为授权对象（会话ID/任务ID）：
   1) 授权对象会话ID空：选择启用域为会话域时，生效域=会话且会话ID为空，含义是新会话包括新任务启用的信任条目。
   2) 授权对象任务ID空：选择启用域为任务域时，生效域=任务且任务ID为空，含义是新任务使用。

 任务开始执行时，选择使用域/启用域（在输入框下面选择，3 种：全局/会话/任务）：
   1) 选择为全局域：生效的信任条目 = 全局域的信任条目 + 会话域的（当前会话ID 的条目 + 无会话ID 的条目）。
   2) 选择为会话：生效的信任条目 = 会话域的（无会话ID 的条目 + 当前会话ID 的条目）。
   3) 选择为任务：生效的信任条目 = 任务域的（无任务ID 的条目 + 当前任务ID 的条目）。

 信任管理页面——新增的 /trust 页面，展示全部信任条目：
   1) 信任条目定义＝数据结构定义包括 4 个部分：核心组 + 产生组 + 域空间 + 授权对象。
   2) 页面排列：全局列、会话列、任务列。
      - 全局列：以全局为组，显示全局域下的所有信任条目。
      - 会话列：以会话为组，显示会话域的所有信任条目（包括无会话ID 的条目和有会话ID 的条目；有会话ID 但无信任条目的也要显示）。
      - 任务列：以任务为组，显示任务域的所有信任条目（包括无任务ID 的条目和有任务ID 的条目；有任务ID 且为 link 的任务，无信任条目的也要显示）。
   3) 信任条目的变更——只是条目的迁移：
      - 生效域改变：从全局、会话、任务之间的变化。
      - 生效的会话对象改变：在不同会话类型之间变更。
      - 生效的任务对象改变：在不同的 link 任务之间变更挪到。
      - 变更的操作方法：
        1) 在页面内部用拖拽的方法变更，即信任条目块块进行鼠标拖到，拖到到目标区域。
        2) 信任页面的核心 UI 模式是 3 列（全局、会话、任务），对应 3 个域。
        3) 这个页面的基本拖拽对象和元素就是信任条目，核心的就是 action + path 两个信息即可。
        4) 第 2 层 UI 对象是任务组，第 3 层对象是会话组。
        5) 其他的信息决定信任条目在哪个对象里面。

 信任条目的管理＝信任管理页 /trust：
   对信任条目进行所属域的改变——可以在全局、会话和任务 3 个空间进行改变。
   对信任条目生效对象的改变——可以从 A 会话改为 B 会话、从 X 任务改为 Y 任务。

 其他页面的 UI 信任的设计基本上大体没有变化。

## 二、需求要求说明


### 2.1 背景与目标

**需求原点**：一次授权不再打扰、范围分档且事后可调、跨会话可复制或移动。

| 目标诉求 | 落地形态 |
|---|---|
| 一次授权不再打扰 | 信任条目命中即免弹（HTL） |
| 范围分档 + 事后可调 | 全局/会话/任务三域分档，条目可跨域迁移 |
| "任务"的口径 | 任务级 = 本任务及其 link 续聊的任务链（组）；隔离键 = 链根 `chat_tasks.context_root_task_id` |

贯穿性约束：① 档位不随会话切换漂移；② 撤销可发现；③ 不做信任变更历史/导出。

### 2.2 信任条目定义

信任条目 = 中风险操作授权/确认的记录；信任是权限的一部分（权限规则的应用产物）。

条目数据结构由四组构成：

| 信息组 | 字段 | 说明 |
|---|---|---|
| 核心组 | action + path | 条目主体。action 必有；path 可缺（bash/系统级命令无路径）。一期只处理有 path 的条目 |
| 产生组 | 时间 + 会话ID + 任务ID | 条目产生时的来源（辅助信息） |
| 生效域 | 全局 / 会话 / 任务 | 数据库三值字段，决定条目归属域 |
| 授权对象 | 会话ID / 任务ID（数组：单任务=[自身task_id]，link 任务链=[链根]） | 定向指定条目可用的会话/任务；可空＝不绑定具体对象 |

### 2.3 产生机制（HTL 授权弹窗）

- 产生入口：HTL 授权弹窗，用户点击"同意"生成条目；弹窗**显示** action、path 与生效域（生效域取输入框底部所选值，弹窗内不可选）。
- 产生截断：核心组(action+path) + 产生组(时间+会话ID+任务ID)。
- 授权对象取值：生成时取当时的"启用域"选择（会话ID、任务ID 数组：单任务=[自身task_id]，link 任务链=[链根 `context_root_task_id`]），规则见 2.4。
- 一期范围：只做有 path 的条目；无 path 的 bash/系统级命令（仅 action）不纳入。

### 2.4 生效域与启用域语义

- 生效域：数据库字段，三值 全局/会话/任务；信任条目页面中称"生效域"。
- 启用域：输入框下方的选择项（全局/会话/任务）。产生条目时决定条目生效域（下表）；任务执行时按 2.5 取生效条目。

产生 HTL 授权时，条目生效域 = 当前任务执行所选的启用域，并据此设定授权对象：

| 启用域 | 条目生效域 | 授权对象·会话ID | 授权对象·任务ID（数组） |
|---|---|---|---|
| 全局 | 全局 | 空 | 空 |
| 会话 | 会话 | 当前会话ID | 空 |
| 任务 | 任务 | 当前会话ID | 单任务=[自身task_id]；link 任务链=[链根 `context_root_task_id`] |

> 任务域对单任务与 link 任务链同等适用；link 链按链根归属，链内任务共享同一批任务域条目。

### 2.5 应用矩阵（任务执行时按启用域取条目）

任务开始执行时，在输入框下方选择"使用域/启用域"（全局/会话/任务），按下表取生效的条目集合（任务＝单任务或 link 任务链；单任务按自身 task_id 匹配，link 按链根 `context_root_task_id` 匹配）：

| 启用域 | 生效的信任条目集合 |
|---|---|
| 全局 | 全局域条目 + 会话域（当前会话ID 条目 + 无会话ID 条目） |
| 会话 | 会话域（无会话ID 条目 + 当前会话ID 条目） |
| 任务 | 任务域（无任务ID 条目 + 本任务归属键条目） |

统一术语：条目的应用对象称"授权对象"（会话ID / 任务ID 数组）。

> **术语对齐 §一**：§一 中"授权对象"（1.3 概念定义）与"生效对象"（1.3 变更处、92–94 管理处置）指同一条。本文统一：数据列与字段称"授权对象"（落库为 `owner_*`）；描述变更动作沿用 §一 说法"生效对象变更"（＝换归属对象）。

### 2.6 授权对象空值语义

空值＝不绑定具体对象：

| 空值 | 含义 |
|---|---|
| 会话ID空（会话域） | 不绑定具体会话：本会话与新会话（含其新任务）都取用 |
| 任务ID空（任务域） | 不绑定具体任务：本任务与新任务都取用 |
| 两者都空 | 全局域（scope=global）；会话域/任务域的空归属组同为两列皆空，靠 scope 区分 |

产生时按 2.4 表填：全局＝都空；会话＝会话ID有值、任务ID空；任务＝会话ID有值、任务ID数组（单任务=[自身task_id]，link 任务链=[链根]）。

> **组合口径（补全 §一 1.3 列举的三种情况）**：本文实际三类条目为 ①两列皆空（全局域，或任务域 ⟨无任务ID⟩ 组）、②仅会话ID（会话域）、③会话ID＋任务ID数组（任务域具体组）——任务域具体组按 §一 1.3 产生规则必须同时带"当前会话ID＋任务ID"，故 §一 1.3 所列"无会话ID＋有任务ID"不成条目。
取用时按 2.5 表：会话域启用 → "会话ID空"条目 ＋ 本会话ID条目；任务域启用 → "任务ID空"条目 ＋ 本任务归属键条目。取用只发生在任务执行时，已完成的老任务不追溯。

特别说明：任务域条目对单任务与 link 任务链同等适用。单任务生命期一次；link 任务链长期存在，按链根归属。任务域条目可迁移到长生命期对象（会话、link 任务链）及全局域。

### 2.7 信任管理页 /trust

定位：展示全部信任条目，支持域间迁移与对象变更。

**三列布局**（核心 UI 模式，对应三域）：

| 列 | 分组 | 显示内容 |
|---|---|---|
| 全局列 | 全局域 | 全局域下所有条目 |
| 会话列 | 会话 | 会话域所有条目：含"会话ID空"的无归属组（不绑定具体会话）+ 含具体会话ID 的会话组；空会话组也显示 |
| 任务列 | 任务（单任务 / link 任务链） | 任务域所有条目：含"任务ID空"的无归属组 + 含具体任务归属键的组（单任务一组、link 链一组，`owner_task_kind` 标注）；无条目的 link 任务链组也显示（单任务组仅在有条目时显示） |

**条目变更**（改生效域＋授权对象，**核心组 action+path 恒不变**），分两种语义：
- **生效域变更**：全局/会话/任务之间迁移（落不同列）。
- **生效对象变更**：A会话→B会话；X任务→Y任务（同列落不同组）。
- **挪动模式（两种，均支持）**：
  - **移动（move）**：条目挪到目标位置，**原位置失效**（原处不再免弹）。
  - **复制（copy）**：条目在目标位置**新增一份**，**原位置继续生效**（两边各一条，按启用域标志独立判定，无覆盖概念）。
  - 两种模式的核心组（action+path）不变；差别仅在"原位置条目是否保留"。

**变更交互（拖拽）**：
- 拖拽对象：条目块，核心信息为 action+path。
- 拖拽目标：目标区域对应的列/组（全局列/会话组/任务组）。
- 模式选择：移动/复制 二选一（默认复制，保证不悄悄收回既有授权；收紧须显式选移动）。
- UI 层级：第1层=条目块(action+path)；第2层=任务组；第3层=会话组。
- 生效域＋授权对象决定条目落在哪个组内；产生组仅用于溯源，不决定分组。

**范围约束**：本次仅变更 /trust 页；其他页面的信任相关 UI 大体保持不变。

### 2.8 贯穿约束

- 档位不随会话切换漂移：会话切换时，已选档位保持不变。
- 撤销可发现：条目撤销后置 `revoked` 留库，页面可被发现（`/trust` 页"已撤销"入口）。
- 不做信任变更历史/导出：move/copy 属变更，不留流水；不提供导出。

## 三、需求分析（基于 §一 需求要点 + §二 需求说明梳理）

> 更新：小欧 2026-10-24 06:40:16（一致性核查修订：档位初始值去 `trust.mode`、补删会话清除口径、Drawer 示例对齐取用矩阵、术语与组合口径桥接 §一、图示示例统一、补 `blocked` 不受豁免注、修三处章节引用）

### 3.1 信任条目的概念模型（三域）

**条目本质**：中风险操作授权/确认的记录，是权限的一部分。

**不变组与可变组**：

| 组 | 内容 | 可变性 |
|------|------|--------|
| **核心组**（最核心，不变） | `action`＋`path` | 不可改（改动＝另一条条目） |
| **产生组**（辅助，可有可无） | 时间＋会话ID＋任务ID | 不可改（溯源用） |
| 生效域 | 全局/会话/任务 | **可改**（变更时迁移到别的域） |
| 授权对象 | 会话ID/任务ID | 可改（换归属对象） |

> 变更只动"生效域＋授权对象"，**核心组（action+path）恒不变**。

**域只有三档，唯一归属维度**：

| 域 | 取值 | 归属标识 |
|------|------|----------|
| 全局域 | `global` | 无（`owner_session_id=''`、`owner_task_ids=[]`） |
| 会话域 | `session` | `owner_session_id` |
| 任务域 | `task` | `owner_session_id` + `owner_task_ids`（数组：单任务=[自身task_id]，link=[链根]） + `owner_task_kind` |

### 3.2 产生机制（HTL 授权弹窗，三域）

- 产生入口：HITL 弹窗点击"同意"生成条目。
- 产生截断：核心组(action+path)＋ 产生组(时间+会话ID+任务ID)＋ 生效域（scope，由启用域决定）。
- **新条目的域 = 勾选瞬间底栏所选档位（启用域）**，按 2.4 表设定归属：

| 启用域 | 条目 scope | 归属·会话 | 归属·任务 |
|--------|-----------|----------|----------|
| 全局 | `global` | `''` | `[]` |
| 会话 | `session` | 当前会话ID | `[]` |
| 任务 | `task` | 当前会话ID | 单任务=[自身task_id]；link=[链根 `context_root_task_id`] |

> **一期范围**：只做有 path 的条目；无 path 的 bash/系统级命令（仅 action）不纳入。

### 3.3 取用机制（按启用域取条目集合）

任务开始执行时，按启用域取生效条目集合：

| 启用域 | 生效条目集合 |
|--------|-------------|
| 全局 | 全局域条目 + 会话域（当前会话ID 条目 + 无会话ID 条目） |
| 会话 | 会话域（无会话ID 条目 + 当前会话ID 条目） |
| 任务 | 任务域（无任务ID 条目 + 本任务归属键条目） |

> 任务＝单任务或 link 任务链：单任务按自身 `task_id` 匹配；link 按链根 `context_root_task_id` 匹配。取用只发生在任务执行时，已完成的老任务不追溯。
> 命中前提：`status='active'` 且未过期（`expires_at > now`）；已撤销、已过期的条目不参与取用。

### 3.4 信任管理页 /trust 与条目挪动（三列布局 + 空归属组 + move/copy）

本页是"条目挪动"的主战场，把**页面布局 → 空归属组 → 挪动语义**串成一体：

**① 三列布局（列＝域）**：

| 列 | 分组 | 显示内容 |
|------|------|----------|
| 全局列 | 全局（**一个组**） | 全局域下所有条目 |
| 会话列 | 会话 | 会话域全部条目：含"会话ID空"的无归属组 + 含具体会话ID 的会话组；**空会话组也显示** |
| 任务列 | 任务（单任务 / link 任务链） | 任务域全部条目：含"任务ID空"的无归属组 + 含具体任务归属键的组（单任务一组、link 链一组，`owner_task_kind` 标注）；**无条目的 link 任务链组也显示**（单任务组仅在有条目时显示） |

> **所有组都是合法落点**：全局组、具体会话组、具体任务组（单任务/link 链）、⟨无会话ID⟩/⟨无任务ID⟩ 空归属组、以及暂时无条目的具体会话组/link 任务链组，**均可落入，组内条目也可挪走**。落点＝(列, 组)，唯一确定"域＋授权对象"。
> 空归属组不是占位符：它表示**不绑定具体对象**（见 ②），条目落入即把授权对象置空，**生效范围变成"该域下所有对象（含新建对象）"**，语义清晰、允许操作。

**② 空归属组（同域内空授权对象）**：

| 组 | 数据标志 | 含义 |
|------|----------|------|
| 无会话ID组（会话列） | `scope=session` 且 `owner_session_id=''` | 不绑定具体会话：本会话与新会话（含其新任务）都取用 |
| 无任务ID组（任务列） | `scope=task` 且 `owner_session_id=''` 且 `owner_task_ids=[]` | 不绑定具体任务：本任务与新任务都取用 |

> 空归属组**不是 UI 占位**，而是"不绑定具体对象"的条目组；取用时"启用域=会话"生效"会话ID空条目 + 本会话ID条目"，"启用域=任务"生效"任务ID空条目 + 本任务归属键条目"。

**③ 条目挪动（拖拽，对象=条目块 action+path，落点=列+组）**：

条目变更 = 改生效域＋授权对象（**核心组 action+path 恒不变**）：
- **生效域变更**：全局/会话/任务之间迁移（落不同列）。
- **生效对象变更**：A会话→B会话、X任务→Y任务（同列落不同组）。

挪动两模式（均支持）：

| 模式 | 数据语义 | 用户可见 |
|------|----------|----------|
| 移动（move） | **删源行**，目标位置新建行（核心组不变，仅生效域/授权对象改） | 源组少一条、目标组多一条 |
| 复制（copy） | 源行**保留**，目标位置另建一条（两边各一条） | 源组仍在、目标组多一条 |

> 默认复制（不悄悄收回既有授权，收紧须显式移动）。copy 后两条各自按启用域标志独立判定，无"覆盖"概念——选哪一档，就按 3.3 查哪一档的条目集合。
> **move/copy 不走 `status` 字段**：move=直接删源行（物理删，非置 revoked）；copy=不动源行。`status` 只服务"撤销"场景（见 §3.5）。

> **任务域条目对单任务与 link 任务链同等适用**。任务域条目可迁移到长生命期对象：会话、link 任务链、全局域（§2.6）。单任务生命期一次；link 任务链长期存在，按链根 `chat_tasks.context_root_task_id` 归属。

### 3.5 数据表结构（统一表 `chat_trust`）

三域合为一张表，靠 `scope` 列区分；`owner_*` 承载授权对象（可空，`''`/`[]` 表示不绑定具体对象；任务域任务ID用数组存归属键）。本节参照 45 号 §1.1.0.7 的字段级说明，**删除**其未来域、继承链（`parent_*`/`root_*`）与 `superseded` 状态，**补入**任务ID数组、`owner_task_kind` 与"一律有限期"。

**① 为什么合表（硬理由）**

| # | 理由 |
|---|---|
| 1 | 三域同构：核心组（action+path）与产生组在三域完全相同，只差 `scope` 与归属 → 一张表即可，无需三张表 |
| 2 | 唯一键首列即 `scope` → 每域各走一次索引范围扫描，性能与分表等价 |
| 3 | 哨兵统一：`''`/`[]` 统一表达"不绑定具体对象"，顺带消灭既有 `path IS NULL` 不去重的老问题 |
| 4 | move/copy 直接增删行、不建继承链 → 无需 `parent_*`/`root_*` 列（45 号合表的"继承链跨表"理由在 47 号不成立） |

**② 字段总表**：

| 字段 | 类型 | 必填 | 含义 | 取值/规则 |
|------|------|------|------|----------|
| `id` | INTEGER PK | ✅ | 行唯一标识 | 自增 |
| `scope` | TEXT | ✅ | **生效域**（3 值） | `session` / `task` / `global` |
| `owner_session_id` | TEXT | ✅（可 `''`） | **授权对象·会话ID** | global 域＝`''`；session 域＝该会话ID；task 域＝条目归属的会话ID（无任务ID 组＝`''`）；**可空**（空＝不绑定具体会话/任务，见 3.4 ②） |
| `owner_task_ids` | TEXT（JSON 数组） | ✅（可 `[]`） | **授权对象·任务ID数组** | 非 task 域＝`[]`；task 域＝单任务 `[自身task_id]` / link 任务链 `[链根 context_root_task_id]`；**可空**（`[]`＝不绑定具体任务，见 3.4 ②） |
| `owner_task_kind` | TEXT | ✅（可 `''`） | **授权对象·任务类型** | 非 task 域＝`''`；task 域＝`single`（单任务）/ `link`（link 任务链）；无任务ID 组＝`''` |
| `action` | TEXT | ✅ | **核心组① 动作** | `read` / `write` / `delete`（取 `tool_constants` 真源） |
| `path` | TEXT | ✅（可 `''`） | **核心组② 路径**（登记范围） | 经 `trust_scope_path` 目录收敛；`''`＝不限路径（一期无 path 条目不入库，仅保留字段） |
| `tool_name` | TEXT | ✅（可 `''`） | 溯源（非主体） | 创建时用的工具名；不参与命中判定、不入唯一键 |
| `creator_session_id` | TEXT | ✅（可 `''`） | **产生组·会话ID** | 条目产生时的会话（不可变，溯源） |
| `creator_task_id` | TEXT | ✅（可 `''`） | **产生组·任务ID** | 条目产生时的任务（不可变，溯源） |
| `created_at` | TEXT | ✅ | **产生组·时间** | 条目产生时刻；同键 UPSERT 冲突**不刷新**（已过期同键重新授权时只续 `expires_at`，见 ⑧） |
| `status` | TEXT | ✅ | 行状态 | `active`（生效）/ `revoked`（被撤销）；**只服务"撤销可发现"**（撤销=置 revoked 留库可发现，非物理删）；**move/copy 不走此字段**（move 直接删源行、copy 不动源行，见 3.4③） |
| `expires_at` | TEXT | ✅ | 生命周期（必有限期） | `created_at + trust.ttl_days`（默认 90 天），不设永不过期；同键未过期不续期 |

**③ 唯一键与索引**：`UNIQUE(scope, owner_session_id, owner_task_ids, action, path)`（`owner_task_ids` 按升序去重后序列化，保证同键稳定）

> 唯一键含 `scope`＋归属两列＋核心组（action+path）。**归属列可空（`''`/`[]`）**正是"不绑定具体对象"（3.4 无会话ID组/无任务ID组）的落库表达：会话域行 `owner_session_id=''`＝不绑定会话；任务域行 `owner_task_ids=[]`＝不绑定任务。
> `owner_task_kind` **不入键**：只描述该任务归属是单任务还是 link 任务链。
> `tool_name` **不入键**：同一 (scope, 归属, action, path) 被不同工具触发时只更新该字段（"最后一次是谁点的"），不新增行。
> **撤销**：置 `status='revoked'`，留库可发现（非物理删，对应 §二 2.8"撤销可发现"）；物理清除交给 TTL 回收（删 `expires_at <= now` 的行，active/revoked 均清）。**move 不走 status**（直接物理删源行）；**copy 不动源行**。

**④ 表结构（DDL）**

```sql
-- 2026-10-24 小欧 - 统一信任表 chat_trust：三域合表(scope 区分)；无继承链列；条目一律有限期
CREATE TABLE IF NOT EXISTS chat_trust (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    scope              TEXT NOT NULL,                    -- 'global' | 'session' | 'task'
    owner_session_id   TEXT NOT NULL DEFAULT '',         -- 授权对象·会话ID; '' = 不绑定具体会话
    owner_task_ids     TEXT NOT NULL DEFAULT '[]',       -- 授权对象·任务ID数组(升序去重序列化); [] = 不绑定具体任务
    owner_task_kind    TEXT NOT NULL DEFAULT '',         -- 'single' | 'link' | ''(非任务域 / 无任务ID)
    action             TEXT NOT NULL,                    -- 核心组①: 'read' | 'write' | 'delete'
    path               TEXT NOT NULL DEFAULT '',         -- 核心组②: 登记范围(目录收敛); '' = 不限路径(一期不入库)
    tool_name          TEXT NOT NULL DEFAULT '',         -- 溯源, 非主体, 不入唯一键
    creator_session_id TEXT NOT NULL DEFAULT '',         -- 产生组·会话(不可变)
    creator_task_id    TEXT NOT NULL DEFAULT '',         -- 产生组·任务(不可变)
    created_at         TEXT NOT NULL,                    -- 产生组·时间(不可变)
    status             TEXT NOT NULL DEFAULT 'active',   -- 'active' | 'revoked'
    expires_at         TEXT NOT NULL                    -- 到期时刻; 一律有限期, 不用 NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_chat_trust_uniq       ON chat_trust(scope, owner_session_id, owner_task_ids, action, path);
CREATE INDEX IF NOT EXISTS idx_chat_trust_scope_task  ON chat_trust(scope, owner_task_ids);     -- 任务域匹配
CREATE INDEX IF NOT EXISTS idx_chat_trust_owner       ON chat_trust(scope, owner_session_id);    -- 会话域取用(⑥)＋会话列清单
CREATE INDEX IF NOT EXISTS idx_chat_trust_action      ON chat_trust(action, path);               -- 按动作+路径查
CREATE INDEX IF NOT EXISTS idx_chat_trust_status      ON chat_trust(status);                     -- 撤销可发现
CREATE INDEX IF NOT EXISTS idx_chat_trust_expires     ON chat_trust(expires_at);                 -- TTL 回收
```

> 无 `parent_*`/`root_*` 列与索引：47 号不建继承链，故不需要"取整条继承链"的索引。

**⑤ 域 → 列 填充规则（一张表怎么表达三种域）**

| scope | `owner_session_id` | `owner_task_ids` | `owner_task_kind` | 匹配条件 | 免弹范围 |
|---|---|---|---|---|---|
| `global` | `''` | `[]` | `''` | `scope='global' AND status='active' AND action=? AND 未过期 AND path 命中` | 所有会话、所有任务 |
| `session` | 当前会话ID（`''`＝不绑定） | `[]` | `''` | `scope='session' AND (owner_session_id='' OR owner_session_id=当前会话) AND …` | 本会话 + 无会话ID 条目 |
| `task` | 条目归属会话ID（`''`＝不绑定） | 单任务 `[自身task_id]`；link `[链根]`（`[]`＝不绑定） | `single` / `link` / `''` | `scope='task' AND (owner_task_ids='[]' OR owner_task_ids=[本任务归属键]) AND …` | 本任务 + 无任务ID 条目 |

> 任务域同时记 `owner_session_id`：① 按会话过滤列清单要用；② 删会话时按会话定位条目（会话是软删、FK `ON DELETE CASCADE` 永不触发，任务域行**不随删会话物理清除**，等 TTL 回收，见 ⑧「删会话」行）。
> 全局域三列全空（哨兵）即"不绑定任何对象"。

**⑥ 查询侧口径（命中判定，按启用域取段）**

```sql
-- ① 全局域（无归属过滤）
SELECT 1 FROM chat_trust WHERE scope='global' AND status='active'
  AND action=? AND expires_at>:now AND path 命中 LIMIT 1;
-- ② 会话域（含无会话ID 条目）
SELECT 1 FROM chat_trust WHERE scope='session' AND status='active'
  AND (owner_session_id='' OR owner_session_id=当前会话)
  AND action=? AND expires_at>:now AND path 命中 LIMIT 1;
-- ③ 任务域（含无任务ID 条目）
SELECT 1 FROM chat_trust WHERE scope='task' AND status='active'
  AND (owner_task_ids='[]' OR owner_task_ids=[本任务归属键])
  AND action=? AND expires_at>:now AND path 命中 LIMIT 1;
```

> 查哪几段由启用域决定（§3.3 取用矩阵）：**不恒三域全查**。
> 路径范围包含口径（唯一）：登记范围（目录）**包含**目标路径，**按路径分量比较**；`LIKE 'D:\proj\src%'` 会把兄弟目录 `src2` 误判命中。SQL 片段仅示意，实现侧按分量判定。
> 按 `action` 命中，不按 `tool_name`：调用方须把本次操作的动作档位（读/写/删）算出来传入。
> 归属过滤不可省（fail-closed）：会话域/任务域必须组归属条件，否则跨会话/跨链越权免弹。
> 一期只入库有 path 的条目；无 path 的 bash/系统级命令不产生条目。

**⑦ 状态机（无继承链）**

```
 用户勾选（或 copy / A→B 导入）          用户撤销           TTL 回收
        │                                │                  │
      ┌──▼─────┐                         ┌──▼──────┐       （删行）
      │ active │ ───────────────────────▶ │ revoked │ ───▶ 物理清除
      └──┬─────┘                         └─────────┘
         │ move：源行物理删，目标位置新建 active（核心组不变）
         ▼
      目标位置 active 行
```

- `active`：唯一参与匹配的行。
- `revoked`：用户撤销，不再免弹、留库可发现（§二 2.8）；语义等同删除，用状态位实现。
- **无 `superseded`**：47 号不建继承链，move 物理删源行、copy 不动源行，不需要"被取代"状态；因此 move 物理删不会留下悬垂父引用。
- 物理清除的唯一时机：TTL 回收（删 `expires_at <= :now` 的行，active/revoked 均清）。

**⑧ 生命周期与续期口径**

| 场景 | `created_at` | `expires_at` | `creator_*` | 理由 |
|---|---|---|---|---|
| 首次授权 | 写入 | `now + trust.ttl_days` | 写入 | — |
| 重复授权（同键，未过期） | 不刷新 | 不刷新 | 不刷新 | 旧到期仍在，续期无必要 |
| 重复授权（同键，已过期） | 不刷新 | 刷新为 `now + trust.ttl_days` | 不刷新 | 已失效的重新授权＝新一次授权，只续到期；创建者不变 |
| move | 沿用源行 | 沿用源行 | 沿用源行 | 产生组不可变（§3.1）；源行物理删 |
| copy | 沿用源行 | 沿用源行 | 沿用源行 | 产生组不可变 |
| A→B 导入 | 沿用源行 | 沿用源行 | 沿用源行 | 授权来自最初那次勾选；同键跳过 |
| 用户撤销 | 不变 | 保留原值 | 不变 | 置 `revoked`；物理清除留给 TTL |
| 删会话 | 不变 | 保留原值 | 不变 | 会话软删、FK `ON DELETE CASCADE` 不触发；任务域行不随删会话清除，也不置 `revoked`（撤销只属于用户主动撤销），等 TTL 回收 |

> move / copy / 导入的新行**一律沿用源行产生组与到期时间，不续期**——"迁移、复制"不该顺带延长有效期。
> 物理清除只有 TTL 一处（⑦）：move / copy / 导入 / 删会话都不物理删条目行。

**⑨ 存量迁移**

> 47 号未定义存量表来源，本节不给出迁移步骤（现状存量只有一张 `chat_session_trust`，`chat_trust` 尚未建表，§3.9 ①）。若需迁存量，按 45 号 §1.1.0.7 八 执行（旧表保留只读、代码只读写新表、逐行幂等），并额外处理两处差异：① 45 号单值 `owner_root_task_id` → 47 号数组 `owner_task_ids=[链根]`；② 45 号 `expires_at NULL＝不过期` → 47 号一律有限期，NULL 行须补到期时间（`created_at + trust.ttl_days`）。

> 产生时 `scope` 由"勾选瞬间输入框底部的域"决定（3.2 表）；`owner_*` 按该域填（全局＝全空、会话＝当前会话ID+任务空、任务＝当前会话ID+任务归属键数组+该任务类型）。域选择只在前端输入框当前状态中（启动初值读配置 `trust.mode`，§4.3），不落 `chat_sessions`。

### 3.7 跨会话导入（A→B）

**定位**：会话内 Drawer（会话页签）的快捷操作（与"复制"类似），把 **A 会话的信任条目复制到 B 会话**；导入行的会话ID 都指**授权对象的会话ID**（`owner_session_id`）。

**导入语义**：

| 项 | 口径 |
|------|------|
| 导入对象 | A 会话的**会话域**条目（`scope=session`，`owner_session_id=A`） |
| 复制方式 | 在 B 会话**新增**同核心组（action+path）的行，`owner_session_id` 改为 **B** |
| 保留 | 源行的产生组（`creator_session_id`/`creator_task_id`）、`created_at`、`expires_at`（不续期） |
| 不导入 | 全局域条目（不属会话域，导入只复制会话域条目）、任务域条目（绑定任务/链，须先改到会话域才能导入） |
| 去重 | 目标键（`scope=session`, `owner_session_id=B`, `owner_task_ids=[]`, `action`, `path`）已存在则**跳过**（幂等，不覆盖 B 的既有行） |
| 撤销 | 导入行独立，撤销 B 的导入行不影响 A 的源行 |

> 导入=把 A 会话"已记住的授权"批量复制到 B 会话，使 B 会话获得同等的会话域信任面。会话ID 全程指**授权对象**（`owner_session_id`），不是产生组/创建者。

| 全局组 | `scope=global`, `owner_*` 全空 | 全局域条目（无归属） | ✅ |

| ⟨无任务ID⟩ | `scope=task`, `owner_session_id=''`, `owner_task_ids=[]` | 不绑定具体任务：本任务与新任务都取用 | ✅ |

### 4.8 UI 规范执行策略

本节是 §4.1–§4.7 的落地规范，**裁剪自 45 号 §3.4**：只保留 47 号三域/四入口/拖拽改域所需项；45 号的冗余/临期/链深度徽标、敞口概览区、信任阶梯矩阵、行内快捷改域钮、移动端底部改域面板、未来组**均不引入**（无 47 号需求依据）。

**① 执行原则**

| 原则 | 要求 |
|---|---|
| 单一真源 | UI 行为、文案、尺寸以 §4 为准；实现与文档不一致时先改文档再改代码，禁止只在代码里漂移 |
| 常量 | 颜色/字号/间距/圆角只用 `stepStyles` 常量，禁止裸色值、裸 px |
| 文案 | 文案集中在 §4.2/§4.4/§4.5/§4.6 图示；组件不复制域/动作映射表（★2） |
| 安全操作 | 警示色只 2 处、危险色只撤销；安全相关操作不加延迟阅读的动效、不弹无关确认 |

**② 色板与语义**

| 语义 | 取值 | 用在哪 |
|---|---|---|
| 警示 | `Colors.WARNING`（#AD6800） | **仅 2 处**：① 底栏 `global` 档描边；② 授权弹窗 `global` 档副释义。**过期不用警示色** |
| 危险 | `Colors.ERROR` | 仅撤销按钮与撤销确认标题 |
| 次级 | 次级文本色 | 过期时间、落点预览、溯源行 |
| 主题 | 只用 `stepStyles` 常量 | 禁止裸色值 |

**③ 徽标与字号间距**

| 项 | 规格 |
|---|---|
| 域/动作徽标 | 高 20px，圆角矩形，`padding 0 6px`，`Radius.SM`，12px/500 |
| 当前标记 | 组头右侧"当前"胶囊，12px/500，不用警示色 |
| 过期时间 | 行尾/卡角次级文本 11px，**必显示**（如 2027-01-18），不用警示色 |
| 功能行 | `Space size=8`；开关内部 `size=4`；分组间距 16；明细行距勾选框 4 |
| 列表行 | 行高 28（徽标 20 + 上下 4）；次级行 18，11px |
| 条目卡 | 白底 + 1px `Colors.BORDER.LIGHT`，`Radius.SM`，内边距 10/12，高 48–64，同组等高 |
| 尺寸 | `Segmented/Select size="small"`；操作列宽 40（`⋯`）；撤销确认按钮宽比 1:1 |
| 弹层 | Drawer `min(360px,80vw)`；Modal `min(520px,92vw)`（既有 HITL 壳宽不变） |
| 溢出 | 路径超长 `ellipsis` + Tooltip 全值；表格不横向滚动 |

**④ 反馈与动效**

| 场景 | 反馈 |
|---|---|
| 切档 | **静默**（控件状态即反馈），无 toast、无动效 |
| 勾选信任 | 勾选框即时选中；**弹窗关闭即结束**，不出现"授权成功"toast |
| 撤销 | 二次确认（`alertdialog`）；成功行消失 + "已撤销" toast 2s |
| 改域 | **不弹确认**；成功 toast 2s（"已改到…"）；失败 `message.error`，行保持原状 |
| 列表加载 | 表格骨架/loading；Drawer 3 行骨架占位，避免高度跳动 |
| 动效纪律 | 只允许浮层展开/收起、Drawer 滑入、行移除（≤150ms）；禁止抖动/闪烁等噪声动效 |

**⑤ 拖拽与空组视觉（47 号特有）**

| 项 | 规格 |
|---|---|
| 拖拽对象 | 条目卡（action+path）；原格半透明 0.4 保留占位 |
