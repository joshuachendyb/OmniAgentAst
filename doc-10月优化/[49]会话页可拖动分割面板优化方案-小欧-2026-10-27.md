## 一、需求背景

### 1.1 现状问题

会话页面（ChatPage）的左侧和右侧区域使用固定的 flex 比例分配：
- 左列：`flex: '1 1 25%'`（约 25%）
- 右列：`flex: '1 1 75%'`（约 75%）

**问题**：
1. 用户无法根据内容调整面板宽度
2. 固定比例不适配不同屏幕尺寸
3. 左侧任务列表可能需要更宽空间显示

### 1.2 优化目标

1. 中间的线可以拖动改变两个区域的宽度
2. 左侧的宽度默认为 1/3
3. 不违反代码 10 大规范，全局逻辑代码最佳

---

## 二、技术方案

### 2.1 设计原则（10 大规范）

| 规范 | 应用 |
|------|------|
| **SRP** | SplitPane 组件只负责分割面板，不负责内容渲染 |
| **DRY** | 拖动逻辑只写一次，复用 Files 页的拖动模式 |
| **KISS-DIRECT** | 直接使用鼠标事件，不引入复杂抽象 |
| **SLAP** | SplitPane 是 UI 层，不混入业务逻辑 |
| **YAGNI** | 不引入第三方库，不预设未来需求 |
| **禁止 backward** | 不使用向后兼容的做法 |

### 2.2 架构设计

```
SessionLayout（布局容器）
  └── SplitPane（可拖动分割面板）
        ├── 左侧面板（任务列表等）
        ├── 分割线（可拖动）
        └── 右侧面板（查看器等）
```

### 2.3 核心实现

#### SplitPane 组件

**职责**：
- 管理左右面板的宽度拖动逻辑
- 提供键盘可访问性（←/→）
- 提供 ARIA 属性（role="separator"）

**状态管理**：
- `leftW`：左侧面板宽度（像素）
- 初始值：容器宽度的 1/3

**拖动逻辑**：
- `mousedown`：记录初始位置，添加 mousemove/mouseup 监听
- `mousemove`：计算新宽度，更新状态
- `mouseup`：清理监听器

**边界约束**：
- 最小宽度：200px
- 最大宽度：容器宽度的 80%（保留右侧最小空间）

#### SessionLayout 修改

**原代码**：
```tsx
<div style={{ flex: '1 1 25%', minWidth: 200, maxWidth: 560 }}>
  {renderSlot(panels, 'left')}
</div>
<div style={{ flex: '1 1 75%' }}>
  {renderSlot(panels, 'right')}
</div>
```

**新代码**：
```tsx
<SplitPane
  left={renderSlot(panels, 'left')}
  right={renderSlot(panels, 'right')}
/>
```

## 五、使用效果

### 5.1 默认状态

- 左侧宽度：容器宽度的 1/3
- 右侧宽度：容器宽度的 2/3

### 5.2 拖动交互

- 鼠标悬停分割线：显示浅蓝色背景
- 鼠标拖动：实时调整面板宽度
- 键盘操作：←/→ 调整宽度（每次 16px）

### 5.3 边界约束

- 左侧最小宽度：200px
- 左侧最大宽度：容器宽度的 80%
- 防止内容挤压，保证可用性
