## 一、需求

用户对分割线需要**两种默认值操作**：

1. **存储新的默认值**：把当前拖到的宽度固定为默认值（以后打开/重置都回到这里）
2. **返回元素默认值**：回到出厂默认（30% 容器宽），清除用户自定义默认

当前 v1.4 只实现了第 1 种（双击 = 存储新默认），第 2 种（返回出厂默认）已随 v1.4 删除 `clearStoredWidth` 而丢失。

---

## 二、设计目标

| 目标 | 说明 |
|------|------|
| 双操作可区分 | 两种默认值操作有清晰、不歧义的触发方式 |
| KISS-DIRECT | 不引入右键菜单/弹窗等重型抽象，用最直接的交互 |
| 可发现性 | 用户能通过 title/aria-label 知道两种操作 |
| 不破坏现有行为 | 双击=存储新默认（v1.4 已确认），保持不变 |
| 符合 10 大规范 | SRP/DRY/YAGNI/禁止backward 全遵守 |

---

## 三、交互设计

| 操作 | 触发方式 | 行为 |
|------|---------|------|
| **存储新默认** | 双击分割线 | 当前宽度写入 localStorage 作为默认值，宽度不跳回 |
| **返回出厂默认** | **Shift + 双击**分割线 | 清除 localStorage + 重置为 30% 出厂默认 |

**选择 Shift+双击 的理由**：
- 双击已是"存储新默认"的主操作，不能占用
- Shift+双击 是键盘修饰键组合，无需引入 UI 组件（右键菜单/弹窗），符合 KISS-DIRECT
- 与主流编辑器（如 VS Code 分割面板）的"修饰键+双击=恢复默认"习惯一致
- 可发现性通过 title/aria-label 提示保证

**备选方案（不采用）**：
| 方案 | 缺点 |
|------|------|
| 右键菜单 | 需引入 context menu 组件，复杂度高，违反 KISS-DIRECT |
| 三击 | 三击不常见，可发现性差 |
| Alt+双击 | 与 Shift+双击相比，Alt 在部分浏览器/系统有系统级快捷键冲突 |

---

## 四、数据设计

| 项 | 键/常量 | 说明 |
|----|--------|------|
| 用户默认值 | `SPLIT_PREFS_KEY` = `omni.split.v1.leftWidth` | 双击时写入；无值=未自定义 |
| 出厂默认值 | `SPLIT_LEFT_DEFAULT_RATIO` = 0.30 | 常量，返回出厂时用 |

**状态判定**：
- `readStoredWidth() !== null` → 有用户默认值（自定义状态）
- `readStoredWidth() === null` → 无用户默认值（出厂状态）

## 五、逻辑设计（代码）

### 5.1 重新引入 clearStoredWidth（v1.4 删除，现 Shift+双击需要）

```typescript
// 清除 localStorage(返回出厂默认用)
const clearStoredWidth = (): void => {
  try {
    localStorage.removeItem(SPLIT_PREFS_KEY);
  } catch {
    // 静默
  }
};
```

### 5.2 handleDoubleClick 支持 Shift 区分两种操作

```typescript
const handleDoubleClick = useCallback((e: React.MouseEvent) => {
  const container = containerRef.current;
  if (!container) return;
  if (e.shiftKey) {
    // Shift+双击: 返回出厂默认(清除自定义默认 + 重置为 30%)
    clearStoredWidth();
    setLeftW(getInitialWidth(container.offsetWidth));  // 清除后 getInitialWidth 返回 30%
    return;
  }
  // 双击: 存储新默认(当前宽度写入 localStorage, 不跳回)
  const cur = leftW ?? getInitialWidth(container.offsetWidth);
  writeStoredWidth(cur);
  setLeftW(cur);
}, [leftW]);
```
