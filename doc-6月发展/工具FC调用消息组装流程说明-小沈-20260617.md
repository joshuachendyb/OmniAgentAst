## 一、整体流程概览

```
注册阶段 → 生成OpenAI工具定义 → LLM调用 → 最终JSON结构
```

| 阶段 | 核心文件 | 职责 |
|------|---------|------|
| 注册 | `file_register.py` | 注册工具，存储元数据 |
| Schema生成 | `schema_utils.py` | Pydantic → JSON Schema |
| 工具定义 | `tool_description.py` | 生成OpenAI格式 |
| 缓存管理 | `tool_cache_manager.py` | TTL缓存 + 分类过滤 |
| LLM调用 | `react_cycle.py` | 组装阶段调 get_openai_tools 获取工具定义 |

```python
def _generate_input_schema(input_model, input_schema):
    if input_model is None:
        return input_schema or {}
    
    schema = input_model.model_json_schema()  # Pydantic V2 API
    schema = _fix_schema_types(schema)        # 修复Union/Optional类型
    return schema
```

## 三、生成OpenAI工具定义

### 3.1 核心函数

**文件**: `backend/app/tools/tool_description.py`

```python
def to_openai_tools(registry, categories, strict=True):
    tools = []
    for name, meta in sorted(registry._tools.items(), key=lambda x: x[0]):
        if not meta.expose_to_llm:
            continue
        if categories is not None and meta.category not in categories:
            continue
        
        func_def = {
            "name": meta.name,              # ← 工具名
            "description": meta.description, # ← 工具描述
            "parameters": meta.input_schema, # ← JSON Schema
            "strict": strict,
        }
        if meta.examples:
            func_def["examples"] = meta.examples  # ← 示例
        
        tools.append({
            "type": "function",
            "function": func_def
        })
    
    return tools
```

### 3.2 字段映射

| OpenAI字段 | 来源 | 说明 |
|-----------|------|------|
| `name` | `meta.name` | 工具名称 |
| `description` | `meta.description` | 工具描述（来自FILE_TOOL_DESCRIPTIONS） |
| `parameters` | `meta.input_schema` | JSON Schema（来自Pydantic模型） |
| `strict` | `strict`参数 | 强制参数校验 |
| `examples` | `meta.examples` | 示例（来自FILE_TOOL_EXAMPLES） |

## 四、LLM调用时

### 4.1 调用链

```
react_cycle.py
    ↓
openai_tools = get_openai_tools(agent)        # react_cycle.py:158
    ↓
tool_cache_manager.py: get_openai_tools(agent)
    ↓
tool_registry.to_openai_tools(categories=agent._loaded_categories)   # registry.py:305 委托
    ↓
tool_description.py: to_openai_tools(registry, categories)            # 实际实现
    ↓
返回 [{"type": "function", "function": {...}}, ...]
```

### 4.2 缓存机制

**文件**: `backend/app/services/agent/tool_cache_manager.py`

```python
def get_openai_tools(agent):
    # 1. 尝试从TTL缓存获取
    cached = agent._tool_cache.get()
    if cached is not None:
        return cached
    
    # 2. 缓存未命中，重新生成
    from app.services.tools.registry import tool_registry
    tools = tool_registry.to_openai_tools(categories=agent._loaded_categories)
    
    # 3. 存入缓存
    agent._tool_cache.set(tools)
    return tools
```

### 4.3 分类过滤

**关键参数**: `categories=agent._loaded_categories`

- 只返回已加载分类的工具
- 例如：`{ToolCategory.FILE, ToolCategory.NETWORK}`
- 未加载的工具不会出现在LLM的工具列表中

### 6.2 tool_search 动态描述（原 tool_categories.json 已删除）

**重要变更（2026-06-18 小健）**：`tool_categories.json` 已删除，改为直接从 `tool_registry` 获取工具分类信息（DRY 原则）。因此旧文档中"读取 tool_categories.json 的 summary/tools 拼接到 tool_search 描述"的描述已作废，本节按当前代码重写。

**当前实现**：`backend/app/services/agent/tool_cache_manager.py` 的 `patch_search_desc(agent)` 直接从 `ToolCategory` 枚举实时计算未加载分类并动态拼装，且采用**副本模式**（写入 `agent._searchtool_desc_override`），不修改全局 `ts_meta.description`。

**文件**: `backend/app/services/agent/tool_cache_manager.py`

```python
def patch_search_desc(agent):
    """动态更新 searchtool 描述: 列出未加载分类（仅列分类名）"""
    unloaded = [
        cat for cat in ToolCategory
        if cat not in {ToolCategory.FUNDAMENTAL, ToolCategory.SHELL, ToolCategory.FILE}
        and cat not in agent._loaded_categories
    ]
    if not unloaded:
        agent._searchtool_desc_override = None
        invalidate_tool_cache(agent)
        return

    ts_meta = tool_registry.get_tool("searchtool")
    if not ts_meta:
        agent._searchtool_desc_override = None
        invalidate_tool_cache(agent)
        return

    base_desc = _get_original_search_desc()  # 剥离历史注入后缀，只取原始描述
    lines = []
    for cat in sorted(unloaded, key=lambda c: c.order):
        lines.append(f"- {cat.name_cn}({cat.value})")   # 仅分类名，不再列工具清单

    if lines:
        agent._searchtool_desc_override = base_desc + "\n\n当前未加载分类:\n" + "\n".join(lines)
    else:
        agent._searchtool_desc_override = None
    invalidate_tool_cache(agent)
```

**最终效果**：`searchtool` 描述动态变为：
```
搜索并注入未加载的工具，按关键词在全部工具中做BM25全文检索...

当前未加载分类:
- 文件(file)
- 网络(network)
- 桌面(desktop)
...
```

**信息来源**：
- 分类列表 ← `ToolCategory` 枚举（不再来自 tool_categories.json）
- 拼接结果写入 `agent._searchtool_desc_override`；`get_openai_tools` 在返回前用该 override 覆盖 `searchtool` 的 `description`（tool_cache_manager.py:28-33），不污染全局元数据

## 七、关键设计要点

### 7.1 职责分离

| 文件 | 职责 | 不负责 |
|------|------|--------|
| `file_schema.py` | 参数验证（Pydantic模型） | 工具描述、示例 |
| `file_register.py` | 工具描述、示例、注册 | 参数验证 |
| `tool_description.py` | 生成OpenAI格式 | 注册、验证 |
| `tool_cache_manager.py` | 缓存、分类过滤 | 生成格式 |

### 7.2 禁止事项

**在`file_schema.py`中禁止写Pydantic类docstring**：

```python
# ❌ 错误示例
class ReadTextFileInput(BaseModel):
    """读取文本文件 - 这个会进入JSON Schema发给LLM"""
    file_path: str = Field(...)

# ✅ 正确示例
class ReadTextFileInput(BaseModel):
    file_path: str = Field(description="要读取的文件路径")
```

**原因**: Pydantic class docstring会自动进入JSON Schema的`parameters.description`并发给LLM，导致重复。

### 7.3 编制方法

#### 7.3.1 register 文件编制方法

**格式**: `功能描述。适用场景:xxx时使用。`

**示例**:
```python
FILE_TOOL_DESCRIPTIONS = {
    "read_text_file": """读取文本文件。支持分页读取。encoding默认utf-8。适用场景:需要读取源代码、日志文件、配置文件时使用。""",
}
```

**要点**: 第一句（核心功能）+ 中间（关键特性）+ 最后（适用场景）

#### 7.3.2 schema 文件编制方法

**要点**: 禁止写 class docstring，只写 Field description

**示例**:
```python
class ReadTextFileInput(BaseModel):
    # ❌ 禁止写 class docstring（会发给LLM重复）
    
    file_path: str = Field(description="要读取的文件路径(绝对路径)")
    head: Optional[int] = Field(default=None, ge=1, le=1000000, description="读取前N行")
```

#### 7.3.3 编制流程

1. schema 文件：定义 Pydantic 模型（无 class docstring）
2. tools 文件：实现工具函数
3. register 文件：添加描述（功能+适用场景）+ 示例 + 注册

### 7.4 缓存机制

- **TTL缓存**: 避免每次LLM调用都重新生成工具定义
- **分类过滤**: 只返回已加载分类的工具，减少LLM token消耗
- **缓存失效**: 工具注册/注销后调用`invalidate_tool_cache()`
