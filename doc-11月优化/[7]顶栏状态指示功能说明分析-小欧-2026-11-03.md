## 一、功能概述

顶栏（Header）在品牌字 `OmniAgentAst.` 之后、三粒胶囊之前，新增了一组**状态指示**功能，回答三个独立问题：

1. **品牌圈圈（TitleStreamIcon）**：当前任务流的"节奏"——停/快/慢，8 档转速随流状态变化（停转=空闲，1s=进行中，3s=迟滞，6s=静默，0.8s=重连）。
2. **ConfigStatusPill**：模型配置是否就绪（五步校验：配置完整性 + 凭证预警 → 绿就绪/黄预警/红错误），语义 = "可发消息与否"。
3. **ServiceStatusPill**：后端服务存活（/health 三级：绿正常/黄缓慢或降级/红离线），挂载自检 + 点击重检。
4. **StreamStatusPill**：当前 SSE 流活没活（8 档 phase：无任务/连接中/流持续/流迟滞/流静默/重连中/待确认/流中断），只读 store 不发请求。

三粒胶囊与品牌圈圈各答各的，**一处一个通道，不重复**：文案/颜色/秒数归 StreamStatusPill，节奏归 TitleStreamIcon，后端存活归 ServiceStatusPill，配置就绪归 ConfigStatusPill。

## 三、TitleStreamIcon — 品牌圈圈 8 档转速联动

### 3.1 实现逻辑

```tsx
// TitleStreamIcon.tsx
export const TitleStreamIcon: React.FC = () => {
  const view = useStreamPulse();   // 订阅单一真源
  return <TitleSpinIcon className={`spin-${view.phase}`} />;
};
```

- 订阅放在本层而非 AppLayout：`view` 的秒数每秒换引用，放壳层会让整个顶栏 1Hz 重渲；放这里重渲范围只有 20px 图标。
- 只做 `phase → 类名` 映射，零秒数零颜色（文案/颜色/秒数仍归 StreamStatusPill）。

### 3.2 8 档 phase 与转速

`StreamPhase`（`useStreamPulse.ts`）：

| phase | 含义 | 转速（CSS animation-duration） |
|-------|------|-------------------------------|
| `idle` | 无任务 | 停转（paused） |
| `connecting` | 请求已发，等待推送 | 1.6s |
| `running` | 流持续（有产出） | 1s（基础） |
| `stalled` | 业务帧停但心跳正常 | 3s |
| `silent` | 连心跳都没了 | 6s |
| `reconnecting` | 断点续传中 | 0.8s |
| `waiting` | 待人工确认 | 停转 |
| `down` | 流中断 | 停转 |

CSS 类 `spin-<phase>` 定义在 `index.css`（`.title-spin-icon.spin-idle/.spin-waiting/.spin-down { animation-play-state: paused }` 等），颜色让位：只有 `spin-silent`/`spin-down` 让位告警色（橙红/红），其余全程品牌三色。

### 3.3 判据优先级（deriveStreamState）

```
断流(down) > 重连/恢复(reconnecting) > 等确认(waiting) > 未建流(connecting)
> 有产出(running) > 只有心跳(stalled) > 都没了(silent)
```

- `bizStale` = 业务帧静默 ≥30s；`dataStale` = 任意字节静默 ≥30s。
- "在产出"必须有证据：有业务帧且未超阈值，从没收到过业务帧一律不算产出。

## 四、ConfigStatusPill — 模型配置状态

### 4.1 实现逻辑

- **五步校验**：配置完整性 + 凭证预警 → 三级可用分级（绿就绪/黄预警/红错误），语义 = "可发消息与否"（非文件校验通过）。
- **挂载自动检测** + **点击重检**（ref 防重入，setState 异步守不住并发）。
- **Tooltip**：模型信息 + 红态列硬错误 / 黄态列预警；红黄态提供「去设置页修改」动作（navigate `/settings2`）。

### 4.2 状态映射

```ts
const deriveState = (checking, hasChecked, status): PillState => {
  if (checking) → '检测中' (busy)
  if (status === null) → hasChecked ? '检测失败'(netfail) : '未检测'(fail)
  if (!status.valid || status.status === 'failed') → '配置错误'(fail, 红)
  if (status.status === 'warning') → '配置预警'(warn, 黄)
  return '配置就绪'(ok, 绿)
};
```

`TONE_OF`：`ok→ok, warn→warn, fail→error, netfail→error, busy→neutral`。

## 五、ServiceStatusPill — 后端服务存活

### 5.1 实现逻辑

- **三级**：绿正常 / 黄缓慢或降级 / 红离线，基于 `/health` 探活。
- **挂载自检**（一次只读探活，无定时器）+ **点击重检**。
- **Tooltip 全量常显**：地址组（本机/访问/前缀/连接）+ 本次探测（响应耗时/应答时刻/数据库）+ 后端进程（PID/存活时长）。
- **打开 Tip 即静默重检**：挂载快照会被后端重启/字段变更拖旧，静默重检不翻"检测中"态免闪烁。

### 5.2 关键阈值与格式

- `SLOW_RESPONSE_MS`：响应缓慢阈值（来自 health.api）。
- `PROBE_TIMEOUT_MS`：探活超时（离线文案吃此常量，免字面量漂移）。
- `LOOP_BAD_MS = 100`：循环延迟越线才追加，定位"慢在链路还是循环"。
- 耗时统一毫秒（北京老陈定案，避免与"已运行"混淆）。
- 存活时长按人话写（天/时/分/秒）。

### 5.3 状态派生

```ts
deriveState(checking, hasChecked, health, latencyMs):
  checking → '检测中'
  health===null → hasChecked ? '服务离线' : '未检测'
  latencyMs >= SLOW_RESPONSE_MS → '服务缓慢' (黄)
  health.status !== 'healthy' → '服务降级' (黄)
  else → '服务正常' (绿)
```

## 六、StreamStatusPill — SSE 流状态

### 6.1 实现逻辑

- **8 档 phase**：无任务/连接中/流持续/流迟滞/流静默/重连中/待确认/流中断。
- **只读 store**，不发任何请求；订阅 `useStreamPulse`（共享 1s 采样）。
- **Tooltip**：流活跃时列会话/状态/任务/数据行/判死/并发；空态一行提示"发送任务后这里显示实时状态"。
- 空态浮层不再复读标题（流/无进行中的任务），改一行提示。

### 6.2 状态映射

`BADGE_OF`：`ok→processing, warn→warning, alert→default(自定义橙红点), error→error, neutral→default`。

`STATUS_TEXT`：`idle→空闲, active→执行中, paused→待确认, retrying→重试中, recovering→恢复中, completed→已完成, failed→失败, cancelled→已取消`。

`shortId`：取前 8 位。

## 七、PillShell — 共用外壳

三个胶囊共用 `PillShell`（容器栅格/hover/tooltip 白卡片），避免三处各写一套。

- `role` / `ariaLabel` / `onClick` / `busy` / `tooltip` / `className`。
- `onTooltipOpenChange`：打开时静默重检（服务胶囊）。
- 字号统一 12px（PillShell 统一定），胶囊文字只留语义色。

## 八、useStreamPulse — 单一真源

### 8.1 实现逻辑

- **共享 1s ticker + 一份快照**：顶栏两个胶囊（StreamStatusPill + TitleStreamIcon）读同一事实，不同步各自的定时器。
- `useSyncExternalStore(subscribe, readView, readView)`：1s 采样 store 聚合快照。
- `sameView` 比较：phase/tone/text/main/heartbeatAgeSec/bizAgeSec/dataAgeSec/bizStale/dataStale/sessionId/status/reconnectStatus/serverTaskId/activeSessions/pumpActive 全等才复用引用（避免无谓重渲）。
- `deriveStreamState(p, nowMs)`：纯函数，可单测；优先级：断流 > 重连/恢复 > 等确认 > 未建流 > 有产出 > 只有心跳 > 都没了。

### 8.2 关键常量

- `PULSE_TICK_MS = 1000`：采样周期。
- `STALE_SEC = 30`：静默阈值 = 后端心跳上限 25s + 5s 余量；心跳必先于阈值到达，灯不会在"正常的静默期"掉到更重的档。
- `IDLE_TIMEOUT`：transport 判死窗口（来自 chatStreamTransport），供 StreamStatusPill 浮层"判死"行。

### 8.3 三个时间戳语义

| 字段 | 含义 | 用途 |
|------|------|------|
| `lastBizTs` | 最近业务帧（有产出） | 判"有没有产出"的唯一依据 |
| `heartbeatTs` | 最近心跳 | 判"连接断没断" |
| `lastDataTime` | 最近收到任意字节（含心跳） | 对齐 60s 判死窗口 |

## 九、技术要点

1. **单一真源（DRY）**：`useStreamPulse` 是唯一数据源，StreamStatusPill 与 TitleStreamIcon 共享，避免两处各算各的导致状态不同步。
2. **1s 采样**：顶栏不需要 token 级实时，1s 粒度足够；避免每 token 重渲顶栏。
3. **PillShell 收口**：容器栅格/hover/tooltip 白卡片/字号统一 12px，三胶囊零重复代码。
4. **phase 作为 CSS 键**：表现层只认 phase，不拿中文文案当判断键（改文案不会悄悄失效）。
5. **TONE_COLOR 语义色**：文字与状态点同色，antd Badge 没有橘红 status 时走自定义 color 点。
6. **ref 防重入**：setState 异步，并发点击守不住，用 ref 守卫。
7. **挂载即自检**：零成本本地校验，点击胶囊 = 重新检测。
8. **Tip 打开静默重检**：保证看到的是此刻真值，而非挂载时的快照。

## 十一、数据流

```
chatStreamStore (getPulse) ──1s采样──► useStreamPulse ──► StreamStatusPill (胶囊文案/颜色/phase)
                                                    └──► TitleStreamIcon (spin-<phase> 转速)
useApp (healthStatus) ──► ServiceStatusPill (/health 三级)
useApp (serviceStatus) ──► ConfigStatusPill (五步校验 三级)
PillShell (共用外壳) ◄── 三个胶囊
```

切会话/流状态变化时：`useStreamPulse` 的 `sameView` 判定引用是否变化 → 无变化零重渲；有变化才更新胶囊与圈圈。

## 十三、已知限制

1. 窄面板顶栏溢出（710px）：三粒胶囊 + 品牌字 + 钟面在窄面板下可能挤，属既有布局缺陷，先不搞。
2. `StreamStatusPill` 的 8 档 phase 依赖 store 快照，store 快照更新频率受 1s 采样限制。
3. `ServiceStatusPill` 挂载自检仅一次，后续依赖点击重检或 Tip 打开静默重检。
