## 1. 结论摘要（先给结论）

**缺陷不是一个"文本文件"的个案，而是一类**：

> 计划器把条目判成 `native`（表示"该模型能用原生通道"），装配层却只给 `attachment`、`url` 两种来源写了 wire 占位；其余来源既不写占位、又被 `native` 集合剔出文本块 → **首发的 user 正文里整条消失**。

受影响分支（首发 `init_history` 路径）：

| 来源 | 内容 | 视觉模型结果 | 非视觉模型结果 |
|---|---|---|---|
| `selection`（文档片段） | text | **丢失** | **丢失** |
| `file`（整份文件） | text | **丢失** | **丢失** |
| `log`（日志） | text | **丢失** | **丢失** |
| `message`（消息） | text | **丢失** | **丢失** |
| `file` / `selection` | image/video/audio/richdoc | **丢失**（判 native 却无占位） | 装配层本可走文本卡，但**解析层读不了二进制，提前丢弃** |
| `attachment` | 任意 | 正常（原生占位） | 正常（降级文本卡，走文本块） |
| `url` | text | 正常（仅链接文本，按设计） | 正常（仅链接文本） |
| `url` | image/video/audio/richdoc | 正常（原生占位） | 正常（降级文本卡） |

插话路径（`build_interject_text`）不传 `plans`，全部按文本块渲染，**不会丢正文**；但 `attachment`/`url` 的媒体在插话里退化为文本卡/链接，**丧失原生投递**（已知降级，非本次主缺陷）。

`*` 处是"装配层假设 content 已就绪"的乐观结果。**真实链路里 `file/selection` 的非文本在解析层就已被丢弃**（见 2.3），根本到不了装配层的"正文可见"。

结论：**丢正文的集合 = `state=native ∧ source_kind ∉ {attachment, url}`**。文本只因"路由恒原生"而全中，图片等则在视觉模型下中招。

### 2.3 解析层独立缺口：file/selection 非文本读不了

`services/refs/resolver.py:193-224`：非 url、非 attachment 一律走 `browse.read_text_file`（外部路径走 `read_external_file`）。
`file_browse/browse_service.py:930-934`：`_probe_text` 判非文本即 `fail(UNSUPPORTED_TYPE)`（415）。

→ 引用项目里的 `.png/.pdf/.mp4` 等（kind=file/selection），在解析期就 `unsupported` 丢弃，**与模型是否视觉无关**。这是与主缺陷独立的第二道门。

### 2.4 生产者（分支是否真被用户触达）

- `file` / `selection`：`quoteFile` / `quoteSelection`（`features/refs/quote.ts`），被 FileDrawer 文件页、`quoteToast`、`@` 提及、素材包投喂、产物"引用"调用；**无文本类型守卫**，可产生 file/selection 的非文本条目。
- `attachment`：`uploadAttachment.enqueue`（上传/拖拽/粘贴/本地导入/产物存为附件）。
- `url`：前端全仓**未找到**创建 `kind:'url'` 的代码；契约/解析/wire 已就绪，属"未接线"。
- `log` / `message`：前端全仓**未找到**生产者；`ChatRef.kind` 类型也只声明 `file|selection|attachment`，属"契约支持但未接线"。
- 素材包投喂（`FileDrawer.feedPack`）对非附件条目一律 `quoteFile(it.path)`，**原始 kind 丢失**降级为 `file`。

## 4. 三堂会审逐维裁定

### 4.1 合规检查（10 大规范）

| 规范 | 裁定 | 依据 |
|---|---|---|
| SRP | 基本合规 | `build_user_turn_text` 只做装配；但"某来源有无占位"的知识被隐式塞进它 |
| DRY | **违规** | "哪些来源有 wire 占位"由 `message_builder` 硬编码 `attachment/url`，与 `attachment_wire` 实际能力是两份知识，易漂移；应单点导出 |
| KISS-DIRECT | **违反** | `native` 同时表达"全文注入"与"原生 part"两种语义，消费方无法直线判断，凭 state 走分支必然漏 |
| SLAP | 合规 | 装配层无底层细节 |
| YAGNI | 部分违规 | `url/log/message` 契约齐备但前端未接线，形成"看似支持、实测不可达"的死能力 |
| 禁止 backward | 合规 | 未发现兼容分支 |
| 关联一致性 | **违规** | 契约 `state_of` 判 native，装配不投递，能力矩阵/徽标与运行时口径再次分叉（与 11-12 修复的"矩阵错显"同类问题） |

### 4.2 合理检查（逻辑是否最优雅）

现行逻辑"先剔除 native 再补占位"要求两个集合恰好互补。实际是：

- 集合 A（有占位来源）= {attachment, url}
- 集合 B（state=native）= {attachment, url, text 全来源, 视觉模型下的 image/video/audio/richdoc}

`B - A ≠ ∅` 时即丢。正确写法应是"**以 A 为准决定跳过文本块**"，而不是"以 state 为准"。一句话：**判据用错了维度**（用"能力可达"当"投递方式"）。

### 4.3 关联检查（上上下下、前前后后）

| 关联点 | 影响 |
|---|---|
| 上游 `contract.state_of` | 11-12 把 text 判为 native（"全文注入"），直接触发本缺陷 |
| 上游 `resolver` | file/selection 非文本走文本读，415 丢弃（第二道门） |
| 下游 `attachment_wire` | 只展开 ATTACHMENT/URL_ITEM，没有第三条原生通道 |
| 旁路 插话 `build_interject_text` | 不传 plans，全部文本渲染 → 不丢正文，但媒体失原生 |
| 旁路 素材包 `feedPack` | 非附件条目 kind 被降级为 file，原始来源语义丢失 |
| 展示层 能力矩阵/徽标 | 仍显示 native，与实际投递不符，误导用户 |

## 6. 各分支逐一裁定

### 6.1 `selection`（文档片段）— 主诉分支
- 首发：text 恒 native → **丢弃**；媒体在视觉模型下 → **丢弃**，非视觉在解析层 415 **丢弃**。
- 插话：文本渲染 → 正常。
- 裁定：**有问题（首发）**。

### 6.2 `file`（整份文件）
- 与 selection 同路由，行为完全一致（区间与否只影响 resolver 读取方式）。
- 裁定：**有问题（首发）**；另加解析层非文本缺口。

### 6.3 `log` / `message`
- 契约 `classify_ref` 恒映射 text → native → 首发**必丢**。
- 前端未接线（无生产者），当前不可达；一旦接上"日志引用/消息引用"立即复现。
- 裁定：**潜伏缺陷**，需随主修一并修掉。

### 6.4 `attachment`
- 首发：native → 占位 → wire 展开为 native part（失败降级注入文本），**正常**。
- 插话：无 plans → 退化为文本卡/注入文本，**媒体失原生**（设计限制）。
- 非视觉：opaque/degraded → 文本块，正常。
- 裁定：**首发正常**；插话降级需知会。

### 6.5 `url`
- 首发：text→opaque 仅链接文本（设计如此）；媒体→native 占位，正常。
- 前端无生产者，属"未接线"；契约/解析/wire 已齐。
- 裁定：**链路正确但未验证**（无真实入口）。

### 6.6 素材包 / 产物
- 素材包：DB 保存 kind，前端投喂却用 `quoteFile` 覆盖为 file，**来源语义丢失**（DRY/一致性小问题）；若条目是图片，再落 6.1 的坑。
- 产物"引用"：走 `quoteFile(path)` → kind=file；若产物是图片/视频，落解析层 415。
- 裁定：**有隐患**。

## 7. 解决方案（分层，含取舍）

### L1 装配层（必须，止血静默丢失）— 单点修复

`message_builder.build_user_turn_text`：把"跳过文本块"的判据从 `state==native` 改成"**该来源确有 wire 占位**"。

```python
# 现状(231-241):
native = {id(r) for r, p in zip(refs or [], plans or []) if p.state == "native"}
text_refs = [r for r in (refs or []) if id(r) not in native]
...
for r, p in zip(refs or [], plans or []):
    if p.state != "native": continue
    if p.source_kind == "attachment": ...
    elif p.source_kind == "url": ...

# 修复:
native_slot = {
    id(r)
    for r, p in zip(refs or [], plans or [])
    if p.state == "native" and p.source_kind in contract.SLOT_SOURCES
}
text_refs = [r for r in (refs or []) if id(r) not in native_slot]
...
for r, p in zip(refs or [], plans or []):
    if id(r) not in native_slot: continue      # 与 text_refs 严格互补, 防双写
    if p.source_kind == "attachment": ...
    elif p.source_kind == "url": ...
```

配套（DRY）：在 `contract.py` 导出唯一真源

```python
SLOT_SOURCES = frozenset({"attachment", "url"})   # 有 wire 占位的来源; 与 attachment_wire 同源
```

效果：
- `file/selection/log/message + text` → 回到文本块，**正文恢复**；
- `file/selection + image/video/audio/richdoc` → 不再被剔出，走文本块（元信息卡），**至少不静默丢**；
- `attachment/url` → 仍走占位，**防双写不变**；
- 不改契约 `state_of`，不影响能力矩阵/徽标口径（矩阵仍表示"能力可达"，投递由占位能力兜底）。

> 取舍说明：L1 不追求"file/selection 媒体真原生"，只保证不丢；真正的原生投递见 L3。

### L2 解析层（必须，修 file/selection 非文本 415）

`resolver._read_one` 的非 url/attachment 分支：先按 `classify(Path(path), mime, size)` 分内容类型，文本走 `read_text_file`；非文本走 `extract` 的对应文本出口（`_image_card` / `_video_card` / `_audio_card` / `_richdoc_body` / `_binary_card`），产出元信息卡而不是 `unsupported` 丢弃。

```python
ck = classify(Path(path), mime, size)
if ck != "text":
    route = KIND_CONTRACT[("file", ck)]
    return ResolvedRef(ref={**ref, "content": route.extractor({...})}, truncated=False, note="")
# 以下保持既有文本读取/区间/摘录逻辑
```

效果：文件页/素材包/产物引用的图片、PDF、视频等不再 415；与契约 `fallback_quality` 语义对齐，也让能力矩阵不再"说谎"。

> 注意：`extractor` 对 attachment 需要记录字段；file 场景需构造最小 att dict（path/label/kind），或新增单参文本出口。实现时须保持"文本出口唯一产生点"的 DRY 约束。

### L3 契约层（结构性根治，后续）

把"能力可达（state）"与"投递方式（delivery）"拆为两个正交维度：`delivery ∈ {wire-slot, text-block, none}`，装配层只读 `delivery`。同时若要"file/selection 媒体真原生"，需扩展 `attachment_wire` 支持按 path 读字节的第三种占位。改动面涉及 contract 全表、批量/预判、徽标展示，建议 L1+L2 稳定后再评估。**字段级正式定义与落地规范见第 10 章。**

### 明确不做
- 不加"回退旧字段/旧逻辑"的兼容分支（违反禁止 backward）；
- 不用测试用例固化错误逻辑来"证明没问题"；
- 不在插话里强行塞 native parts（历史恒为 str，需另立设计，本次只标注降级）。

## 10. 治理规范：状态模型与 wire 前缀体系（全局·长远）

> 本章不是补丁，是**标准**。目标：把"状态标签"与"前导标签"两件含糊事，按"语义唯一、单一真源、处理器一一对应"定到数据模型层与注册表层，使后续新增来源/内容类型只需登记一条，不改装配、不改展开、不做中途翻译。
>
> 规范生效后，第 7 章的 L1/L2/L3 收敛为本章的一次性切割，不再分三次打补丁。

### 10.0 治理定到哪一层（分层原则）

| 层 | 名称 | 交付物 | 载体 | 守门 |
|---|---|---|---|---|
| L0 | 术语契约 | 每个词只有一个含义，禁止一物多用 | 本文档本章 | 评审 |
| L1 | 数据模型 | 字段/枚举正交、取值封闭 | `contract.py`、`wire_prefix.py` | 类型 + 枚举断言 |
| L2 | 单一真源 | 前缀↔处理器绑定在注册表，禁止散落 | `wire_prefix.py`、`SLOT_WRITERS` | AST 扫描测试 |
| L3 | 消费纪律 | 装配/渲染/展开/前端只读投影，不自行判档 | 各自模块 | 契约测试 |
| L4 | 守门测试 | 规矩变成可执行断言 | `tests/` | CI 全绿 |

**为什么定到 L1/L2 而不是只改 `message_builder`**：当前缺陷的根因在"字段语义"和"字面量散落"两处，改调用点只能消灭一个实例；字段与注册表才是缺陷的生成器。

---

### 10.1 状态标签定性：一个枚举背了五种语义

`state ∈ {native, degraded, opaque}` 目前同时承担：

| 语义 | 例子 | 消费方 | 代码坐标 |
|---|---|---|---|
| ① 模型能力可达 | 视觉模型能收 image | `ref_capability_map` 矩阵 | `contract.py:195-212` |
| ② 投递方式 | 写 wire 占位 / 写文本块 | `build_user_turn_text` | `message_builder.py:231-241` |
| ③ 保真度 | 全文 / 元信息 / 仅链接 | 前端徽标、preflight | `ModelTabRefCapability.tsx:36-56` |
| ④ 可投递性 | 有无原生通道 | `state_of` | `contract.py:143-158` |
| ⑤ 展示档位 | 绿/蓝/灰徽标 | `CapabilityBadge` | `frontend/.../CapabilityBadge.tsx` |

**三个实证（可复核，非推测）**：

1. **死代码证明语义缺口**：`contract.py` 的 `_reason()` 有分支返回 `"载荷不可获取"`，但该分支只在 `cap and cap.native` 为真时命中；而 `_reason` 仅在 `not (cap and cap.native)` 的 `else` 分支被调用 → 该返回值**永不发生**。代码想表达"模型支持但拿不到载荷"，枚举里却没有这个格子。
2. **矩阵与运行时口径分叉**：`ref_capability_map` 传 `transport_ok=False` 曾致视觉模型图片格不显 native（11-12 已修），说明同一字段被两套判据反复解释。
3. **前端在做翻译**：`ModelTabRefCapability.tsx` 用 `(content_kind, state)` 组合再映射文案（`'richdoc:degraded': '文档抽取信息注入'`、`'video:degraded': '媒体元数据注入'`、`'url:opaque': '链接地址注入'`）。这就是"说一套做一套中间带翻译"的典型：后端一个含糊档位，前端靠类型组合还原真实语义。

**结论**：`state` 不是"状态"，是"能力+动作+保真"三件事挤在一个词里。必须按语义拆开，且每个词只回答一个问题。

### 10.2 状态模型规范（L1）

#### 10.2.1 三个字段，各答一问

| 字段 | 回答的问题 | 取值（封闭） | 谁读 |
|---|---|---|---|
| `quality` | 这条最终能拿到**多好的信息** | `native_part` \| `text_full` \| `text_card` \| `link_only` \| `none` | 前端徽标、矩阵、日志/指标 |
| `delivery` | 装配层**怎么投递** | `slot` \| `text` \| `none` | 仅 `build_user_turn_text` / wire |
| `reason` | 为什么没到更高档 | 自由文本（面向排障/UI tooltip） | 日志、UI tooltip |

- `quality` 是**保真结果**，不驱动装配；
- `delivery` 是**装配动作**，不描述保真；
- 二者是声明式全映射，不是分散在各处的 `if` 翻译：

```python
QUALITY_TO_DELIVERY = {
    "native_part": "slot",
    "text_full":   "text",
    "text_card":   "text",
    "link_only":   "text",
    "none":        "none",
}
```

#### 10.2.2 `quality` 的唯一派生规则

```python
def quality_of(source_kind, content_kind, cap, slot_writer) -> str:
    route = kind_route(source_kind, content_kind)
    if slot_writer and cap.native:          # 有原生通道 + 模型支持
        return "native_part"
    return {
        "content":  "text_full",
        "metadata": "text_card",
        "card":     "text_card",
        "link":     "link_only",
    }.get(route.fallback_quality, "none")
```

关键修正：`slot_writer` 是否存在**参与判定**。`file/selection` 的 image 在视觉模型下，`cap.native=True` 但**来源无原生 slot** → 落到 `text_card`（并给出 `reason="来源无原生投递通道"`）。这正是 10.1 死代码想表达、旧枚举无处安放的情形。

#### 10.2.3 旧值 → 新值映射（一次性替换，不做兼容）

| 旧 `state` | 实际情形 | 新 `quality` | 新 `delivery` |
|---|---|---|---|
| `native` | attachment/url 媒体，模型支持 | `native_part` | `slot` |
| `native` | text / richdoc 全文注入 | `text_full` | `text` |
| `native` | 模型支持但来源无 slot（旧版丢失 bug） | `text_card` | `text` |
| `degraded` | 媒体元信息卡 | `text_card` | `text` |
| `degraded` | 富文档抽取全文 | `text_full` | `text` |
| `opaque` | 仅链接地址 | `link_only` | `text` |
| `opaque` | 未知/不可用 | `none` | `none` |

#### 10.2.4 装配契约：一个 `delivery` 值对应一个分支

`build_user_turn_text` 此后**只读 `delivery`**，结构固定为三分支：

```python
if p.delivery == "slot":
    refs_block += SLOT_WRITERS[p.source_kind].make(ref)   # 注册表取用，无 source 硬编码
elif p.delivery == "none":
    refs_block += notice_line(p)                           # 明确告知"未投递"
else:                                                      # text
    text_refs.append(ref)                                  # 交 render_refs_block
```

- 禁止再出现 `if p.source_kind == "attachment" ... elif == "url"`；
- 禁止在装配层重新解释 `quality`；
- `attachment + text` 由"slot 绕一圈降到 text"改为**直接 `text_full`**（正文由 resolver 已产出），去掉无意义往返。

#### 10.2.5 前端与矩阵投影

- `ref_capability_map` 更名 `ref_quality_map`，直接返回值 `quality`（5 值），**不再由 `content_kind` 二次翻译文案**；
- `CapabilityBadge` 的 key 从 `(content_kind, state)` 改为 `quality`；
- 徽标语义固定：`native_part`=原生投递、`text_full`=全文注入、`text_card`=元信息注入、`link_only`=仅链接、`none`=不可用。

#### 10.2.6 明确删除

- `STATES = ("native","degraded","opaque")` → 删除，替换为 `QUALITIES` / `DELIVERIES`；
- `aggregate_state()` 当前**无任何调用方**（已核实），直接删除，不保留死代码；
- `state_of()` 更名为 `quality_of()`，签名去掉已无意义的参数。

### 10.3 前缀体系规范（L1）

#### 10.3.1 五层分类，括号风格唯一

| 层 | 用途 | 括号风格 | 是否闭合 | 方向 |
|---|---|---|---|---|
| `ENVELOPE` | 包裹整段材料，划边界 | `<类型> … </类型>` | 必须闭合 | 后端→模型 |
| `ITEM` | 多条材料的条目标识 | `【类型N】` | 不闭合，单行 | 后端→模型 |
| `INLINE` | 单条内容头 / 状态注 | `[主体·形态]` | 不闭合，单行 | 后端→模型 |
| `SLOT` | 机器占位，wire 期替换 | `[[TYPE:payload]]` | 不闭合，正则可解析 | 后端内部 |
| `TOOL_PREFIX` | 工具结果前缀 | `[Observation]` | 不闭合 | 协议面向 |

铁规：
- **一个层只用一种括号风格**，禁止 `【】` 与 `[]` 混表不同层语义；
- `SLOT` 是 **ABI，冻结不可改**（历史/持久化里是字符串，改名即断链）；
- `【文件引用】` 属"提示区段头"，单列为 `PROMPT_SECTION`，不参与数据前缀归一。

#### 10.3.2 机器占位（冻结，禁止改名）

| 占位 | 产出 | 消费 |

| `[[ATTACHMENT:<32hex>]]` | `attachment_wire.attachment_slot` | `ATTACHMENT_SLOT_RE` + `_expand_attachment` |
| `[[URL_ITEM:<b64url>]]` | `attachment_wire.url_item_slot` | `URL_SLOT_RE` + `_expand_url` |
| `[[文件:<path>#L12-L20]]` | 模型输出（非输入占位） | 前端 `projectPath.preprocessFileRefs` |

#### 10.3.3 语义/包裹前缀全量清单与归一目标

| 层 | 现值 | 产出坐标 | 目标 | 处置 |

### 10.4 前缀 ↔ 处理器：单一注册表（L2，核心）

#### 10.4.1 词表模块 `app/wire_prefix.py`（零依赖）

只放**字面量与正则**，被 `extract` / `render` / `workspace_block` / `attachment_wire` / `message_builder` 导入：

```python
ENV_REFS_OPEN   = "<引用资料>"
ENV_REFS_CLOSE  = "</引用资料>"
ENV_WS_OPEN     = "<事项目录>"
ENV_WS_CLOSE    = "</事项目录>"
ITEM_REF        = "【引用{n}】"
INLINE_LINK     = "[链接]"
INLINE_ATT_BODY = "[附件·正文]"
INLINE_ATT_PREV = "[附件·正文·预览]"
INLINE_ATT_META = "[附件·元信息·{kind}]"
INLINE_ATT_FAIL = "[附件·未发送: {why}]"
INLINE_URL_FAIL = "[链接·未转发: {why}]"
INLINE_EXTRACT_FAIL = "[附件·抽取失败({err})]"
INLINE_TRUNCATED    = "[已截断：…]"
SLOT_ATTACHMENT_RE  = re.compile(r"\[\[ATTACHMENT:([0-9a-f]{32})\]\]")
SLOT_URL_RE         = re.compile(r"\[\[URL_ITEM:([A-Za-z0-9_\-=]+)\]\]")
```

#### 10.4.2 占位写入器注册表（唯一真源）

```python
@dataclass(frozen=True)
class SlotWriter:
    can:    Callable[[dict], bool]   # 本条能否写占位（id 存在 / URL 可编码且不超长）
    make:   Callable[[dict], str]    # 写占位
    pattern: re.Pattern              # 解析占位
    expand: Callable                 # 占位 → wire part / 降级文本

SLOT_WRITERS: Dict[str, SlotWriter] = {
    "attachment": SlotWriter(..., attachment_slot, SLOT_ATTACHMENT_RE, _expand_attachment),
    "url":        SlotWriter(..., url_item_slot,    SLOT_URL_RE,        _expand_url),
}
```

- 旧 `contract.SLOT_SOURCES` 删除，来源集合**只由 `SLOT_WRITERS.keys()` 提供**（消除第二真源）；
- 装配写占位、wire 展开、正则识别，全部走同一张表；
- 新增来源（如 `file` 直读字节）= **加一条 `SlotWriter`**，装配/展开/渲染零改动（OCP）。

#### 10.4.3 四条消费纪律

1. 任何模块**不得**再写字面量前缀，只能引用 `wire_prefix` 常量（AST 守门）；
2. `build_user_turn_text` 不得出现 `source_kind` 字面量分派，只能 `SLOT_WRITERS[p.source_kind]`；
3. `attachment_wire` 的扫描正则只能来自注册表，禁止另起 `re.compile`；
4. 前端不得按 `content_kind` 组合翻译 `quality`，只按 `quality` 查一张文案表。

#### 10.4.4 接入成本（可扩展性验收）

| 场景 | 旧成本 | 新成本 |
|---|---|---|
| 新增内容类型 | 改 contract + extract + 装配 + 前端 | `KIND_CONTRACT` 加一行 + 一个 extractor |
| 新增来源 | 改 state_of + plan + 装配 + expand + 前端 | `SLOT_WRITERS` 加一条（若需原生） |
| 改文案标签 | 全仓搜替换 | `wire_prefix` 改常量 |

### 10.5 落地顺序（禁止 backward，一次性切割）

| 阶段 | 内容 | 触及文件 | 验收 |
|---|---|---|---|
| P0 词表 | 新建 `wire_prefix.py`，替换全部散落字面量（**输出逐字节不变**） | extract/render/workspace_block/attachment_wire/message_builder | 现有单测全绿 + 快照一致 |
| P1 状态 | `state`→`quality/delivery/reason`；装配三分支；矩阵/徽标改投影；删 `aggregate_state`/`STATES` | contract/message_builder/react_loop/model_service/前端 | 2.2 矩阵全部"正文可见或 slot"；无丢失 |
| P2 语义前缀 | 按 10.3.3 归一 `[附件·…]` 系列；同步 e2e 断言 | extract/attachment_wire/attachment_service/测试 | 前缀配对测试 + e2e |
| P3 扩展 | （可选）`file/selection` 原生 slot 入注册表 | attachment_wire/resolver | 矩阵显 `native_part` |

- 禁止双写旧字段过渡（违反禁止 backward）；
- 每阶段独立可回滚（回滚的是整阶段提交，不是代码内兼容分支）。

### 10.6 守门测试（L4：把规矩变成断言）

1. **无散落字面量**：AST 扫描 `app/`，凡出现 `wire_prefix` 已登记的字面量、且不在 `wire_prefix.py`，判失败；
2. **前缀↔处理器配对**：遍历 `wire_prefix` 每个常量，断言有且仅有 1 个产出点、1 个消费点；
3. **占位注册表完备**：`SLOT_WRITERS` 每条 `pattern` 与 `make` 互逆（make→pattern 必匹配）；
4. **状态合法性**：`QUALITY_TO_DELIVERY` 覆盖全部 `QUALITY`，且无多余键；
5. **全分支快照**：6 来源 × 7 内容 × 2 模型 × 2 路径，断言 `delivery != none` 时 user 正文必含对应 slot 或正文（直接守 1.1 的"静默丢失"类缺陷）；
6. **前端只读 quality**：类型层禁止 `CapabilityBadge` 接收 `content_kind` 参与判档。

---

### 10.7 风险与取舍

- **可见文案变更**（P2）：`[附件档案卡·图片] → [附件·元信息·图片]` 会改变模型提示词与前端 e2e 断言；收益是长期可读与可维护，需一次性同步测试。
- **不引入能力字段**：`capability` 仅作 `quality_of` 的中间量，不落库、不下发，避免再造一个"可被误读的档位"。
- **`<会话工作目录>`**：若仍在产出，与 `<事项目录>` 语义重叠，必须在 P2 一并核查合并，禁止两套目录块并存。
- **插话路径**：`build_interject_text` 目前不传 plans，P1 必须与首发共用同一 `delivery` 计划，否则"首发原生、插话降级"的分叉会复现。
