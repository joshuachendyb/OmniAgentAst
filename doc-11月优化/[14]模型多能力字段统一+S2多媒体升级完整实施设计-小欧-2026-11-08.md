## 0. 摘要（一句话）

把系统里 **model 多能力表达从"capabilities 与 input_modalities 两套并存"收口为 `input_modalities`（理解输入）+ `output_modalities`（生成输出）两个正交字段，枚举统一为远端标准 `{text, image, file, video, audio}`**（这是基础，不含兼容回退；`image_url` 是图片入参的**传输形式**而非枚举值，`file` 是**独立于 image 的文档能力**，看图走 input、生图/生视频走 output），并在此之上落地 **S2 多媒体升级：agent 从文本支持升级为按模型 input 能力收发图片**（配置层 + 模型请求层全链路贯通）。

## 1. 背景与根因（实测钉死，非推测）

前几轮用真实 API + `get_models()` 实测确认了三条硬事实：

### 1.1 agnes `/v1/models` 不返回能力字段
实测返回仅 `{id, object, created, owned_by, supported_endpoint_types}`，**没有** `input_modalities`/`capabilities`/`vision` 等能力位。→ **能力只能来自本地 `config.yaml 的 model_meta` 手工维护**，模型接口不可作为能力来源。

### 1.2 config 层两套字段并存（历史遗留）
实测 12 个 provider 的 `model_meta`：

| 用 `capabilities`（老） | 用 `input_modalities`（新） |
|---|---|
| **agnes**、**ZenFree**（仅 2 个，且 image 能力写在 `capabilities:['text','image']`） | sensenova、zhipuai、Discoversh、openrouter、longcat、zenmux、DeepSeek、moonshot、minimax、kilo（10 个） |

**结论**：早期系统写 `capabilities`，后来改成 `input_modalities`，老厂商（agnes/ZenFree）没迁移，两套并存。

### 1.3 后端读写断链（比 agnes 更严重）
- `_models_of`（get_models 下发已保存库）**只读 `meta.get("capabilities")`，不读 `input_modalities`**。
- 模型库 tab 保存（`replace_provider_models`）写的是 **`input_modalities`**。

实测后果——**同一批支持图片的模型，能力被后端下发逻辑丢掉**：

| 模型 | config.input_modalities | get_models 暴露的 capabilities |
|---|---|---|
| sensenova-6.8-flash | `['text','image']` | **`[]` 丢失** |
| Discoversh.Agents-A1 | `['text','image']` | **`[]` 丢失** |
| DeepSeek.deepseek-flash | `['text','image']` | **`[]` 丢失** |
| agnes-image-2.1-flash | `[]` | `['text','image']` ✓（恰好用老字段） |

**讽刺**：只有 agnes/ZenFree 这两个"老格式"厂商能力能正常暴露；10 个"新格式"主力厂商的支持图片模型，`get_models` 下发时能力全部丢失。

### 1.4 前端两处消费不同字段 + 这也是**两 tab 能力写入方式不同的直接后果（根源）**

两个 tab 对"模型能力"的处理方式**从源头就不一致**，这正是字段不统一的真正根源：

| Tab | 能力来源 | 写到 config 的字段 | 读回字段 |
|---|---|---|---|
| **Tab模型选择（设置界面能力编辑区）** | 用户**手动勾选/手写**能力 | `capabilities`（get_models→add_model/update_model） | `capabilities` |
| **模型库 tab（拉远端/勾选保存）** | 系统**保存时自动获取**（fetch_remote_models 从 `/v1/models` 拉取输入模态） | `input_modalities`（replace_provider_models） | `input_modalities` |

- **根源链条**：手写能力区（老，`capabilities`）与自动获取模型库（新，`input_modalities`）是**两套并行的能力管道**，各自读写自己的字段 → config 里两字段并存 → 后端与前端各自对不上。
- **前端消费侧**：
  - 模型库 tab（ModelLibraryTab）读 `fetchRemoteModels().input_modalities`，显示"输入模态"列。
  - 能力编辑区（useSettings/SettingsPage 能力 Checkbox、ModelSelector、CurrentModelRefCard）读 `get_models().capabilities`。
- **前端能力枚举还不一致**（list 值都不统一，见 §1.6）：能力编辑区 `CAPABILITY_OPTIONS` = `text/image/video/audio/pdf`，模型库 tab `MODALITY_LABEL` = `text/image/file/video/audio` —— **`pdf` vs `file` 冲突**。

### 1.5 agent 调用链现状
- agent 目前**不消费任何模态字段**，`observation_formatter` 直接把 base64 图塞进文本。
- `supports_image_input` 是 S2 要新建的判断位，现有 `[10]` S2 蓝图主张它"只读 `input_modalities`"，但**前提是 config 里 `input_modalities` 是完整真源——此前提被 1.3 实测证伪**（能力编辑区落的是 `capabilities`）。

### 1.6 能力 list 枚举不一致（第三层不统一）
除**字段标签**（`capabilities` vs `input_modalities`）不统一外，**list 的枚举值（能力取值集合）也不一致**：

| 位置 | 枚举集合 | 备注 |
|---|---|---|
| 能力编辑区 `CAPABILITY_OPTIONS`（tab模型选择，手写） | `{text, image, video, audio, pdf}` | **用 `pdf`** |
| 模型库 tab `MODALITY_LABEL`（远端自动获取显示） | `{text, image, file, video, audio}` | **用 `file`** |

→ 同一"文档输入能力"，一处叫 `pdf`、一处叫 `file`，两 tab 的能力值集合对不上。用户明确要求：**字段标签统一后，list 里的取值也必须统一**（list 有几个、叫什么，也一并收口）。

### 1.7 枚举值与多模态研究结论（本轮网络研究 + 实测钉死）

为把能力枚举搞准确，本论调研了 OpenAI/OpenRouter/ZenMux/Orq 等官方多模态文档，并对 agens 全部模型实测，得出以下**权威结论**：

**① `image_url` 不是枚举值，是"图片的入参传输形式"**
- OpenAI 多模态 content part 的 `type` 字段是 `text` / `image_url` / `file` / `input_audio` / `video_url` 等——`image_url` 是**发送图片的方式**（公共 URL 或 base64 data URI），不是模型"支持什么模态"。
- `input_modalities` 的枚举值只有 5 种：`text / image / file / video / audio`（本仓 `model_routes.py:165` 实测 OpenRouter 460 模型：`text(460)/image(292)/file(182)/video(85)/audio(44)`）。
- **结论**：模型"支持 `image_url`" = 支持 `image` 模态，`image_url` 是该模态的 wire 入参形式，**不进枚举**。

**② `file` 模态 ≠ 仅 PDF，且与 `image` 是独立能力**
- OpenRouter 实测 `file` 上传类型涵盖：`PDF / DOCX-XLSX-PPTX / 图片引用 / 音频 / UTF-8 文本`。
- Orq 明确警告：**"Image support and PDF support are separate capabilities. A model that reads images very often cannot read a PDF."** —— 看图能力与读文档能力**独立**，`file` 不能与 `image` 混为一谈。
- **结论**：`file` 保留为独立枚举值，表达"能处理文档/PDF"。

**③ office/PDF 存在"直接支持 vs 间接支持"两种**
- **间接支持**（本系统现状）：S1 用 `extract.py` 读 office/PDF **转出文本**，通过文本模型消费——任何文本模型都能"间接读文档"。
- **直接支持**：新版模型原生接受 `file` content part（OpenRouter/ZenMux 支持原生 PDF/office 传入），无需转文本。
- OpenRouter 的 PDF 是"智能解析提取文本"（间接为主），但也支持原生 file part（直接）。
- **结论**：能力枚举 `file` 应表示"直接支持 file 入参"；office/PDF 的间接支持是 S1 已有能力，不占 `file` 枚举。

**④ agnes 视觉理解实测 + 官方文档（决定性反转，input 理解 vs output 生成）**：对 `agnes-*` 全部模型用 `image_url` 实拍 1px 图测看图，并核对官方文档（读者提供的 `agnes-image-20-flash`/`agnes-video-25-flash` 页面）：

**核心认知**：`agnes-image-*`/`agnes-video-*` **不是"不支持 image"**，而是它们是**生成输出（output）模型**——走独立的**生成端点**（`/v1/images/generations`、`/v1/videos`），不是 `/v1/chat/completions` 的"输入看图"通道。这正是 **`input_modalities`（理解输入）与 `output_modalities`（生成输出）两个独立维度的区别**。

| 模型 | 像 agens 文本 flash 那样用 image_url 看图(input) | output 生成能力 | 调用端点 | config 现状 |
|---|---|---|---|---|
| `agnes-2.5-flash` | ✅ 能看图（返回 "Red"） | 文本 | `/v1/chat/completions` | `capabilities=[]`❌ 漏标 image |
| `agnes-3.0-flash` | ✅ 能看图（返回 "Red"） | 文本 | `/v1/chat/completions` | `capabilities=[]`❌ 漏标 image |
| `agnes-2.5-pro/alpha/beta` | ⚠️ 收 image_url 但返回空 | 文本 | `/v1/chat/completions` | `capabilities=[]` 支持通道，待核 |
| `agnes-image-2.0/2.1/2.5-flash` | ❌ 不走 chat/completions 看图 | **图像生成**（文生图/图生图/多图合成） | `/v1/images/generations` | `capabilities=['text','image']` ❌ 标注语义错 |
| `agnes-video-2.5/2.5-flash` | ❌ 不走 chat/completions | **视频生成**（文生视频/首尾帧/参考图） | `/v1/videos`（异步任务） | `capabilities=['text','image','video']` ❌ 标注语义错 |

**权威依据（读者提供文档）**：
- `agnes-image-2.0-flash` 官方页：`POST /v1/images/generations`，模型 `agnes-image-2.0-flash`，支持"文生图、图生图、多图合成"→ **`output_modalities: [image]`**。
- `agnes-video-2.5-flash` 官方页：`POST /v1/videos`（创建）+ `GET /agnesapi?video_id=&model_name=`（查询），异步生成视频 → **`output_modalities: [video]`**。

> **重大理解修正**：我之前把 `agnes-image-*`/`agnes-video-*` 简单归为"不支持 image"是**不准确的**。准确说法是：**它们不是"输入看图"模型（`input_modalities` 不含 image），而是"生成输出"模型（`output_modalities` 含 image/video），走独立的生成端点，能力标在 output 维度**。这与 sensenova 一致：`sensenova-6.8-flash` 等是支持 image_url 输入的**多模态理解模型**（`input_modalities:[text,image]`），`sensenova-u1.5-lite/fast` 是**图片创作（生成）模型**（`output_modalities:[image]`）。

### 1.8 "模型能力"是两个正交维度：`input_modalities`（理解输入）vs `output_modalities`（生成输出）

读者点破的核心，能力应分两个独立字段：

| 维度 | 字段 | 含义 | 典型模型 | 走 /v1/chat/completions 吗 |
|---|---|---|---|---|
| **理解（输入）** | `input_modalities` | 能**接收**什么类型入参 | 文本 flash `['text','image']`（看图） | ✅ 是 |
| **生成（输出）** | `output_modalities` | 能**产出**什么类型 | `agnes-image-*`→`[image]`、`agnes-video-*`→`[video]`、`sensenova-u1.5-*`→`[image]` | ❌ 否，走独立生成端点 |

- **看图**（多模态理解）= `input_modalities` 含 `image`，走 chat/completions + `image_url` part。
- **生图** = `output_modalities` 含 `image`，走 `/v1/images/generations`。
- **生视频** = `output_modalities` 含 `video`，走 `/v1/videos`。
- 系统 `model_service` **已支持 `output_modalities`**（`_parse_remote_models_body` 已从远端归一该字段，model_routes.py 注释明确"output_modalities=image 才是图像生成模型"），**只是 config 的 agnes 没用品这个维度表达**——这正是要补的。

## 2. 设计目标与约束

### 2.1 目标
1. **字段统一到 `input_modalities` + `output_modalities` 两个正交维度**（理解输入 / 生成输出），config / model_service / 前端 / agent 全链路只认这两个字段表达"模型可接收/可产出模态"。
2. **S2 多媒体升级**落地：agent 按 `input_modalities` 是否含 `image` 决定"图片走 `image_url` parts 还是走文本档案卡"（理解看图）。
3. 升级同时体现在**配置层**（config 迁移 + 保存口径）与**模型请求层**（wire parts 展开）。
4. **准确区分能力方向**：看图 → `input_modalities:[image]`；生图 → `output_modalities:[image]`；生视频 → `output_modalities:[video]`（各自对应不同端点，见 §1.8）。

### 2.2 铁规约束（用户明确要求）
- **不搞兼容**：不做 `capabilities` 读一套、`input_modalities` 读一套的双读兜底；统一后一律读写 `input_modalities` + `output_modalities` 双字段。
- **不违反 10 大规范**：SRP / DRY / KISS-DIRECT / SLAP / YAGNI / 禁止 backward；重构 4 条 OCP/LSP/ISP/复用优先。
- **逻辑直线不绕弯**：能力判定只在 **model_service 一处归一**，config 是唯一真源，agent 与前端都不再造第二套解析。

### 2.3 字段名裁决依据
统一到 **`input_modalities`（理解输入）+ `output_modalities`（生成输出）两个字段**，其中输入统一到 `input_modalities`，理由（KISS-DIRECT + 一致性）：
1. 它是 **config 主流（10/12 厂商已在用）**。
2. 它是**远端拉取标准归一字段**（OpenAI/SenseNova/OpenRouter 生态，`_KEY_ALIASES` 已归一到此）。
3. 它是 **S2 `supports_image_input` 现有蓝图读的字段**（`[10] §3.20`）。
4. `capabilities` 语义与"输入模态"重复，且只有老厂商用，本就是要淘汰的。

> **不再保留 `capabilities`**：老厂商数据迁移到 `input_modalities` 后，`capabilities` 字段在 config / 前端 / model_service 一律删除。

**list 枚举值裁决**（D6）：统一到 **远端标准值集合 `{text, image, file, video, audio}`**。依据（KISS-DIRECT + 一致性）：
1. 它与 **OpenAI/SenseNova/OpenRouter `/models` 远端实测值一致**（实测 `input_modalities` 仅 5 种：`text/image/file/video/audio`，见 model_routes.py:165 注释）。
2. 模型库 tab 的 `MODALITY_LABEL` 已是这套值。
3. `capabilities` 的 `pdf` 是孤例，与远端 `file` 冲突 → 淘汰 `pdf`、统一为 `file`（`pdf` 是 `file` 的子集，语义可覆盖）。

**枚举语义澄清**（承 §1.7/§1.8 研究结论，**input/output 双维度**）：
- **`input_modalities`（理解输入）**：模型能**接收**什么类型入参。`image` = 能看图（wire 上是 `image_url` part，URL 或 base64，走 `/v1/chat/completions`）。这是 S2 关注的能力。
- **`output_modalities`（生成输出）**：模型能**产出**什么类型。`image` = 能**生成**图（`/v1/images/generations`），`video` = 能**生成**视频（`/v1/videos`）。生图/生视频模型的能力标在这里，不标在 input。
- `image_url` **不是枚举值**，是 `image` 模态的 wire 入参传输形式；`file`（input）与 `image`（input）独立（能看图≠能读文档）。
- office/PDF 的**间接支持**（S1 `extract.py` 转文本）不占 `file` 枚举。

> **统一字段 = `input_modalities` + `output_modalities` 两个正交维度**，枚举值同为 `{text, image, file, video, audio}`。全链路唯一，`pdf` 不再出现；`image_url`/`file` 是 wire part 传输形式，各司其职。

## 3. 统一方案（基础，要求 1/2）

### 3.1 后端：`_models_of` 修正断链（model_service）

`_models_of` 下发键 `capabilities` 应改为下发 **`input_modalities` + `output_modalities`**，并分别读 `meta.get("input_modalities")` / `meta.get("output_modalities")`。以下是 **补全后的完整函数**（基于本地 `model_service.py:257` 原实现 3.1 修正）：

```python
def _models_of(ai: Dict[str, Any], provider: str) -> List[Dict[str, Any]]:
    """已保存库 → 下发模型条目。能力位拆分 input/output 双维度（修断链，见 [14] §3.1）。"""
    p = ai.get(provider, {})
    raw_models = p.get("models") or [] if isinstance(p, dict) else []
    params_block = (p.get("model_params", {}) or {}) if isinstance(p, dict) else {}
    meta_block = (p.get("model_meta", {}) or {}) if isinstance(p, dict) else {}
    out: List[Dict[str, Any]] = []
    for m in raw_models:
        if not isinstance(m, str):
            m = str(m.get("name") or "") if isinstance(m, dict) else str(m)
        if not m or any(o["name"] == m for o in out):
            continue
        meta = (meta_block.get(m) or {}) if isinstance(meta_block, dict) else {}
        params = (params_block.get(m) or {}) if isinstance(params_block, dict) else {}
        out.append({
            "name": m,
            "label": str(meta.get("label") or m),
            "model_params": params,
            "range": meta.get("range") or {},
            # [14] 断链修正：capabilities 拆为 input_modalities + output_modalities，各自只读真源
            "input_modalities": meta.get("input_modalities") or [],
            "output_modalities": meta.get("output_modalities") or [],
            "param_options": _resolve_param_options(ai, provider, m, params, meta),
            "context_length": meta.get("context_length"),
            "max_output_length": meta.get("max_output_length"),
        })
    return out
```

> 改动点：原 `"capabilities": meta.get("capabilities") or []`（只读 capabilities → 断链）替换为上两行 `input_modalities` / `output_modalities`。其余字段、循环、去重逻辑与本地原实现逐字节一致，**只改能力位**，不触碰 context_length/param_options 等既有行为（KISS-DIRECT：问题在能力位断链，只修能力位）。

### 3.2 后端：`add_model` / `update_model` / `replace_provider_models` 字段白名单统一
把涉及能力写库的白名单从 `capabilities` 改为 **`input_modalities` + `output_modalities`** 双字段：
- `add_model` 的形参/落盘：`capabilities` → `input_modalities` + `output_modalities`（完整函数见下）。
- `update_model` / `replace_provider_models` 的 `LIST_FIELDS` 已含 `input_modalities`、`output_modalities`，保持；`capabilities` 从白名单移除。

**补全后的完整 `add_model`**（基于本地 `model_service.py:329` 原实现，能力落盘位 3.2 修改）：

```python
def add_model(provider: str, model: str, label: str = "",
              model_params: Optional[Dict[str, Any]] = None,
              range_: Optional[Dict[str, Any]] = None,
              input_modalities: Optional[List[str]] = None,
              output_modalities: Optional[List[str]] = None,
              param_options: Optional[Dict[str, List[str]]] = None) -> Dict[str, Any]:
    """新增模型到已保存库。能力位 input/output 双维度落盘（[14] §3.2）。

    与 update_model 同规则：选项表须为非空 string[]，值须在表内（小欧 2026-09-22）。
    """
    ai = _raw_ai()
    if provider not in _provider_names(ai):
        raise ValueError(f"Provider 不存在: {provider}")
    _raise_if_env_takeover(provider)
    if not model:
        raise ValueError("模型名不能为空")
    if any(m["name"] == model for m in _models_of(ai, provider)):
        raise ValueError("同名模型已存在")
    allowed = dict(param_options or {})
    for k, vs in allowed.items():
        if not isinstance(vs, list) or not vs or not all(isinstance(x, str) for x in vs):
            raise ValueError(f"不支持的选项表: {k}须为非空string[]")
    for k, v in (model_params or {}).items():
        allow = allowed.get(k, DEFAULT_PARAM_OPTIONS.get(k))
        if allow is not None and v not in allow:
            raise ValueError(f"不支持的配置项值: {k}={v!r}，允许{allow}")
    models = list(ai[provider].get("models", []) or [])
    if not all(isinstance(m, str) for m in models):
        models = [_m["name"] for _m in _models_of(ai, provider)]
    models.append(model)
    tree: Dict[str, Any] = {
        "ai": {provider: {
            "models": models,
            "model_params": {model: model_params or {}},
            "model_meta": {model: {
                "label": label or model,
                "range": range_ or {},
                "input_modalities": input_modalities or [],
                "output_modalities": output_modalities or [],
                **({"param_options": param_options} if param_options else {}),
            }},
        }}
    }
    merge_nested_patch(tree, scope="model")
    return {**get_models(), "ok": True, "mtime": _config_mtime()}
```

> 改动点：原形参 `capabilities: Optional[List[str]]` → `input_modalities` + `output_modalities` 两个；落盘 `"capabilities": capabilities or []` → `input_modalities or []` + `output_modalities or []`。其余 provider/校验/merge 逻辑与本地原实现逐字节一致（KISS-DIRECT：只改能力位双维度）。

### 3.3 后端：能力归并收口到 model_service（复用优先 / 迁移落地）

`_merge_supports_modalities` 已处理 Moonshot 布尔；**补 agnes/ZenFree 式老 `capabilities` 的一次性迁移**（在 config 写入/启动钩子执行，非双读）：

```python
def _merge_capabilities_into_modalities(modalities: List[str], capabilities: Any) -> List[str]:
    """agnes/ZenFree 老格式: capabilities:['text','image'] → 并入 input_modalities（迁移用, 一次性）。"""
    out = list(modalities)
    if isinstance(capabilities, list):
        for v in capabilities:
            if isinstance(v, str) and v not in out:
                out.append(v)
    return out
```

> **注意**：老 `capabilities` 是"能力"混排（image 可能是看图也可能是生图，video 同理），**不能直接机械并 input**——否则会把 agnes-image-* 的生图能力误标到 input，违背 §3.4.2 的双维度修正。因此迁移目标**必须以 §3.4.2 / §3.4.3 的手工标注表为准**（哪些模型标 input、哪些标 output），`_merge_capabilities_into_modalities` 只作为"把已判定的 input 值补充进 input"的兜底，不承载方向判定。

启动一次性迁移钩子（真实完整代码，启动时执行一次，两文件同构）：

```python
def _migrate_legacy_capabilities(config_path: Path) -> None:
    """启动一次性迁移：把老 capabilities 迁为 input/output 双维度，删 capabilities 键（[14] §3.3）。

    迁移表由 §3.4.2/§3.4.3 手工标注驱动（image / video 的方向已判定），
    capabilities 仅作为缺省补充源；此函数幂等，config 无 capabilities 时零改动。
    """
    raw = _read_yaml(config_path)                 # 读 config 为 dict
    ai = raw.get("ai") or {}
    changed = False
    for prov, p in (ai.items() if isinstance(ai, dict) else []):
        if not isinstance(p, dict):
            continue
        meta = p.get("model_meta") or {}
        if not isinstance(meta, dict):
            continue
        for mid, m in meta.items():
            if not isinstance(m, dict) or "capabilities" not in m:
                continue
            legacy = m.pop("capabilities")        # 删旧键，不留双字段
            # 缺省补充 input（方向已由手工标注表定，这里只并入遗留 text 等通用值）
            m["input_modalities"] = _merge_capabilities_into_modalities(
                m.get("input_modalities") or [], legacy)
            m.setdefault("output_modalities", []) # 显式建 output 维度
            changed = True
    if changed:
        _write_yaml(config_path, raw)             # 回写（config 与 example 各调一次）
```

迁移入口：`replace_provider_models` / `fetch_remote_models` 落盘前，以及 startup 对 `config/config.yaml` 与 `backend/config.yaml.example` 各调一次 `_migrate_legacy_capabilities`。全程只认新字段，无 capabilities 双读。

### 3.9 能力枚举的 wire 传输形式（与枚举各司其职，**input/output 双端点**）
枚举是"模型支持什么模态"，wire part 是"怎么传"。两者不混淆（承 §1.7/§1.8/§2.3）。

**input_modalities（理解输入，走 `/v1/chat/completions`）wire part：**

| 枚举值 | 含义 | wire 入参形式 |
|---|---|---|
| `text` | 文本 | `{"type":"text","text":...}` |
| `image` | 能**接收**图片（看图） | `{"type":"image_url","image_url":{"url":...}}`（URL 或 base64 data URI） |
| `file` | 能**接收**文档（PDF/Office） | `{"type":"file",...}`（与 `image` 独立，不混用） |
| `video` | 能接收视频 | `{"type":"video_url",...}` |
| `audio` | 能接收音频 | `{"type":"input_audio",...}` |

**output_modalities（生成输出，走独立生成端点）：**

| 枚举值 | 含义 | 端点 |
|---|---|---|
| `image` | 能**生成**图 | `/v1/images/generations`（如 `agnes-image-*`、`sensenova-u1.5-*`） |
| `video` | 能**生成**视频 | `/v1/videos`（如 `agnes-video-2.5*`，异步任务） |

- **S2 只做 input 的 `image` 模态**：wire 展开 `image_url` part（base64 data URI），即 `[10]` 蓝图 B18 的实现。
- `image_url` 不是枚举值，是 `image` 模态的发送方式；配置与前端枚举里**不加** `image_url` 值。
- `file` 表达"直接读文档"，与 S1 的 `extract.py` 间接转文本是**两套独立通道**，本设计统一枚举后，`file` 能力位单独表达直接支持，S1 间接支持不受影响。
- 生图/生视频（output）能力本设计**只统一标注**，**不实现生成请求**（S 系列后续另行设计生成通道）；S2 的 `supports_image_input` 只看 **input 维度**，不会误触发生图端点。

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-04 小欧 新建: 视觉通道(S2)唯一判定与 parts 生成 — 小欧-2026-11-04
# 2026-11-08 小欧 对照 [14] 字段统一: 能力判定只读 input_modalities(不碰 capabilities) — 小欧-2026-11-08

"""services.agent.vision — 视觉通道(S2, 图片类型阶段)。

设计边界:
  1. conversation_history **恒为 str**: 图片以 `[[IMAGE_ATTACHMENT:<id>]]` 占位入列,
     压缩/裁剪/持久化/回执全部零改动;
  2. 仅在 wire 边界(prepare_messages_for_llm)把占位展开成 OpenAI `image_url` parts;
  3. 能力判定只看模型配置 `input_modalities` 是否含 image(统一后唯一真源, 不写死模型名, 无 capabilities 分支);
  4. 展开失败(记录没了/图超限/读不出)退化为一行说明文字, 不阻断本轮;
  5. 生图/生视频(output)能力不参与判定: S2 只看 input 维度, 生图模型(input 无 image)不会被误判为看图。
"""
import asyncio
import base64
import re
from typing import Any, Dict, List, Optional, Tuple

from app.config import get_config
from app.logger import logger

IMAGE_SLOT_RE = re.compile(r"\[\[IMAGE_ATTACHMENT:([0-9a-f]{32})\]\]")
# 单图内联上限: base64 膨胀 4/3, 2MB 原图 → ~2.7MB 文本, 再大既慢又易撞窗口
VISION_INLINE_MAX_BYTES = 2 * 1024 * 1024

# 手动缓存(data URL 按 绝对路径+mime): 同一任务多轮 LLM 调用不重复 base64; 最多 8 张, 内存上限约 22MB。
# 不用 lru_cache: 异步读盘需 asyncio.to_thread 卸载事件循环, lru_cache 不支持异步函数 (Agnes 补)。
_data_url_cache: Dict[Tuple[str, str], str] = {}
_DATA_URL_MAX = 8


def supports_image_input(llm_model: Any) -> bool:
    """模型是否接受 image 入参（看图）。

    统一后唯一读 config.model_meta.input_modalities（[14] §3 字段统一），
    不再有 capabilities 分支；不写死模型名。走 chat/completions 的看图能力。
    """
    provider = getattr(llm_model, "provider", "") or ""
    model = getattr(llm_model, "model", "") or ""
    providers = get_config().get("providers") or {}
    meta = ((providers.get(provider) or {}).get("model_meta") or {}).get(model) or {}
    mods = meta.get("input_modalities") or []
    return isinstance(mods, list) and "image" in mods


def split_vision_refs(refs: Optional[list]) -> Tuple[list, list]:
    """(文本引用, 可内联图片引用)。只认 kind=attachment 且 mime=image/*。"""
    text_refs: List[Dict[str, Any]] = []
    image_refs: List[Dict[str, Any]] = []
    for r in refs or []:
        is_img = (r.get("kind") == "attachment"
                  and str(r.get("mime") or "").startswith("image/"))
        (image_refs if is_img else text_refs).append(r)
    return text_refs, image_refs


def image_slot(ref: Dict[str, Any]) -> str:
    """纯文本占位: 由 wire 层替换为 image part; 无 id 时退化为空(不产生坏锚)。"""
    aid = str(ref.get("attachment_id") or "")
    return f"[[IMAGE_ATTACHMENT:{aid}]]" if aid else ""


async def _data_url(stored_path: str, mime: str) -> str:
    """读图 + base64 编码, 经 asyncio.to_thread 卸载出事件循环(Agnes 补: 原同步 open 阻塞)。"""
    key = (stored_path, mime)
    cached = _data_url_cache.get(key)
    if cached:
        return cached
    def _read_and_encode() -> str:
        with open(stored_path, "rb") as fh:
            return f"data:{mime};base64,{base64.b64encode(fh.read()).decode('ascii')}"
    url = await asyncio.to_thread(_read_and_encode)
    if len(_data_url_cache) >= _DATA_URL_MAX:
        _data_url_cache.pop(next(iter(_data_url_cache)), None)  # 最旧淘汰
    _data_url_cache[key] = url
    return url


async def expand_image_slots(text: str) -> Any:
    """含占位 → OpenAI parts; 无占位原样返回 str(零退化)。"""
    if not IMAGE_SLOT_RE.search(text or ""):
        return text
    from app.attachments.attachment_service import get_attachment   # 延迟导入防循环

    parts: List[Dict[str, Any]] = []
    pending: List[str] = []
    cursor = 0

    def _flush() -> None:
        if pending:
            parts.append({"type": "text", "text": "".join(pending)})
            pending.clear()

    for m in IMAGE_SLOT_RE.finditer(text):
        pending.append(text[cursor:m.start()])
        att = get_attachment(m.group(1))
        reason = ""
        if not att:
            reason = "附件记录已失效"
        elif int(att.get("size") or 0) > VISION_INLINE_MAX_BYTES:
            reason = f"图片超过 {VISION_INLINE_MAX_BYTES // (1024 * 1024)}MB 未随消息发送"
        else:
            try:
                url = await _data_url(att["stored_path"], att.get("mime") or "image/png")
            except OSError as e:
                logger.warning(f"[vision] 读图失败 id={m.group(1)} err={e}")
                reason = "图片文件不可读"
            else:
                _flush()
                parts.append({"type": "image_url", "image_url": {"url": url}})
        if reason:
            name = att.get("original_name") if att else m.group(1)
            pending.append(f"[图片附件未内联: {name} — {reason}]\n")
        cursor = m.end()
    pending.append(text[cursor:])
    _flush()
    return parts
```
