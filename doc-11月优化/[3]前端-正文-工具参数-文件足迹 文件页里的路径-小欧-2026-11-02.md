## 一、现状概述

当前实现是四层结构，每层只有一个实现点，职责与边界如下：

| 层 | 唯一实现 | 职责 | 边界 |
|----|---------|------|------|
| 取根 | `hooks/useProjectRoot.ts` 的 `fetchProjectRoot()` | 实时向 `/api/v1/files/root` 取当前项目根 | 不缓存结果（只合并同刻在途请求）、不猜根 |
| 判据 | `utils/projectPath.ts` 的 `resolvePathTarget()` | 形态校验、内外归属、目录/文件判定、URL 拼装 | 零 import（无 React、无网络），不发请求、不碰 React |
| UI | `components/PathLink.tsx` | 渲染 chip / inline 两形态、徽标、tooltip、键盘可达 | 不做任何路径判定 |
| 入口 | 正文、工具参数、产出物清单、文件足迹、上下文包、文件页 | 调用上面三者 | 不各自拼 URL、不各自判内外 |

三个结构性约束当前全部成立：

1. 判定只有一个函数：所有路径的「文件/目录、根内/根外」归属只由 `resolvePathTarget` 一处给出。
2. 渲染只有一个组件：所有链接只由 `components/PathLink.tsx` 渲染。
3. 点击只有一个口径：判不过不跳，跳转统一带 `{ state: { internal: true } }`。

历史上前端曾有 7 套链接/判定实现、10 处自建判据，现已全部收敛到上表的唯一实现点；被删除的旧实现清单见第十章。

## 二、路径解析（当前唯一实现）

### 2.1 解析函数 `resolvePathTarget`

路径判据全部集中在 `src/utils/projectPath.ts`，对外只暴露这一个解析函数：

```
resolvePathTarget(rawPath, root, opts?: { dirHint?, lineRange?, strictShape? })
  → { linked, rel, url, isDir, isExternal, pending, reason? }
```

返回的 7 个字段就是全部结论，当前各字段的判定口径：

| 输出 | 当前判据 |
|------|---------|
| `isExternal` | 形态成立 且 `isDriveAbsPath(raw)` 且 `toRelativePath(raw, root) === null`（`''` = 等于根 → 根内） |
| `isDir` | `isDirPath(raw)` ∪（非 strictShape）`isAbsDirLikePath(raw)` ∪ `dirHint` |
| `rel` | `toRelativePath(raw, root)`；`''`（等于根）折成 null |
| `linked` | `rel` 非 null（形态校验已在 `relFromRoot` 单点完成）且（`isLinkableRelPath(rel)` 或 `isDir`） |
| `url` | 根外：目录补尾 `/` 走 `ext=1`，文件走 `ext=1`；根内：`/files?path=<rel>` |
| `pending` | `isDriveAbsPath(raw) && !root`：归属未定，调用方等根重算，不得当「找不到」报错 |
| `reason` | 仅 `linked=false` 时给出（Tooltip 直接显示，调用方不得二次猜原因） |

### 2.2 取根入口与点击入口

当前只有两个入口函数，都在 `src/hooks/useProjectRoot.ts`：

- **点击入口**：`resolveChipUrlFresh(raw, lineRange?, opts?)`，内部先 `await fetchProjectRoot()`，再调 `resolvePathTarget`。
- **取根入口**：`fetchProjectRoot()`，实时打 `/files/root`，结果不缓存，同刻在途请求合并；设置保存后由 `invalidateProjectRoot()` 发信号。

`utils/projectPath.ts` 本身零 import，取根与 React 订阅全部在 hook 层。

## 三、目录判定规则（当前 4 条，按顺序）

四条按顺序短路，命中即止：

| # | 条件 | 结论 | 备注 |
|---|------|------|------|
| 1 | 以 `\` 或 `/` 结尾 | 目录 | 最可靠信号 |
| 2 | 盘符绝对 + 无扩展名 + 无尾分隔符（`F:\a\b`） | 目录 | 仅正文/文件页（宽松）；工具参数 `strictShape` 不认 |
| 3 | 工具声明该参数必为目录（`dirHint`：listdir/tree/find） | 目录 | 「路径 == 项目根」时不生效 |
| 4 | 以上都不满足 | 文件 | 带扩展名按文件 |

## 四、目录与特殊路径的当前处理结果（5 场景）

判定为目录之后，当前按「根内 / 根外 / 等于根 / 根未取回 / 根内裸名」五种情形处理：

| 场景 | `isExternal` | `linked` | 生成的 URL |
|------|--------------|----------|-------------|
| 根内目录 `E:\root\sub` | false | true | `/files?path=sub`（目录不带行号） |
| 根外目录 `F:\x\y` | true | true | `/files?ext=1&path=F%3A%5Cx%5Cy%2F`（补尾 `/`） |
| 路径 == 项目根 | false | false | 不生成链接（避免把根挂成外部树） |
| 根未取回 + 盘符绝对 | — | false | 不生成链接（归属未定，等根） |
| 根内裸名 `src`（无分隔符无扩展名） | false | 仅 `dirHint` 时 true | `/files?path=src` |

## 六、链接组件 PathLink（当前）

链接 UI 当前只有 `src/components/PathLink.tsx`，支持 chip / inline 两形态，含徽标、tooltip、键盘可达。

当前行为约定：

- 该组件**不做任何路径判定**：渲染态判据来自 `resolvePathTarget`，点击态来自 `resolveChipUrlFresh`。
- 文案即 `rawPath`，没有 `text` 入参。
- 别针：`pin` 开关（默认关，仅正文 chip 传）在「已链接且非目录」时并列渲染 `QuoteButton`，可见性用同一次解析结果判定。
- 产出物清单的引用按钮由业务层并列渲染（`StaticStatsBlock` 自己在 `<PathLink>` 后另放 `<QuoteButton>`），组件本身没有 `after` 插槽。

组件内部对 `features/refs/QuoteButton` 只有一条依赖（为 `pin` 服务）；引用实现仍在 `features/refs`（`quote.ts` 是唯一实现）。`pin` 默认关闭，参数面板 / 产出物清单 / 文件足迹 / 设置页的链接不经过这条依赖路径。

## 七、点击口径（当前唯一）

当前三处调用方统一写法：

```ts
const url = resolvePathTarget(raw, root, opts).url;   // 或 await resolveChipUrlFresh(...)
if (url) nav(url);                                    // 空串 = 形态非法/归属未定 → 不跳空链
```

- `resolveChipUrlFresh` 当前不带任何兜底深链（旧实现 `|| buildFileDeepLink(...)` 已删除）：判不过就是空串，调用方 `if (url)` 不跳。
- 所有跳转统一带 `{ state: { internal: true } }`（文件页据此清外部预览态）。
- 无 Router 环境由 `useOptionalNavigate(to, options?)` 处理：有 Router 走 SPA，无则整页跳。

### 8.2 模块内单点（当前写法）

`utils/projectPath.ts` 当前靠以下私有单点消除模块内重复：

| 单点 | 当前服务的位置 |
|------|--------------|
| `EXT_MAX = 10` | 生成 `HAS_EXT_RE` / `PATH_EXT` / `EXT_ANCHOR_SRC` / `LAST_SEGMENT_FILE_RE` 四个正则的扩展名长度上限 |
| `ENDS_WITH_SEP_RE = /[\\/]+$/` | `isDirPath`、`isFileLikePath`、`withDirTail` |

| `relFromRoot(p, root)` | `toRelativePath` 的根内切片；形态校验只在这一处做 |
| `relSegments()` | `toRelativePath` / `toAbsolutePath` 共用的「滤段 + 拒 `..`」 |

| `spacedPath(run)` | 正文识别的「切段 → `resolveAbsCand` → `trimCjkGlue`」 |

三套扩展名正则当前语义不同、各有用途（非重复）：末段判断须字母开头（排版本号 `1.2.3`）；`EXT_ANCHOR_SRC` 取 run 内末个锚；形态判据字母数字均可；长度上限统一由 `EXT_MAX` 生成。`MarkdownBody` 的 `FILEREF_MD_RE` 只圈 markdown 链接结构（切段用），`parseFileRefLink` 只解 href 参数，两者职责不同。
