## 一、背景与实证

### 1.1 问题定位（用户四问）

设置页②区对 `agnes-image-2.1-flash` 实测显示「输入图片能力验证 ✗」，用户先后追问：

1. 这模型应该"可以支持"吧？——判 X 是不是探测腿的问题？
2. 是不是要用厂家特殊端点 `/v1/images/generations`（图）、`/v1/videos`（视频）？
3. 请求体是不是厂家独特的？
4. 厂商文档说明 image 模型支持 URL 图片输入（图生图）、输出支持 base64 或 URL；video 的输入方式不明——与"输入图片能力 X"的实测结论对不上。

### 1.2 实证一：输入侧（chat/completions 腿，2026-11-09 真机）

| 实验 | 结果 |
|------|------|
| chat/completions 探测腿打生成模型 | HTTP 400，厂商原话点名专用端点：`模型 agnes-image-2.1-flash 为 image 模型，请使用 /v1/images/generations`；`agnes-video-2.5 为 video 模型，请使用 /v1/videos` |
| config.yaml 既有 probe 记录 | 三个生成模型 `media.accept.image=none`，evidence 即上述 400 原文（inline=url 腿全拒） |

### 1.3 实证二：生成专用端点（images / videos 协议全景，2026-11-09 真机）

| 实验 | 结果 |
|------|------|
| `POST /v1/images/generations` 空体 | 404（缺省解析成 dall-e —— 网关按路由分发） |
| `POST /v1/images/generations` `{model, prompt}` 最小体 | **HTTP 200**：`data[0].url`（COS 公网真图）+ `b64_json`（本次空串占位）+ `revised_prompt` + `created` + 顶层 `task_id` |
| 产物图 HEAD | HTTP 200，image/png，224111 字节——t2i（文生图）闭环 |
| `POST /v1/images/generations` `{model, prompt, image:<COS URL>}` | **HTTP 200**，任务路径 `/images/i2i/`（图生图）；产物白底**蓝点**（输入红点图 + prompt"改蓝点"内容级目检）——模型真实消费输入图 |
| 同体改 `image_url` 参数 | 400 `image_url 不是本线路图生图支持的字段` —— 图生图参数名是 **`image`**，不是 chat 腿的 `image_url` |
| `POST /v1/videos` 空体 | 400 `未指定模型名称` |
| `POST /v1/videos` `{model}` 缺 prompt | 400 `prompt 不能为空`，结构化 `data.param=prompt` —— t2v（文生视频）prompt 必填 |
| `POST /v1/videos` `{model, prompt, image:123}`（类型错值） | 400 `image 必须是字符串`——`image` 是字符串型字段，但它是**首帧别名**：`mode:"text"` 带它被拒（"text 模式不能包含素材字段"），`mode:"reference"` 带它被拒（"reference 模式不能包含 first_frame 或 last_frame"）→ 图生视频只能用 `images` 数组 |
| `POST /v1/videos` `{model, prompt, image_url:123}` | 400 不支持字段 → 视频腿无 `image_url` |
| `POST /v1/videos` `{model, prompt, duration:"abc"}` | 400 不支持字段 → 视频腿无 `duration` |
| `GET /v1/videos/{task_id}`（假 id） | 400 `task_not_exist` → **异步轮询端点确认**：`GET /v1/videos/{task_id}` |
| `POST /v1/videos` 缺 `mode` | 400 `mode 不能为空`（`data.param=mode`）——`mode` 必填 |
| `mode` 枚举（30+ 候选；用 `size` 错值挡真实生成，只探校验） | 合法值仅 **`text`**（纯文生视频）与 **`reference`**（带参考图）；`t2v`/`i2v`/`image`/`image2video`/分辨率/时长等一律 400 `mode 无效` |
| `mode:"text"` + `first_frame` | 400 `text 模式不能包含素材字段`（`data.param=first_frame`）——素材字段与 mode 互斥 |
| `mode:"reference"` + `images:[公网图]` | 提交 200（`task_id`/`video_id`）——图生视频的素材字段是 `images`（数组），传 `image`/`first_frame` 被 400 拒 |
| 队列满 | 503 `video_queue_full`（账号级拥堵，非模型问题） |
| 真实 t2v 全链路（真机，两次） | 提交 200 → `queued`（≈250s）→ `in_progress`（progress 10→100）→ `completed`；直连脚本 **402s**、设置页「生成验证」端到端 **380s**；产物在 **`metadata.url`**：`https://cos-platform-outputs.agnes-ai.cn/videos/agnes-video-2.5/task_*.mp4` |
| 真实 i2v 全链路（`mode:"reference"` + `images:[人民网 jpg]`） | 提交 200（task_id）→ 轮询 437s 后 `status=failed`，响应无原因字段 → 判**未定**（不据此断定无 i2v 能力）；换厂商 COS 图源复测见 §5.2 |

> 注：videos 早期只做参数探测；v1.6 已补真实生成实证（t2v 402s 出片、`metadata.url` 取产物、`mode` 枚举仅两值）。视频产物**计费**仍未在账单侧核对，探测按最低档（5s / 720P / flash）发一次。

### 1.4 全景结论（本设计的立论点）

**输入侧全景**：

| 模型 | chat/completions 多模态输入（设置页现有验证腿） | 生成端点图片输入 |
|------|------|------|
| agnes-2.5-flash / pro / 3.0-flash | both（inline+URL，实证 OK） | 不适用（text 模型） |
| agnes-image-2.1-flash | **X（400 点名专用端点）** | **✓ `image` 参数（i2i，200 + 内容级实证）** |
| agnes-video-2.5(/-flash) | **X（400 点名专用端点）** | ✓ `mode:"reference"` + `images:[URL]`（图生视频）+ `prompt`（t2v 必填），已实证提交走通 |

**三条立论**：

1. `model_meta.media.accept.image=none` 的语义是「**chat 腿不吃图**」——对生成模型判 X 是这条腿下的正确事实，输入验证腿没有坏；但**它不等于"模型无图片输入能力"**：图生图（i2i）输入在 `/v1/images/generations` 的 `image` 参数里，已真机实证。
2. **输出侧至今没有实测腿**：设置页②输出模态徽标是纯声明展示（v1.6.6 定版），"能不能真生成"从未在页面上验证过；请求体并无厂家独特之处（OpenAI Images 兼容风格，`{model, prompt}` 最小体即工作），仅响应多了 agnes 自有 `task_id`、错误信封两腿不同。
3. **现有 LLM 主链（agent_runner→chat/completions）走不到生成端点**——这是 `output_modalities` 无业务消费的结构性原因，生图/生视频落地必须新建输出通道，且必须与验证腿共用同一调用点（→ 第三章架构）。

**视频异步链**（已实证落地）：提交 `POST /v1/videos`（`mode` 必填，合法值仅 `text`/`reference`；图生视频带 `images:[URL]`）→ 响应 `{task_id, video_id, status:"queued", progress}` → 轮询 `GET /v1/videos/{task_id}`（`queued`→`in_progress`→`completed`）→ 终态取 `metadata.url`（`.mp4` 公网直链）。真机单次 402s（排队≈250s + 出片≈150s），队列满返回 503 `video_queue_full`。

## 二、设计目标与边界

| 目标 | 说明 |
|------|------|
| **本期（Phase A）** | 设置页②区新增「生成能力验证」一行：按模型声明的输出模态真调生成端点——image 跑 t2i+i2i，video 跑 t2v+i2v（异步提交+轮询），**输入与输出一并验证**，落库 `model_meta.media.generate.{image,video}`；同时重构②区生成模型行的错误显示（「内联X/输入能力X」→ 置灰「不适用」） |
| **基石（共有点）** | 生成调用收敛**单点 `generation_client`**：探测腿与未来真生图/生视频业务打同一个函数，禁止第二套调用代码 |
| **非目标（YAGNI）** | 不做会话内生图/生视频编排、产物入库、视频产物前端 Viewer |

## 三、总体架构（共有优先）

```
                      ┌─ probe_output (model_service) ──→ 设置页②「生成能力验证」
generation_client ────┤      generate_image（图腿，同步）
(唯一生成调用点)      └─ 未来业务通道 (Phase B): 会话生图工具 / 产物转发 ──→ chat 链
       │               generate_video（视频腿，异步 submit→poll）
       ├─ 协议常量单源: IMAGE_PATH=/images/generations  VIDEO_PATH=/videos
       │                REJECT_STATUS={400,415,422}（输入腿 _probe_once 同取此常量）
       ├─ 探测素材单源: PROBE_PROMPT / PROBE_I2I_PROMPT / PROBE_IMAGE_URL
       │                PROBE_VIDEO_PROMPT / PROBE_VIDEO_I2V_PROMPT
       │   （i2i/i2v 图源=公网位图直链；输入腿用 8×8 内联 png，两侧素材互不借用）
       ├─ 视频枚举单源: VIDEO_MODE_T2V="text" / VIDEO_MODE_I2V="reference"
       │                VIDEO_POLL_INTERVAL/VIDEO_POLL_TIMEOUT/VIDEO_QUEUE_RETRIES
       ├─ 端点分派: get_provider_adapter(name).generation_paths() 可选钩子
       │   （默认 OpenAI 兼容常量；厂家漂移时改 adapter，不动 client——OCP）
       └─ 返回归一: (ok, evidence≤160, settled) 三元组
            · 探测只回答"能不能生成"，不持有产物；产物 url/b64 由 Phase B 扩出参带走（§5.1 末行 / §5.2 登记）
```

**三条共有单向法则**：

1. **同一函数**：`generate_image()` / `generate_video()` 是探测与业务共用的唯一 HTTP 调用点（探测=业务通道的零成本子集，probe 只是参数更瘦；图生图=同一函数加可选 `image` 参数即达）。"同一函数"指同一个 HTTP 出口，不指同一份返回值：探测要三态判定、业务要产物，出参差异在 Phase B 以扩展方式解决。
2. **同一次持久化**：探测结果与未来产物元数据都落 `model_meta.<model>.media` 树（`merge_nested_patch` 深 merge，input 块不受影响）。
3. **同一展示体系**：②区徽标/tooltip 现有分层（输入验证 tip 已有耗时/token 分段），输出实测行挂同一 tooltip 机制，不新做浮层。

## 四、Phase A —— 设置页「生成验证」（本期落点）

### 4.1 后端：生成调用单点 `app/services/generation/generation_client.py`（新建）

```python
# 端点协议常量（OpenAI Images 兼容默认值；厂家漂移改 provider adapter 钩子，不改本文件）
IMAGE_PATH = "/images/generations"
VIDEO_PATH = "/videos"

# 厂商明确拒绝状态集：单源常量，输入腿 _probe_once 与本文件共用这一份（不再各写一份）
REJECT_STATUS = frozenset({400, 415, 422})

# 探测 prompt 常量（真机实证：一次一图、语句极短、确定性图形，成本最低）
PROBE_PROMPT = "一个红色圆点，白色背景"
# 生成腿探测图源（i2i 图片输入 / i2v 参考图）：公网位图直链，禁 ico/短链/鉴权地址
PROBE_IMAGE_URL = "https://www.people.com.cn/img/2020peopleindex/img/2024tp/rmwj.jpg"
PROBE_I2I_PROMPT = "把图片主色调改为蓝色"

async def generate_image(api_base: str, headers: Dict[str, str], model: str, prompt: str,
                         *, image: Optional[str] = None, timeout: float = 120.0
                         ) -> Tuple[bool, str, bool]      # (产物成功?, evidence≤160, 结论是否确定)

# 职责边界（SRP）：client 只懂协议——不读配置树、不查 key、不拼 provider 名。
#   取值链（env {NAME}_API_KEY → config ai.{p}.api_key）、静态头、超时仍留在 model_service
#   （与 probe_model_media 同处），算好后由调用方传入 api_base/headers。
# POST {api_base}{IMAGE_PATH}  body={"model": model, "prompt": prompt}（image 非空时补 "image"）
# 判定 settled：200 且 data[0].url / b64_json 非空=OK；200 无产物=确定无；
#   400/415/422=明确拒绝；401/403/429/5xx/网络错=未定（与输入腿 _probe_once 同 settled 语义，不误写结论）
# evidence 成功/失败两侧一律截短 160 字符（完整产物 URL 不在此处持有，见 §5.2）
```

视频腿（`generate_video`，异步 submit→poll）：

```python
async def generate_video(api_base, headers, model, prompt, mode, *,
                         images: Optional[List[str]] = None,
                         timeout: float = 120.0, poll_timeout: float = 600.0
                         ) -> Tuple[bool, str, bool]

# body: {"model","prompt","mode"}; images 非空时补 "images": [url...]
# POST {api_base}/videos → task_id/video_id；每 5s GET /videos/{task_id} 直到终态
# 终态 completed/succeeded/success → 取 metadata.url（递归找 video 键 / .mp4 直链）
# settled：有产物=OK；failed/error 或 400·415·422=确定拒绝；
#   队列满（503 video_queue_full）/轮询超时/网络错/轮询非 200/终态无产物地址 = 未定
# 队列满是账号级拥堵：提交重试 3 次、间隔 30s 后才记未完成
# mode 枚举真机实证仅 {text, reference}：text=纯文生、reference=带参考图（素材走 images）
```

### 4.2 后端：探测路由 `model_service.probe_output(name, model)`

- 路由：`POST /api/v1/providers/{name}/models/{model:path}/probe-output`（model_routes.py，与 probe-media 相邻注册）
- 流程：校验 provider/model 在配置内（复用 `_require_provider_for_fetch` 同款前置）→ 读 `model_meta.{model}.output_modalities` → **既不含 `image` 也不含 `video` 直接 400**（后端闸门，与前端按钮同口径：前端不渲染的，后端也拒）→ 按声明依次跑对应腿：
  1. 图腿（含 image）：`generate_image(api_base, headers, model, PROBE_PROMPT)` —— t2i，验证**文本输入→图片输出**
  2. 图腿第二枪：`generate_image(..., PROBE_I2I_PROMPT, image=PROBE_IMAGE_URL)` —— i2i，验证**URL 图片输入→图片输出**（**仅当 t2i 取证且成功**才打第二枪，否则记 skipped）
  3. 视频腿（含 video）：`generate_video(..., PROBE_VIDEO_PROMPT, VIDEO_MODE_T2V)` —— t2v，异步等出片
  4. 视频腿第二枪：`generate_video(..., PROBE_VIDEO_I2V_PROMPT, VIDEO_MODE_I2V, images=[PROBE_IMAGE_URL])` —— i2v（**仅当 t2v 取证且成功**才打第二枪）
  → 组装双腿结果；一次点击 2~4 次调用，图腿费用≈2 张小图，视频腿=最低档 5s/720P

- **持久化 schema（model_meta 深合并，不触碰 input 块）**：

```yaml
model_meta:
  agnes-image-2.1-flash:
    media:
      # ……既有 accept/probed_at/…（输入/chat 腿记录，不动）……
      generate:                    # ← 新增分支（按输出模态二选一或并存）
        image:                     # 图腿，每腿同款结构
          t2i:                     # 文生图（文本输入→图片输出）
            state: ok              # ok / none / unverified / skipped
            ms: 348                # 单腿耗时（单调钟；视频腿含排队+出片）
            evidence: 'url=https://cos-.../output.png'   # 成功腿同截 160 字符
            at: '2026-11-09T13:30:00'
          i2i:                     # 图生图（URL 图片输入→图片输出）
            state: ok
            ms: 402
            evidence: 'url=https://cos-.../i2i.png'
            at: '2026-11-09T13:30:05'
  agnes-video-2.5-flash:
    media:
      generate:
        video:                     # 视频腿（异步任务）
          t2v:                     # 文生视频（mode=text）
            state: ok
            ms: 402000             # 真机 402s（排队≈250s + 出片≈150s）
            evidence: 'url=https://cos-platform-outputs.agnes-ai.cn/videos/.../*.mp4'
            at: '2026-11-09T15:10:00'
          i2v:                     # 图生视频（mode=reference + images）
            state: ok
            ms: ...
```

- **分组落库**：`image` / `video` 两组各自独立——某组首条腿已取证就落该组，另一组超时/排队不连坐（`settled_groups` 只含已取证组）；全组未取证时**完全不写盘**，原记录不动。

- 响应：`{ok, provider, model, generate, conclusive, persisted, message}`；`generate` 即上面落库的同构块（含未取证组，前端不二次解析 evidence）；`conclusive` = **无未定腿**（`skipped` 不计，含「首腿被拒→次腿未发」这类确定结论）；message 口径与输入腿同款短句（验证通过 / 可文生图；文生视频未完成（厂商视频队列已满，稍后重试））。

### 4.3 前端：②区语义重构（生成模型处置 + 「生成验证」按钮）

**判定基线**：`生成模型 = output_modalities 含 image 或 video`；`chat 腿验证行仅在 input_modalities 含 image 时有意义`。两句合成**唯一谓词** `chatLegMuted = 生成模型 && !input_modalities 含 image`，全章与代码同用此谓词（置灰、隐藏按钮、换 tooltip 三处一个来源，避免"重叠型模型"被误判）。数据层零改动（`accept=none` 照旧记录），全部为展示语义。

| 文件 | 改动 |
|------|------|
| `services/api/model.api.ts` | +`probeOutput(provider, model)`（镜像 probeMedia 签名，显式 30 分钟超时——视频腿串行最坏可上探 23 分钟）；`MediaProbe` interface 扩 `generate?: { image?: {t2i?,i2i?}; video?: {t2v?,i2v?} }` |
| `SettingsPage.tsx` 输入图片能力验证行 | `chatLegMuted` 为真：内联/URL/判定词徽标全部**置灰「不适用」**（新增 `na` 态：灰底无图标、不显红✗）；「验证」按钮**不渲染**（非 disabled）；tooltip 固定口径："该模型为生成模型：图片输入/输出走生成专用端点，chat 腿 400 为预期现象"。chat 多模态模型与重叠型模型：现状 3 态不变 |
| `SettingsPage.tsx` 生成能力验证行（独立一行，与输入行同语法） | 腿徽标按输出模态派生：image → 文生图／图生图，video → 文生视频／图生视频；**结论词直接上界面**（可用／部分可用／不可用／未完成／未验证），悬停只补逐腿耗时与验证时间；行尾「生成验证」按钮 |

```python
async def probe_model_output(name: str, model: str) -> Dict[str, Any]:
    """生成验证（[15] Phase A）：t2i+i2i 双枪验证输入与输出，落 media.generate.image  - 小欧-2026-11-09

    复用三级取值链（env→config）/ adapter 静态头 / _persist_media_probe 深合并
    （merge_nested_patch 按叶子路径写盘，accept 等输入腿字段物理不可被触碰）；
    evidence 口径与 _probe_once 同源，message 复用 _probe_hint 短语。
    闸门：只在模型声明 image 输出时执行——与设置页按钮条件同口径，前端不显示的这里也拒。
    """
    ai = _raw_ai()
    p, api_base = _require_provider_for_fetch(name, ai)
    configured = [m for m in (p.get("models") or []) if isinstance(m, str)]
    if model not in configured:
        raise HTTPException(status_code=404, detail=f"模型 {model} 不在 provider {name} 的 models 列表")
    meta = p.get("model_meta") or {}
    outs = ((meta.get(model) or {}).get("output_modalities") or []) if isinstance(meta, dict) else []
    if "image" not in outs:
        raise HTTPException(status_code=400, detail=f"模型 {model} 未声明 image 输出，无生成验证腿")
    api_key = os.environ.get(f"{name.upper()}_API_KEY") or str(p.get("api_key") or "")
    headers = get_provider_adapter(name).static_headers(api_key)
    timeout = float(p.get("timeout") or 60)

    async def _probe_leg(prompt: str, image: Optional[str] = None) -> Tuple[Dict[str, Any], bool]:
        t0 = time.monotonic()
        ok, ev, settled = await generation_client.generate_image(
            api_base, headers, model, prompt, image=image, timeout=timeout
        )
        rec = {
            "state": "ok" if ok else ("none" if settled else "unverified"),
            "ms": int((time.monotonic() - t0) * 1000),
            "evidence": ev,
            "at": datetime.now().isoformat(timespec="seconds"),
        }
        return rec, settled

    t2i, t2i_settled = await _probe_leg(generation_client.PROBE_PROMPT)
    # 图源=generation_client.PROBE_IMAGE_URL(生成腿专用公网位图, 与输入腿素材解耦); t2i 未取证或未成功不打第二枪
    if t2i_settled and t2i["state"] == "ok":
        i2i, _ = await _probe_leg(
            generation_client.PROBE_I2I_PROMPT, image=generation_client.PROBE_IMAGE_URL
        )
    else:
        i2i = {"state": "skipped", "evidence": "", "at": datetime.now().isoformat(timespec="seconds")}
    generate = {"image": {"t2i": t2i, "i2i": i2i}}
    persisted = _persist_media_probe(name, model, {"generate": generate}) if t2i_settled else False
    if not t2i_settled:
```
