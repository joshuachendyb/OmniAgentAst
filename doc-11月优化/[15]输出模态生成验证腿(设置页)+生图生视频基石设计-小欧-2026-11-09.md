## 一、背景与实证

### 1.1 问题定位（用户四问）

设置页②区对 `agnes-image-2.1-flash` 实测显示「输入图片能力验证 ✗」，用户先后追问：

1. 这模型应该"可以支持"吧？——判 X 是不是探测腿的问题？
2. 是不是要用厂家特殊端点 `/v1/images/generations`（图）、`/v1/videos`（视频）？
3. 请求体是不是厂家独特的？
4. 厂商文档说明 image 模型支持 URL 图片输入（图生图）、输出支持 base64 或 URL；video 的输入方式不明——与"输入图片能力 X"的实测结论对不上。

### 1.2 实证一：输入侧（chat/completions 腿，2026-11-09 真机）

| 实验 | 结果 |
|------|------|
| chat/completions 探测腿打生成模型 | HTTP 400，厂商原话点名专用端点：`模型 agnes-image-2.1-flash 为 image 模型，请使用 /v1/images/generations`；`agnes-video-2.5 为 video 模型，请使用 /v1/videos` |
| config.yaml 既有 probe 记录 | 三个生成模型 `media.accept.image=none`，evidence 即上述 400 原文（inline=url 腿全拒） |

### 1.3 实证二：生成专用端点（images / videos 协议全景，2026-11-09 真机）

| 实验 | 结果 |
|------|------|
| `POST /v1/images/generations` 空体 | 404（缺省解析成 dall-e —— 网关按路由分发） |
| `POST /v1/images/generations` `{model, prompt}` 最小体 | **HTTP 200**：`data[0].url`（COS 公网真图）+ `b64_json`（本次空串占位）+ `revised_prompt` + `created` + 顶层 `task_id` |
| 产物图 HEAD | HTTP 200，image/png，224111 字节——t2i（文生图）闭环 |
| `POST /v1/images/generations` `{model, prompt, image:<COS URL>}` | **HTTP 200**，任务路径 `/images/i2i/`（图生图）；产物白底**蓝点**（输入红点图 + prompt"改蓝点"内容级目检）——模型真实消费输入图 |
| 同体改 `image_url` 参数 | 400 `image_url 不是本线路图生图支持的字段` —— 图生图参数名是 **`image`**，不是 chat 腿的 `image_url` |
| `POST /v1/videos` 空体 | 400 `未指定模型名称` |
| `POST /v1/videos` `{model}` 缺 prompt | 400 `prompt 不能为空`，结构化 `data.param=prompt` —— t2v（文生视频）prompt 必填 |
| `POST /v1/videos` `{model, prompt, image:123}`（类型错值） | 400 `image 必须是字符串`（报"类型错"非"不支持字段"）→ **存在 `image` 字段**（i2v 图生视频首帧 URL），与 images 腿同名 |
| `POST /v1/videos` `{model, prompt, image_url:123}` | 400 不支持字段 → 视频腿无 `image_url` |
| `POST /v1/videos` `{model, prompt, duration:"abc"}` | 400 不支持字段 → 视频腿无 `duration` |
| `GET /v1/videos/{task_id}`（假 id） | 400 `task_not_exist` → **异步轮询端点确认**：`GET /v1/videos/{task_id}` |

> 注：videos 全部为参数探测（错值触发校验拒绝，未启动真实生成）；图像探测含 3 次真实生成（每张成本极低，已实证可行）。视频产物结算形态与计费**未实测**（启动一次真实视频生成需用户授权）。

### 1.4 全景结论（本设计的立论点）

**输入侧全景**：

| 模型 | chat/completions 多模态输入（设置页现有验证腿） | 生成端点图片输入 |
|------|------|------|
| agnes-2.5-flash / pro / 3.0-flash | both（inline+URL，实证 OK） | 不适用（text 模型） |
| agnes-image-2.1-flash | **X（400 点名专用端点）** | **✓ `image` 参数（i2i，200 + 内容级实证）** |
| agnes-video-2.5(/-flash) | **X（400 点名专用端点）** | ✓ `image`（i2v 首帧）+ `prompt`（t2v 必填），字段存在实证 |

**三条立论**：

1. `model_meta.media.accept.image=none` 的语义是「**chat 腿不吃图**」——对生成模型判 X 是这条腿下的正确事实，输入验证腿没有坏；但**它不等于"模型无图片输入能力"**：图生图（i2i）输入在 `/v1/images/generations` 的 `image` 参数里，已真机实证。
2. **输出侧至今没有实测腿**：设置页②输出模态徽标是纯声明展示（v1.6.6 定版），"能不能真生成"从未在页面上验证过；请求体并无厂家独特之处（OpenAI Images 兼容风格，`{model, prompt}` 最小体即工作），仅响应多了 agnes 自有 `task_id`、错误信封两腿不同。
3. **现有 LLM 主链（agent_runner→chat/completions）走不到生成端点**——这是 `output_modalities` 无业务消费的结构性原因，生图/生视频落地必须新建输出通道，且必须与验证腿共用同一调用点（→ 第三章架构）。

**视频异步链**（协议已探明，实现挂 Phase B）：提交 `POST /v1/videos` → 返回 `task_id` → 轮询 `GET /v1/videos/{task_id}` → 结算拿视频产物 URL。

## 二、设计目标与边界

| 目标 | 说明 |
|------|------|
| **本期（Phase A）** | 设置页②区新增「生成验证」：对声明了 image 输出的模型，一键双枪（t2i+i2i）真调生成端点，**输入与输出一并验证**，落库 `model_meta.media.generate.image`；同时重构②区生成模型行的错误显示（「内联X/输入能力X」→ 置灰「不适用」） |
| **基石（共有点）** | 生成调用收敛**单点 `generation_client`**：探测腿与未来真生图/生视频业务打同一个函数，禁止第二套调用代码 |
| **非目标（YAGNI）** | 不做会话内生图编排、产物入库、视频自动验证腿、视频异步轮询前端 Viewer |

## 三、总体架构（共有优先）

```
                      ┌─ probe_output (Phase A, model_service) ──→ 设置页②验证按钮
generation_client ────┤
(唯一生成调用点)      └─ 未来业务通道 (Phase B): 会话生图工具 / 产物转发 ──→ chat 链
       │
       ├─ 协议常量单源: IMAGE_PATH=/images/generations  VIDEO_PATH=/videos
       │                REJECT_STATUS={400,415,422}（输入腿 _probe_once 同取此常量）
       ├─ 端点分派: get_provider_adapter(name).generation_paths() 可选钩子
       │   （默认 OpenAI 兼容常量；厂家漂移时改 adapter，不动 client——OCP）
       └─ 返回归一: (ok, evidence≤160, settled) 三元组
            · 探测只回答"能不能生成"，不持有产物；产物 url/b64 由 Phase B 扩出参带走（§5.1 末行 / §5.2 登记）
```

**三条共有单向法则**：

1. **同一函数**：`generate_image()` 是探测与业务共用的唯一 HTTP 调用点（探测=业务通道的零成本子集，probe 只是参数更瘦；Phase B i2i 图生图=同一函数加可选 `image` 参数即达）。"同一函数"指同一个 HTTP 出口，不指同一份返回值：探测要三态判定、业务要产物，出参差异在 Phase B 以扩展方式解决。
2. **同一次持久化**：探测结果与未来产物元数据都落 `model_meta.<model>.media` 树（`merge_nested_patch` 深 merge，input 块不受影响）。
3. **同一展示体系**：②区徽标/tooltip 现有分层（输入验证 tip 已有耗时/token 分段），输出实测行挂同一 tooltip 机制，不新做浮层。

## 四、Phase A —— 设置页「生成验证」（本期落点）

### 4.1 后端：生成调用单点 `app/services/generation/generation_client.py`（新建）

```python
# 端点协议常量（OpenAI Images 兼容默认值；厂家漂移改 provider adapter 钩子，不改本文件）
IMAGE_PATH = "/images/generations"
VIDEO_PATH = "/videos"

# 厂商明确拒绝状态集：单源常量，输入腿 _probe_once 与本文件共用这一份（不再各写一份）
REJECT_STATUS = frozenset({400, 415, 422})

# 探测 prompt 常量（真机实证：一次一图、语句极短、确定性图形，成本最低）
PROBE_PROMPT = "一个红色圆点，白色背景"
PROBE_I2I_PROMPT = "把圆点改成蓝色，白色背景不变"

async def generate_image(api_base: str, headers: Dict[str, str], model: str, prompt: str,
                         *, image: Optional[str] = None, timeout: float = 120.0
                         ) -> Tuple[bool, str, bool]      # (产物成功?, evidence≤160, 结论是否确定)

# 职责边界（SRP）：client 只懂协议——不读配置树、不查 key、不拼 provider 名。
#   取值链（env {NAME}_API_KEY → config ai.{p}.api_key）、静态头、超时仍留在 model_service
#   （与 probe_model_media 同处），算好后由调用方传入 api_base/headers。
# POST {api_base}{IMAGE_PATH}  body={"model": model, "prompt": prompt}（image 非空时补 "image"）
# 判定 settled：200 且 data[0].url / b64_json 非空=OK；200 无产物=确定无；
#   400/415/422=明确拒绝；401/403/429/5xx/网络错=未定（与输入腿 _probe_once 同 settled 语义，不误写结论）
# evidence 成功/失败两侧一律截短 160 字符（完整产物 URL 不在此处持有，见 §5.2）
```

视频（`VIDEO_PATH`）本期只定常量不实现：异步轮询端点虽已探明，但结算形态与计费未实测、耗时不可控——视频验证腿挂 Phase B 按需立项。

### 4.2 后端：探测路由 `model_service.probe_output(name, model)`

- 路由：`POST /api/v1/providers/{name}/models/{model:path}/probe-output`（model_routes.py，与 probe-media 相邻注册）
- 流程：校验 provider/model 在配置内（复用 `_require_provider_for_fetch` 同款前置）→ 读 `model_meta.{model}.output_modalities` → **不含 `image` 直接 400**（后端闸门，与前端按钮同口径：前端不渲染的，后端也拒）→ 含 `image` 则**依次双枪**：
  1. `generate_image(api_base, headers, model, PROBE_PROMPT)` —— t2i：验证**文本输入→图片输出**
  2. `generate_image(api_base, headers, model, PROBE_I2I_PROMPT, image=<图源URL>)` —— i2i：验证**URL 图片输入→图片输出**（图源复用 media.probe_image_url 配置既有公网图；**仅当 t2i 取证且成功**才打第二枪，否则记 skipped）
  → 组装双腿结果；一次点击两次调用，总费用≈2 张小图（已实证单张成本极低）

- **持久化 schema（model_meta 深合并，不触碰 input 块）**：

```yaml
model_meta:
  agnes-image-2.1-flash:
    media:
      # ……既有 accept/probed_at/…（输入/chat 腿记录，不动）……
      generate:                    # ← Phase A 新增分支
        image:                     # 双腿，每腿同款结构
          t2i:                     # 文生图（文本输入→图片输出）
            state: ok              # ok（200+产物）/ none（400/415/422 拒，或 200 无产物）/ unverified（401/429/5xx 未定）/ skipped（未执行）
            ms: 348                # 生成耗时（单调钟）
            evidence: 'url=https://cos-.../output.png'   # 成功腿同截 160 字符
            at: '2026-11-09T13:30:00'
          i2i:                     # 图生图（URL 图片输入→图片输出）——输入侧 URL 图片能力的真验证
            state: ok
            ms: 402
            evidence: 'url=https://cos-.../i2i.png'
            at: '2026-11-09T13:30:05'
```

- 响应：`{ok, provider, model, generate, conclusive, persisted, message}`；`generate` 即上面落库的同构块（前端不二次解析 evidence）；message 口径与输入腿同款短句（已记录·输入与输出验证通过 / 已记录·可文生图 / 未完成·厂商网络问题）。

### 4.3 前端：②区语义重构（生成模型处置 + 「生成验证」按钮）

**判定基线**：`生成模型 = output_modalities 含 image 或 video`；`chat 腿验证行仅在 input_modalities 含 image 时有意义`。两句合成**唯一谓词** `chatLegMuted = 生成模型 && !input_modalities 含 image`，全章与代码同用此谓词（置灰、隐藏按钮、换 tooltip 三处一个来源，避免"重叠型模型"被误判）。数据层零改动（`accept=none` 照旧记录），全部为展示语义。

| 文件 | 改动 |
|------|------|
| `services/api/model.api.ts` | +`probeOutput(provider, model)`（镜像 probeMedia 签名，显式 180s 超时）；`MediaProbe` interface 扩 `generate?: { image?: { t2i?: OutputProbeRec; i2i?: OutputProbeRec } }` |
| `SettingsPage.tsx` 输入图片能力验证行 | `chatLegMuted` 为真：内联/URL/判定词徽标全部**置灰「不适用」**（新增 `na` 态：灰底无图标、不显红✗）；「验证」按钮**不渲染**（非 disabled）；tooltip 固定口径："该模型为生成模型：图片输入/输出走生成专用端点，chat 腿 400 为预期现象"。chat 多模态模型与重叠型模型：现状 3 态不变 |
| `SettingsPage.tsx` 输出模态行 | 生成模型渲染「生成验证」按钮（含 image 才出现；与输入「验证」同款式）；tooltip 追加逐腿实测行：`实测：文生图✓·348ms` / `实测：图生图✓·402ms`，none 态为 `实测：图生图✗·厂商拒绝`，腿 skipped 或无记录不显示该行；行名 tooltip 口径"生图类可点「生成验证」实测，生视频暂无自动验证腿" |
| 隐性约束 | 重叠型模型（既声明 image 输入又声明 image 输出）：`生成模型=真` 但 `input_modalities 含 image` → `chatLegMuted=假`，故 chat 腿 3 态与「验证」按钮照常、与「生成验证」两行并存各管各腿 |

**不动的**：模型库列（纯声明展示）、添加模型流程声明入口、useSettings 保存链（probe 不进脏判定）、`media.accept.*` 数据链（象义不变，只改生模型的翻译层）。

## 五、Phase B —— 未来真业务的基石面（本期只架构占位，不写代码）

### 5.1 共用收口点（设计冻结，落地按需）

| 未来需要 | 复用面 | 说明 |
|----------|---------|------|
| 会话内生图（工具调用） | `generation_client.generate_image` 同号调用 | toolhelper 工具层挂 `media_generate_image` 工具（注册走 `{cat}_register.py` 惯例，cat=media），**禁止工具内再写 httpx** |
| 图生图（i2i） | 同上，`generate_image` 加可选 `image` 参数 | 参数名 `image`（URL 字符串）已实证，不引入第二调用点 |
| 产物进入对话 | 产物 url → 现有「转发图片外链」链 | agnes COS 是公网 URL，天然匹配外链转发面；不需要先入库 |
| 生视频（异步） | `generate_video()`（submit+wait+poll 三段式） | 轮询端点 `GET /v1/videos/{task_id}` 已实证；落地只需再探结算形态与耗时，再补实现 |
| 产物持久化 | `merge_nested_patch` + model_meta | 产物元数据（url/task_id/尺寸）留 probe 同款 schema，不另开表 |
| 产物原样回传（url/b64） | `generate_image` **出参扩展**（三元组 → 带产物） | 本期探测只判"能不能生成"，不持有产物（YAGNI）；Phase B 首次需要时扩出参，仍是同一 HTTP 出口，不开第二套调用代码 |

### 5.2 已知风险登记

| 风险 | 缓解 |
|------|------|
| 视频异步结算时长/计费未知 | 本期不自动验证视频；UI 仅在视频徽标 tooltip 提示「视频生成无自动验证腿（按需立项）」 |
| images 端点错误信封与 videos 不同（`{error:..}` vs `{code,message,data.param}` 平铺） | evidence 只存原文截短串，不做信封结构化解析——探测判定只看 HTTP 状态码与 `data[0].url`，规避信封漂移 |
| 未来厂家在 IMAGE_PATH 漂移 | adapter `generation_paths()` 钩子是唯一改点（OCP），client 不加 provider 分支 |
| 生成费用滥用 | 探测与业务均走无重试调一次口径（复用 _probe_once settled 语义）；生成业务将来加配额/预算闸门属 Phase B 范围 |
| **i2i 图源格式**：默认图源是 `media.probe_image_url`（缺省 `https://cn.bing.com/favicon.ico`，32×32 ico），厂商可能按"不支持的图片格式"拒收 | i2i 判 none 时先换常见位图（png/jpg）图源复测，再下结论；不得据一次 ico 被拒就断定模型无图生图能力 |
| **产物 url/b64 不随探测返回** | 探测侧不留半成品字段；产物出参在 Phase B（§5.1 末行）扩展，避免本期先造无人消费的结构 |

```python
# -*- coding: utf-8 -*-
"""生图/生视频端点调用单点（generation 通道唯一 HTTP 出口）。

探测腿（settings2 生成验证 probe-output）与未来真业务（会话生图工具等）
共用本函数；生成端点禁直连 httpx。视频（VIDEO_PATH）常量冻结，实现挂
Phase B（异步轮询端点已探明 GET /videos/{task_id}，结算形态未实测）
- 小欧-2026-11-09
"""
from typing import Any, Dict, Optional, Tuple

import httpx

# OpenAI Images 兼容协议常量（厂家漂移时改 provider adapter generation_paths() 钩子）
IMAGE_PATH = "/images/generations"
VIDEO_PATH = "/videos"

# 厂商明确拒绝的状态: 只有这三个算"确定不收", 其余错误码是环境问题。
# 单源常量: 输入腿(_probe_once)也从这里取, 两腿判定口径物理同源 - 小欧-2026-11-09
REJECT_STATUS = frozenset({400, 415, 422})

# 生成验证探测 prompt（真机实证：一次一图、语句极短、确定性图形，成本最低）
PROBE_PROMPT = "一个红色圆点，白色背景"
# 图生图探测 prompt（i2i 第二枪：红点图改蓝点，确定性图形，产物可目检闭环）
PROBE_I2I_PROMPT = "把圆点改成蓝色，白色背景不变"

# evidence 只作人读取证: 成功腿的 COS 地址带签名可达数百字符, 一律截短 - 小欧-2026-11-09
_EV_LIMIT = 160


async def generate_image(
    api_base: str,
    headers: Dict[str, str],
    model: str,
    prompt: str,
    *,
    image: Optional[str] = None,
    timeout: float = 120.0,
) -> Tuple[bool, str, bool]:
    """生成一张图 → (产物成功?, evidence, 是否确定结论)。

    settled 口径与 model_service._probe_once 对齐：200 且产物 url/b64 非空
    = 确定 OK；400/415/422 = 确定拒绝；401/403/429/5xx/网络错 = 未定，
    调用方不得写结论。image 传 URL 时走图生图（i2i），与 t2i 同端点同函数
    - 小欧-2026-11-09
    """
    body: Dict[str, Any] = {"model": model, "prompt": prompt}
    if image:
        body["image"] = image
    try:
        async with httpx.AsyncClient(timeout=timeout) as client:
            resp = await client.post(
                f"{api_base.rstrip('/')}{IMAGE_PATH}", headers=headers, json=body
            )
    except Exception as e:
        return False, f"network_error: {type(e).__name__}: {e}"[:_EV_LIMIT], False
    if resp.status_code != 200:
        return (
            False,
            f"http_{resp.status_code}: {resp.text}"[:_EV_LIMIT],
            resp.status_code in REJECT_STATUS,
        )
    try:
        data = resp.json()
    except Exception:
        return False, "bad_json", False
    rec = (
        data.get("data")[0]
        if isinstance(data, dict)
        and isinstance(data.get("data"), list)
        and data.get("data")
        else {}
    )
    url = str(rec.get("url") or "")
    b64 = str(rec.get("b64_json") or "")
    if url:
        return True, f"url={url}"[:_EV_LIMIT], True
    if b64:
        return True, f"b64_len={len(b64)}", True
    return False, "no_output", True
```
