## 1 业界多 Agent 通信范式总览

| # | 范式 | 代表 | 核心机制 | 通信特征 | 复杂度 |
|---|------|------|----------|----------|--------|
| ① | **Tool-call 委托（父子同步）** | OpenAI Agents SDK、OmniAgent 本设计 | 父 Agent 调 tool → 创建子 Agent → await 回传摘要 → 子销毁 | 同步、单向、一次性 | ★★☆ |
| ② | **Handoff 移交（平级切换）** | OpenAI Swarm | 当前 Agent 把控制权"交"给目标 Agent，自身暂停或结束 | 同步、单向、控制权迁移 | ★★☆ |
| ③ | **图编排（DAG/状态机）** | LangGraph | 节点=Agent，边=状态传递；支持循环/条件/并行/检查点 | 可同步可异步、状态持久化 | ★★★★ |
| ④ | **消息驱动（对话/群聊）** | AutoGen、MetaGPT | Agent 间互发消息，GroupChat Manager 管理轮转，SOP/角色驱动协作 | 异步、多向、长驻 | ★★★★★ |
| ⑤ | **角色协作（Manager 分派）** | CrewAI、Semantic Kernel | Manager Agent 按 SOP 分派给角色 Agent（PM/Dev/QA），顺序或层级 | 半同步、层级 | ★★★ |

**关键区别矩阵**：

| 维度 | ① Tool-call | ② Handoff | ③ 图编排 | ④ 消息驱动 | ⑤ 角色协作 |
|------|------------|-----------|----------|-----------|-----------|
| Agent 生命周期 | 一次性（用完即毁） | 平级切换 | 节点级（可重入） | **长驻** | 任务级 |
| 上下文 | 隔离 | 移交后共享 | 共享 State 对象 | 共享对话历史 | 角色各持上下文 |
| 并行 | asyncio.gather（有界） | 不支持 | 图并行分支 | 群聊轮转 | 顺序/层级 |
| 持久化/恢复 | 无 | 无 | Checkpointer | 对话记录 | 任务状态 |
| 框架依赖 | 零（自研即可） | 轻（SDK） | 重（LangGraph） | 重（AutoGen） | 中（CrewAI） |
| 新增代码量 | ~4 文件 | ~2 文件 | 引入整框架 | 引入整框架 | 引入整框架 |

## 2 OmniAgent 选择 ① 的理由

| 决策 | 理由 |
|------|------|
| 不引 LangGraph/AutoGen | 项目已有完整 ReAct 循环 + 工具执行框架，加一个 tool 是最小侵入路径 |
| 选 ① 不选 ② | Handoff 是平级移交，OmniAgent 主 Agent 是编排中心不宜"交出"控制权；父子更贴合"主调子"语义 |
| 选 ① 不选 ③④⑤ | 当前需求是**上下文隔离** + **资源有界** + **可并行**，不需要图循环/检查点/群聊轮转 |
| 零框架依赖 | P0 新增 4 文件 + 4 改动，不改 react_loop/universal_agent/base_agent/agent_runner |

## 3 父子模式与群聊模式的关系

**核心结论：不是替代，是同层叠加。**

```
┌─────────────────────────────────────────────────────────┐
│ 通信层                                                    │
│                                                         │
│  P0  delegate_to_agent(同步 await, 子Agent一次性)         │ ← 保留
│  P2+ 消息总线(异步, Agent长驻, GroupChat轮转)             │ ← 新增
├─────────────────────────────────────────────────────────┤
│ 配置层                                                    │
│                                                         │
│  AgentConfig + AgentRegistry                             │ ← 保留
│  群聊扩展: AgentConfig.chat_role="pm"/"engineer"/"qa"   │ ← 加字段
├─────────────────────────────────────────────────────────┤
│ Agent 本体层（完全不动）                                   │
│                                                         │
│  UniversalAgent / BaseAgent / run_react_cycle           │
│  不管通信模式怎么变, 每个 Agent 内部仍是 ReAct 循环         │
├─────────────────────────────────────────────────────────┤
│ 工具层（完全不动）                                         │
│                                                         │
│  ToolRegistry / ToolLoader / ToolCategory / 安全hooks    │
│  工具子集注入机制不变                                       │
└─────────────────────────────────────────────────────────┘
```

### 3.1 同步委托 vs 异步群聊差异

| 维度 | P0 父子（tool-call） | P2+ 群聊（消息驱动） |
|------|---------------------|---------------------|
| Agent 生命周期 | **一次性**：创建→跑→销毁 | **长驻**：常驻内存，收消息→响应→待命 |
| 通信 | `await callback()` 同步阻塞 | 异步消息队列 / pub-sub |
| 上下文 | 隔离（子不继承父历史） | 可共享对话历史（GroupChat 共享 context） |
| 轮转 | 无（主 Agent 控制顺序） | Manager 分配发言权，多 Agent 轮流响应 |
| 前端展示 | 一条 `delegate_to_agent` 工具行 | 多角色对话流（折叠/展开） |
| 入口 | tool 调用 | 消息总线 API（HTTP 长连接 / SSE 多路） |
| token 归口 | usage 合并到父 Agent | 各 Agent 独立计费 + Manager 汇总 |

### 3.2 `delegate_to_agent` 在群聊模式下的定位

群聊上线后 `delegate_to_agent` **不删**，退化为"快捷单发"：

```
场景 A: "拉个群让 3 个 Agent 讨论方案"  → 走消息总线 GroupChat
场景 B: "单独让 reviewer 审一下这段代码"  → 走 delegate_to_agent（快捷委托）
```

两者并存，LLM 按任务复杂度自选通道。

## 4 升级路径

```
P0  delegate_to_agent (同步, 一次性子Agent)
 │
 │  复用: AgentConfig / AgentRegistry / UniversalAgent / run_react_cycle / 工具系统
 ▼
P2+ 消息总线 + GroupChat Manager
     │
     ├─ 新增: MessageBus (async pub-sub)
     ├─ 新增: AgentSession (长驻 Agent 管理, 空闲回收)
     ├─ 新增: ChatRoundManager (轮转策略: 顺序/自由/Manager指定)
     ├─ 新增: SSE 多角色对话流 (前端折叠/展开)
     ├─ 扩展: AgentConfig.chat_role + AgentRegistry.list_by_role()
     ├─ 保留: delegate_to_agent 作为"单发快捷委托"并存
     └─ 不动: UniversalAgent / BaseAgent / react_loop / 工具系统
```

| 阶段 | 新增 | 改动 | 不动 |
|------|------|------|------|
| P0 | agent_config.py / delegate_runner.py / delegate.py / delegate_schema.py | agent_register / context / tool_executor | 所有 Agent 核心 + 工具系统 |
| P2+ | message_bus.py / agent_session.py / chat_round_manager.py / SSE 多角色协议 | AgentConfig 加 chat_role / 前端步骤流扩展 | P0 全部代码 + Agent 核心 + 工具系统 |

## 5 结论

| 问题 | 回答 |
|------|------|
| 业界都是 tool-call 模式？ | 不是。5 种范式从轻到重，OmniAgent 取最轻一档 |
| 群聊模式要推翻父子？ | 不推翻。通信层叠加，Agent 本体/工具层/配置层全复用 |
| `delegate_to_agent` 会被删？ | 不会。退化为"单发快捷委托"，与群聊并存 |
| 升级成本 | P2+ 新增 ~5 文件，改 AgentConfig 加 1 字段，P0 代码零改动 |
