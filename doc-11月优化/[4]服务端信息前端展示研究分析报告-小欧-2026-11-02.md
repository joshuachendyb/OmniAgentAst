## 一、研究范围与方法

1. **研究范围**：`backend/app/api/v1/` 全部路由文件、`backend/app/monitoring/`（监控独立库）、`backend/app/services/task/`（任务注册/状态）、`backend/app/main.py` 路由挂载、`frontend/src/` 现有页面与菜单。
2. **研究方法**：逐文件实读路由定义（`@router.get/post/...`）与响应模型字段，核对前端 `services/api/` 已接通的接口，找出"后端有数据、前端未展示"的信息面。
3. **研究问题**：
   - 后端现有哪些信息面可展示？
   - 哪些已有 API 但前端未用（零后端开发即可上屏）？
   - 哪些信息有价值但缺 API（需少量后端新增）？

## 二、研究结论（先说重点）

1. 后端现有 **6 类可直接展示的信息面**，全部有现成 API；
2. 其中 3 类（运行指标、token 全局用量、任务中心数据）**前端尚未展示**，属"临门一脚"；
3. 任务中心数据**完全现成**——`GET /tasks` 全局列表端点已存在（v1.0 误判"缺列表端点"，v1.1 已核实更正：task_queries.py:37，`tasks` 表自带 status/total_operations/success_count/failed_count 字段），任务监控页**后端零新增**；
4. 首选落地方案：**侧边菜单单一"任务监控"页（四区布局：关键指标 / 运行指标 / Token 用量 / 任务中心，后端零改动）+ 顶栏 1 个综合健康灯（四态 · Tooltip 悬浮详情）**。

## 四、SSE 流内已有、适合任务级动态展示的信息

来源：`app/monitoring/agent_telemetry.py`（帧类型口径在 `M_SKIP` 集合中定义）与 `agent_runner` 的发布链路。

| 帧类型 | 可展示内容 | 适合的 UI |
|--------|-----------|----------|
| `stats` / `final_stats` | tool_stats、llm_call_count、retry_count、step_count、artifacts 清单(tool_name+path 去重) | 任务执行进度、步骤统计卡、产物清单 |
| `history_context` | `compressed`(权威压缩判定) + `compress_saved_pct`(节省百分数) + 注入摘要 | **上下文比例条**（现成的比例条数据源） |
| `usage` | 单轮 token 用量 | 轮次消耗徽标 |
| `paused/resumed/retrying/cancelled/rejected` | 任务运行态迁移 | 状态指示灯 |
| `authorization_required`、`notice` | 待确认授权、通知信封 | 提示条/弹窗 |

## 五、有价值但目前未暴露 API 的信息（需小量后端新增）

| 信息 | 现状 | 需要的工作 |
|------|------|-----------|
| 内存活跃任务实时态(running/paused) | `app/services/task/task_registry.py` 有 `has_active_task_in_session`（running/paused 判定），但无"列出全部活跃任务"端点 | 新增 1 个只读端点；任务监控页一期可不做（DB status 已够展示） |
| 事件循环看门狗状态 | `app/monitoring/loop_watchdog.py` 有心跳/停摆检测 + py-spy dump 留证，纯内部无 API | 新增只读端点（停摆自动取证状态=高级运维展示点，三期） |
| 进程级资源与日志 | `backend/logs/`、`prompt-logs/` 只落盘无 API | 新增 1~2 个只读端点（日志尾/CPU/内存，三期） |
| SQLite 三库文件占用 | `/health` 只回 degraded 判定，无文件大小 | 扩展 /health 或新端点（二期） |

> v1.4 更正：实读 `frontend/src/components/Layout/index.tsx` 核实——导航菜单在**左侧边栏（antd Sider）**，顶栏 Header（43px 高）只有 Logo + 品牌名 "OmniAgentAst."，**没有菜单项**。上图按真实布局重画。

- **1 个综合健康灯**（antd `Badge` 小圆点），四种状态语义，**宕机必须是红色**（比降级更醒目，信号不倒挂）：

| 灯态 | 颜色 | 含义 | 判定 |
|------|------|------|------|
| 未加载 | 灰（`rgba(0,0,0,0.25)`） | 首屏首次请求未返回 | 无数据且无失败 |
| 正常 | 绿（`Colors.SUCCESS #52c41a`，图形色） | 服务与三库全健康 | `status=healthy` 且 `dbs` 逐库 healthy |
| 降级 | 黄（`Colors.WAIT_ACTION #fa8c16`，图形色） | 有库不可用/聚合 degraded | 请求成功但上述条件不满足 |
| 后端无响应 | 红（`Colors.ERROR #ff4d4f`，图形色） | 最近一次请求失败 | 请求异常（保留最后已知数据供 Tooltip 参考） |

- **版本号小字**（灯旁灰色小字，如 `v4.20`，一眼可见当前版本）；加载期只显灰点、**不显 `--`**，版本到手才出文字；
- 顶栏常驻 = 上述 **2 个元素**（1 个图标位 + 1 小段文字），占了最少的顶栏空间；移动端（Layout 既有 `isMobile`）只显灯、隐版本小字；
- **鼠标悬浮灯上弹出 Tooltip 悬浮详情**（3 行明细，不常驻不占空间）：

| Tooltip 详情行 | 数据源 |
|---------------|--------|
| 服务状态：正常 / 降级（失败时首行红字"后端无响应"） | `GET /health` 的 `status` 字段 |
| 三库分灯：chat 正常 / operations 正常 / task_tracker 正常 | `GET /health` 的 `dbs` 字段（三库逐库 SELECT 1） |
| 版本：v4.xx | `GET /health` 的 `version` 字段（实时读 version.txt） |

- **v1.2 北京老陈裁定**：provider/model 不进顶栏悬浮详情——前端已有 provider/model 下拉框，同一信息只留一个展示入口（杜绝重复，单一来源）；模型状态仍在「任务监控」页与设置页可查。
- **轮询口径**：10s 一次（与 /health 轻量实测成本匹配）；灯与监控页①区健康卡**共用 `features/monitor/hooks/useHealthPolling` 模块级单例**（同一份请求、同一状态快照），既避免同屏双轮询，也杜绝"灯绿卡黄"的不一致。订阅者全部卸载时停表，有订阅再启。
- **与顶栏「检查服务」按钮的分工**：按钮=用户主动触发、弹 toast/Modal 报明细；灯=被动常驻、静默轮询不打扰。两者不合并、不重复提示。

/** 区块取数三态: data=最新数据(失败时保留旧值), error=最近一次请求失败, retry=立即重拉 */
export interface PollState<T> {
  data: T | null;
  error: boolean;
  retry: () => void;
}

/** health.status 中文文案(顶栏灯 Tooltip 与①区健康卡同源, 杜绝中英混排) — 小欧 2026-11-02 v1.8 */
export function healthText(status: string): string {
  if (status === 'healthy') return '正常';
  if (status === 'degraded') return '降级';
  return status;
}

/** 通用 10s 静默轮询 + JSON diff(值未变不 setState) — 小欧 2026-11-02
 *  retry() 给区块级「重试」按钮用: 换 tick 触发 effect 重跑(重设 interval 一并归零)。 */
export function useMonitorPolling<T>(fetcher: () => Promise<T>): PollState<T> {
  const [data, setData] = useState<T | null>(null);
  const [error, setError] = useState(false);
  const [tick, setTick] = useState(0);
  const fetcherRef = useRef(fetcher); // 恒最新取数器, effect 不依赖其身份
  fetcherRef.current = fetcher;

  useEffect(() => {
    let alive = true;
    const run = async () => {
      try {
        const next = await fetcherRef.current();
        if (!alive) return;
        setData((prev) => (JSON.stringify(prev) === JSON.stringify(next) ? prev : next));
        setError(false);
      } catch {
        // _silent 封装默认无 toast, 区块级 Alert 呈现
        if (alive) setError(true);
      }
    };
    void run();
    const intervalId = setInterval(() => void run(), 10_000);
    return () => {
      alive = false;
      clearInterval(intervalId);
    };
  }, [tick]);

  return { data, error, retry: () => setTick((n) => n + 1) };
}

// ===== /health 共享单例(灯 + 监控页健康卡) =====
interface HealthSnapshot {
  data: HealthStatus | null;
  /** 最近一次请求失败: 灯转红档「后端无响应」; 有旧数据时保留供 Tooltip 参考 */
  failed: boolean;
}

let snapshot: HealthSnapshot = { data: null, failed: false };
const listeners = new Set<() => void>();
let timer: number | null = null;
let inflight = false;

const emit = () => listeners.forEach((l) => l());
const getSnapshot = (): HealthSnapshot => snapshot;

async function healthTick(): Promise<void> {
  if (inflight) return;
  inflight = true;
  try {
    const next = await healthApi.checkHealth(SILENT);
    const prev = snapshot;
    const unchanged =
      prev.data !== null &&
      !prev.failed &&
      prev.data.status === next.status &&
      prev.data.version === next.version &&
      JSON.stringify(prev.data.dbs) === JSON.stringify(next.dbs);
    if (!unchanged) {
      snapshot = { data: next, failed: false };
      emit();
    }
  } catch {
    if (!snapshot.failed) {
      snapshot = { ...snapshot, failed: true };
      emit();
    }
  } finally {
    inflight = false;
  }
}

function subscribe(listener: () => void): () => void {
  listeners.add(listener);
  if (timer === null) {
    void healthTick();
    timer = window.setInterval(() => void healthTick(), 10_000);
  }
  return () => {
    listeners.delete(listener);
    if (listeners.size === 0 && timer !== null) {
      window.clearInterval(timer);
      timer = null;
    }
  };
}

/** /health 共享轮询(顶栏灯 + 监控页①区): 一份请求、一份状态快照 */
export function useHealthPolling(): PollState<HealthStatus> {
  const snap = useSyncExternalStore(subscribe, getSnapshot, getSnapshot);
  return { data: snap.data, error: snap.failed, retry: () => void healthTick() };
}
