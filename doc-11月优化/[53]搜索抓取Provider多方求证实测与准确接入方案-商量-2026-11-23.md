## 5. 现网隐患与修复（最紧急）

### 5.1 隐患定位

`search_web.py` 第 283 行 MCP 调用：

```python
async with client.stream("POST", config["url"], json=payload,
        headers={"Accept": "application/json, text/event-stream"}) as resp:
```

**headers 仅带 `Accept`，没有 `User-Agent`**。而 `create_http_client`（`http_client_sdk.py` 第 220 行）不默认带 UA——`httpx.AsyncClient` 默认 UA 是 `python-httpx`。实测证明：**httpx 默认 UA 调 Exa / Parallel 会触发 Cloudflare 403**。

### 5.2 影响面

- **现网 Exa / Parallel 搜索链很可能正在 403 失效**（`search_web.py` 第 194-197 行 `SEARCH_CHAIN` 默认 parallel → exa，两家都受影响）；
- 抓取链 `fetch_webpage.py` 的 Jina Reader（`_fetch_via_external_reader`，682 行）用 `client.get` 不带 UA，但 Jina 端点对 UA 不敏感，暂不受影响。

### 5.3 修复方案

给第 283 行 headers 补 `User-Agent: TOOL_BROWSER_UA`。**该常量已在 `search_web.py` 第 68 行 import**（来自 `app.tools.tool_constants`），且第 381 行 Bing 兜底已在使用，无需新增依赖：

```diff
--- a/backend/app/tools/network/search_web.py
+++ b/backend/app/tools/network/search_web.py
@@ -282,7 +282,7 @@ async def _search_mcp_engine(engine: str, query: str, num_results: int, proxy: O
             async with client.stream("POST", config["url"], json=payload,
-                    headers={"Accept": "application/json, text/event-stream"}) as resp:
+                    headers={"Accept": "application/json, text/event-stream", "User-Agent": TOOL_BROWSER_UA}) as resp:
```

**验收**：修复后真实调用 Exa / Parallel 各一次，确认 200 且有结果（原先 403）。

## 8. 详细设计（代码级可实施方案）

本章给出搜索链与抓取链的**端点顺序（首选/次选/理由）**与**完整代码设计**，可直接落地。代码注释按项目规范只写技术逻辑与署名日期，不含文档号、章节号或问题编号。

### 8.1 搜索链详细设计（search_web.py）

#### 8.1.1 端点顺序（首选/次选/理由）

搜索链是**发现型**工具（query → items[]），追求"快、准、稳、冗余"。端点顺序如下：

| 顺序 | 端点 | 工具 | keyless | 理由 |
|---|---|---|---|---|
| **首选** | `search.parallel.ai/mcp` | `web_search` | ✅（须带浏览器 UA） | **结构化结果最干净**——读 `structuredContent` 直接出 `{title,url,excerpts}`，无需文本正则解析；实测 keyless 带 UA 200；现网在用，无新增依赖 |
| **次选** | `mcp.exa.ai/mcp` | `web_search_exa` | ✅（须带浏览器 UA） | **结果质量高**——AI 语义搜索，`Title:/URL:` 文本块；实测 keyless 带 UA 200；现网在用，与 Parallel 互为备份 |
| **三选** | `mcp.firecrawl.dev/v2/mcp` | `firecrawl_search` | ✅（免 UA） | **免费层兜底**——实测 200 无需 UA；补两家之外的第三冗余；但免费层限速（仅 scrape/search/parse 三工具），故放中后位 |
| **四选** | `agent.tinyfish.ai/mcp` | `search` | ✅（带 keyless header） | **备用冗余**——实测 200，免握手；免费层配额更严，故放最后 |

**为什么首选 Parallel 而非 Exa**：两者 keyless 均可用，但 Parallel 返回 `structuredContent`（结构化），解析零脆弱；Exa 返回自然语言文本块，需正则解析（`URL:/Title:`），多一层解析失败点。故 Parallel 居首，Exa 次之——这是"稳定性优先"的选择。

**为什么 Firecrawl/TinyFish 放中后位**：两者免费层有限速（Firecrawl 仅三工具限速、TinyFish 配额更严），作为冗余后备而非主通道；若主通道（Parallel/Exa）因 UA 未修或上游故障失效，才由它们顶上。

### 8.2 抓取链详细设计（fetch_webpage.py）

#### 8.2.1 端点顺序（首选/次选/理由）

抓取链是**检索型**工具（url → 正文），追求"反爬穿透 + 正文质量 + 多级兜底"。端点顺序如下：

| 顺序 | 端点 | 工具 | keyless | 理由 |
|---|---|---|---|---|
| **首选** | `r.jina.ai` | Jina Reader | ✅ | **零本地依赖 + 绕反爬**——现网在用，自有 IP+指纹，能绕 Cloudflare；返回干净 markdown；无需 key |
| **次选** | `mcp.exa.ai/mcp` | `web_fetch_exa` | ✅（须带浏览器 UA） | **补 Jina 单点**——实测 keyless 200，返回干净 markdown；Jina 被反爬/限流时顶上 |
| **三选** | `mcp.firecrawl.dev/v2/mcp` | `firecrawl_scrape` | ✅（免 UA） | **最强抓取级**——实测 200，JS 渲染 + 强反爬；免费层限速故放第三 |
| **四选** | 本地 httpx + trafilatura | — | 无 | **本地兜底**——零外部依赖，静态 HTML + 正文抽取 |
| **五选** | 本地 Playwright | — | 无 | **JS 渲染兜底**——SPA/动态页，最重最慢，最后用 |

**为什么 Jina 仍居首而非 Exa/Firecrawl**：Jina 现网在用、零本地依赖、绕反爬效果好，且返回 markdown 无需二次抽取；Exa/Firecrawl 作为**新增冗余**补 Jina 单点，不喧宾夺主。若 Jina 因上游反爬/限流失效，则 Exa（次选）顶上，Firecrawl（三选）最后兜底。

**为什么 Exa 先于 Firecrawl**：两者 keyless 均可用，但 Exa 实测返回干净 markdown（与 Jina 同质，无缝衔接）；Firecrawl 免费层限速（仅三工具），作最强抓取级放第三，且其 JS 渲染能力与本地 Playwright 重叠，故不抢 Exa 的次选位。

#### 8.2.2 新增 `_fetch_via_exa(url, timeout)`

仿 `_fetch_via_external_reader`（682 行）结构，但走 MCP `web_fetch_exa`，**带浏览器 UA**（实测必需）：

```python
# 2026-11-23 商量 - Exa web_fetch_exa 抓取兜底(keyless, 须带浏览器UA); 补 Jina 单点
async def _fetch_via_exa(url: str, timeout: int) -> Optional[str]:
    payload = {
        "jsonrpc": "2.0", "id": 1, "method": "tools/call",
        "params": {"name": "web_fetch_exa", "arguments": {"urls": [url]}},
    }
    try:
        async with create_http_client(timeout_sec=timeout) as client:
            async with client.stream("POST", "https://mcp.exa.ai/mcp", json=payload,
                    headers={"Accept": "application/json, text/event-stream", "User-Agent": TOOL_BROWSER_UA}) as resp:
                resp.raise_for_status()
                raw = b"".join([c async for c in resp.aiter_bytes()]).decode("utf-8", "replace")
        data = parse_json(raw, raise_on_error=True) if raw.lstrip().startswith("{") else None
        if data is None:
            for line in raw.split("\n"):
                line = line.strip()
                if line.startswith("data: "):
                    data = parse_json(line[6:], raise_on_error=True)
                    break
        content_list = (data or {}).get("result", {}).get("content", [])
        md = "\n".join(str(c.get("text", "")) for c in content_list if c.get("type") == "text")
        if len(md) > 50:
            return _clean_markdown_content(md)
    except Exception:
        pass
```

#### 8.2.3 新增 `_fetch_via_firecrawl(url, timeout)`

走 MCP `firecrawl_scrape`，keyless 免 UA：

```python
# 2026-11-23 商量 - Firecrawl firecrawl_scrape 抓取兜底(keyless 免费层, JS渲染+强反爬)
async def _fetch_via_firecrawl(url: str, timeout: int) -> Optional[str]:
    payload = {
        "jsonrpc": "2.0", "id": 1, "method": "tools/call",
        "params": {"name": "firecrawl_scrape", "arguments": {"url": url, "formats": ["markdown"]}},
    }
    try:
        async with create_http_client(timeout_sec=timeout) as client:
            async with client.stream("POST", "https://mcp.firecrawl.dev/v2/mcp", json=payload,
                    headers={"Accept": "application/json, text/event-stream"}) as resp:
                resp.raise_for_status()
                raw = b"".join([c async for c in resp.aiter_bytes()]).decode("utf-8", "replace")
        data = parse_json(raw, raise_on_error=True) if raw.lstrip().startswith("{") else None
        if data is None:
            for line in raw.split("\n"):
                line = line.strip()
                if line.startswith("data: "):
                    data = parse_json(line[6:], raise_on_error=True)
                    break
        # 实施发现(2026-11-23 实测): firecrawl_scrape 返回 structuredContent{markdown} 干净文本, 优先读 markdown;
        #   content 的 text 是 JSON 包裹({markdown:...}), 仅当 markdown 缺失时回落 text
        result = (data or {}).get("result", {})
        _sc = result.get("structuredContent")
        md = str(_sc.get("markdown", "")) if isinstance(_sc, dict) and _sc.get("markdown") else ""
        if not md:
            content_list = result.get("content", [])
            md = "\n".join(str(c.get("text", "")) for c in content_list if c.get("type") == "text")
        if len(md) > 50:
            return _clean_markdown_content(md)
    except Exception:
        pass
    return None
```

#### 8.2.4 降级链端点顺序改造

在 Jina 失败后追加 Exa / Firecrawl 兜底，形成多级外部 API 链（8.2.1 顺序）：

```
Jina Reader → Exa web_fetch_exa → Firecrawl firecrawl_scrape → httpx 静态 + trafilatura → Playwright
```

**接入点**（以实施时为准，均"Jina 失败后追加"）：

| 接入点 | 位置 | 追加逻辑 |
|---|---|---|
| Jina 优先分支 | `fetchpage` 765 行起（`format=markdown and not js_render`） | Jina 失败（`_jina_md` 为空或 <200 字符）后，先试 `_fetch_via_exa`，再试 `_fetch_via_firecrawl`，成功即返回 |
| 403 → Jina 降级分支 | `fetchpage` 859 行起 | Jina 失败后追加 `_fetch_via_exa` → `_fetch_via_firecrawl` |
| js_render 渲染失败 → 外部 API 兜底 | `fetchpage` 807 行起 | Jina 失败后追加 `_fetch_via_exa` → `_fetch_via_firecrawl` |

三个接入点共用同一逻辑：**外部 API 兜底 = Jina → Exa → Firecrawl 依次尝试，任一成功即返回**，全部失败才落到本地 httpx/Playwright。为 DRY，可抽取一个 `_fetch_via_external_chain(url, timeout)` 依次调三家，但按 KISS-DIRECT 优先在现有 `_fetch_via_external_reader` 调用点就近追加（复制不改业务逻辑，避免重写引入新错误）。
