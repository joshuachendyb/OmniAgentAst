## 0. 一页看懂

本方案不改"某一条缺陷"，而是**换掉产生缺陷的那套结构**。

当前系统的真问题只有一句话：

> **附件类型轴（kind）与模型模态轴（modality）是两套独立分类，二者之间只靠三处硬编码 if 临时对接。**

三处硬编码分别在：`attachments/extract.py:86 build_inject_text` 的 kind 分支、`services/agent/vision.py:101 split_vision_refs` 的 image-only 分流、`services/agent/media_payload.py:149 build_media_part` 的 image-only 构 part。

因此 D1~D6 不是六个独立 bug，而是**同一个结构性缺口**的六种表现：

- 新增一种附件（audio，D1）→ 没有入口，因为 kind 词典里根本没有它；
- 新增一种原生传输（file/video，D2）→ 无处安放，因为分流只认 image；
- 判定只有"能/不能"（D3）→ 因为能力被压缩成一个 bool；
- 实测只覆盖 image（D4）→ 因为探针和 accept 结构写死了 image；
- 矩阵无守门测试（D5）→ 因为矩阵不以数据形式存在，只散落在 if 里；
- 截断无完整性标记（D6）→ 因为抽取器各自为政，没有统一出口契约。

**目标架构：把"类型 × 能力 → 渲染方式"从代码分支提升为一份可测试的数据契约，再加一个纯函数计划器。**

一句话定义应用模式：

> **能力协商式附件渲染（Capability-Negotiated Attachment Rendering, CNAR）**：附件不以"文件类型"决定命运，而以"文件类型 × 当前模型有效能力 × 传输方言"三元组协商出唯一渲染计划；原生能收则发原生 part，不能则降维成内容文本，再不能则降为档案卡，且每一级降维对用户可见。

这套模式一次性把 D1~D6 全部收进同一张契约表、同一个计划器、同一个守门测试。新增任何类型/模态，**只加表行，不改流程**。

## 1. 现状与根因

### 1.1 两条轴与真正的耦合点

| 轴 | 取值 | 唯一真源 |
|---|---|---|
| 附件内容类型 content_kind | text / image / video / audio / richdoc / binary / unknown | `attachments/extract.py:52 classify`（后缀词典 :38-49；audio/unknown 由本方案 P3 扩展） |
| 模型模态 modality | text / image / audio / video / file | `services/model/model_service.py:910 normalize_modalities` |

两轴的对接现状（全部为隐式硬编码）：

1. `react_loop.py:218-231`：只有 `supports_image_input` 为真时才调用 `split_vision_refs` 把 image 摘出正文；其余类型一律走文本。
2. `vision.py:101 split_vision_refs`：以 `mime.startswith("image/")` 识别，天然只认图片。
3. `media_payload.py:149 build_media_part`：`if kind != "image": return None`，原生 part 只有图片一种。
4. `vision.py:75 supports_image_input`：读取 `media.accept.image` 实测值 → 回落 `input_modalities` 是否含 image，**结果是一个 bool**。

关键事实：resolver 在计划之前**已经把所有附件解析成了注入文本**（`services/refs/pipeline.py:38` → `resolver.py:249`）。也就是说——

> 每一份"降维文本"其实早已算好，只是当图片被判定走原生时被丢弃了。

这条事实决定了本方案最省的一步：**原生失败时无需重新抽取，直接复用 ref 上已存在的 `content` 作为降级文本**。

### 1.2 缺陷与根因映射

| 编号 | 现象 | 直接根因 | 结构性根因 |
|---|---|---|---|
| D1 | audio 无附件入口 | kind 词典无 audio；classify 无分支 | 类型轴与模态轴未对齐（modality 有 audio，kind 没有） |
| D2 | file/video 模态悬空 | 传输层只实现 image part | 缺"逻辑 part → 方言 part"的运输层 |
| D3 | 判定缺"降维可用"中间态 | 能力被压成 bool | 缺三级能力画像 |
| D4 | 实测只覆盖 image | accept 结构与探针写死 image | 探针未按模态维度建模 |
| D5 | 矩阵无守门测试 | 矩阵不存在，只在 if 里 | 缺可被测试的单一契约数据 |
| D6 | 截断无完整性标记 | 各抽取器各自决定 | 缺统一抽取出口契约 |

注意 D1 与 D4 的对称性：模态轴早就有 audio，类型轴与探针却都没有 —— 这正说明两条轴是各自演化的，没有共同契约。

## 2. 设计原则与不变量

### 2.1 五条设计原则（对齐 KISS-DIRECT）

1. **单一契约**：类型→模态→降级方式只允许存在于一张表里，前后端与测试共用其投影。
2. **声明即首选请求模式**：请求模式以模型标注的输入/输出模态（`input_modalities` 等配置声明）为首选依据——声明了就按该模态原生发送，请求失败才回退降级（`on_native_fail`）。实测探针结果**不参与请求判定**，仅作设置页参考与模型推荐展示（探针数据可能过期/失效/丢失，不能作为请求判据）。
3. **降级必须保底**：每一种 kind 都必须有一个"永远成功"的文本出口（内容文本 / 元数据 / 档案卡三档之一）。
4. **不新增状态机**：沿用现有"history 恒 str + 占位 + wire 边界展开"的 V3 不变量，不做双份历史。
5. **不搞注册表膨胀**：契约是"内容类型 × 来源"的二维表（默认行 + URL 覆盖构建，含 unknown）+ 一个纯函数计划器 + 一个 5 分支运输函数；不引入插件框架、不引入能力注册中心。

### 2.2 必须守住的不变量

- `conversation_history` 内 content 永远是可序列化字符串；压缩/裁剪/持久化零改动。
- base64/大文本不得入落库与日志；原生 part 只在 wire 边界生成。
- 失败不阻断本轮：任一条目失败退化为文字说明，继续发送。
- 输出模态（生图/生视频）不参与附件入参判定，只看 input 侧。

## 3. 目标架构

### 3.1 分层视图

```
┌─────────────────────────────────────────────────────────────┐
│ 体验层  前端：能力徽标 / 发送前对齐 / 抽取态可视化             │
├─────────────────────────────────────────────────────────────┤
│ 投影层  model DTO.ref_capability_map（source_kind→content_kind→状态）│
├─────────────────────────────────────────────────────────────┤
│ 计划层  contract.plan_refs(items, profile) → list[ItemPlan]  │
├─────────────────────────────────────────────────────────────┤
│ 能力层  capability.profile(llm_model) → {modality: NativeCap} │
├─────────────────────────────────────────────────────────────┤
│ 契约层  contract.KIND_CONTRACT（(source_kind,content_kind) → 模态/降级/出口）│
├─────────────────────────────────────────────────────────────┤
│ 运输层  media_payload(logical part) → wire part（chat/responses）│
├─────────────────────────────────────────────────────────────┤
│ 抽取层  extract.build_inject_text（统一完整性标记）             │
└─────────────────────────────────────────────────────────────┘
```

职责各一段，单向向下依赖，无回调、无环：

- 契约层只依赖 classify 的后缀词典与模态词汇，**零 IO、零配置**；
- 能力层只读配置与实测记录，纯函数；
- 计划层只做集合拆分，纯函数；
- 运输层只做格式翻译，纯函数 + 缓存；
- 抽取层是唯一读盘处。

### 3.2 核心数据结构

```python
# app/attachments/contract.py  （新增，零 IO）

# 降级质量：决定"降维后模型还能理解多少内容"
#   content  完整内容（文本正文 / 富文档抽取）
#   metadata 部分内容（视频/音频的时长/编码等）
#   card     仅档案信息（文件名/大小/类型，模型看不到内容）
#   link     仅链接文本（URL 来源兜底）
@dataclass(frozen=True)
class KindRoute:
    native_modality: str | None      # 可尝试的原生模态；None=永远走文本
    fallback_quality: str            # content | metadata | card | link
    extractor: Callable              # 永远成功的文本出口（URL 行为 _link_body）
    on_native_fail: str              # reuse_text | link_text | notice
    fetch: str = "none"              # none | optional | required（URL 来源用）

# 二维契约：键为 (source_kind, content_kind)
#   source_kind : file | selection | attachment | url | log | message
#   content_kind: text | image | video | audio | richdoc | binary | unknown
# 同一 content_kind 在不同来源下可给不同兜底：附件·image 兜底是 card，
# URL·image 兜底是 link（模型只拿到链接文本）。
_BASE: dict[str, KindRoute] = {
    "text":    KindRoute(None,    "content",  _text_body,     "reuse_text"),
    "richdoc": KindRoute("file",  "content",  _richdoc_body,  "reuse_text"),
    "image":   KindRoute("image", "card",     _image_card,    "reuse_text"),
    "video":   KindRoute("video", "metadata", _video_card,    "reuse_text"),
    "audio":   KindRoute("audio", "metadata", _audio_card,    "reuse_text"),
    "binary":  KindRoute(None,    "card",     _binary_card,   "reuse_text"),
    "unknown": KindRoute(None,    "link",     _link_body,     "notice"),
}
# URL 来源覆盖：不落地文件的内容一律以"链接文本"兜底，fetch 按需
_URL_OVERRIDE: dict[str, KindRoute] = {
    "image":   KindRoute("image", "link", _link_body, "link_text", fetch="optional"),
    "video":   KindRoute("video", "link", _link_body, "link_text", fetch="optional"),
    "audio":   KindRoute("audio", "link", _link_body, "link_text", fetch="optional"),
    "richdoc": KindRoute("file",  "link", _link_body, "link_text", fetch="optional"),
    "binary":  KindRoute(None,    "link", _link_body, "link_text"),
}
# URL 行 extractor 一律 _link_body：URL 来源无本地 stored_path，_video_card/_audio_card 需读盘跑
#   ffprobe 不可达，且与 fallback_quality='link' 自相矛盾；元数据探测仅服务"fetch 成功且原生
#   内联"的 native 分支，不经降级 extractor。

_SOURCE_KINDS = ("file", "selection", "attachment", "url", "log", "message")
_CONTENT_KINDS = tuple(_BASE)


def _build_contract() -> dict[tuple[str, str], KindRoute]:
    table: dict[tuple[str, str], KindRoute] = {}
    for source in _SOURCE_KINDS:
        for content in _CONTENT_KINDS:
            # log/message 是内部来源，内容恒为文本语义
            if source in ("log", "message"):
                table[(source, content)] = _BASE["text"]
            elif source == "url":
                table[(source, content)] = _URL_OVERRIDE.get(content, _BASE[content])
            else:
                table[(source, content)] = _BASE[content]
    return table


KIND_CONTRACT: dict[tuple[str, str], KindRoute] = _build_contract()
KIND_MODALITY = {k: r.native_modality for k, r in _BASE.items()}
```

### 3.2.1 URL 内容类型识别七类细分（归类规则）

识别入口只有 `classify_url(url, content_type="")` 与 `scan_text_urls(text)`，二者**不读模型能力**，按 URL 后缀词典归入 `content_kind` 七类；未知后缀先查 content-type，仍未知兜底 `unknown`：

| content_kind | URL 后缀 | 归类规则 | 后续处理（wire 展开） | 消费模型 |
|---|---|---|---|---|
| `image` | `.png/.jpg/.jpeg/.gif/.webp/.bmp` | 后缀词典唯一真源；content-type `image/*` 仅无后缀时兜底 | 实测支持外链→`image_url` part 直传；否则 fetch 后压缩内联→`image_url` part | 视觉模型（`profile["image"]`） |
| `video` | `.mp4/.mov/.mkv/.webm/.avi/.m4v` | 同上；content-type `video/*` 仅无后缀时兜底 | 实测支持外链→`video_url` part 直传；否则 fetch 后内联→`video_url` part；无方言→链接文本 | 视频模型（`profile["video"]`；声明即首选，失败回退） |
| `audio` | `.mp3/.wav/.m4a/.aac/.flac/.ogg/.opus/.wma` | 同上；content-type `audio/*` 仅无后缀时兜底 | 实测支持外链→`audio_url` part 直传；否则 fetch 后内联→`audio_url` part；无方言→链接文本 | 音频模型（`profile["audio"]`；声明即首选，失败回退） |
| `richdoc` | `.pdf/.docx/.xlsx/.pptx` | 同附件 `richdoc` 词典（唯一真源） | **按附件 richdoc 的后续处理方法复用**：fetch 下载→`_richdoc_body` 抽取→`content` part；fetch 失败→链接文本 | 文件模型（`profile["file"]`；声明即首选原生，失败回退抽取文本注入） |
| `text` | `.txt/.md/.log/.csv/.json/.xml/.html/.js/.py` 等 `TEXT_SUFFIXES` | 同附件 `text` 词典（唯一真源） | **按附件 text 的后续处理方法复用**：fetch 下载→`_text_body` 读正文→`content` part；fetch 失败→链接文本 | 任意文本模型（纯文本恒可用） |
| `binary` | `.zip/.rar/.7z/.exe/.apk` 等非词典后缀 | 有后缀但不在任何词典→`binary`（不靠 content-type 翻案） | 仅链接文本（`_link_body`→`fallback_quality='link'`） | 仅链接文本，不消费任何模态 |
| `unknown` | 无后缀且 content-type 未知 | 兜底 | 仅链接文本（`_link_body`→`fallback_quality='link'`），`on_native_fail='notice'` | 仅链接文本，不消费任何模态 |

要点：

1. **识别与能力判定分离**：本表只回答"URL 是什么"，不回答"当前模型是否支持"；`state/transport` 由 `plan_refs/state_of` 在请求前与发送前判定。
2. **后缀词典单一真源**：七类后缀词典全部由 `extract.py` 的 `IMAGE_SUFFIXES/VIDEO_SUFFIXES/AUDIO_SUFFIXES/RICH_SUFFIXES/TEXT_SUFFIXES` 提供，`contract.py` 只引用不复制。
3. **文档类归附件后续处理方法**：`richdoc/text` URL 与同名附件共用同一抽取器（`_richdoc_body`/`_text_body`，均支持 `(bytes, filename)` 入口），差异仅在来源（本地文件 vs 远端下载）。
4. **`unknown/binary` 只给链接文本**：二者无内容可抽，`fallback_quality='link'` 归 `opaque` 状态，前端徽标灰"仅链接"。

```python
# app/services/agent/capability.py （新增，纯函数）

@dataclass(frozen=True)
class NativeCap:
    native: bool          # 可发原生 part
    transport: frozenset  # {"inline"} / {"inline","url"} / ∅
    source: str           # measured | declared | none（仅展示/推荐标注，不改变请求模式）
    # 组合约束（唯一真源，计划器不自行判断 accept）：
    #   声明该模态 → native=True, transport={"inline"}（首选请求模式，失败由 on_native_fail 回退）
    #   measured  → 仅作为设置页参考/推荐标注；实测 accept∈{url,both} 额外解锁 transport="url"（运输优化，非模态准入）
    #   none      → native=False, transport=∅

def profile(llm_model) -> dict[str, NativeCap]:
    """image/audio/video/file 四模态能力画像。
    规则：
      - input_modalities 含 m → native=True, transport={"inline"}, source=declared（首选请求模式）；
      - media.accept[m] 实测存在 → 仅标注 source=measured 供设置页展示/推荐；
        实测 accept∈{url,both} 时 transport 增补 "url"（外链直传优化）；
      - 否则 native=False, source=none。
    实测探针不作为请求判定标准：样本缺失/过期/失效只影响展示，不影响请求模式。"""

def ref_capability_map(profile) -> dict[str, dict[str, str]]:
    """source_kind → {content_kind: native|degraded|opaque}（二维只读投影）。
    由 state_of 遍历全部 (source,content) 预计算；供前端索引与 23 preflight 复核。"""
```

### 3.3 能力画像：从 bool 到三级

| 状态 | 含义 | 判定 |
|---|---|---|
| `native` | 模型直接消费原始内容 | `profile[modality].native` |
| `degraded` | 模型读到内容文本或元数据 | 非 native 且 `fallback_quality ∈ {content, metadata}` |
| `opaque` | 模型只知文件名/大小 | `fallback_quality ∈ {card, link}` |

> `link` 专供 URL 来源：模型仅得到链接文本（无内容），归 `opaque`；`content/metadata` 归 `degraded`。状态由 `state_of(source_kind, content_kind, profile, transport_ok)` 判定，来源与内容一起进函数。

这张表直接回答 D3：**"降维可用"是一等状态，不再是 bool 的副产物。** 前端拿到的是 `(source_kind,content_kind)`→状态，不需要自己推。

### 3.4 计划器：唯一分流点

用 `classify_ref(item)` 复用上传时的唯一分类真源，**不新增字段、不查库、不复制词典**：

```python
source_kind, content_kind = classify_ref(item)
route = KIND_CONTRACT[(source_kind, content_kind)]
```

- `classify_ref` 对 attachment 用 `stored_path` 后缀（与上传时同一 `extract.classify`），对 file/selection 用 path，对 url 用 `classify_url`（后缀优先、content-type 兜底）；log/message 恒映射为 text；
- 返回**内容类型** `content_kind`，同时带出来源 `source_kind`；二者一起索引二维契约；
- P0 阶段（URL 尚未接入）处置结果与今天逐字节一致：只有附件 image 会进 native；URL 接入后的原生/降级规则见 [23] §4.4。

**识别与能力判定分离（C10）**：`classify_ref(item)` 与 `scan_text_urls(text)` 只回答"这是什么"，**不接收 `profile` / `model`，不因模型不支持而跳过，也不只识别图片**；同一输入在任何模型下得到的 `(source_kind, content_kind)` 完全一致。模型能力判断只发生在 `plan_refs/state_of`，由 [23] 在**请求前 preflight** 调用一次、发送前再调用一次（唯一权威），识别阶段不做任何"支持/不支持"判断。

### 3.5 运输层与安全守门

原生传输存在三重门槛，缺一不可：

```
native 可用 ⇔ 模型能力(声明模态) ∧ 方言支持 ∧ 载荷可获取(内联/公网URL)
```

- **模型能力**：见 3.3——以模型标注的输入/输出模态为准；
- **方言支持**：`to_wire_part` 按 `dialect` 产出；video 在 chat 方言无标准结构，只有适配器显式支持才产出；
- **请求模式定案**（关键）：
  - `image / file / audio / video` 声明即首选原生请求（不再设"必须实测"门槛）；
  - 原生请求失败 → `on_native_fail` 运行时回退（附件取 `ref.content`，URL 取链接文本），并回写失败观测供设置页参考；
  - 实测探针结果仅用于设置页展示与模型推荐，**不参与请求判定**（探针样本可能错误/过期/丢失，不能作为请求判据）。

**识别不参与这道门槛**：门槛只约束"怎么发"，不约束"认不认"。识别阶段对全部来源/类型无条件产出 `content_kind`；是否 native、是否外链、是否降级，全部在 `plan_refs/state_of` 用 `profile` 判定，且判定点在请求前与发送前，而非识别时。

**`transport` × `source` 组合约束（唯一真源在 `profile`，计划器只读）**：

| source | native | transport | 含义 |
|---|---|---|---|
| measured | true | {"inline"} | 实测支持内联 |
| measured | true | {"inline","url"} | 实测支持外链直传 |
| declared | true | {"inline"} | 声明模态即首选请求模式（内联）；实测 url 支持可增补 "url" |
| none | false | ∅ | 走文本降级 |

`transport_ok(item, cap)` 只读 `cap`，不自行判断 accept；`transport="url"` 仅当实测 accept ∈ {url, both}（外链直传属运输优化，无实测一律内联，不影响模态准入）。

原生失败时：附件等有本地内容的来源 `on_native_fail == "reuse_text"`，直接使用 `ref["content"]`（resolver 早已算好）插入文本，不重新读盘、不重新抽取；**URL 来源无 `ref.content`**，`on_native_fail == "link_text"`，降级为链接文本（`fallback_quality='link'`）。这同时解决了"原生化后丢降级"和"失败无回执"两个问题。

### 3.6 抽取出口契约与完整性标记（D6）

所有抽取器返回 `str` 的出口统一经过一个 helper：

```python
def with_completeness(body: str, *, shown: int, total: int,
                      unit: str, path: str) -> str:
    """截断时追加统一尾注；未截断原样返回。
    尾注格式：\\n[已截断：仅呈现 {shown}/{total} {unit}；完整内容请用文件工具读取 {path}]"""
```

适用：`_text_body`（256KB 头尾摘录）、`_sheet_text`（行上限）、`_richdoc_body`（分页/截断）、`_video_card`/`_audio_card`（元数据本身即摘要，标注"仅元数据"）。
守门测试对每个抽取器喂超限样本，断言输出含尾注。**D6 由测试锁定，不靠自觉。**

## 4. 应用模式与体验设计

### 4.1 体验三条铁律

1. **预见性**：发送前就能看到"这个文件在当前模型下会被怎样处理"，而不是发完才知道。
2. **一致性**：前后端对同一文件同一模型给出同一结论；结论来自同一张契约投影，不各自解释。
3. **无惊扰**：降级是常态，静默完成；只有"opaque（模型只能拿到文件名）"才用醒目但不阻塞的提示。发送永远不被阻断（除非用户开启严格模式）。

### 4.2 状态矩阵（前端展示的唯一依据）

> 下表为**附件/文件来源**的主矩阵；URL 来源的对应行见 [23] §7.3（同表只补 URL 行，不另建一套状态口径）。

| content_kind（附件来源） \ 状态 | native | degraded | opaque |
|---|---|---|---|
| text | — | — | —（始终作为完整文本注入，显示"文本"） |
| image | 绿 原生理解 | — | 灰 仅文件名 |
| richdoc | 绿 原生理解 | 蓝 文本抽取 | — |
| video | 绿 原生理解 | 蓝 仅元数据 | — |
| audio | 绿 原生理解 | 蓝 仅元数据 | — |
| binary | — | — | 灰 仅文件名 |
| unknown | — | — | 灰 仅链接/仅文件名 |

颜色/文案是表现层，可本地化；**状态值必须来自后端 `ref_capability_map`（二维投影）**。
richdoc/video/audio 行的"绿 原生理解"均带方言前提（§3.5：chat 方言无标准 file/video part，仅适配器显式声明支持时才出现绿），与"显式原因不制造虚假能力"同源。

### 4.3 场景走查

| 场景 | 现状 | 升级后 |
|---|---|---|
| 上传 PDF，模型无 file 能力 | 无提示，发后靠回执 | 抽屉行显示"文本抽取"，发送前一致 |
| 上传 PDF，模型声明 file 但未实测 | 可能整轮 400（若强行 native） | 首选原生发送，失败自动回退文本抽取（on_native_fail） |
| 上传 MP4 | 档案卡 | 蓝"仅元数据"（时长/分辨率/编码） |
| 上传 MP3 | 被拒或落 binary | 接收，蓝"仅元数据"（D1 闭环） |
| 引用图片后切到纯文本模型 | 图片卡（无内容） | 徽标实时变"仅文件名"，切模型即刷新 |
| 引用图片后切到视觉模型 | 绿 原生理解 | 同，且移除时不再残留占位 |
| 大文本/大表格被截断 | 末尾可能无提示 | 统一"已截断 N/M"尾注，预览可见 |
| 原生 part 发送失败 | 一行说明 | 自动改用已解析文本，回执说明降级原因 |

### 4.4 状态聚合函数（预检接口归 [23]）

本方案只提供**聚合函数** `aggregate_state(states) → worst`（`state_of` 派生，纯函数），不自建预检接口：

```
worst = aggregate_state([state_of(source_kind, content_kind, prof, ok) for item in items])
opaque → 黄色行内提示："以下输入当前模型只能拿到降级信息（附件仅文件名 / URL 仅链接文本）：xxx、yyy。可切换模型或继续。"
degraded → 无提示（蓝徽标已表达）
native → 无提示
```

- 附件/文件 chip 的状态由 model DTO `ref_capability_map`（二维投影）直接索引，无需请求；
- URL 与跨来源逐项状态由 [23] `POST /inputs/preflight` 返回 `items[].state` 与 `worst_state`（内部调用本函数）；
- 两条读取路径的**计算函数唯一**（`state_of`），守门测试断言二者相等。不弹窗、不阻断，符合"无惊扰"。

+    if modality == "video" and dialect == "chat":

+    if modality == "audio":

+    return None, f"该模态无 {dialect} 方言实现"

+    """载荷可获取性(0.2-6): url 直传; inline 需字节时按 route.fetch 调 remote_fetch。"""

+    return ({"modality": item.get("content_kind"), "mime": "", "data": raw, "url": None}, "") \
+        if raw else (None, reason)

+def _host_reject_reason(host: str) -> str:
+    """DNS 解析后逐 IP 判定: 拒私网/回环/保留(字面量判定拦不住 DNS 重指向)。"""
+    try:
+        infos = socket.getaddrinfo(host, None)

+    async with httpx.AsyncClient(follow_redirects=False, timeout=_TIMEOUT) as client:
+        while hops < _MAX_HOPS:

+            if resp.is_redirect:

`backend/tests/test_attachment_contract.py`：

1. **完备性**：`set(KIND_CONTRACT)` 覆盖全部 `source_kind × content_kind` 组合（含 `unknown`），无孤儿、无缺失。

## 12. 非目标与风险

### 12.1 明确不做（YAGNI）
- 不引入 OCR 让非视觉模型"读图"：image 的降级仍是档案卡；契约的 `extractor` 槽位已为未来 OCR 预留，但本期不实现。
- 不做"解析拖入即预览大图"等纯展示工程。
- 不为旧 token/旧函数保留双实现（禁止 backward）；用一次性数据迁移解决历史数据。

### 12.2 已知取舍
- **resolve 先于 plan**：原生路径也会先算一次抽取文本（浪费少量 IO）。换来的是"原生失败零重算"和"回执一致"。仅在性能画像证明必要时，才考虑 plan 前置 + 懒抽取（列为后续优化，不纳入本期）。
- **声明模态即首选请求模式**：file/audio/video 声明即按原生发送，失败由 `on_native_fail` 运行时回退兜底；实测探针仅作设置页参考与推荐标注，不参与请求判定。

### 12.3 风险
- 实测探针仅作设置页参考：样本缺失/数据过期失效只影响展示与推荐标注，不影响请求模式（声明模态即首选，失败才降级）。
- provider 方言差异：video 原生可能长期不可用；运输层已用"显式原因"表达，不制造虚假能力。
