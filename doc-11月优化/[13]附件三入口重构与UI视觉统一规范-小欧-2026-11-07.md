## 0. 结论摘要

| 项 | 定案 |
|---|---|
| 三个入口的本质 | 一个动作（把文件放进本轮）的**多种来源** + 一个仓库（合集） |

## 1. 问题与目标

### 1.1 现状的三个入口

```
附件（浏览器读字节 → 上传）
从本机导入（只传路径 → 后端读盘）
素材包（只存清单 → 投喂时送回引用区）
```

三者平铺在同一行，把「动作」和「仓库」放在同一层级，用户无法建立心智模型。

### 1.2 实测暴露的问题

| # | 级别 | 问题 | 根因 |
|---|---|---|---|
| 1 | 高 | 目录树点文件必 415 | 前端传相对 key，后端要求绝对盘符（`LocalImportButton.tsx:106` vs `local_import.py:101`） |
| 2 | 高 | 跨会话引用附件必 404 | 会话归属校验拦截（`MaterialPackPanel.tsx:106`） |
| 3 | 中 | 按钮行溢出，文字竖排 | `SubmitBar.tsx:59` 单行 flex 无换行 |
| 4 | 中 | 附件传完即失联 | `attachmentApi.list/remove` 前端零调用点 |
| 5 | 低 | 空态无引导、失败文案误导 | 「已失效」掩盖了真实原因 |
| 6 | 低 | 大小/类型看不到 | 素材库绕过资产表，只存路径快照 |

> 关键发现：`attachments` 表本来就存了 `original_name/mime/size/sha256/stored_path/created_at`。  
> 「大小/类型」不是没数据，而是**素材库没去读资产表**。这决定了修复方向：让素材库读资产表，而不是新建表。

### 1.3 设计目标

1. 用户不需要理解「上传 / 读盘 / 存清单」的技术差异。
2. 用户不需要手动保存任何东西，历史自动存在。
3. 同机时文件不传输字节，大文件也秒进。
4. 跨会话可复用，且不再出现 404。
5. 三个入口的视觉与交互统一到一套设计语言。

## 2. 设计原则与心智模型

### 2.1 三条原则

| 原则 | 含义 | 落地判定 |
|---|---|---|
| **一个动作** | 用户只做一件事：把文件放进本轮 | 不存在「上传」「导入」「投喂」三个动词 |
| **说人话** | 不用内部黑话 | 「投喂」「存包」「载入」全部禁用 |
| **不让用户为架构买单** | 会话/全局、字节/路径是系统的事 | 跨会话自动升级，不弹 404 让用户去「收藏」 |

### 2.2 心智模型

```
本轮文件（临时，发完清空）      ← 用户唯一需要理解的对象
      ↑ 加入
文件抽屉（系统知道的所有文件）   ← 按来源分组，不需要用户整理
      ├─ 本会话附件（自动）
      ├─ 本会话产物（自动）
      ├─ 他会话附件（自动）
      ├─ 项目文件（同机可读）
      ├─ 后端电脑（同机可读）
      └─ 收藏 / 合集（可选，唯一需要人动手的地方）
```

## 3. 术语统一表（全站强制）

| 旧用词 | 新用词 | 理由 |
|---|---|---|
| 引用区 / 当前引用区 | **本轮文件** | 屏幕上直接可见，主谓宾完整 |
| 附件（按钮） | **保留原名「附件」** | 已有元素直接复用；改名等于多出一个新按钮，与"不新增"冲突 |
| 从本机导入 | **本机文件**（抽屉内来源名） | 与「最近用过」「项目文件」并列，都是来源 |
| 素材包 | **合集** | 一册命名文件集合 |
| 存当前 | **新建合集** | 入口在抽屉左栏，动作即对象 |
| 投喂 | **加入本轮** | 去掉农事隐喻 |
| 引用 N · 发送到当前会话 | **本轮文件 · N 个 · 共 x.x MB** | 一眼知道是什么、有多少、多大 |

**禁用词**（代码注释除外）：投喂、存包、存当前、素材包、载入。

## 4. 信息架构

### 4.1 一个入口 + 自动路由

```
点 [ 📎 附件 ]
   │
   ├─ 判定同机（后端真实 IP 命中本机网卡）
   │     └─→ 自研文件浏览器（后端列盘，只传路径，0 传输）
   │           底部保留「改用上传」退路
   │
   └─ 判定跨机
         └─→ 系统文件选择框（浏览器读字节，HTTP 上传）
```

| 判定 | 数据流 | 用户感知 | 谁读文件 |
|---|---|---|---|
| 同机 | 只传路径，后端读盘 | 秒进，无进度条 | **后端** |
| 跨机 | 传字节 | 有上传进度 | 浏览器 |

**为什么必须分两条路**：浏览器的 `input[type=file]` 只给 `C:\fakepath\文件名`，任何 JS 拿不到真实路径。这不是可优化项，是浏览器内核行为。解法不是绕过沙箱，而是**换读取方**——同机时由后端列目录、后端读盘。

### 4.2 桌面结构（≥1280px）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 本轮文件 · 3 个 · 共 2.4MB                                  [清空]    │
│ [📄 诗歌.txt 224B ×] [📄 季度报告.pdf 2.1MB ×] [🖼 封面.png ×]   [+] │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  输入消息，Shift+Enter 换行…                                          │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│ [📎 附件]   [🕘] [⚡] [💬]   模型 ▾    插话    工作区 ①    [发送]     │
└──────────────────────────────────────────────────────────────────────┘
```

- 左端只有一个文字按钮「📎 附件」——**沿用 `AttachmentArea.tsx` 现有按钮，不新增任何按钮元素**，只把它从"上传触发器"改为"打开文件抽屉"。其余次要控件（历史输入 / 指令 / 续聊）改图标 + Tooltip。
- 模型选择保留文字（要看见当前模型），工作区保留文字（要看见计数）。
- 全屏只有「发送」是 `type="primary"`。

### 4.3 响应式

| 断点 | 行为 |
|---|---|
| ≥1280 | 全文字，如上图 |
| 1024–1279 | 历史/指令/续聊 → 图标 + Tooltip |
| <1024 | 工具行 `flex-wrap: wrap` + `row-gap: 8`；「附件」缩为纯图标按钮（仅 `PaperClipOutlined`，`aria-label="附件"`） |
| <768 | 文件抽屉全屏；本轮文件条最多 2 行，其余折叠为 `+N` |

### 4.4 入口落点：改造既有按钮，不新增控件

**定案**：不新增任何按钮。直接改造 `AttachmentArea.tsx:117-124` 已有的「📎 附件」按钮，让它点击后打开文件抽屉。

| 现状组件 | 位置 | 处置 |
|---|---|---|
| `AttachmentArea.tsx`「📎 附件」 | `SubmitBar` 的 `attachment` 插槽 | **保留**，`onClick` 由"触发上传"改为"打开文件抽屉" |
| `LocalImportButton`「从本机导入」 | 紧跟附件按钮 | **删除**，能力并入抽屉「项目文件 / 我的电脑」分栏 |
| `MaterialPackPanel`「素材包」 | `SubmitBar` 的 `rightExtra` 插槽 | **删除**，能力并入抽屉「收藏 / 合集」分栏 |

**为什么不改名**：

1. 改名（如「添加文件…」）在实现上就是新增一个按钮再删旧按钮，比直接改 `onClick` 多一次改动、多一次回归风险。
2. 「附件」是既有的、用户已经认识的词，且在本系统语境下没有歧义（不是邮件附件，就是给 AI 的文件）。
3. 按钮文字不承载"上传/读盘"的技术差异——差异由系统判定后的对话框体现，按钮只表示"我要加文件"。

**因此**：`SubmitBar` 的 `attachment` 插槽与 `rightExtra` 插槽中，最终只保留 `attachment` 一个（内部改为打开抽屉），`rightExtra` 归空。`SubmitBar` 本身仍是纯布局组件，不认识抽屉实现（SRP 不变）。

## 5. 自研文件浏览器（同机模式）

### 5.1 已有能力（不重写）

| 能力 | 现成端点 | 状态 |
|---|---|---|
| 列项目根目录树 | `GET /files/tree` | ✅ |
| 列项目根外任意目录 | `GET /files/external/tree?path=` | ✅ 只读 + 审计 + 盘符校验 |
| 文件名搜索 | `GET /files/search?q=` | ⚠ 限项目根，需加 `root` |
| 单文件 stat | `GET /files/stat` | ✅ |
| 同机判定 | `GET /attachments/local-capability` | ✅ 真实 IP vs 本机网卡 |
| 按路径导入 | `POST /attachments/import-local` | ⚠ 限项目根 + 会话工作区 |

**结论**：后端已具备 80%，只补三个小接口。

### 5.2 三个缺口

| 缺口 | 补法 |
|---|---|
| 不知道有哪些盘 | 新增 `GET /fs/drives`：盘符 + 卷标 + 总/剩余空间 |
| 能浏览但不能导入 | `_import_roots` 增加「用户授权目录」：首次从该目录导入时确认一次，写 SQLite 台账 `local_auth_dirs` + 审计日志，可撤销（**不写 `config.yaml`**：授权是运行时数据，写配置会引出新增配置键的三处同步） |
| 搜索限项目根 | `/files/search` 增加可选 `root`，命中上限 100、深度上限 6 |

### 5.4 规格

| 项 | 规格 |
|---|---|
| 路径栏 | 可编辑、可粘贴；`↑` 上级、`转到`（或回车）跳转；不存在/无权限的路径在列表区提示「无法打开…」 |
| 位置栏 | 常用位置（桌面/下载/文档，后端只下发**真实存在**的目录）+ 盘符（卷标；悬停显示「可用/共」容量）；均为 chip，窄屏自动换行 |
| 列表 | 单层不递归；目录优先、名称排序；列：名称 / 类型或大小 · 修改时间 |
| 选中 | **单击文件即导入**（与抽屉「点即加入」同一口径）；**不做** `Ctrl/Shift` 多选与底部确认条 —— 目录层级由「点目录进入」解决，无需"先选中再确认" |
| 搜索 | 防抖 300ms，`/files/search?root=当前目录`（深度 6、命中上限 100），结果显示绝对路径；目录命中点击即进入 |
| 授权 | 导入未授权目录 → 403 `LOCAL_READ_DENIED` → 弹**一次**确认 → `POST /fs/authorize` → 自动重试；已授权目录以 `Tag ×` 展示，可随时撤销 |
| 键盘 | 路径栏 `Enter` 跳转；列表 `↑↓` 移动焦点、`Space` 加入/移出、`Enter` 预览、`Backspace` 移出（P4 已实装，抽屉级统一监听，输入框内不拦截） |
| 性能 | 单层列目录（不递归扫描）；搜索受深度/命中双闸门 |
| 提示 | 顶部一行：「同机模式：直接读取本机文件，不传输、不占额外空间」 |
| 退路 | 顶部「上传文件」按钮（网络盘 / 权限不足 / 加密盘 / 跨机） |

> **v1.8 P2 实装偏离说明**：上表「选中」原定为"单击选中 + `Ctrl/Shift` 多选 + 底部 `[加入本轮 (N)]`"，
> 实装改为**单击文件即导入**。理由与 §6.3「点整行即加入」同源：抽屉内所有来源都遵循"点即生效"，
> 「我的电脑」若单独引入"选中 + 确认"两段式，同一面板出现两套心智模型；且授权确认已承担唯一必要的一次确认。
> 代价是多选要逐个点，换取的是零学习成本与代码直线（无选中态、无批量条、无确认按钮）。

### 5.5 安全边界

| 项 | 规则 |
|---|---|
| 前提 | 仅同机（真实 IP，XFF 仅在受信代理后采信且取最右一跳） |
| 路径 | 仅盘符绝对路径；拒 UNC、相对、符号链接、非普通文件 |
| 硬黑名单 | `.ssh`、`.aws`、`.gnupg`、凭据目录、`System32\config`、浏览器配置目录 |
| 授权 | 到目录粒度，可撤销；撤销不影响已导入的附件；台账落 SQLite `local_auth_dirs`（同机闸门后才可读写） |
| 审计 | 每次列目录 / 导入写日志（路径 + 会话 + 时间） |
| 大小 | `stat` 判大小后再读，读入字节复核（沿用现有实现） |
| 兜底 | 读失败自动回退上传并提示，不报错卡死 |

## 6. 文件抽屉（统一面板）

### 6.1 结构

```
┌ 附件 ────────────────────────────────────────────────────────── ✕ ┐
│ 🔍 搜索文件名…                                                      │
├──────────────┬─────────────────────────────────────────────────────┤
│ 本会话附件    │  ✓  📄 季度报告.pdf                         ☆   ⋯   │
│ 本会话产物    │        PDF · 2.1MB · 3 天前 · 已加入                │
│ 他会话附件     │     📄 旧稿.txt                             ★   ⋯   │
│ 项目文件      │        TXT · 12KB · 上周                           │
│ 后端电脑      │     🖼 封面.png                             ☆   ⋯   │
│               │        PNG · 340KB · 刚刚                          │
│ ───────────   │                                                     │
│ 收藏          │                                                     │
│  ★ 已收藏 (3) │                                                     │
│  📚 周报模板(4)│                                                   │
│  📚 设计参考(7)│                                                   │
│  ＋ 新建合集   │                                                    │
├──────────────┴─────────────────────────────────────────────────────┤
│ 已加入 2 项 · 共 2.4MB                                       [ 完成 ] │
└────────────────────────────────────────────────────────────────────┘
```

**读法（三件事，从左到右）**

| 区域 | 是什么 | 怎么用 |
|---|---|---|
| 左栏 | **从哪来**（最近 / 本会话 / 项目 / 我的电脑 / AI） + **收藏与合集** | 点一下切换当前列表 |
| 中间行 | 一个文件 | **点整行 = 加入本轮 / 取消**（左侧 `✓` 变实） |
| 行尾 `☆` `⋯` | 单文件操作 | `☆` 收藏；`⋯` 删除等低频操作 |
| 底部 | 当前已加入的数量与总大小 | `[完成]` 关闭抽屉（不需要保存） |


### 6.2 来源栏定义

| 栏 | 数据来源 | 说明 |
|---|---|---|
| **他会话附件** | `attachments` 中 `scope='session' 且 session_id≠当前 且 use_count>0 且 last_used_at ≥ 近 30 天` | 近 30 天在**其它对话**发送过的附件；自动产生，上限 200，可清空。排除本会话（归「本会话附件」）与全局资产（归「已收藏」）——四栏判据互斥，同一行不重复出现 |
| **本会话附件** | `attachments` 中 `session_id = 当前`（附件台账行：上传 / 导入 / 存为附件的副本） | 本会话的全部附件**实体**（不含引用——引用不落台账，只在输入框「本轮文件」区）；**发送后仍在**（附件是会话级资产，不清除） |
| **本会话产物** | `chat_tasks.artifacts`（任务产出物真源，全部任务，任务时间倒序） | 本会话 AI 任务**产出**的文件（工具成功时以 `with_artifact_file` 声明）；点行 = 根内引用源文件 / 根外存为附件。**不取 `attachments` 台账**（工作区内产物走引用模式从不落库，用台账判据取该清单恒为空） |
| **项目文件** | `GET /files/tree` | 项目根目录树，内嵌展开 |
| **后端电脑** | `GET /fs/drives` + `/files/external/tree` | **仅同机显示**（读后端进程所在机器的盘）；跨机时该栏替换为「上传文件」项 |
| **收藏** | `scope='global'`（`★` 星标）+ 合集表 | 唯一需要手动的地方：单文件星标 **1 击**、建合集 **1 击 + 回车** |

> **v1.7 P1 实装口径（与上表的差异，已按代码落地）**：P1 只实装 **本会话 / 项目文件 / 后端电脑 / 合集（含新建合集）** 四栏。
> 「最近用过」「收藏」「任务产物」三栏**推迟到 P3** —— 它们的判据是 `scope='global'` 与 `last_used_at`，
> 而当时后端 `resolver` 按 `get_attachment_scoped` 校验会话归属（B-03），跨会话附件必 404；
> 此刻上线收藏/最近用过即为死功能（点得动、用不了），故与 P3 的 promote 一并交付。**→ v1.9 P3 已全部实装（见 §14 P3 实装记录）。**

### 6.3 行为

| 行为 | 规格 |
|---|---|
| 点一行 | **立即加入本轮**：左侧空心 `○` → 实心 `✓`，行底变 `#e6f4ff`；再点取消。**没有复选框、没有确认、没有"投喂"按钮** |
| `☆` 收藏 | 单文件星标开关，**1 击生效，无弹窗、无输入框**；详见 6.5 |
| `⋯` 更多 | 低频操作：删除该文件（放在第二层，不抢主流程） |
| `＋ 新建合集` | 把「本轮文件」存成一个有名字的组；名字自动填，**回车即存**；详见 6.5 |
| 预览 | 点文件名 → 右侧预览抽屉（不占列表空间） |
| 容量预检 | 加入后超 20 项 → 拦截并提示"当前已加 N 项，上限 20" |
| 关闭 | 已加入的条目保留在本轮文件条中（关闭 ≠ 撤销） |

**核心**：抽屉里没有「确定」「保存」「投喂」——**点即生效，关即完成**。唯一需要"确认"的是建合集时按一次回车。

### 6.4 列表行规格

```
[✓/○] [类型图标 16] 文件名 14/500 #333                  [☆] [⋯]
                    类型 · 大小 · 来源 · 相对时间 12/400 #8c8c8c
```

| 状态 | 表现 |
|---|---|
| default | 透明底；左侧勾位为空心 `○`（24×24 热区） |
| hover | `#fafafa` 底；`☆` / `⋯` 由 60% 透明变常显 |
| 已加入 | 左侧 `✓` 主色 + 行底 `Colors.BG.SELECTED` `#e6f4ff` + 左边 2px `#1677ff`；次行追加 `· 已加入` |
| 已收藏 | 右侧 `★` 实心 `Colors.WARNING` `#AD6800`；未收藏为线框 `☆` `#8c8c8c` |
| 仅本会话 | 次行追加 `↑ 仅本会话`（12px 灰） |
| 失效 | `opacity .6` + `⚠ 源文件已不存在`（`#a8071a`），`☆` 置灰，`⋯` 只剩「移除」 |

> 行内**只有两个图标**：`☆`（收藏）与 `⋯`（更多）。不设复选框——整行就是开关，减少一次"先勾选再点按钮"的往返。

### 6.5 收藏 与 合集：在哪点、点几下（图解）

> 这一节回答"图标看不懂"的问题。两个动作都在**抽屉内部**，输入框下面**没有**任何相关按钮。

#### 6.5.1 一句话分清

| | 收藏 `☆` | 合集 `📚` |
|---|---|---|
| 操作对象 | **一个**文件 | **一组**文件 |
| 要不要起名字 | 不要 | 要（但自动填） |
| 成本 | 1 次点击 | 1 次点击 + 1 次回车 |
| 解决什么 | 这个文件我常要用，别被时间轴冲走 | 这几个文件是一套，下次一起发 |
| 能不能互相替代 | 不能。星标文件也可以属于多个合集 | 不能。合集里的文件也可以单独星标 |

#### 6.5.2 控件地图（先看清楚在哪）

```
┌ 附件 ────────────────────────────────────────────────── ✕ ┐
│ 🔍 搜索文件名…                                              │
├──────────────┬──────────────────────────────────────────────┤
│ ① 本会话附件   │  ②  ○  📄 季度报告.pdf        ③ ☆   ④ ⋯      │
│   本会话产物   │         PDF · 2.1MB · 3 天前                  │
│   他会话附件   │    ○  📄 旧稿.txt             ★    ⋯       │
│   项目文件     │         TXT · 12KB · 上周                     │
│   后端电脑     │                                               │
│ ───────────  │                                                │
│ ⑤ 收藏        │  ⑥ ★ 已收藏 (3)   ← 点它：只看星标文件         │
│   ⑥ 📚 周报模板(4) ← 点它：展开这组合集                     │
│   ⑥ 📚 设计参考(7)                                            │
│   ⑦ ＋ 新建合集  ← 唯一"创建合集"的入口                      │
├──────────────┴──────────────────────────────────────────────┤
│ 已加入 2 项 · 共 2.4MB                              [ 完成 ]  │
└─────────────────────────────────────────────────────────────┘
```

| 编号 | 控件 | 作用 | 说明 |
|---|---|---|---|
| ① | 左栏来源 | 切换"从哪来" | 本会话附件 / 本会话产物 / 他会话附件 / 项目文件 / 后端电脑 |
| ② | 行首 `○ / ✓` | **加入本轮** | 点**整行任意位置**都等于点这里；再点取消 |
| ③ | `☆ / ★` | **收藏** | 线框=未收藏，实心金=已收藏；再点取消 |
| ④ | `⋯` | 更多 | 删除该文件（第二层操作，不抢注意力） |
| ⑤ | 收藏分栏 | 分组标题 | 下面同时放"星标文件"和"合集" |
| ⑥ | `★ 已收藏(N)` / `📚 名字(N)` | 打开 | 点星标项→只看星标；点合集→展开该组文件 |
| ⑦ | `＋ 新建合集` | **建合集** | 把「本轮文件」整个存成一组；名字自动填，回车即存 |

#### 6.5.3 收藏：一次点击，无弹窗

```
① 鼠标移到行上                 ② 点 ☆                        ③ 左栏计数 +1
┌────────────────────────┐   ┌────────────────────────┐   ┌──────────────┐
│ 📄 季度报告.pdf  ☆  ⋯  │ → │ 📄 季度报告.pdf  ★  ⋯  │ → │ 收藏         │
│    PDF · 2.1MB · 3 天前 │   │    PDF · 2.1MB · 3 天前 │   │  ★ 已收藏 (3)│
└────────────────────────┘   └────────────────────────┘   └──────────────┘
        线框星 = 未收藏              实心星 = 已收藏              数字 +1
```

- **取消收藏**：再点一次 `★` → 变回 `☆`，计数 -1。
- **没有确认框、没有输入框、没有"保存"按钮**。
- 收藏后 `scope` 变为 `global`（跨会话可用），副本按 sha256 去重，不重复占盘。
- 取消收藏**不影响**已经发送过的历史，也不影响它属于哪个合集。

#### 6.5.4 合集：从「本轮文件」存一次，回车即完成

```
① 先把要存的文件加进本轮         ② 左栏点「＋ 新建合集」      ③ 名字已填好，直接回车
┌ 本轮文件 · 4 个 ──────────┐   ┌──────────────┐           ┌────────────────────────┐
│ [📄 周报.docx ×]          │   │ 收藏         │           │ 新建合集                │
│ [📄 数据.xlsx ×]          │ → │  ★ 已收藏(3) │        →  │ ┌────────────────────┐ │
│ [📄 要点.md ×]            │   │  📚 周报模板 │           │ │11月7日 · 4 个文件   │ │
│ [📄 图.png ×]             │   │  📚 设计参考 │           │ └────────────────────┘ │
└───────────────────────────┘   │  ＋ 新建合集 │           │      [取消]  [保存]    │
                                └──────────────┘           └────────────────────────┘
                                                              光标已就位，可改可回车
```

- **合集的原料永远是"本轮文件"**——这是唯一的建立方式，不需要第二套选择器。
- 名字自动填「{日期} · {N} 个文件」；不想改名就直接回车。
- 「＋ 新建合集」在本轮为空时置灰，Tooltip：「先把文件加入本轮」。
- 同名 → 409 → 就地提示「已有同名合集」+ `[改名]` `[追加进去]` 两个选项。

#### 6.5.5 合集：怎么用（单文件 / 整组）

```
左栏点「📚 周报模板」→ 列表只显示这组的 4 个文件
┌ 附件 ────────────────────────────────────────────────────── ✕ ┐
│ ← 返回   📚 周报模板 · 4 个文件              [ 全部加入本轮 ]    │
├────────────────────────────────────────────────────────────────┤
│  ○  📄 周报模板.docx   DOCX · 18KB · 10-27   ☆   ⋯             │
│  ○  📄 数据.xlsx       XLSX · 240KB · 10-27  ☆   ⋯             │
│  ○  📄 要点.md         MD · 3KB · 10-27      ★   ⋯             │
│  ○  🖼 图.png          PNG · 120KB · 10-27   ☆   ⋯             │
└────────────────────────────────────────────────────────────────┘
```

| 想要 | 怎么做 |
|---|---|
| 整组一起用 | 右上 `[全部加入本轮]`，1 击 |
| 只挑其中两个 | 点这两行（点行即加入） |
| 用完之后回来 | 左栏 `📚 周报模板` 始终在，不随时间轴消失 |

#### 6.5.6 合集：改、加、删

```
左栏合集行悬停 → ⋯
   ├─ 把本轮 4 个文件加进来      ← 追加：先在"本轮"选好，再从这里并入
   ├─ 重命名
   └─ 删除合集（文件本身保留，只删这个分组）
```

#### 6.5.7 什么时候用哪个（照着选就行）

| 你心里的想法 | 用哪个 | 点几下 |
|---|---|---|
| "这个文件我老用，别被时间冲走" | `☆` 收藏 | **1** |
| "这 4 个文件是一套，下周还要一起发" | `＋ 新建合集` + 回车 | **2** |
| "上次那套再加两个" | 合集 `⋯` → 把本轮文件加进来 | **2** |
| "我只想看自己挑了星的" | 左栏 `★ 已收藏` | **1** |
| "整组甩进去" | 合集 → `[全部加入本轮]` | **1** |
| "什么都不想管，就是想找上周那个" | 左栏 `他会话附件` / 搜索框 | **1** |

> **默认路径不需要任何操作**：只要在别的对话发过一次，文件就在「他会话附件」里。  
> 收藏和合集是**可选的加速器**，不是使用前提。

## 10. 交互流程

### 10.1 添加文件（点「附件」触发，自动路由）

```
点 [附件]
  ├─ 同机 → 自研文件浏览器 → 选文件 → 校验 → POST /attachments/import-local（只传路径）
  └─ 跨机 → 系统文件选择框 → 选文件 → 校验 → POST /attachments/upload（传字节）
       └─ 无会话先建会话（D1）→ 串行处理 → 每个成功即入本轮 chip
  失败：逐条报错，不整批回滚（已成功的保留）
```

### 10.2 召回（他会话附件）

```
点 [附件] → 左侧「他会话附件」→ 点一行 → 立即加入本轮
```
无需任何保存动作。记录点在后端 resolver 注入附件时（`use_count+1`、`last_used_at=now`），单一真源。
该栏只列**近 30 天**在**其它对话**发送过的附件：本会话的归「本会话附件」，已收藏的归「已收藏」。

### 10.3 收藏（可选，1 击）

```
点行尾 ☆ → 变 ★（1 击，无弹窗）
  → 后端把该附件 scope 升为 global（复制到全局目录，sha256 去重）
  → 左栏「★ 已收藏」计数 +1
再点 ★ → 取消收藏，计数 -1
```
- 线框 `☆` = 未收藏；实心 `★` = 已收藏。无二次确认。
- 取消收藏不影响已发送过的历史，也不影响它所属的合集。

### 10.4 合集（可选，2 击）

```
点左栏「＋ 新建合集」
  → 名字自动填「11月7日 · 4 个文件」
  → 回车（或点「保存」）
  → 左栏出现「📚 11月7日 · 4 个文件」，可重命名
```

| 项 | 规则 |
|---|---|
| 原料 | **只能是「本轮文件」**（唯一来源，不另设选择器） |
| 默认 | **不建合集也能正常用**，最近用过 + 搜索覆盖大多数场景 |
| 命名 | 自动填，只需回车；可改 |
| 同名 | 409，就地提示「已有同名合集」+ `[改名]` `[追加进去]` |
| 追加 | 合集行 `⋯` →「把本轮 N 个文件加进来」 |
| 使用 | 点合集展开 → `[全部加入本轮]`（整组）或点单行（单个） |
| 上限 | 单合集 10 个文件 |

### 10.5 跨会话

```
会话 A 上传报告.pdf → attachments(scope=session)
  → 会话 B 引用 → 后端发现 scope=session 且非本会话
  → 自动 promote：复制到全局目录 + 建 scope=global 行（sha 去重）
  → 返回新 id，前端入队成功（toast：已自动收藏）
```

- 用户不感知 404，不需要先「收藏」。
- 全局资产在会话删除时不受影响。

### 10.6 删除

| 对象 | 文案 | 磁盘 |
|---|---|---|
| 单条（全局） | 「删除「x」？其他会话将无法再引用。」 | 无其他行共享该路径时删文件 |
| 单条（会话级） | 「从本会话移除「x」？」 | 同上 |
| 合集 | 「删除合集「x」？文件本身会保留。」 | 无 |
| 清空最近使用 | 「清空最近使用记录？不会删除任何文件。」 | 只清 `use_count/last_used_at` |

## 11. 数据模型

### 11.1 不新建 assets 表

`attachments` 已具备 `id/original_name/mime/size/sha256/stored_path/created_at`，与资产字段重合 90%。  
新建同构表会导致长期双表同步（DRY 违）。结论：**`attachments` 加 3 列，升格为资产台账**。

### 11.2 表变更

**SQLite 无法 `ALTER` 去掉 `NOT NULL` / 表级 `UNIQUE` / `FOREIGN KEY`**，而 archive 需要「同 sha 的 session 行与 global 行并存」「全局资产不随来源会话删除」，故走**重建表**（`db_initializer._migrate_attachments_ledger`，幂等：已带 `scope` 且无会话外键则跳过）：

```sql
-- 目标形态（重建后的 attachments）
id TEXT PRIMARY KEY,
session_id TEXT,                                  -- 来源会话；global 行恒 NULL（原 NOT NULL 已放宽）
... 原 13 列不变 ...
scope        TEXT NOT NULL DEFAULT 'session',     -- session | global
last_used_at TEXT,                                -- 注入时间（resolver 记账）
use_count    INTEGER NOT NULL DEFAULT 0           -- 注入次数（「最近用过」判据）
-- 无 FOREIGN KEY(session_id) → chat_sessions：会话删除不带走全局资产

-- 唯一性改由两个「部分索引」承担（同 sha 的 session/global 行可并存）
CREATE UNIQUE INDEX idx_attachments_dedup
  ON attachments(session_id, sha256) WHERE scope = 'session';
CREATE UNIQUE INDEX ux_attachments_global_sha
  ON attachments(sha256) WHERE scope = 'global';
CREATE INDEX idx_attachments_scope_used
  ON attachments(scope, last_used_at DESC);
```

重建时按 `PRAGMA table_info` 逐列搬运（缺列补默认值），四类索引统一由 `_create_attachment_indexes` 幂等补建；历史重复行按组保留最早一条。

**语义订正**（写入代码注释）：`session_id` 表示**来源会话**，不再作为访问判定字段；`scope='global'` 对所有会话可读。

### 11.3 全局文件落盘

```
{data_dir}/assets/{YYYYMM}/{sha256[:16]}-{safe_name}
```

- `data_dir` 复用 `resolve_db_dir()`（`OMNIAGENT_DATA_DIR` → 默认 `~/.omniagent`）。
- 不能放会话工作区下（会话删除会带走全局资产）。

### 11.4 promote（升级为全局）

```
promote(id):
  if row.scope == 'global': return row                       # 幂等
  if exists(global AND sha256 = row.sha256): return that id  # 去重，不复制
  copy(stored_path → assets/...)                             # shutil.copy2
  insert attachments(scope='global', session_id=NULL, ...)    # 部分唯一索引兜并发
  return new id
```

- 并发收口：`INSERT` 被 `ux_attachments_global_sha` 拦下 → 回查幸存行复用；仅当幸存行**不指向同一磁盘路径**时才清理本次副本（同 sha 同名时目标路径必然相同，删了就是删幸存行的文件）。
- 触发点两处共用同一实现：`☆` 收藏（`POST /attachments/id/{id}/promote`）与跨会话发送链（`get_attachment_scoped(auto_promote=True)`——仅 `GET /id`（发送预检/引用入队）与 resolver 注入）。纯预览端点 `/raw`/`/text` 走严格校验（`auto_promote=False`），读不产生写副作用（2026-11-07 三堂会审口径）。
- 列表行补三个派生字段：`available`（磁盘文件是否还在）、`favorited`（同 sha 是否存在 global 行）、`global_id`（该 global 行 id，前端取消收藏按此 DELETE）。

### 11.5 合表不变

`material_pack_items(pack_id, seq, path, label, kind, attachment_id)` 保持不变：
- `kind='attachment'` → 指向 global 资产 id。
- `kind='file'` → 项目文件路径快照（不复制）。
- 类型/大小展示时 JOIN `attachments`；file 类型显示「—」。

删除语义（`delete_attachment`）：
1. 访问权：`scope='global'` 任意会话可删；`session` 行限本会话（不匹配 404）。
2. 被 `material_pack_items` 引用（条目身份=`attachment_id` 优先；无 aid 存量条目按写入时同源的 `rel_to_root` 相对路径命中）且 `force=false` → 409 `ATTACHMENT_IN_USE`。
3. `purge=true` 时按 `stored_path` 计数：仅当无其他行共享该路径才删磁盘文件，随后清合集条目。

新增错误码：
- `ATTACHMENT_NOT_AVAILABLE`（410）— 行在但磁盘文件不存在
- `ATTACHMENT_IN_USE`（409）— 删除被合集引用且未确认
- `LOCAL_READ_DENIED`（403）— 未授权目录 / 跨机访问

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 全局资产占盘 | 磁盘增长 | sha256 去重；最近用过只记元数据；抽屉显示总占用 |
| 跨会话放行越权 | 安全 | 仅 `scope='global'` 放行；`session` 级仍严格校验 |
| 同机误判（Docker/WSL） | 用户看到错误的盘 | `local-capability` 返回 `host_label`，抽屉标题显示「我的电脑 · {hostname}」 |
| 授权目录过宽 | 敏感文件入系统 | 硬黑名单 + 目录粒度授权 + 审计日志 + 可撤销 |
| 术语替换不彻底 | 半新半旧更困惑 | P0 一次性替换，`grep` 校验旧词零残留（注释除外） |
| 删除共享文件 | 其他行失效 | 删除前按 `stored_path` 计数，>1 只删行不删文件 |
| 存量库迁移失败 | 启动失败 | `_ensure_column` 幂等 + 唯一索引单独 try |
