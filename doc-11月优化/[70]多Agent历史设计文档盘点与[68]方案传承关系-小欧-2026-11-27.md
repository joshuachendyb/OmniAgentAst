## 2 关键发现：[68] 与 D11 一脉相承

D11（2026-06-05，小欧）的核心决策与 [68]（2026-11-27）逐条对照：

| D11 决策（v3.0 依据） | [68] 对应 | 一致性 |
|----------------------|-----------|--------|
| delegate_to_agent 是**普通工具**，不是管家方法（§7 决策） | delegate_to_agent 是 AGENT 分类下的普通 tool | ✅ 完全一致 |
| AgentTemplate：name/role/allowed_tools/can_delegate | AgentConfig：agent_id/tool_categories/allow_delegate | ✅ 同构，[68] 简化掉 role/engine/memory_layers |
| SubAgent 成本归父（§5.6） | usage 合并到父 Agent accumulated_usage | ✅ 完全一致 |
| can_delegate=False 防递归 | allow_delegate=False + 工具集剔除 AGENT 分类 | ✅ 完全一致 |
| 4 角色模板（executor/manager/dispatcher/distiller） | 内置 3 Agent（researcher/reviewer/kb_analyst） | ⚠️ 语义不同：D11 按职能角色，[68] 按业务场景 |
| 消息总线（内存队列→Redis→Kafka） | P0 不做，[69] 列为 P2+ 群聊升级路径 | ✅ 分期一致 |
| Memory 隔离（private/team/global） | P0 子 Agent 不继承父历史（天然隔离） | ✅ P0 等价实现，分级共享留 P2+ |
| Router 任务分发 | 主 Agent LLM 自主决定调 delegate_to_agent | ✅ 一致（LLM 自主 > Router 裁决） |

**结论**：[68] 不是新发明，是 D11 决策在 OmniAgent 现有代码基座上的**落地版**——同一作者（小欧）时隔半年、砍掉未验证的重型件（4角色/Router/消息总线/TaskCard状态机）、只保留已验证的最小核心。

## 3 历史方案为什么全部搁浅

| 死因 | 证据 |

| **[74] 建议正式废弃** | 9月对照总结建议废弃多 Agent 架构 |

## 4 [68] 相对历史方案的取舍

| 维度 | 历史方案（D11/TaskAgent v4.5） | [68] 落地版 | 理由 |
|------|------------------------------|-------------|------|
| Agent 定义 | AgentTemplate 薄壳（身份/契约/状态） | AgentConfig dataclass（10 字段） | KISS：契约 schema/SLA 无消费方，YAGNI 砍掉 |
| 角色体系 | 4 固定角色 | 3 业务场景 Agent + 插件 manifest | 角色是研究概念，场景才对应真实用例 |
| 任务分发 | TaskCard + 状态机 + Router | task 字符串自包含（≤500字） | 状态机无消费方；ReAct 循环自带状态推进 |
| 子 Agent 执行 | 独立 Session + 推理引擎绑定 | 复用 UniversalAgent + run_react_cycle | 现有代码已支持 initial_categories，零新抽象 |
| 消息总线 | P0 即设计（内存队列起步） | P2+ 再做（[69] 升级路径） | 先验证单发委托有真实收益 |
| 工具集 | allowed_tools 工具名列表 | tool_categories 分类 + tool_names 可选覆盖 | 与现有 ToolLoader 分类注入机制对齐 |

## 5 结论

| 问题 | 回答 |
|------|------|
| [68] 与历史设计冲突吗？ | 不冲突。核心决策（delegate_to_agent=普通工具、成本归父、防递归、LLM 自主分发）与 D11/v3.0 §7 逐条一致 |
| [68] 推翻了 [74] 的废弃建议吗？ | 部分推翻：[74] 废弃的是重型多 Agent 架构（4角色/Router/消息总线），[68] 保留的只是其中最轻的委托核心，4 文件 + 4 改动即可落地 |
| 历史文档还有效吗？ | D11/v3.0/v4.5 的决策记录仍是 [68] 的设计依据；TaskAgent 三部曲（600KB）的重型件（TaskCard/Router/4角色）确认不实施 |
| 插件/Skill 通道有历史依据吗？ | 有。v4.5 "LLM 通过 delegate_to_agent 自主委托" 与 [68] §6 manifest 注册为 AgentConfig 是同一条路线 |
