## 1 问题分析

### 1.1 事故现场（可复核的硬证据）

现场进程：`OmniAgentBackend.exe`，pid 412，启动时刻 21:18:41，卡死起始 22:36:52（单工具执行 `tool=bash`，命令为 `python -m pytest tests/test_inputs_preflight.py -q -x --timeout=60`）。

py-spy 抓到的真实栈（`py-spy dump --pid 412 --nonblocking --locals`）：

```
Thread 23548 (idle): "shell-exec-7"
    __init__ (subprocess.py:1029)
    popen_init (utils\spawn_gate.py:256)
    shell (tools\fundamental\execute_shell_command.py:1302)
    <lambda> (tools\tool_retry_engine.py:282)
    _run (utils\workers.py:52)
```

该帧 locals 同时给出四个事实：

- `processed_command = "python -m pytest tests/test_inputs_preflight.py -q -x --timeout=60 2>&1 | Select-Object -Last 20"`
- `_slot_acquired = True`、`_remaining = 599.9998042`（并发名额已拿到，600s 超时一秒未消耗）
- `pwsh_exe = "E:\Appsw\powershell7\7\pwsh.exe"`（解释器定位已完成）
- **没有 `_iso` 这个局部变量**

结论：栈停在 `subprocess.Popen.__init__` 内部（即 `_winapi.CreateProcessW`），而不是 `drain_until_exit`；600s 超时只约束读管道，对创建进程一步没有任何约束。

### 1.2 为什么「py 已更新」而运行不生效

先比对磁盘代码（`G:\OmniAgent-SPA\_internal\app` 对 `F:\OmniAgentAs-01\backend\app`，逐文件 sha256）：

- py 文件数：开发 396，运行 395。
- 内容不同仅 2 个：`main.py`、`services\refs\render.py`（均为 `[23]阶段A inputs` 改动，与卡死无关）。
- 仅开发有：`api\v1\inputs.py`、`services\inputs\preflight.py`；仅运行有：`services\agent\vision.py`。
- `execute_shell_command.py`、`spawn_gate.py`、`proc_io.py`、`tool_retry_engine.py` 的 sha256 完全一致。

**磁盘上运行目录确实已经是修复后的代码**。但同一份文件对 git 历史做行号核对：

- `353f3116a^` 版本的 Popen 起始行：1278 / 1308 / 1342；
- 当前工作区版本的 Popen 起始行：1309 / 1340 / 1374；
- 运行中进程的栈帧：**1302**。

两个版本都不存在 1302 这处 Popen。同时 `_iso` 在 1293 行（新代码）必被赋值，而现场 locals 里没有它。两条证据（行号 + 变量）互不依赖，同时指向同一个结论：**pid 412 运行的模块对象是进程启动时导入的旧版源码，不是磁盘上现在这份**。

生效机制的真相：

- `OmniAgentBackend.spec:55` 以 `Tree(...)` 把 `backend/app` 整棵源码树拷入 `_internal/app`；
- `run_server.py:196` 在 frozen 时执行 `sys.path.insert(0, sys._MEIPASS)`，随后 `import app.main`，业务代码按**普通源码**导入；
- 只有 bootloader 与 `run_server.py` 冻结在 exe 的 PYZ 里。

所以「改 app 下的 py」不需要重编译 exe，但**必须重启进程**；正在跑的进程永远用旧模块对象。

再解释 mtime 悖论：运行目录 `_internal/app/**` 的文件 mtime 是 21:04:43（早于进程启动 21:18:41），内容却是修复后的 —— 因为部署脚本用 `shutil.copy2`，它保留源文件 mtime。`copy2` 复制发生在 21:18 之后，覆盖了进程已经导入过的磁盘文件，但改不了进程内存。**mtime 不能作为「有没有换代码」的证据，只有内容哈希可以。**

### 1.3 为什么 `353f3116a` 的隔离修复必然无效（三个硬事实）

事实一：`CREATE_NO_WINDOW` 仍会分配一个隐藏控制台。实测：用该 flag 起的 pwsh（pid 22572）名下存在 conhost 子进程（pid 13696）。`CREATE_NO_WINDOW` 只是不显示窗口，控制台设备对象照样创建，`GetConsoleMode` 一类 IOCTL 照样会被走到。

事实二：现场卡住的两个 pwsh（16180、20072）**没有** conhost 子进程，说明它们创建时 `creationflags=0`，直接继承了父进程（pid 412）的 conhost 16388。这正是旧代码的行为。

事实三：`spawn_gate.py` 自己记录了「`CreateProcessW` 持锁不释放 GIL」。CPython 的 `_winapi.CreateProcess` 是未放开 GIL 的 C 调用。一旦卡在这个 IOCTL 里，**整个解释器冻结**：看门狗线程、faulthandler、join 超时逻辑、`/health` 全部拿不到 GIL。

由此直接推翻两个流行方案：

- 「给 Popen 创建套线程 + `join(timeout)`」——join 的主线程自己也需要 GIL，卡死时它根本执行不到超时判断。
- 「`CREATE_NO_WINDOW` + `STARTF_USESTDHANDLES` 止血」——不改变控制台对象存在这一前提，只是换了个不显示的控制台。

剩下的唯一根因消除手段是：**让父进程根本不拥有控制台**，或**让创建进程这个动作不在主解释器里发生**。

### 1.4 三条根因

- R1（工程纪律）：部署与运行之间没有指纹校验。改了磁盘、没重启、或用 `copy2` 覆盖后 mtime 反而更旧，任何一方都无法自证「我跑的是哪份代码」。本次事故的全部排查成本都来自这一点。
- R2（技术根因）：打包产物 `console=True`，父进程绑定 conhost，`CreateProcessW` 走控制台 IOCTL 时可在不释放 GIL 的情况下无限阻塞，形成全站僵死。
- R3（架构缺陷）：创建子进程的代码分散在 5 个文件，各自设置 flags，没有单一入口、没有创建阶段超时、没有统一的「卡死隔离边界」。

### 1.5 对 [41] 文档的结论修正

- 修正：「exe 没有更新」→ 实际是「磁盘已更新、进程未重启，运行的是旧模块」。
- 修正：「三处 flag 已止血」→ 实测 `CREATE_NO_WINDOW` 不消除控制台对象，不能止血。
- 保留：租约式闸门、看门狗、`drain_until_exit`、零线程管道读取等既有设计，本方案不改动这些。
- 补充：[41] 的进程宿主方向（shell 执行外置）判断正确，本文给出可落地的接口与代码骨架（P3）。

## 2 实施方案

### 2.1 阶段划分与判据

四个阶段，按「见效速度 / 改动成本」排序。P0、P2 只改 py，重启即生效，不需要重编译 exe；P1、P3 需要重新打包。

- P0 止血（当天可上）：frozen 启动即 `FreeConsole()`，stdio 重定向到日志。父进程不再持有控制台，R2 的触发条件当场消失。
- P1 根因（下次打包）：spec 改 `console=False`，把无控制台作为默认形态；同时补齐启动期所有裸 `print` 的容错。
- P2 纪律（当天可上）：运行代码指纹落盘 + `/health` 暴露 + 部署脚本校验，R1 永久关闭。
- P3 兜底（下个迭代）：shell 执行外置到独立宿主进程，主解释器零 `CreateProcessW`，R3 从架构上消除；即使将来出现别的控制台/loader lock 触发源，也只卡宿主，重启宿主即可。

判据（每阶段独立验收，不达标不进入下一阶段）：

- P0：卡死复现脚本（连续 30 次 `pwsh -Command "$PSVersionTable"` + 20 并发）全绿，`/health.spawn.popen_max_ms < 100`。
- P1：双击 exe 无窗口、日志完整、端口冲突提示可读。
- P2：dev / 打包 / 部署目录三处 `/health.build.modules` 完全一致。
- P3：宿主进程被 `Stop-Process -Force` 后，主服务 5s 内自愈并返回明确错误，`/health` 不超时。

### 2.2 P0 止血：启动即脱离控制台（只改 py）

```python
【问题】打包版 console=True 启动即绑定 conhost; 子进程默认继承该控制台句柄,
CreateProcessW 在 GetConsoleMode 的 IOCTL 内可无限阻塞且不释放 GIL(CPython 的
_winapi.CreateProcess 未放开 GIL) —— 解释器整体冻结, 看门狗/心跳一并停摆,
只能杀进程。实测 CREATE_NO_WINDOW 仍会分配隐藏控制台, 不能消除该前提。

【做法】frozen 且本进程仍持有控制台时: FreeConsole() 摘掉关联, 随后把
sys.stdout / sys.stderr 重定向到 logs/boot_YYYY-MM-DD.log, sys.stdin 指向 NUL。
父进程不再持有控制台 → 子进程无从继承 → 该 IOCTL 分支不再被触发。

【边界】FreeConsole 只解除本进程与 conhost 的关联, 不负责结束 conhost 进程;
彻底形态由打包 console=False 承担(P1)。本函数与 P1 叠用时 FreeConsole 返回 0,
直接返回, 幂等无副作用。环境变量 OMNI_KEEP_CONSOLE=1 可关闭本行为(排障用)。
"""
import ctypes
import os
import sys
import time

_applied = False


def _boot_log_path():
    from app.logger import LOG_DIR
    return LOG_DIR / f"boot_{time.strftime('%Y-%m-%d')}.log"


def _redirect_stdio():
    try:
        fp = open(_boot_log_path(), "a", encoding="utf-8", buffering=1)
    except OSError:
        fp = open(os.devnull, "w", encoding="utf-8", buffering=1)
    sys.stdout = fp
    sys.stderr = fp
    sys.stdin = open(os.devnull, "r", encoding="utf-8")


def detach_console_if_needed() -> None:
    """frozen 且有控制台时脱离控制台(幂等); 返回后所有 print 落 boot 日志。"""
    global _applied
    if _applied or sys.platform != "win32":
        return
    _applied = True
    if not getattr(sys, "frozen", False):
        return
    if os.environ.get("OMNI_KEEP_CONSOLE") == "1":
        return
    if not ctypes.windll.kernel32.FreeConsole():
        return      # 本来就没有控制台(或已脱离): 不碰 stdio
    _redirect_stdio()
    print("[console_mode] 已脱离父控制台, stdio 重定向到 boot 日志", flush=True)
    print(f"[console_mode] path={_boot_log_path()}", flush=True)
```

### 2.4 P2 纪律：运行代码指纹闭环

新增 `backend/app/utils/build_fingerprint.py`：

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: 运行代码指纹(frozen/app_root/关键模块哈希), 落盘 + /health 暴露
"""build_fingerprint — 运行代码指纹 — 小欧 2026-11-15

【问题】app/ 以源码树放入 _internal/app, 改 py 只需重启生效; 但只要出现
"改了磁盘没重启" 或 "copy2 覆盖后 mtime 更旧", 任何一方都无法自证跑的是哪份代码,
2026-11-15 pid 412 事故的排查成本全部来自这一点(mtime 完全不可用作证据)。

【做法】启动时对关键模块算 sha256(前 16 位)并记录 frozen/_MEIPASS/pid/exe 大小,
落一条 INFO 日志, 同时经 /health.build 暴露。dev、打包、部署目录三处比对同一组哈希,
不一致即可判定"运行的不是你以为的那份代码"。
"""
import hashlib
import os
import sys
import time
from pathlib import Path

from app.logger import logger

_KEY_MODULES = (
    "tools/fundamental/execute_shell_command.py",
    "tools/fundamental/shell_background.py",
    "utils/spawn_gate.py",
    "utils/proc_io.py",
    "utils/proc_utils.py",
    "utils/console_mode.py",
)

_snapshot = None


def app_root() -> Path:
    return Path(__file__).resolve().parent.parent


def _file_sha16(path: Path) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as fp:
        for chunk in iter(lambda: fp.read(1024 * 1024), b""):
            h.update(chunk)
    return h.hexdigest()[:16]


def _exe_info():
    if not getattr(sys, "frozen", False):
        return None
    exe = Path(sys.executable)
    st = exe.stat()
    return {"path": str(exe), "size": st.st_size, "mtime": int(st.st_mtime)}


def build_snapshot(force: bool = False) -> dict:
    """关键模块指纹(进程内缓存; 强制刷新只在部署校验脚本里用) — 小欧 2026-11-15"""
    global _snapshot
    if _snapshot is not None and not force:
        return _snapshot
    root = app_root()
    modules = {}
    for rel in _KEY_MODULES:
        path = root / rel
        modules[rel.replace("\\", "/")] = (
            {"sha256": _file_sha16(path), "size": path.stat().st_size,
             "mtime": int(path.stat().st_mtime)}
            if path.is_file() else {"missing": True}
        )
    _snapshot = {
        "frozen": bool(getattr(sys, "frozen", False)),
        "app_root": str(root),
        "meipass": getattr(sys, "_MEIPASS", ""),
        "exe": _exe_info(),
        "pid": os.getpid(),
        "detected_at": time.strftime("%Y-%m-%d %H:%M:%S"),
        "modules": modules,
    }
    return _snapshot


def log_build_fingerprint() -> None:
    """启动期落一条完整指纹: 部署核对的第一证据 — 小欧 2026-11-15"""
    snap = build_snapshot(force=True)
    parts = [f"{k}={v.get('sha256', 'MISSING')}" for k, v in snap["modules"].items()]
    logger.info(
        f"[构建指纹] frozen={snap['frozen']} app_root={snap['app_root']} "
        f"meipass={snap['meipass']} pid={snap['pid']} exe={snap['exe']}")
    logger.info("[构建指纹] " + " ".join(parts))
```

### 2.5 P3 兜底：shell 执行外置宿主进程

目标：主解释器永不调用 `CreateProcessW`。即使将来出现新的控制台/loader lock 触发源，冻结范围也只在一个可抛弃的子进程内。

新增宿主服务 `backend/app/utils/shell_host.py`（由 `proc_spawn` 以子进程方式拉起，独立于 uvicorn）：

```python
# -*- coding: utf-8 -*-

# 2026-11-15 - 小欧 - 新建: shell 执行宿主(命名管道 + JSON 行协议), 主进程零 CreateProcessW
"""shell_host — shell 执行宿主进程 — 小欧 2026-11-15

【为什么要独立进程】CreateProcessW 卡在控制台 IOCTL 时不释放 GIL, 任何同解释器内的
线程(含 join 超时逻辑、看门狗、faulthandler)都无法执行。唯一能"卡住而主服务不受影响"

【协议】命名管道 \\.\pipe\omni-shell-<host_pid>, 每行一个 JSON:
  请求 {"id": int, "argv": [...], "cwd": str|null, "env": {..}|null, "timeout": float|null}
  输出 {"id": int, "stream": "out"|"err", "b64": "..."}  (分块, 不限次数)
  结束 {"id": int, "rc": int, "timed_out": bool, "pid": int}

宿主自身以 DETACHED_PROCESS 启动, 不持有控制台。

import json
import os
import subprocess
import sys
import threading
import time

MULTI = threading.Semaphore(int(os.environ.get("OMNI_SHELL_HOST_CONCURRENCY", "8")))
_pipe = None
_lock = threading.Lock()
_host_pid = None


def _spawn_host():
    global _pipe, _host_pid
    exe = sys.executable
    argv = [exe, "-m", "app.utils.shell_host"] if not getattr(sys, "frozen", False) else [exe, "--shell-host"]

    proc = subprocess.Popen(argv, stdin=subprocess.DEVNULL, stdout=subprocess.DEVNULL,
                            stderr=subprocess.DEVNULL, creationflags=creationflags,
                            close_fds=True)
    _host_pid = proc.pid
    pipe_name = rf"\\.\pipe\omni-shell-{proc.pid}"
    import win32pipe  # 依赖 pywin32(已在 requirements? 需确认; 缺则用 ctypes 实现)

                pipe_name, win32pipe.PIPE_ACCESS_DUPLEX,
                win32pipe.PIPE_TYPE_BYTE | win32pipe.PIPE_READMODE_BYTE | win32pipe.PIPE_WAIT,
                1, 65536, 65536, 0, None)
            return _pipe
```

### 2.6 五处 Popen 统一入口改造

新增 `backend/app/utils/proc_spawn.py`，把「隔离参数」从 `execute_shell_command.py` 迁出，并作为全仓唯一出口：

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: 子进程创建唯一出口; 隔离参数自 execute_shell_command 迁入(DRY)
"""proc_spawn — 子进程创建唯一出口 — 小欧 2026-11-15

唯一职责: 给所有 Popen 注入同一组"不继承父控制台"的参数, 并提供唯一的 spawn 包装
(留统一日志与指标)。新增子进程调用一律走 spawn(), 不得再直接 subprocess.Popen。
"""
import subprocess
import sys
from typing import Any, Dict

from app.logger import logger

__all__ = ["isolation_kwargs", "spawn"]


def isolation_kwargs() -> Dict[str, Any]:
    """子进程不继承父控制台的 Popen 公共参数(仅 Windows 非空)。

    1) CREATE_NO_WINDOW: 不显示窗口(仍会分配隐藏控制台, 故只是必要条件不是充分条件);
    2) stdin=DEVNULL: 不继承控制台输入句柄(输入缓冲区串行独占, 读到即挂);
    3) STARTF_USESTDHANDLES: 标准句柄只认调用方给的管道/NUL, 不回落父控制台。
    父进程无控制台(P0/P1)时这组参数退化为普通创建, 无副作用。
    """
    if sys.platform != "win32":
        return {}
    startupinfo = subprocess.STARTUPINFO()
    startupinfo.dwFlags |= subprocess.STARTF_USESTDHANDLES
    return {
        "stdin": subprocess.DEVNULL,
        "creationflags": subprocess.CREATE_NO_WINDOW,
        "startupinfo": startupinfo,
    }


def spawn(args, **kwargs):
    """唯一 Popen 出口: 自动补齐隔离参数, 其余参数原样透传。"""
    merged = isolation_kwargs()
    merged.update(kwargs)              # 调用方显式参数优先(如自己的 creationflags)
    logger.debug(f"[proc_spawn] {args!r}")
    return subprocess.Popen(args, **merged)
```

## 附录 A 控制台隔离模式 A/B 探针

上面所有结论中，只有「`DETACHED_PROCESS` + 显式三句柄能否稳定跑 pwsh」未经本地实测（纯 `DETACHED_PROCESS` 实测 pwsh 会立即退出，故 P0/P1 未采用它作为主路径）。落 P3 前必须先跑这个探针，读结果再定宿主的创建参数：

```python
# E:\test_dir\20261114-230717-14e5\probe_console_modes.py
import subprocess
import sys

PWSh = r"E:\Appsw\powershell7\7\pwsh.exe"
MODES = {
    "inherit": 0,
    "no_window": subprocess.CREATE_NO_WINDOW,
    "detached": subprocess.DETACHED_PROCESS,
    "detached_group": subprocess.DETACHED_PROCESS | subprocess.CREATE_NEW_PROCESS_GROUP,
    "new_console": subprocess.CREATE_NEW_CONSOLE,
}

for name, flags in MODES.items():
    si = subprocess.STARTUPINFO()
    si.dwFlags |= subprocess.STARTF_USESTDHANDLES
    try:
        p = subprocess.run(
            [PWSh, "-NoProfile", "-Command", "'ok'; Get-Process -Id $PID | Select-Object -Expand SessionId"],
            stdin=subprocess.DEVNULL, stdout=subprocess.PIPE, stderr=subprocess.PIPE,
            creationflags=flags, startupinfo=si, timeout=20)
        con = subprocess.run(["tasklist", "/FI", f"PID eq {p.returncode}", "/FO", "CSV"],
                             capture_output=True, text=True).stdout.strip().splitlines()
        print(f"{name:16s} rc={p.returncode} out={p.stdout.strip()!r} err={p.stderr.strip()[:80]!r}")
    except Exception as e:
        print(f"{name:16s} EXC {type(e).__name__}: {e}")
```

判定标准：`detached` 与 `detached_group` 两种模式下 pwsh 能返回 `ok` 且不残留进程，才可作为 P3 宿主的创建模式；否则 P3 沿用 `no_window`（此时宿主靠「父进程无控制台」这一前提保证安全）。
