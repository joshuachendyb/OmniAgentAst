## 一、问题与结论

### 1.1 问题

生成图片、生成视频两个工具的 tool_result 里，data（执行结果 result）装的到底是什么：厂商返回的公网 URL，还是落盘到本地的图片/视频文件地址？

### 1.2 结论

data 装的是**产物指针，按厂商返回形态二选一**，不是固定某一种，也不是两者同时给：

| 厂商返回形态 | data 内容 |
|---|---|
| 回公网 URL（agnes 系） | `{"url": "https://cos-platform-outputs.agnes-ai.cn/...png", "type": "image"}` |
| 只回 base64（sensenova U1.5 系） | `{"file_path": "E:\\data-doc\\...\\attachments\\20261121-010009-abc.jpg", "attachment_id": "32位十六进制", "type": "image"}` |
| 两者都没有 | `{}`（空对象），原因写在 llm_data.status 与 detail |

base64 本身**永不进入 data**：一张 2048² 的 PNG 转 base64 约 4MB，既不能塞进消息体，也不该交给模型阅读。

## 二、判定链路

产物形态不是工具自己决定的，而是沿链路逐层收敛的结果。

### 2.1 厂商响应先落 out（generation_client）

- 生图：`out.update(url=url, b64=b64)`，厂商给哪个就写哪个，两者可同时存在。
- 生视频：`out["url"] = raw_url`，保持厂商原始大小写（签名串大小写有别，取证件与出参分开处理）。
- 该层不做任何下载或转存，只把厂商响应里的地址与字节原样交出。

### 2.2 编排层决定是否落盘（media_generate.invoke_generate）

判定只有一条：

```python
if ok and not url and b64:      # 没有 URL、只有 b64 才落盘
    saved = await asyncio.to_thread(_save_b64_attachment, ...)
```

- 落盘目录为 `get_tool_dir("attachments")`：会话默认目录优先，兜底项目根。
- 落盘走系统产出专用写盘口，不受会话存在性、会话总量配额、单文件上限约束。
- 落盘成功后回填 `file_path`（本地绝对路径）与 `attachment_id`（附件台账行主键）。
- 产物后缀由字节魔数判定真实格式（PNG/JPEG/WEBP/GIF/WEBM/MP4/MOV），不按模态硬编码。

### 2.3 工具层决定 data 形状（generate_image / generate_video）

```python
if url:    data = {"url": url, "type": kind}
else:      data = {"file_path": ..., "attachment_id": ..., "type": kind}
```

成功判定同步收窄：**必须拿到 url 或落盘 file_path 才算成功**；引擎回了 b64 但落盘失败、或厂商什么都没回，都判失败（`exec_code=error`）——前者是模型已生成、本地产物丢失（`ERR_GENERATE_PERSIST_FAILED`），后者是厂商没交付（`ERR_GENERATE_REJECTED`）。落盘失败重试数次才判定，避免瞬时占锁误报。

data 里不再回显 prompt、model 等入参——入参归 llm_data.action.params，data 只放本次执行产出。

### 2.4 产物清单与 data 同值

llm_data.action.artifacts 的条目与 data 指向同一产物：

- URL 形态：`{"name": "generated_image.jpg", "path": "<原 URL>", "type": "image"}`，name 按 URL 路径末段真实后缀定名，签名查询串不进名字；
- 本地形态：`{"name": "<落盘文件名>", "path": "<本地绝对路径>", "type": "image"}`。

### 2.5 厂商响应其余字段的落点

产物地址之外的字段（规格、用时、任务标识、用量、修订提示词、失败原因）同样不丢弃，按用途分三处落：

| 落点 | 承载什么 | 是否进模型观察 |
|---|---|---|
| llm_data.summary | 结论 + 规格，拼成**一句通顺中文**（见 2.5.1） | 是，summary 就是模型看到的结论 |
| llm_data.metrics | 厂商回显的标量：model（以厂商回显覆盖请求值）、尺寸、格式、秒数、清晰度、质量档、tokens | 是，渲染为「统计:」行 |
| other_data.provider | 其余原样整包：created、task_id、video_id、created_at / completed_at、progress、status、input_*、usage 原结构、revised_prompt、失败态 code / message | 否，落库落档但不进 observation |

成功时 summary 只报结论与规格，**不再复述产物指针**：URL 或本地附件路径本来就在 data 里，summary 再说一遍只是噪音。故公网形态与本地落盘形态的成功 summary 完全一致。

b64 内容**绝不进 data / llm_data / other_data**：它在引擎里只走内存交接（`out["b64"]` → 回调出参），落盘成功后由 data 携带 `file_path` 与 `attachment_id`（路径与台账主键，不是内容）。厂商响应进 `other_data` 前统一过一道剔除：键名命中产物本体（`b64_json` / `url` / `image_url` / `video_url` / `image` / `mask`）、键名含 `b64` 或 `base64` 的字符串、以及任何超过 8192 字符的字符串，一律不落库。

#### 2.5.1 标准规格字段与映射

规格按模态定一套标准字段，各厂商响应按键名候选映射进来：**命中即显示，映射不到就不显示**，不猜、不编造。

| 模态 | 标准规格 | 厂商候选键名（按优先级） | summary 拼接形态 |
|---|---|---|---|
| 图像 | 尺寸 | size / resolution / image_size | `，1024x1024` |
| 图像 | 格式 | output_format / format / image_format / mime_type | `，png 格式` |
| 图像 | 用时 | 见下方时间戳 | `，用时 9 秒` |
| 视频 | 时长 | seconds / duration / video_seconds | 与清晰度同段 |
| 视频 | 清晰度 | size / resolution / video_size | `，5 秒 720P` |
| 视频 | 质量档 | quality / quality_level | `（standard）` 缀在上段后 |
| 视频 | 用时 | 见下方时间戳 | `，用时 461 秒` |

- 用时取**厂商返回的任务时间戳**（created_at / created / started_at → completed_at / completed / finished_at），不是工具墙钟：墙钟含排队提交与轮询粒度，实测同一任务墙钟 525.6 秒、厂商侧 461 秒。
- 厂商只回起点不回终点时（图类同步响应常见），用时整段不显示；不编造、不用墙钟顶替。
- 新增厂商只需往候选键名里加名字，映射表是唯一真源（`generation/vendor_spec.py`），工具与文案零改动。
- metrics 的键值统一取 `{value, text}` 形：前端工具行标签只认 text/value，直接放标量会渲染成空标签。

两个样例（前者为真实调用，后者用同一厂商真实完成态响应做桩）：

```jsonc
// 生图 agnes：厂商只回产物地址与任务号，无尺寸/格式/完成时间戳 → 规格段整段缺席
"summary":  "生成图像，成功：模型 agnes-image-2.1-flash"
"metrics":  {"model": {"value": "agnes-image-2.1-flash", "text": "agnes-image-2.1-flash"}}
"other_data": {"provider": {"created": 1795224637, "task_id": "task_fIKg...", "data": [{"revised_prompt": ""}]}}

// 生视频 agnes：created_at→completed_at 差 461 秒
"summary":  "生成视频，成功：模型 agnes-video-2.5-flash，5 秒 720P（standard），用时 461 秒"
"metrics":  {"model": ..., "seconds": ..., "size": ..., "quality": ...}
"other_data": {"provider": {"completed_at": ..., "created_at": ..., "id": ..., "progress": 100,
                             "status": "completed", "task_id": ..., "video_id": ...,
                             "input_seconds": 0, "input_image_count": 0, "input_audio_seconds": 0, ...}}
```

## 三、三种形态对照

### 3.1 成功·公网 URL

| 项 | 内容 |
|---|---|
| 触发条件 | 厂商响应里带可用 URL |
| 本地副本 | 无（不下载、不落盘） |
| data 字段 | url、type |
| 前端表现 | 内嵌缩略图 / 播放器，可直接看、可播放，附「查看 / 下载」 |
| 附件台账 | 不登记 |

### 3.2 成功·本地落盘

| 项 | 内容 |
|---|---|
| 触发条件 | 厂商只回 base64，无 URL |
| 本地副本 | 有，落在 `get_tool_dir("attachments")` |
| data 字段 | file_path（本地绝对路径）、attachment_id、type |
| 前端表现 | PathLink 深链，点击用系统看图/播放器打开，**不内嵌预览** |
| 附件台账 | 登记一行，attachment_id 即该行主键，附件抽屉与带 token 预览据此工作 |

file_path 是磁盘真实绝对路径，与台账对外的相对路径（path 字段）不是同一个口径：前者用来落盘与打开文件，后者用来展示与跨端引用。

### 3.3 失败

data 为空对象，原因在 llm_data.status：

- 厂商确定拒绝（模型/参数/鉴权/无输出位、或模型未配置）→ exec_code=error，code=ERR_GENERATE_REJECTED，出路是换模型或检查配置；
- 未交付（厂商回了 b64 但落盘失败，或什么都没回）→ exec_code=error，前者 code=ERR_GENERATE_PERSIST_FAILED（出路：重试，持续失败查附件目录写入权限与磁盘空间），后者 code=ERR_GENERATE_REJECTED；
- 未定（队列满、网络、超时）→ exec_code=warning，code=ERR_GENERATE_INCOMPLETE，出路是稍后重试。

失败与警告的分界是「有没有交付产物、结论是否确定」：落盘失败是模型已生成、产物没交到用户手里，属确定的失败，不能报成「完成但有警告」误导模型说稍后重试就行。

## 四、真实样本与实测

### 4.1 历史记录形态统计（本机聊天库，近 800 条含生成工具的 step）

| data 形态 | 条数 | 说明 |
|---|---|---|
| url 形态（含旧版连带入参回显） | 16 | 全部为 agnes 系，URL 形如 `https://cos-platform-outputs.agnes-ai.cn/images/t2i/task_xxx/output_xxx.png`、`.../videos/agnes-video-2.5/task_xxx.mp4` |
| 无产物（仅回显入参） | 4 | sensenova 侧失败（http_404），非 b64 成功 |
| 本地落盘形态 | 0 | 尚无真机样本，见 7.2 |

### 4.2 厂商 URL 可访问性实测（2026-11-21）

对 4.1 中一条图片 URL、一条视频 URL 分别发起带 Range 的 GET：

- 图片：`206 Partial Content`，Content-Type `image/png`；
- 视频：`206 Partial Content`，Content-Type `video/mp4`。

两条均在生成后一天多仍可读，说明该厂商产物地址是长期可读的 CDN 直链，不是短时效签名链接。此前「URL 很快过期」的猜测在本机未得到证据支持。

## 五、两种形态的消费差异

### 5.1 前端渲染位置

前端按任务性质分两处呈现，读的都是同一份 data：

| 场景 | 呈现位置 | URL 形态 | 本地落盘形态 |
|---|---|---|---|
| 实时任务（含刚完成的当前任务） | 工具子行下方的产物卡片 | `<img>` / `<video controls>` 内嵌 | PathLink 深链，点击由系统程序打开 |
| 历史回放（从库里翻出的旧任务） | 「浮层参数 → TOOL结果」标签 | `<img>` / `<video controls>` 内嵌 | 经带 token 的附件 raw 接口取回字节、转 objectURL 后内嵌 |

- 历史回放不挂卡片：历史以看过程为主，产物在需要时点开标签查看即可。
- 两种形态都是「能看到图/片」：URL 由浏览器直连厂商 CDN；本地形态的文件在后端机器磁盘上，浏览器无权访问且裸 `<img src>` 带不了 Authorization 头，故经带 token 的附件接口取字节再转 objectURL。
- 媒体下方附一行产物指针纯文字（URL 或 file_path），可选中复制；同时 URL 形态有「查看 / 下载」、本地产物有「下载」。
- 浮层关闭即卸载内容并回收 objectURL，反复开关不累积视频内存。
- 兜底行（登记失败、无 attachment_id）没有可取的字节，只显文字：`产物无法内嵌预览，仅地址：<path>`。
- 该派发按 data 形状判定（`type` 为 image/video 且带 http url 或 file_path），不按工具名，其它工具的结果不受影响。

### 5.2 附件台账

只有落盘形态产生 attachment_id，因此只有它能进入附件抽屉、收藏、存为资产等基于台账的能力；URL 形态是「外部产物」，在台账里没有行。

### 5.3 对模型

data 作为执行产出随工具结果下发，模型据 summary 得知成功与否与产物位置；base64 不下发，避免单条消息被数 MB 字符串撑爆。

## 六、设计取舍

### 6.1 为什么不能统一成 URL

sensenova U1.5 只回 base64、不提供任何公网地址，统一成 URL 在这类厂商上直接做不到。此时若不落盘，产物无处安放，用户等于没拿到图。

### 6.2 为什么没有统一成本地路径

统一落盘在技术上可行，代价是：

- 每次成功后都要额外下载一次（视频数十 MB），生成耗时与带宽随之增加；
- 需要额外处理下载失败的降级分支（下载失败时还能不能回 URL）。

### 6.3 当前取舍

能拿到 URL 就不下载，省带宽省磁盘，厂商 CDN 即权威副本；只有拿到 base64 无处安放时才落盘。两种形态各有消费差异（见第五章），由前端按路径特征自行分流，工具层不为统一形态而在无收益时多做一次下载。

## 七、验证边界

### 7.1 已实证

- 厂商响应到 out 的两种形态提取（图 url 与 b64、视频 url 原大小写）。
- 落盘分支的写盘、登记、后缀按魔数定名、同内容去重、登记失败兜底行与台账行同构：以真实聊天库副本与模拟回调验证，全部通过。
- 成功判定收窄、未定与确定失败的三态归因、产物名按 URL 后缀定名。
- 前端渲染真机验证（2026-11-21）：真实历史任务里，URL 形态的图片与视频在「浮层参数 → TOOL结果」标签内内嵌显示（图片按原图 1312×736 渲染、视频可播放并带「查看 / 下载」），同一任务在流水线中不挂产物卡片；关闭浮层后内容卸载，objectURL 随组件卸载回收。
- 厂商字段三处落点（2026-11-21）：生图走真实厂商调用、生视频用该厂商真实完成态响应做桩，summary 拼句、metrics 标量、other_data.provider 整包三项产出与 2.5 样例一致；同一份结果生成的模型观察文本只含 summary 与「统计:」行，other_data 不出现在观察中。

### 7.2 未端到端验证

本机聊天库中尚无一条真实的本地落盘产物记录。历史那次 sensenova 调用止于 http_404（未定），未走到 b64 落盘。因此「厂商真的只回 base64」的端到端链路目前只有逻辑与落盘单元层面的验证，缺一次真机出图。

### 7.3 外部依赖风险

URL 形态的产物依赖厂商 CDN 持续可读。实测当前可用，但这属外部依赖：一旦厂商回收或迁移，历史回放中点开该条标签时媒体将无法显示，而库里存下的正是这个 URL。

## 八、后续可选方向

### 8.1 维持现状

二选一形态不变，前端已能同时消费两种，改动为零。

### 8.2 URL 也落盘一份

成功且拿到 URL 时同样下载落盘，data 统一为 file_path 加 attachment_id，url 仅作展示字段保留。收益是历史永久可见、离线可看、产物进台账；代价是每次多一次下载与磁盘占用，并需定义下载失败时的降级（回退为纯 URL 形态）。

该方向改动的是行为而不只是形态，须在明确取舍后再实施，不默认执行。
