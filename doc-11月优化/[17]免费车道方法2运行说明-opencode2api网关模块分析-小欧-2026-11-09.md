## 1. 这是什么

后端宿主（OmniAgent）通过 provider 名 **`opencli`** 走 OpenCode Zen 免费模型车道
（`-free` 后缀模型 + big-pickle）。本目录是**方法2**的完整落库：

```
后端 :8100 /api/v1/chat/stream (SSE)
  → resolver 读 config.yaml opencli 块 (api_base=127.0.0.1:8080/v1, Bearer token)
  → 本网关 opencode2api.exe :8080   ← 本目录唯一常驻进程
      鉴权 → 工具形状门禁 → 官方提示注入 → 指纹头装配
  → WARP 出口池 (userspace WireGuard, 429 自动换出口)
  → https://opencode.ai/inference (OpenCode CLI 2.x 匿名车道)
  ← SSE 原路回传 → 后端 chunk/action/observation/final
```

**后端零代码改动**——只改了 `config/config.yaml` 的 opencli 块（指向本网关）。
旧 `gateways/`（CLI 驱动）方案死穴：CLI 是 agent 型，拦截工具，宿主工具不执行；
本网关是纯 HTTP 形状改写，工具双向通（宿主工具经网关上天、结果回宿主执行，实测 version.txt 真读成功）。

## 3. 起作用的代码（模块职责分析）

### 3.1 internal/gateway — 核心编排（改写与中继都在这）

| 文件 | 职责（依包级/类型注释核实） |
|------|------|
| `gateway.go` (29.8K) | HTTP 入口：路由、server_keys 鉴权（crypto/subtle 常量比较）、**v1/v2 双车道**选择——v1=`/zen`(OpenCode 1.x 形状), v2=`/inference`(2.x 形状, 匿名免费层只用这条) |
| `upstream.go` (64.7K, 最大) | 上游装配与中继：把 OpenAI 兼容请求改写成 OpenCode CLI 形状、发 `/inference`、上游 SSE 翻译回 OpenAI 流；诊断请求沙箱（不污染键冷却状态） |
| `pool.go` (31.8K) | 出口传输池：`proxyTransport`(direct/轮换代理各带常规+**bun 伪装**两个 client——free 流量伪装成 Bun runtime 发出)、健康跟踪、失败冷却 |
| `toolshape.go` (20.6K) | **工具形状门禁**：`go:embed` 官方 13 工具定义（`opencode_tools.json`=2.x 车道 / `_v1`=1.x），免费层只收 agent 形状流量；宿主工具 `clint_` 前缀改名上天/响应还原 |
| `opencode_prompt.go` + `opencode_prompt_v2.txt` | 官方系统提示注入（门禁要求，≈5.7k token/轮） |
| `first_event.go` / `probe.go` | 首事件超时探测（30s 无首帧判上游死） |
| `refresh.go` | 模型目录周期刷新（300s，对应 `/v1/models` 11 个） |
| `rotation.go` | 模型轮换别名（config rotation.sota.order） |
| `runtime.go` | Gateway 结构组装、启停 |
| `availability.go` / `abuse.go` / `health.go` | 出口可用性记账 / 滥用限速 / `/healthz` |
| `warp.go` | 请求绑定 WARP 出口（见 3.2） |
| `title.go` | 会话标题生成 |

### 3.2 internal/warp — WARP 出口池（破配额窗的关键）

| 文件 | 职责 |
|------|------|
| `pool.go` (21.4K) | 出口池：**egressCooldown 30min**——上游拒绝过的公共 /64（IPv6）或 /32（IPv4）整块冷却（免费层配额按此块计）；重复出口检测（Cloudflare 只发有限不同 /64，连续 3 次重复即退避 1→5min）；429→退役→后台补注册 |
| `exit.go` (14K) | 单出口生命周期：userspace wireguard-go 隧道（**无需 TUN/管理员**） |
| `registrar.go` (10.5K) | Cloudflare WARP 自动注册（拿设备凭证+对端配置） |
| `bind.go` + `freebind_*.go` | Linux IP_FREEBIND 特化；Windows 走通用路径 |

实测：2 出口不同 /64；本地 IP 配额窗被烧时，换出口即刻 200，不等 Retry-After。

### 3.3 internal/identity — 指纹（过门禁的钥匙）

`request.go`：`CanonicalSessionID` 降序时间戳会话 id（2026-10-14 门禁验证），
`x-opencode-session`（会话亲和键）+ `x-opencode-session-id`（子代理保留客户端自己的 id）成对发出；
`message.go`：用户消息 id 派生。**403 FreeTierError = 指纹被拒** 的排查点在这。

### 3.4 其余支撑包

`config`(配置加载) `models`(模型目录) `protocol/wire`(上游协议类型) `rotation`(轮换配置)
`httpx`(共享 HTTP 客户端) `admin`(WebUI :8081) `telemetry`(日志环) `jsonutil` `buildinfo`

## 4. 配置契约（改前必读）

| 项 | 值 | 说明 |
|----|----|------|
| `config.json.listen` | `127.0.0.1:8080` | **只听本机**，勿改 0.0.0.0 |
| `config.json.server_keys` | 64-hex token | **必须与后端 config.yaml opencli.api_key 同值**（换令牌两处同改） |
| `config.json.warp` | enabled / pool_size 2 / ipv6 | 出口池；/64 全局共享段被烧时可能连续换出口 |
| `config.json.webui` | `0.0.0.0:8081` | 管理台（admin / 改-this-admin-password） |
| 后端 `config.yaml` | opencli 块（≈L542） | api_base `http://127.0.0.1:8080/v1`；models 清单由 UI/手工管理（2026-11-09 晚为 7 个含 big-pickle，网关实际可出 11 个，加名字即启用） |
| 后端模型选择 | UI 里 `ai.model_ref` | → `opencli/big-pickle`；**`/chat/stream` 不吃请求字段**，模型走会话级 override |
| 后端多轮契约 | **两段式** | 先 `POST /sessions/{id}/messages` 落库用户消息，再 `/chat/stream`(session_id+link_enabled)；裸发 stream 历史注入 0 条 |
