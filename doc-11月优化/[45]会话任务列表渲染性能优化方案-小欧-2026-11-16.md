## 第 1 章 问题分析

### 1.1 现象

会话任务条数达到 20+ 后，以下操作出现明显卡顿：

- **刷新页面**（F5）：页面白屏 → 任务列表渲染完成之间有明显延迟
- **切换会话**：从会话 A 切到会话 B，左栏任务列表渲染慢
- **切换页面后回来**：从文件页/设置页切回会话页，任务列表重新挂载慢

此前已做过一轮优化（Skeleton 条件收窄、保留旧列表不卸载等），有所改善，但 20+ 条时仍可感知。

### 1.2 会话 UI 架构特点

会话页采用**单页双栏插槽化骨架**（`SessionLayout`）：

```
SessionLayout
├── 顶栏 (topbar): ChatHeader + TopbarStats + 模型信息
├── 中部 SplitPane
│   ├── 左栏 (left): TaskListPanel ← 性能瓶颈所在
│   └── 右栏 (right): RightViewer（执行步骤详情）
│       └── rightBottom: FileTrailPanel（文件足迹）
└── 底部 dock
    ├── taskinfo: TaskInfoBar
    ├── config: 信任操作面板
    └── input: ChatInput
```

**关键特征**：所有 7 个面板由 `useChatPanels` 的**一个巨型 `useMemo`** 组装，依赖数组含 **40+ 项**。

### 1.3 TaskListPanel 渲染特征

每个任务项（`tasks.map()`）渲染以下子结构：

| 区域 | 组件/元素 | 说明 |
|---|---|---|
| 元信息行 | 5+ 个 `<span>` | 时间、模型标签、状态标签（含 IIFE）、链号徽标（含 IIFE）、续跑徽标、轮次标签 |
| 用户问题区 | `CollapsibleText` + 复制按钮 | 折叠/展开，每实例含 `useDisclosure` hook |
| 追加消息块 | `CollapsibleText` × N | 默认收起，展开时每条独立渲染 |
| 回复区 | `CollapsibleText`（含 `MarkdownSlot`）+ 复制按钮 | **折叠态**只渲染纯文本摘要；**展开态**才触发 `MarkdownSlot`（`React.lazy` + `react-markdown`） |
| 推荐行 | `Tag` × ≤3 | 仅最新任务渲染 |
| 引用台账行 | `Tag` × N | 每任务都调用 `ledgerForTask()` |

20+ 任务 × 每项 ~15 个 DOM 节点 = **300+ DOM 节点**，每次全量重渲需 diff 全部。

### 1.4 根因清单（5 个瓶颈）

#### 瓶颈 1：TaskListPanel 无 React.memo，全量重渲（★★★★★）

`TaskListPanel` 是普通函数组件，未包 `React.memo`。它挂在 `useChatPanels` 的巨型 `useMemo` 内部，该 memo 依赖数组 40+ 项，包含 `executionSteps`、`sessionTokens`、`streamStatus`、`waitClock`、`liveError`、`authorizationPending`、`isReceiving`、`isPaused` 等**高频变化状态**。

**触发链**：

```
SSE 推 chunk → executionSteps 变 → useChatPanels useMemo 重算
→ panels 数组重建（7 个面板全部重新构造 JSX）
→ TaskListPanel 拿到新 props 引用（即使 tasks 内容没变）
→ 全量重渲所有任务项（20+ × 每项含 CollapsibleText × 2 + IIFE × 2）
```

SSE 流式期间每秒可能多次触发，每次重渲数百个 React 元素。

**代码位置**：
- `useChatPanels.tsx:225` — `return useMemo<SessionPanel[]>(...)` 依赖数组 `:431-489`
- `useChatPanels.tsx:300-311` — `<TaskListPanel tasks={tasks} ... />` 在 useMemo 内构造
- `TaskListPanel.tsx:127` — `const TaskListPanel: React.FC<TaskListPanelProps> = (...)` 无 memo

#### 瓶颈 2：useChatPanels 巨型 useMemo 将无关面板捆绑重算（★★★★）

`useChatPanels` 把 7 个面板的 JSX 全部在一个 `useMemo` 闭包里构造。`TaskListPanel` 只依赖 `tasks / activeTaskId / loading / latestTaskId / rightOpen / sessionId / steps` 共 7 项，但与 `ChatInput`（依赖 `draft / handleSend / routingMode` 等）、`RightViewer`（依赖 `executionSteps / streamStatus` 等）共用同一个 memo。

**任何一个面板的依赖变化 → 所有面板重建**。SSE 流式期间 `executionSteps` 高频变化 → `TaskListPanel` 被迫跟着每秒多次重算，即使任务列表本身完全没变。

**代码位置**：`useChatPanels.tsx:225-491`

#### 瓶颈 3：ledgerForTask 在 render 期间同步调用 store（★★★★）

```tsx
// TaskListPanel.tsx:624
{sessionId && ledgerForTask(t.task_id).length > 0 && (
```

`ledgerForTask` 在 `tasks.map()` 循环内**每个任务都调用一次**，同步访问 `chatStreamStore.getSentRefLedger()` 做 `.filter()`。20+ 任务 = 20+ 次 filter。返回值不缓存，每次重渲都重复计算。

**代码位置**：
- `TaskListPanel.tsx:177-183` — `ledgerForTask` 定义
- `TaskListPanel.tsx:624, 627` — map 内调用

#### 瓶颈 4：CollapsibleText 每次渲染都 text.split('\n')（★★★）

```tsx
// CollapsibleText.tsx:71-74

    const lineCount = text.split('\n').length;
    return lineCount > maxLines || text.length > maxChars;
}, [text, maxLines, maxChars]);
```

`useMemo` 依赖 `text`，但父组件每次重渲时 `text` prop 的引用可能变（从 `.map()` 产生的新对象上读取），导致 `split` 重复执行。20+ 任务 × 2 个 `CollapsibleText` = 40+ 次 split。

**代码位置**：`CollapsibleText.tsx:71-74`

#### 瓶颈 5：无虚拟滚动——全量 DOM 渲染（★★★）

`tasks.map()` 直接渲染所有任务项到 DOM，无 `react-window` / `react-virtuoso` 等虚拟列表。20+ 任务项每项含大量子元素，DOM 节点数 500+。全量渲染 + 全量重渲（瓶颈 1）叠加后，每次重渲的 DOM diff 成本显著上升。

**代码位置**：`TaskListPanel.tsx:321` — `tasks.map((t) => { ... })`

### 2.1 P0：TaskListPanel 包 React.memo + 提取 TaskItem 子组件

#### 2.1.1 设计说明

**核心思路**：把 `tasks.map()` 内的渲染体抽成独立的 `TaskItem` 组件，两者都包 `React.memo`。

- `TaskListPanel`（外层）：包 `React.memo`，props 不变时不重渲
- `TaskItem`（内层）：包 `React.memo`，只在该任务数据变化时重渲

**memo 比较函数**：`TaskItem` 的 props 包含 `task`（对象）、`active`（布尔）、`isLatest`（布尔）等。默认浅比较即可——`task` 是 `SessionTaskItem` 对象，`useSessionTasks` 的 `refresh` 每次 `.map()` 产生新对象，但 `updateTaskResponse` 只改对应一项。需要自定义比较函数确保**只有 task_id + response + status 变化时才重渲**。

**不提取的部分**：推荐行（`recommend`）和引用台账行（`ledgerForTask`）只在最新任务上渲染，且依赖外部 hooks 数据，留在 `TaskListPanel` 外层渲染后通过 props 传入 `TaskItem`。

### 2.4 P3：CollapsibleText overflow 判定优化

#### 2.4.1 设计说明

**核心思路**：用 `text.length` 快速否决 + `indexOf` 循环计数替代 `split('\n')` 全量分割。

原实现每次 `text.split('\n')` 创建一个完整数组（O(n) 内存分配）。优化后先用 `text.length > maxChars` 快速判定（大部分短文本直接命中），只有超长文本才进一步数行数，且用 `indexOf` 循环计数不分配数组。
