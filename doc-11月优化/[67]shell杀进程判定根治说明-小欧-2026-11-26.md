## 一、结论摘要

1. 杀进程判定存在三处根因：换行被压成空格导致两条命令被合并、词法切分不感知大括号块、CMD `taskkill /F` 正则要求 `/F` 紧跟在某处空白之后。三者叠加造成同一类命令「改排版即从拦截变放行/反之」。
2. 三处根因已根除：换行归一为语句边界、切分器跟踪 `{}` 深度与 `${name}` 变量、`taskkill` 的 `/F` 改按「任意位置出现即命中」判定。
3. 本轮复核在验证上述修复时，**又发现三处连带逻辑缺陷**（均为 real 缺陷，已实测复现并同步根治，见第四章），其中一处为**严重漏拦**：有界 `foreach` 块内对全量进程执行杀动作，被误判为放行。
4. 新增回归测试 55 例（真实调用解析函数与自杀判定入口，无 Mock），连同既有 5 个 shell 测试文件共 **217 例全部通过**；`ruff --select F` 零告警。
5. v1.1 追加逐壳审计：又发现并根治 4 类自杀漏拦（`$PID` 自动变量、对象变量字面 PID、opaque 可见目标、字符串数组含自身名），同时修正 v1.0 自身引入的字符串数组误伤。详见第八章。

## 二、原始问题与根因

| 序 | 现象 | 根因 | 位置 |
|---|---|---|---|
| 1 | 带换行的块状命令，`$env` 展开后两条语句被合并成一条，判定的目标集合与实际执行不一致 | `prepare()` 把 `\r\n` 与 `\n` 一律压成空格，丢掉语句边界 | `lexer.prepare` |
| 2 | 块体（`{...}`）内用 `;`/换行/`|` 时，`foreach` 头与其块内 Kill 被拆到不同语句；「加一个分号」即从拦截变放行 | `_split_respect_quotes` 未跟踪 `{}` 深度，块内分隔符被当外层切分点 | `lexer._split_respect_quotes` |
| 3 | `taskkill /PID 5 /F`、`taskkill /FI "..." /F` 等未触发强制杀进程确认 | 正则 `taskkill\b.*\s/f\b` 原意只是任意位置出现 `/F`，但被误读为「`/F` 必须跟在空白后且是最后一段」的实际效果不稳定 | `shell_command_risk` 中风险表 |

## 三、三处根因修复

### 3.1 换行归一为语句边界

`lexer.prepare` 仅做 `\r\n → \n` 归一，不再把换行压成空格；由语句切分器把换行当作分隔符。块内换行在 3.2 的块感知下不参与切分，两条独立语句不再被合并。

### 3.2 词法块感知切分

`_split_respect_quotes` 增加两层状态：

- **块深度**：跟踪 `{` / `}` 深度，深度大于 0 时块内的 `;`、`&&`、`||`、换行、`|` 一律不切分（块内属单一语句）。
- **变量语法**：`${name}` 整段吞下，其 `}` 不参与块深度计数，避免把变量结束符误当块结束。

该改动同时惠及所有复用该切分器的解析（如删除、移动），使「块内多命令」的目标抽取与无块写法保持一致。

### 3.3 CMD taskkill /F 参数任意位置

`/F` 与参数顺序无关。只要命令中出现独立的 `/F`（`/F` 后为非单词字符或行尾），即补中风险确认；`/FI`（后接 `i`，无词边界）不被误命中。

## 四、本轮新发现并同步根治的三处连带缺陷

复核第三章修复时，用真实命令矩阵实测，发现以下三处独立缺陷，均已根治并纳入回归测试。

| 序 | 命令示例 | 修复前判定 | 实际语义 | 危害 | 修复后判定 |
|---|---|---|---|---|---|
| 4.1 | `foreach ($p in @(1,2)) { Get-Process \| Stop-Process }` | `literal [1,2]` | 块体未使用 `$p`，全量杀所有进程 | **严重漏拦**（非保护 PID 直接放行） | `unbounded`（硬拦） |
| 4.2 | `foreach ($x in "a","b") { Stop-Process -Name $x }` | `bounded_dynamic` | 迭代源是字符串数组，非数字集合 | 分类错误（被「有界」假象掩盖） | `unbounded`（转人工） |
| 4.3 | `$ids=1,2; foreach ($p in $ids) { Stop-Process -Id $p }` | `unbounded` | 合法有界的裸数字列表 | 误拦（合法写法被硬拦） | `literal [1,2]` |

### 4.1 块内全量枚举不得借「有界迭代源」豁免（严重）

原逻辑只判断「迭代源有界」，未校验块体是否真的消费迭代变量。当块体与迭代变量无关、直接对全量进程操作时，仍被并入有界源的 PID 并判为 `literal` 放行。

根治口径：

- 仅在**块体确实引用迭代变量**（如 `-Id $p` / `$p.Kill()`）且迭代源有界时，才并入源 PID 并豁免 `foreach` 无界信号。
- 块体不引用迭代变量时，再分两种：块体是**无筛选的全量枚举源**（`Get-Process` 等且无 `-Name`/`-Id`）→ 仍判 `unbounded`；块体是**与迭代变量无关的确定操作**（如显式 `-Name chrome`）→ 按目标自身判定，不并入源 PID。

### 4.2 迭代源改用原始文本提取（引号感知）

原实现用「涂空引号后的文本」提取迭代源，`"a","b"` 被涂成 `,` 后误命中「纯数字列表」分支。改为在原始段上做括号平衡扫描，引号内括号不参与计数、源文本保留引号原文，字符串数组不再被判为纯数字有界。

### 4.3 数组赋值表支持裸数字列表

原数组赋值正则只认 `$var=@(...)`，不认 `$var=1,2`。裸数字列表是合法有界源，已并入可枚举分支，与 `@(1,2)` 同等处理。

## 七、已知保守行为

以下行为为「安全优先」的既定取舍或静态分析的固有边界，非本次缺陷，予以说明：

1. 数字范围降序或超展开上限时判「有界但不展开具体 PID」，交由确认环节兜底。
2. 块体同时消费迭代变量又包含独立全量枚举的病态写法，按 `unbounded` 处理（宁可拦，不放行）。
3. CMD 变量 `taskkill /PID %PID% /F` 按既有口径放行（`%PID%` 非 Windows 内置变量，不构成现实自杀向量；既有回归已钉死此口径）。
4. `-EncodedCommand` 内容静态不可解码时保持 `opaque` 放行；若引号内显式目标可见则按 literal 抽取核对（见第八章）。

## 八、逐壳审计补漏（v1.1）

### 8.1 审计方法

以当前 python 进程 PID 模拟「后端自身」，对 `parse_kill_actions` 与 `check_shell_self_kill` 做真实调用矩阵，逐壳（ps7/ps5/cmd/bash）覆盖三类断言：

- **自杀必拦**：目标为自身 PID/自身镜像名/无上界杀形 → 必须 `blocked=True`。
- **零误伤**：普通进程/只读命令/求助演习 → 必须 `blocked=False`。
- **分类准确**：`literal`/`bounded_dynamic`/`unbounded`/`opaque` 与目标静态可枚举性一致。

三批 probe 共 80 个场景（35+25+20，含跨轮重叠），去重后实测发现 15 项不一致：11 项自杀漏拦 + 2 项 v1.0 引入的误伤 + 2 项既定放行口径。

### 8.2 新发现并根治的自杀漏拦

| 序 | 命令形态 | 修复前 | 危害 | 修复后 |
|---|---|---|---|---|
| 8.2.1 | `Stop-Process -Id $PID` / `$pid` / `${PID}` / `($PID)` / 管道上游 | `bounded_dynamic` 放行 | PowerShell `$PID` 是自动变量＝当前进程 PID，杀它必自杀 | `unbounded` 硬拦（仅 ps 壳） |
| 8.2.2 | `$p=Get-Process -Id <自身PID>; $p.Kill()` / `-InputObject $p` / `-Id $p.Id` | `bounded_dynamic` 放行 | 目标 PID 静态可见却未还原 | 还原为 `literal` PID 交保护盾核对 |
| 8.2.3 | `iex "Stop-Process -Id <自身PID>"` / `bash -c "kill -9 <自身PID>"` | `opaque` 放行 | 引号内目标静态可见却被 opaque 一律放行 | 显式目标可见时按 `literal` 抽取核对 |
| 8.2.4 | `foreach ($x in "python","chrome") { Stop-Process -Name $x }` | `unbounded`（v1.0 误伤） | 自身名混在字符串数组中时虽被拦，但普通名也被误拦；且自身名未被精确核对 | 字符串数组抽为 `literal` 名字集合，自身名硬拦、普通名放行 |

### 8.3 v1.0 自身引入的误伤及修正

v1.0 为堵「引号字符串数组被涂空误判数字有界」，把 `"a","b"` 迭代源判为 `unbounded`，导致 `foreach ($x in "a","b") { Stop-Process -Name $x }` 这类普通命令被硬拦——违反「可以漏掉但不能误伤」口径。

修正：`_source_bounded` 用保留引号的原文判定字符串列表，抽为 `literal` 名字集合。自身名（如 `python`）命中保护名单仍硬拦，普通名（如 `a`、`b`）放行。修正后该场景回归测试由「断言 unbounded」改为「断言 literal 名字集合」。

### 8.4 审计后实测结论

- 三批 probe 最终：批一剩 2 项均为第七章所列既定放行口径（非缺陷），批二、批三 **0 不一致**。
- 全量测试：`217 passed`（既有 162 + 新增 55）；`ruff --select F` 零告警；`py_compile` 通过。
- 自杀类在 ps/bash/cmd 三壳下均达成 100% 拦截（可静态判定的范围内）；不可静态判定的编码命令按第七章既定口径处理。

## 九、二次审计（v1.2）

### 9.1 审计方法与结论

对 v1.1 新增的 55 例测试做「过度测试 / 真实场景遗漏」双向审查，并以 36+18 场景真实 probe 复测（自我 PID 模拟后端自身，无 Mock）。结论：

- **既有测试无过度**：所断言的均为已实测的判定口径，未发现「以测试锁死错误逻辑」的用例。
- **发现 1 类真实场景遗漏（自杀漏拦）**：PowerShell 标量变量间接杀。`$id=$PID; Stop-Process -Id $id` / `$target=<自身PID>; Stop-Process -Id $target` 落入 `-Id $` 的 `bounded_dynamic` 兜底放行——`$PID` 硬拦只查杀段与上游段的字面出现，不追变量赋值链。
- 顺带复核确认按名杀（`-Name python`/`killall python`/`/IM python.exe`/`pkill -f python`）、`$$`/`$PPID`、cmd `/FI "PID eq <自身>"`、wmic `processid=` 过滤等真实场景均已被现有逻辑正确拦截，但**缺确定性回归钉死**（既有覆盖依赖宿主真实镜像名，测试环境换镜像即失效）。

### 9.2 根治：标量变量间接目标还原

`parse_kill.py` 新增 `_build_scalar_vars`（抽 `$v=$PID`/`$v=<数字>`/`$v=$w` 标量赋值表，别名沿赋值链传递，键统一小写——PowerShell 变量名大小写不敏感）与 `_scalar_refs`（扫 `-Id $var` 引用还原目标）：

| 命令形态 | 修复前 | 修复后 |
|---|---|---|
| `$id=$PID; Stop-Process -Id $id`（含链式 `$a=$PID; $b=$a`、`${PID}`、大小写变体） | `bounded_dynamic` 放行 | `unbounded` 硬拦 |
| `$target=<数字>; Stop-Process -Id $target` | `bounded_dynamic` 放行 | 还原 `literal` PID 交保护盾核对 |
| `Stop-Process -Id $unknownVar`（未定义变量） | `bounded_dynamic` | 不变（不误伤） |

### 9.3 回归补齐

- `TestScalarVarIndirection`：变量间接自杀必拦 5 形态 + 字面 PID 还原 + 未定义/普通字面量变量零误伤。
- `TestNameAndFilterSelfKill`：按名杀自己（killall/pkill/taskkill /IM/-Name/管道）、`$$`/`$PPID`、`/FI` 与 wmic 过滤子句，用 `is_shell_process_kill_protected` **注入**保护集合（PID=5、名=python.exe），消除对宿主真实镜像名的耦合；普通目标（chrome/999999）零误伤同套钉死。
- 端到端 `TestSelfKillEndToEnd` 补 `$id=$PID`、`$target={pid}`、`kill -9 $$` 三形态。

### 9.4 实测结论

- 二次审计 probe（36 场景主矩阵 + 18 场景边界）：修复后 **0 不一致**；误伤仍为 0。
- 全量测试：**247 passed**（既有 162 + 回归 85）；`ruff --select F` 零告警；`py_compile` 通过。
- 既定放行口径（`%PID%`、不可解码 `-EncodedCommand`）不变，见第七章。
