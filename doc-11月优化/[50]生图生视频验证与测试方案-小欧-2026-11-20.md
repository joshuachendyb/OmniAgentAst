## 一、方案目标与范围

### 1.1 目标

验证生图、生视频及其支撑链路在架构调整后的功能完整性与行为一致性，确认请求方言、响应方言、素材公网化、模态门控、探测腿复用均按设计工作，既有功能无退化。

### 1.2 覆盖范围

本方案针对以下四条链路：

| 链路 | 代码位置 | 验证重点 |
|---|---|---|
| 生成链路 | tools/media → media_generate → generation_client → adapter | 请求方言、响应方言、产物出参 |
| 素材公网化 | public_image / media_generate 图源归一 | 本地图 i2i data URI、本地图 i2v 公网直链 |
| 输入 part 构造 | capability / media_payload / utils/modality | 模态门控、逻辑 part → 方言 part |
| 探测腿 | model_service.probe_model_output | 复用生成引擎、不传 adapter 走通用基类 |

### 1.3 测试原则

- 真机优先：真实后端（8100）+ 真实 LLM + 真实工具 + 真实前端（5173），一次一项，观察完整运行过程。
- 隔离：测试不写生产配置；探测腿真实调用会落盘，改以代码契约核对与逻辑验证替代。
- 分层：端到端测真实出图/出片；厂商响应相关的钩子机制用模拟响应验证覆写与回退；纯函数用单测。
- 判定：PASS 必须有可核验证据（产物 URL、渲染结果、耗时、单测数）；FAIL 必须深挖到代码或外部限制，不得跳过。

## 二、环境与准备

### 2.1 服务

- 后端：8100，watchfiles 热加载（start_watch.bat），改动自动生效，无需重启。
- 前端：5173，浏览器驱动，以自然语言发起请求，由 LLM 自主选择工具与参数。
- 检查：端口监听状态用 Get-NetTCPConnection 确认。

### 2.2 素材

- 本地图：166KB jpg，英文临时路径，用于 i2i data URI 与公网化上传。
- 公网图：图床返回的真实直链，用于 i2v 参考图。
- 探测图：generation_client 内置 PROBE_IMAGE_URL，仅探测腿使用，与输入腿素材解耦。

### 2.3 方法

- 生图/生视频：前端新建会话 → 自然语言请求 → 等待完成 → 检查工具调用、产物 URL、markdown/video 渲染、耗时。
- 响应钩子：模拟厂商响应（提交返回 task_id、轮询返回终态），分别验证基类默认回退与 adapter 覆写。
- 输入模态：pytest 本地单测（test_input_capability_media.py）。
- 探测腿：核对 _image_leg/_video_leg 调用 generation_client 时不传 adapter。

## 三、生图验证项

### 3.1 文生图 t2i

请求"用 generate_image 生成一张图：戴帽子的橘猫，卡通风格，size=1K、ratio=16:9"。判定：工具被正确选择；POST /images/generations 返回 200；产物为公网直链且可访问；markdown 正常渲染；LLM 回复中的尺寸与比例回显为 1K/16:9，证明 size/ratio 方言正确。

### 3.2 图生图 i2i

以本地 jpg 为参考重绘为水彩风格，再以公网 URL 为参考重复。判定：本地图经图源归一转为 data URI 传入 image 参数；产物 URL 路径含 /images/i2i/；图片内容发生风格变化。

### 3.3 请求方言参数

覆盖 size 档位、ratio、return_base64、response_format、多图参考。判定：请求体字段位置与厂商协议一致；不传时请求体只含通用字段（OCP）。本轮真机覆盖 size/ratio，其余参数按同一钩子机制生效。

### 3.4 响应方言

覆盖 url 与 b64_json 两种产物形态。判定：基类默认从 data[0] 提取；厂商覆写 parse_image_result 时优先用覆写值；产物未截断写入 out 供工具下载。

## 四、生视频验证项

### 4.1 文生视频 t2v

请求"用 generate_video 生成一段视频：橘猫在草地上奔跑，5秒"。判定：POST /v1/videos 提交返回 task_id；GET 轮询至 completed；产物 mp4 公网直链写入 out 并渲染。队列满记外部限制，不判模型能力失败。

### 4.2 图生视频 i2v

本地图经 public_image 上传为公网直链后，以 images:[url] + mode=reference 提交。判定：upload_image 返回可访问直链；请求体 mode 与素材字段符合厂商协议（images 数组，非 image/first_frame）。

### 4.3 响应方言与状态解析

判定：基类默认递归提取 status/state/task_status 与含 video/.mp4 的 URL；厂商覆写 parse_video_status/parse_video_reason/parse_video_url 时优先用覆写值；终态取不到地址返回 no_output_field，不判无生成能力。

### 4.4 轮询与超时语义

判定：工具 timeout 映射为 poll_timeout 控制总轮询时长；轮询超时返回 poll_timeout: <status>；单请求超时用引擎默认，不再被工具 timeout 误设。

## 五、输入模态与探测腿验证

### 5.1 输入模态单测

运行 test_input_capability_media.py，判定全部通过。关注 URL 直传、富文档原生通道、视频双投递、文档内联、预检边界、上限、模型库扫描。

### 5.2 探测腿契约

核对 _image_leg/_video_leg 复用 generation_client 且不传 adapter，产物分析走基类通用启发式；不真实调用以避免 _persist_media_probe 写生产配置。

### 6.2 发现与处理

输入模态单测中 test_probe_gates_only_image_url 原断言视频 transport 仅 {url}，与已实现的 url + inline 双通道（本地视频字节转 data URI 走 video_url，mimo 实测）冲突。核查代码后确认实现正确、断言过期；该用例为未入库本地测试，仅本地修正断言与表述，未改系统代码、未提交。

### 6.3 外部限制

视频生成队列为厂商账号级资源，queue_full 与本次架构调整无关；此类情况按未定处理，不判模型无生成能力。待厂商队列恢复后按 4.1/4.2 补真实出片验证。
