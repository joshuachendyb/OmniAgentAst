### 1.4 一个被忽视的共同点

12 次事故中，**没有一次是业务逻辑写错**。全部落在三个底层交互点：

1. **同步 I/O 写进事件循环线程**（第 7 次、第 10 次）；
2. **创建线程（`Thread.start`）发生在运行期热路径**（第 8、9、11 次）；
3. **创建进程（`CreateProcessW`）发生在主进程内**（第 8、9、11、12 次）。

这三个点的共同物理属性：**都在 CPython 无法中断、无法超时、无法回收的原生区**。无论上层怎么加 try/except、怎么加 timeout，一旦进入这几个原生调用，Python 代码就没有任何机会执行。

### 2.3 关键构件逐个审查

#### 2.3.1 `spawn_gate.py`（进程闸门）——方向对，但只串行不消除

- 设计：`install_spawn_gate()` patch `Popen.__init__` 与 `Thread.start`（:247/:248），用可回收租约 + 看门狗（`HOLD_LIMIT=8s`、`ACQUIRE_TIMEOUT=15s`、`SLOW_WARN=1s`）。
- **正确之处**：把"会焊死的 RLock"换成"会被回收的租约"，是 11-04 事故的正确修复。
- **致命缺陷**：
  1. **闸门是"互斥"不是"消灭"**——它没减少 `CreateProcessW` 次数，只是把 14 个池的线程创建全部排到一把锁后面；
  2. **看门狗在主进程里**——主进程因 loader lock 停摆时，看门狗自己也要 GIL 才能跑，救不了；
  3. **实测 12h 内从未回收租约**——说明闸门在慢（1.9s）而非死时选择"等"，但等的过程中所有池的线程创建全部阻塞；
  4. `spawn_gate.py` 自 11-04 `9c1fd4fa8` 合入后**一行未改**，是存量根因。

#### 2.3.2 `WorkerPool`（`workers.py`）——语义正确，但超时不归还线程

- `__init__` 构造期建满 N 个 daemon 线程（:42），`submit` 只 `queue.put`，这是正确设计。
- **缺陷**：`submit` 超时（`fut.result(timeout)`）只放弃等待，**任务和线程仍在池内**。若任务卡在原生调用，该线程永久失效。
- 这与 `_SHELL_SLOTS` / `_TOOL_SLOTS` 的行为**不一致**：信号量在超时路径会 `release()`，但线程不会归还。
- **实验结果（exp1/exp2）**：
  - exp1：两次超时后 `sem._value=0`，后续请求 1.00s 直接失败——**信号量泄漏**；
  - exp2：仅 `release()` 信号量（不归还线程），信号量回到 2，但新任务排在死 worker 后，2.01s 仍失败——**信号量归还 ≠ 容量恢复**。
  - 结论：`sem` 与真实可用线程数是**两套独立计数**，无法用 `release()` 修复卡死。

#### 2.3.3 `_SHELL_SLOTS` / `_TOOL_SLOTS`（`tool_retry_engine.py:193/202`）——与执行器解耦的隐患

- 代码：`_SHELL_SLOTS = threading.BoundedSemaphore(_SHELL_EXECUTOR_MAX)`，与 `_SHELL_EXECUTOR` 容量数字相同，但**语义上是两把独立的锁**。
- 超时路径（:289-315）释放信号量，却不释放执行器线程；
- 实验证明这种"数字对齐"只是巧合，一旦线程死亡，两者永久错位。

#### 2.3.4 bash 容错路由与语法校正——路由正确，**校正算法致命**

本项分两段看，必须分开定性，否则会误判成"该删路由"。

**（a）路由本身：容错正确，方向没错**

- `shell_type` 默认 `ps7`（:1108）；`_looks_like_bash()`（定义 :893，调用 :1156）在引号外检测到 `grep`/`ls`/`head` 等即路由到 Git Bash；
- 实测确认 **PowerShell 7 环境没有 `grep`**（`Get-Command grep` 空、直接执行报"术语不被识别"），LLM 写 `grep` 时若不路由到 bash 必然失败；
- `_strip_quoted_content()`（:762）先剥离引号内容再判定，避免 `echo "grep"` 之类字面量误判——判定层考虑是周到的；
- 结论：**这不是"偷渡"，是必要的容错路由**。上一轮用"偷渡"定性不准确，此处更正。

**（b）校正算法：`fixed.replace('\\', '/')` 全局无差别替换，摧毁正则**

- `_auto_fix_bash_syntax()`（:847）唯一动作是 `fixed.replace('\\', '/')`，**不区分引号内外、不区分路径与正则/转义**；
- 该行自 2026-07-28 引入后代码本体从未变过（仅 08-06/11-06 改注释），是长期存量缺陷；
- 破坏面：`\b`/`\d`/`\s`/`\.` 等正则元字符、`awk '{print $1"\t"}'`、`printf "%s\n"`、`echo "a\tb"` 全部被改写；
- 危害形态是**静默错误**：替换后多数仍是"合法正则"，grep `rc=0`，只是匹配结果残缺，LLM 拿到残缺数据继续推理——比直接报错危险得多；
- 详细实证见 **4.5 节**。

#### 2.3.5 语法校正处理阶段与缺陷定性：机制正确、方法错误

上一轮只说了 `_auto_fix_bash_syntax` 改坏了命令，但没交代它**在流水线哪一步被调用**，因此"机制问题还是方法问题"也看不清。本节补齐。

**（a）校正落在流水线的哪个阶段**

`execute_shell_command.py` 有显式 stage 划分（见 :1134-1144 注释），校正位于 **stage 1.2**：

| 阶段 | 代码位置 | 动作 | 是否改命令文本 |
|---|---|---|---|
| stage 1.0 | :1120-1132 | 参数校验（null byte、cwd 存在性） | 否 |
| stage 1.0a | :1136 | 通用预处理 `python3→python`（全流程仅此一处，DRY） | 是（仅此替换） |
| stage 1.1 | :1149-1178 | 三路检测 + 路由，**只改 `shell_type`** | **否** |
| **stage 1.2** | **:1180-1193** | **按最终 `shell_type` 选校正器改命令文本**（bash → `_auto_fix_bash_syntax`，:1190-1193） | **是** |
| stage 2 | :1195-1221 | 安全检查（危险层/中风险层） | 否 |
| stage 2.5 / 2.9 | :1211-1226 | 后台收紧 / 转后台执行 | 否 |
| stage 3 | :1242+ | 执行（PS 引擎 / cmd.bat / Git Bash） | 否 |
| stage 4 | — | 后处理（杀进程 / 读残存 / 组结果） | 否 |

一句话：**先路由定类型（1.1）→ 再按类型校正文本（1.2）→ 再安全体检（2）→ 最后执行（3）**。校正处于"路由之后、执行之前"，且校正函数由路由结果决定（`shell_type == "bash"` 才调 bash 校正器）。

**（b）是机制问题，还是方法问题？——机制正确，方法错误**

必须拆成两个维度，否则又会像上一轮那样把结论下偏：

| 维度 | 判定 | 依据 |
|---|---|---|
| **机制**（流程编排） | ✅ 正确 | "先路由后校正、按最终类型分派校正器"是单向直线流程（KISS-DIRECT）；路由只看引号外结构、校正只处理本 shell 的已知错误，职责单一（SRP）；校正函数各自独立、不互相调用（无循环依赖） |
| **方法**（校正实现） | ❌ 错误 | `_auto_fix_bash_syntax` 的 `str.replace('\\','/')`（:847）对**整条命令无差别**替换，不区分引号内外、不区分路径与正则/转义，粒度过粗（矫枉过正） |

因此修复边界明确：**只改方法（把全局替换改为引号感知 + 仅路径 token），不动 stage 1.2 的位置，也不动"按类型分派"的编排**。这正是 5.2 L1-5 的范围——它是一个函数体修复，不是流程重构。

**（c）附带发现：校正先于安全检查（顺序本身值得注意）**

stage 1.2 校正早于 stage 2 安全检查。正面看，安全检查针对的是"最终要执行的命令"，合理；负面看，**若校正具有破坏性，安全检查评估的就是被改坏的命令**——本事故中 `\b` 已被改成 `/b`，安全检查面对的是残缺文本。当前 bash 校正改动幅度小，安全影响有限；但规则一多就危险。原则上校正应只做"语义减法"（去转义、统一分隔符）而不做结构性改写，避免改变安全判定所依赖的命令骨架。

#### 2.3.6 `/health` 自身的 DB 探测——观测工具反成卡死放大器

- `health.py` 的 DB 探测走 `db.atxn → to_thread`，即又会提交到线程池；
- 主进程卡死时，`/health` 请求本身也要排队，**观测失效**；
- 这是第 11 次事故里"日志静默 29 分钟无人知"的直接原因之一。

#### 2.3.7 启动期预热（`main.py`）——正确，但被 11-15 新增池稀释

- `_prewarm_loop_default_executor()`（:518）与 `prewarm_shell_binaries()`（def :171，调用 :604）方向正确；
- 但 11-15 `e6947dc44` 新增 `_TOOL_EXECUTOR(16)`，**让非 shell 工具也进入有界池**，虽然隔离了默认池，却把「一个慢 CreateProcess 阻塞全闸门」的影响面扩大到更多池。

### 2.4 正确性总判定

| 构件 | 设计正确性 | 实际有效性 | 问题定性 |
|---|---|---|---|
| WorkerPool 常驻线程 | ✅ 正确 | ✅ 生效（131 线程 idle） | 无 |
| 启动期预热 | ✅ 正确 | ✅ 生效（`runtime_thread_starts=0`） | 被新增池稀释 |
| 零线程读管道 `proc_io` | ✅ 正确 | ✅ 生效 | 无 |
| psutil 树杀 `proc_utils` | ✅ 正确 | ✅ 生效 | 无 |
| spawn_gate 租约闸门 | ⚠️ 方向对 | ❌ 只串行不消除，看门狗同进程 | 致命 |
| `_SHELL_SLOTS`/`_TOOL_SLOTS` | ⚠️ 数字对齐 | ❌ 线程死亡后永久错位 | 致命 |
| bash 容错路由 | ✅ 必要（ps7 无 grep） | ✅ 判定含引号剥离，合理 | 无 |
| bash 语法校正（反斜杠→正斜杠） | ❌ 全局无差别替换 | ❌ 摧毁引号内正则，静默错误 | **致命** |

## 第 3 章 多层进程/线程交互的冲突分析

### 3.1 真正在抢的只有三种资源

| 资源 | 层级 | 谁能抢 | 能否被 Python 中断 |
|---|---|---|---|
| **loader lock** | OS 内核 | `CreateProcessW`、新线程 bootstrap（`DLL_THREAD_ATTACH`） | **否** |
| **GIL** | 解释器 | 所有 Python 线程 | **否**（卡在 C 调用时） |
| **逻辑槽位** | 应用 | 4 套 `BoundedSemaphore` + 14 个队列 | 是（但归还≠恢复） |

14 个池、直连 14 行 / 7 文件的进程创建点，最终全部竞争这 3 种资源。

### 3.2 冲突链：为什么"隔离"越多反而越脆弱

```
用户命令
  → shell-exec 池线程取到任务
  → spawn_gate 约租（全局唯一一把锁）
  → subprocess.Popen.__init__ → CreateProcessW
      → 杀软实时扫描（实测 1.9s，最坏无限）
      → 持 loader lock + 不释放 GIL
  → 此时任何线程想 Thread.start
      → 都要 loader lock → 全部排在 spawn_gate 后面
      → ACQUIRE_TIMEOUT=15s 后抛 SpawnGateBusy
  → 同时 GIL 被持
      → 看门狗线程也跑不了 → 无法回收租约
      → /health 线程也跑不了 → 观测失效
      → 日志线程也跑不了 → 日志静默
```

### 3.3 池间协调现状：名义隔离，实际共享闸门

| 隔离维度 | 是否隔离 | 说明 |
|---|---|---|
| 执行线程 | ✅ 各池独立 | shell-exec / tool-exec / bg-shell-wait 互不占位 |
| 默认 executor | ✅ 已隔离 | `_TOOL_EXECUTOR` 不吃 `tool-sync` |
| **CreateProcess** | ❌ **共享** | 所有池的 Popen 都走同一把 `spawn_gate` |
| **loader lock** | ❌ **共享**（OS 级） | 无法在应用层隔离 |
| **GIL** | ❌ **共享**（解释器级） | 无法在应用层隔离 |
| 看门狗 | ❌ 同进程 | 主进程死则看门狗死 |
| `/health` 观测 | ❌ 同进程 | 主进程死则观测死 |

**核心矛盾**：前四行是应用层能做到的真隔离；中间三行是物理共享，应用层无法隔离。之前的全部修改都集中在前四行，而事故全部发生在中间三行。

### 3.4 具体冲突场景（可复现）

| 场景 | 触发条件 | 结果 |
|---|---|---|
| S1 单点慢 | 一条命令的 `CreateProcessW` 被 Defender 拉到 1.9s | 全局闸门 1.9s 内所有池的线程创建阻塞 |
| S2 槽位错位 | shell 任务超时，信号量归还但线程不还 | 信号量显示"有容量"，实际无可用线程，后续任务排队到死 |
| S3 观测失效 | 主进程卡在 loader lock | `/health` 排队、看门狗无法回收、日志停写 → 29 分钟无人知 |
| S4 池扩容放大 | 新增 `_TOOL_EXECUTOR(16)` | 更多池共享闸门，慢窗口内受影响请求数增加 |
| S5 隐式路由 | 命令含 `grep`/`echo`/`cd \` | 被切到 Git Bash `-l`，多一次登录 shell 初始化 + 一次 extra CreateProcess |

### 3.5 结论

> 系统不是"池太多"乱，而是**池再多也绕不开 OS 的 loader lock 和解释器的 GIL**。应用层的所有隔离、信号量、超时，都只能在"原生调用返回之后"才生效。而卡死恰恰发生在"原生调用返回之前"。

这解释了为什么"简化所有模式"后仍出事：**每次简化都在应用层做，从未改变"建进程发生在主进程内"这个前提。**

## 第 5 章 基于上述问题的根治方案

### 5.1 总原则

> **不变量：主进程启动完成后，永不执行 `CreateProcess`。**

线程可以启动期建满（已验证 `runtime_thread_starts=0` 可行），进程不能——每个用户命令都是一个新进程，杀软必扫。因此根治方向不是"再多加一层池/闸门"，而是**把建进程这个动作搬出主进程**。

> - **Defender 排除：L1 阶段强烈需要，L2 之后降为可选。** L2 落地后建进程搬到 broker，主进程卡死风险归零；但 broker 仍要为用户命令建进程，杀软仍会扫 broker 的 `CreateProcessW`。区别在于：主进程被扫→整服务停摆；broker 被扫→只是一个 broker 变慢，可 `TerminateProcess` 换下一个，不再致命。故 L2 后 Defender 排除从"必须"降为"性能优化"。

#### L2（架构根治，3~5 天，唯一能消灭 loader lock 风险）【未开始】

**核心：`shell-broker` 独立进程池**

```
主进程                          broker 进程（2~3 个，常驻）
  │                                    │
  ├─ 用户命令 {argv,cwd,env,timeout} ─→│
  │                                    ├─ CreateProcessW（在 broker 里）
  │                                    ├─ 流式 stdout/stderr
  │←──────────── {rc, stream} ─────────┤
  │                                    │
  └─ 卡死时：TerminateProcess(broker) ─→ 换下一个预热 broker
```

| 要点 | 设计 |
|---|---|
| 主进程零建进程 | 所有 `Popen` 调用改为 broker RPC |
| broker 预热 | 启动期拉起前台 3 + 后台 1 + 热备 2 = 6 个，已 warm |
| broker 卡死 | 主进程 `TerminateProcess` 杀 broker（此操作不需要 loader lock），换下一个 |
| 协议 | loopback TCP（`127.0.0.1`，broker 侧 `bind(port=0)` 由内核分配端口），长度前缀帧 + JSON 控制帧；不用命名管道（见 6.13） |
| 失败矩阵 | 连接失败→换 broker；broker 崩溃→标记并重启；全部 broker 忙→有界排队 |
| 池收敛 | 只收敛**进程创建**相关能力；线程池一个都不砍（见 7.1 逐项判定） |
| 槽位问题 | `_SHELL_SLOTS`/`_TOOL_SLOTS` **保留**（它们是线程闸门，与进程无关）；broker 前台数另行限制并发 |

**L2 的效果**：
- 主进程永不 `CreateProcessW` → loader lock 风险归零；
- broker 卡死可被 `TerminateProcess` 硬杀（OS 级，不需要 Python 跑起来）→ "不可中断"问题消失；
- `/health` 看门狗存活 → 观测永远可用；
- 槽位/信号量**不是 L2 的删除对象**（它们是线程并发闸门，与进程创建无关）；进程创建能力收敛到 broker 后，槽位错位（P2）由 L1-1 的 `WorkerSlots` 记账解决，与 L2 解耦

### 6.1 三层必要性与规范映射（先回答"L2/L3 要不要"）

#### 6.1.1 逐层判定：什么是止血、什么是根治

| 层 | 解决的问题 | 是否必需 | 判定依据（不可反驳的事实） |
|---|---|---|---|
| **L1** 止血 | 主进程内建线程/建进程的**频次与错位** | 必需 | 能在不改架构的前提下把 trigger 减到最少；但它**不能**消除 loader lock 本身 |
| **L2** broker | **主进程永不 `CreateProcessW`** | **必需（唯一根治）** | loader lock 是 Windows 内核在 `CreateProcessW` 调用期持有、且调用期间**不释放 GIL** 的锁。只要建进程还在主进程里，就必然与任意 `Thread.start()` 存在互锁窗口。任何"少建一点""建得快一点"都是概率优化，不是不变量。**把建进程搬到另一个进程，主进程内就不存在这个并发对** —— 这是唯一能把"概率"变成"不可能"的做法。 |
| **L3** supervisor | **主进程整体卡死时的自愈** | **必需（但不是全部）** | 见 6.1.2 分层拆解：外置看门狗必需，broker 负载均衡非必需 |

**L3 不是一个整体，必须拆开判定**（一刀切说"L3 要"或"L3 不要"都是耍流氓）：

| L3 子项 | 内容 | 判定 | 理由 |
|---|---|---|---|
| L3-a | **外置 supervisor**：独立进程监控主进程 `/health` + pid，超时则杀进程树重启 | **必需** | 进程内看门狗（`spawn_gate` 的 `_watchdog_loop`）是 Python 线程，**卡死时它自己也要 GIL**。11-04 事故已实证：主进程僵死时，看门狗线程连巡检都跑不动。自愈必须发生在**另一个进程**里，这是物理约束，不是设计偏好。 |
| L3-b | broker 负载均衡 / 动态扩缩容 | **不做（YAGNI）** | 当前并发上限是 `_SHELL_EXECUTOR_MAX=32` / `_TOOL_EXECUTOR_MAX=16`，实测峰值远低于此。固定 3 个 broker × 每个串行处理已覆盖需求。引入动态扩缩容＝运行期建进程＋策略状态机，**直接违背铁律**（运行期零建进程）。 |
| L3-c | 主进程重启后恢复未完成后台任务 | **不做（YAGNI）** | 后台任务产物已在 `output/` 落盘、注册表在内存；跨重启续跑需要持久化任务状态机，与"根治卡死"零关系，属于另一个产品需求。现有 `cleanup_orphan_artifacts` 已覆盖残留清理。 |

**结论**：L1 全部 + L2 全部 + L3-a。L3-b/L3-c 明确不做，并在 6.13 写明理由，避免下轮又被当成"漏项"。

#### 6.1.2 为什么"只做 L1"就是打补丁（自证）

| 假设 | 反例 |
|---|---|
| "L1 把建线程清零就安全了" | `CreateProcessW` 本身持 loader lock 且不释放 GIL → 此时**其他进程/线程**（如 AnyIO 线程池、uvicorn 的 worker、GC 触发的原生库懒加载）若同时进 loader lock，仍互锁。L1 只能管住"本仓库代码"，管不住三方库与解释器内部。 |
| "L1-4 硬拒 Thread.start 就安全了" | 硬拒只能拒绝**Python 层**的 `Thread.start`。`CreateProcessW` 仍是主进程发起，`DllMain(DLL_PROCESS_ATTACH)` 仍在主进程地址空间执行，第三方 C 扩展仍可能在其内部建线程。 |
| "反正很少发生" | 12 次实证事故、跨 4 个月、3 种不同面貌复发。概率优化在长尾上必然兑现。 |

> 一句话：**L1 让"卡死"变少，L2 让"卡死"不可能，L3 让"万一卡死"能自愈**。三者是三层不同性质的保证，缺一层就退回上一个层次。

#### 6.1.3 10 大规范逐条落点

| 规范 | 在本章设计中的具体落点 |
|---|---|
| **SRP** | `protocol`（编解码）/`server`（执行）/`client`（单连接）/`pool`（借还+健康）/`facade`（业务门面）五件事五个文件；`proc_io` 只管读、`proc_utils` 只管杀、broker 只管"在别的进程里执行"，不互相掺和 |
| **DRY** | broker **不复制**读/杀逻辑，直接 import `proc_io`/`proc_utils`/`job_object`；日志通过 `setup_logger` 的进程角色分支复用，不另建一套 |
| **KISS-DIRECT** | broker **单线程、单连接、一次一请求**（串行），并发完全由"多进程"提供；不做多路复用、不做协程、不做消息队列。协议只有"长度+tag+body"三要素 |
| **SLAP** | `facade.run()` 只做"转成请求→拿结果"，不做协议拼帧；拼帧在 `client`，执行在 `server`，三者不越层 |
| **YAGNI** | 不做 L3-b 动态扩缩、不做 L3-c 任务恢复、不做 broker 内线程池、不做流式 token 回放（当前无调用方消费流式） |

| **LSP** | `RemoteProcess` 与 `subprocess.Popen` 在**被使用到的子集**上同签名同语义（`pid/poll/wait/returncode/kill`），`shell_background` 无需改判定逻辑 |
| **ISP** | `facade` 只暴露 4 个方法（`run/run_raw/spawn/kill_tree`）+ 2 个生命周期方法（`start/shutdown`）与只读 `is_started()`；`query/epoch` 留在 `pool`，不泄给业务 |

#### 6.10.1 架构与不变量

```
┌──────────────────────── 主进程 (uvicorn / FastAPI) ────────────────────────┐
│  business: execute_shell_command / sandbox / shell_background / notify / … │
│                           │ 只调 4 个门面方法                                │
│                    facade.run / run_raw / spawn / kill_tree                │
│                           │                                                 │
│                    pool: 借还 + 热备提升 + 崩溃丢弃                          │
│                           │                                                 │

│                                                                             │

│  【不变量-2】运行期 broker 下线只能"提升热备"，绝不在主进程补建进程            │

┌─────────────────────────────────────▼───────────────────────────────────────┐
│  broker 进程 (python -m app.utils.spawn_broker.server)                       │
│  【单线程串行】一次只处理一条连接 → 本进程内不存在 Thread.start × CreateProcess│

└─────────────────────────────────────────────────────────────────────────────┘
```

**线程模型对照**（这是根治的核心，必须理解）：

| 位置 | 建线程 | 建进程 | 是否可能互锁 |
|---|---|---|---|
| 主进程（L2 后） | 运行期零建线程（L1-4 硬拒） | **零** | **不可能**（互锁需要两个都发生） |
| broker 进程 | 零（单线程串行，不 `Thread.start`） | 有（业务请求驱动） | **不可能**（同样缺一侧） |
| 其他工具线程池 | 启动期建满 | 零 | 不可能 |

L1 让第 1 行的"建线程"变零，L2 让第 1 行的"建进程"变零 —— 两者都到位，主进程侧这个并发对才**在数学上不存在**。

#### 6.10.2 帧协议（6.10.3 实现依据）

| 项 | 规定 |
|---|---|
| 传输 | TCP `127.0.0.1`，broker `bind(port=0)` 由内核分配端口，避免端口抢占竞态 |
| 连接模型 | **一次请求一条连接**；不接受多路复用（无请求 id、无乱序、无半包状态机） |
| 帧格式 | `[4B 大端长度 N][1B tag][N-1 字节 body]`，`1 ≤ N ≤ 32MiB` |
| tag | `b"J"`=JSON 控制帧；`b"O"`=stdout 块；`b"E"`=stderr 块；数据块 ≤1MiB 分帧 |
| 握手 | 每连接首帧必须是 `J`：`{"token": "<启动期随机>"}`，不匹配立即断开 |
| 请求 op | `run`（前台，全局 job）/ `runjob`（前台，请求级内存限制 job，沙箱用）/ `spawn`（后台，输出到文件）/ `query`（poll）/ `kill`（杀树） |
| 响应 | `run/runjob`：若干 `O`/`E` 帧 + 末帧 `J{rc,timed_out,truncated}`；其他 op：单帧 `J`；任何异常统一回 `J{"error": "..."}` |
| socket 超时 | 连接 3s；`run/runjob` = 请求 `timeout`+10s（无 timeout 时 610s）；`spawn` 5s；`query` 2s；`kill` 5s。任一超时→`BrokerDown`→池丢弃该 broker。**没有这一行，主进程会在"broker 卡住"时被 socket 无限期挂死，等于把病根搬到主进程** |
| 端口公告 | broker `bind` 成功后把 `READY <port> <epoch>` 写入环境变量 `OMNI_BROKER_READY_FILE` 指定文件；池侧有界轮询该文件（不用 `stdout.readline()`，那是无界阻塞） |

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: broker 帧协议(4B 长度 + 1B tag + body), 单连接单请求
"""spawn_broker.protocol — 帧协议 — 2026-11-15 小欧

帧 = [4B 大端长度 N][1B tag][body(N-1 字节)]
  tag b"J" JSON 控制帧 / b"O" stdout 块 / b"E" stderr 块

【为什么不做多路复用】一个连接只承载一次请求的响应流。多路复用会引入
"请求 id 路由 / 乱序重组 / 中途取消" 三类状态机，而本项目所有调用都是
"发一条命令、等它结束"，用不到 —— KISS-DIRECT。并发由"多 broker 进程"提供。
"""
import json
import socket
import struct

_LEN = struct.Struct(">I")
MAX_FRAME = 32 * 1024 * 1024   # 单帧上限: 超限即判流损坏, 防错位长度拖死内存


def send(sock: socket.socket, tag: bytes, body: bytes) -> None:
    sock.sendall(_LEN.pack(len(body) + 1) + tag + body)


def send_json(sock: socket.socket, obj) -> None:
    send(sock, b"J", json.dumps(obj, ensure_ascii=False).encode("utf-8"))


def _recv_exact(sock: socket.socket, n: int) -> bytes:
    buf = bytearray()
    while len(buf) < n:
        chunk = sock.recv(n - len(buf))
        if not chunk:
            raise ConnectionError("broker 连接被对端关闭")
        buf.extend(chunk)
    return bytes(buf)


def recv(sock: socket.socket):
    (n,) = _LEN.unpack(_recv_exact(sock, 4))
    if n < 1 or n > MAX_FRAME:
        raise ConnectionError(f"非法帧长度: {n}")
    data = _recv_exact(sock, n)
    return data[:1], data[1:]
```

```python
# 2026-11-15 - 小欧 - 新建: broker 进程入口(单线程串行执行子进程), 主进程零 CreateProcess 的落点
"""spawn_broker.server — broker 进程入口 — 2026-11-15 小欧

1. 本进程是唯一执行 CreateProcessW 的地方; 主进程只做 socket I/O + psutil 查询。
2. 单线程串行: 同一时刻只处理一个连接 —— 本进程内不存在 "Thread.start() ×

_CHUNK = 1024 * 1024        # 数据块 1MiB: 大输出分帧, 不撑爆接收端内存
_ACTIVE_LIMIT = 2048        # 全局 job 进程数上限(堵 fork 炸弹, 远高于正常命令需求)

_procs: Dict[int, subprocess.Popen] = {}   # 后台进程表; broker 死则表消失(子进程由 job 收编)


def _prune_procs() -> None:
    """清理已退出的后台进程条目 — 2026-11-15 小欧
    通知/explorer 这类"发起后无人 poll"的 spawn 若不清表, _procs 只增不减。"""
    for pid, p in list(_procs.items()):
        if p.poll() is not None:
            _procs.pop(pid, None)


def _send_chunks(sock: socket.socket, tag: bytes, data: bytes) -> None:
    for i in range(0, len(data), _CHUNK):
        protocol.send(sock, tag, data[i:i + _CHUNK])


def _exec(req: dict, job: SandboxJob) -> dict:
    """建一个子进程 → 收入 job → 读完输出; 超时/截断的杀树都在本函数内完成。"""
    proc = subprocess.Popen(
        req["argv"], shell=bool(req.get("shell")),
        cwd=req.get("cwd") or None, env=req.get("env") or None,
        stdout=subprocess.PIPE, stderr=subprocess.PIPE,
        creationflags=int(req.get("creationflags") or 0),
    )
    try:
        job.assign(proc)
    except OSError:
        kill_process_tree(proc)     # 收编失败必须当场杀掉, 否则脱离 job 成为孤儿
        raise
    timeout = req.get("timeout")
    out, err, timed_out, truncated = drain_until_exit(
        proc, None if timeout is None else float(timeout))
    if truncated:
        kill_process_tree(proc)
        err += TRUNCATED_NOTE
    if timed_out:
        kill_process_tree(proc)
        tail_out, tail_err = drain_after_exit(proc, 1.0)
        out += tail_out
        err += tail_err
    rc = proc.returncode if proc.returncode is not None else -1
    return {"rc": rc, "timed_out": timed_out, "truncated": truncated,
            "out": out, "err": err}


def _emit_result(sock: socket.socket, res: dict) -> None:
    _send_chunks(sock, b"O", res.pop("out"))
    _send_chunks(sock, b"E", res.pop("err"))
    protocol.send_json(sock, res)


def _dispatch(sock: socket.socket, hello: dict, job: SandboxJob) -> None:
    op = hello.get("op")
    if op == "run":
        _emit_result(sock, _exec(hello, job))
        return
    if op == "runjob":
        own_job = SandboxJob(
            process_memory_limit_mb=int(hello.get("mem_limit_mb") or 2048),
            active_process_limit=64)
        try:
            res = _exec(hello, own_job)
        finally:
            own_job.close()     # KILL_ON_JOB_CLOSE: 命令结束后残留孙进程随句柄关闭被清杀
        _emit_result(sock, res)
        return
    if op == "spawn":
        _prune_procs()
        fh = open(hello["out_file"], "ab")   # 追加: 调用方已建空文件, 内容只由子进程写
        try:
            proc = subprocess.Popen(
                hello["argv"], shell=bool(hello.get("shell")),
                cwd=hello.get("cwd") or None, env=hello.get("env") or None,
                stdout=fh, stderr=subprocess.STDOUT,
                creationflags=int(hello.get("creationflags") or 0),
            )
        finally:
            fh.close()
        try:
            job.assign(proc)
        except OSError:
            kill_process_tree(proc)
            raise
        _procs[proc.pid] = proc
        protocol.send_json(sock, {"pid": proc.pid})
        return
    if op == "query":
        _prune_procs()
        proc = _procs.get(int(hello.get("pid") or 0))
        protocol.send_json(sock, {"rc": proc.poll() if proc is not None else -1})
        return
    if op == "kill":
        proc = _procs.pop(int(hello.get("pid") or 0), None)
        if proc is not None:
            kill_process_tree(proc)
        protocol.send_json(sock, {"ok": True})
        return
    protocol.send_json(sock, {"error": f"未知 op: {op!r}"})


def _serve(conn: socket.socket, token: str, job: SandboxJob) -> None:
    tag, body = protocol.recv(conn)
    if tag != b"J":
        return
    hello = json.loads(body.decode("utf-8"))
    if hello.get("token") != token:
        logger.warning("[broker] 握手 token 不匹配, 断开连接")
        return
    try:
        _dispatch(conn, hello, job)
    except Exception as e:      # 错误必须回给调用方, 否则客户端等到 socket 超时才失败
        logger.exception(f"[broker] 请求执行异常: {e!r}")
        try:
            protocol.send_json(conn, {"error": f"{type(e).__name__}: {e}"})
        except OSError:
            pass

    epoch = int(os.environ.get("OMNI_BROKER_EPOCH", "0"))
    from app.tools.fundamental.shell_engine import prewarm_shell_binaries
    prewarm_shell_binaries()    # 首次 CreateProcessW 留在 broker 启动期, 不进主进程
    job = SandboxJob(process_memory_limit_mb=None, active_process_limit=_ACTIVE_LIMIT)
    srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind(("127.0.0.1", 0))
    srv.listen(16)
    port = srv.getsockname()[1]
    _announce_ready(port, epoch)
    logger.info(f"[broker] 就绪: pid={os.getpid()}, port={port}, epoch={epoch}")
    while True:
        conn, _ = srv.accept()
        try:
            with conn:
                _serve(conn, token, job)
        except (ConnectionError, OSError) as e:
            logger.warning(f"[broker] 连接处理失败(继续服务): {e!r}")
        except Exception as e:      # 未知异常同样不得退出: 退出=运行期要补建进程
            logger.exception(f"[broker] 未预期异常(继续服务): {e!r}")


if __name__ == "__main__":
    raise SystemExit(main())
```

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: broker 单连接客户端(每请求一连接, 首帧 token 握手)
"""spawn_broker.client — 单 broker 连接的请求封装 — 2026-11-15 小欧

每次请求新建一条 loopback 连接: 请求-响应严格一一对应, 无请求 id/无多路复用。
连接失败或中断统一抛 BrokerDown, 由 pool 决定"提升热备"还是"明确失败"。

【socket 超时 — 不可省】前台命令的执行超时由 broker 侧 proc_io 负责; 但"broker 自身
卡住/不响应"只能由 socket 层兜住。若连接设成阻塞无超时, 主进程线程会被无限期挂死
—— 那等于把病根原封不动搬回主进程。故每类 op 都给硬上限(见 _OP_TIMEOUT)。
"""
import json
import socket
from typing import Optional

from app.utils.spawn_broker import protocol

_CONNECT_TIMEOUT = 3.0
_RUN_TIMEOUT_DEFAULT = 600.0      # 未显式给 timeout 时的兜底(保险丝正常都会给)
_RUN_GRACE = 10.0                 # broker 侧杀树+读残存窗口, 必须晚于命令自身超时
_OP_TIMEOUT = {"spawn": 5.0, "query": 2.0, "kill": 5.0}


class BrokerDown(RuntimeError):
    """broker 不可达 / 超时 / 连接中断 / 响应非法。"""


class BrokerClient:
    def __init__(self, pid: int, port: int, token: str, epoch: int) -> None:
        self.pid = pid
        self.port = port
        self.token = token
        self.epoch = epoch

    def _connect(self) -> socket.socket:
        try:
            return socket.create_connection(("127.0.0.1", self.port),
                                            timeout=_CONNECT_TIMEOUT)
        except OSError as e:
            raise BrokerDown(f"连接 broker 失败(port={self.port}): {e!r}") from e

    def _request(self, hello: dict, collect: bool = False, sock_timeout: float = 5.0):
        hello["token"] = self.token
        try:
            with self._connect() as sock:
                sock.settimeout(sock_timeout)     # 本次请求的硬上限(含读响应流)
                protocol.send_json(sock, hello)
                if not collect:
                    tag, body = protocol.recv(sock)
                    if tag != b"J":
                        raise BrokerDown(f"响应帧类型错位: {tag!r}")
                    res = json.loads(body.decode("utf-8"))
                    if "error" in res:
                        raise BrokerDown(res["error"])
                    return res
                out, err = bytearray(), bytearray()
                while True:
                    tag, body = protocol.recv(sock)
                    if tag == b"O":
                        out.extend(body)
                    elif tag == b"E":
                        err.extend(body)
                    elif tag == b"J":
                        res = json.loads(body.decode("utf-8"))
                        if "error" in res:
                            raise BrokerDown(res["error"])
                        res["out"] = bytes(out)
                        res["err"] = bytes(err)
                        return res
                    else:
                        raise BrokerDown(f"未知帧 tag: {tag!r}")
        except (OSError, ConnectionError) as e:   # socket.timeout 是 OSError 子类
            raise BrokerDown(
                f"broker 通信中断(port={self.port}, op={hello.get('op')}, "
                f"timeout={sock_timeout}s): {e!r}") from e

    @staticmethod
    def _run_budget(timeout) -> float:
        return (_RUN_TIMEOUT_DEFAULT if timeout is None else float(timeout)) + _RUN_GRACE

    def run(self, **req) -> dict:
        return self._request(dict(req, op="run"), collect=True,
                             sock_timeout=self._run_budget(req.get("timeout")))

    def runjob(self, mem_limit_mb: int, **req) -> dict:
        return self._request(dict(req, op="runjob", mem_limit_mb=mem_limit_mb), collect=True,
                             sock_timeout=self._run_budget(req.get("timeout")))

    def spawn(self, **req) -> int:
        return int(self._request(dict(req, op="spawn"),
                                 sock_timeout=_OP_TIMEOUT["spawn"])["pid"])

    def query(self, pid: int) -> Optional[int]:
        rc = self._request({"op": "query", "pid": pid},
                           sock_timeout=_OP_TIMEOUT["query"])["rc"]
        return None if rc is None else int(rc)

    def kill(self, pid: int) -> None:
        self._request({"op": "kill", "pid": pid}, sock_timeout=_OP_TIMEOUT["kill"])
```

#### 6.10.6 新增 `backend/app/utils/spawn_broker/pool.py`（全文）

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: broker 池(启动期预热 size+spare, 前台借还, 后台独占, 崩溃提升热备)
"""spawn_broker.pool — broker 池 — 2026-11-15 小欧

【为什么预留热备而不是崩溃后重建】运行期不得 CreateProcess(铁律)。broker 异常
下线时只能从启动期预留的热备提升; 热备耗尽则**明确失败并告警**, 而不是顺手在
运行期再建一个 —— 后者会把"主进程建进程"这个原病根原封不动搬回来。

【前台/后台分池】后台进程表在 broker 内存里, query/kill 必须路由到"创建它的那个
broker"。故后台固定由一个独占 broker(及其热备)承载, 请求用锁串行化(都是毫秒级);
前台命令用 size 个 broker 做并发。路由复杂度为零 —— 一个 pid 只属于 bg 池。
"""
import os
import queue
import subprocess
import sys
import tempfile
import threading
import time
import uuid
from pathlib import Path
from typing import Dict, List, Optional

from app.logger import logger
from app.utils.spawn_broker.client import BrokerClient, BrokerDown

_READY_TIMEOUT = 20.0       # broker 冷启动上限(import app.* 常 1~3s)
_ACQUIRE_TIMEOUT = 30.0     # 前台并发超出 broker 数时的排队上限
_IS_FROZEN = bool(getattr(sys, "frozen", False))


def _backend_root() -> Path:
    """包含 app 包的目录(= backend/), 作为 broker 子进程 cwd, 保证 -m 可解析。"""
    return Path(__file__).resolve().parents[3]


def _broker_argv() -> List[str]:
    if _IS_FROZEN:      # 打包态: 用自身 exe + 专用开关进入 broker 角色
        return [sys.executable, "--omni-broker"]
    return [sys.executable, "-m", "app.utils.spawn_broker.server"]


class RemoteProcess:
    """远端进程句柄: 在 shell_background 用到的子集上与 subprocess.Popen 同语义(LSP)。"""

    def __init__(self, pid: int, pool: "BrokerPool", epoch: int) -> None:
        self.pid = pid
        self.args = ""
        self._pool = pool
        self._epoch = epoch
        self._rc: Optional[int] = None

    @property
    def returncode(self) -> Optional[int]:
        return self._rc

    def poll(self) -> Optional[int]:
        if self._rc is None:
            self._rc = self._pool.query(self.pid, self._epoch)
        return self._rc

    def wait(self, timeout: Optional[float] = None) -> int:
        deadline = None if timeout is None else time.monotonic() + timeout
        while True:
            rc = self.poll()
            if rc is not None:
                return rc
            if deadline is not None and time.monotonic() >= deadline:
                raise subprocess.TimeoutExpired(self.args, timeout)
            time.sleep(0.05)

    def kill(self) -> None:
        self._pool.kill(self.pid, self._epoch)


class BrokerPool:
    def __init__(self, size: int, spare: int = 2) -> None:
        self._size = max(1, size)
        self._spare = max(1, spare)
        self._token = uuid.uuid4().hex
        self._epoch = 0
        self._idle: "queue.Queue[BrokerClient]" = queue.Queue()
        self._handles: Dict[int, subprocess.Popen] = {}
        self._bg_client: Optional[BrokerClient] = None
        self._bg_spares: List[BrokerClient] = []
        self._bg_lock = threading.Lock()

    # ── 生命周期 ────────────────────────────────────────────
    def start(self) -> None:
        for _ in range(self._size):
            self._idle.put(self._spawn())
        self._bg_client = self._spawn()
        for _ in range(self._spare):
            self._bg_spares.append(self._spawn())
        logger.info(f"[broker] 池就绪: 前台={self._size}, 后台=1, 热备={len(self._bg_spares)}")

    def _spawn(self) -> BrokerClient:
        self._epoch += 1
        # ready 文件握手(不用 stdout.readline: 那是无界阻塞, broker import 卡住会把主进程启动一起挂死)
        ready = os.path.join(tempfile.gettempdir(),
                             f"omni_broker_ready_{os.getpid()}_{self._epoch}.txt")
        try:
            os.unlink(ready)
        except OSError:
            pass
        env = dict(os.environ)
        env.update({
            "OMNI_BROKER_TOKEN": self._token,
            "OMNI_BROKER_EPOCH": str(self._epoch),
            "OMNI_BROKER_READY_FILE": ready,
            "OMNI_PROC_BROKER_CHILD": "1",
            "PYTHONIOENCODING": "utf-8",
            "PYTHONUTF8": "1",
        })
        proc = subprocess.Popen(
            _broker_argv(), cwd=str(_backend_root()), env=env,
            stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL,
            creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0),
        )
        deadline = time.monotonic() + _READY_TIMEOUT
        line = ""
        while time.monotonic() < deadline:
            if proc.poll() is not None:      # 启动失败=已退出, 立即显形, 不空等
                break
            try:
                line = Path(ready).read_text(encoding="utf-8").strip()
            except OSError:
                line = ""
            if line.startswith("READY "):
                break
            time.sleep(0.02)
        try:
            os.unlink(ready)
        except OSError:
            pass
        if not line.startswith("READY "):
            proc.kill()
            raise RuntimeError(f"broker 启动握手失败(rc={proc.poll()}, ready={line!r})")
        _, port, epoch = line.split()
        self._handles[proc.pid] = proc
        return BrokerClient(proc.pid, int(port), self._token, int(epoch))

    def _discard(self, client: BrokerClient) -> None:
        """broker 已不可用: TerminateProcess 硬杀它本体(零建进程), 其 job 句柄随之关闭,
        内核按 KILL_ON_JOB_CLOSE 清杀该 broker 名下全部子孙进程。"""
        proc = self._handles.pop(client.pid, None)
        if proc is not None and proc.poll() is None:
            try:
                proc.kill()
            except OSError as e:
                logger.debug(f"[broker] discard kill 异常(已退出, 忽略): {e!r}")
        logger.warning(f"[broker] 已丢弃 broker(pid={client.pid}, epoch={client.epoch}), "
                       f"其名下子进程由 job 关闭清杀")

    def shutdown(self) -> None:
        while True:                      # 清空空闲队列, 避免关闭后仍被借出旧 client
            try:
                self._idle.get_nowait()
            except queue.Empty:
                break
        clients = list(self._handles.keys())
        for pid in clients:
            proc = self._handles.pop(pid, None)
            if proc is not None and proc.poll() is None:
                try:
                    proc.kill()
                except OSError:
                    pass
        self._bg_client = None
        self._bg_spares.clear()
        logger.info(f"[broker] 池已关闭: 终止 {len(clients)} 个 broker(各自 job 清杀子进程)")

    # ── 前台: 借还 ──────────────────────────────────────────
    def _acquire(self) -> BrokerClient:
        try:
            return self._idle.get_nowait()
        except queue.Empty:
            pass
        try:
            return self._idle.get(timeout=_ACQUIRE_TIMEOUT)
        except queue.Empty:
            raise BrokerDown(f"前台 broker 全部忙, 排队 {_ACQUIRE_TIMEOUT}s 超时")

    def run(self, timeout=None, mem_limit_mb: Optional[int] = None, **req) -> dict:
        client = self._acquire()
        ok = False
        try:
            if mem_limit_mb:
                res = client.runjob(mem_limit_mb, timeout=timeout, **req)
            else:
                res = client.run(timeout=timeout, **req)
            ok = True
            return res
        except BrokerDown as e:
            self._discard(client)
            raise BrokerDown(f"前台执行失败, broker 已丢弃: {e}") from e
        except BaseException:
            # 超时/序列化/协议错位等: 该连接状态不可信(可能停在半帧), 绝不能回池
            self._discard(client)
            raise
        finally:
            if ok and client.pid in self._handles:
                self._idle.put(client)

    # ── 后台: 独占 + 热备 ───────────────────────────────────
    def _bg_take(self) -> BrokerClient:
        if self._bg_client is None:
            raise BrokerDown("后台 broker 未初始化")
        return self._bg_client

    def _bg_promote(self) -> None:
        old = self._bg_client
        if old is not None:
            self._discard(old)
        if not self._bg_spares:
            self._bg_client = None
            raise BrokerDown("后台 broker 与热备均已下线, 后台执行不可用(需重启服务)")
        self._bg_client = self._bg_spares.pop()
        logger.warning(f"[broker] 后台 broker 热备接管: epoch={self._bg_client.epoch}, "
                       f"剩余热备={len(self._bg_spares)}")

    def spawn(self, **req) -> RemoteProcess:
        with self._bg_lock:
            client = self._bg_take()
            try:
                pid = client.spawn(**req)
            except BrokerDown:
                self._bg_promote()
                pid = self._bg_take().spawn(**req)
            return RemoteProcess(pid, self, client.epoch)

    def query(self, pid: int, epoch: int) -> Optional[int]:
        with self._bg_lock:
            if epoch != getattr(self._bg_client, "epoch", -1):
                return -1       # 创建它的 broker 已下线: 其 job 已清杀, 按失败收口
            try:
                return self._bg_client.query(pid)
            except BrokerDown:
                self._bg_promote()
                return -1

    def kill(self, pid: int, epoch: int) -> None:
        with self._bg_lock:
            if epoch != getattr(self._bg_client, "epoch", -1):
                return          # 旧 broker 已死, job 已清杀, 无需再杀
            try:
                self._bg_client.kill(pid)
            except BrokerDown:
                self._bg_promote()
```

> **握手与后台轮询的取舍**：`_READY_TIMEOUT` 现在真实生效（ready 文件 + 有界轮询），broker 启动失败要么进程已退出、要么超时显形，主进程启动不会被无限期挂住。后台 `RemoteProcess.wait()` 仍是 0.05s 轮询（每次 `query` 一次 2s 上限的 loopback 往返），这是为了让 `kill` 能随时插队——若改成 broker 侧阻塞等待，单线程 broker 会把这唯一线程占住，`kill` 永远进不来。

```python
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: 主进程进程执行门面(Windows 走 broker, 非 Windows 走本地)
"""spawn_broker.facade — 主进程唯一进程执行入口 — 2026-11-15 小欧

对外 4 个方法(ISP):
  run      —— 与 proc_io.run 同签名同语义(超时抛 TimeoutExpired), 供 18 处既有调用点
  run_raw  —— 返回 {rc, out, err, timed_out, truncated}, 供需要自行处理超时的调用方
  spawn    —— 后台进程(输出到文件), 返回 RemoteProcess
  kill_tree —— 杀远端进程树

非 Windows 平台无 loader lock 问题, run/run_raw 直接走本地实现 —— 这是能力差异,
不是"双路径兼容"; Windows 上 broker 未启动直接抛错(启动期错误必须早暴露)。
"""

import subprocess
import sys

def is_active() -> bool:
    """本平台是否有 broker 通道(Windows)。仅表达能力, 不表达是否已启动。"""
    return _WINDOWS

    """broker 池是否已启动 — proc_io.run 据此决定委托还是走本地实现。"""
    return _pool is not None

    global _pool
    if not _WINDOWS or _pool is not None:
        return
    _pool = BrokerPool(size, spare)
    _pool.start()


def shutdown() -> None:
    global _pool
    if _pool is not None:
        _pool.shutdown()
        _pool = None


def _require_pool() -> BrokerPool:
    if _pool is None:
        raise RuntimeError("spawn_broker 未启动: main.py startup 必须调用 facade.start()")
    return _pool


def run_raw(args, *, timeout=None, cwd=None, env=None, shell=False,
            creationflags: int = 0, mem_limit_mb: Optional[int] = None) -> dict:
    """返回 {rc, out(bytes), err(bytes), timed_out, truncated}。超时不抛, 由调用方判定。"""
    if not _WINDOWS:
        from app.utils.proc_io import _run_local_raw
        return _run_local_raw(args, timeout=timeout, cwd=cwd, env=env, shell=shell,
                              creationflags=creationflags)
    return _require_pool().run(
        timeout=timeout, mem_limit_mb=mem_limit_mb,
        argv=list(args), cwd=str(cwd) if cwd else None, env=env,
        shell=shell, creationflags=int(creationflags or 0))


def run(args, *, timeout=None, cwd=None, env=None, shell=False,
        encoding=None, errors=None, text=False, mem_limit_mb: Optional[int] = None,
        creationflags: int = 0):
    """与 proc_io.run 同签名: 超时先杀树再抛 subprocess.TimeoutExpired(携带已读输出)。"""
    if text and encoding is None:
        encoding = locale.getpreferredencoding(False)
    res = run_raw(args, timeout=timeout, cwd=cwd, env=env, shell=shell,
                  mem_limit_mb=mem_limit_mb, creationflags=creationflags)
    out_b, err_b = res["out"], res["err"]
    if res["timed_out"]:
        raise subprocess.TimeoutExpired(
            args, timeout,
            output=out_b.decode(encoding, errors or "strict") if encoding else out_b,
            stderr=err_b.decode(encoding, errors or "strict") if encoding else err_b)
    return subprocess.CompletedProcess(
        args, res["rc"],
        stdout=out_b.decode(encoding, errors or "strict") if encoding else out_b,
        stderr=err_b.decode(encoding, errors or "strict") if encoding else err_b)


def spawn(args, *, out_file: str, cwd=None, env=None, shell=False,
          creationflags: int = 0) -> RemoteProcess:
    if not _WINDOWS:
        raise RuntimeError("spawn_broker 后台通道仅 Windows 启用")
    return _require_pool().spawn(
        argv=list(args), out_file=out_file, cwd=str(cwd) if cwd else None,
        env=env, shell=shell, creationflags=int(creationflags or 0))


def kill_tree(proc) -> None:
    """与 proc_utils.kill_process_tree 等价: 对 RemoteProcess 走 broker 杀树, 其它走本地。"""
    if isinstance(proc, RemoteProcess):
        proc.kill()
        return
    from app.utils.proc_utils import kill_process_tree
    kill_process_tree(proc)
```

### 6.11 L3-a：外置看门狗（supervisor）【未开始】

#### 6.11.1 为什么必须外置（物理约束，不是设计偏好）

| 方案 | 卡死时能否自救 | 结论 |
|---|---|---|
| 进程内看门狗线程（现状 `spawn_gate._watchdog_loop`） | 不能：线程调度要 GIL，主进程僵死时它连 `time.sleep` 后的下一轮都跑不动 | 只能做"健康时巡检"，不能做"病时抢救" |
| 独立进程 + HTTP 探活 | 能：探活与杀树都在另一个进程的地址空间 | **唯一可行** |
| 操作系统服务（Windows Service / 计划任务） | 能，但引入部署复杂度与权限要求 | 本项目不需要，supervisor 作为父进程已足够 |

`supervisor` 是**主进程的父进程**：先存在、后退出；自身零线程、零业务导入（不 import `app.*`，避免拉起 FastAPI 栈与日志文件竞争）。

#### 6.11.2 新增 `backend/app/utils/supervisor.py`（全文）

```python
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-11-15 - 小欧 - 新建: 外置看门狗(supervisor) —— 主进程卡死时唯一可行的自救路径
"""supervisor — 外置看门狗 — 2026-11-15 小欧

【为什么必须外置】进程内看门狗是 Python 线程, 主进程僵死时它同样拿不到 GIL,
连"发现卡死"都做不到(11-04 事故实证)。能救主进程的只可能是另一个进程。

【职责(SRP)】只做四件事: 起主进程 / 定时探活 / 判卡死后杀树 / 再起。
零线程、零 app.* 导入(不拉起 FastAPI 与主日志, 避免进程间文件竞争)。

【判活双条件】连续 FAILS 次同时满足才判卡死:
  1) GET /health 在 timeout 内未返回 200;
  2) 主进程 pid 仍存活。
  pid 已消失 = 普通退出/崩溃 → 不计入卡死, 直接快速重启。

【用法】
  python -m app.utils.supervisor -- python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
  环境变量:
    OMNI_SUP_HEALTH_URL   (默认 http://127.0.0.1:8000/health)
    OMNI_SUP_HEALTH_TIMEOUT (秒, 默认 10)
    OMNI_SUP_INTERVAL     (秒, 默认 15)
    OMNI_SUP_FAILS        (连续失败阈值, 默认 3)
    OMNI_SUP_MAX_RESTARTS (最大重启次数, 默认 5)
    OMNI_SUP_LOG          (默认 <backend>/logs/supervisor.log)
"""
import logging
import os
import subprocess
import sys
import time
import urllib.error
import urllib.request
from dataclasses import dataclass
from pathlib import Path
from typing import Optional

try:
    import psutil
except ImportError:      # 无 psutil 时退化为"只杀根进程", 不中断看护
    psutil = None

logger = logging.getLogger("omni.supervisor")


@dataclass
class _Config:
    health_url: str
    health_timeout: float
    interval: float
    fails_threshold: int
    max_restarts: int
    log_file: str

    @classmethod
    def from_env(cls) -> "_Config":
        root = Path(__file__).resolve().parents[2]      # backend/
        return cls(
            health_url=os.environ.get("OMNI_SUP_HEALTH_URL", "http://127.0.0.1:8000/health"),
            health_timeout=float(os.environ.get("OMNI_SUP_HEALTH_TIMEOUT", "10")),
            interval=float(os.environ.get("OMNI_SUP_INTERVAL", "15")),
            fails_threshold=max(1, int(os.environ.get("OMNI_SUP_FAILS", "3"))),
            max_restarts=max(0, int(os.environ.get("OMNI_SUP_MAX_RESTARTS", "5"))),
            log_file=os.environ.get("OMNI_SUP_LOG", str(root / "logs" / "supervisor.log")),
        )


def _setup_log(log_file: str) -> None:
    Path(log_file).parent.mkdir(parents=True, exist_ok=True)
    h = logging.FileHandler(log_file, encoding="utf-8")
    h.setFormatter(logging.Formatter("%(asctime)s %(levelname)s %(message)s"))
    logger.addHandler(h)
    logger.addHandler(logging.StreamHandler())
    logger.setLevel(logging.INFO)


def _probe_health(cfg: _Config) -> bool:
    try:
        with urllib.request.urlopen(cfg.health_url, timeout=cfg.health_timeout) as resp:
            return 200 <= resp.status < 300
    except (urllib.error.URLError, OSError, ValueError):
        return False


def _pid_alive(pid: int) -> bool:
    return psutil is not None and psutil.pid_exists(pid)


def _kill_tree_and_wait(proc: subprocess.Popen, wait_sec: float = 10.0) -> Optional[int]:
    """psutil 杀整棵树(零建进程) → 有界等待根退出。返回退出码或 None(未确认)。"""
    if psutil is not None:
        try:
            procs = psutil.Process(proc.pid).children(recursive=True)
            for p in reversed(procs):
                try:
                    p.kill()
                except Exception:
                    pass
        except Exception:
            pass
    try:
        proc.kill()
    except OSError:
        pass
    try:
        return proc.wait(timeout=wait_sec)
    except subprocess.TimeoutExpired:
        logger.error(f"[supervisor] 杀树后 {wait_sec}s 仍未见退出, pid={proc.pid}")
        return None


def _watch(proc: subprocess.Popen, cfg: _Config) -> str:
    """返回 'stopped'(自行退出) / 'hung'(判定卡死) 。"""
    fails = 0
    while True:
        if proc.poll() is not None:
            return "stopped"
        if _probe_health(cfg):
            fails = 0
        elif _pid_alive(proc.pid):
            fails += 1
            logger.warning(f"[supervisor] /health 探测失败 {fails}/{cfg.fails_threshold} "
                           f"(pid={proc.pid} 仍存活)")
            if fails >= cfg.fails_threshold:
                return "hung"
        else:
            return "stopped"    # pid 消失: 崩溃/正常退出, 不是卡死
        time.sleep(cfg.interval)


def main(argv: Optional[list] = None) -> int:
    argv = list(sys.argv[1:] if argv is None else argv)
    if "--" not in argv:
        print("用法: python -m app.utils.supervisor -- <主进程命令...>", file=sys.stderr)
        return 2
    cmd = argv[argv.index("--") + 1:]
    if not cmd:
        print("用法: -- 之后必须给出主进程命令", file=sys.stderr)
        return 2
    cfg = _Config.from_env()
    _setup_log(cfg.log_file)
    restarts = 0
    proc = None
    try:
        while True:
            proc = subprocess.Popen(cmd, env=dict(os.environ))
            logger.info(f"[supervisor] 主进程已启动: pid={proc.pid}, 重启计数={restarts}")
            reason = _watch(proc, cfg)
            rc = _kill_tree_and_wait(proc)
            if reason == "stopped":
                logger.info(f"[supervisor] 主进程自行退出(rc={rc}), 停止看护")
                return 0
            restarts += 1
            if restarts > cfg.max_restarts:
                logger.error(f"[supervisor] 重启次数耗尽({cfg.max_restarts}), 放弃并退出")
                return 1
            logger.warning(f"[supervisor] 判定卡死(连续 {cfg.fails_threshold} 次探活失败), "
                           f"已杀主进程树; 准备第 {restarts} 次重启")
            time.sleep(min(5.0 * restarts, 30.0))   # 递增退避, 防"重启即卡"打满 CPU
    except KeyboardInterrupt:
        # Ctrl+C 同时发给整个进程组: 收口杀树后退出, 不重启、不留孤儿
        logger.warning("[supervisor] 收到 Ctrl+C, 终止主进程树后退出(不重启)")
        if proc is not None:
            _kill_tree_and_wait(proc, 5.0)
        return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

#### 6.11.4 停机与 supervisor 的交互

| 场景 | 期望行为 |
|---|---|
| 正常关闭（用户 Ctrl+C / 服务停止） | 主进程收到信号 → `shutdown_event` 跑完 → 进程退出 → supervisor `poll()` 非空 → 记 `stopped` 并自身退出（不重启）。**Ctrl+C 会同时发给进程组**：已在 6.11.2 `main()` 外层加 `except KeyboardInterrupt` → 收口 `_kill_tree_and_wait` 后退出，不留主进程孤儿（不是待办项，代码已含） |

|---|---|---|
| L3-b broker 动态扩缩容 / 负载均衡 | 不做 | 见 6.1.1；固定 3+1+2 已覆盖当前并发上限 |
| L3-c 跨重启恢复未完成后台任务 | 不做 | 与"根治卡死"无关，属独立产品需求 |
| broker 间共享进程表 | 不做 | 后台进程固定归属单一 broker，路由复杂度为零 |
| 用命名管道替代 TCP | 不做 | loopback TCP + token 在本机威胁模型下足够，且零依赖（命名管道需额外 Win32 封装） |
| 流式输出（边执行边回传增量） | 不做 | 当前无调用方消费流式；`drain_until_exit` 聚合语义不变 |

|---|---|---|
| uvicorn 多 worker 模式下**每个 worker 各有自己的 broker 池**（6 个/worker） | 进程数随 worker 线性增长 | 部署文档按 worker 数调 `size`；默认单 worker 部署 |

**顺序不可调换的三条硬理由**

1. **L1 必须先行**：否则 L2 迁移期间的对比回归没有稳定基线（bash 静默丢行、超时槽位错位都会污染对比结果）。
2. **阶段 2 必须先于阶段 3**：阶段 2 完成前 `proc_io.run` 未接门面，阶段 3 改出来的 `proc_run` 会走本地实现，"以为迁完其实没走 broker"。
3. **阶段 4 必须最后**：`spawn_gate` 的 `popen_calls` 是**迁移进度表**；提前拆补丁就失去"还有几处在建进程"的唯一可观测信号。

**每阶段的提交粒度**：一项一个 commit，信息格式 `fix:<代码名> <说明> - 小欧-2026-11-15`。禁止把"新增 broker 包"和"删除旧路径"放进同一提交（无法单步回滚）。
