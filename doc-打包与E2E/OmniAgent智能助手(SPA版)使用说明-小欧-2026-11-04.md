## 一、启动和运行

### 1.1 包里有什么，放在哪

绿色版，不用安装：把**整个文件夹**拷到本机任意位置（如 `D:\OmniAgent`）就能用。

**不能只拷 exe**：`OmniAgentBackend.exe` 和 `_internal\` 是配套的一对，必须放在同一目录、同进同退。

| 文件 / 目录 | 作用 | 能不能动 |
|---|---|---|
| `OmniAgentBackend.exe` | 主程序，双击启动（约 39.6 MB） | 升级时整体替换 |
| `_internal\` | 程序依赖 + 网页界面 | 不可删、不可改名、不可只拷一部分；升级时整体替换 |
| `config\config.yaml` | 你的全部配置（首次启动自动生成） | 可改，见第三章 |
| `config.yaml.example` | 配置模板 | 只读参考，改它无效 |
| `logs\` | 运行日志，一天一个文件 | 旧文件可删 |
| `files\` | 任务产生的临时文件 | 可随时清理 |
| `version.txt` | 当前版本号 | 每次启动自动同步，别手改 |
| `OmniAgent.md` | 交给 AI 的项目规则（工作约定） | 可改 |
| `OmniAgent使用说明.md` | 就是你现在看的这份说明（打包时自动放到 exe 旁边） | 可删，不影响运行 |

运行开销：常驻内存约 220 MB，占用 **8500** 一个端口。

### 1.2 启动（三步）

1. 双击 `OmniAgentBackend.exe` → 弹出黑色窗口，**别关它**（关掉就等于退出程序）。
2. 等约 10~13 秒（机器慢会更久）。
3. 窗口里出现 `Uvicorn running on http://127.0.0.1:8500` 后，浏览器打开 **http://127.0.0.1:8500**。

本机打开**免口令**，直接进「对话任务」界面。启动成功的窗口长这样：

```
当前版本: 1.6.3
LLM 配置: provider=sensenova, model=sensenova-6.8-flash-lite
INFO:     Uvicorn running on http://127.0.0.1:8500 (Press CTRL+C to quit)
```

> 网页界面由这个程序自己提供，只有 8500 一个端口，**不用另外开前端**。

打不开时按顺序查：

| 现象 | 去查 |
|---|---|
| 窗口一闪就没了，或提示端口被占用 | 看 §1.5 |
| 窗口还在，浏览器打不开 | 地址是否 `http://127.0.0.1:8500`（不是 https）；再试一次刷新 |
| 窗口里有红色报错 | `logs\app_当天日期.log` 的最后几十行 |

### 1.3 界面上都有什么

左侧菜单（点一下切页）：

| 菜单 | 用来做什么 |
|---|---|
| 对话任务 | 主界面：发消息、看每一步执行过程 |
| 文件管理 | 浏览和查看项目目录里的文件 |
| 历史会话 | 找回以前的对话 |
| 快捷指令 | 常用指令面板 |
| 设置页面 | 所有配置项（第三章） |
| 知识库 | 灰色，暂未开放 |

顶栏右侧（从左到右）：

| 位置 | 含义 |
|---|---|
| 模型下拉框 | 切换**全局**模型；切换成功会提示「已切换到 xxx」 |
| 模型配置状态 | 🟢 配置就绪 = 可以正常发消息；🟡 配置预警 / 🔴 配置错误 = 点开看具体原因，浮层里有「去设置页修改」 |
| 后端服务状态 | 点一下重新检测；悬停可看访问地址、响应耗时、数据库状态、进程与已运行时长 |
| 流状态小灯 | 只反映当前这条回答的数据流是否正常，悬停看详情 |
| 菜单宽窄 / 头像 | 版面切换、当前用户显示 |

### 1.4 关闭与重启

- **正常关闭**：在黑窗口按 `Ctrl+C`，看到 `Application shutdown complete` 后再关窗口。
- **直接点 ✕**：程序随之退出，正在跑的对话/任务会被中断；下一次启动若提示端口被占用，按 §1.5 处理。
- **重启**：关掉窗口，重新双击即可。改大部分配置**不需要重启**（见 §3.1）。

### 1.5 提示「端口 8500 已被占用」

启动时会先检查端口。被占用就**立即停住**并说明占用者是谁、有几条出路（不会再初始化到一半才死）。下例假设占用者就是本程序（PID、进程名、路径按实际显示）：

```
====================================================================
[run_server] ❌ 端口 8500 已被占用, 本次启动终止(未改动任何文件)
====================================================================
  占用者: PID 32156  OmniAgentBackend.exe
          G:\OmniAgent-SPA\OmniAgentBackend.exe

  ✅ 判断: 本程序已经在运行, 不用再开一个 —— 浏览器直接访问:
     👉 http://127.0.0.1:8500

  只有确认要重启时才需要结束它:

  ① 结束占用进程
     PowerShell:  Stop-Process -Id 32156 -Force
     CMD:         taskkill /F /PID 32156
  ② 再双击本程序

  不想清理也可以直接换端口启动(两种命令行相同):
     OmniAgentBackend.exe --port 8501
====================================================================
  本窗口保留 30 秒后自动关闭 (按任意键立即关闭)...
```

怎么处理：

| 判断结果 | 你该做的 |
|---|---|
| 占用者就是本程序（上一次没关干净或还在跑） | 先用浏览器打开 8500 看看——能用就直接用；确实要重开才按上面命令结束它 |
| 占用者是别的程序 | 按上面命令结束它，或直接 `--port 8501` 换端口启动 |
| 想知道到底是谁占的 | 命令窗口执行 `netstat -ano | findstr :8500` 看 PID，再按 PID 结束 |

提示窗口会**停留 30 秒**（按任意键可提前关），方便看清。程序**不会自动替你结束别的进程**——怕误杀正在跑任务的实例或无关软件。脚本里调用时可以加 `--no-wait` 让它立刻退出。

### 1.6 让局域网同事也能用（必须设口令）

1. 用带参数的方式启动（在该文件夹地址栏输入 `cmd` 回车，再执行）：
   `OmniAgentBackend.exe --host 0.0.0.0`
2. 首次这样启动时 Windows 可能弹防火墙询问，选**允许**（专用网络）。查本机 IP：`ipconfig`。
3. 同事在浏览器访问 `http://<你的IP>:8500`，会看到登录页要求输入访问口令。
4. **口令只能在服务端这台机器上设**：本机浏览器打开 `http://127.0.0.1:8500` → 设置页面 → **前端** → **登录与准入** → 「访问口令」（至少 8 位，建议 16 位以上随机串）。
5. 同一块里的「免口令 IP 白名单」：一行一个 IP 或网段（如 `192.168.1.0/24`），写进去的来源访问时不用输口令。

| 情况 | 结果 |
|---|---|
| 在**别人的电脑**上去设口令 | 被拒绝（403）—— 安全设计，只能服务端本机设 |
| 口令已由环境变量 `OMNIAGENT_ACCESS_TOKEN` 指定 | 设置页里改不动，保存会报 409；要改只能改环境变量后重启 |
| 启动参数写成 `--forwarded-allow-ips *` | 变成谁都能伪造来源，本机访问也不再免口令 —— 别这么写 |
| 彻底关闭口令校验（仅限本机自用） | 设环境变量 `OMNIAGENT_REQUIRE_AUTH=0` 后重启 |

### 1.7 数据、日志在哪（备份与换机看这里）

| 内容 | 位置 |
|---|---|
| 配置 | `<包目录>\config\config.yaml`，自动备份 `config.yaml.backup.1` ~ `.5` |
| 运行日志 | `<包目录>\logs\app_YYYY-MM-DD.log`（一天一个，单文件 10 MB，保留 5 份） |
| 任务临时文件 | `<包目录>\files\` |
| 对话、任务、监控等数据 | `C:\Users\<用户名>\.omniagent\` 下的 `chat_history.db`、`task_tracker.db`、`monitoring.db`、`operations.db`、`timers.db` |
| 下载的文件 / 回收站 | `C:\Users\<用户名>\.omniagent\downloads\`、`recycle_bin\` |

- **升级**只替换 exe 和 `_internal`，上面这些一样都不会丢。
- **换电脑**：拷走整个包目录 + `C:\Users\<用户名>\.omniagent\` 整个目录，放到新机器同样位置即可。

## 二、配置模型

### 2.1 最短路径：配好一个模型（三步）

1. 设置页面 → **模型** → 找到 `③ Provider 配置`，填 `api_base`（供应商接口地址）和 `api_key`（供应商给的密钥）。
2. 点旁边的「**测试连接**」，出现 ✅ 说明地址和密钥可用。
3. 点「**保存 Provider 配置（立即生效）**」。

然后在上方 `① 选择器` 选中要用的模型（或直接用顶栏下拉切换）。**保存即生效，不用重启**。

> `api_key` 留空 = 保留原密钥不动；要清掉已有密钥，用「清空 api_key」。

### 2.2 两个层级：全局模型 与 单个会话的模型

| 切换位置 | 影响范围 | 怎么切 |
|---|---|---|
| **顶栏**的模型下拉 | 所有会话的默认模型 | 选一个，提示「已切换到 xxx」即成功 |
| **对话页面**输入框下方的模型框 | 只管当前这个会话 | 选哪个就只改了当前会话；选「跟随全局」回到默认 |

> 想临时用另一个模型问一件事，用下面那个会话级模型框，不会影响别人/别的会话。

### 2.3 管理可选模型清单（模型库）

- 设置页面 → **模型库** → 选 Provider → 点「获取模型列表」拉取 → 勾选要用的 → 点「保存所选（N）」。
- 保存是**替换式**：取消勾选的模型会从清单里消失；**当前正在用的那个模型不要取消**。
- 远程拉不到清单（例如 `openrouter`、`amdapi` 本身就是空的）→ 回「模型」页签，在 `① 选择器` 旁点「添加模型」手动填模型名。

### 2.4 直接改配置文件（批量改、想留档时）

`config\config.yaml` 里与模型相关的只有两块：`ai.model_ref`（当前用哪个）和各供应商的 `ai.<供应商名>`。下面按真实结构节选（密钥打码、模型清单只列几条）：

```yaml
ai:
  model_ref:              # 当前生效的模型（唯一开关）
    provider: sensenova
    model: sensenova-6.8-flash-lite

  sensenova:              # 供应商段名，与 model_ref.provider 必须完全一致
    api_base: https://token.sensenova.cn/v1     # 只写到 /v1
    api_key: sk-********************
    models:               # 该供应商可选模型清单
      - sensenova-6.8-flash-lite
      - deepseek-flash
      - kimi-k3
    timeout: 200          # 单次请求超时（秒）
    max_retries: 4        # 失败重试次数
    model_params:         # 按模型覆盖采样参数（可选）
      kimi-k3:
        temperature: 1
        top_p: 0.95
```

三条规矩：

1. `model_ref.provider` 必须与下面某个供应商段名**完全一致**；`model_ref.model` 必须出现在该段的 `models` 里。
2. `api_base` 只写到 `/v1`，不要带 `/chat/completions`。
3. 保存文件后程序会自动重读配置文件：`ai.model_ref` 换了模型，下一条消息就按新模型走；采样参数（`temperature`、`max_tokens` 等）若发现没变化，在顶栏把模型切一次再切回来，或直接重启程序。

### 2.5 各字段含义

| 字段 | 必填 | 说明 |
|---|---|---|
| `api_base` | 是 | 供应商的 OpenAI 兼容接口地址，一般以 `/v1` 结尾 |
| `api_key` | 是 | 供应商密钥；默认掩码显示，点眼睛图标并确认后可临时看明文（30 秒后自动复原） |
| `models` | 是 | 该供应商可选的模型名，一行一个 |
| `timeout` | 否 | 单次请求超时秒数（本机配置为 200） |
| `max_retries` | 否 | 网络或服务端出错时的重试次数（本机配置为 4） |
| `model_meta` | 否 | 模型信息（上下文长度等），界面展示用 |
| `model_params` | 否 | 针对某个模型单独覆盖 `temperature`、`top_p` 等 |

### 2.6 怎么确认改对了

| 看哪里 | 应该看到 |
|---|---|
| 顶栏模型下拉 | 显示的是新模型 |
| 顶栏「模型配置状态」 | 🟢 配置就绪，展开后模型名正确 |
| 发一条消息 | 能正常回答（不是报错、不是一直转圈） |
| `logs\app_当天.log` | 在设置页保存后有 `配置热重载触发: 已重载 config.yaml, 生效模型=<provider>/<model>`（直接改文件不会打印这行，属正常） |

### 2.7 常见故障对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 报 401 / invalid api key | 密钥错、过期，或该密钥不属于这个供应商 | 设置页重填 `api_key` → 测试连接 |
| 报 404 / model not found | 地址路径不对，或模型名不在清单里 | 地址只写到 `/v1`；模型名必须在该供应商的 `models` 里 |
| 模型下拉是空的 | 该供应商的 `models` 清单为空 | 「模型库」拉取勾选，或在 `① 选择器` 旁用「添加模型」手动加 |
| 一直转圈直到超时 | 网络不通、供应商限流、`timeout` 太小 | 先测连接；必要时调大该供应商的 `timeout` |
| 报上下文超限 | 设置的上下文窗口大于模型真实能力 | 调小 `llm.context_length_default`（§3.2） |
| 改了没反应 | 改的是 `config.yaml.example`，或改的不是运行目录里的 `config.yaml` | 只认 `<包目录>\config\config.yaml` |
| 保存时报 409 | 密钥/口令被环境变量接管了 | 改环境变量并重启，界面上改不了 |

## 三、常用配置

### 3.1 三条规矩：改哪、怎么改、怎么回滚

| 事项 | 做法 |
|---|---|
| 改哪 | `<包目录>\config\config.yaml`（不是 `config.yaml.example`） |
| 怎么改 | 优先用**设置页面**（有校验、危险项二次确认、自动备份）；也可以直接编辑文件 |
| 怎么回滚 | 设置页面每保存一次会把旧文件滚进 `config.yaml.backup.1` ~ `.5`（1 最新、5 最旧）；把要回的那份复制成 `config.yaml` 即可。**直接编辑文件不会产生备份**，改前自己复制一份 |
| 哪些要重启 | 大部分项保存即生效；设置页面保存后若弹出「含重启生效项」，按提示重启程序才生效 |
| 改坏了 | 日志出现 `加载配置文件失败`（启动时）或 `配置热重载失败`（运行中改坏）；把备份复制回去 |

设置页面顶部有搜索框，直接输入中文名或配置键（如 `temperature`）就会跳到那一项。

### 3.2 常用项速查（按设置页的页签归类）

**通用**

| 配置键 | 默认 | 说明 |
|---|---|---|
| `workspace.project_root` | 空 | 项目根目录，AI 的读写和执行都在它下面 |
| `workspace.allowed_dirs` | 空 | 额外授权的目录，一行一个 |
| `agent.max_steps` | 10000 | 单个任务最多执行多少轮（防止跑飞） |
| `logging.debug` | true | 调试模式（详细内部日志） |
| `logging.level` | WARNING | 日志级别：DEBUG / INFO / WARNING / ERROR |
| `llm.sampling.temperature` | 0.7 | 越高越发散；写代码、查数据建议 0.2~0.7 |
| `llm.sampling.max_tokens` | 16384 | 单次回复的最大长度 |
| `llm.sampling.top_p` | 1.0 | 核采样，一般不动 |
| `llm.sampling.enable_thinking` | true | 思考开关（仅支持推理的模型有效） |
| `llm.sampling.reasoning_effort` | medium | 推理深度 low / medium / high，越高越慢越贵 |
| `llm.context_length_default` | 262144 | 上下文窗口上限，**不能超过模型真实能力** |

**模型**

| 配置键 | 默认 | 说明 |
|---|---|---|
| `ai.model_ref` | — | 当前全局模型（见第二章）；供应商、密钥、模型清单在「模型」页签里用界面操作，不在这一项里 |

**安全**

| 配置键 | 默认 | 说明 |
|---|---|---|
| `security.system.enabled` | true | 安全模块总开关 |
| `security.system.shell_danger_block` / `shell_risk_block` | true | 拦截危险命令 / 风险命令 |
| `security.system.white_list_block` | true | 拦截白名单之外的路径 |
| `security.hitl.enabled` | true | 人工确认总开关（关掉 = AI 全自动执行，风险自负） |
| `security.hitl.write_confirm` / `delete_confirm` / `shell_path_confirm` | true | 写文件 / 删除 / 执行命令各自是否需要确认 |
| `security.hitl.auto_confirm_delay` | 10 | 自动确认倒计时（秒），到时自动放行；实际倒计时最短 3 秒 |
| `security.hitl.timeout` | 120 | 等你点确认的最长时间（秒） |
| `security.hitl.shell_readonly_prefixes` | `get-, ls, cat, …` | 这些开头的只读命令免确认 |
| `security.trust.ttl_days` | 90 | 会话信任有效期（天） |

**沙箱**

| 配置键 | 默认 | 说明 |
|---|---|---|
| `sandbox.enabled` | true | 沙箱开关 |
| `sandbox.backend` | job_object | 沙箱实现方式（Windows 用 job_object） |

### 3.3 常用场景配方

**① 只许它在指定目录里干活**

```yaml
workspace:
  project_root: D:\myproject
  allowed_dirs:
    - D:\myproject-data
    - E:\shared
```
> 越界的读写会被安全模块拦下。不要把 `C:\Windows`、`C:\Users` 这类目录填进去。

**② 让它少问几句（危险操作仍保留确认）**

```yaml
security:
  hitl:
    enabled: true
    write_confirm: false        # 写文件不再每次都问
    delete_confirm: true        # 删除仍然要确认
    auto_confirm_delay: 5       # 倒计时 5 秒后自动放行
```

**③ 平时日志别太吵，排错时再打开**

```yaml
logging:
  debug: false
  level: INFO                   # 排错时临时改成 DEBUG
```

**④ 报「上下文超限」**

```yaml
llm:
  context_length_default: 131072    # 改成该模型真实窗口，如 128K
```

**⑤ 历史对话自动清理**

```yaml
system:
  chat_retention_days: 90       # 只保留 90 天，0 = 永久保留
```
> 清理只在程序**启动时**执行一次，删掉的是到期会话本身及它的任务、执行步骤、流事件；`files\` 里的文件和配置**不会**被删。删除不可撤销，设小值前先备份 `C:\Users\<用户名>\.omniagent\chat_history.db`。环境变量 `OMNIAGENT_CHAT_RETENTION_DAYS` 会覆盖此项。

### 3.4 改完没生效怎么查

1. 确认改的是 `<包目录>\config\config.yaml`（不是 `config.yaml.example`）。
2. 检查 YAML 写法：缩进用**空格**不能用 Tab，冒号后面要有空格。
3. 看 `logs\app_当天.log`：出现 `加载配置文件失败`（启动时）或 `配置热重载失败(未换代, 旧配置继续生效)`（运行中）就是写坏了；在设置页保存后出现 `配置热重载触发` 与 `生效模型=...`，说明已生效（直接编辑文件时不会打印这两行，属正常）。
4. 在设置页面改一项再点「保存本组」，若 `config.yaml.backup.1` 的修改时间变成刚才，说明写盘正常；没有则检查文件是否只读、是否被杀毒软件锁定。
5. 仍然不对：把最近的 `config.yaml.backup.N` 复制成 `config.yaml`，重启程序再试。
