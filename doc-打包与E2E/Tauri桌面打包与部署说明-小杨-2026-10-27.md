## 一、方法概述

### 1.1 什么是"Tauri 桌面模式"

在已有 **同源 SPA 打包方案**（PyInstaller onedir）基础上，增加一层 **Tauri 桌面壳**（Rust + WebView2），将 React 前端嵌入原生桌面窗口，同时以 **sidecar 子进程** 方式启动后端 `OmniAgentBackend.exe`：

| 特性 | 说明 |
|---|---|
| 桌面窗口 | 双击 `.exe` 直接弹出独立桌面窗口（WebView2 渲染前端），**不打开浏览器** |
| 后端 sidecar | Tauri 启动时自动 spawn `OmniAgentBackend.exe`，监听 `127.0.0.1:8500` |
| 前端复用 | 与同源 SPA 模式共用同一份 `frontend/dist/`（`npm run build` 产物） |
| 后端复用 | 与同源 SPA 模式共用同一份 PyInstaller onedir 产物（`OmniAgentBackend.exe` + `_internal/`） |
| 双模共存 | 同一份前端代码，打包时选择"同源 SPA"或"Tauri 桌面"，**互不干扰** |

### 1.2 工作原理

```
┌────────────────────────────────────────────────────────┐
│  OmniAgentApp.exe（Tauri 壳，Rust 编译）                │
│  ┌────────────────────────────────────────────────────┐ │
│  │  WebView2 窗口（渲染 React 前端）                    │ │
│  │  源: tauri://localhost                            │ │
│  │  API → http://127.0.0.1:8500/api/v1/*（绝对路径）  │ │
│  └────────────────────────────────────────────────────┘ │
│                                                         │
│  ┌────────────────────────────────────────────────────┐ │
│  │  Sidecar 子进程                                     │ │
│  │  OmniAgentBackend.exe（现有 PyInstaller 产物）       │ │
│  │  监听 127.0.0.1:8500                               │ │
│  │  serve /_internal/web/（同源 SPA 模式下才需要）      │ │
│  │  提供 /api/v1/* API                               │ │
│  └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

- Tauri 壳启动时 **自动 spawn** sidecar（`OmniAgentBackend.exe`），后端进程独立运行。
- 前端 WebView 源是 `tauri://localhost`，**不是** `http://127.0.0.1:8500`，所以 API 请求必须走 **绝对路径** `http://127.0.0.1:8500/api/v1/*`。
- 后端关闭时 Tauri 壳随之退出；用户关窗口 → Tauri 壳终止 sidecar → 后端停止。

### 1.3 与同源 SPA 模式的对比

| 维度 | 同源 SPA（现有） | Tauri 桌面（本文档） |
|---|---|---|
| 用户操作 | 双击 exe → 浏览器打开 `:8500` | 双击 exe → 弹出桌面窗口 |
| 前端渲染 | 浏览器标签页 | WebView2 独立窗口（原生标题栏、可集成系统托盘） |
| 前端 API 路径 | 相对 `/api/v1`（同源） | 绝对 `http://127.0.0.1:8500/api/v1`（跨源） |
| 需要浏览器 | ✅ 是 | ❌ 否（WebView2 内嵌） |
| 工具链 | Node + Python + PyInstaller | Node + Python + PyInstaller + **Rust + C 编译器** |
| 产物大小 | exe 39MB + _internal ~80MB | Tauri 壳 ~5MB + 后端 39MB + _internal ~80MB（+~5MB） |
| 系统托盘 | ❌ | ✅（可扩展） |
| 自动更新 | ❌ | ✅（Tauri updater） |

### 1.4 前端环境自动检测机制

**核心原则：一份前端代码，两种打包出口，零冲突。**

```typescript
// 前端 client.ts 改造点（详见 §六 代码说明）
const isTauri = typeof window !== 'undefined'
  && '__TAURI_INTERNALS__' in window;

// Tauri 模式: 绝对路径（WebView 源是 tauri://，相对路径打不到后端）
// 同源 SPA:  相对路径（前后端同端口，不跨域）
const baseURL = isTauri ? 'http://127.0.0.1:8500/api/v1' : '/api/v1';
```

| 打包模式 | 前端 `__TAURI_INTERNALS__` | `getApiBaseUrl()` 返回值 | API 到达路径 |
|---|---|---|---|
| 同源 SPA（浏览器） | 不存在 | `''`（空串） | 相对 → 同端口后端 |
| Tauri 桌面（WebView2） | 存在 | `'http://127.0.0.1:8500'` | 绝对 → sidecar 后端 |

> 对 **同源 SPA 打包流程零影响**：非 Tauri 环境下 `__TAURI_INTERNALS__` 不存在，走原有逻辑。

## 三、改造说明（代码变更点）

> 以下为**需要改造的代码清单**，实际改造实施时逐步完成。两种模式 **互不影响**，
> 所有改动均为 **增量扩展**，不修改现有同源 SPA 行为。

### 3.1 前端：`client.ts`（~5 行改动）

```typescript
// ===== 改动前（现状） =====
export function getApiBaseUrl(): string {
  return VITE_ENV.VITE_API_BASE_URL || '';
}

// ===== 改动后（Tauri 兼容） =====
/** Tauri WebView 源是 tauri://localhost，相对路径打不到后端；
 *  同源 SPA 模式下不存在 __TAURI_INTERNALS__，走空串（相对路径）。
 *  两种模式同一份代码，零分叉。 — 小杨-2026-10-27
 */
export function getApiBaseUrl(): string {
  // Tauri 桌面模式：__TAURI_INTERNALS__ 由 Tauri 运行时注入到 window
  const isTauri =
    typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window;
  if (isTauri) {
    return 'http://127.0.0.1:8500';  // 绝对路径 → sidecar 后端
  }
  // 同源 SPA / 开发模式：空串 → 相对路径 /api/v1
  return VITE_ENV.VITE_API_BASE_URL || '';
}
```

**影响面**：`API_BASE_URL`、`axios.baseURL`、`chatStreamTransport.baseURL`、`network.ts`、`useChatSend.ts` 等所有引用 `API_BASE_URL` / `getApiBaseUrl()` 的位置**自动生效**，无需逐处改。

### 3.2 前端：`main.tsx`（~20 行，Tauri 下 health-check 等待）

```typescript
// ===== 新增：Tauri 模式下等待 sidecar 后端就绪 =====
// Tauri 启动后立刻渲染前端，但 sidecar（后端）可能还在启动中 →
// 前端 API 全部超时。加一个 health-check 轮询，后端 ready 后再 mount React 树。
// 同源 SPA 模式下跳过此等待（后端先于浏览器启动，天然 ready）。 — 小杨-2026-10-27
async function waitForBackend(baseURL: string, timeout = 15_000): Promise<void> {
  const isTauri =
    typeof window !== 'undefined' && '__TAURI_INTERNALS__' in window;
  if (!isTauri) return;  // 非 Tauri 模式直接返回

  const start = Date.now();
  while (Date.now() - start < timeout) {
    try {
      const res = await fetch(`${baseURL}/health`);
      if (res.ok) return;
    } catch { /* 后端未启动，继续轮询 */ }
    await new Promise((r) => setTimeout(r, 500));
  }
  throw new Error('后端启动超时（15s）');
}
```

在 `ReactDOM.createRoot` 之前调用：
```typescript
// main.tsx 改造点
const rootElement = document.getElementById('root');
if (rootElement) {
  waitForBackend(API_BASE_URL).then(() => {
    ReactDOM.createRoot(rootElement)!.render(/* ... */);
  });
}
```

> 同源 SPA 模式下 `waitForBackend` 检测到非 Tauri 立即返回，**不影响现有行为**。

### 3.3 前端：`index.html`（~1 行）

Tauri 模式下 WebView 加载的前端 `index.html` 与同源 SPA 完全相同（都是 `frontend/dist/index.html`），**无需改动**。

### 3.4 后端：**零改动**

| 说明 | 理由 |
|---|---|
| `run_server.py` | 不变。Tauri sidecar 以 `spawn` 方式启动 `OmniAgentBackend.exe`，exe 自身逻辑（端口、配置部署）与同源 SPA 完全一致 |
| `main.py` | 不变。`_HAS_WEB` 逻辑在 Tauri 模式下仍然 serve 静态文件（无害），API 路由照常 |
| `OmniAgentBackend.spec` | 不变。后端打包方式不受 Tauri 影响 |
| 跨域 | Tauri WebView 发起的 HTTP 请求 **不受浏览器 CORS 限制**（`tauri://` 源不走 CORS 检查）；同源 SPA 模式下后端 CORS 中间件空转 |

#### sidecar 启动逻辑（`src/main.rs`，~30 行核心）

```rust
// 启动时 spawn sidecar（OmniAgentBackend.exe）
#[cfg_attr(all(debug_assertions, target_os = "windows"),
    windows_subsystem = "windows")]
fn main() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![/* ... */])
        .setup(|app| {
            // 找到 exe 同级（或 Tauri bundle 内的） OmniAgentBackend 文件夹
            let exe_dir = app.path_resolver().resource_dir()?;
            let backend = exe_dir.join("sidecar").join("OmniAgentBackend.exe");
            let _ = tauri::api::process::Command::new(backend)
                .arg("--port").arg("8500")
                .arg("--host").arg("127.0.0.1")
                .spawn();
            Ok(())
        })
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

> 实际实施时使用 Tauri 2.x 的 `Shell` API（`tauri-plugin-shell`）替代旧版 `api::process`，具体写法见 Tauri 官方文档。

## 四、打包方法

### 4.1 打包步骤（严格按顺序）

```
① 前端构建 ──→ ② 后端 PyInstaller 打包 ──→ ③ 组装 Tauri sidecar 目录 ──→ ④ cargo tauri build
```

#### 第一步：构建前端（同源 SPA 和 Tauri 模式共用）

```powershell
cd F:\OmniAgentAs-01\frontend
npm run build
```

- 产物输出到 `frontend/dist/`：
  - `index.html`（~2.6KB）
  - `assets/`（~71 个文件，~7MB）
  - `stats.html`（包体积分析，不影响运行）

#### 第二步：打包后端（同源 SPA 和 Tauri 模式共用）

```powershell

E:\Appsw\python31311\Scripts\pyinstaller.exe OmniAgentBackend.spec --noconfirm
```

- 产物输出到 `backend/dist/OmniAgentBackend/`：
  - `OmniAgentBackend.exe`（~39MB）
  - `_internal/`（含 `web/` 前端文件 + Python 源码 + 依赖）
  - `config.yaml.example` / `version.txt` / `OmniAgent.md`

> ⚠️ 必须先完成第一步再执行第二步，否则 `_internal/web/` 为空。

#### 第三步：组装 Tauri sidecar 目录

将后端 PyInstaller 产物拷贝到 Tauri 壳的 sidecar 目录：

```powershell
$src = "F:\OmniAgentAs-01\backend\dist\OmniAgentBackend"
$dst = "F:\OmniAgentAs-01\desktop\src-tauri\sidecar"

# 清理旧的

# 拷贝整个 OmniAgentBackend 目录
Copy-Item $src $dst -Recurse
```

最终 `desktop/src-tauri/sidecar/` 结构：

```
sidecar/
├── OmniAgentBackend.exe      (~39MB)
├── _internal/
│   ├── web/                  ← 前端 dist（同源 SPA 模式也需要，无害）
│   ├── app/
│   ├── version.txt
│   ├── config.yaml.example
│   └── OmniAgent.md
└── ... (PyInstaller 依赖)
```

> Tauri 的 `externalBin` 声明的是 `OmniAgentBackend`，构建时 Tauri 会自动将 `sidecar/` 目录整体打包进 bundle。

#### 第四步：编译 Tauri 壳


- 首次编译 **~10-20 分钟**（编译 Tauri + 所有 Rust 依赖）

> - 创建 `logs/` `files/` `data/` 目录

用户解压即用，**无需安装**。

### 5.3 安全说明

与同源 SPA 一致：

- 默认绑定 `127.0.0.1`（本机回环），局域网其他设备不可访问
- 首次使用需设置访问口令（设置页 → 前端 → 访问口令）
- Tauri 壳本身不暴露额外端口

## 六、相关代码配置说明

### 6.1 前端 `client.ts`（`src/services/api/client.ts`）

| 要素 | 说明 |
|---|---|
| `getApiBaseUrl()` | Tauri 模式返回 `'http://127.0.0.1:8500'`（绝对）；同源 SPA 返回 `''`（相对） |
| `API_BASE_URL` | 由 `getApiBaseUrl()` 拼接 `/api/v1` 得出，所有 API 调用统一使用此常量 |
| `axios.baseURL` | `${getApiBaseUrl()}/api/v1`，与 `API_BASE_URL` 同源（历史 404 bug 已修复） |

**双模兼容原则**：所有通过 `API_BASE_URL` 或 `getApiBaseUrl()` 取路径的前端代码（REST axios、SSE fetch、health-check、网络状态检测）**无需逐处改动**，自动适配 Tauri / 同源 SPA。

### 6.2 前端 `main.tsx`（`src/main.tsx`）

| 要素 | 说明 |
|---|---|
| `waitForBackend()` | Tauri 模式下轮询 `${API_BASE_URL}/health`，后端 ready 后再 `ReactDOM.createRoot().render()` |
| 超时 | 默认 15 秒，超时报错提示用户 |
| 同源 SPA 模式 | `__TAURI_INTERNALS__` 不存在 → 函数立即 `return`，行为零变化 |

### 6.3 `tauri.conf.json` 关键配置项

| 配置键 | 值 | 说明 |
|---|---|---|
| `build.frontendDist` | `../../frontend/dist` | 前端产物路径（复用 `npm run build` 的 dist） |
| `build.beforeBuildCommand` | `""`（空） | 不在 Tauri 构建时重复构建前端 |
| `tauri.externalBin` | `["OmniAgentBackend"]` | 声明 sidecar 可执行文件名（Tauri 自动加平台后缀 `.exe`） |
| `tauri.security.csp.connect-src` | `["http://127.0.0.1:8500", "http://localhost:8500"]` | 允许前端请求本地后端 |
| `tauri.windows[0].title` | `"OmniAgent"` | 窗口标题 |
| `tauri.bundle.identifier` | `"com.omniagent.desktop"` | 应用标识符 |

### 6.5 后端 `run_server.py`（零改动）

| 要素 | 说明 |

## 七、与同源 SPA 模式的打包对照

### 7.1 两种模式打包命令汇总

```
╔══════════════════════════════════════════════════════════╗
║          模式 A：同源 SPA（现有流程，零改动）               ║
╠══════════════════════════════════════════════════════════╣
║  ① cd frontend && npm run build                         ║
║  ② cd backend && pyinstaller OmniAgentBackend.spec      ║
║  ③ 产物: backend/dist/OmniAgentBackend/                 ║
║     双击 OmniAgentBackend.exe → 浏览器 :8500             ║
╠══════════════════════════════════════════════════════════╣
║          模式 B：Tauri 桌面（新增）                        ║
╠══════════════════════════════════════════════════════════╣
║  ① cd frontend && npm run build                         ║
║  ② cd backend && pyinstaller OmniAgentBackend.spec      ║
║  ③ 拷贝 sidecar:  backend/dist/OmniAgentBackend/        ║
║     → desktop/src-tauri/sidecar/                       ║
║  ④ cd desktop && cargo tauri build                      ║
║  ⑤ 产物: target/release/bundle/msi/OmniAgentApp_x.msi  ║
║     安装后双击 → 桌面窗口弹出                               ║
╚══════════════════════════════════════════════════════════╝
```

### 7.2 共用与独立部分

| 环节 | 模式 A（同源 SPA） | 模式 B（Tauri） |
|---|---|---|
| 前端构建 | ✅ 共用 | ✅ 共用 |
| 后端 PyInstaller | ✅ 共用 | ✅ 共用 |
| Tauri 壳编译 | ❌ 不需要 | ✅ 独有 |
| sidecar 组装 | ❌ 不需要 | ✅ 独有 |
| 产物形态 | exe + _internal（浏览器） | msi/exe + sidecar（桌面窗口） |

> **关键设计：两种模式的前端构建产物完全相同**（`frontend/dist/`），区别仅在壳和启动方式。

## 八、常见问题

| 问题 | 原因 | 解决 |
|---|---|---|
| 双击 `OmniAgentApp.exe` 窗口打开但白屏 | sidecar 后端未启动或端口冲突 | ① 检查 `8500` 是否被占用；② 看 sidecar 目录下 `logs/` 日志 |
| 前端 API 全部 404 | `getApiBaseUrl()` 在 Tauri 模式下未走绝对路径 | 确认前端已包含 `__TAURI_INTERNALS__` 检测逻辑（§三.1） |
| 前端启动超时（15s）报错 | 后端启动慢（PyInstaller 首次解压） | 调大 `waitForBackend` 的 `timeout` 参数；或预解压 `_internal/` |
| `cargo tauri build` 编译失败 | C 编译器未安装或 Rust 工具链不匹配 | 确认 C 编译器已装（§二.3），工具链类型匹配 |
| WebView2 报错 / 窗口崩溃 | WebView2 Runtime 缺失（老版 Win10） | 手动安装 [WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) |
| 关闭 Tauri 窗口后后端进程未终止 | sidecar 退出逻辑未正确关联 | 确认 `main.rs` 中 `on_window_close` 回调有 kill sidecar 逻辑 |
| Tauri 包体积比同源 SPA 大 ~5-10MB | Tauri 壳本身 + Rust 运行时 | 可接受；后端 part 体积不变 |
| `tauri.conf.json` 中 `externalBin` 路径不对 | sidecar 目录结构不匹配 | 确认 `sidecar/OmniAgentBackend.exe` 与 `externalBin` 声明的文件名一致 |

## 九、与开发模式对照

| 维度 | 开发模式 | 同源 SPA（打包版） | Tauri 桌面（打包版） |
|---|---|---|---|
| 前端服务 | Vite dev :5173 | 后端 :8500 serve | Tauri WebView（`frontend/dist/`） |
| API 服务 | uvicorn :8000（proxy 转发） | 同 :8500（同端口） | sidecar :8500（跨源绝对路径） |
| 浏览器访问 | `http://localhost:5173` | `http://127.0.0.1:8500` | 桌面窗口（无浏览器） |
| 跨域 | 无（proxy 同源） | 无（同端口） | 有（`tauri://` → `:8500`，但 Tauri 不走 CORS） |
| 热更新 | ✅ Vite HMR | ❌ 需重新打包 | ❌ 需重新打包 |
| 启动命令 | `npm run dev` + `uvicorn --reload` | 双击 `OmniAgentBackend.exe` | 双击 `OmniAgentApp.exe` |
| 产物大小 | 源码 | exe 39MB + _internal ~80MB | 壳 ~5MB + sidecar 39MB + _internal ~80MB |
| 额外依赖 | Node + Python | Node + Python + PyInstaller | Node + Python + PyInstaller + Rust + C 编译器 |
