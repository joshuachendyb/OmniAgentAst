## 一、先确认后端在跑

前端只是页面，所有数据都问后端要。**先把后端跑起来**（详见《后端exe使用方法》），再弄前端。

确认方法：浏览器打开下面这个地址，看到 `healthy` 字样就是好的：

```
http://127.0.0.1:8000/api/v1/health
```

看不到 → 先去把后端弄好，前端不用试。

---

## 二、启动前端（选一种）

### 方式一：开发模式（推荐，有源码就能用）

1. 打开 PowerShell，进前端目录：
```powershell
cd F:\OmniAgentAs-repair\frontend
```

2. 第一次需要装依赖（以后不用重复）：
```powershell
npm install
```

3. 启动：
```powershell
npm run dev
```

4. 看到类似下面的字样就是起来了：
```
VITE ready in ... 
➜  Local:   http://localhost:5173/
```

5. 浏览器打开 **`http://localhost:5173`**（注意是 5173，不是 8000）。

> 8000 是后端（API），5173 是前端（页面）。页面打不开先确认输的是 5173。

### 方式二：用打好的包（没源码也能用）

1. 找个目录放前端文件（比如 `E:\omni-front`），确保里面有 `index.html` 和 `assets` 文件夹。

2. 进这个目录启动：
```powershell
cd E:\omni-front
python -m http.server 4173
```

3. 看到 `Serving HTTP on ... port 4173` 就是起来了。

4. 浏览器打开 **`http://127.0.0.1:4173/`**（注意最后的 `/`，根路径）。

> ⚠️ 两个不要踩的坑：
> 1. `python -m http.server` 后面**必须写端口**（不写默认 8000，会和后端撞车起不来）；
> 2. 进去之后**用鼠标点**，不要在地址栏是 `/settings2` 这类子路径时按刷新——会 404（这是静态服务器的限制，不是 bug，详见《前端打包手册》§四）。

## 三、第一次打开看到什么

| 看到 | 说明 |
|---|---|
| 聊天框 + 发送按钮 | ✅ 正常，前后端都通了 |
| 页面空白 / 转圈不停 | 后端没起，回去看第一章 |
| `设置加载失败` | 前端调不通后端：检查后端地址对不对（方式一不用管；方式二确认包构建时烘了正确的后端地址） |
| `Network Error` 小黄条 | 同上，网络层没通；按 F12 看 Console 红字定位 |

## 四、日常使用

| 动作 | 做法 |
|---|---|
| 发消息 | 输入框打字 → 回车（或点发送） |
| 停掉服务 | 关掉对应的黑窗口（前端一个、后端一个，各关各的） |
| 换端口 | 前端换端口要同步改后端 CORS 白名单并**重启后端**（`localhost` 和 `127.0.0.1` 算两个不同的源，都要加） |
| 改配置 | 前端设置页直接改（推荐）；手改 `config.yaml` 后刷新页面即可，后端配置热加载 |

---

## 五、坏了找谁

| 症状 | 先看 |
|---|---|
| 页面打不开 | 服务窗口还在不在？端口对不对（5173/4173 不是 8000）？ |
| 能打开但数据出不来 | `http://127.0.0.1:8000/api/v1/health` 通不通？浏览器 F12 Console 红字是什么？ |
| 改了配置没生效 | CORS 改了要**重启后端**；前端包换了后端地址要**重打**（地址烘进 JS 改不了） |
| 子路径刷新 404 | 正常现象，回根路径。详见《前端打包手册》§四 |
