## 一、方法概述

### 1.1 什么是"同源SPA"

将前端 SPA（React + Vite 构建产物）和后端 API（FastAPI/uvicorn）部署在 **同一个端口、同一个源** 下，由后端直接 serve 前端静态文件：

| 特性 | 说明 |
|---|---|
| 单端口 | 浏览器只需访问一个地址（默认 `http://127.0.0.1:8500`） |
| 同源 | 页面请求和 API 请求同 host:port → 不触发 CORS 预检 |
| 单 exe | 双击一个可执行文件即获得完整应用（前端页面 + 后端API） |
| 无 Nginx | 不需要独立前端服务器、不需要反向代理 |

### 1.2 工作原理

```
浏览器
  │
  ├── GET /               → 后端返回 index.html（前端 SPA 入口）
  ├── GET /assets/xxx.js  → 后端 StaticFiles 直接 serve 静态资源
  ├── GET /chat /files…   → 后端 catch-all 返回 index.html（React Router 接管）
  └── POST /api/v1/…     → 后端 API 路由处理（同端口，无跨域）
```

- 前端 `axios` baseURL 默认为 `/api/v1`（相对路径），同源直连后端 API。
- 后端 FastAPI 中注册 `StaticFiles` mount `/assets` + `/{path:path}` SPA catch-all，
  按 **注册顺序** 优先匹配精确 API 路由，非 API 路径 fallback 到 `index.html`。

### 1.3 与开发模式的关系

| 模式 | 前端源 | API 源 | 是否跨域 | 需要 CORS |
|---|---|---|---|---|
| **打包版（同源SPA）** | `:8500` 后端 serve | 同 `:8500` | ❌ 同源 | ❌ |
| 开发 Vite proxy | `:5173` Vite | proxy→`:8000` 后端 | ❌ 同源（proxy透明） | ❌ |
| E2E 代理 :9000 | `:5173` | 直连 `:9000` | ✅ 跨域 | ✅ |

> 打包版下配置项 `network.cors_origins`（设置页"允许访问的页面地址"）**无需配置**，CORS 中间件空转。

## 二、打包方法

### 2.1 前置条件

| 项目 | 要求 |
|---|---|
| Node.js | ≥18（含 npm） |
| Python | 3.13（与构建机一致） |
| PyInstaller | 已安装于 `E:\Appsw\python31311\Scripts\pyinstaller.exe` |
| 项目根目录 | `F:\OmniAgentAs-01\` |

### 2.2 打包步骤（严格按顺序）

#### 第一步：构建前端

```bash
cd F:\OmniAgentAs-01\frontend
npm run build
```

- 命令实际执行 `tsc && vite build`（TypeScript 类型检查 + Vite 打包）。
- 产物输出到 `frontend/dist/`：
  - `index.html`（~2.6KB 入口）
  - `assets/`（~71 个 JS/CSS/字体文件，合计 ~7MB）
  - `stats.html`（Vite 包体积分析，不影响运行）

#### 第二步：打包后端（含前端）

```bash
cd F:\OmniAgentAs-01\backend
E:\Appsw\python31311\Scripts\pyinstaller.exe OmniAgentBackend.spec --noconfirm
```

- spec 文件中 `_frontend_datas` 条件判断：
  - `frontend/dist/` **存在** → 将 dist 内容塞入 `_internal/web/`
  - `frontend/dist/` **不存在** → 跳过（打包成功但 exe 运行时无前端，降级为纯 API）

> ⚠️ 必须先完成第一步再执行第二步，否则 `_internal/web/` 目录为空，前端不可用。

#### 第三步：验证产物

```
F:\OmniAgentAs-01\backend\dist\OmniAgentBackend\
├── OmniAgentBackend.exe          (~39MB 主程序)
├── OmniAgent使用说明.md          ← 给最终用户的使用说明(spec 打包后处理自动放入, exe 同级)
├── _internal\
│   ├── web\                      ← 前端 dist 内容
│   │   ├── index.html
│   │   ├── assets\ (71 files)
│   │   └── stats.html
│   ├── app\                      ← Python 业务源码
│   ├── version.txt
│   ├── config.yaml.example
│   └── OmniAgent.md
└── ... (其他依赖)
```

确认 `_internal/web/index.html` 存在 → 前端已正确嵌入。

> **打包后处理（自动，无需手工拷贝）** — 小欧-2026-11-04：spec 末尾在 `COLLECT` 之后把 `doc-打包与E2E\` 下最新一份 `OmniAgent智能助手(SPA版)使用说明*.md` 复制为 `dist\OmniAgentBackend\OmniAgent使用说明.md`（固定名、不带日期/签名，升级时覆盖同名文件，部署目录不积累历史版本）。构建输出会打印 `[post-build] 使用说明 -> ...`；文档缺失只打印告警，不阻断打包。

## 三、部署方法

### 3.1 部署包结构

将以下文件/目录整体拷贝到目标机器任意位置（如 `D:\OmniAgent\`）：

```
D:\OmniAgent\
├── OmniAgentBackend.exe
├── OmniAgent使用说明.md  (给最终用户看的使用说明, 双击前先看这个)
└── _internal\           (整个目录, 含 web/ 前端文件 + version.txt/config.yaml.example/OmniAgent.md)
```

> 只需拷 **exe + OmniAgent使用说明.md + _internal/** 三样（onedir 绿色目录）。`_internal/` 根部已自带 `version.txt` / `config.yaml.example` / `OmniAgent.md`（datas "." 目标落位），exe 启动时 `_deploy_resources()` 会将其自动复制到 exe 同级，无需手动补。

> **本机实际部署目录（2026-10-30 小欧补记）**：`G:\OmniAgent-SPA`。文档示例 `D:\OmniAgent\` 仅为"目标机器任意位置"的示意，**不是固定规定路径**；实际部署位置随机器而异，本仓库对应开发机即部署在 `G:\OmniAgent-SPA`（2026-10-30 热更核对：`G:\OmniAgent-SPA\_internal\app` 下 8 个后端源码文件已与仓库最新版一致）。

### 3.2 首次启动自动行为

| 动作 | 说明 |
|---|---|
| 部署资源文件 | `_internal/` → exe 同级（按 mtime 刷新） |
| 生成 config.yaml | 若 `config/config.yaml` 不存在，自动从 `config.yaml.example` 复制 |
| 创建目录 | `config/` `logs/` `files/` `data/` 首次按需创建 |
| 启动服务 | 默认监听 `127.0.0.1:8500` |

### 3.3 安全说明

- 默认仅绑定 `127.0.0.1`（本机回环），局域网其他设备不可访问。
- 如需局域网访问，启动参数加 `--host 0.0.0.0`（但建议配合口令鉴权）。
- 首次访问需设置访问口令（设置页 → 前端 → 访问口令）。

### 3.4 升级部署方式（只换 exe + _internal）

升级时**只替换 `OmniAgentBackend.exe`、`OmniAgent使用说明.md` 与 `_internal/` 三项**，部署目录内 `config/`、`files/`、`logs/`、`version.txt`、`OmniAgent.md`、`config.yaml.example` 一律不动（`config/config.yaml` 内含密钥与用户配置，被覆盖即等于重置）。

仓库已固化部署脚本 `backend/deploy_spa.py`（2026-11-04 小欧），打包完后执行：

```
python backend/deploy_spa.py                 # 默认 target=G:\OmniAgent-SPA
python backend/deploy_spa.py --target D:\OmniAgent --dist <打包产物目录>
```

脚本行为：目标 exe 在跑 → 只打印 PID + PowerShell/CMD 结束命令后退出（`exit 1`，不自动杀进程）；打包产物缺失 → `exit 2`；正常部署后打印目录清单 + 前端产物/版本/配置自检。

| 对象 | 做法 | 说明 |
|---|---|---|
| `OmniAgentBackend.exe` | 原地覆盖（`shutil.copy2`） | 覆盖前必须先停止占用 8500 的旧实例：Windows 下运行中的 exe 被写会 `PermissionError` |
| `OmniAgent使用说明.md` | 原地覆盖（`dist` 根下 `OmniAgent使用说明*.md`） | 打包后处理已放进 `dist` 根；部署时一并同步，目标目录 exe 同级始终是本版说明 |
| `_internal/` | **覆盖合并**（`shutil.copytree(..., dirs_exist_ok=True)`） | 同名文件按新包内容覆盖，部署目录多出来的文件保留 |

> 为什么不用"先删整目录再复制"：`rmtree` 删除完成后若 `copytree` 中途失败（磁盘满、进程被杀），会留下残缺 `_internal/`，程序直接起不来；覆盖合并失败时文件仍齐全，最坏只是新旧混合，重跑一次即修复。
>
> 代价：PyInstaller 新版不再产出的旧文件（过期 DLL、改名模块）会残留在 `_internal/`。若怀疑残留导致异常行为（升级后仍跑旧逻辑），手工清空 `_internal/` 再整体复制一次即可。

## 四、使用方法

### 4.1 启动

**方式一：双击 exe**

直接双击 `OmniAgentBackend.exe`，控制台窗口弹出，看到：

```
[run_server] _deploy_resources: skipped version.txt (dst >= src)
[run_server] _deploy_resources: skipped config.yaml.example (dst >= src)
...
INFO:     Uvicorn running on http://127.0.0.1:8500 (Press CTRL+C to quit)
```

即启动成功。

**方式二：命令行（可传参）**

```powershell
cd D:\OmniAgent
.\OmniAgentBackend.exe --port 2000
```

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 监听地址 |
| `--port` | `8500` | 监听端口 |
| `--forwarded-allow-ips` | `127.0.0.1` | 信任的对端 X-Forwarded-For 来源 IP |

### 4.2 访问前端

启动后浏览器打开：

```
http://127.0.0.1:8500
```

即出前端页面（React SPA），所有 API 请求同端口走 `/api/v1/*`，无需额外配置。

### 4.3 日常运维

| 操作 | 说明 |
|---|---|
| 停止服务 | 控制台窗口按 `Ctrl+C` 或关闭窗口 |
| 查日志 | exe 同级 `logs/app_YYYY-MM-DD.log` |
| 改配置 | 编辑 exe 同级 `config/config.yaml`，重启生效 |
| 升级 | 替换整个目录（旧 `config.yaml` 和 `data/` 保留即配置/数据不丢） |

## 五、相关代码配置说明

### 5.1 后端 main.py（`app/main.py` 第 257-443 行）

```python
# 前端静态目录定位
_WEB_DIR = (
    Path(sys._MEIPASS) / "web"              # 打包版：_internal/web/
    if getattr(sys, "frozen", False)
    else Path(__file__).resolve().parent.parent.parent / "frontend" / "dist"  # 源码调试
)
_HAS_WEB = _WEB_DIR.is_dir()

if _HAS_WEB:
    app.mount("/assets", StaticFiles(directory=str(_WEB_DIR / "assets")), name="static-assets")

    @app.get("/{path:path}", include_in_schema=False)
    async def spa_fallback(path: str):
        return FileResponse(str(_WEB_DIR / "index.html"))
```

| 要素 | 说明 |
|---|---|
| `_WEB_DIR` | frozen 模式读 `_internal/web/`；源码调试读 `../frontend/dist/` |
| `_HAS_WEB` | 目录不存在时为 False → 不 mount，exe 降级为纯 API 服务 |
| `mount("/assets")` | 直接 serve 静态资源（JS/CSS/字体），避免走 catch-all |
| `/{path:path}` catch-all | 注册在所有 API 路由之后，非 API 路径返回 `index.html`（React Router 接管前端路由） |
| 注册顺序保护 | FastAPI 按注册顺序匹配 → `/api/v1/*` 精确路由先命中 → 不会误入 SPA fallback |

### 5.2 spec 文件（`OmniAgentBackend.spec` 第 56-59 行）

```python
# 前端 dist → _internal/web/（双击exe完整应用）
_frontend_dist = REPO / "frontend" / "dist"
_frontend_datas = [(str(_frontend_dist), "web")] if _frontend_dist.is_dir() else []
```

- PyInstaller 将 `frontend/dist/` 整体复制到 `_internal/web/`。
- 条件判断：dist 不存在时 `_frontend_datas` 为空列表，打包不报错但前端缺失。

### 5.3 run_server.py（打包启动入口）

| 关键逻辑 | 说明 |
|---|---|
| `DEFAULT_PORT = 8500` | 打包版默认端口（开发惯例 8000，打包用 8500 避免双开冲突） |
| `_deploy_resources()` | 启动时自动将 `_internal/` 中 version.txt / config.yaml.example / OmniAgent.md 部署到 exe 同级 |
| `_ensure_config()` | 首次启动自动从 example 生成 `config/config.yaml` |
| `console=True`（spec） | exe 带黑色控制台窗口（方便看日志/手动停止） |

### 5.4 前端 client.ts（`src/services/api/client.ts`）

```typescript
function getApiBaseUrl(): string {
  const env = import.meta.env.VITE_API_BASE_URL;
  return env ? env : '';  // 未设 → 空串 → axios baseURL = '/api/v1'（相对路径，同源）
}
```

- **同源SPA 模式下**：不设置 `VITE_API_BASE_URL`，前端所有 API 请求走相对路径 `/api/v1/*`，由同端口后端处理。
- **跨域模式（E2E/CDN）**：打包前设 `VITE_API_BASE_URL=http://10.0.0.1:8500`，前端请求直连指定地址。

### 5.5 CORS 配置（仅跨域场景需要）

| 配置位置 | 值 | 说明 |
|---|---|---|
| `config.yaml` → `network.cors_origins` | `"http://localhost:2000,http://127.0.0.1:2000"` | 仅跨域部署时生效；**打包版同源运行无需配置** |
| `main.py` → `CORSMiddleware` | 读上述配置 | 同源请求不经过 CORS 检查，中间件空转 |

### 5.6 配置文件（`config/config.yaml` 相关项）

| 键 | 说明 |
|---|---|
| `network.cors_origins` | 跨域白名单（打包版同源不用管） |
| 其余所有配置 | 与前端部署方式无关，正常编辑即可 |

## 六、常见问题

| 问题 | 原因 | 解决 |
|---|---|---|
| 浏览器访问 `:8500` 报 404 | 打包时 `frontend/dist/` 不存在 → `_HAS_WEB=False` → 无 SPA fallback | 重新执行"第一步"再"第二步"，确认 `_internal/web/index.html` 存在 |
| 页面白屏但控制台 200 | JS 加载失败（assets 路径错误） | 确认 `_internal/web/assets/` 目录完整（71 文件 ~7MB） |
| API 请求 401 | 未设置访问口令或 token 过期 | 浏览器访问 `http://127.0.0.1:8500` 完成口令认证 |
| 端口被占用 | 8500 已被其他进程占用（含上一次没退干净的实例） | exe 启动时**已自动预检**并打印占用者 PID/进程名/路径 + 两条出路；提示后窗口**驻留 30 秒**（按任意键立即关，`--no-wait` 可跳过）便于看清。确认是本程序在跑就直接开浏览器，否则按提示 `Stop-Process -Id <PID> -Force`（PowerShell）或 `taskkill /F /PID <PID>`（CMD）后重开，也可 `--port 8501` 换端口 |
| 局域网其他机器访问不了 | 默认绑 `127.0.0.1` 仅本机回环 | `--host 0.0.0.0` + 设好口令 + 防火墙放行端口 |
| 自建 Nginx 等反代时设置页「生成验证」视频腿报 504/断连 | 生成验证的生视频腿是提交+轮询的异步长请求，单腿最坏 ≈ 3×30s 队列重试 + 600s 轮询，两腿串行 ≈ 23 分钟；反代 proxy_read_timeout 默认 60s 会先断（后端任务仍在跑且计费） | 反代 `proxy_read_timeout` / `proxy_send_timeout` 放行 ≥ 30 分钟（1_800_000ms，与前端 axios 超时同值）；无反代的同源打包版无此问题 |
