## 一、打包是什么，产物长什么样

### 1.1 目的

把 Python + FastAPI 后端打成 Windows 可执行文件，让**没有 Python 环境的用户机**也能直接运行。

**打包方式**：PyInstaller **onedir** 模式（生成一个目录，整目录拷走即用）。
**构建命令所在**：`backend/OmniAgentBackend.spec`
**产物位置**：`backend/dist/OmniAgentBackend/`

### 1.2 产物结构（务必先看懂，否则误删导致起不来）

```
dist/OmniAgentBackend/
├── OmniAgentBackend.exe        ≈ 95 MB   启动器 + 压缩字节码包(PYZ)
├── _internal/                   ≈ 910 MB  真正的主体：引擎、依赖、业务源码树
├── version.txt                  版本号（exe 同级，非 _internal）
├── config.yaml.example          配置模板（exe 同级）
├── OmniAgent.md                 项目规则文件（exe 同级）
└── config/                      首次启动自动生成
└── logs/                        运行期自动生成
```

> `version.txt` / `config.yaml.example` / `OmniAgent.md` 三份由 `run_server.py` 的
> `_deploy_resources()` 在**首次启动时**从 `_internal/` 自动部署到 exe 同级（见 4.4）。
> 构建产物里即使没有这三份，启动后也会自动补齐。

### 1.3 exe 与 `_internal` 的关系（高频误解）

**exe 本身几乎不干活**。它是 PyInstaller 的两层结构：

| 组成 | 位置 | 内容 |
|---|---|---|
| bootloader（启动壳） | exe 内部 | 操作系统加载入口，几 KB |
| PYZ 归档 | exe 内部 | 所有**纯 Python 模块的字节码**，压缩后约 95 MB |
| Python 引擎与第三方库 | `_internal\` | `python313.dll`、`libcrypto`、`sqlite3.dll`、`base_library.zip` 等，约 11000 个文件 |

**启动流程**：exe 被双击 → 加载 `_internal` 里的 `python313.dll` → 从自身解出 PYZ 字节码 → 把 `_internal` 挂进 `sys.path` → 执行 `run_server.py` → 拉起 uvicorn。

> ⚠️ **`_internal` 不是多余文件，删了 exe 立刻起不来。** 整目录一起拷、一起删。

### 1.4 为什么 `_internal\app\` 里是源码而不是字节码

这是**刻意设计**，spec 里有原始注释：

> `app/` 系命名空间包（无 `__init__.py`），collect_all/modulegraph 收不全 → 业务源码整树以源码形式拷入 `_internal/app`，由 launcher 置 `sys.path` 后按普通源码导入 — 小欧 2026-09-19

`app/` 用了命名空间包（没有 `__init__.py`），PyInstaller 静态分析对它支持不好。与其跟工具链较劲，不如整棵源码树原样带上。

- **好处**：不碰业务代码就能打包，模块解析行为与源码运行**完全一致**
- **代价**：源码可见（注释、规则都在里面），且体积没有压缩空间（910 MB 大头是第三方依赖）

### 1.5 不随包走的外部依赖

| 依赖 | 说明 |
|---|---|
| Playwright 浏览器 | 用户机需自行 `playwright install chromium` |
| tesseract / pycorrector 模型 | 与源码运行行为一致，需另行准备 |
| Node.js | 前端构建与静态服务需要，后端 exe 不含 |

```

### 2.3 安装打包工具

```powershell
E:\Appsw\python31311\python.exe -m pip install pyinstaller platformdirs
```

- **pyinstaller**：打包工具本体
- **platformdirs**：`setuptools/pkg_resources` 的运行时依赖，构建机若缺失会导致 exe 启动时报 `ImportError: The 'platformdirs' package is required`

### 2.4 【关键】补装 jaraco —— 换机器打包必做

**缺失症状**：exe 双击无反应 / 窗口一闪即退，控制台报：

```
ImportError: The 'jaraco' package is required; normally this is bundled with
this package so if you get this warning, consult the packager of your distribution.
[PYI-XXXXX:ERROR] Failed to execute script 'pyi_rth_pkgres' due to unhandled exception!
```

**根因**：构建机 setuptools 处于"半残"状态——`pkg_resources` 能找到，但它依赖的 `jaraco.text` / `jaraco.functools` 没装。PyInstaller 检测到 `pkg_resources` 就会生成运行时钩子 `pyi_rth_pkgres`，exe 一启动就执行该钩子，随即崩溃。

> **这个故障在编译期完全不报错，只在运行期暴露**，因此"打包成功"不等于"能启动"。

**修复命令**：

```powershell
E:\Appsw\python31311\python.exe -m pip install jaraco.text jaraco.functools
```

**验证**：

```powershell
E:\Appsw\python31311\python.exe -c "import pkg_resources, jaraco.text, jaraco.functools; print('OK')"
```

> ⚠️ **严禁用 `excludes=["pkg_resources"]` 规避。**
> 2026-10-11 实测：为了绕开这个崩溃一度全局排除了 `pkg_resources`，结果依赖它的 `win10toast`（桌面通知工具）连带失效——**用一个工具换掉另一个工具，属于功能退化**。
> **正解是在构建机补齐 jaraco**，spec 里已恢复为 `excludes=[]` 并留注释警示。

### 2.5 版本锁定（不可随意升级）

| 包 | 锁定版本 | 原因 |
|---|---|---|
| **httpx** | `0.26.0` | 0.28.1+ 会连带升级 httpcore，导致 TLS 失效 |
| **httpcore** | `1.0.1` | 同上 |

### 2.6 确认版本号

打包前确认 `version.txt`（项目根目录）首行是正确版本号，exe 启动时读取它。

## 三、`OmniAgentBackend.spec` 逐项讲透

spec 是打包的唯一配置源。下面每一项都有存在理由，**改动前先读完本节**。

### 3.1 `Tree` —— 业务源码树

```python
app_tree = Tree(str(BACKEND / "app"), prefix="app",
                excludes=["__pycache__", "*.pyc"])
```

把整个 `app/` 源码树拷进 `_internal/app`。理由见 1.4。启动时由 `run_server.py` 的 `_exe_dir()` 执行 `sys.path.insert(0, sys._MEIPASS)`，使其可被正常导入。

### 3.2 `collect_all()` —— 整包收集

```python
for _pkg in ("html2text", "reportlab", "openpyxl", "docx", "fitz", "pdfplumber",
             "pandas", "psutil", "pywin32", "win32gui", "pythoncom", "pywintypes",
             "pyautogui", "mss", "pyperclip", "pptx", "win10toast",
             "tree_sitter", "tree_sitter_javascript", "tree_sitter_typescript"):
    try:
        _d, _b, _h = collect_all(_pkg)
        ...
    except Exception:
        pass
```

**为什么必须显式收**：见 3.3。`except` 兜底保证构建机没装的包**跳过而不中断打包**。

### 3.3 为什么会有动态依赖问题（7/9 分类）

**现象**：打包版启动日志只注册 **7/9** 工具分类，`network`、`document` 两类失败：

```
[ToolRegistry] network 分类注册失败：缺少 html2text
[ToolRegistry] document 分类注册失败：缺少 reportlab
```

**根因**：`backend/app/tools/registry.py` 用**变量式 `__import__(模块名)`** 动态加载各分类模块：

```python
module = __import__(f"app.tools.{category}_tools", ...)   # 变量拼出来的
```

PyInstaller 的 modulegraph 靠静态 AST 分析追不进去，因此这些分类的**独占依赖不会自动进包**。源码运行没问题（环境里装着），打包后就断。

**结论**：`registry.py` 注册了哪些分类、每个分类声明了哪些 `ensure_dependency`，就必须在 spec 里显式收一遍。

### 3.4 `collect_submodules()` —— 懒加载依赖

```python
for _pkg in ("httpx", "httpcore", "anyio", "h11", "certifi", "sniffio", "idna", "win10toast"):
    _hiddenimports += collect_submodules(_pkg)
    _datas += collect_data_files(_pkg)
```

**为什么 `collect_all` 不够**：`httpx` / `httpcore` 在 LLM 服务里是**函数内懒加载 import** 的，静态分析同样扫不到，必须显式收子模块。

### 3.5 `hiddenimports` 里的 uvicorn 系列

`uvicorn.loops.auto` / `protocols.*.auto` / `lifespan.on` 等全部显式列出。uvicorn 用 `importlib` 动态选择实际实现（httptools 有无、websockets 有无都会走不同分支），不显式列就会漏。

### 3.6 `excludes=[]` —— 保持为空

**不要为了省体积排除 `pkg_resources`**，理由见 2.4。

### 3.7 `runtime_hooks=[]` —— 保持为空

曾用 runtime hook 改默认端口，现已改为 `run_server.py` 里的 `DEFAULT_PORT` 常量，**单一机制，不留两套**。

### 3.8 `console=True` + `exclude_binaries=True`

带控制台便于看日志；`exclude_binaries=True` 是 onedir 模式的必要项（EXE 只出启动器，二进制由 COLLECT 统一收集）。

## 四、完整打包流程

### 4.1 前置检查

```powershell
# 1. jaraco 在位（2.4 的验证命令必须通过）
E:\Appsw\python31311\python.exe -c "import pkg_resources, jaraco.text, jaraco.functools; print('OK')"
```

### 4.2 清理旧产物

```powershell
cd F:\OmniAgentAs-repair\backend
Remove-Item -Recurse -Force dist\OmniAgentBackend -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force build -ErrorAction SilentlyContinue
```

> 不清理会残留旧模块，导致"改了依赖却仍缺"的假象。

### 4.3 构建（约 3~4 分钟）

```powershell
E:\Appsw\python31311\Scripts\pyinstaller.exe OmniAgentBackend.spec --noconfirm
```

看到 `Build complete!` 才算构建成功。

### 4.4 资源自动部署（启动时，无需手动收尾）

onedir 模式下 `datas` 目标不能是 `..`，这三份文件只能落到 `_internal/`：

| 文件 | 作用 | 缺失后果 |
|---|---|---|
| `version.txt` | 版本显示 | 版本号显示异常 |
| `config.yaml.example` | 配置模板 | 首次启动无法生成 `config/config.yaml` |
| `OmniAgent.md` | 项目规则文件 | 运行期自动建空文件 → **项目规则不注入 Prompt** |

**启动时自动处理**：`run_server.py` 的 `_deploy_resources()` 在 `import app.main` 之前，把这三份从 `_internal/` 部署到 exe 同级。**收尾拷贝不再是必需步骤**。

**刷新判据**：源文件 mtime 新于目标则覆盖（`src.stat().st_mtime > dst.stat().st_mtime`），三份文件同一判据。

| 场景 | 行为 | 启动日志 |
|---|---|---|
| 目标缺失（首次启动） | 创建 | `refreshed` |
| 源新于目标（升级后） | 覆盖 | `refreshed` |
| 目标新于源 / 相等 | 不动 | `skipped` |
| 写盘异常（只读、权限、磁盘满） | 不动，不中断启动 | `⚠️ FAILED` |

> **为什么用 mtime 而不是 `exists()`**：升级打包版本后 `_internal/` 内的文件已更新，若只判 `exists()`，exe 同级旧文件会**永不刷新** —— 版本号显示旧值、`OmniAgent.md` 项目规则不随升级生效，且全程无任何报错（静默失效）。

> **`config.yaml.example` 刷新无害**：`_ensure_config` 仅在 `config/config.yaml` **缺失**时才从 example 复制，用户已生成的 `config.yaml` 不受任何影响。

> **手动拷贝仍可用作离线兜底**（构建机无网络、需提前备好产物时）：
> ```powershell
> Copy-Item ..\version.txt        dist\OmniAgentBackend\
> Copy-Item config.yaml.example   dist\OmniAgentBackend\
> Copy-Item ..\OmniAgent.md      dist\OmniAgentBackend\
> ```
> 注意 `Copy-Item` 默认不覆盖已存在文件（需 `-Force`），因此手工拷贝不会冲掉用户已生成的 exe 同级文件；启动时 `_deploy_resources` 仍会按 mtime 复核一次。

### 4.5 部署与升级

整个目录拷到目标机，例如 `G:\Omni-AI`。运行期还会自动生成 `config/` 与 `logs/`。

首次启动若 `config/config.yaml` 缺失，由 `config.yaml.example` 复制生成。

**升级**：整目录覆盖拷贝即可，无需手动清理旧文件。启动时 `_deploy_resources` 会按 mtime 自动刷新 `version.txt` / `OmniAgent.md` / `config.yaml.example`（见 4.4）；用户已有的 `config/config.yaml`、`logs/`、SQLite 库均不受影响。

## 五、运行期路径解析（代码根）

所有程序资源都相对"**代码根**"定位，解析点唯一：`backend/app/config.py` 的 `_get_code_root()`。

### 5.1 两种形态

| 形态 | 判定 | 代码根 |
|---|---|---|
| 源码运行 | 非 frozen | `Path(__file__).parent.parent.parent` = 仓库根 `F:\OmniAgentAs-repair` |
| 打包运行 | `sys.frozen` | `Path(sys.executable).parent` = **exe 所在目录** |

### 5.2 落点对照

| 资源 | 源码态 | 打包态 |
|---|---|---|
| `version.txt` | 仓库根 | exe 同级 |
| `config/config.yaml` | 仓库根 `config\` | exe 同级 `config\` |
| `logs/` | 仓库根 `logs\` | exe 同级 `logs\` |
| `OmniAgent.md` | 仓库根 | exe 同级 |
| SQLite 库 | `~/.omniagent` | `~/.omniagent`（用户主目录，不随包） |

> ⚠️ **代码读的是 exe 同级那份 `version.txt`**，不是 `_internal` 里那份。`_internal` 那份是 PyInstaller datas 的落点，启动时由 `_deploy_resources` 按 mtime 刷到 exe 同级（见 4.4）。**改 `_internal` 里那份只有在 mtime 更新时才会传播**；要立刻生效，直接改 exe 同级那份最可靠。

### 5.3 项目规则文件 `OmniAgent.md`

**定位**：`app/services/prompts/project_context.py`

| 规则 | 说明 |
|---|---|
| 目录基准 | 代码根（`get_code_root()`），与 `version.txt`/`config`/`logs` 同源 |
| 文件名 | 基准名 `OmniAgent.md`，**大小写不敏感**（`OMNIAGENT.MD` 等变体也能命中） |
| 缺失处理 | 自动创建空文件占位 |
| 内容上限 | `tuning.content.project_context_max_chars`，默认 10000 字符，超出截断 |
| 作用 | 注入 System Prompt 第②块，是项目级规则入口 |

## 六、运行期依赖体系

### 6.1 三类依赖与收集策略

| 类别 | 特征 | 收集方式 | 举例 |
|---|---|---|---|
| 静态可扫 | 常规 `import` | PyInstaller 自动 | FastAPI、SQLAlchemy |
| 动态加载 | 变量式 `__import__` | **spec 里 `collect_all()`** | html2text、reportlab、pyautogui |
| 懒加载 | 函数内 import | **spec 里 `collect_submodules()`** | httpx、httpcore |

### 6.2 打包版不执行 pip 安装

`app/utils/dependency.py` 的 `ensure_dependency()` 在源码态的行为是：导入失败 → `pip install` → 失败再降级 `--user`。

**打包版必须短路**，原因两条：

1. frozen 下 `sys.executable` 是 `exe` 自身，`pip install` 会被自家 argparse 以 `unrecognized arguments` 打回，**刷屏且必然失败**
2. 即便装成功，frozen 进程的 `sys.path` 只认 `_MEIPASS`，系统 pip 装到 site-packages 的包**进程看不见**

当前行为：frozen 下直接返回 `False`，并打印可操作提示：

```
[依赖] 打包版(exe)缺失依赖 'xxx'：不支持运行时 pip 安装，已跳过。
需要该功能请重打包含该依赖的版本；或改用源码运行并执行 `pip install xxx`。
```

> 结论：**打包版缺依赖只能通过重打解决**，日志会指名缺哪个。

### 6.3 frozen 下跳过版本核对

`ensure_dependency()` 在导入成功后还会核对版本：

```python
if version and version.startswith("=="):
    installed = importlib.metadata.version(pip_package)   # frozen 下必然失败
```

**打包环境里 dist-info 不参与运行期元数据查询**，该调用抛 `PackageNotFoundError`，被外层 `except ImportError` 捕获，**误判成"依赖缺失"**。

实测症状：`httpx` 明明已正确打进包，仍反复报缺失。

**修复**：frozen 下跳过版本核对——版本已由构建机 `requirements.txt` 锁定并随包落地，运行期再查没有意义。源码运行行为不变。

## 七、默认端口与启动参数

```python
DEFAULT_PORT = 8500        # run_server.py
```

| 场景 | 端口 |
|---|---|
| 源码开发 | 8000 |
| **打包版无参启动** | **8500** |

显式传 `--port` 恒优先。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | `127.0.0.1` | 监听地址 |
| `--port` | `8500` | 监听端口 |
| `--forwarded-allow-ips` | `127.0.0.1` | 信任哪些对端的 `X-Forwarded-For` |

> ⚠️ `--forwarded-allow-ips=*` 有风险：任意客户端可伪造来源 IP 冒充 `127.0.0.1` 免口令访问（可读全部明文密钥、可改口令）。确需信任内网反代时**只列该反代的 IP**。填 `*` 会打印告警，且应用层 fail-closed（本机也要输口令）。

## 八、验收清单（逐条勾）

打包后**必须**逐条验证，"构建成功"不等于"能运行"。

| # | 验收项 | 判定 |
|---|---|---|
| 1 | 双击 exe 不闪退 | 窗口持续存在 |
| 2 | 端口监听 | `netstat` 见 8500 LISTENING |
| 3 | 健康检查 | `http://127.0.0.1:8500/api/v1/health` 返回 `healthy` + 正确版本 |
| 4 | **缺失依赖告警 = 0 条** | 见 6.2，这是动态依赖是否收全的**唯一可靠指标** |
| 5 | 无 pip 刷屏 | 日志中不得出现 `OmniAgentBackend.exe -m pip install` |
| 6 | 工具分类注册 | 9/9，无 `分类注册失败` |
| 7 | 项目规则注入 | `OmniAgent.md` 在 exe 同级且非空 |
| 8 | 配置生效 | `config/config.yaml` 存在且为预期配置 |

### 8.1 一键核对命令

```powershell

## 九、故障排查手册

| 症状 | 根因 | 处置 |
|---|---|---|
| exe 双击闪退，控制台报 `The 'jaraco' package is required` | 构建机缺 `jaraco.text` / `jaraco.functools` | 按 2.4 补装，**不要排除 `pkg_resources`** |
| `Failed to execute script 'pyi_rth_pkgres'` | 同上 | 同上 |
| 启动报 `No module named 'pkg_resources'`，且 notify 工具失效 | spec 被误加 `excludes=["pkg_resources"]`，误伤 `win10toast` | 恢复 `excludes=[]`，改在构建机补 jaraco |
| 日志刷 `unrecognized arguments: -m pip install ...` | frozen 下执行了 pip | 检查 `dependency.py` frozen 短路是否生效 |
| 分类注册失败（7/9），提示缺 html2text / reportlab | 动态依赖未收 | 按 3.2 补进 `collect_all` 清单后重打 |
| 依赖明明打进包，仍报缺失 | frozen 下版本核对误判 | 按 6.3 跳过版本核对 |
| 端口冲突或与源码版混淆 | 打包版默认 8500、源码版 8000 | 显式传 `--port` |
| 版本号显示不对 | 改了 `_internal` 里那份但 mtime 未更新，或 exe 同级那份被手工改旧 | 看启动日志 `_deploy_resources` 行：`skipped` 说明 exe 同级更新、需删掉它重启；`refreshed` 说明已刷新，检查 `_internal` 那份内容 |
| 项目规则没注入 Prompt | `OmniAgent.md` 缺失、为空，或 exe 同级那份比 `_internal` 更新（用户手工改过旧版后启动） | 看启动日志：`skipped` → 删掉 exe 同级那份重启即强制刷新；`FAILED` → 查权限/只读；`refreshed` 但仍不生效 → 检查 `_internal` 那份内容是否为空 |

## 十、改动影响速查

| 改了什么 | 必须同步做什么 |
|---|---|
| spec 依赖收集清单 | 改完**必须**重打并跑第八章验收 |
| 构建机 Python 环境 | 换机器后先补 jaraco（2.4） |
| `run_server.py` 默认端口 | 重打才生效；显式传参不受影响 |
| 新增工具分类的依赖 | 在 `registry.py` 找到该分类的 `ensure_dependency`，补进 spec 收集清单 |
| `OmniAgent.md` | 改内容后重打；启动时按 mtime 自动刷新到 exe 同级（4.4） |
| `version.txt` | 改内容后重打；启动时按 mtime 自动刷新到 exe 同级（4.4） |
| `_deploy_resources` 判据 | 三份文件共用 `_deploy_one`，改判据只改一处；改完重打并看启动日志三类输出 |
