## 一、概述

OmniAgentAst 后端已打包为 Windows 可执行文件（exe），用户无需安装 Python 环境即可运行。

**exe 能做什么：**
- 启动后端 API 服务（FastAPI + uvicorn）
- 提供聊天、任务管理、工具执行等全部后端功能
- 与前端（Vite + React）配合使用

**exe 不能做什么：**
- 不包含前端页面（前端需单独启动或构建）
- 不包含 playwright 浏览器（网页抓取工具需另装）
- 不包含 tesseract OCR（文字识别工具需另装）

## 二、目录结构

拿到 `OmniAgentBackend` 目录后，结构如下：

```
OmniAgentBackend/
├── OmniAgentBackend.exe        ← 双击启动
├── version.txt                 ← 版本号（第一行，如 v1.0.1）
├── config.yaml.example         ← 配置模板
├── config/                     ← 运行时自动生成
│   └── config.yaml             ← 你的配置（首次启动自动从 example 复制）
├── logs/                       ← 运行时自动生成
│   ├── app_2026-09-19.log      ← 应用日志
│   └── prompt-logs/            ← Prompt 调试日志
└── _internal/                  ← Python 依赖和业务源码（勿动）
    ├── app/                    ← 后端业务代码
    ├── fastapi/                ← Web 框架
    ├── uvicorn/                ← ASGI 服务器
    └── ...                     ← 其他依赖包
```

**关键说明：**
- `config/`、`logs/` 目录首次运行时自动创建，无需手动建
- `_internal/` 是 PyInstaller 打包的内部文件，**不要手动修改或删除**
- `config.yaml.example` 是配置模板，**不要直接编辑它**，编辑复制后的 `config/config.yaml`

## 三、首次使用

### 3.1 编辑配置文件

打开 `config/config.yaml`（首次启动后自动生成），填入你的 API 密钥：

```yaml
ai:
  provider: opencode        # 当前使用的 Provider 名称

  opencode:
    api_base: https://opencode.ai/zen/v1
    api_key: sk_xxx...      # ← 填入你的 API Key
    models:
      - minimax-m2.5-free
      - kimi-k2.5-free
    timeout: 120
```

**至少配置一个 Provider 的 `api_key`**，否则 LLM 调用会失败。

### 3.2 启动服务

**方式一：双击启动**

双击 `OmniAgentBackend.exe`，会弹出控制台窗口，看到以下信息表示启动成功：

```
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000
```

**方式二：命令行启动**

```powershell
cd F:\OmniAgentAs-repair\backend\dist\OmniAgentBackend
.\OmniAgentBackend.exe --port 8000
```

### 3.3 验证服务

浏览器访问 `http://127.0.0.1:8000/api/v1/health`，返回以下 JSON 表示正常：

```json
{
    "status": "healthy",
    "timestamp": "2026-09-19T13:38:09.866152",
    "version": "1.0.1",
    "db_status": "healthy"
}
```

也可用 PowerShell 快速验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
```

## 四、配置说明

`config/config.yaml` 与源码版完全通用，字段含义如下：

### 4.1 AI Provider 配置

```yaml
ai:
  provider: opencode          # 当前激活的 Provider 名称（对应下方同名子项）

  opencode:                   # Provider 名称（可自定义）
    api_base: https://...     # API 地址
    api_key: sk_xxx...        # API 密钥
    models:                   # 可用模型列表
      - minimax-m2.5-free
      - kimi-k2.5-free
    timeout: 120              # 请求超时（秒）

  longcat:                    # 可配置多个 Provider
    api_base: https://...
    api_key: ak_xxx...
    models:
      - LongCat-Flash-Thinking
    timeout: 120
```

### 4.2 环境变量覆盖

除了编辑 config.yaml，也可通过环境变量覆盖配置（优先级更高）：

| 环境变量 | 作用 | 示例 |
|---------|------|------|
| `AI_PROVIDER` | 覆盖 `ai.provider` | `set AI_PROVIDER=longcat` |
| `LOG_LEVEL` | 覆盖日志级别 | `set LOG_LEVEL=DEBUG` |
| `{PROVIDER}_API_KEY` | 覆盖对应 Provider 的 api_key | `set OPENCODE_API_KEY=sk_yyy...` |

## 五、启动参数

```
OmniAgentBackend.exe [--host HOST] [--port PORT]
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--host` | `127.0.0.1` | 监听地址。`127.0.0.1` 仅本机可访问；`0.0.0.0` 允许局域网访问 |
| `--port` | `8000` | 监听端口。若 8000 被占用，可用 `--port 8001` 指定其他端口 |

**示例：**

```powershell
# 默认启动（127.0.0.1:8000）
.\OmniAgentBackend.exe

# 指定端口
.\OmniAgentBackend.exe --port 8001

# 允许局域网访问
.\OmniAgentBackend.exe --host 0.0.0.0 --port 8000
```

## 六、运行时行为

### 6.1 日志

exe 启动后自动在同目录创建 `logs/` 目录：

| 文件 | 内容 | 说明 |
|------|------|------|
| `logs/app_YYYY-MM-DD.log` | 应用日志 | 按日期自动轮转，含请求日志、错误日志 |
| `logs/prompt-logs/` | Prompt 调试日志 | 每次 LLM 请求一个 JSON 文件，用于调试 prompt 组装 |

日志格式与源码版完全一致，排查问题时查看这些文件即可。

### 6.2 数据库

SQLite 数据库文件位于用户主目录（**不在 exe 旁**）：

```
~/.omniagent/chat_history.db    ← 聊天历史
```

即 `C:\Users\{用户名}\.omniagent\chat_history.db`。

这个路径与源码运行时相同，**exe 版和源码版可以共享同一个数据库**。

### 6.3 版本号

exe 启动时从 `version.txt`（exe 旁）读取第一行作为版本号，显示在：
- 启动日志：`Backend version: 1.0.1`
- health 接口响应：`"version": "1.0.1"`

更新版本号只需修改 `version.txt` 第一行，无需重新打包。

### 6.4 排查文件

当 `config.yaml` 中 `app.debug: true` 时，任务排查文件（文件 A/B）写入 `exe旁/files/`。

当 `app.debug: false`（默认）时，写入 `~/.omniagent/files/`。

## 七、外部依赖

以下工具不随 exe 打包，需要用户单独安装：

### 7.1 Playwright 浏览器（网页抓取）

```powershell
# 安装 playwright
pip install playwright

# 安装 Chromium 浏览器（约 150MB）
playwright install chromium
```

若未安装，`fetch_webpage` 工具的 JS 渲染模式会失败，但静态抓取仍可用。

### 7.2 Tesseract OCR（文字识别）

```powershell
# 下载安装 tesseract-ocr-w64
# https://github.com/UB-Mannheim/tesseract/wiki

# 安装后确保 tesseract 在 PATH 中
tesseract --version
```

若未安装，`ocr_extract` 工具不可用。

### 7.3 pycorrector 模型（中文纠错）

首次使用时会自动下载模型（约 200MB），需要网络连接。若离线环境，需提前在有网机器上下载后拷贝到 `~/.pycorrector/` 目录。

## 八、常见问题

### 8.1 启动报 "配置文件不存在"

**原因：** `config/config.yaml` 不存在，且 `config.yaml.example` 也不存在（手动删除了）。

**解决：** 从其他地方拷贝一份 `config.yaml.example` 到 exe 旁，重启 exe 会自动复制为 `config.yaml`。

### 8.2 启动报 "port 8000 already in use"

**原因：** 8000 端口被占用（可能是上次没关、或其他程序占用）。

**解决：**
```powershell
# 查找占用进程
netstat -ano | findstr :8000

# 杀掉进程（替换 PID）
taskkill /PID <进程ID> /F

# 或换端口启动
.\OmniAgentBackend.exe --port 8001
```

### 8.3 启动报 "No module named 'xxx'"

**原因：** 构建时遗漏了某个依赖。

**解决：** 在 `OmniAgentBackend.spec` 的 `hiddenimports` 列表中添加缺失模块名，重新构建。

### 8.4 杀毒软件拦截

**原因：** PyInstaller 打包的 exe 可能被杀毒软件误报。

**解决：** 将 exe 所在目录加入杀毒软件白名单。这是 PyInstaller 的已知问题，不影响安全性。

### 8.5 health 接口返回 200 但前端连不上

**原因：** 前端连接地址不对，或 CORS 配置问题。

**解决：** 确认前端连接的是 `http://127.0.0.1:8000`（与 exe 启动端口一致），且 config.yaml 中 CORS 配置包含前端地址。

## 九、与源码版差异对比

| 对比项 | 源码版 | exe 版 |
|--------|--------|--------|
| **启动方式** | `python -m uvicorn app.main:app` | 双击 `OmniAgentBackend.exe` |
| **Python 环境** | 需要 Python 3.13+ | 不需要，自带 Python 运行时 |
| **日志位置** | `backend/logs/` | `exe旁/logs/` |
| **Prompt 日志** | `backend/logs/prompt-logs/` | `exe旁/logs/prompt-logs/` |
| **配置文件** | `backend/config/config.yaml` | `exe旁/config/config.yaml` |
| **版本来源** | `backend/version.txt` | `exe旁/version.txt` |
| **数据库** | `~/.omniagent/chat_history.db` | 同左（共享） |
| **排查文件(debug)** | `backend/files/` | `exe旁/files/` |
| **排查文件(正式)** | `~/.omniagent/files/` | 同左（共享） |
| **热重载** | `--reload` 可用 | 不支持（需重启） |
| **产物大小** | 无（源码） | 约 42-915MB |
| **功能一致性** | - | 完全一致（路径不同，业务逻辑零差异） |

**核心结论：** exe 版与源码版功能完全一致，仅程序自身资源（日志、配置、版本）的定位路径从 `backend/` 变为 `exe 所在目录`。用户数据（数据库、排查文件正式模式）位置不变，两版可共享。
