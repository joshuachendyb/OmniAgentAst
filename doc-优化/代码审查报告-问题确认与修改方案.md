## 三、Major 问题（68个 — 架构/逻辑/设计问题）

### 3.1 架构违规（14个）

#### M-01: `tool_cache_manager.py` 同一模块 import 3次

**文件**: `backend/app/services/agent/tool_cache_manager.py` L25/L48/L75

#### M-02: `llm_stream.py` 4个函数体内 import + 分号语句

**文件**: `backend/app/services/agent/llm_stream.py` L79/L117/L156/L157  
**问题**: 4个 import 在函数体内。另外 L143/L149 使用分号分隔语句：`_p = ...; _c = ...; _t = ...`。`_p`/`_c`/`_t` 提取模式在 `tool_calls_result` 分支和 `answer` 分支重复。  
**修复**: import 移顶部，分号句改多行，重复模式抽函数。

#### M-03: `_build_call_list` 返回 6 元组

**文件**: `backend/app/services/agent/core_agent/handlers/action_handler.py` L313-340  
**问题**: 返回 `(tool_name, tool_params, fc_context, pending_calls, all_calls, is_parallel)` 共6个值，调用方解包顺序容易出错。  
**修复**: 用命名元组 `BuildCallListResult` 或 `dataclass`。

#### M-04: `_inject_conversation_history` 消息复制不完整

**文件**: `backend/app/services/agent/core_agent/initialize_run_state.py` L30-49  
**问题**: tool 消息复制只取 `tool_call_id` 和 `content`，缺 `name` 字段。assistant 消息的 `tool_calls` 在复制时 `arguments` 字段不校验。FC 协议可能不完整。  
**修复**: 使用 MessageBuilder 的 add_system_message/add_user_message 类型安全方法。

#### M-05: DB 外键不生效

**文件**: `backend/app/db/db_initializer.py` L140  
**问题**: `REFERENCES tasks(task_id) ON DELETE CASCADE` 定义了外键，但 SQLite 默认 `PRAGMA foreign_keys = OFF`，从未执行该 pragma，约束不生效。  
**修复**: 建表后执行 `conn.execute("PRAGMA foreign_keys = ON")`。

#### M-06: `_make_safe_loader()` 每次调用创建新类

**文件**: `backend/app/config.py` L13-25  
**问题**: 每次加载配置都创建一个新 `_Loader` 类。类定义是编译期操作，反复创建无意义。  
**修复**: 定义为模块级单例，或缓存类引用。

#### M-07: `_make_yaml_loader` 与 config.py 重复

**文件**: `backend/app/api/v1/ai_config/_helpers.py` L69-83
