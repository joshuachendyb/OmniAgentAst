## 一、先说结论：系统处理错误分两大类

整个系统里所有出错情况，按"任务停不停"分成两大类，互不重叠，各自独立路径：

### 1.1 核心分类架构

```
错误处理架构
├── 系统层次错误 (System Errors)          —— 任务停
│   ├── LLM流层错误（3种，同根因）
│   ├── ReAct循环层错误（8种，全部正确）
│   ├── 安全检查层错误（3种，全部正确）
│   └── 基础设施层错误（2种，全部正确）
│
└── 工具层次错误 (Tool Errors)            —— 任务不停
    ├── 前置校验错误（3种，全部正确）
    ├── 执行重试错误（4种，全部正确）
    └── 执行段错误（1种，全部正确）
```

```
系统类错误（任务停）：LLM流层 + ReAct循环层 + 安全检查层 + 基础设施层
├── 特征：Agent循环中断，设FAILED/CANCELLED/RETRYABLE_ERROR
└── 位置：llm_stream → _process_single_step → _dispatch_handler → run_react_cycle

工具层错误（任务不停车）：前置校验 + 执行重试 + 执行段
├── 特征：Agent循环继续，错误作为ObservationStep喂回给LLM
└── 位置：action_handler → tool_executor → tool_retry_engine
```

### 1.2 第一类：系统层次的错误（任务会停）

比方说：
- 调AI大模型的时候网络断了
- AI大模型返回的数据格式完全不对
- 跑任务跑超时了（太久没出结果）
- 安全检查认定某个操作有风险，不让执行
- 用户点了"取消"

遇到这类错误，**任务直接终止**，系统告诉用户"任务失败了，原因是XXX"。

> 简单理解：**系统自己出了问题，任务没法继续了。**

### 1.3 第二类：工具层次的错误（任务不停）

定义：发生在工具执行过程中的错误。每个工具独立处理，自带重试机制，不炸到系统层。

LLM说"要用工具X"→ 系统去执行工具X → 工具执行有问题 → 但问题不扩散到系统层→ 包装成ObservationStep喂回给LLM → LLM自己决定：重试、换工具、回答

比方说：
- AI说要调一个工具，但这个工具的名字系统里找不到
- AI调工具时给的参数不对
- AI漏了必填的参数
- 调工具时出错了（比如网络超时），重试了几次还是不行

遇到这类错误，**任务不终止**。系统把"工具执行出错了"这个信息包装好，喂回给AI大模型。AI大模型自己决定下一步怎么办：
- 重试一次这个工具
- 换别的工具试试
- 直接回答用户"这个事我办不了"

> 简单理解：**工具执行不顺利，但AI自己会想办法，任务还能继续。**

### 1.4 两类错误的核心区别

| 特性 | 系统层次错误 | 工具层次错误 |
|------|------------|-------------|
| 循环是否中断 | 是，直接break | 否，LLM看到错误结果后自行决定 |
| 前端看到什么 | ErrorStep + FinalStep | ObservationStep（error状态） |
| Agent状态 | FAILED / RETRYABLE_ERROR / CANCELLED | 保持THINKING，循环继续 |
| 能否恢复 | 一部分可以（RETRYABLE_ERROR） | 可以，LLM重试或换工具 |
| 谁创建Step | ErrorStep + FinalStep | ObservationStep |
| 错误码来源 | error_type字符串 | constants.py中的ERR_xxx |

| 核心区别 | 系统层次错误 | 工具层次错误 |
|---------|------------|-------------|
| **任务停不停** | **停** | **不停** |
| **用户看到什么** | "任务失败，原因是..." | AI自己处理，用户可能看到AI说"我重试一下"或者"办不了" |
| **谁来决定下一步** | 系统自己决定（终止/重试整轮） | AI自己决定（重试/换工具/放弃） |

### 2.5 关于safety_blocked的分类说明

check_safety_and_confirm在action_handler里，但它中断了循环（设FAILED）。它不是Tool执行本身的错误，而是安全检查基础设施阻止了Tool执行。

所以正确的分类应该是：
- 21号safety_blocked → 系统层次（中断循环，设FAILED）
- 22号user_rejected → 系统层次（中断循环，设FAILED）
- 23号invalid_action → 系统层次（中断循环，设FAILED）

### 2.6 系统层次错误处理架构图

```
call_llm_with_fallback()
    │
    ├── 正常响应 (response type ──── limit / no error)
    │   ├── "action" ──→ _dispatch_handler ──→ handle_action()
    │   └── "answer" ──→ _dispatch_handler ──→ handle_answer() → COMPLETED
    │
    └── 错误响应 (error type)
        └── _dispatch_handler ──→ handle_error() → FAILED
                                      │
                                      ├── ErrorStep(error_type, error_message)
                                      ├── add_assistant_message(content)
                                      ├── agent.set_failed(content)
                                      └── FinalStep(response=content)
```

```
call_llm_stream 异常
    ↓
_yield_error_response("LLM流式错误: xxx", agent)
    ↓
returns ("response", {"type": "error", "content": "LLM流式错误: xxx"})
    ↓
_process_single_step 收到 response
    ↓
_dispatch_handler 解析 type == "error"
    ↓
handle_error(agent, llm_response, chunk_buffer)
    ├── add_assistant_message(content)
    ├── agent.set_failed(content)
    ├── yield ErrorStep(error_type="llm_stream_error", ...)
    └── yield FinalStep(response=content, ...)
    ↓
run_react_cycle 检查 status == FAILED → break
    ↓
任务终止，返回"任务失败，原因是LLM流式错误: xxx"
```

## 三、工具层次的错误（共7条，都有对）

### 3.1 核心思想

AI说"我要用工具X"→ 系统去执行工具X → **工具执行有问题**

但**问题不传到系统层**，而是：
1. 把错误包装成**结构化的结果**
2. 通过"观察步骤"喂给AI
3. AI自己决定下一步

### 3.5 工具层次错误处理流程

```
AI说"用工具X"
    ↓
系统去执行工具X
    ↓
工具重试引擎开始工作：
    ├── 工具名字找不到 → 返回"工具未找到"

```
