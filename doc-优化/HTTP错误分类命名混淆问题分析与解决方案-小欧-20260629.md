# HTTP错误分类命名混淆问题分析与解决方案

## 1. 问题发现

在review tool重试架构时，发现HTTP错误分类存在命名混淆问题：

### 1.1 命名混淆
`ErrorCategory`枚举中使用了`API_`前缀来命名HTTP状态码错误：
```python
# error_classifier.py
API_RATE_LIMIT = "api_error_429"      # 实际是HTTP 429
API_UNAUTHORIZED = "api_error_401"    # 实际是HTTP 401  
API_FORBIDDEN = "api_error_403"       # 实际是HTTP 403
API_BAD_REQUEST = "api_error_400"     # 实际是HTTP 400
```

### 1.2 逻辑矛盾
`http_request`工具的重试逻辑：
```python
# constants.py
RETRYABLE_HTTP_STATUS_CODES = {
    HTTP_RATE_LIMIT,          # 429 - 在可重试列表中
    HTTP_INTERNAL_ERROR,      # 500
    HTTP_BAD_GATEWAY,         # 502  
    HTTP_SERVICE_UNAVAILABLE, # 503
    HTTP_GATEWAY_TIMEOUT,     # 504
}

# http_request.py
if e.response.status_code not in RETRYABLE_HTTP_STATUS_CODES:
    return build_error(...)  # 不重试
else:
    raise  # 传播给ToolRetryEngine重试
```

但`TOOL_RETRY_CONFIG`中没有配置`"api_error_429"`，导致HTTP 429不会被重试。

## 3. 影响分析

### 3.1 对`http_request`工具的影响
- HTTP 429（限速）在`RETRYABLE_HTTP_STATUS_CODES`中 → 会传播给`ToolRetryEngine`
- 但`TOOL_RETRY_CONFIG`中没有`"api_error_429"` → 不会被重试
- 造成逻辑矛盾：应该重试但没有配置

### 3.2 对错误处理的影响
- HTTP 4xx错误被标记为`API_*`，但实际是HTTP工具错误
- 命名误导：`API_`前缀暗示是内部API调用错误，实际是外部HTTP请求错误

### 3.3 对重试配置的影响
当前`TOOL_RETRY_CONFIG`配置：
```python
"retryable_errors": ["timeout", "connect", "network", "server", "protocol"]
```
缺少：
- `"api_error_429"`（HTTP 429限速，应该重试）
- 其他HTTP 4xx错误（不应该重试）

---

## 4. 解决方案

### 4.1 方案A：最小改动（推荐）
**只修正`TOOL_RETRY_CONFIG`配置，添加缺失的错误类型：**

```python
# tool_retry_engine.py
TOOL_RETRY_CONFIG = {
    "http_request": {
        "max_retries": 3, 
        "retryable_errors": [
            "timeout",          # 超时错误
            "connect",          # 连接错误  
            "network",          # 网络错误
            "server",           # HTTP 5xx服务器错误
            "protocol",         # 协议错误
            "api_error_429"     # HTTP 429限速（临时性，应该重试）
        ]
    },
    # ... 其他网络工具类似配置
}
```

**在`error_classifier.py`中添加注释说明：**
```python
# HTTP状态码到错误类型的映射
# 注意：API_前缀实际对应HTTP状态码，不是内部API调用错误
# 历史原因保留此命名，实际表示HTTP工具的错误
HTTP_STATUS_TO_ERROR_TYPE: Dict[int, ErrorCategory] = {
    400: ErrorCategory.API_BAD_REQUEST,      # HTTP 400 Bad Request
    401: ErrorCategory.API_UNAUTHORIZED,     # HTTP 401 Unauthorized
    403: ErrorCategory.API_FORBIDDEN,        # HTTP 403 Forbidden
    429: ErrorCategory.API_RATE_LIMIT,       # HTTP 429 Too Many Requests
    500: ErrorCategory.SERVER,               # HTTP 500 Internal Server Error
    # ...
}
```

### 4.2 方案B：修正命名（中等改动）
**修改`ErrorCategory`枚举，把`API_`前缀改为`HTTP_`：**

```python
# error_classifier.py
HTTP_RATE_LIMIT = "http_429"
HTTP_UNAUTHORIZED = "http_401"  
HTTP_FORBIDDEN = "http_403"
HTTP_BAD_REQUEST = "http_400"

# 同时修改映射
HTTP_STATUS_TO_ERROR_TYPE: Dict[int, ErrorCategory] = {
    400: ErrorCategory.HTTP_BAD_REQUEST,
    401: ErrorCategory.HTTP_UNAUTHORIZED,
    403: ErrorCategory.HTTP_FORBIDDEN,
    429: ErrorCategory.HTTP_RATE_LIMIT,
    # ...
}
```

**`TOOL_RETRY_CONFIG`对应修改：**
```python
"retryable_errors": ["timeout", "connect", "network", "server", "protocol", "http_429"]
```

### 4.3 方案C：彻底重构（大改动）
**区分HTTP工具错误和API调用错误：**

```python
# HTTP工具错误（外部HTTP请求）
HTTP_BAD_REQUEST = "http_bad_request"
HTTP_UNAUTHORIZED = "http_unauthorized"
HTTP_FORBIDDEN = "http_forbidden"
HTTP_RATE_LIMIT = "http_rate_limit"
HTTP_SERVER_ERROR = "http_server_error"

# API调用错误（内部API调用，如LLM）
API_BAD_REQUEST = "api_bad_request"
API_UNAUTHORIZED = "api_unauthorized"
API_FORBIDDEN = "api_forbidden"
API_RATE_LIMIT = "api_rate_limit"
```

---

## 5. 最终决策

**采用方案A（最小改动）+ 添加注释说明**，理由：

1. **改动最小**：只修改`TOOL_RETRY_CONFIG`配置，不改变现有`ErrorCategory`枚举
2. **保持兼容**：不影响现有代码，所有调用`ErrorCategory.API_RATE_LIMIT`的地方继续工作
3. **解决实际问题**：HTTP 429现在能被正确重试
4. **风险最低**：不需要修改多处引用`ErrorCategory`的代码
5. **清晰明了**：通过注释说明命名约定的历史原因
