## 一、问题说明

### 1.1 现象

设置页 → 模型 Tab → ② 参数区（跟随当前模型）：当用户选择一个 **config.yaml 中未配置 `model_params`** 的模型时（如 qiniu provider 的 deepseek-v3.1），参数区**完全空白**，没有任何可操作控件。

### 1.2 根因

`ModelParams.tsx` 渲染逻辑（行 46）：
```tsx
{Object.keys(defaults).map((key) => { ... })}
```

`defaults` 来自后端 `_models_of()` 返回的 `default_params`，而 `default_params` 来自 `config.yaml → ai.{provider}.model_params.{model}`。**config.yaml 中没有 `model_params` 块的模型 → `default_params = {}` → `Object.keys({}) = []` → 零渲染。**

### 1.3 用户需求

在参数区增加 **「+ 添加参数」按钮**，允许用户动态为当前模型添加自定义参数（如 temperature、max_tokens、reasoning_effort 等），无需手动编辑 config.yaml。

### 1.4 项目实际使用的模型参数

从 `config.yaml` 和 `backend/app/llm/` 代码中提取：

| 参数名 | 类型 | 范围/选项 | 用途 | 通用性 |
|--------|------|----------|------|--------|
| `temperature` | number(float) | 0.0 ~ 2.0 | 采样温度 | 通用（所有模型） |
| `max_tokens` | number(int) | 1 ~ 100000 | 最大输出 token | 通用 |
| `top_p` | number(float) | 0.0 ~ 1.0 | 核采样阈值 | 通用（[64]后后端全量消费） |
| `frequency_penalty` | number(float) | -2.0 ~ 2.0 | 频次重复惩罚 | 通用（[64]后后端全量消费） |
| `presence_penalty` | number(float) | -2.0 ~ 2.0 | 话题重复惩罚 | 通用（[64]后后端全量消费） |
| `reasoning_effort` | enum(string) | low / medium / high | 推理深度 | 仅推理模型 |
| `context_limit` | number(int) | 1000 ~ 900000 | 上下文裁剪阈值 | 通用 |
| `seed` | number(int) | 任意整数 | 随机种子 | 通用 |
| `chat_template_kwargs` | object(JSON) | `{"enable_thinking":true}` | 模板开关 | 通用（走自定义模式输入JSON） |

**说明**：v1.0 曾写“`top_p`、`frequency_penalty`、`presence_penalty` 代码零引用”——该结论已过期，[64] 后 `client_sdk._build_request_body` + `base_service` 对三参全量消费；三参值域明确，最适合进预定义表。

## 二、修改策略及 UI 形式

### 2.1 策略选择

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| A. 纯自由输入 | 用户手动填 key + 选类型 + 填值 | 灵活 | 拼错 key、类型选错、不知道填什么 |
| **B. 预定义 + 自定义混合** | **下拉选常用参数（自动带出默认值/范围/控件），兜底自定义输入** | **安全 + 灵活** | 需维护预定义表 |
| C. 全自动注入 | 后端自动给无 model_params 的模型注入全局默认参数 | 零操作 | 用户无法控制、参数膨胀 |

**选择方案 B**：预定义 8 个常用参数 + 自定义兜底（自定义覆盖 object/JSON 等特殊类型）。

### 2.4 控件自动映射

| 条件 | 渲染控件 | 来源 |
|------|---------|------|
| 有 range | `Slider` + `InputNumber` | `PARAM_PRESETS[i].range` 注入 `state.model.ranges` |
| 有 options | `Select` | `PARAM_PRESETS[i].options` 注入 `state.model.paramOptions` |
| 值为 number 无 range | `InputNumber` | `typeof value === 'number'` |
| 值为 boolean | `Switch` | `typeof value === 'boolean'`（[62]P4 五分支已支持） |
| 值为 string | `Input` | `typeof value === 'string'` |
| 值为 object | `TextArea`(JSON) | 自定义模式输入 JSON 字符串解析后注入 |

**关键修正（v1.1 P0-1）**：`ModelParams.tsx` 按 `Object.keys(defaults)` 遍历渲染，而 `addParam` 为保脏故意不注入 `defaults`——若不动渲染，新行点确认后**不可见**。修法：渲染改遍历 `params ⊔ defaults` 并集（`ModelParams.tsx:46` 改 1 行，见 §4.4），判脏逻辑不动（新 key 在 defaults 中无 → 天然判脏）。

## 三、关联逻辑和参数冲突性分析

### 3.1 数据流完整性分析

```
[添加参数]
addParam(key, value, meta)
  → state.model.params[key] = value      ← 编辑副本
  → state.model.defaults[key] = value     ← 基线（不同步则立即判脏）
  → state.model.ranges[key] = meta.range  ← 控件类型
  → state.model.paramOptions[key] = meta.options  ← 枚举选项
  → ModelParams 自动渲染新行
       ↓
[保存]
saveModelGroup()
  → dirty = isDirty(params, defaults, envOverride)
  → changed = {k: params[k] for k in dirty if dirty[k]}
  → PUT /models/{provider}/{model}  body: {default_params: changed}
       ↓
[后端写入]
update_model()  (model_service.py:229-270)
  → old_params = config.yaml 原值
  → old_params.update(changed)  ← 自动合并新 key
  → node["model_params"][model] = old_params
  → merge_nested_patch() → config.yaml
       ↓
[回读]
GET /models → _models_of() → params_block.get(model) → 包含新 key
→ defaults 包含新 key → UI 正常显示
```

**保存链路无需任何改动**——`update_model()` 的 `old_params.update(dp)` 已支持任意新 key。

### 3.2 脏态冲突分析

| 场景 | 行为 | 是否冲突 |
|------|------|---------|
| 添加参数后 defaults 同步注入 | 新 key 在 params 和 defaults 中值相同 → `isDirty = false` → 不脏 | ⚠️ 用户未编辑却显示"已保存" |
| **添加参数后 defaults 不同步** | **新 key 在 defaults 中不存在 → `isDirty = true` → 立即脏** | ✅ 正确：必须保存才落盘 |
| 保存后 defaults 同步 | `patchModel({ defaults: { ...params } })` → defaults 更新为 params 快照 | ✅ 正确：新基线 |
| 切换模型后未保存 | `selectModel` 先 `ensureModelSaved` 自动保存（BUG-D），新参数随之落盘 | ✅ 不丢失，无需提示 |

**决策：defaults 不同步注入**。添加参数后 `defaults` 中无此 key → `isDirty` 遍历 `Object.keys(params)` 发现该 key 在 defaults 中无 → `sameValue(params[key], undefined)` → `false` → `isDirty[key] = true` → 立即脏。用户必须点"保存本组"才落盘。

**配套（v1.1 P0-1）**：渲染侧改遍历并集后，新行立即可见 + DirtyDot 正常显示（`dirty[key]` 由本地 `isDirty()` 算出，与 state 无关），与本决策无冲突。

### 3.3 isDirty 函数兼容性验证

```typescript
// modelUtils.ts:35
Object.keys(params).forEach((key) => {
    out[key] = !env[key] && !sameValue(params[key], defaults[key]);
});
```

当 `defaults` 中无新增 key 时：
- `defaults[key]` = `undefined`
- `sameValue(value, undefined)` = `false`（任何值与 undefined 比较都 false）
- `isDirty[key]` = `true` ✅

**无冲突，无需修改 `isDirty` 函数。**

### 3.4 保存链路兼容性验证

```python
# model_service.py:256-257
old_params = dict(ai[provider].get("model_params", {}).get(model, {}) or {})
old_params.update(dp)  # dp = {temperature: 0.7}
```

当 config.yaml 中 model 无 `model_params` 块时：
- `ai[provider].get("model_params", {})` = `{}`（不存在则返回空 dict）
- `{}.get(model, {})` = `{}`
- `old_params = {}`
- `{}.update({temperature: 0.7})` = `{temperature: 0.7}`
- `node["model_params"][model] = {temperature: 0.7}` ✅

**无冲突，后端自动处理。**

### 3.5 后端校验兼容性验证

```python
# model_service.py:252-254
for k, v in dp.items():
    if k in allowed and v not in allowed[k]:
        raise ValueError(f"不支持的配置项值: {k}={v!r}，允许{allowed[k]}")
```

当 `allowed = {}`（空 param_options）时：
- `k in allowed` = `False` → 跳过校验 ✅

**无冲突。**

### 3.6 切换模型/Provider 冲突

| 操作 | 行为 | 影响 |
|------|------|------|
| 切换模型 | `selectModel` 先调 `ensureModelSaved` 自动保存未落库参数（失败才阻止切换，BUG-D 2026-09-21），再重置 params/defaults/ranges/paramOptions | 新参数随自动保存落盘，不丢失；无需 SaveBar 提示 |
| 切换 Provider | 同上（`selectProvider` 同款 ensureModelSaved 门） | 同上 |
| 保存全部 | `saveAll` → 依次调 saveGroup | 新参数随 model 组一起保存 |

**说明（v1.1 修正）**：v1.0 写“未保存切走则丢失”已过期；现行为是切走前自动保存。新参数在切走瞬间即落盘（`PUT /models` 全量 changed 含新 key），`selectModel` 用新模型条目重置三件套，无跨模型泄漏。

### 3.7 envOverride 冲突

新添加的参数 key 不在 `envOverride` 中（envOverride 从后端 `provider.env` 构建，只包含已有参数的 env 接管标记）。

- `envOverride[key]` = `undefined` → `!undefined` = `true` → 不禁改 ✅
- 新参数始终可编辑 ✅

**无冲突。**

### 3.8 param_options 校验冲突

`setParam` 中有枚举拦截：
```typescript
const opts = state.model.paramOptions[key];
if (opts && !opts.includes(value as string)) { ... return; }
```

新添加的预定义参数（如 reasoning_effort）通过 `addParam` 注入 `paramOptions` → `setParam` 编辑时自动校验 ✅

自定义参数无 `paramOptions` → 不校验 → 自由输入 ✅

**落盘边界（v1.1 补充）**：`saveModelGroup` 只送 `default_params`，注入的 `ranges/paramOptions` 不落盘——保存后本会话内控件形态 intact（state 未清）；整页刷新后新行按后端 `param_options` 回显（无则退化为 InputNumber/Input）。如需持久化选项形态，走既有「管理选项」通道（`ParamOptionsModal` → `updateModel({param_options})` → `refreshModels`），本次不扩保存链。

**无冲突（保存链不动）。**

// 编辑历史: 2026-09-23 小欧 - 新建：模型参数区「+ 添加参数」内联表单（预定义+自定义混合）
// v1.1: 预设 5→8（加 top_p/frequency_penalty/presence_penalty，默认值对齐注册表）；确认按钮有效性门禁（禁空值/枚举必选/布尔严格）

/** 预定义参数表：从项目实际使用的模型参数中提取 */
const PARAM_PRESETS = [
  { key: 'temperature',      type: 'number' as const, default: 0.7,    range: { min: 0, max: 2 },       label: '温度 (temperature)' },
  { key: 'max_tokens',        type: 'number' as const, default: 16384,    range: { min: 1, max: 100000 },   label: '最大Token (max_tokens)' },
  { key: 'top_p',             type: 'number' as const, default: 1.0,      range: { min: 0, max: 1 },         label: '核采样 (top_p)' },
  { key: 'frequency_penalty', type: 'number' as const, default: 0,        range: { min: -2, max: 2 },        label: '频次惩罚 (frequency_penalty)' },
  { key: 'presence_penalty',  type: 'number' as const, default: 0,        range: { min: -2, max: 2 },        label: '存在惩罚 (presence_penalty)' },
  { key: 'reasoning_effort', type: 'enum' as const,   default: 'medium', options: ['low', 'medium', 'high'], label: '推理深度 (reasoning_effort)' },
  { key: 'context_limit',     type: 'number' as const, default: 262144,   range: { min: 1000, max: 900000 }, label: '上下文限制 (context_limit)' },
  { key: 'seed',             type: 'number' as const, default: null,   range: { min: 0, max: 999999 },   label: '随机种子 (seed)' },
];

interface AddParamFormProps {
  onAdd: (key: string, value: unknown, meta?: { range?: { min: number; max: number }; options?: string[] }) => void;
  onCancel: () => void;
}

const AddParamForm: React.FC<AddParamFormProps> = ({ onAdd, onCancel }) => {
  const [mode, setMode] = useState<'preset' | 'custom'>('preset');
  // v1.2 勾选清单：checked 勾选态，values 每行输入值（初始=默认值转字符串，null 填空）
  const [checked, setChecked] = useState<Record<string, boolean>>({});
  const [values, setValues] = useState<Record<string, string>>(() =>
    Object.fromEntries(PARAM_PRESETS.map((p) => [p.key, p.default !== null ? String(p.default) : '']))
  );
  const [customKey, setCustomKey] = useState('');
  const [customType, setCustomType] = useState<'string' | 'number' | 'boolean'>('number');
  const [value, setValue] = useState<string>('');

  const presetValid = (p: (typeof PARAM_PRESETS)[number], v: string): boolean => {
    if (v === '') return false;
    if (p.type === 'number') {
      const n = Number(v);
      return !isNaN(n) && n >= p.range.min && n <= p.range.max;
    }
    if (p.type === 'enum') return (p.options ?? []).includes(v);
    return true;
  };

  // v1.1 有效性门禁：勾选至少一个且所勾行全有效；自定义空值/非法禁确认（不落 null、不存空串；布尔只认 true/false）
  const canConfirm = (() => {
    if (mode === 'preset') {
      const keys = Object.keys(checked).filter((k) => checked[k]);
      if (!keys.length) return false;
      return keys.every((k) => {
        const p = PARAM_PRESETS.find((x) => x.key === k);
        return p ? presetValid(p, values[k] ?? '') : false;
      });
    }
    if (!customKey.trim()) return false;
    if (value === '') return false;
    if (customType === 'number') return !isNaN(Number(value));
    if (customType === 'boolean') return value === 'true' || value === 'false';
    return true;
  })();

  const handleAdd = () => {
    if (!canConfirm) return;
    if (mode === 'preset') {
      Object.keys(checked).filter((k) => checked[k]).forEach((k) => {
        const p = PARAM_PRESETS.find((x) => x.key === k);
        if (!p) return;
        const v: unknown = p.type === 'number' ? Number(values[k]) : values[k];
        onAdd(p.key, v, { range: p.range, options: p.options });
      });
    } else {
      // 自定义模式
      const key = customKey.trim();
      if (!key) return;
      let v: unknown = value;
      if (customType === 'number') v = Number(value);
      if (customType === 'boolean') v = value === 'true';
      onAdd(key, v);
    }
  };

  const inputStyle = { width: settingsControl.inputNumberWidth };

  return (
    <div
      style={{
        display: 'flex',
        gap: Spacing.SM,
        alignItems: 'center',
        padding: `${Spacing.SM}px ${Spacing.MD}px`,
        margin: `${Spacing.SM}px 0`,
        border: '1px dashed #d9d9d9',
        borderRadius: 4,
        background: '#fafafa',
      }}
    >
      <Radio.Group
        value={mode}
        onChange={(e) => { setMode(e.target.value); setValue(''); setCustomKey(''); }}
        size="small"
      >
        <Radio.Button value="preset">常用参数</Radio.Button>
        <Radio.Button value="custom">自定义</Radio.Button>
      </Radio.Group>

      {mode === 'preset' ? (
        <div style={{ display: 'flex', flexDirection: 'column', gap: Spacing.XS, flex: 1 }}>
          {PARAM_PRESETS.map((p) => (
            <div key={p.key} style={{ display: 'flex', gap: Spacing.SM, alignItems: 'center' }}>
              <Checkbox
                checked={!!checked[p.key]}
                onChange={(e) => setChecked((c) => ({ ...c, [p.key]: e.target.checked }))}
              />
              <span style={{ width: 280 }}>{p.label}：{p.desc}</span>
              {p.type === 'enum' ? (
                <Select
                  value={values[p.key] || undefined}
                  onChange={(v) => setValues((s) => ({ ...s, [p.key]: v }))}
                  style={{ width: 120 }}
                  options={(p.options ?? []).map((o) => ({ value: o, label: o }))}
                />
              ) : (
                <Input
                  value={values[p.key] ?? ''}
                  onChange={(e) => setValues((s) => ({ ...s, [p.key]: e.target.value }))}
                  style={inputStyle}
                />
              )}
              <span style={{ color: Colors.TEXT.SECONDARY }}>默认 {p.default !== null ? String(p.default) : '空'}</span>
            </div>
          ))}
        </div>
      ) : (
        <Input
          placeholder="参数名"
          value={customKey}
          onChange={(e) => setCustomKey(e.target.value)}
          style={{ width: 160 }}
        />
      )}


      {mode === 'custom' && (
        <>
          <Select
            value={customType}
            onChange={setCustomType}
            style={{ width: 100 }}
            options={[
              { value: 'number', label: '数字' },
              { value: 'string', label: '文本' },
              { value: 'boolean', label: '布尔' },
            ]}
          />
          <Input placeholder="值" value={value} onChange={(e) => setValue(e.target.value)} style={inputStyle} />
        </>
      )}

      <Button type="primary" size="small" onClick={handleAdd} disabled={!canConfirm}>确认</Button>
      <Button size="small" onClick={onCancel}>取消</Button>
    </div>
  );
};
