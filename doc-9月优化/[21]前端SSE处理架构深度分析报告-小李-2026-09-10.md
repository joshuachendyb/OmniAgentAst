### 3.3 暂停缓冲区原子合并（BUG10修复）

**位置**: `useChatCallbacks.ts:703-744`

**实现**:
```typescript
const errorItems: Array<string | SSEError> = [];

setMessages((prev) => {
  const lastMessage = prev[prev.length - 1];
  if (lastMessage && lastMessage.role === 'assistant' && lastMessage.isStreaming) {
    let content = lastMessage.content;
    const newSteps = [...(lastMessage.executionSteps || [])];

    displayBufferRef.current.forEach((data) => {
      const item = data as BufferItem;
      if (item.type === 'chunk' && item.content) {
        content += item.content;
      } else if (item.type === 'step' && item.step) {
        newSteps.push(item.step);
      } else if (item.type === 'error' && item.error) {
        errorItems.push(item.error);
      }
    });

    const updated = [...prev];
    updated[updated.length - 1] = {
      ...lastMessage,
      content,
      executionSteps: newSteps,
    };
    return updated;
  }
  return prev;
});

// error类型需单独处理
for (const err of errorItems) {
  onError(err);
}
```

**解决的问题**:
- 批处理乱序问题
- 缓冲区数据丢失
- 恢复时状态不一致

**评价**: ✅ **方案优秀**，原子合并避免了竞态条件

### 3.5 sessionStorage防抖（300ms）

**位置**: `useSSE.ts:484-498`

**实现**:
```typescript
const saveStepsTimerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

const saveStepsToStorage = useCallback((steps: ExecutionStep[]) => {
  if (steps.length === 0 || !config.sessionId) return;
  if (saveStepsTimerRef.current !== null) clearTimeout(saveStepsTimerRef.current);
  saveStepsTimerRef.current = setTimeout(() => {
    const storageKey = `${SSE_STORAGE_KEY}_${config.sessionId}`;
    try {
      sessionStorage.setItem(storageKey, JSON.stringify(steps));
    } catch (e) {
      console.warn('[SSE] 保存到 sessionStorage 失败:', e);
    }
    saveStepsTimerRef.current = null;
  }, 300);
}, [config.sessionId]);
```

**解决的问题**:
- N个事件→N次JSON.stringify
- N次sessionStorage.setItem
- O(N²)主线程阻塞

**评价**: ✅ **方案巧妙**，合并连续事件避免性能问题

### 3.6 重连策略（指数退避+Full Jitter）

**位置**: `useSSE.ts:338-349`

**实现**:
```typescript
const calculateReconnectDelay = (attempt, baseDelay, maxDelay) => {
  const exponentialDelay = baseDelay * Math.pow(2, attempt);
  const jitter = Math.random() * exponentialDelay;
  return Math.min(jitter, maxDelay);
};
```

**参数配置**:
- maxAttempts: 3
- baseDelay: 1000ms
- maxDelay: 10000ms

**评价**: ✅ **方案优秀**，Full Jitter避免惊群效应

## 四、架构缺陷分析（严重程度排序）

### 🔴 缺陷1：useSSE.ts过度膨胀（严重度：高）

**问题描述**:
- `useSSE.ts` 承载了**6大职责**：连接管理、重连逻辑、空闲超时、sessionStorage、轮询观察、意图标记
- 1086行代码，违反**SRP单一职责原则**

**具体表现**:
```typescript
// useSSE.ts 内混杂的职责：
```

- 修改一个功能可能影响其他功能

```typescript

function useStateWithRef<T>(initialValue: T) {

  const ref = useRef(initialValue);
  
  const setValue = useCallback((value: T) => {
    ref.current = value;
    setState(value);
  }, []);
  
  return { state, ref, setValue };
}
```

```typescript
sseParser.onError(error)
  → useSSE.handleSSEError(error) [重连判断]
  → useChatStreaming.sseOnError(error) [聚合blocked/timeout]
  → useChatCallbacks.onError(error) [后端错误分道]
```

**影响**:
- 调试困难
- 容易遗漏某个环节

**修复建议**:
```typescript
// 使用中间件模式统一错误处理：
type ErrorHandler = (error: SSEError) => void;

const createErrorMiddleware = (...handlers: ErrorHandler[]): ErrorHandler => {
  return (error: SSEError) => {
    for (const handler of handlers) {
      handler(error);
    }
  };
};

// 使用：
const errorHandler = createErrorMiddleware(
  handleSSEError,      // 重连判断
  sseOnError,          // 聚合blocked/timeout
  onError              // 后端错误分道
);
```

### 5.3 重连策略（指数退避+Full Jitter）

**当前方案**:
```typescript
// useSSE.ts:338-349
const calculateReconnectDelay = (attempt, baseDelay, maxDelay) => {
  const exponentialDelay = baseDelay * Math.pow(2, attempt);
  const jitter = Math.random() * exponentialDelay;
  return Math.min(jitter, maxDelay);
};
```

**评估**:
- ✅ **优势**: Full Jitter避免惊群效应
- ✅ **优势**: 最大重试3次，避免无限重连
- ✅ **优势**: 重连耗尽后轮询观察（方案二）

**结论**: ✅ **方案优秀**，符合最佳实践
