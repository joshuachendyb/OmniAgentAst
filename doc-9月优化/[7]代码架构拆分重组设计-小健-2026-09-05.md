## 一、目标与原则

**一句话**：先把底座打正（名实相副、层归其位），再修yield——[3]全部diff按当前切分锚定，重组后旧址失效，现在实施等于沙地盖楼。

**四原则**：①名实相副（名即职责契约）；②SRP（一文件一职责，超载即拆）；③先备份后动手（重构前原文件整份备份到备份目录，前后可diff对账）；④复制不重写（搬迁逐字复制+行为对账，见七）。

**与[5]/[3]关系**：[5]网关先行（暂停收编）；本档重组随后；[3]继续暂停，重组落地后diff按新址重写。

### 8.3 每阶段TDD五步标准流程（含备份与测试文件处理）

```
步骤①TEST(红)：先写/迁移测试指向新模块接口（import新路径），跑→必须失败（证明测试锁定新地址）
                ★测试文件仅作验证用，不进commit（AGENTS.md铁规：严令禁止commit任何测试相关代码文件）
步骤②BACKUP(备份)：动手前原文件整份拷入仓库根的前提下，先跑`git status`确认生产文件干净；
                `git stash`（如有临时改动）；确认无未提交生产修改才进入下一步
步骤③CODE(绿)：复制搬迁函数（逐字复制、只改import路径），同步改生产引用；测试引用同步改
步骤④TEST(验证)：跑全部相关测试 + 全仓回归子集 → 全绿；再对比备份diff账/行数账
步骤⑤COMMIT：只提交生产代码文件（禁含任何测试文件）；独立commit（一个阶段一个commit），
              坏即 revert 单段；备份保留至回归通过后一个版本再清
```

> **备份的落法**：与八章7章不同，本计划在步骤②用 git 原生能力做**可回滚备份**——每阶段独立commit即天然回滚位（revert 单段）；另按七章要求把原文件整份拷入`refactor_backup/20260905-<阶段名>/`供diff对账，附`md5.txt`。
> **测试文件纪律**：TDD的测试文件逐个阶段演化（红→绿→回归），**绝不进commit**；最终是否入库由北京老陈单独定（默认不进，回归靠15个现有测试文件+阶段新测试在本地跑）。
