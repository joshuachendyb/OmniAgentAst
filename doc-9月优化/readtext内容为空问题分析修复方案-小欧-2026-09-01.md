## 一、问题现象

1. 工具执行（readtext）实际**成功**读到内容：
   - `✔ 读取文件E:\task\task005.txt，成功: 9/9行，732字节`
   - `read_text_file.py` 确认有内容 → `_data["content"]` 有值、`exec_code="success"`。
2. 前端 step（实时 ToolCallLine 展开区）同时显示：
   - 标题徽标：**「读取文件成功」**
   - 正文占位：**「文件内容为空」**
3. 二者并存即矛盾：成功标志显示、内容却显示为空。

## 二、结论（一句话）

**后端确实读到了内容，但 readtext 的原始内容 `data.content` 在"后端 → step"链路中被丢弃**，前端只发到了 `tool_result[].data_text`（observation 展示文本，已包含全部文件内容）；而前端 readtext 渲染器死读 `data.content`、不读 `data_text`，于是拿到空 → 走「文件内容为空」占位。

> 北京老陈质疑成立：**信息是够的，observation 里已有全部文件内容**，不需要另造 content 字段。修法是让前端读它手上已经有的 `data_text`。

---

## 三、完整链路与根因（详细正确彻底）

> 以下行号均为本次核实时的真实代码位置。

### 3.1 后端 readtext 读到了内容（正常，非本 bug 源头）

`backend/app/tools/file/read_text_file.py:297-300`：

```
如果 raw 非空:  _data["content"] = add_line_numbers(raw, ...)   # content 有值
返回 build_success(data=_data, ...)  →  {data:{content,...}, llm_data:{...}}  exec_code="success"
```

**结论**：工具返回值里 `data.content` 完整存在。

### 3.2 后端把 content 转成「observation 展示文本」，原始 data 被丢弃（关键断点 1）

`backend/app/services/agent/handlers/action_handler.py:809-820`：

```python
tool_result.append({
    "tool_name": _tool,
    "llm_data": _llm,                     # = result["llm_data"]
    "llm_data_text": format_llm_data_text(_llm),
    "data_text": obs_text,                # 关键：这里是 observation 展示文本，不是原始 data
    "other_data": _other,
})
```

- `obs_text = build_observation_text(result, ...)` → 对 readtext 走 `_format_readtext_result`（observation_formatter.py:1345-1364），输出**人类可读多行文本**，例如：

```
── 文件内容 ── E:\task\task005.txt
第1行内容...
...
✓ 无截断-完整
```

  **不是 `{content:...}` JSON**。
- **原始 `result["data"]`（含 `content`）在构造 tool_result 时被丢弃**，只留了 `data_text`（obs_text 字符串）。

> 佐证：listdir 的 `_format_entries`（observation_formatter.py:759-791）同样输出 `name [文件]` 展示文本，非 JSON。即**所有工具的 `data_text` 都是 observation 展示文本**，readtext 不是特例。

### 3.3 ObservationStep 只发 tool_result（关键断点 2）

`backend/app/services/agent/steps/observation_step.py:27-36`：

```python
def get_content(self) -> str:
    return ""
@property
def tool_result(self): return self._tool_result
def _extra_fields(self):
    return {"tool_result": self._tool_result}   # 顶层无 data、无 execution_result、无 content
```

- 前端读 `step.execution_result?.data`（`execData`）→ **不存在**。
- 前端真正能拿到的只有 `step.tool_result[].data_text`。

### 3.4 前端只认 `JSON.parse(data_text)` 出的 content，对非 JSON 丢弃（根因）

`frontend/src/features/chat/components/ToolResultRenderer/shapeRenderers.tsx:44-59`（`extractResult`）：

```ts
let textData = {};
if (Array.isArray(step.tool_result)) {
  for (const item of step.tool_result) {
    const dt = (item as any).data_text;
    if (typeof dt === 'string') {
      try {
        const parsed = JSON.parse(dt);        // readtext 的 data_text 非 JSON → 抛错
        textData = { ...textData, ...parsed };
      } catch { /* 解析失败忽略 → readtext 内容在此被丢弃 */ }
    }
  }
}
```

- readtext 的 `data_text` 是 `── 文件内容 ──` 裸文本 → `JSON.parse` **抛错** → `catch` 忽略 → `textData = {}` → 无 `content`。
- `data = { ...textData, ...execData }`，而 `execData`（execution_result.data）也不存在 → 最终 `data` 无 `content` 键。

### 3.5 前端 readtext 渲染走空占位（现象呈现）

- `resultTypes.ts:21`：`readtext: 'code'` → 走 `CodeResultRenderer`。
- `shapeRenderers.tsx:401`：`content = (data.content as string) || ''` → **空字符串**。
- `shapeRenderers.tsx:418-428`：`if (!content)` → 显示「**文件内容为空**」；
  而 `success = (llm_data.status.exec_code === 'success')`（shapeRenderers.tsx:68）→ 真 → 标题徽标「读取文件**成功**」。

### 3.6 实时 ToolCallLine 完整还原

`ToolCallLine.tsx:136-203`（展开区构造 `singleStep.tool_result=[results[i]]` → `ToolResultRenderer` → CodeResultRenderer）：
- 折叠摘要（ToolCallLine.tsx:64-76）：读 `llm_data.summary` = `"读取文件E:\task\task005.txt，成功: 9/9行，732字节"` ✅（正是老陈看到的那句）
- 展开正体（CodeResultRenderer）：读 `data.content` → 空 → 「文件内容为空」❌
- **同屏：`singleStep.tool_result[0].data_text` 明明含全部 9 行内容，但 CodeResultRenderer 不读它。**

## 四、根因归类

| 层级 | 问题 |
|------|------|
| 直接根因 | 前端 `extractResult` 假设 `tool_result[].data_text` 可 `JSON.parse` 出 `content`，对 readtext 的非 JSON 观察文本解析失败即丢弃 |
| 深层根因 | 2026-08-27 前后端"按结果形状渲染"重构时，前端读 `data.content`，但后端从未把 readtext 的 `data.content` 放进前端可读字段（ObservationStep 只发 `data_text`=展示文本），**契约未闭合** |
| 信息完备性 | observation（`data_text`）**已含全部文件内容**；无需后端新增 content 字段（北京老陈质疑成立） |

---

## 五、影响面

- readtext 实时 step / 历史 step 展开区**全部**显示「文件内容为空」（非本次偶发）。
- 依赖 `data.content` / `data_text` JSON 解析的结构化渲染路径通用受影响。
- LLM 侧不受影响（LLM 吃 observation 文本观察内容）；纯前端展示问题。

---

## 六、修复方案（推荐：只改前端，`extractResult` 对非 JSON 的 data_text 兜底为 content）

**核心思路**：readtext 的 `data_text` 本身就是完整文件内容文本。前端 `extractResult` 在 `JSON.parse` 失败时，**把 `data_text` 原文回退为 `content`**，`CodeResultRenderer` 即可显示真实文件内容。后端零改动。

### 6.1 `frontend/src/features/chat/components/ToolResultRenderer/shapeRenderers.tsx`

修改 `extractResult`（现 shapeRenderers.tsx:44-59）：

```diff
   let textData: Record<string, unknown> = {};
   if (Array.isArray(step.tool_result)) {
     for (const item of step.tool_result) {
       if (item && typeof item === 'object') {
         const dt = (item as Record<string, unknown>).data_text;
         if (typeof dt === 'string') {
           try {
             const parsed = JSON.parse(dt) as Record<string, unknown>;
             textData = { ...textData, ...parsed };
           } catch {
-            // 解析失败忽略
+            // 2026-09-01 小欧(北京老陈驱动): 解析失败说明 data_text 是 observation 展示文本
+            // (readtext 为 "── 文件内容 ──" 完整文件内容, listdir 为条目文本, 均非 JSON)。
+            // 兜底把原文当作 content 供 CodeResultRenderer 显示, 消除"读取成功却文件内容为空"矛盾。
+            if (textData['content'] === undefined) {
+              textData['content'] = dt;
+            }
           }
         }
       }
     }
   }
```

> 说明：
> 1. 优先保留 `JSON.parse` 成功的结构化数据（`textData` 被后续条目/execData 正常合并）。
> 2. 仅当 `content` 尚未被填充时才用 `data_text` 原文兜底，避免覆盖已解析出的结构化 `content`。
> 3. 对 readtext：`data_text` 含 `── 文件内容 ──` 头 + 各行 + `✓ 无截断-完整` 尾（observation 视角文本），能完整展示 9/9 行内容，问题解决，信息完备。
> 4. **兜底必然性（决定性依据）**：readtext 的 `data_text` 由 `observation_formatter.py:1345-1364` 构造，**必以 `── 文件内容 ── {path}` 开头、以 `⚠ 已截断` / `✓ 无截断-完整` 结尾**（含中文 `──` 头行与多行正文），故**永远不可能是合法 JSON** → `JSON.parse` 必抛错 → 6.1 兜底必然稳定触发。因此不存在"文件内容恰为 JSON 导致 try 分支成功、兜底不触发"的边界遗漏。

### 6.2 可选增强（`CodeResultRenderer` 容忍带观察头的 content）

`CodeResultRenderer`（shapeRenderers.tsx:397-428）目前对 `data.content` 为空显示占位。6.1 兜底后 content 非空，不触发占位，**无需改**。若老陈希望展开区显示纯净文件内容（去掉 `── 文件内容 ──` 头尾），可另行在后端补发 `data.content`（方案 B，见 6.3），本次不改。

### 6.3 备选方案（后端补发纯净 content，本次不采用）

`action_handler.py:814-819` 给 `tool_result` 增加 `data` 字段（原样带上 `result["data"]`），前端 `extractResult` 读 `entry.data.content`。契约闭环、展示纯净文件内容；但改动后端构造 + 前端取数两处，且需处理敏感/体积。**结论：老陈质疑成立，observation 信息已够，不采用此方案，避免过度设计（YAGNI）。**
