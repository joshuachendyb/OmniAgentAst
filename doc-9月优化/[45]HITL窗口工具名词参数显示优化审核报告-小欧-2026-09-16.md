## 二、当前问题分析

### 2.1 高度不稳定（核心缺陷）

| 问题 | 说明 | 影响 |
|------|------|------|
| 参数区高度随内容伸缩 | `maxHeight:120` 仅封顶，参数少时高度收缩、参数多时被撑高 | **HITL弹窗整体高度变来变去，窗口跳动** |
| 无最高行数约束 | 参数行数随参数数量无限增长，直到撞120px上限 | 弹窗被撑高，可能超出屏幕 |

> 注：参数"每参数一行"本身的展示方式可保留（易读），缺陷在**没有固定高度上限**。定案加"固定4行高+滚动条+超长参数自动换行"，不改变每参数一行的排列方式。

### 2.2 视觉层次不够清晰

| 问题 | 说明 |
|------|------|
| 工具名称标签太弱 | `fontSize: 12` + 灰色，与参数标签视觉权重相同，工具名不突出 |
| 参数值没有高亮 | 参数key和value都是灰色，缺乏区分 |
| 双层视觉冗余 | 外层`#fafafa`灰底 与 内层`#fff`白底+`#e8e8e8`边框叠两层，视觉过重 |

### 2.3 紧凑度不足

| 项目 | 当前值 | 优化方向 |
|------|--------|----------|
| 工具名称行 marginBottom | 4px | 压缩至2px |
| 参数标签行 marginBottom | 4px | 合并到工具名称行 |
| 参数区内边距 | 6px | 压缩至4px |
| 参数区高度约束 | maxHeight 120px(伸缩) | **固定 height 72px(4行×18px)** |
| 参数行高 | 18px | 保持18px(定案行高) |
| 参数区视觉容器 | 双层(外层灰底+内层白底框) | 收敛为**单层轻量容器**(浅灰底+细边框)，视觉边界保留 |

## 三、优化方案

### 3.1 参数区定案方案（P0+P1+P1b，必做）

**北京老陈定案核心**:

| 编号 | 定案内容 | 来源 |
|------|---------|------|
| ① | **禁JSON式显示**：参数区不用JSON花括号/缩进包裹，改 `key=value` 纯文本 | v1.1定案 |
| ② | **参数区固定4行高**：高度钉死，不随参数数量伸缩 | v1.1定案 |
| ③ | **HITL弹窗整体高度固定不变**：不因参数多少变来变去 | v1.1定案 |
| Ⅰ | **每参数一行** `key=value`，超4行滚动 | v1.2拍板 |
| Ⅱ | **仅参数区恒定即可**，不硬设Modal height | v1.2拍板 |
| Ⅲ | **超长参数固定宽度内自动换行**（`wordBreak: break-all`） | v1.2拍板 |

**定案规格**:

| 项目 | 值 | 说明 |
|------|-----|------|
| 参数排列 | 每参数一行 `key=value` | `\n` 连接，禁JSON缩进 |
| 参数区高度 | 固定 4行（`height:72px`，行高18px） | 钉死不伸缩，非maxHeight |
| 滚动条 | `overflow: auto` | 超过4行出现垂直滚动条 |
| 超长参数 | 固定宽度内自动换行 | `wordBreak: break-all`，防长路径溢出 |
| 视觉区分 | 单层轻量容器：浅灰底`#fafafa`+细边框`1px #e8e8e8`+圆角4 | 参数区与正文边界清晰，去双层冗余 |
| 弹窗整体高度 | 仅参数区恒定即可 | 不硬设Modal height，弹窗自然稳定 |

**代码示意**:
```jsx
// 参数格式化：每参数一行 `key=value`，禁JSON缩进

  try {
    const p = request?.params;
    if (!p || typeof p !== 'object') return String(p ?? '');
    return Object.entries(p)
      .map(([k, v]) => `${k}=${String(v ?? '')}`)
      .join('\n');
  } catch {
    return '[参数序列化失败]';
  }
}, [request?.params]);

// 参数值区域：固定4行高 + 滚动条 + 超长自动换行 + 单层轻量视觉容器
<div style={{
  height: 72,            // 固定4行×18px，钉死不伸缩
  overflow: 'auto',      // 超出4行出现垂直滚动条
  lineHeight: '18px',
  borderRadius: 4,
  padding: '4px 6px',
  backgroundColor: '#fafafa',   // 浅灰底：视觉区分
  border: '1px solid #e8e8e8',  // 细边框：视觉区分
  marginBottom: 4,
  boxSizing: 'content-box',     // 保证内容区=72px(4行×18px)
  textAlign: 'left',            // 覆盖外层继承的textAlign:center，参数文本左对齐
}}>
  <span style={{
    fontSize: 12,
    whiteSpace: 'pre-wrap',   // 每参数一行
    wordBreak: 'break-all',   // 超长自动换行，防溢出
  }}>
    {paramsStr}
  </span>
</div>
```

## 五、注意事项

### 5.1 兼容性
- 参数区 `whiteSpace: 'pre-wrap'`：每参数一行按 `\n` 换行（定案保留）
- 参数区 `wordBreak: 'break-all'`：长参数路径在固定宽度内自动换行，不溢出、不撑高弹窗

### 5.2 可访问性
- 保持 `fontSize: 12` 最小字号，确保可读性
- 保持足够的对比度（灰色文字在浅背景上）

### 5.3 响应式
- 参数区 **固定高度**（`height: 72px` 而非 `maxHeight`），任何屏幕尺寸下高度一致
- `overflow: 'auto'` 确保参数过多时在固定区域内滚动，弹窗整体高度永不变化

## 七、北京老陈定案汇总

### 7.1 定案三条硬性要求（v1.1）

| 序号 | 定案要求 | 说明 |
|------|---------|------|
| ① | **参数区禁用JSON式显示** | json那类"东西"（花括号包裹缩进）占用空间，禁用 |
| ② | **参数区固定高度几行** | 高度钉死为固定4行，确定后即不伸缩；超出固定行数**加滚动条** |
| ③ | **HITL弹窗整体高度固定不变** | 弹窗高度不能因参数数量多少变来变去，杜绝窗口跳动 |

### 7.2 三点细化拍板（v1.2）

| 序号 | 待定点 | 拍板结论 |
|------|--------|----------|
| Ⅰ | 参数区内多个参数如何排列 | **每参数一行** `key=value`，超4行滚动 |
| Ⅱ | 弹窗整体高度固定机制 | **仅参数区恒定即可**，不硬设Modal height |
| Ⅲ | 超长参数溢出处理 | **固定宽度内自动换行**（`wordBreak: break-all`），不撑高 |

### 7.3 初始方案被定案处置（历史留痕）

| 初始方案(v1.0) | 被定案后处置 | 隶属优先级 |
|----------------|--------------|-----------|
| 3.3 参数格式 `key=value` 空格分隔(≤2参数) | 升级为**每参数一行** `\n` 连接(v1.2拍板Ⅰ) | P1 |
| 3.2 参数区 `maxHeight:100`(封顶伸缩) | 改为**固定 `height:72`**(4行×18px)，非maxHeight(v1.2拍板Ⅱ) | P0 |
| 3.1 工具名称+参数标签合并 | 保留为**建议项** 未定案 | P2 |
| 3.4 工具名称高亮 | 保留为**建议项** 未定案 | P4 |

### 7.4 参数区定案规格（最终版）

| 项目 | 定案值 |
|------|--------|
| 高度 | 固定 4行（即 `height:72px`，行高18px） |
| 滚动 | `overflow:auto`，超4行出现垂直滚动条 |
| 参数排列 | `key=value` **每参数一行**，`\n` 连接 |
| 超长参数 | 固定宽度内**自动换行**（`wordBreak: break-all`） |
| 视觉区分 | 单层轻量容器：浅灰底`#fafafa`+细边框`1px #e8e8e8`+圆角4 |
| 弹窗整体高度 | 仅参数区恒定即可，不硬设Modal height，弹窗自然稳定 |

---

**审核结论**: 当前实现功能完整，但存在核心缺陷——参数区高度随参数数量伸缩，导致HITL弹窗整体高度变来变去。北京老陈已定案三条硬性要求（禁JSON式/固定4行加滚动条/弹窗高度固定）并三点细化拍板（每参数一行/仅参数区恒定/超长自动换行），构成必做项 P0+P1+P1b，另有 P2/P3/P4 可选配套建议。
