## 一、目标

让 `opencodeZen` provider 通过 **Zen 免费无key 认证**（`Authorization: Bearer public`）直连 `https://opencode.ai/zen/v1`，做到：

1. **零付费额度、零余额消耗**：免费模型名称带 `-free` 或为 `big-pickle`，`cost=0`，key 余额不动。
2. **架构可扩展、接入模式一次定死**：以 `opencodeZen` 为首个示范，建立「**一 provider 一适配文件**」的目录适配架构——以后任何 provider 需要特殊 HTTP 握手差异，**只新增一个适配文件**，其余代码零改动。
3. **无侵入默认路径**：本次改动不触碰 `agnes` 等既有 provider 的任何行为（零 backward 兼容性干扰）。

## 二、现状剖析（证据链）

### 2.1 Zen 免费层准入校验（2026-09-23 门禁重验，旧两条件结论作废）

经桌面端 1.18.31 独立抓包全量 body 隔离重放，服务端现为**请求头 + 请求体联合校验**，四者齐备即放行（返回 200），缺一即 403 FreeTierError：

| # | 位置 | 校验项 | 要求 | 实测通过值 |
|---|------|------|------|-----------|
| 1 | 头 | `User-Agent` | 必匹配 `opencode/<语义化版本>`，且版本 ≥ 1.17.0；缺失/非法/低于 1.17.0 分别返回 403 FreeTierError 或 426 UpgradeRequired | `opencode/1.18.31 ai-sdk/provider-utils/4.0.23 runtime/bun/1.3.14` |
| 2 | 头 | `x-opencode-session` | 合法格式会话ID：`ses_` + 12位小写十六进制 + 14位 base62 字符（共 30 字符）；随机生成即可，服务端只验格式不验存在性 | 自动生成，每 `LLMClient` 实例创建时生成一次（`static_headers()` 调用一次；每次 `snapshot()` 会话切模新建客户端即换新 session，无碍） |
| 3 | 体 | `tools` | 数组必须**同时包含**名为 `bash` 的 function 与名为 `read` 的 function；只看名字，description/顺序/其余 tool 不限；空数组、只含其一、无 tools 字段均 403 | 业务 tools 原样 + 追加 bash/read 两个最小 stub（见 5.2.3） |
| 4 | 体 | `stream` | 必须为 `true`；`false` 或缺省即 403 | 发送前强制置 `true`（见 5.2.3 `ensure_gate_body`） |

不参与校验：`Authorization` 值、`x-opencode-client` / `x-opencode-project` / `x-opencode-request`（仍每请求刷新 `msg_` + 6字节时间组件hex + 14位base62随机，不校验）、`tool_choice`、system 消息内容、messages 具体内容。

### 2.3 后端 LLM 出口链路（唯一出口）

`opencodeZen` 配置从 config.yaml 进入后端后，有 **两条平行创建路径**，最终都汇聚到唯一 HTTP 出口 `LLMClient`：

```
路径一（全局/默认模型）：
config.yaml opencodeZen
  → create_service_instance (lifecycle/service.py:106) 读 api_key/api_base/timeout/max_tokens/temperature/seed/top_p/frequency_penalty/presence_penalty/model_params
  → BaseAIService.__init__ (base_service.py:106)
  → _ensure_client (base_service.py:168) → create_llm_client (client_sdk.py:337)
  → LLMClient.__init__ (client_sdk.py:139)
  → httpx.AsyncClient(headers={"Authorization": f"Bearer {api_key}"})   ← client_sdk.py:171 ONLY这个头!

路径二（L2 会话级切模，独立客户端快照）：
resolve_session_client (resolver.py:154) 按 _ov.provider 从 config 查配置
  → ai_service.snapshot() (base_service.py:185-219) 构造独立 BaseAIService 副本
  → _ensure_client → create_llm_client → LLMClient  → httpx.AsyncClient(headers=...)
  → 注: 同 provider 快照复用全局 shared_client(resolver.py:210-213), 跨 provider 则 shared_client=None 新建
```

### 2.4 关键结论

1. **缺口**：`client_sdk.py` 只发 `Authorization`，没有 UA/session，没有 body 门禁保障，且端点写死 `/chat/completions` → 匿名请求必死于 `403 FreeTierError`，muse 模型无路可达（实测证实）。
2. **校验层零阻碍**：`validation.py:49-53`（api_key 非空）+ `services/model/config_helpers.py:254-255`（api_key 字段存在）——配置填 `api_key: public` 即全部通过，**validation 无需改动**。
3. **需要扩展三个层面的 HTTP 行为**：
   - **静态头**（UA / session / x-opencode-client / x-opencode-project）：客户端创建时合并进 httpx `headers`，全连接生命周期固定。
   - **动态头**（x-opencode-request 每请求新 id）：走 `LLMClient.request()` / `request_stream()` 的 per-request `headers=` 参数（httpx 的 post/stream 均支持传 headers，自动与客户端默认头合并）。
   - **请求体门禁**（tools 含 bash 与 read + stream:true）：发送前调适配层 `ensure_gate_body(body)` 补齐；zen 的 `request()` 非流式语义改走流式收集（见 5.3）。
   - **端点路由**（muse 走 responses 端点）：发送前按模型名调适配层 `endpoint_for(model)` 选路（muse 返回相对路径 `/responses`，与 base_url `.../zen/v1` 拼成 `/zen/v1/responses`；chat 返回 `/chat/completions`），chat 与 responses 用各自 body 格式。

| 6 | 错误分类 | `error_classifier.py:100-109` | 全局黑名单：403 一律 CLIENT 不可重试 | 403 不可重试是**普适语义**，全局正确；zen FreeTierError 只是消息可更友好 | 主体否（保持全局）；**错误消息映射为增强项**(已实现, 见 5.2.3) |

**统一/分散结论（三思三省）**：
- **统一进适配层**：真正 provider 独有、且发生在 **HTTP 接缝层**的握手差异——① 头/认证 ② 端点路由（chat/responses 按模型分路） ⑥ 错误消息映射(可选)，以及门禁 body 保障（tools 补 stub + stream 强制：网关只验名字与开关的准入探测，非业务语义）。
- **必须保持全局、绝不 provider 化**：③ schema、④ reasoning、⑤ 工具别名——前两者是通用正确性，⑤ 是安全正确性（provider 化会开安检漏洞）。
- **请求参数名差异（北京老陈核查 2026-09-17）**：不属适配层。chat 端点统一 OpenAI 兼容格式 + 服务端对未知参数静默 + config `model_params` 按模型粒度配特有参数（见 5.0），已天然覆盖；思考层参数（reasoning_effort 等）是**模型粒度**差异，落在 config，与 provider 无关。responses 端点用其自有 body 格式（input + flat tools），由端点路由连带确定，不另设映射层。
- **判据口诀**：*只按 provider 分道 HTTP 握手（含网关门禁探测与端点路由）；业务内容链(请求体语义/响应解析)与工具链(别名/安检)一律全局。*

## 三、设计原则（遵守 AGENTS.md 铁规 + 10 大规范）

|------|---------|
| KISS-DIRECT | 适配层三文件小目录：base(通用默认) + opencodeZen(定制) + __init__(查询)；client_sdk 只调统一接口 `static_headers()/per_request_headers()/ensure_gate_body()/endpoint_for()/force_stream()/to_responses_body()`，不感知 zen 细节 |

## 五、详细设计

### 5.0 请求/响应载荷差异处置机制（核查定案——北京老陈 2026-09-17）

> **现状事实（北京老陈确认，2026-09-23 修订）**：chat 端点请求走**统一 OpenAI 兼容格式**（`client_sdk.py` `_build_request_body`）；provider/模型特有参数唯一走 `extra_body` 通道（config `model_params` 合并，含 `enable_thinking:True` 兜底）；**多余参数对不识别的模型服务端静默忽略**。responses 端点（muse 免费）用自有格式（`input` + flat tools，见 2.2）。响应 chat 端统一读 `choices/message/delta`，思考字段差异已由 `reasoning.py` 三字段链全局兼容；responses 端点 SSE event 形态差异待 E2E 实测验证（见八章 B26）。

**定案结论**：
1. **不引入任何参数名映射层**（YAGNI 充分成立）：chat 端统一格式 + 服务端静默 + config 按模型粒度配 `model_params` 已覆盖全部参数名差异。
2. **思考层次参数差异本质是模型粒度**（同 provider 不同模型也不同）——落在 config `model_params` 粒度，与 provider 适配层无关，**不进适配层**。
3. **门禁 body 是网关准入探测，不属业务参数差异**：tools 只验 bash/read 名字、stream 只验开关，与业务语义无关，故由适配层 `ensure_gate_body` 统一保障（见 5.2.3），不污染业务参数通道。
4. **例外预案**：若未来某 provider 服务端**不静默**（严格拒绝未知参数），再临时评估——按 YAGNI 当前不建空壳，真实案例出现时再议。

import time
from typing import Dict, List

# ---- ID 生成器：格式级兼容 opencode/packages/schema/src/identifier.ts ----
# 参考文件: F:\agenttool\opencode-1.18.31\packages\schema\src\identifier.ts
#          F:\agenttool\opencode-1.18.31\packages\schema\src\session-id.ts
#          F:\agenttool\opencode-1.18.31\packages\schema\src\v1\session.ts (MessageID)
# 原始逻辑: 时间戳(ms) << 12 + counter, descending 用按位取反, ascending 不取反
# TS 的 ascending()/descending() 共享模块级 counter — 结构对齐
# 前12字符=时间组件(hex)，后14字符=加密安全随机(base62)
# 兼容性声明: 服务端只校验格式(ses_/msg_+12hex+14base62), 不解析数值语义,
#   故本实现保证格式级兼容; Python `~` 为无限精度整数、TS `~` 为 32 位语义,
#   大数下数值位必然分叉 — 属可接受差异(YAGNI)。 — 小欧 2026-09-23

_CHARS = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"


class _IdentifierGenerator:
    """有状态 ID 生成器，与 TypeScript identifier.ts 共享 counter 语义对齐 — 小欧 2026-09-23"""

    def __init__(self):
        self._last_timestamp = 0
        self._counter = 0

    def generate(self, prefix: str, descending: bool) -> str:
        now_ms = int(time.time() * 1000)
        if now_ms != self._last_timestamp:
            self._last_timestamp = now_ms
            self._counter = 0
        self._counter += 1

        current = now_ms * 4096 + self._counter
        value = ~current if descending else current

        time_hex = "".join(
            format((value >> (40 - 8 * i)) & 0xFF, "02x")
            for i in range(6)
        )

        rand_bytes = os.urandom(14)
        rand_part = "".join(_CHARS[b % 62] for b in rand_bytes)

        return prefix + time_hex + rand_part


# 模块级单实例: ses_/msg_ 共享同一计数器(与 TS identifier.ts 行为一致) — 小欧 2026-09-23
_gen_id = _IdentifierGenerator()


def _gen_session_id() -> str:
    """生成 session ID: ses_ + 12位hex + 14位base62，客户端生命周期内固定复用 — 小欧 2026-09-23"""
    return _gen_id.generate("ses_", descending=True)   # 与 session-id.ts 的 descending() 对齐


def _gen_request_id() -> str:

    """opencodeZen 适配: zen_free 匿名免费层 — 小欧 2026-09-23"""

    @staticmethod
    def static_headers(api_key: str) -> Dict[str, str]:
        headers = {"Authorization": f"Bearer {api_key}"}
        headers.update({
            "User-Agent": _ZEN_USER_AGENT,

        })

    @staticmethod
    def per_request_headers() -> Dict[str, str]:
        return {"x-opencode-request": _gen_request_id()}   # 每请求刷新(不参与校验)

    @staticmethod
    def ensure_gate_body(body: Dict) -> Dict:
        tools = body.get("tools") or []
        names = {t.get("function", {}).get("name")
                 for t in tools if isinstance(t, dict)}
        missing = [s for s in GATE_STUBS
                   if s["function"]["name"] not in names]
        if missing:
            body = dict(body)
            body["tools"] = list(tools) + missing
        if body.get("stream") is not True:
            body = dict(body)
            body["stream"] = True
        return body

    @staticmethod
    def endpoint_for(model: str) -> str:

        # chat 默认 rel=/chat/completions → zen/v1/chat/completions ✓

        if (model or "").startswith("muse-"):

                             "parameters": fn.get("parameters", {})})

#### 5.2.5 扩展规则与接入三步骤

**扩展规则（一 provider 一文件）**：
- 新 provider 需特殊 HTTP 握手 → `adapters/` 新建 `{provider}.py`（继承 base 覆写 static_headers/per_request_headers/ensure_gate_body/endpoint_for/force_stream/to_responses_body/error_message_map）+ `__init__.py` `_ADAPTERS` 加一行 `"{provider}": {Xxx}Adapter()`。
- 完全无特殊握手的 provider（agnes/openai/deepseek 等）→ 不建文件，自动走默认基类（==现状），**零文件零逻辑**。

**接入三步骤（新 provider 按此操作）**：
1. **判定**：差异是否属于 HTTP 接缝握手（含网关门禁探测与端点路由）？→ 是→进适配层；否（业务请求体语义/响应解析/工具别名/安检）→ 保持全局不动。

3. **注册**：`adapters/__init__.py` 的 `_ADAPTERS` 加一行 `"{provider}": {Xxx}Adapter()`。

| 场景 | 做法 | 改动面 |
|------|------|--------|
| 新 provider 要自定义头（如某网关要求 x-api-key） | adapters/ 加文件 + __init__ 注册 | 2 处（新增文件+1行注册），既有代码零改动 |

             "function": {"name": acc["name"], "arguments": acc["arguments"]}}
            for _, acc in sorted(tool_acc.items()) if acc.get("name")
        ]
        message: Dict[str, Any] = {"content": content}
        if reasoning:
            message["reasoning_content"] = reasoning
        if tool_calls_list:
            message["tool_calls"] = tool_calls_list
        if finish_reason is None:
            finish_reason = "tool_calls" if tool_calls_list else "stop"
        return {"choices": [{"index": 0, "message": message, "finish_reason": finish_reason}]}
```

> **说明（`_request_via_stream_collect`）**：
> - **返回形态与 `request()` 完全同构**：`base_service.request()` 只消费 `choices[0].message.{content,tool_calls,reasoning*}` 与 `extract_reasoning_from_message`，收集路径按此形态组装，服务层/装配层零感知。
> - **软配额不双计**：收集路径在 `request()` 入口提前 return，不进 `request()` 自身的信号量段；信号量由内部 `request_stream()` 自己 acquire/release。
> - **错误路径复用**：`request_stream()` 的 `>=400` 分支已含 `_raise_http_error` 的 error map，403/426 友好文案在收集路径同样生效。
> - **reasoning 复用全局**：调 `extract_reasoning_from_chunk`（2.5 #4 全局层），不复制三字段链逻辑（DRY）；`ling-free` 纯 reasoning 输出在收集路径归入 `message.reasoning_content`，由 `extract_reasoning_from_message` 正常取出。
> - **`_wrap_text_response` 不需要**：直接在方法内组装完整 `choices/message` 结构，少一层透传（KISS-DIRECT）。

from typing import Dict, Optional, Set


def _first_output_text(content) -> Optional[str]:
    """message.content 兼容 str(整体文本)/list(output_text 块), 取首段文本 — 小欧 2026-09-24
    已查 FUNCTIONS.md 无同能公用函数(text_utils 仅 XML 提取), 复用优先合规。"""
    if isinstance(content, str):
        return content or None
    for cp in content or []:
        if isinstance(cp, dict) and cp.get("type") == "output_text" and cp.get("text"):
            return cp["text"]
    return None


def _tool_meta(name, call_id, item_id, arguments, *, full=False, is_new=False) -> Dict:
    """工具归一元数据 dict 统一构造 — 小欧 2026-09-24
    id 恒取 call_id(仅 added/item.done 帧携带, 权威); item_id 供折叠层做稳定 index 分配, 不作 id 兜底
    (已回滚 item_id 兜底: 会让 done 帧覆盖建档帧的权威 call_id, C15/C17/C20 回归实证)。"""
    m = {"name": name or "", "id": call_id, "item_id": item_id,
         "arguments": arguments or "", "full": full}
    if is_new:
        m["is_new"] = True
    return m


def _chat_frame(delta: Dict, *, finish_reason: Optional[str] = None,
                usage: Optional[Dict] = None) -> str:
    """chat 形 SSE 行(choices[0].delta + 可选 finish_reason/usage) — 小欧 2026-09-24
    函数化(DRY+SLAP: 主循环所有落地统一, 4 处 json.dumps 收敛为单点)。"""
    frame = {"choices": [{"index": 0, "delta": delta}]}
    if finish_reason is not None:
        frame["choices"][0]["finish_reason"] = finish_reason
    if usage:
        frame["usage"] = usage
    return json.dumps(frame, ensure_ascii=False)


class _DeltaFoldState:
    """responses 流 chat delta 折叠状态(文本增量标记/工具建档表/参数增量去重集) — 小欧 2026-09-24
    函数化(主循环瘦身): 集中承载逐帧 emit 的去重状态, 供 _fold_emit_delta 单点读写。"""

    __slots__ = ("saw_text_delta", "tool_idx", "saw_tool_args_idx")

    def __init__(self):
        self.saw_text_delta = False             # 已 emit 过文本增量(delta): 其后整段文本快照丢弃防重复
        self.tool_idx: Dict[str, int] = {}      # 工具 item_id→稳定 index(并行工具不串槽)
        self.saw_tool_args_idx: Set[int] = set()  # 已 emit 参数增量的 index 集(按工具分开, 防误弃其余工具快照)


def _norm_responses_delta(data: Dict) -> Dict:
    """responses 端点事件 → 归一片段(实测事件形态收敛) — 小欧 2026-09-24
    实测(2026-09-24 muse-spark-1.3 真实 SSE): 文本增量事件 output_text.delta;
    done/content_part.done/output_item.done 为整段快照, 若也提取
    同一文本会拼 4 次(重复 bug)——故快照标记为 content_full(保底源, 由消费侧
    仅在"全程无增量"时当唯一来源, 支持只发整段快照的 provider；有增量则丢弃防重复)。
    推理增量: reasoning_summary_text.delta(唯一实证事件名) → {"reasoning"};
    tool 片段带 item_id(流唯一标识)与 is_new(建档标记), 供消费侧按工具分配稳定 index(并行不串槽);
    message 快照兼容 content 为 str(整体文本)与 list(output_text 块)两种形态。
    工具链: output_item.added{function_call} 建档 + function_call_arguments.delta 增量 +
    function_call_arguments.done/output_item.done 整段覆盖(full=True)。completed 事件(终帧信令:
    文本快照+finish_reason 推断+usage)由消费侧 _responses_completed_eval 单遍处理, 不经本函数。"""
    et = data.get("type")
    if et == "response.output_text.delta":
        d = data.get("delta")
        return {"content": d} if d else {}
    if et == "response.reasoning_summary_text.delta":   # 唯一实证推理增量事件名 — 小欧 2026-09-24
        d = data.get("delta")
        return {"reasoning": d} if d else {}
    # 文本整段快照保底识别(仅流全程无 delta 增量时由消费侧作唯一来源) — 小欧 2026-09-24
    if et == "response.output_text.done":
        t = data.get("text")
        return {"content_full": t} if t else {}
    if et == "response.content_part.done":
        part = data.get("part") or {}
        if part.get("type") == "output_text":
            t = part.get("text")
            return {"content_full": t} if t else {}
    if et == "response.output_item.added":
        item = data.get("item") or {}
        if item.get("type") == "function_call":
            return {"tool": _tool_meta(item.get("name") or "", item.get("call_id"),
                                       item.get("id") or item.get("call_id"), "", is_new=True)}
    if et == "response.function_call_arguments.delta":
        d = data.get("delta")
        return {"tool": {"arguments": d, "item_id": data.get("item_id"),
                         "full": False}} if d else {}
    if et == "response.function_call_arguments.done":
        return {"tool": _tool_meta(data.get("name") or "", None, data.get("item_id"),
                                   data.get("arguments") or "", full=True)} \
            if data.get("arguments") else {}
    if et == "response.output_item.done":
        item = data.get("item") or {}
        if item.get("type") == "function_call":
            return {"tool": _tool_meta(item.get("name") or "", item.get("call_id"),
                                       item.get("id") or item.get("call_id"),
                                       item.get("arguments") or "", full=True)}
        if item.get("type") == "message":   # 文本快照保底; 兼容 str/list content — 小欧 2026-09-24
            t = _first_output_text(item.get("content"))
            return {"content_full": t} if t else {}
    return {}


def _tool_delta_frame(idx: int, tool: Dict, with_args: bool) -> Dict:
    """chat 形 tool_calls delta 帧(携带稳定 index) — 小欧 2026-09-24
    with_args=False 用于建档帧: 只带 id/name, 参数一律由增量/快照帧供(防 provider added 携全参数 → 与增量重复拼接)。
    id 恒取 call_id(仅 added/item.done 帧携带), 不用 item_id 兜底——
    一旦"满 id 兜底"会让 done 帧携带 item_id, 累加器用后帧覆盖已建档的权威 call_id(C15/C17/C20 回归实证);
    真实 responses 协议恒先 output_item.added(从建档帧), 纯 args.delta/done 无 call_id 属假想边界不作处理。"""
    fn = {}
    if tool.get("name"):
        fn["name"] = tool["name"]
    if with_args and tool.get("arguments"):
        fn["arguments"] = tool["arguments"]
    tc = {"index": idx}
    if tool.get("id"):
        tc["id"] = tool["id"]
    tc["function"] = fn
    return tc


def _responses_completed_eval(ev: Dict) -> tuple:
    """response.completed → (文本快照, meta(finish_reason/usage)) 单遍扫描 output — 小欧 2026-09-24
    函数化(DRY: 原 _norm completed 分支与 completed meta 对同一 output 遍历两遍 → 收敛单遍):
    responses 无 stop_reason 字段(实测): 出现 function_call → tool_calls, incomplete_details 非空 → length,
    否则 stop; 同时顺路提取 message 文本快照(content_full, 兼容 str/list); usage 取 response.usage(实证位置)。"""
    resp = ev.get("response") or {}
    content_full = None
    fr = "stop"
    if resp.get("incomplete_details"):
        fr = "length"
    else:
        for oi in resp.get("output") or []:
            if not isinstance(oi, dict):
                continue
            if oi.get("type") == "function_call":
                fr = "tool_calls"
            elif oi.get("type") == "message" and content_full is None:
                content_full = _first_output_text(oi.get("content"))
    usage = resp.get("usage")
    meta: Dict = {"finish_reason": fr}
    if usage:
        meta["usage"] = usage
    return content_full, meta


def _fold_emit_delta(norm: Dict, st: _DeltaFoldState) -> Optional[Dict]:
    """归一片段 → 待 emit 的 chat delta(None=本帧丢弃) — 小欧 2026-09-24
    函数化(主循环瘦身): 文本增量→快照保底→推理增量→工具(建档/增量/整段按 index 去重)的
    emit 决策与状态读写收敛为单点, 主循环只剩"解析+落底 _chat_frame"两行。"""
    if norm.get("content"):
        st.saw_text_delta = True
        return {"content": norm["content"]}
    if norm.get("content_full"):
        # 整段文本快照保底: 全程无文本增量才作唯一来源(有增量→丢弃防重复)
        return {"content": norm["content_full"]} if not st.saw_text_delta else None
    if norm.get("reasoning"):
        # reasoning 增量: 独立通道, 与正文 content 互不干扰, 消费侧走 is_reasoning
        return {"reasoning_content": norm["reasoning"]}
    tool = norm.get("tool")
    if not tool:
        return None
    _tid = tool.get("item_id") or tool.get("id") or ""
    if tool.get("is_new"):
        # 建档帧: 按 item_id 分配稳定 index, 仅带 id/name; 无 item_id → 落 0 不占槽不登记(状态一致) — 小欧 2026-09-24
        idx = len(st.tool_idx) if _tid else 0
        if _tid:
            st.tool_idx[_tid] = idx
        return {"tool_calls": [_tool_delta_frame(idx, tool, with_args=False)]}
    idx = st.tool_idx.get(_tid, 0) if _tid else 0
    if tool.get("full"):
        # 整段参数快照: 该 index 未 emit 过参数增量→保底 emit 完整参数; 已单向过→丢弃防重复
        if idx in st.saw_tool_args_idx:
            return None
        st.saw_tool_args_idx.add(idx)
        return {"tool_calls": [_tool_delta_frame(idx, tool, with_args=True)]}
    _has_args = bool(tool.get("arguments"))   # 单取防双判 — 小欧 2026-09-24
    if _has_args:
        st.saw_tool_args_idx.add(idx)
    return {"tool_calls": [_tool_delta_frame(idx, tool, with_args=_has_args)]}
```

#### 5.3.6 /responses 事件归一行为（当前）

**消费链（当前）**：
- **流式主路径**：`BaseAIService.request_stream` → `LLMClient.request_stream` →（`_is_responses`）逐帧归一为 chat 形 `choices[0].delta` 行 yield → `BaseAIService` 既有 chat 四解析链（`_parse_sse_data`/`_extract_tool_calls`/`_extract_usage`/`_extract_finish_reason`）一字不改读通（base_service 层零改动）。
- **非流式路径**：`request()` → `force_stream` → `_request_via_stream_collect` → 消费已归一的 chat 形行（纯 chat 消费，无协议分支）。
- **协议判定**：`_adapt_request` 内 `_endpoint.endswith("/responses")` 单点（请求侧 body 转换与主循环分派共用）。

**实测事件形态与归一规则**（2026-09-24 muse-spark-1.3-contributor-free 真实 SSE，HTTP 200 完整事件链）：

| 事件 type | 实测载荷 | 归一结果 | 消费规则 |
|-----------|---------|---------|---------|
| `response.output_text.delta` | `{delta: "文本增量"}` | `{"content": delta}` | **唯一文本产出来源**：增量事件，emit 并置 `saw_text_delta` |
| `response.reasoning_summary_text.delta` | `{delta: "推理增量"}` | `{"reasoning": delta}` | 独立通道 → `reasoning_content`，与正文互不干扰 |
| `response.output_item.added` | `{item: {type:"function_call", name:"bash", call_id:"call_…", arguments:""}}` | `{"tool": {name, id:call_id, item_id, is_new, arguments:"", full:False}}` | 工具**建档**：按 `item_id` 分配稳定 index，仅带 id/name |
| `response.function_call_arguments.delta` | `{item_id, delta: "参数增量"}` | `{"tool": {arguments: delta, item_id, full:False}}` | 参数**增量**，按 index 拼发并登记 `saw_tool_args_idx` |
| `response.function_call_arguments.done` | `{arguments: "完整参数", name:"bash", item_id}` | `{"tool": {name, item_id, arguments, full:True}}` | 参数**整段快照**：该 index 未发过参数增量→保底 emit，否则丢弃 |
| `response.output_item.done{function_call}` | `{item: {type:"function_call", name, call_id, arguments:"完整"}}` | `{"tool": {name, id:call_id, item_id, arguments, full:True}}` | 工具**最终快照**：同上保底规则 |
| `response.output_item.done{message}` | `{item: {type:"message", content:[…output_text…]}}` | `{"content_full": t}`（str/list 兼容） | 文本**整段快照**：仅全程无增量时作保底唯一来源 |
| `response.output_text.done` | 载荷含**整段文本快照** | `{"content_full": t}` | 同上（同一答复文本在 done/content_part.done/output_item.done/completed 共出现 4 次大快照，若照收会拼 4 次 → 仅无增量时取一次） |
| `response.content_part.done`（`part.type=="output_text"`） | 整段文本快照 | `{"content_full": t}` | 同上 |
| `response.completed` | **无 `stop_reason` 字段**（实测）；`response.output[*]` 含 message/function_call；`response.usage` | 单遍 `_responses_completed_eval` → `(content_full, meta)` | 有文本且全程无增量→补 emit 快照帧；恒 emit 终帧：`finish_reason` 推断（function_call→`tool_calls`、`incomplete_details` 非空→`length`、否则 `stop`）+ `usage` |
| `response.created` / `response.in_progress` / `ping` | 无产出载荷 | `{}` | 丢弃（状态/保活事件） |

**emit 决策（`_fold_emit_delta` 单点）**：
- **文本防重复**：增量优先 emit；`content_full` 整段快照仅 `saw_text_delta=False`（全程无对应增量）时作保底唯一来源 emit——兼容"只发整段快照不发增量"的 provider（防重复 + 保底两全）。
- **工具按 index 去重**：建档帧（`is_new`）按 `item_id` 分配稳定 index（并行工具不串槽），只带 id/name 不带参数；参数增量按 index 拼发；`full=True` 整段参数快照在该 index 未发过参数时保底 emit、否则丢弃。**前提**：responses 单工具参数流为顺序单流（added→delta*→done）。
- **reasoning**：独立通道 `reasoning_content`，与正文互不干扰。
- **非 JSON 行**：原样透传（#7 防内容丢失）。

**测试**（test_client_sdk_adapter.py：C15 工具链收集、C16 文本不重复、C17 流式主路径 chat 形帧、C18 只发快照保底；详见七章 Step2 / 八章验收）。
