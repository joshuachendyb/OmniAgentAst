## 一、缺什么常用参数

> 编写人：小欧 2026-09-22 22:19:22

### 1.1 现状请求体实际拼入的字段

后端 LLM 请求体构建唯一入口 `_build_request_body`（`backend/app/llm/client_sdk.py:51-89`）当前只拼：

| 字段 | 来源 |
|------|------|
| model / messages | 固定 |
| max_tokens | `provider_config.max_tokens` |
| temperature | `provider_config.temperature`（默认 0.7） |
| seed | `provider_config.seed`（可 None） |
| stream / stream_options | 流式开关 + tuning.llm.stream_options |
| tools / tool_choice / parallel_tool_calls | 工具调用 |
| extra_body | `model_params.{model}` 余量透传（服务层第二通道，绕过校验） |
| context_limit | ❌ 无请求体字段（**窗口基准，非 OpenAI 字段**）；`model_params.{model}.context_limit` 逐模型配置，未配置时兜底 `DEFAULT_CONTEXT_LIMIT=262144`(256K，`compaction_constants.py:41`) |

### 1.2 缺失的常用采样参数清单

| 参数 | OpenAI 兼容字段名 | 值域 | 是否在注册表中 | 当前能否传到请求体 |
|------|------------------|------|:---:|------|
| top_p | `top_p` | 0~1（默认 1） | ❌ | ⚠️ 仅能躲进 extra_body 手写 config.yaml |
| frequency_penalty | `frequency_penalty` | -2~2（默认 0） | ❌ | ⚠️ 同上 |
| presence_penalty | `presence_penalty` | -2~2（默认 0） | ❌ | ⚠️ 同上 |
| stop | `stop` | 字符串/数组 | ❌ | ❌ 完全不可达 |
| top_k | `top_k`（**非 OpenAI 标准**） | 1+ | ❌ | ⚠️ 部分国内厂商（如 minimax）支持 |
| n / logit_bias / user / response_format | — | — | ❌ | ❌（评估不建议加，见第三章 3.4） |

结论：**系统当前对"除 temperature/seed 外的采样控制"零正式支持**（temperature 挂在 tuning 调优组，语义错位），全靠 extra_body 透传逃生门（无类型校验、无 UI、有 400 风险）。这就是本文档要补的缺口。

> 关联项：上下文窗口兜底 262144(256K) 已核实，见第三章 3.5（北京老陈要求该值在 config.yaml 体现）。

## 二、有什么价值、什么场景有用、哪些国内模型支持

> 编写人：小欧 2026-09-22 22:19:22

### 2.1 各参数的价值与适用场景

| 参数 | 价值 | 典型场景（本系统视角） |
|------|------|------------------------|
| **top_p**（0~1） | 核采样：只从累计概率达标的最小候选集合里采样，等效"裁剪长尾噪声词" | ①**工具选择**：FC 模式下把 top_p 降到 0.8~0.9，减少模型在"多个可用工具"之间摇摆、误选伪工具名；②**代码/JSON 输出**：调低 top_p 提升结构化输出稳定性；③与 temperature 二选一（见 2.3） |
| **frequency_penalty**（-2~2） | 按"词/符号出现的频次"惩罚重复 | ①**Agent 长任务**：模型反复调用同一工具、反复输出同一路径/同一段代码——此项直接压制工具调用层面的重复；②结果汇总重复内容被有效降低 |
| **presence_penalty**（-2~2） | 按"是否出现过"惩罚（讨论过的话题整体降权） | ①长链推理中模型**绕圈子复述旧结论**；②多轮对话中换话题时甩不掉旧主题的粘性 |
| stop | 停止序列 | 输出到固定边界即止（如 JSON 收尾、表格结尾），需维护边界串列表，收益场景窄（本期不做，二期备选） |
| top_k | 截取概率最高的 K 个候选 | 仅对支持该非标字段的厂商有意义（如 minimax）；**OpenAI 兼容主流接口会 400 拒绝**（见 3.4 结论） |

### 2.2 哪些国内模型支持（按本项目实际配置的 provider 域）

本项目当前真实配置 5 个 provider（`config/config.yaml` ai 区，均走 OpenAI 兼容 /v1 接口）：**sensenova（商汤）、qiniu（七牛聚合：deepseek/glm/kimi/minimax）、zhipuai（智谱 GLM）、agnes、opencodeZen**。

| 参数 | DeepSeek 系 | 智谱 GLM 系 | Moonshot Kimi 系 | MiniMax 系 | 商汤 sense 系 | agnes / opencodeZen（聚合/桥接） |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| temperature | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| top_p | ✅ | ✅ | ✅ | ✅（另有 top_k） | ✅ | 🔶 按上游透传 |
| frequency_penalty | ✅ | 🔶 部分版本 | ✅ | ✅ | 🔶 需实测 | 🔶 按上游透传 |
| presence_penalty | ✅ | 🔶 部分版本 | ✅ | ✅ | 🔶 需实测 | 🔶 按上游透传 |
| seed | ✅ | 🔶 部分 | ✅ | ✅ | 🔶 需实测 | 🔶 按上游透传 |
| stop | ✅ | ✅ | ✅ | ✅ | 🔶 需实测 | 🔶 按上游透传 |

> **说明（诚信标注，不得夸大）**：
> 1. ✅ 表示各家官方 OpenAI 兼容文档明确支持；🔶 表示"厂商文档未明示/版本间不一致"，**必须按本系统一贯做法对目标 provider 发真实请求验证字段合法性**（同 [62] BY-08 对 reasoning_effort 的做法），不能仅凭推测上线。
> 2. **top_k 是特例**：DeepSeek/GLM/Kimi 的 OpenAI 兼容端点均**不认 top_k**（会 400），仅 MiniMax 型厂商接受 → 论证结论为"不做通用 top_k"（见 3.4）。
> 3. 所有 provider 最终都汇聚到本系统 `_build_request_body` 这一个拼体入口，参数是否生效取决于"拼进去了 + 对端认这个字段"两者同时满足。
> 4. temperature / top_p / frequency_penalty / presence_penalty / max_tokens 均为**模型无关**的采样/输出控制，已定案整类迁入顶层域 `llm.sampling`，归属"设置 → 通用"（见 3.2/3.3）。

### 2.3 temperature 与 top_p 的互斥提醒

OpenAI 官方建议：**temperature 与 top_p 不同时使用**（两者都作用于采样分布，同时改会产生叠加且互相掩盖）。落地时 UI 应给提示（如：修改 top_p 时提示"建议与 temperature 二选一为主控"），后端不做强制互斥（多做反而限制自由度，语义留给用户）。

## 三、可否设置为与模型无关的通用参数

> 编写人：小欧 2026-09-22 22:19:22

### 3.1 直接结论

**top_p / frequency_penalty / presence_penalty 可以，而且应当做成"模型无关的全局通用参数"。**

理由（OpenAI 兼容体系的事实）：
- 这三个字段在 OpenAI 兼容巨头（DeepSeek/GLM/Kimi/MiniMax）里是**同名同义同值域**的公共语言，不随模型变；
- 它们的语义（采样分布裁剪/重复惩罚）是"模型属性无关"的，不像 `context_limit`（受模型窗口硬约束）必须逐模型配置；
- 系统已有全局参数先例佐证：`tuning.llm.*` 的温度/单次 token 本就是跨模型全局生效（本次顺带整类迁出）；`client_sdk.py:172` 早已预留 `llm.provider_urls` 顶层命名（`llm` 域有先例，本次落地）。

### 3.2 落点：新增 config.yaml 顶层 `llm.sampling`（UI=设置→通用，模型无关）

北京老陈 2026-09-22 拍板：采样参数**不进"调优"组**，整类迁入新增顶层域 `llm.sampling`，UI 归"设置 → 通用"。完整配置文件落盘见 **3.6 集中落盘**。

| 键 | 类型 | 默认值 | 值域 | 来源 | 说明 |
|------|------|--------|------|------|------|
| `llm.sampling.temperature` | float | 0.7 | 0~2 | tuning.llm 迁入 | LLM 采样温度 |
| `llm.sampling.max_tokens` | int | 16384 | 1~100000 | tuning.llm 迁入 | 单次最大输出 token |
| `llm.sampling.top_p` | float | 1.0 | 0~1 | 新增 | 核采样阈值，1.0=不启用 |
| `llm.sampling.frequency_penalty` | float | 0 | -2~2 | 新增 | 频次重复惩罚 |
| `llm.sampling.presence_penalty` | float | 0 | -2~2 | 新增 | 话题重复惩罚 |

默认值语义："0/1.0" 即无损旁路 → **不设置的用户行为与现状逐字节一致**。
迁移：`tuning.llm.temperature` / `tuning.llm.max_tokens` 走 `OLD_KEY_MAP` 平滑迁入（旧 yaml 值带入、不留新旧双源，禁 backward）。

### 3.3 与"调优组 / 模型级参数"的关系辨析（三分法不冲突）

| 类 | 配置域 | UI | 参数 | 模型无关 |
|----|--------|----|------|:---:|
| A 采样 | `llm.sampling`（新增） | 设置 → 通用 | temperature / top_p / frequency_penalty / presence_penalty / max_tokens | ✅ |
| B 调优 | `tuning.llm` / `tuning.llm_net`（现状） | 设置 → 调优 | stream_options / retries / response_* / 超时 / 连接池 | ✅ |
| C 模型级 | `ai.{provider}.model_params.{model}`（现状） | 模型管理（逐模型） | context_limit / reasoning_effort | ❌ 逐模型 |

**实施策略**：A 类走 `client_sdk._build_request_body` 显式拼参（默认即旁路），**不改成逐模型特殊处理**；B 类现状不动；C 类个别需求仍走 `model_params` 逃生门，本次不扩展。

### 3.4 明确"不做"的（模型无关性反面）

| 候选 | 结论 | 理由 |
|------|------|------|
| top_k | **不做通用参数** | 非 OpenAI 标准，主流 vendor 400 拒绝；若个别厂商（如 MiniMax）需要，应走 model_params 逃生门逐模型配，归模型级而非通用级 |
| n / logit_bias / user / response_format | 不做 | 无消费方 / 结构难 UI / 非采样需求，YAGNI |
| stop | 二期备选 | 需维护边界串，收益窄；若做同样入 llm.sampling |

### 3.5 context_limit 兜底 256K 的配置化（C 类关联项）

> 北京老陈 2026-09-22 拍板：兜底上下文大小必须在配置文件中体现，不能只藏在代码常量里。

**现状查证**：

| 项 | 位置 | 值 |
|----|------|-----|
| 兜底常量 | `backend/app/services/agent/compaction_constants.py:41` | `DEFAULT_CONTEXT_LIMIT = 262144`（**256K，不是 250K**） |
| 语义 | 同上 L39-41 | 上下文窗口默认上限；`model_params.{model}.context_limit` **未配置时**才用它兜底 |
| 消费链 | `service.py:99` `pop("context_limit", DEFAULT_CONTEXT_LIMIT)` → BaseAIService → 压缩/裁剪门限（start×0.5 / loop×0.75 / buffer 20K，`message_builder.py:100` 联动） | 窗口基准 |

**配置化落点**（C 类 → 不进 `llm.sampling`，归模型级窗口域；完整 yaml 见 **3.6 集中落盘**）：

| 候选键 | 归属 | 说明 |
|--------|------|------|
| （无） | 现状 | 256K 只在代码常量，**config.yaml 无体现** — 北京老陈要求补 |

**关键设计**：全局兜底为"所有未配置窗口的模型的统一下限"，逐模型配置仍优先（现状语义不变）；`llm.context_limit_default` 让"临时调大/调小全系统窗口"不用改代码，贴近老陈要"配置文件体现"的诉求。
