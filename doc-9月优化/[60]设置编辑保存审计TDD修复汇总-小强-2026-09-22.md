## 五、全量前端套件 6 项失败根因分析与修正（2026-09-22）

> 全量首跑 6 项失败均与「设置编辑保存」产品改动无关，属独立缺陷/过时用例/并行 flaky，逐一分类修正。

### 5.1 F7：settings2-live-probe —— 真实后端契约缺陷（已修复，产品代码）

- **现象**：`expect(schema label 唯一数).toBe(总数)` 得 32/33。
- **根因（小欧 2026-09-22）**：`settings_registry.py` 中 `workspace.project_root`（应「项目根目录」）与 `paths.project_root` 重复使用 label「项目根目录」→ schema 存在重复 label。
- **修复**：`backend/app/services/settings/settings_registry.py` `paths.project_root` label 改为「生效项目根目录」。
- **验证**：真实 schema 现 33 项 / 33 唯一 label；F7 单跑通过。fixture `live-*.json` 为 v4.20 旧快照未动。
- 注：后端回归 44 项不受影响（不断言 label 文案）。

### 5.2 BUG-25：audit-pages-layout-bugs —— case 过时（已退役）

- **现象**：`expected 1 to be greater than 1`（断言死状态仍有使用点）。
- **根因**：死状态 `isManualRefreshing` 已于 2026-09-21 按 YAGNI 删除（小强，Layout/index.tsx），该审计 case 未同步 → **case 过时**。
- **修复**：`audit-pages-layout-bugs.test.tsx` v1.2 版本历史 + 退役注释替换旧断言；describe 改名「审计快照…已修转绿/已退役」。
- **顺带修复既有损坏**：文件预存 U+FFFD 乱码 + BUG-24/BUG-30 断言行被并入 `//` 注释（假绿，断言行从未执行）。用 Python 字节安全修复（PowerShell 被严禁用于代码编辑），恢复 BUG-24/30 真实断言。
- **验证**：文件 5/5 真实绿（此前 24/30 为假绿）。

### 5.3 trust-panel ×3 —— 并行 flaky（超时鲁棒化）

- **现象**：静态 `Modal.confirm` 并行池下挂载延迟 > 默认 5s testTimeout。
- **修复（小强 2026-09-22）**：为「撤销弹确认」「撤销失败不抛异常」等用例补 `{ timeout: 20000 }`，与确认框「取消/Esc」用例口径一致。
- **验证**：trust-panel + review-bugs 合跑 21/21。

### 5.4 BUG3：review-bugs —— 并行 flaky（点击路由 + 2s 自关竞态，实证排误）

- **现象**：`Unable to find an element with the text: 模型验证失败`；DOM 无 `ant-modal-root`。
- **实证排误（探针，负载轮）**：
  - 按钮 enabled + isConnected，但 `fireEvent.click` 后 `chatApi.validateService` 调用数 = 0 → 点击事件未被 React 路由（jsdom + React18 并行负载下 onClick 偶发不路由）。
  - Layout 失败弹框 2s 自动关闭（`Layout/index.tsx:298-305`），轮询受事件循环饥饿影响易错过窗口。
- **修复（小强 2026-09-22）**：改用 `@testing-library/user-event` 全事件序列点击（pointer/mouse/click）+ 兜底二次点击；`act()` 同步冲刷 + 微任务刷新替代 waitFor 轮询，规避 2s 自关竞态。
- **验证**：负载轮测试 confirm（calls=1、modal 挂载）；默认 5s→20s/40s 超时；产品行为正确（独跑/串行恒绿），纯测试环境问题。

## 六、并行竞态收尾（settings2-live-write / live-write2）

> 新增发现：两文件并行时跨文件互踩真实 DB（串行 `--fileParallelism=false` 39/39 证明竞态，非产品缺陷）。用户裁定「仅加超时不动配置」+ 受影响 case 内注释说明。

### 6.1 超时注入
- 两文件全部 39 个用例（20 + 19）注入 `{ timeout: 20000 }`，规避并行池下真实 CRUD > 默认 5s 误杀；文件头 09-22 编辑历史。
- Q1/Q2/P12/W17 用例内加并行互扰场景注释。

### 6.2 断言语义修正（不改变验证价值）
- **Q2（live-write2）作用域修正**：原 `startsWith('__probe_')` 会把并行中 live-write（前缀 `__probe_`）的存活探针误判为本文件残留 → 每次全量必红。本文件探针统一前缀 `__probe2_`，改为自有前缀过滤 =「本文件自证清理」准确语义（Q1 同口径）。
- **M1（live-write）双端点相等快照**：原数组字面量内两次 `await` 实为顺序读（窗口大），并行下另一探针写 settings 致两次读间漂移（实测 0.46s 级）。改为 `Promise.all` 真并行 + 有界重试（5 次）取安静窗口；断言语义不变（真实独立漂移仍必现）。
