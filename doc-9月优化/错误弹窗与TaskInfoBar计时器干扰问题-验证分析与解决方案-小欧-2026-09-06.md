## 一、你看到的现象

页面时不时**弹出一个黄色/红色的小提示条**（toast），然后下面好像"乱了套"：
- 任务信息条里那个**"耗时 Ns"的计数器**一会变 0、一会又跳回一个更大的数——像被捣乱了；
- 感觉**自动滚动**也不正常了。

老陈的原话：这个计数器受干扰了，页面出现奇怪情况。

页面上一共有 **3 个地方**可能显示"错误"，先认清它们（后文都靠这三个位置说话）：

```
【位置1】弹窗小条 ── 右上角飘出来，自己消失
   ┌─────────────────────┐
   │ ⚠ 危险操作已被拦截       │   ← 约3~5秒后自动消失
   └─────────────────────┘

【位置2】聊天气泡 ── 对话区正在播放的那段
   ┌─────────────────────┐
   │ 好的，我帮你整理 D:\旧资料 │   ← AI 正在一句句"打字"
   │ 已经找到以下文件……         │
   └─────────────────────┘
   （出错时可能被整段替换成一行红字，见下）

【位置3】任务信息条第4位 ── 任务条里靠右那段
   ╔ 任务12·耗时12s·[失败]  🛑工具已被拦截：xxx ═══╗
                          └── 这一小段就是"第4位"
   （会一直挂着，直到你再发一句或换会话才消失）
```

## 二、结论先给你（一句话规则）

**总原则（北京老陈 2026-09-06 拍板）：**
> **前端自己的错误，只能弹窗提示；后端的错误，只进任务信息条那些显示，不弹窗。**

也就是把错误按"来源"分成两类，各走各的路：

| 错误来源 | 例子 | 修复后怎么表现 |
|---|---|---|
| **后端的错误**（任务/工具本身的事） | 工具被安全拦截、模型空回复、确认超时…… | 只进任务信息条/消息，**绝不弹窗** |
| **前端自己的错误**（网络/管道的事） | 网断了、服务器没反应、60秒没数据 | **照常弹窗**提示我（唯一该弹的） |

后端的错误再分两种"轻重"：

| 后端错误轻重 | 例子 | 任务 | 修复后怎么表现 |
|---|---|---|---|
| **小波折（可恢复）** | 这个工具被拦、确认超时 | 任务**还在继续**，换别的招干 | 不动正在播放的内容、不动计时；只在任务信息条第4位标一下 |
| **大事（任务终态）** | 模型空回复、累积超时、服务器异常 | 任务**已经失败收场** | 把占位消息变成红字结论（正常收场）；不弹窗 |

前端的错误（断网/超时）：照旧弹窗，什么都不改。

## 三、问题根源：一条错误搅动六处

现状代码里，一条错误进来，身上挂着 6 根线，全被连着动（后面会修掉一部分）：

```
                 一条错误（现在是"不分来源"地进来）
                          │
        ┌─────────────────┼──────────────────────────┐
        │                 │                          │
     ① 弹窗小条        ② 正在播放的聊天内容         ③ 等待计时器
        │  被弹         │  被整段替换成红字          │  被清停且不再启动
        │                 │                          │
        ├─────────────┬───┴───────┬──────────────────┤
       ④ 任务条第4位   ⑤ 徽标变"失败"   ⑥ 左栏任务列表重刷
        │  显示错误    │  （连带把"耗时"计数器         │
        │              │   清零停表了！）              │
```

其中**两条经测试实锤**（每一条都用取证测试证实过——测试能复现，就说明是真实问题）：

- **B1【实锤】**：错误一来，徽标变"失败" → "耗时 Ns"计数器**清零、停表**；任务恢复后又**回跳**到累计值。
  - 表现：执行到一半，数字从 1 秒清零成 0，等一会儿又"噔"跳到 4 秒——中间那 2 秒就像没发生过。
  - **这条已经修好**（见第五章），修完后不再有"清零＋回跳"。
- **B3【实锤】**：一次错误 "同时"干了三件事——弹窗 ＋ 正在播的内容变红字 ＋ 计时被停，观感是"一个错，三处一起动"。

其余几处是本设计如此（比如"重刷左栏任务列表"），不属于 bug，只是被一起讲清楚。

## 四、错误都是从哪儿来的（源头全部列清）

### 4.1 后端的错误（会进"弹窗链条"，是要改的那批）

后端只会通过**同一条**通道把错误送到前端（代码里叫 SSE 的 error 事件）。这条通道里所有错误类型，**一个不漏**如下：

**固定 12 个（其中说得上"类型"的就这些）：**

| 类型 | 一句话 | 任务状态 | 归哪类 |
|---|---|---|---|
| 工具被拦截 | 安全系统拦下了这个工具 | 继续 | 小波折（可恢复） |
| 确认超时 | 等你确认等了太久 | 继续 | 小波折（可恢复） |
| 无效命令 | 模型要执行个空命令 | 继续 | 小波折（可恢复） |
| 模型空回复 | 模型什么都没说 | 已失败收场 | 大事（终态） |
| 累积超时 | 半天没攒够一句完整回答 | 已失败收场 | 大事（终态） |
| 熔断 | 服务熔断器打开 | 已失败收场 | 大事（终态） |
| 客户端错 | 请求本身不对（4xx） | 已失败收场 | 大事（终态） |
| 服务器错 | 服务器报错（5xx） | 已失败收场 | 大事（终态） |
| 未知 | 识别不出来的异常 | 已失败收场 | 大事（终态） |
| 限流/配额 | 接口限流、配额用尽 | 已失败收场 | 大事（终态） |
| 空响应（异常支）| LLM 异常里判出的空响应 | 已失败收场 | 大事（终态） |
| 空闲超时（异常支）| LLM 侧长时间没回内容 | 已失败收场 | 大事（终态） |

**还有一批错误根本不走这条通道**：任务结束信号（final 事件）自己带错误信息（死循环终止、重试耗尽、任务执行异常……）。它们走的是"正常收场"的路，**本来就不弹窗**，这次的改动**完全不碰**它们——它们只负责把"失败"写进消息和状态里。

### 4.2 前端自己的错误（照常弹窗，不动）

| 来源 | 什么时候发生 |
|---|---|
| 60 秒没收到数据 | 连接"凉"了，自动补连 |
| 首条响应一直没来 | 任务都没接上，重连也没目标 |
| 重连反复失败 | 彻底连不上 |

这三类都是"前端到后端的管道"出问题，按总原则——**弹窗提醒你**，行为完全不变。

## 五、第一处修复：计数器（R1）—— 已改完、已提交

**病根**："走不走表" 绑在了 "任务成败徽标" 上。错误一来徽标变"失败"，连带着把计时清零停表；任务恢复就算重新走，也跳过了中间那段 → 数字乱跳。

**修法**（一行思路）：走不走表，只看"还在不在接收实时数据"，不再看徽标记。
- 正在实时收数据 → 继续走表；
- 流停 / 切到历史记录 → 才归零。
- 错误导致徽标变色，**不再影响计数器**。

已提交：`a3d7a38a0`（修复）。大小：约 13 行。

## 六、第二处修复：错误分流（R3）—— 方案待审核

### 6.1 你要拍板的规则（就是第二章那张表）

| 进来的错误 | 弹窗 | 正在播的聊天内容 | 等待计时 | 任务条第4位 |
|---|---|---|---|---|
| **后端·小波折**（可恢复） | 不弹 | 不碰 | 不停 | 显示 |
| **后端·大事**（任务终态） | 不弹 | 替换成红字（正常收场） | 清停（结束了） | 显示 |
| **前端·连线问题** | 弹 | 替换成红字 | 清停 | 显示 |

一句话记忆：**后端的错不弹窗；可恢复的连内容都不碰；只有前端连线问题才弹窗。**

### 6.2 怎么改（三处，都是前端，后端一行不动）

1. 后端错误在出厂时贴个**"我是后端来的"标签**（一行代码）；
2. 前端收到错误时，**看标签分路**：
   - 没标签 ＝ 前端自己的错 → 照旧弹窗；
   - 有标签 ＋ 类型是小波折 → 直接放行：不弹、不碰内容、不停计时，只在任务条第4位亮一下；
   - 有标签 ＋ 其它 → 不弹窗，该替换红字的替换、该清计时的清停。
3. 弹窗的"引擎"本身不动、前端的网络判断不动——只是"什么该进引擎"这件事，现在按总原则重新分了门。

### 6.3 不碰什么（边界）

- 后端 **一行都不用动**；
- 前端错误中心、66 秒空闲超时、任务条第4位、徽标、被拒工具灰字点名（之前 B2 已做的那套）**都不改**；
- 不加新东西、不改协议，那个"我是后端来的"标签只存在前端内部。

### 6.4 风险与兜底

| 万一…… | 结果 |
|---|---|
| 后端以后新增错误类型 | 没认出来的，一律按"大事（终态）"处理 → 不弹窗，仍符合总原则 |
| 以后新增了"小波折"型错误但没记进清单 | 会按"大事"处理 → 最坏是多替换一行红字，仍不弹窗，可以接受 |
| 旧错误对象没贴标签 | 按"前端错误"弹窗 → 宁肯弹，也不静默吞掉 |

### 6.5 怎么验收

写取证测试，**铁证**三个行为：
1. `工具被拦截`（后端·小波折）→ 断言：不弹窗、不动聊天内容、不停计时；
2. `模型空回复`（后端·大事）→ 断言：不弹窗、内容变红字、计时清停；
3. `60秒空闲超时`（前端连线）→ 断言：照旧弹窗（这条现状就对的，守住它）。

再加：前端编译检查、类型检查全部清零；相关现有测试不回归。
