## 一、目标

让 `opencodeZen` provider 通过 **Zen 免费无key 认证**（`Authorization: Bearer public`）直连 `https://opencode.ai/zen/v1`，做到：

1. **零付费额度、零余额消耗**：免费模型名称带 `-free` 或为 `big-pickle`，`cost=0`，key 余额不动。
2. **架构可扩展、接入模式一次定死**：以 `opencodeZen` 为首个示范，建立「**一 provider 一适配文件**」的目录适配架构——以后任何 provider 需要特殊 HTTP 握手差异，**只新增一个适配文件**，其余代码零改动。
3. **无侵入默认路径**：本次改动不触碰 `agnes` 等既有 provider 的任何行为（零 backward 兼容性干扰）。

## 二、现状剖析（证据链）

### 2.1 Zen 免费层准入校验（实测破解，2026-09-17）

经抓包（mitmproxy 代理真实 1.18.31 客户端）与重放实验定位，服务端对匿名免费层的准入只校验两个"客户端特征"，二者齐备即放行（返回 200）：

| 校验项 | 要求 | 实测通过值 |
|------|------|-----------|
| `User-Agent` | 必匹配 `opencode/<语义化版本>`，且版本 ≥ 1.17.0；缺失/非法/低于 1.17.0 分别返回 403 FreeTierError 或 426 UpgradeRequired | `opencode/1.18.31 ai-sdk/provider-utils/4.0.23 runtime/bun/1.3.14` |
| `x-opencode-session` | 合法格式会话ID：`ses_` + 12位小写十六进制 + 14位 base62 字符（共 30 字符）；格式不符仅返回 403 FreeTierError | 自动生成，客户端生命周期内固定复用 |
| `x-opencode-request` | 不参与校验 | 每请求刷新 `msg_` + 随机（与真实客户端每次调用生成新消息ID一致） |

### 2.3 后端 LLM 出口链路（唯一出口）

`opencodeZen` 配置从 config.yaml 进入后端后，有 **两条平行创建路径**，最终都汇聚到唯一 HTTP 出口 `LLMClient`：

```
路径一（全局/默认模型）：
config.yaml opencodeZen
  → create_service_instance (lifecycle/service.py:95) 读 api_key/api_base/timeout/max_tokens/temperature/seed/model_params
  → BaseAIService.__init__ (base_service.py:84)
  → _ensure_client (base_service.py:124) → create_llm_client (client_sdk.py:252)
  → LLMClient.__init__ (client_sdk.py:108)
  → httpx.AsyncClient(headers={"Authorization": f"Bearer {api_key}"})   ← client_sdk.py:134 ONLY这个头!

路径二（L2 会话级切模，独立客户端快照）：
resolve_session_client (resolver.py:132) 按 _ov.provider 从 config 查配置
  → ai_service.snapshot() (base_service.py:140-168) 构造独立 BaseAIService 副本
  → _ensure_client → create_llm_client → LLMClient  → httpx.AsyncClient(headers=...)
```

### 2.4 关键结论

1. **缺口**：`client_sdk.py:134` 只发 `Authorization` 一个头，没有 UA、没有 session、没有 request id → 匿名请求必死于 `403 FreeTierError`（实测证实）。
2. **校验层零阻碍**：`validation.py:49-53`（api_key 非空）+ `config_helpers.py:195-196`（api_key 字段存在）——配置填 `api_key: public` 即全部通过，**validation 无需改动**。
3. **需要扩展两个层面的 HTTP 行为**：
   - **静态头**（UA / session / x-opencode-client / x-opencode-project）：客户端创建时合并进 httpx `headers`，全连接生命周期固定。
   - **动态头**（x-opencode-request 每请求新 id）：走 `LLMClient.request()` / `request_stream()` 的 per-request `headers=` 参数（httpx 的 post/stream 均支持传 headers，自动与客户端默认头合并）。

### 2.5 provider 特殊处理散落点全核查（6 类，归属判定——北京老陈核查 2026-09-17）

全文排查后端，provider 相关特殊处理目前共 6 类、分散 4 个模块。逐一判定「该不该 provider 化」：

| # | 维度 | 现实现位置 | 现状 | 归属判定 | 是否进适配层 |
|---|------|-----------|------|---------|------------|
| 1 | 请求头/认证 | `client_sdk.py:134` 仅 Authorization + Zen 本次新增 | provider 维度，取决于认证方式差异 | **真 provider 维度** → 进适配层 | 是（本文件核心） |
| 2 | API 地址 | `client_sdk.py:138-154` `_DEFAULT_URLS` + config `provider_urls` | **已按 provider 收敛**的 dict 映射，且支持配置覆盖 | 现成范本，机制已好 | 已是 provider 维度，**原地不动**，适配层声明归并 |
| 3 | 请求体 schema | `tools/schema_utils.py:24,49`（注册期统一生成） | 全局统一 anyOf（兼容 opencode/DeepSeek 严格校验） | **通用正确性**：anyOf 是标准 JSON Schema，所有 OpenAI 兼容 API 都支持 | 否（保持全局，不 provider 化） |
| 4 | 响应 reasoning | `core.py` StreamChunk / `llm_call.py:135` / `reasoning.py:62` | 三字段兼容已全局兜底：`content = full_content or full_reasoning`，纯思考(content空)有 observation 兜底 | **已通用已兜底**，ling-free 缺实测验证 | 否（保持全局 + 实测验证） |
| 5 | 工具幻觉名 | `tools/tools_alias_mapper.py:338` | 独立 dict，**32 处引用**遍布安全层/执行层/registry/trust | **安全正确性**：所有 LLM 通病（writefile 等）；provider 化 = 未配别名的 provider 直接安检漏洞 | 否（**必须保持全局**，绝非 provider 维度） |
| 6 | 错误分类 | `error_classifier.py:99-108` | 全局黑名单：403 一律 CLIENT 不可重试 | 403 不可重试是**普适语义**，全局正确；zen FreeTierError 只是消息可更友好 | 主体否（保持全局）；**错误消息映射为增强项**(已实现, 见 5.2.3) |

**统一/分散结论（三思三省）**：
- **统一进适配层**：真正 provider 独有、且发生在 **HTTP 接缝层**的握手差异——① 头/认证 ② 地址(申明归并) ⑥ 错误消息映射(可选)。
- **必须保持全局、绝不 provider 化**：③ schema、④ reasoning、⑤ 工具别名——前两者是通用正确性，⑤ 是安全正确性（provider 化会开安检漏洞）。
- **请求参数名差异（北京老陈核查 2026-09-17）**：不属适配层。现网统一 OpenAI 兼容格式 + 服务端对未知参数静默 + config `model_params` 按模型粒度配特有参数（见 5.0），已天然覆盖；思考层参数（reasoning_effort 等）是**模型粒度**差异，落在 config，与 provider 无关。
- **判据口诀**：*只按 provider 分道 HTTP 握手；内容链(请求体/响应解析)与工具链(别名/安检)一律全局。*

## 三、设计原则（遵守 AGENTS.md 铁规 + 10 大规范）

| 原则 | 落实设计 |
|------|---------|
| KISS-DIRECT | 适配层三文件小目录：base(通用默认) + opencodeZen(定制) + __init__(查询)；client_sdk 只调统一接口 `get_provider_adapter(provider).static_headers()/per_request_headers()`，不感知 zen 细节 |
| OCP 开闭 | 新 provider 特殊 HTTP 握手 = `adapters/` 加一个文件（继承 base 覆写）；既有文件零改动 |
| SRP 单一职责 | base 只定义通用默认行为；每个 provider 文件只管自己的握手差异；查询接口只管分派 |
| DRY 不重复 | 通用逻辑在 base 一份；zen 专属（UA/ID 生成）在 opencodeZen.py 一份；client_sdk 不重复实现 |
| 禁止backward | 默认无适配 / base 基类行为 == 现状（仅 Authorization + 无动态头 + 原 _DEFAULT_URLS），不留双份逻辑、不增加兼容开关 |
| 唯一出口 | 请求头注入集中在 `LLMClient` 内部（调适配层接口），不散落在编排层/会话层 |
| 先查后建 | `_gen_zen_id` 为 opencodeZen.py 模块内私有能力，仅供该文件使用；若未来多 provider 复用再登记 FUNCTIONS.md |

## 五、详细设计

### 5.0 请求/响应载荷差异处置机制（核查定案——北京老陈 2026-09-17）

> **现状事实（北京老陈确认）**：现网 LLM 请求全部走**统一 OpenAI 兼容格式**（`client_sdk.py:44-82` `_build_request_body`）；provider/模型特有参数唯一走 `extra_body` 通道（config `model_params` → `base_service.py:105-112` 合并，含 `enable_thinking:True` 兜底）；**多余参数对不识别的模型服务端静默忽略**。响应统一读 `choices/message/delta`，思考字段差异已由 `reasoning.py:148-152` 三字段链全局兼容（reasoning_content/thinking/reasoning/标记型）。

**定案结论**：
1. **不引入任何参数名映射层**（YAGNI 充分成立）：统一格式 + 服务端静默 + config 按模型粒度配 `model_params` 已覆盖全部参数名差异。
2. **思考层次参数差异（老陈判断高概率区）本质是模型粒度**（同 provider 不同模型也不同，如 sensenova 下 deepseek-v4-flash/glm-5.2 各配 `reasoning_effort: medium`）——落在 config `model_params` 粒度，与 provider 适配层无关，**不进适配层**（符合 2.5 #3 判据：请求体 schema 属全局层）。
3. **例外预案**：若未来某 provider 服务端**不静默**（严格拒绝未知参数），再临时评估——按 YAGNI 当前不建空壳，真实案例出现时再议。

### 5.1 配置层（config.yaml）—— 保持常规结构

`opencodeZen` 与其他 provider 完全同构，**不新增任何特殊字段**：

```yaml
opencodeZen:
  api_base: https://opencode.ai/zen/v1
  api_key: public                 # 常规字段；值填 public=匿名(过校验层, Bearer public)。付费则填 sk-...
  max_retries: 3
  models:
    - big-pickle
    - mimo-v2.5-free
    - nemotron-3-ultra-free
    - nemotron-3.5-lightning-free
    - ling-3.0-flash-fin-free
  model_params:
    big-pickle:            { context_limit: 10000 }
    mimo-v2.5-free:        { context_limit: 10000 }
    nemotron-3-ultra-free: { context_limit: 10000 }
    nemotron-3.5-lightning-free: { context_limit: 10000 }
    ling-3.0-flash-fin-free:     { context_limit: 10000 }
  timeout: 150                  # zen 免费 thinking 模型较慢(实测 65.6s), 超时放大
```

> `api_key` 允许 `public` 与付费 `sk-` 之间切换——换 key 即切换身份，零代码。

# -*- coding: utf-8 -*-
# 模块说明: provider 适配基类 — 默认行为==现状(仅 Authorization, 无动态头, 空错误消息)
#   新 provider 特殊 HTTP 握手 = 继承本基类覆写对应钩子; 未覆写即完全默认(现状语义)。
#   归属依据(北京老陈核查 2026-09-17 §2.5): 只承载 HTTP 接缝差异#1/2/6;

# 编辑历史: 2026-09-17 小欧 新建

from typing import Dict

    """provider 适配基类 — 小欧 2026-09-17"""

    @staticmethod
    def static_headers(api_key: str) -> Dict[str, str]:

    @staticmethod

#### 5.2.3 opencodeZen.py —— zen_free 定制（本文件核心）

```python
# -*- coding: utf-8 -*-
# 模块说明: opencodeZen 免费无key 适配 — 小欧 2026-09-17
#   准入配方(实测破解 v3): UA(>=1.17) + 合法 x-opencode-session; x-opencode-request 每请求刷新(不校验)。
#   只覆写 HTTP 接缝差异(#1/6), 不触碰全局层(#3/4/5)。
# 编辑历史: 2026-09-17 小欧 新建

import random
import string
from typing import Dict

from app.llm.adapters.base import ProviderAdapter

_ZEN_USER_AGENT = "opencode/1.18.31 ai-sdk/provider-utils/4.0.23 runtime/bun/1.3.14"

_B16 = "0123456789abcdef"
_B62 = string.ascii_letters + string.digits


def _gen_zen_id(prefix: str) -> str:
    """生成 Zen 客户端风格ID: 前缀+12位小写hex+14位base62 — 小欧 2026-09-17
    与 test_zen_stress.py v3 同格式; ses_ 固定于客户端生命周期, msg_ 每请求刷新
    (模块内私有能力, 仅本文件使用; 若未来多 provider 复用再登记 FUNCTIONS.md)"""
    return (prefix
            + "".join(random.choice(_B16) for _ in range(12))
            + "".join(random.choice(_B62) for _ in range(14)))


class OpencodeZenAdapter(ProviderAdapter):
    """opencodeZen 适配: zen_free 匿名免费层 — 小欧 2026-09-17"""

    @staticmethod
    def static_headers(api_key: str) -> Dict[str, str]:
        headers = {"Authorization": f"Bearer {api_key}"}
        headers.update({
            "User-Agent": _ZEN_USER_AGENT,
            "x-opencode-client": "cli",
            "x-opencode-project": "global",
            "x-opencode-session": _gen_zen_id("ses_"),   # 客户端生命周期固定(每客户端一次)
        })
        return headers

    @staticmethod
    def per_request_headers() -> Dict[str, str]:
        return {"x-opencode-request": _gen_zen_id("msg_")}   # 每请求刷新(不参与校验)

    @staticmethod
    def error_message_map() -> Dict[int, str]:
        # 可选(最小增强): zen 免费层特有错误码 → 友好文案; 未覆盖的由全局分类兜底 — 小欧 2026-09-17
        return {
            403: "Opencode Zen 免费层准入失败: 请检查 UA/session 头注入(适配层)或改用付费 key",
            426: "Opencode Zen 要求客户端升级(UpgradeRequired)",
        }
```

```python

#   新 provider 接入 = 在本文件 _ADAPTERS 加一行 + adapters/ 加其定制文件; 其余代码零改动。
# 编辑历史: 2026-09-17 小欧 新建

from typing import Dict

from app.llm.adapters.base import ProviderAdapter
from app.llm.adapters.opencodeZen import OpencodeZenAdapter

# 模块级默认实例: 未注册 provider 复用同一实例(行为==现状), 避免每次 new — 小欧 2026-09-17
_DEFAULT_ADAPTER: ProviderAdapter = ProviderAdapter()

_ADAPTERS: Dict[str, ProviderAdapter] = {
    "opencodeZen": OpencodeZenAdapter(),
}


def get_provider_adapter(provider: str) -> ProviderAdapter:
    """按 provider 名返回适配实例; 未注册(无特殊握手)返回默认基类(行为==现状) — 小欧 2026-09-17"""

```

**扩展规则（一 provider 一文件）**：
- 新 provider 需特殊 HTTP 握手 → `adapters/` 新建 `{provider}.py`（继承 base 覆写 static_headers/per_request_headers/error_message_map）+ `__init__.py` `_ADAPTERS` 加一行 → **仅 2 处小改，既有代码零改动**。
- 完全无特殊握手的 provider（agnes/openai/deepseek 等）→ 不建文件，自动走默认基类（==现状），**零文件零逻辑**。

**接入三步骤（新 provider 按此操作）**：
1. **判定**：差异是否属于 HTTP 接缝握手？→ 是→进适配层；否（请求体/响应解析/工具别名/安检）→ 保持全局不动。
2. **建文件**：`adapters/{provider}.py` 继承 `ProviderAdapter`，覆写 static_headers / per_request_headers / error_message_map 钩子。
3. **注册**：`adapters/__init__.py` 的 `_ADAPTERS` 加一行 `"{provider}": {Xxx}Adapter()`。

| 场景 | 做法 | 改动面 |
|------|------|--------|
| 新 provider 要自定义头（如某网关要求 x-api-key） | adapters/ 加文件 + __init__ 注册 | 2 处（新增文件+1行注册），既有代码零改动 |
| 新认证模式（azure/oauth 等不同握手算法） | 同上（覆写 static_headers 的逻辑差异化在定制文件内） | 2 处 |
| 无特殊握手的 provider（agnes/openai/deepseek） | 不建文件，自动默认基类 | 零 |

## 六、风险与边界

| 风险 | 等级 | 缓解 |
|------|------|------|
| 匿名免费层服务端随时可收紧（v3 已是弱校验绕过） | 中 | `api_key` 一键切回 `sk-`，架构不变 |
| IP 配额共享（约 200 次/天，全站同出口 IP） | 中 | 免费模型用于按需测试/低频场景；重负载走付费 key 或切换 provider |
| 国内出口 IP 达配额后变慢（约 100 次后） | 低 | 海外出口更稳；同上有偿化兜底 |
| 全局单例 client 复用同一 session（多会话共享） | 低 | 实测服务端只校验格式不校验唯一性 |
| httpx 0.26.0 / httpcore 1.0.1 版本锁定不容破坏 | 高 | 本次改动不触碰任何依赖版本 |
| 适配器误将全局逻辑 provider 化（破坏 schema/别名安全） | 中 | 2.5 判定 + 三章"内容链/工具链一律全局"红线写死，评审把关 |
| thinking 模型（nemotron-3.5）响应慢（65.6s） | 低 | `timeout: 150` 已放大覆盖 |
| ling-3.0-flash-fin-free 输出在 reasoning 字段 | 低 | 实测认证路径 OK；`llm_call.py:135` 已有 content/reasoning 兜底，接入后实测验证；属模型特性非集成缺陷 |
