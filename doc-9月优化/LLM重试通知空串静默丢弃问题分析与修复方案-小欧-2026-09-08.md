## 一、问题概述

### 1.1 现象

2026-09-08 14:57 生产实测：LLM 请求发生 L1 读超时重试，后端日志可见 `[Retry][L1] 重试 1/3 ...` 记录，但**前端未收到任何重试通知**（任务条位4 🔁 不变、无 MetaStep(retrying) 事件）。

### 1.2 影响

- 用户看到的只是"长时间无响应"，不知后端正在自动重试，体验与设计（2026-09-02 实时重试透出）不符。
- L2 重试、FC 降级链路不受此 bug 影响（其 meta 由 `llm_call.py` 直接构造，文案非空）。

---

## 二、源码级证据链（三层实证，与线上环境版本一致）

**环境**: Py 3.13.11 @ `E:\Appsw\python31311\`，`httpx==0.26.0`、`httpcore==1.0.1`（与 `backend/requirements.txt` 锁定一致）。

### 2.1 第一层：生产日志实证（空串的直接证据）

`backend/logs/app_2026-09-08.log` 第 14273 行（按码点逐字解析）：

```
2026-09-08 12:53:35 - WARNING - ... - base_service.py:417 - [Retry][L1] ... 错误: [ReadTimeout]
```

`[ReadTimeout]` 之后**仅 1 个分隔空格（U+0020）**，`{e}` 部分为空串——即 `str(e) == ""`。

### 2.2 第二层：httpx 0.26.0 异常体系（空串的生成机制）

- `httpx._exceptions.py`：`HTTPError.__init__` 仅调用 `super().__init__(message)`，**无自定义 `__str__`** → `str(e)` 恒等于构造时传入的 `message`。
- 实测：`str(httpx.ReadTimeout("read timeout")) == "read timeout"`，`str(httpx.ReadTimeout("")) == ""`。

### 2.3 第三层：底层异常来源（为何 message 是空串）

- `httpcore._exceptions.py:8` `map_exceptions`：`raise to_exc(exc) from exc`，将底层 `socket.timeout` / `TimeoutError` 直接包装进 `ReadTimeout`，**不注入任何文案**。
- `httpx._transports/default.py:83-84`：`message = str(exc)` → `raise httpx.ReadTimeout(message) from exc`。
- 实测：asyncio 读超时抛出的是**无参 `TimeoutError()`**，`str(TimeoutError()) == ""`（len=0）。
- 结论：`TimeoutError()`（空）→ 经 httpcore、httpx 逐层原样包装 → `httpx.ReadTimeout("")` → `str(e) == ""`。

### 2.4 消费侧丢弃点（bug 落点）

| 位置 | 代码 | 缺陷 |
|------|------|------|
| `base_service.py:422`（修复前） | `retry_notice=str(e)` | `str(e)` 为空串 |
| `llm_call.py:93` | `if isinstance(chunk, StreamChunk) and chunk.retry_notice:` | **真值判定**：空串 `""` 为 falsy → 整体判 False → 静默 `continue` 丢弃，永不走 `create_payload_chunk` 转 MetaStep(retrying) |
| `react_step.py:226-235` | 消费 payload | 永远到不了此层 |

### 2.5 判定链一图流

```
asyncio 读超时 → TimeoutError()（无参，str=""）
→ httpcore.map_exceptions 包装 → httpcore.ReadTimeout(str_exc="")
→ httpx map_exceptions → httpx.ReadTimeout(message="")
→ base_service.py:422 retry_notice=str(e)==""（falsy）
→ llm_call.py:93 if chunk.retry_notice: 判 False → continue 丢弃
→ 前端永不收 retrying 事件
```

## 三、为什么此前审核与测试未发现（诚实复盘）

| 原因 | 说明 |
|------|------|
| 缺陷是**运行时**而非静态 | 只有真实发生"LLM 读超时"且超时异常为"无参空 str"形态才触发；单测/Lint 不制造网络超时 |
| 既有单测构造的是**非空异常** | `test_llm_retry_visibility.py` 用例用 `httpx.ReadTimeout("read timeout")` 构造——`str(e)` 非空，故真值判定天然为 True，无法暴露此分支；**回归缺口**在于从未用例覆盖"空 str 异常"形态 |
| 注释误导 | `base_service.py:419`（修复前）注释明写 `str(ReadTimeout)="read timeout"`，让审核者误以为 str 必非空，进而认为 `retry_notice` 真值判定安全 |
| 作者自身失误 | 初判"str 为空"时仅凭日志观感，未实测即下结论；受用户质疑后才补做源码级实证。教训：**异常 str 行为必须实测，不得凭直觉或注释断言** |

## 四、修复方案

### 4.1 修复内容（`backend/app/llm/base_service.py`）

**位置**: L1 重试分支 `yield StreamChunk(...)`（:420-423）。

- 修复前: `retry_notice=str(e)`
- 修复后: `retry_notice=str(e) or type(e).__name__`

**同步修复**: 同分支日志行（:417）`错误: [{type(e).__name__}] {e}` → `错误: [{type(e).__name__}] {str(e) or type(e).__name__}`，让日志正文不再出现空串。

### 4.2 兜底语义

- `str(e)` 非空时（绝大多数异常）：原文案不变，零影响。
- `str(e)` 为空串时：兜底为**异常类型名**（例：`ReadTimeout`），保证 `retry_notice` 恒非空 → `llm_call.py:93` 真值判定通过 → 正常转 MetaStep(retrying) 发前端，前端文案为 `LLM请求重试 1/3: ReadTimeout`。

### 4.3 不改动的部分（保持最小变更）

- `llm_call.py:93` 真值判定**不改**：因上游兜底后 `retry_notice` 恒非空，此判定语义已正确；若再叠 `is not None` 反而允许多余分支，违背 KISS。
- 不发多次消息、不改透传次数、不改等待退避逻辑——设计语义（每次重试发起前发 1 条、重试几次发几条）本就正确，本次仅补"消息被吞掉"的漏洞。

### 5.2 用例

```python
@pytest.mark.asyncio
async def test_l1_retry_empty_str_exception_notice_nonempty():
    """回归: 异常 str(e) 为空串(L1 可重试)时 retry_notice 必须兜底为非空, 防真值判定丢弃"""
    import httpx
    from app.llm.base_service import BaseAIService

    client = _make_client_first_call_raise(httpx.ReadTimeout(""))   # 空消息异常, 与生产同源
    svc = _make_service(client)
    with patch("app.llm.base_service.asyncio.sleep", new=AsyncMock()):
        chunks = []
        async for c in svc.request_stream(messages=[], tools=None):
            chunks.append(c)

    retry_chunks = [c for c in chunks if getattr(c, "retry_notice", None)]
    assert len(retry_chunks) == 1, f"空str异常也应透出1条非空 retry_notice, 实际 {len(retry_chunks)}"
    rc_ = retry_chunks[0]
    assert rc_.retry_notice, f"retry_notice 必须非空, 实际 {rc_.retry_notice!r}"
    assert "ReadTimeout" in rc_.retry_notice, f"空str异常应兜底为类型名, 实际 {rc_.retry_notice!r}"
    assert rc_.retry_attempt == 1
    assert rc_.retry_total == LLM_STREAM_MAX_RETRIES
    assert any(c.is_done for c in chunks), "重试成功后应正常 is_done 收尾"
```
