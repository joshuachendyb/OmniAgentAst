## 一、总述与结论

对设计文档 [54] 第九章前端部分（9.2.1~9.2.9 新建全量 + 9.3.4~9.3.7 修改 diff）与实际前端实现逐文件点对点核对，结论如下：

1. **落地率高**：34 个按 9.x 落地项中 **27 个零差异按原样实施**，差异全部集中在 4 个"行为层"文件（useSettings / SettingsPage / SettingRow / ModelModals）；纯层文件（api / types / utils / tokens / icons）全部原样。
2. **7 处未按原样实施的差异，无一"实现不如设计"**，全部由真实 bug 或仓库规则驱动：
   - 4 类：修复设计遗留 bug（BUG-A/B/C/D/F）；
   - 1 类：修复类型契约错误（deleteProvider 缺 mtime 导致 TS 编译失败）；
   - 1 类：仓库 lint 规范（no-restricted-syntax 禁 message.* 直调）合规必需；
   - 1 类：有意调整设计 8.2.10 切换语义（数据安全优先，见第四章差异③）。
3. **唯一的功能承诺降级**：设计 8.2.10"切换模型保留已修改参数 + 截断 + [已修改] 标记"被 BUG-D 修复覆盖（改为切换前先强制落盘再展示新模型默认值），属守数据、弃 UX 的合理取舍。

## 四、未按原样实施的差异详表（7 处）

> 结论先行：以下每处均有明确原因（真实 bug / 类型契约 / 仓库规则），且**全部为实际实现更优**。详见各条"为什么好"。

| # | 文件:行 | 设计做法 | 实际做法 | 原因 | 谁更好 |
|---|---|---|---|---|---|
| ① | `model.api.ts:113` | `deleteProvider` 返回 `{ok, switched_to}`，无 mtime | 返回 `ModelMutationResult`（含 `mtime`） | 后端 `delete_provider` 实际响应带 mtime；设计缺该字段导致 SettingsPage onConfirmDelete 中 `res.mtime` 在表单 union 后 TS 编译报错 | **实现更好**：类型对齐后端真实契约，修复编译错误，且 syncMtime(res.mtime) 需要它 |
| ② | `useSettings.ts` / `SettingsPage.tsx` / `SettingRow.tsx` | 直调 `message.info/success/error/warning` | 全部改走 `showMessage(ErrorType.INFO/WARNING/VALIDATE_CONFIG_FAILED/MODEL_CONFIG_ERROR, …)` 与 `showSuccess` | 仓库 lint 规范 `no-restricted-syntax` 禁止 `message.*` 直调（统一提示中心：30s 去重 / 防裸数字 / antdApp 上下文）；设计代码原样落地会 eslint 报错、构建不过 | **实现更好**：合规必需 + 提示行为全站统一 |
| ③ | `useSettings.ts:363-380,412,446` | 切换模型/Provider 时按 8.2.10 合并参数（未改项恢复默认、已改项 clamp 保留 + toast） | 切换前先 `ensureModelSaved()` 强制落盘未保存的参数，**失败则阻止切换**；落盘后新模型按默认值展示，无残留脏态 | BUG-D 实证（2026-09-21 小强）：agnes（空 default_params) ↔ sensenova（有 default_params) 切换后参数静默丢失 / 带出幽灵参数。设计 8.2.10 的"保留已修改参数"只在同字段集模型间成立 | **实现更好**：修复数据丢失真实场景。代价：8.2.10 的"保留 + 截断 + [已修改]+toast"承诺不再成立（见第五章二期建议） |
| ④ | `useSettings.ts:31-45,287-307` | 保存成功仅删 dirtyKeys，secret 明文值留在 state | 新增 `normalizeSecret`：保存成功后把 secret 明文/clear 标记归一回 `{configured,suffix}` | BUG-C 实证：明文残留 state → SettingRow 再渲染误显"未配置"，且再次保存会重复提交明文 | **实现更好**：设计遗漏了保存后 secret 内部状态归一 |
| ⑤ | `SettingRow.tsx:52-62` | secret 按 `{configured,suffix}` 结构取 configured | 兼容明文瞬时态：`isPlain = typeof raw === 'string'` 分支，明文按长度判 configured | BUG-B 实证：保存中/保存后未回读的瞬时态 value 为明文字符串，原逻辑 `cfg?.configured` 对字符串取到 undefined → 闪"未配置" | **实现更好**：设计假设只在 GET 回读后成立 |
| ⑥ | `ModelModals.tsx:39-41` | `useState(props.selectedProvider)` 仅初始化一次 | 加 `useEffect(() => setMProvider(props.selectedProvider), [props.selectedProvider])` 联动 | BUG-A 实证：父级切换所选 Provider 后，弹窗内 Provider 下拉仍指向旧 Provider（陈旧状态） | **实现更好**：修复设计遗留状态同步 bug |
| ⑦ | `SettingsPage.tsx:151,215` | 删除模型 target 用 `${provider}/${model}`，解析用 `split('/')` | 改用 `model:{provider}::{model}` + `'::'` 解析；删除 Provider 仍用 `provider:{name}` | BUG-F 实证：模型名可含 `/`（如 `z-ai/glm-4.7`），`split('/')` 会把模型名拦腰截断 → 删除定位错位、可能删错对象 | **实现更好**：修复路径分隔符冲突 |

> 注：差异②本次前已确认 5 处编辑历史补齐（model.api.ts / ModelModals.tsx / handler.ts / api/index.ts / Layout/index.tsx，2026-09-21），符合代码编辑历史规范。

## 五、总评与二期建议

### 5.1 总评

1. **结构骨架 100% 落地**：api 契约、types、tokens、utils 纯函数、icons 唯一出口、13 组件、路由/菜单/桶导出/3 错误枚举，全部按设计建立。
2. **行为层 7 处偏差 = 7 处"实现更好"**：本质是实际编码过程发现并修复了设计文档遗漏的 5 个真实缺陷场景（BUG-A/B/C/D/F）+ 1 个类型契约错 + 1 个 lint 合规硬约束。设计文档 v4.19 以"架构正确、类型正确"为前提静态推演，未覆盖保存中瞬时态、跨模型字段差异、路径含分隔符等运行时细节，实际实现补齐了这些。
3. **纪律合规**：全部差异均有编辑历史 + 述明原因，符合"功能只能增强、严禁退化"的代码复核纪律。

### 5.2 二期建议（含一处功能承诺恢复）

1. **恢复"切换模型保留已修改参数"的可行子集**：若需兑现 8.2.10 UX，建议二期在"前后两模型 default_params 字段集一致"且"字段名完全对齐"的前提下，才做已改参数保留 + clamp；字段集不一致时维持现实现（BUG-D 语义），并补 toast 说明。
2. **SearchBox 命中提示**：现 onSearch 命中后无 toast/告知"已定位到 X 组"，用户可能感知不到跳转，建议二期补一次 `showMessage(ErrorType.INFO, '已定位：{label}')`。
3. **删除 Provider 级联数量提示**：8.2.8 承诺弹窗显示"将级联删除所有子模型"，现确认弹窗文案已含该警示，建议二期把子模型数量动态带出（`该 Provider 下 N 个模型`）。
