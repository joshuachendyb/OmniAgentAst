## 一、目标与约束

**一句话**：暂停事件只许一个源头（HITL网关），时序由原语实现保证，不由调用方代码位置保证；本阶段先实施。

**三条约束**：
1. paused必须在阻塞等待前到达前端（确认弹窗），resumed在恢复瞬间到达—— functional correctness，不可谈判。
2. event_log append-only + seq语义不动（断线重连/回放依赖，见agent_runner.py行201-205）。
3. agent_runner通道路由表不动（thought仅落库/thought-start与chunk仅SSE/其余双写，见agent_runner.py行307-314）。

### 1.1 方案思路与取舍（v1.2新增 — 小健-2026-09-05）

**核心矛盾**：handler是async generator，"阻塞前先发射paused"依赖yield写在await之前的代码位置——这是三宗时序风险的唯一根。解决方向只有两条路：

| 方向 | 做法 | 解决什么 |
|------|------|---------|
| **方案A：统一暂停源头** | 新增网关模块，所有paused/resumed由publish直写event_log | 位置耦合、双paused、事后补发 |
| **方案B：消除generator** | handler从generator改async函数，不再yield暂停事件 | generator时序脆弱（禁return值、output参数复杂） |

**采纳方案：A+B组合**（本设计文档），理由：

1. **方案A是方案B的前提**：handler要从generator改async函数，前提是暂停事件有其他通道发出——publish提供了这个通道。没有A，B做不了。
2. **方案B是方案A的延伸**：网关落地后handler不再需要yield透传暂停事件，generator→async自然发生，输出参数方案（_verdict/_result_out/_emit_events）作废。
3. **两者不冲突，是先后关系**：步骤一二做A（publish+网关），步骤三四五做B（handler纯函数化）。[6]的实施顺序本身已包含A+B。
4. **改动面可控**：不改agent_runner路由/event_log/DB/SSE/前端，只改handler编排层。

**排除的方案**：

| 方案 | 排除理由 |
|------|---------|
| C：不改架构，加固现有代码 | 治标不治本（位置耦合是架构缺陷），下次重构必重蹈 |
| D：只做B不做A | 没有publish通道，generator→async后暂停事件无处发出，行不通 |

**与[5]的关系**：见1.2概述与八章详述。

### 1.2 与[5]的关系（概述，详见八章）

- [5]v1.6停在设计评审。本设计落地后[5]的5.2/5.3/5.4按网关API重写（输出参数方案作废）；[5]的一/三/四章架构结论不受影响。
- [5]的handler改造方案（输出参数_verdict/_result_out/_emit_events）基于"handler必须是generator"的前提——因为当时没有publish通道。[6]落地后这个前提消失，handler可直接纯函数化（步骤三四五）。

### 2.2 两条暂停通道（必须区分）

- **确认通道**（#1-#4）：confirm_id驱动，前端弹窗裁决；超时/取消语义见hitl_confirmation.py行115-155。

### 2.3 三宗时序风险（现状即bug温床）

1. **位置耦合**：paused正确性依赖"yield写在await之前"的手工顺序，任一重构挪行即违法序（如[5]v1.4曾误删paused改经_emit_events致弹窗迟到，[5]5.2.6有载）。
2. **嵌套裁决双paused**：主路paused（#1）与沙箱paused（#4）叠加，resumed配对靠嗅探`any(resumed)`（action_handler行389/401/465），脆弱。
3. **事后补发诱惑**：任何把paused收进列表事后emit的方案都直接违法序（弹窗迟到）。

## 三、总线原语：StreamBuffer.publish（10行，单写原则）

### 3.1 为什么需要总线

pull式generator管线里，"阻塞前先发射"要求阻塞帧即发射帧——这就是全部时序bug的根。有了推送通道，网关`publish(paused)`后立即可见，再安心阻塞，时序由原语保证。

### 3.2 设计（复用event_log，不另起队列）

event_log + cond + seq本身就是队列（agent_runner.py行201-205 append+seq+notify）。缺的只是生产者直写入口：

```python
# task_state.py StreamBuffer新增（示意，实施时落盘为准）
async def publish(self, step_dict: dict) -> int:
    """生产者直写：append + seq + 唤醒消费者。返回seq。
    必须async：cond.notify_all只能持锁调（同agent_runner._append行207-210，
    否则RuntimeError）；append与notify原子性照抄_append模式。"""
    step_dict["seq"] = len(self.event_log)
    self.event_log.append(step_dict)
    async with self.cond:
        self.cond.notify_all()
    return step_dict["seq"]
```

`publish`由调用方注入`buffer.publish`绑定方法（react/handlers经agent task上下文取buffer，与现有`agent_streams.get(task_id)`同源）。

### 3.3 单写原则（防双发）

一个事件只走一条路：经publish直写的Step对象打标`_published=True`，下游`async for`透传时跳过（`if getattr(e, "_published", False): continue`）。时序关键事件走publish直写；普通事件走yield透传。去重靠构造不靠事后对账。`_published`标记为过渡期机制，handler全纯函数化后yield透传消失即废除（v1.2声明 — 小健-2026-09-05）。

## 四、HITL网关：hitl_confirm（唯一暂停源头）

### 4.1 落点与复用

新模块`app/services/task/hitl_gateway.py`。复用hitl_confirmation三原语（create行87 / wait行115 / resolve行158），不重写等待/超时/取消语义（含2s轮询cancel检查行139-150、expired标记行152、finally清表行154-155）。

### 4.2 原语签名与流程（v1.2重写 — 小健-2026-09-05，示意，实施时落盘为准）

```python
async def hitl_confirm(agent, spec: ConfirmSpec, publish) -> ConfirmVerdict:
    """确认通道唯一入口。
    spec: {mode("hitl"|"bypass"), tool_name, params(原始未脱敏),
           path(可空, 为空网关内算), content, safety_level, auto_confirm(bool, 默认None由mode推导)}。
    网关内统一四件事（原分散在主路/sandbox三处，现收拢，DRY）：
      ①超时计算：hitl→security.hitl_timeout / bypass→security.auto_confirm_delay，
        钳制公式与原三处同源（confirm=max(MIN, backend-LEAD)）；
      ②trust_path提取：app.tools.trust.extract_trust_path + 回落键扫描
        （原主路_extract_trust_path与sandbox回落扫描两套，现收拢）；
      ③params脱敏：SENSITIVE_FIELDS过滤（原两处paused各做，现收拢，防调用方漏脱敏）；
      ④set_status：hitl/bypass统一 SUSPENDED→wait→EXECUTING（现状bypass路径agent
        从未变SUSPENDED，badge不翻paused，是隐患；hitl路径行411/432/449翻转，
        网关接管后调用方不再翻转 — v1.2 L1修正 — 小健-2026-09-05）。
    verdict: {"confirmed": bool, "expired": bool, "trust_session": bool, "confirm_id": str}。
    网关不管授权：grant_temp_auth归调用方按verdict做（见4.4）。
    sandbox②场景：needs_ruling+非bypass时sandbox也调网关（纯函数化），
      不再自己yield paused——"唯一暂停源头"约束要求sandbox②场景也经网关
      （v1.2 L2修正，步骤三sandbox切流覆盖 — 小健-2026-09-05）。
    import约束：本模块顶层只import叶子（steps/status_table/constants/logger）；
      hitl_confirmation/config/trust/SENSITIVE_FIELDS一律函数内延迟import，
      否则重蹈sandbox_gate顶部注释的循环import环（handlers→网关→hitl→task_runtime→task_registry→…）。"""
    from app.services.task.hitl_confirmation import (  # 延迟import防环 — 小健-2026-09-05
        create_confirmation, wait_for_confirmation_result)
    _path = spec.path or _resolve_trust_path(spec.tool_name, spec.params)  # 网关内统一
    confirm_id = await create_confirmation(agent.task_id, spec.tool_name, _path)  # path透传(v1.5 tool+path落库，P0-3)
    _safe_params = _desensitize(spec.params)  # 网关内统一脱敏
    _backend_timeout, _confirm_timeout = _resolve_timeouts(spec.mode)  # 网关内统一
    paused = agent._step_emitter.emit(MetaStep(step=agent.llm_call_count, type="paused",
        content=spec.content, confirm_id=confirm_id, tool_name=spec.tool_name,
        params=_safe_params, safety_level=spec.safety_level, severity="attention",
        trust_path=_path, auto_confirm=(spec.mode == "bypass"),
        confirm_timeout=_confirm_timeout, backend_timeout=_backend_timeout))
    set_status(agent, AgentStatus.SUSPENDED, f"等待用户确认: {spec.tool_name}")  # hitl+bypass统一（L1修正）
    await publish(paused.to_dict())               # 先to_dict再publish（P0-1：emit返回Step对象非dict）
    auth = await wait_for_confirmation_result(confirm_id, timeout=_backend_timeout)
    set_status(agent, AgentStatus.EXECUTING, "用户裁决完成")  # hitl+bypass统一恢复（L1修正）
    if auth.get("confirmed"):
        resumed = agent._step_emitter.emit(MetaStep(step=agent.llm_call_count, type="resumed",
            content=f"已确认执行: {spec.tool_name}", severity="info", confirm_id=confirm_id))
        await publish(resumed.to_dict())          # confirmed才publish（P0-2）
    # 拒绝/超时：不publish resumed（与现状一致，原来拒绝路径只发error不发resumed，
    # 前端badge不闪running）；调用方按verdict发error事件，见4.4。
    return {"confirmed": bool(auth.get("confirmed")), "expired": bool(auth.get("expired")),
            "trust_session": bool(auth.get("trust_session", False)), "confirm_id": confirm_id}
```

### 4.3 语义（从hitl_confirmation原文继承）

- 超时→`{"confirmed": False, expired: True}`；取消→`{"confirmed": False}`；entry丢失→False并告警。
- 幂等：confirm_id一次性（wait finally清表）；网关不重试，重试由调用方按verdict决策。
- bypass（auto_confirm）调用方同样走网关：paused带`auto_confirm=True`照发（前端倒计时照转），S1等待语义保留在调用方。

```python
# app/services/task/hitl_gateway.py  — 小健-2026-09-05（骨架，按4.2语义实现）
"""HITL确认唯一入口。复用hitl_confirmation三原语，不重写等待/超时/取消。"""
from typing import Optional
from app.services.agent.steps import MetaStep
from app.services.agent.status_table import set_status
from app.services.agent.constants import AgentStatus

async def _resolve_trust_path(tool_name, params) -> Optional[str]:
    from app.tools.trust import extract_trust_path        # 延迟import防环
    # 网关内统一提取（原主路_extract_trust_path + sandbox回落扫描，收拢）
    return extract_trust_path(tool_name, params) or next(
        (v for k in ("path", "file_path", "source_path", "dest_path", "target", "dir_path")
         if isinstance((v := params.get(k)), str) and v), None)

def _desensitize(params) -> dict:
    from app.services.agent.constants import SENSITIVE_FIELDS   # 延迟import防环
    return {k: v for k, v in (params or {}).items() if k not in SENSITIVE_FIELDS}

async def _resolve_timeouts(mode):
    from app.config import get_config                            # 延迟import防环
    sec = get_config().get("security", {})
    return (float(sec.get(mode + "_timeout"))
            or (float(sec.get("hitl_timeout")) if mode == "hitl" else float(sec.get("auto_confirm_delay"))))

async def hitl_confirm(agent, spec, publish):
    """spec: {mode, tool_name, params, path, content, safety_level, auto_confirm}→verdict。
    网关内统一：超时计算/trust_path/脱敏/SUSPENDED→wait→EXECUTING。"""
    from app.services.task.hitl_confirmation import (            # 延迟import防环
        create_confirmation, wait_for_confirmation_result)
    from app.services.agent.constants import HITL_TIMEOUT
    _path = spec.get("path") or await _resolve_trust_path(spec["tool_name"], spec.get("params"))
    confirm_id = await create_confirmation(agent.task_id, spec["tool_name"], _path)
    _bt, _ct = await _resolve_timeouts(spec["mode"])
    paused = agent._step_emitter.emit(MetaStep(step=agent.llm_call_count, type="paused",
        content=spec.get("content", ""), confirm_id=confirm_id, tool_name=spec["tool_name"],
        params=_desensitize(spec.get("params")), safety_level=spec.get("safety_level", ""),
        severity="attention", trust_path=_path, auto_confirm=spec.get("auto_confirm", spec["mode"] == "bypass"),
        confirm_timeout=_ct, backend_timeout=_bt))
    set_status(agent, AgentStatus.SUSPENDED, f"等待用户确认: {spec['tool_name']}")
    await publish(paused.to_dict())
    auth = await wait_for_confirmation_result(confirm_id, timeout=_bt)
    set_status(agent, AgentStatus.EXECUTING, "用户裁决完成")
    if auth.get("confirmed"):
        resumed = agent._step_emitter.emit(MetaStep(step=agent.llm_call_count, type="resumed",
            content=f"已确认执行: {spec['tool_name']}", severity="info", confirm_id=confirm_id))
        await publish(resumed.to_dict())
    return {"confirmed": bool(auth.get("confirmed")), "expired": bool(auth.get("expired")),
            "trust_session": bool(auth.get("trust_session", False)), "confirm_id": confirm_id}
```
