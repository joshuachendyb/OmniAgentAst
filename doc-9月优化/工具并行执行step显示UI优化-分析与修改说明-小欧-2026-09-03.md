## 一、问题(现象)

**工具调用时,一上来先弹出大量"参数子行"(`├─ tool 参数:{...}` + 展开三角 ▼),但此刻工具还没执行、没有结果。**

用户预期:**先看到干净的摘要头**(`🔧 调用 1 个工具 [read_file]` / `🔧 并行 6 个工具 [a, b, ...]`),**等工具真正执行完、结果就位,再展示工具子行和结果**。

此问题**单工具和并行工具都会出现**(不只是并行)。

## 二、现状(逐行代码证据)

当前 `frontend/src/features/chat/components/pipeline/ToolCallLine.tsx`:

| 代码位置 | 行为 |
|---------|------|
| L132-134 | 摘要头 `🔧 {firstLine} {attemptLabel}` **无条件渲染**;`firstLine`=集合名+`[工具列表]` |
| L136-250 | `{tools.map((t, i) => ...)}` **无条件渲染每个工具子行**(`├─/└─ tool 参数:{...}` L198-201、展开三角 L202-211);**对单工具/并行工具一律进入** |
| L214 | `{sum && (...)}` 结果摘要行,依赖 `sum`(来自 observation)→ 结果行**天然等 observation** |

现状效果:
- action 到达 → 摘要头 + 全部工具参数子行(无结果行)
- observation 到达 → 每个子行补结果行(一起出现)

## 三、病根(根本原因 — 前端渲染时机错误)

**工具子行在 action 帧一到就立刻渲染,而不是等 observation(结果)到达。**

逐行证据链:

| 层 | 代码 | 行为 |
|----|------|------|
| 解析 | `sseParser.ts:536-631` `case 'action'` | 解析 action 帧(只含 `tools` 数组 + `exec_type`),`setExecutionSteps` 追加该 step(L577)。**action 只带工具名+参数,不带结果** |
| 段构建 | `PipelineRenderer.tsx:110-112` | 见 action 帧,立即建 `{kind:'tool', action, observations:[]}` 段,交 ToolCallLine 渲染 |
| 渲染 | `ToolCallLine.tsx:136-250` | `{tools.map((t,i)=>...)}` **无条件渲染每个工具的参数子行**(L198-201 参数、L202-211 展开三角),**不检查是否有结果** |
| 渲染 | `ToolCallLine.tsx:214` | 仅结果行 `{sum && ...}` 等 observation(来自 `results`) |

**病根一句话:** `ToolCallLine` 的 `tools.map` 依赖的是 **action(`tools[i].params`),不是 observation(`results`)**,导致**参数子行抢跑在结果之前显示**。它渲染的是"将要执行的工具"而非"已有结果",在工具真正执行完(In-Progress)之前就把参数行当成完整内容弹出来。且 `tools.map` 绕开 `exec_type`,对单/并行**一律抢跑**。

## 四、病因(设计契约 / 为什么错)

observation(观察)要等工具**执行完**才有(`build_observation` 把 N 个工具结果打包成一个帧一次 emit)。但前端把"显示工具子行"与"显示工具结果"两件事**绑错在同一时间点**:

- 显示**参数子行**用的数据是 `action.tools`(action 帧一到就有)→ 被错误当作"可渲染整个工具卡片"的充分条件。
- 实际上"参数子行 + 展开三角"应属于 **"有结果才展开的内容"**,它却**没等 observation**,于是抢跑。

**结果**:
- action 帧到 → 参数子行已弹(空转占位,无结果),视觉上"一堆参数冒出来却不知道结果"。
- observation 帧到 → 结果行才补上(但参数子行早弹了),用户看到的是"先参数后结果"的割裂,而非"先摘要头、工具完成后整体呈现"。

病根与病因概括:**渲染工具子行的触发源错了(用 action 触发,应改用 observation 触发);`tools.map` 缺少 `results.length > 0` 的门控。**

## 五、目标

北京老陈要求:**action 到达只显示摘要头;工具子行(参数+结果+展开三角)等 observation 到达后一起出现。单工具与并行工具统一适用。**

(defining from 三/四:摘要头先显 → 参数子行收敛到 observation 后;并在 action 等待期补一个执行等待动画,见六。)

## 六、执行等待动画设计(北京老陈 2026-09-03 定案,UI 设计)

### 6.1 定位

行动作阶段(action 帧到、只显示摘要头)时,**摘要头下方**显示一个**执行等待动画**,提示用户"工具正在执行中";observation 帧到后**动画结束**,并在动画让出的同一位置**开始显示工具子行**(动画消失的位置被子行占据——"盖住动画")。

参考 thought 等待光标(`.waiting-cursor`),但**图标样式 + 颜色更换**:
- thought 光标:缺口圆弧 SVG + 绿 `#52c41a`。
- 本动画:**齿轮+扳手组合旋转** + 橙 `#fa8c16`。

### 6.2 位置绑定(局部挂 tool 段,非全局末段)

区分 thought 等待与工具执行等待的挂载点:

| | thought 等待光标 | 本工具执行等待动画 |
|--|-----------------|------------------|
| 挂载位置 | `PipelineRenderer.tsx:302-322` 全局**末段之下** | **tool 段内摘要头下方**(ToolCallLine 内部) |
| 生命周期 | 整条流水线 streaming 判断 | 与该 action→observation 段绑定 |
| 结束/覆盖 | 首 chunk 到 → 内容覆盖 | observation 到 → 子行盖住动画位置 |

本动画**不放全局末段**,而是**嵌套在 ToolCallLine 摘要头之后、工具子行容器之前**,与 `results.length` 门控同一触发点。

### 6.3 触发与门控

- `results.length === 0`(action 已到、observation 未到)→ **显示执行等待动画**。
- `results.length > 0`(observation 到)→ **动画消失**,工具子行(参数+结果+展开)在同一位置渲染,"盖住"动画。

### 6.4 图标与颜色规格

| 项 | 规格 |
|----|------|
| 图标 | 齿轮+扳手组合(SVG 双 path 放同一 `<g>`,整体旋转),齿轮=执行中、扳手=操作中,语义更明确 |
| 颜色 | `#fa8c16`(橙,区别于 thought 绿 `#52c41a`) |
| 尺寸 | 1.4em≈20px(与 thought 一致) |
| 动效 | 复用 `waiting-spin` 逆时针 1s 线性,渲染为旋转 |
| 排版 | 居中、无 margin/padding(同 thought,让位给子行覆盖) |

### 6.5 结束/覆盖行为

observation 到 → `results.length>0` → 动画节点卸载(`===0` 分支不再渲染)+ 子行容器在同位置渲染 → **动画让出的位置被工具子行盖住**,无闪烁、无常驻(同 thought"内容覆盖接管,禁止常驻"原则)。

## 八、边界确认

- 单工具(`exec_type=single`,`tools=["read_file"]`):action 只显"调用 1 个工具 [read_file]"+齿轮+扳手组合动画,observation 到才显 `└─ read_file 参数...`
- 并行多工具(`exec_type=multi`,N>1):action 只显"并行 N 个工具 [a,b,...]"+齿轮+扳手组合动画,observation 到才显 N 个子行(最后一个 `└─`,其余 `├─`)
- 无 observation(`results=[]`):子行不出现,防浮空参数行;动画保持(工具一直执行中/异常未回)
