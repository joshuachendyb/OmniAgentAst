## 一、背景

1. 任务信息块第一行`TaskInfoBar.tsx:130-228`长期被误读：`耗时1963s 步骤8/轮次2 本轮T(P/C) | 本任务累计T(P/C) 上下文295tok`各段含义与来源未显性文档化。
2. 实时任务`receiving=true`（SSE流式中）时，用户在左侧`TaskListPanel.tsx:99`点击历史任务，原链路**故意不`disconnect` SSE**以保活后台进度，但`detail`/`frames`/`executionSteps`/`metaFrames`/`liveErrorText`/`topbarTokens`的隔离与竞态未硬化，导致闪烁、串味、误报。

本报告：先正名第一行，再给出切历史的全链路证据与漏洞清单，最后给6处最小修复设计（先文档后代码）。

## 五、设计原则（经v1.0→v1.2 3轮三堂会审）

- **不中断后台**：切历史**不`disconnect`**，保活是特性非bug，仅硬化隔离与节流（`YAGNI`不加新重试层）。
- **最小最直接**：只在`detail/frames`边界加守卫与清空，不引新框架/状态机（`KISS-DIRECT`直线、`SLAP`同层、`DRY`复用既有`isCurrentLive`）。
- **职责边界**：`LIVE: frames/steps/metaFrames/SSE` vs `HISTORY: detail/historySteps`，二者`detail`优先互不越界（`禁止backward`不加兼容开关）。

## 六、修复方案（6处最小硬化，按漏洞编号）

### 6.1 `useTaskSelection.ts:28-44` — V2+V3+V11

改法：
```diff
 const handleSelectTask = (id:string|null) => setActiveTaskId(id)
 useEffect(()=>{
   if(!activeTaskId || activeTaskId===serverTaskId){ setSelectedDetail(null); return }
+  setSelectedDetail(null); // 乐观清空防闪旧 V2
+  const ac = new AbortController()
-  getTaskDetail(id).then(...).catch(()=>setSelectedDetail(null))
+  getTaskDetail(id,{signal:ac.signal}).then(...).catch(e=>{
+    if(e.name==='AbortError') return
+    setSelectedDetail(undefined as any) // 失败不回落直播，交骨架 V3
+  })
+  return ()=>ac.abort() // V11 真 abort
 },[activeTaskId,serverTaskId])
```

效果：点历史即空，失败显骨架不串直播，网络真取消。

关联核查：`RightViewer`不再读`null`回落的`frames`，`TaskInfoBar`见`detail===undefined`显`Skeleton`。

### 6.2 `RightViewer.tsx:62,107,179` — V4+V5+V6

改法：
```diff
- const isCurrentLive = active===server && receiving
+ const isCurrentLive = (active===server && receiving) || (receiving && !server && !active) // V6 间隙判活：加括号明确优先级
  useEffect(()=>{
+  if(!isCurrentLive) setHistorySteps([]) // V4 同步清空防闪
   if(!active||isCurrentLive){ setDetail(null); return }
  },[active,isCurrentLive])
- {liveErrorText && <Alert ...>}
+ {liveErrorText && isCurrentLive && <Alert ...>} // V5 历史不泄漏
```

### 6.3 `useChainTokens.ts:39,54 + useChatPanels.tsx:152` — V9

改法：顶栏仅`active===server`直播时跟`metaFrames`，历史时保持DB值。
```diff
- useEffect(()=>{ if(metaFrames.session) setSession(metaFrames.session) },[metaFrames])
+ useEffect(()=>{ 
+   if(activeTaskId===serverTaskId && activeTaskId!==null) {
+     setSession(metaFrames.session) 
+   }
+   // else: 历史时不覆盖，保持DB值
+ },[metaFrames,activeTaskId,serverTaskId])
```

### 6.4 `TaskInfoBar.tsx:92-111 + useTaskInfo.ts:52` — V8+V3

改法：区分`null`（未选/直播）与`undefined`（拉失败）：
```diff
- if(detail) return {overview:'',...} // 旧：null与undefined同回落直播
+ if(detail != null) return {...} // 历史成功：取detail（松散相等排除null/undefined）
+ if(detail === undefined) return {badge:'unknown', overview:'', truncatedTip:null, processEvents:[], ...} // 拉失败：显骨架不回落 V3
- startRef.current = frames.startTimestamp || Date.now()
+ if(frames.startTimestamp && startRef.current) startRef.current = frames.startTimestamp // 迟到校正 V8
```

### 6.5 `TaskListPanel.tsx:50 + ChatPage.tsx:85` — V12+V7+V5

改法：
```diff
- useEffect(()=>anchorRef.current?.scrollIntoView(),[latestTaskId])
+ useEffect(()=>{ if(active===latestTaskId || (receiving&&active===server)) anchorRef.current?.scrollIntoView() },[latestTaskId,active])
- const handleSelectTaskOpenRight = id=>{ setRightOpen(true); handleSelectTask(id) }
+ const handleSelectTaskOpenRight = id=>{ setRightOpen(true); setLiveErrorText(null); handleSelectTask(id) } // V5 清红条
 // V7 新消息拽回：若 active为历史且非用户显式“跟随直播”，不自动 setActive=server，保留历史视图
```

### 6.6 `useSSE.ts:352 + useSSE.ts:573` — V1 保活节流

改法：保持SSE后台保活不中断，仅节流防`O(n)`：
```diff
- saveStepsToStorage(steps) // 每chunk写
+ // 节流：每20步或2s写一次，历史页仍增量但不刷爆 sessionStorage（空数组不写）
+ if(steps.length > 0 && steps.length % 20 === 0) saveStepsToStorage(steps)
- idleTimeout = setTimeout(reconnect, 60000) // 闭包读isReceiving旧值
+ idleTimeout = setTimeout(()=>{ if(serverTaskIdRef.current) reconnect() }, 60000) // 用ref读最新 V1
```

> 6处均为`if/else`守卫与`setState(null/[]) + AbortController/节流`，无新重试层、无兼容开关，符合`KISS-DIRECT/禁止backward`。
