### 第2遍：取消/暂停/恢复安全性

```
  → set_cancelled(task_id) → running_tasks[task_id]["cancelled"] = True
  → ai_service.cancel() → 该任务 snapshot 的 _cancelled = True（不影响其他任务）
```

```
断线: CancelledError → agent 后台继续 → buffer.done.set()
重连: GET /chat/stream/{task_id}?after_seq=N → get_stream_buffer(task_id)
  → stream_reader(buffer, task_id, after_seq=N) → 重放事件
心跳: stream_reader 超时 → yield `HEARTBEAT_INTERVAL + ": ping\n"`（M3）→ 前端忽略
```

**验证**: 心跳不进入 event_log，不影响 after_seq 重连 ✅

### 第4遍：DB 并发安全性

```
Task A: db.get_conn("chat") → allocate_and_insert_message() → append_execution_step() → conn.close()
Task B: db.get_conn("chat") → allocate_and_insert_message() → append_execution_step() → conn.close()
```

**验证**: SQLite WAL 模式允许并发读，单写串行化，busy_timeout=30s 足够 ✅

### 第5遍：资源泄漏检查

```
httpx.AsyncClient: 模块级管理，进程退出时 close
BaseAIService: 每任务 snapshot() 独立创建，任务结束时无引用→GC 回收
LLMClient: 复用共享连接池，请求结束时无引用→GC 回收
_stream_buffer: call_later(300) 延迟回收
running_tasks: task_cleanup() 正常清理，cancelled 1h 后清理
inbox 队列(B机制): 随任务终态一并清理（13.4.1），无独立生命周期
```

**验证**: 无资源泄漏 ✅（已按 B 机制 13.4 更新，废弃 `_session_semaphores`）

## 十二、多会话并行任务必要性分级与新方案骨架（补充）—— 小欧 2026-09-20

> **术语（北京老陈 2026-09-20 定）**：本文档目标 = **「多会话并行任务」**：每个会话各自持有任务，**跨会话并发执行**；同一会话内**维持串行续聊**（linked 链），不放开同会话并发。

### 12.5 与 [55] 原设计的差异（四点）

1. **跨任务文件冲突检测 X2** 由 L1 低危 **提升为最高优先级**，做成核心模块 `file_write_arbiter`（锁 + 登记 + 排队），不再混在 Phase2 里排后

```python
- 线程安全: threading.Lock 保护登记表(sync 工具在 asyncio 事件循环线程内以同步调用执行, 线程锁正确)。
- 不强制阻断: 冲突时返回占用者 (task_id, acquired_at), 调用方按策略处理, arbiter 绝不自动覆盖。
小欧 2026-07-05(参考 file_state 既有持久口径) / 2026-09-20 扩展
"""
import threading
import time as _time
from pathlib import Path
from typing import Dict, Optional, Tuple

from app.logger import logger

# {resolved_path_str: {"task_id": str, "acquired_at": float}}
_write_claims: Dict[str, Dict] = {}
_claims_lock = threading.Lock()


def acquire_write(file_path: str, task_id: str) -> Optional[str]:
    """登记文件正被 task_id 写入 → 返回 None=登记成功(无冲突); str=冲突, 返回占用者 task_id — 小欧 2026-09-20"""
    key = str(Path(file_path).resolve())
    with _claims_lock:
        holder = _write_claims.get(key)
        if holder is not None and holder["task_id"] != task_id:
            return holder["task_id"]
        _write_claims[key] = {"task_id": task_id, "acquired_at": _time.time()}
        return None


def release_write(file_path: str, task_id: str) -> None:
    """任务写完释放登记(仅释放本人占用, 防跨任务误删) — 小欧 2026-09-20"""
    key = str(Path(file_path).resolve())
    with _claims_lock:
        holder = _write_claims.get(key)
        if holder is not None and holder["task_id"] == task_id:
            del _write_claims[key]


def who_writes(file_path: str) -> Optional[Tuple[str, float]]:
    """查询当前占用者(task_id, acquired_at), 无占用返回 None — 小欧 2026-09-20"""
    key = str(Path(file_path).resolve())
    with _claims_lock:
        holder = _write_claims.get(key)
        if holder is None:
            return None
        return (holder["task_id"], holder["acquired_at"])


__all__ = ["acquire_write", "release_write", "who_writes"]
```

### 13.4 P3：X5/X6 同会话串行化闸门 + 运行中注入（B 机制，北京老陈 2026-09-20 定案）

**设计**（12.7 ③会话内串行、会话间并行；**2026-09-20 北京老陈定案：同会话已有活跃任务时，新消息「注入当前任务 loop」（机会②：每轮 LLM 调用前合并），不是排队也不是拒绝**）：

- 同会话**同时只跑一个任务**（L5 语义：1 串行，弃 3 并发）。
- 任务执行中新消息：**不新建任务**，写入当前活跃任务的 **inbox 队列**（可多条）。
- agent 在**每一轮 LLM 调用前**（`react_step.py` `prepare_messages_for_llm()` 之前）把 inbox 积压的 **N 条新 user 消息一并 `add_user_message` 进对话历史**，本轮 LLM 请求自然带上——覆盖**所有轮**（工具轮+answer 轮+重试轮），answer 终态轮也不漏。
- **机制边界**（确认接受）：工具执行期间来的新消息**不能打断当前工具**（文件写一半没法收），等该工具跑完、进入下一轮 LLM 前被吸收。LLM 生成中来的新消息同理，等本轮生成结束、下一轮 LLM 调用前才可见（机会②在 LLM 前合并，天然满足）。
- 无活跃任务时：走正常新建任务路径（不受影响）。
- 跨会话互不等待、并行执行。
