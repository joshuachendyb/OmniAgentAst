## 二、高风险问题（必须修复）

### H1. 硬编码fontSize 13px游离于设计系统之外

**文件**: `ToolCallLine.tsx`

**问题描述**: stepStyles.ts定义FontSize只有14/12/11/10四档，但ToolCallLine多处硬编码`fontSize: 13`，无任何常量支撑。与全局14/12二档体系冲突，扫视时13px与14px肉眼难辨但与12px又拉不开层级。

**涉及位置（6处）**:
- `:183` 根容器 `fontSize: 13`
- `:301` 工具子行 `fontSize: 13`
- `:332` 结果摘要行 `fontSize: 13`
- `:382` 被拒工具行 `fontSize: 13`
- `:212` / `:226` 占位提示 `fontSize: 12`（这个对了，但与上方13px不统一）

**风险等级**: 高 — 视觉扫描时字号层次混乱，违反M2定案（全链仅14/12二档）

**优化方案**:
1. 将所有`fontSize: 13`统一改为`FontSize.SECONDARY`(12)或`FontSize.PRIMARY`(14)
2. 推荐：工具行主体用`FontSize.PRIMARY`(14)，参数摘要用`FontSize.SECONDARY`(12)
3. 同步修改lineHeight计算，确保`lineHeight = fontSize + Spacing.XS`

---

### H2. 静态统计块大量魔法数字未经令牌化

**文件**: `StaticStatsBlock.tsx`

**问题描述**: 10处硬编码数值不在Spacing/FontSize枚举中，属于设计系统外溢出。

**涉及位置**:

| 行号 | 硬编码值 | 应使用常量 |
|------|---------|-----------|
| :49 | `marginTop: 10` | `Spacing.LG`(12) 或 `Spacing.MD`(8) |
| :52 | `paddingTop: 8` | `Spacing.MD` |
| :123 | `marginTop: 6` | `Spacing.SM`(6) |
| :175 | `marginTop: 4` | `Spacing.XS` |
| :189 | `fontSize: 11` | `FontSize.CAPTION` 或 `FontSize.SMALL` |
| :235 | `marginTop: 4` | `Spacing.XS` |
| :272 | `gap: 8` | `Spacing.MD` |
| :273 | `marginTop: 2` | 无对应常量(需确认) |
| :313 | `gap: 8` | `Spacing.MD` |
| :344 | `fontSize: 11` | `FontSize.CAPTION` |

**风险等级**: 高 — 修改任意间距时极易遗漏同步，且10/2/6等值不在Spacing枚举中

**优化方案**:
1. 将所有硬编码值替换为Spacing/FontSize常量
2. 对于`marginTop: 2`这种极小间距，可考虑在stepStyles.ts新增`Spacing.XXS: 2`常量
3. 对于`fontSize: 11`，确认是用`FontSize.CAPTION`(10)还是`FontSize.SMALL`(11)

---

### H3. 折叠箭头三种视觉风格不统一

**涉及文件**: CollapsibleText.tsx、ToolCallLine.tsx、TitleBlock.tsx

**问题描述**: 三处折叠按钮视觉语言完全不一致，用户无法建立统一的"可折叠"视觉心智模型。

| 组件 | 折叠实现 | 颜色 | 大小 | 交互态 |
|------|---------|------|------|--------|
| **CollapsibleText** (:66-103) | `Typography.Link` | AntD默认蓝 | 12px文字 | 下划线hover |
| **ToolCallLine** (:312-322) | `CircleArrow` | `Colors.TEXT.PRIMARY`灰 | 20px | 无glow |
| **TitleBlock** (:120-125) | `CircleArrow` | 默认蓝 | 24px | `glow` |

**风险等级**: 高 — 同一页面三种折叠样式，用户认知混乱

**优化方案**:
1. **统一使用CircleArrow组件**，废弃CollapsibleText中的Typography.Link
2. **统一颜色规范**: 建议全部使用`Colors.PRIMARY`(蓝)或`Colors.TEXT.PRIMARY`(灰)
3. **统一尺寸规范**: 建议工具行20px、标题行24px、正文折叠行16px（按层级递减）
4. **统一交互态**: glow效果仅用于标题级折叠，工具行/正文行不用

## 三、中风险问题（建议修复）

### M1. 工具调用行信息冗余

**文件**: `ToolCallLine.tsx:106-110,306`

**问题描述**: 收起态展示两层工具名：
```
🔧 调用 1 个工具  [read_file]        ← 第一层：collectionLabel
   ├─ read_file  参数：{"path":"..."}  ← 第二层：branch + 工具名
```

单工具场景下工具名出现两次，视觉冗余。并行多工具时第一层有意义，但单工具时可以简化。

**风险等级**: 中 — 不影响功能，但视觉冗余

**优化方案**:
1. 单工具时省略第一层collectionLabel，直接显示工具子行
2. 多工具时保留第一层显示"并行 N 个工具"
3. 或统一将第一层改为更简洁的描述（如"工具调用"）

---

### M2. 等待图标尺寸未显式约束

**文件**: `WaitingIcons/index.tsx`

**问题描述**: 三个等待图标尺寸控制方式不一致。

| 图标 | CSS尺寸 | SVG viewBox |
|------|---------|------------|
| ThoughtWaitingIcon | `1.4em` (组件内联) | 24x24 |
| ToolWaitingIcon | CSS类 `.tool-waiting-cursor` 1.1em | 24x24 |
| ActionWaitingIcon | `1.4em` (组件内联) | 36x36 |

**风险等级**: 中 — Thought和Action是1.4em，Tool是1.1em，且Tool的尺寸由CSS类控制而非组件props

**优化方案**:
1. 统一三个图标为相同尺寸（推荐1.4em或新增size prop）
2. 将ToolWaitingIcon的尺寸控制从CSS类移入组件props，保持一致性
3. 在stepStyles.ts新增`IconSize`常量统一管理

---

### M3. StatusLine错误样式单薄

**文件**: `StatusLine.tsx:27-36`

**问题描述**: StatusLine仅有红字+无背景，在流水线中视觉冲击力不足。

```tsx
<div style={{ color: Colors.ERROR, fontSize: FontSize.TERTIARY, margin: stepMargin(false) }}>
  ⚠️ {step.error_message || ...}
</div>
```

对比StaticStatsBlock的错误警示条（:373-384）有`ERROR_BG`背景 + `ERROR_BORDER`边框 + `borderRadius:4`。

**风险等级**: 中 — 错误信息容易被上下的thinking/tool段淹没

**优化方案**:
1. 给StatusLine增加`ERROR_BG`背景和`ERROR_BORDER`边框
2. 与StaticStatsBlock错误条样式对齐，保持错误视觉语言统一
3. 可考虑加左侧红色竖线增强视觉锚点

---

### M4. 打字机光标与思考光标视觉风格迥异

**涉及文件**: ThinkingStream.tsx、TextStream.tsx

**问题描述**: 两种光标代表"LLM在思考"和"LLM在输出"，但视觉语言差异过大。

| 组件 | 光标类型 | 视觉效果 |
|------|---------|---------|
| **ThinkingStream** | `thinking-cursor` | 灰色`▍`闪烁(50%透明度交替) |
| **TextStream** | `ActionWaitingIcon` | 蓝色核心圆+双层波纹扩散(1.8s) |

**风险等级**: 中 — 不像同一系统的组件

**优化方案**:
1. 方案A：保持差异（灰色闪烁=思考中，蓝色波纹=输出中），但在文档中明确设计意图
2. 统一为同色系（如思考光标改蓝色闪烁），保持"LLM活动中"的统一视觉语言
3. 建议保持现状但补充设计说明，因为两种状态确实需要区分

---

### M5. observation行缺少视觉边界

**文件**: `PipelineRenderer.tsx:425-436`

**问题描述**: observation行仅绿色文字+emoji，无左侧线、无背景、无边框。

```tsx
<div style={{ color: Colors.SUCCESS, fontSize: FontSize.TERTIARY, lineHeight: ..., margin: stepMargin(false) }}>
  📋 {seg.step.summary || seg.step.content || ''}
</div>
```

在复杂流水线中（多个tool+obs交替），绿色文字容易与上方ToolCallLine的结果摘要绿色混淆。

**风险等级**: 中 — 视觉分界不清晰

**优化方案**:
1. 增加左侧绿色竖线（与流水线容器左线对齐）
2. 或增加极浅绿色背景（如`rgba(82, 196, 26, 0.06)`）
3. 或在observation前增加"结果:"前缀增强语义

### H3. CollapsibleText 折叠链接 → CircleArrow组件

**问题描述**: CollapsibleText用Typography.Link蓝色文字，ToolCallLine用灰色CircleArrow，TitleBlock用蓝色发光CircleArrow，三种折叠样式不统一。

**改什么文件**: `CollapsibleText.tsx`

**改什么代码**: Typography.Link替换为CircleArrow

**怎么改**:

```tsx
// ===== 改前（:66-103）=====
{overflow && !expanded && (
  <Typography.Link
    onClick={(e) => { e.stopPropagation(); setExpanded(true); }}
    onKeyDown={...}
    style={{ fontSize: 12, marginLeft: 8 }}
  >
    展开全文
  </Typography.Link>
)}
{overflow && expanded && (
  <Typography.Link
    onClick={(e) => { e.stopPropagation(); setExpanded(false); }}
    onKeyDown={...}
    style={{ fontSize: 12, marginLeft: 8 }}
  >
    收起
  </Typography.Link>
)}

// ===== 改后 =====
{overflow && (
  <span
    role="button"
    tabIndex={0}
    aria-expanded={expanded}
    onClick={(e) => { e.stopPropagation(); setExpanded(!expanded); }}
    onKeyDown={(e) => {
      if (e.key === 'Enter' || e.key === ' ') {
        e.preventDefault();
        e.stopPropagation();
        setExpanded(!expanded);
      }
    }}
    style={{ cursor: 'pointer', marginLeft: Spacing.SM }}
  >
    <CircleArrow
      size={16}
      color={Colors.PRIMARY}
      expanded={expanded}
      animated={false}
    />
  </span>
)}
```

**import补充**:
```tsx
import { CircleArrow } from '@/components/CircleArrow';
import { Colors, Spacing } from '@/utils/stepStyles';
```

### M5. PipelineRenderer observation行 → 与ToolCallLine对齐，去掉emoji，改灰色

**问题描述**: observation行（📋绿色文字）与ToolCallLine（🔧工具行+分支线+绿色结果摘要）视觉不对齐、颜色混淆、层级混乱。observation作为工具执行结果的"补充说明"，应与ToolCallLine形成视觉整体。

**当前视觉结构**（问题）：
```
│ 🔧 调用 1 个工具 [read_file]
│    ├─ read_file 参数：{"path"...}
│    └─ ✔ 文件读取成功...
│ 📋 文件读取成功，内容为空...      ← observation：📋与🔧大小不一致，
│                                      绿色与结果摘要混淆，缩进不对齐
```

**优化后视觉结构**：
```
│ 🔧 调用 1 个工具 [read_file]
│    ├─ read_file 参数：{"path"...}
│    └─ ✔ 文件读取成功...
│       文件读取成功，内容为空...    ← observation：灰色，与└─同缩进，
│                                      作为结果摘要的补充说明
```

**改什么文件**: `PipelineRenderer.tsx`

**改什么代码**: observation段的style和内容

**怎么改**:

```tsx
// ===== 改前（:425-436）=====
<div
  key={`obs-${i}-${seg.step.step ?? i}`}
  style={{
    color: Colors.SUCCESS,
    fontSize: FontSize.TERTIARY,
    lineHeight: `${FontSize.TERTIARY + Spacing.XS}px`,
    margin: stepMargin(false),
  }}
>
  📋 {seg.step.summary || seg.step.content || ''}
</div>

// ===== 改后 =====
<div
  key={`obs-${i}-${seg.step.step ?? i}`}
  style={{
    color: Colors.TEXT.SECONDARY,        // 灰色，与绿色结果摘要区分
    fontSize: FontSize.SECONDARY,        // 12px，与ToolCallLine子行一致
    lineHeight: `${FontSize.SECONDARY + Spacing.XS}px`,
    margin: stepMargin(false),
    paddingLeft: Spacing.SM,             // 与ToolCallLine工具子行同缩进
  }}
>
  {seg.step.summary || seg.step.content || ''}   // 去掉📋 emoji
</div>
```
