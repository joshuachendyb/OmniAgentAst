## 一、问题背景

在"前后端业务数据配合优化分析"文档中，我们解决了架构分层问题（业务层/转换层/SSE层）。

但还有一个数据层问题需要解决：**Step/Meta的数据结构一致性**。

核心问题：
1. MetaStep承载过重，type="error" 承载6种子类型
2. 统计类信息（usage/stats/final_stats/context_overview）混在MetaStep中
3. severity级别不规范（info/warn/attention）
4. 字段命名不一致（error_type在MetaStep是kwargs，在FinalStep是属性）

---

## 二、当前Step类型体系

### 2.1 Step继承体系

```
ReasoningStep (ABC)           -- 基类
├── MetaStep                  -- 运行时元事件 (TYPE 动态, IS_DONE=False)
├── ThoughtStep               -- 思考 (TYPE="thought", IS_DONE=False)
├── ThoughtStartStep          -- 思考开始信号 (TYPE="thought-start", IS_DONE=False)
├── StartStep                 -- start 完整任务契约 (TYPE="start", IS_DONE=False)
├── ActionStep                -- 工具执行前信号 (TYPE="action", IS_DONE=False)
├── ObservationStep           -- 工具执行结果 (TYPE="observation", IS_DONE=False)
├── ChunkStep                 -- LLM 流式文本片段 (TYPE="chunk", IS_DONE=False)
├── FinalStep                 -- 最终回答/终态 (TYPE="final", IS_DONE=True)
└── ErrorStep                 -- 错误 (TYPE="error", IS_DONE=True) ← 已废弃
```

### 2.2 各Step类型用途

| Step类型 | TYPE值 | IS_DONE | 用途 | 数据来源 |
|---------|--------|---------|------|---------|
| StartStep | `"start"` | False | 任务开始契约 | react_cycle |
| ThoughtStartStep | `"thought-start"` | False | 思考开始信号（仅SSE） | handler |
| ThoughtStep | `"thought"` | False | 思考内容（仅落库） | handler |
| ActionStep | `"action"` | False | 工具执行前信号 | action_handler |
| ObservationStep | `"observation"` | False | 工具执行结果 | action_handler |
| ChunkStep | `"chunk"` | False | LLM流式文本（仅SSE） | llm_stream |
| MetaStep | 动态 | False | 运行时元事件 | 多处 |
| FinalStep | `"final"` | True | 最终回答/终态 | handler |
| ErrorStep | `"error"` | True | 错误（已废弃） | - |

## 四、核心问题分析

### 4.1 问题一：MetaStep承载过重

**当前状态**：`type="error"` 承载6种语义

**问题**：
- 一个type值承载6种语义，前端需要通过error_type再判断
- 逻辑复杂，容易出错
- 违反KISS-DIRECT原则

**影响**：前端代码复杂度高，需要多层判断

### 4.2 问题二：统计类信息混在MetaStep

**当前状态**：`usage`、`stats`、`final_stats`、`context_overview` 都用MetaStep承载

**问题**：
- 这些是**数据报告**，不是**事件通知**
- 前端需要根据type值再区分是事件还是数据
- 混在一起导致语义不清

**影响**：前端解析逻辑复杂，数据结构不清晰

### 4.3 问题三：severity级别不规范

**当前状态**：severity值有三种
- `"info"` → 信息
- `"warn"` → 警告
- `"attention"` → 关注

**问题**：
- `"attention"` 不是标准severity级别
- 与 `"warn"` 语义重叠

**影响**：前端展示逻辑不统一

### 4.4 问题四：字段命名不一致

| 字段 | MetaStep | FinalStep | 问题 |
|------|---------|-----------|------|
| `error_type` | kwargs透传 | `_error_type` | ⚠️ 命名不一致 |
| `error_message` | kwargs透传 | `_error_message` | ⚠️ 命名不一致 |
| `severity` | kwargs透传 | 无 | ⚠️ MetaStep有，FinalStep没有 |
| `confirm_id` | kwargs透传 | 无 | ⚠️ 仅MetaStep有 |

**影响**：前端解析逻辑不统一，需要针对不同Step类型做特殊处理

## 五、优化方案

### 5.1 MetaStep type值归一化

**当前10种type值 → 优化后8种**

| type值 | 语义 | 是否保留 |
|--------|------|---------|
| `"error"` | 通用错误 | ❌ 拆分为具体type |
| `"blocked"` | 安全拦截 | ✅ 新增 |
| `"timeout"` | 超时 | ✅ 新增 |
| `"user_rejected"` | 用户拒绝 | ✅ 新增 |
| `"invalid_action"` | 无效action | ✅ 新增 |
| `"empty_response"` | 空响应 | ✅ 新增 |
| `"chunk_buffer_timeout"` | 响应累积超时 | ✅ 新增 |
| `"resumed"` | 恢复执行 | ✅ 保留 |
| `"paused"` | 暂停等待确认 | ✅ 保留 |
| `"retrying"` | 重试通知 | ✅ 保留 |
| `"truncated"` | 截断通知 | ✅ 保留 |

**删除的type值**：
- `"usage"` → 独立为UsageStep
- `"stats"` → 独立为StatsStep
- `"final_stats"` → 独立为FinalStatsStep
- `"context_overview"` → 独立为ContextOverviewStep

### 5.2 新增Step类型

```python
class UsageStep(ReasoningStep):
    """LLM token消耗报告"""
    TYPE = "usage"
    # 字段：prompt_tokens, completion_tokens, total_tokens, 
    #        task_accumulated_tokens, session_accumulated_tokens, chain_accumulated_tokens

class StatsStep(ReasoningStep):
    """流式统计"""
    TYPE = "stats"
    # 字段：step_count, llm_call_count, retry_count, duration

class FinalStatsStep(ReasoningStep):
    """终态统计"""
    TYPE = "final_stats"
    # 字段：duration, artifacts, final_status

class ContextOverviewStep(ReasoningStep):
    """上下文概览"""
    TYPE = "context_overview"
    # 字段：message_count, estimated_tokens, truncated, injected_ratio
```

### 5.3 统一severity级别

| 当前 | 优化后 | 语义 |
|------|--------|------|
| `"info"` | `"info"` | 信息 |
| `"warn"` | `"warning"` | 警告 |
| `"attention"` | `"warning"` | 关注（合并为warning） |

### 5.4 统一字段命名

| 字段 | MetaStep | FinalStep | 统一后 |
|------|---------|-----------|--------|
| `error_type` | kwargs透传 | `_error_type` | 统一为 `error_type` |
| `error_message` | kwargs透传 | `_error_message` | 统一为 `error_message` |
| `severity` | kwargs透传 | 无 | 所有Step都支持 |
| `confirm_id` | kwargs透传 | 无 | 所有Step都支持 |

## 六、优化效果

| 维度 | 当前 | 优化后 |
|------|------|--------|
| MetaStep type值 | 10种（混乱） | 8种（清晰） |
| 统计类信息 | 混在MetaStep | 独立Step类型 |
| severity级别 | 3种（不规范） | 2种（标准） |
| error_type子类型 | 6种混在type="error" | 独立type值 |
| 前端判断逻辑 | 复杂（先type再error_type） | 简单（单层type） |
| 字段命名 | 不一致 | 统一 |
