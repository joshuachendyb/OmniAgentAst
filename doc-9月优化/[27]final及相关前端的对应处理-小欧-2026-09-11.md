## 一、问题说明

### 1.1 北京老陈的两项调整决定

| 序号 | 决定 | 说明 |
|------|------|------|
| ① | **final 事件加 `duration` 字段** | `float`，取 `now - _run_start_ts`，与 DB 落库 duration **同源**；是前端唯一可得的运行时长**实时源** |
| ② | **final_stats 不能和 final 一起发** | final_stats 含统计计算；必须等统计信息**全部完成、每个地段都有信息后**才发 |

### 1.2 现状与问题（代码实据）

**（1）final 事件字段全清单（现状 17 键）** —— 基类 `type/step/timestamp/content`（`base.py:79-87`）+ `FinalStep._extra_fields`（`final_step.py:114-130`）：

|---|------|------|------|---------|

前端 sseParser final_stats 分支期望键（`sseParser.ts:364-375`）：duration / tool_stats / artifacts / final_status / retry_count —— **`tool_stats` 与 `retry_count` 后端不发 → 解析恒 undefined**。

**（3）final 无 duration** —— 由（1）表：final 17 键无运行时长；现状运行时长唯一实时源是 final_stats.duration（且与 final 同拍发）。前端收 final 无法立即得运行时长。

**（4）final 与 final_stats 背靠背同拍 publish** —— `step_emitter.emit_final_with_stats`（`step_emitter.py:61-67`）返回 `(final, stats)` 二元组，调用点连续两条 publish：
- `react_loop.py`：L151-152、L195-196、L225-226、L260-261、L285-286（5 处）
- `react_step.py`：L426-427、L480-481（2 处）
- handler 4 处经 `_events` extend 后由 `react_loop.py:211-212` 逐条 publish

即 final_stats 与 final **同刻实时流出**；且此时**只组装了 duration/artifacts/final_status 三块真值**，tool_stats/llm_call_count/retry_count/step_count 根本没组装就发——**残缺组装即发**（判定违规，见 2.2 发布铁律（0））。

**（5）异常/取消/守卫路径无 final_stats** —— `agent_runner.py:451-455`（异常 final）、`:501-513`（守卫 final）只发 final，不发 final_stats → final_stats 仅正常路径有，失败/取消/守卫路径折叠统计永不出现。

**（6）竞态根因回顾** —— 前端收 final 实时 → 立刻 REST `getTaskDetail` → DB `update_task` 未落 → 读到 stale `executing`/旧时长（此前诊断文档实证）。

### 1.3 三思三省：本设计必须规避的 4 个坑

| # | 坑 | 规避设计 |
|---|----|---------|
| 1 | final 各构造点漏传 duration → 前端读 undefined | `step_emitter.emit` 的 FinalStep 分支统一防御注入（外部已传不覆盖），一处覆盖全构造点 |
| 2 | completed 短信号剥离版（`agent_runner.py:399-400`）只留 4 键 → 重连回放无 duration | 剥离键集合补 `"duration"` |
| 3 | final_stats 移出 react_loop 后，旧"原位覆写"逻辑（`_final_stats_publish_index` L247、收集 L405-410、覆写 L615-617）全部变死码，残留必致 bug | 全删（禁 backward），final_stats 改由 runner 延后单发 |
| 4 | 异常/取消/守卫路径必达 final_stats（字段空数组也发），否则折叠详情永不补全 | runner 统一收口单点发布，全路径调用 |

## 二、后端优化方案

### 2.1 final 加 duration

- **字段**：`final.duration: float`，值 `round(time.time() - telemetry._run_start_ts, 1)`，与 `agent_telemetry.py:207` 同式、与 DB `update_task` 同源。
- **注入时机**：`step_emitter.emit` 的 FinalStep 分支（与既有 `accumulated_usage`/三层 token 注入同模式），外部已传不覆盖；telemetry 缺失/无 `_run_start_ts` 时防御回退（不抛异常）。
- **短信号**：`agent_runner.py:399-400` 剥离键集合 `("type","step","timestamp","outcome")` → `+("duration")`，保证重连回放短信号也带运行时长，与实时一致。
- **实时时序**：final 是 react_loop 产出的第一终态实时帧，带 duration 后前端**收 final 即知状态+时长**，不再依赖 final_stats/DB。

### 2.2 final_stats 延后单发、字段补全

**（0）发布铁律（北京老陈 2026-09-11 铁令）：final_stats 必须全体段数据计算组装完成后才发，缺一段不发。**

- **禁止残缺组装即发**：现状 `emit_final_with_stats`（`step_emitter.py:67`）在 final 发射动作里同步 build_final_stats_step → 只装了 `duration/artifacts/final_status` 三块真值（`tool_stats/llm_call_count/retry_count/step_count` 根本没组装）就 publish——**违反本铁律，该做法彻底废弃**（产出+发布全部移出循环链）。
- **落库保留（不退化）**：现状 final_stats 走 `agent_runner.py:380-381` else 分支 `_persist` 落库（完整 dict 进 `chat_task_steps`，L405-410 再进终态缓冲统一补发）。改造后该落库行为**必须保留**：final_stats 在组装完成后由 runner 单发时，**SSE 发布 + DB 落库一并完成**，不得把现有已落库数据弄丢。
- **组装顶点**：全体段最终值取决于 ①工具记账（`_tool_stats`/`_artifacts`）②LLM 轮数/重试（`llm_call_count`/`_retry_count`）③步骤数（agent.steps）④运行时长（`_run_start_ts`）——全部在 react_loop **返回后**才为终值。故 final_stats **只能在 react_loop 返回后的 runner 收口点构建**，代码层杜绝提前。
- **发前完整性校验（硬门禁）**：构建后、publish 前逐段校验 7 键齐且类型正确——`duration(≥0 浮点)` / `artifacts(list)` / `final_status(非空)` / `tool_stats(dict)` / `llm_call_count(int)` / `retry_count(int)` / `step_count(int)`。任一缺失/类型错 → **不 publish** + ERROR 日志（抓代码 bug，禁残发）。
- **空值 ≠ 缺装**：`artifacts=[]`、`tool_stats={}`、`retry_count=0` 属合法终值（本次没调工具/没重试），正常发；缺键/None/类型错才是"没组装完"。

**（1）位置变更**：final_stats **移出 react_loop/react_step/handlers 实时链**，由 `agent_runner` 收口——在 react_loop 全部完成、telemetry 统计全齐后**统一构建单条：SSE 实时 publish + DB 落库（双保留）**。天然满足决定②"计算信息全部完成、每个地段都有信息后才发"与发布铁律（0），且不丢失现状落库数据。

**（2）字段补全**（`build_final_stats_step`）：

| 动作 | 字段 | 值 |
|------|------|----|
| 保留 | `duration` | 同源 `now - _run_start_ts` |
| 保留 | `artifacts` | `list(self._artifacts)` |
| 保留 | `final_status` | 显式 outcome |
| **新增** | `tool_stats` | `dict(self._tool_stats)`（按工具聚合，`_tool_stats` 是权威源） |
| **新增** | `llm_call_count` | `agent.llm_call_count` |
| **新增** | `retry_count` | `agent._retry_count` |
| **新增** | `step_count` | 与 `build_stats_step`（L188）同口径 |
| **删除** | `content=""` | 无信息量 |
| **删除** | `severity="info"` | 无信息量 |
| 不动 | `step` | 前端按 event_log seq 排序，语义不动 |

**（3）全路径必达**：正常/异常/取消/守卫路径 final_stats 都必须发（现状异常/守卫路径本就缺失，一并补齐），字段空数组也要发。

**（4）发布点选择**：`agent_runner` 的 DB 终态落库段（`await _persist_final(db.atxn(...))` 处）**之前**：统计在 react_loop 返回时已齐，**不必等 DB**（老陈口径：等计算齐，不等 DB）；runner 一处收口，正常与守卫路径各调一次；发布时间序仍在落库 `_persist_final`（update_task）之前，保持现状"发布先行"的时序不退化。落库动作在发布点同步完成（见 3.5 代码）。

### 2.3 目标时序全景

| 时刻 | 事件 | 前端效果 |
|------|------|---------|
| t0 | react_loop 产 final → 实时 publish（**带 duration**） | 立即渲染状态+运行时长（**不查 DB**），左侧 response 即时处理 |
| t1 | 前端 REST `getTaskDetail` 异步拉详情 | 后台进行，不参与首屏 |
| t2 | react_loop 返回、扫描+短信号覆写 → runner 构建 final_stats（**统计全齐**）SSE publish + **DB 落库** | 折叠统计详情（工具聚合/步数/轮数/重试/产出物）实时到位 |
| t3 | DB `update_task` 落库完成（duration 同源） | DB REST 归还终态，补 token 明细等 DB 独有字段 |

t0~t3 与老陈定案三步顺序完全吻合（①final 先做状态+时长渲染 ②response 即时处理 ③统计计算与折叠详情由 final_stats+DB 异步补齐），根除"final 到→查 DB→闪旧值"竞态。

### 3.5 `agent_runner.py` —— 延后单发 + 死码清理

**（1）新增 final_stats 延后发布（保证全体段组装完成才发，发布铁律（0）落地）**：
