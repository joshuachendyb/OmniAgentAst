## 二、需求分解（北京老陈 2026-09-01 指示）

前端右侧查看区底部「任务统计」区块（`StaticStatsBlock`）当前仅展示：最终状态/总耗时/token 终值/工具汇总/错误/产出物。本次增强：

1. **产出物**（`| 产出物数量(artifacts) | 0个 |`）：由仅显示 `name(type)` 标签，改为**按 E2E 测试记录 §2.2 表2 的方法输出**——4 字段明细表：序号 / 工具(tool_name) / 文件名(name) / 类型(type) / 路径(path)。
2. **新增头部信息**，对齐测试记录 §1 测试基本信息表，共 8 个信息点：开始时间、结束时间、运行耗时、SSE总事件数、LLM调用次数、Token使用(prompt/completion/total)、model 结构信息、逻辑步数。其中** Token 使用单列独立节（③）**，其余 7 项入「② 基本信息」节（见 5.2/6.1）。（**不含 SSE接收耗时**——北京老陈 2026-09-01 裁定：其本质=任务完成耗时/客户端端到端，与已展示"运行耗时/总耗时"重复，无新增价值，去掉。**不含跨任务注入上下文**——北京老陈 2026-09-01 拍板：该值为遥测监控域指标，本已落 monitoring.db task_metrics，前端权威源为 chat.db，补列跨域冗余/超出范围，且将引入后端改动，砍掉保 YAGNI。）
3. **新增「工具调用链」折叠区**（对齐测试记录 §3 工具调用链）：工具调用顺序(`工具A -> 工具B -> ...`) + 各调用参数明细。**不做** §5.2 全部执行步骤（右侧已有 `PipelineRenderer` 步骤流呈现执行步骤，避免重复）。

### 2.1 老陈已拍板的方向决策

| 决策点 | 结论 |
|--------|------|
| display_name | **不要**；model 结构信息只显示 `provider + model` |
| §5.2 执行步骤 + §3 工具调用链只做哪个 | **只做工具调用链**（执行步骤已有 PipelineRenderer） |
| 跨任务注入上下文 | **去掉**（2026-09-01 拍板：遥测监控域指标，落 monitoring.db task_metrics，补落 chat.db 跨域冗余 + 引入后端改动，砍掉保 YAGNI） |
| SSE接收耗时 | **去掉**（本质=任务完成耗时，与已展示"运行耗时/总耗时"重复） |
| 产出物 + 头部信息范围 | **全部落地** |
| 实施路径 | **一次性全部做完**（不分子阶段交付） |
| 工具调用链数据源 | **前端从 action 步骤提取**（复用既有 C2 步骤接口/既有 steps 数据） |

## 三、现状盘点（已核实 · 基于当前最新代码）

### 3.1 前端现状

- **组件**：`frontend/src/features/chat/components/right/StaticStatsBlock.tsx`（仅历史任务回放时渲染，`RightViewer.tsx:207` 条件 `!isCurrentLive`）。
- **数据源**：`TaskDetail`（REST `GET /chat/execution/task/{task_id}` → `adaptTaskDetail`）。
- **产出物现状**：`detail.artifacts.map(a => <Tag>{a.name}({a.type})</Tag>)`，仅 2 字段展示，无序号/工具/路径。
- **类型**：`TaskArtifact { name, path, type }`（`task.api.ts:98-103`）——**缺 `tool_name`**；`adaptTaskDetail` 未透传 tool_name。

### 3.2 后端现状（数据源判定）

| 目标信息 | 后端是否已有 | 存储/来源 | 历史任务可回溯? | 前端当前有? |
|----------|-------------|-----------|----------------|------------|
| 开始时间 | ✅ | `chat_tasks.created_at`(本地ISO) | ✅ | ❌未展示 |
| 结束时间 | ✅ | `chat_tasks.updated_at` | ✅ | ❌未展示 |
| 运行耗时 | ✅ | `chat_tasks.duration` | ✅ | ✅(总耗时) |
| SSE总事件数 | ✅ | `chat_tasks.total_steps` | ✅ | ✅(有字段未展示) |
| LLM调用次数 | ✅ | `chat_tasks.llm_call_count` | ✅ | ✅(有字段未展示) |
| Token(p/c/t) | ✅ | `chat_tasks.accumulated_usage` | ✅ | ✅(token终值) |
| model(provider/model) | ✅ | `sessionModel` JSON→parse_session_model 派生 | ✅ | ❌(类型缺) |
| 逻辑步数 | ✅ | ≈ `total_steps`（步数去 chunk） | ✅ | ❌ |
| SSE接收耗时 | ❌ 已去掉 | 无；本质=任务完成耗时/客户端端到端，与运行耗时重复，不再提供(北京老陈 2026-09-01 裁定) | — | — |

**关键结论**：
- **后端无需改动**：开始/结束时间、运行耗时、SSE总事件数、LLM次数、Token、model(provider/model)、逻辑步数——**全部在 chat.db chat_tasks 已有**，本次前端直接读取即可。（跨任务注入上下文原拟补落库，已砍；SSE接收耗时已裁定去掉，均不做。）
- **工具调用链数据源**：`chat_tasks` 步骤回放（C2 `/steps`）的 action 步骤含 `tools[]` 数组，**每元素 `{tool, target, params}`**（工具名=`tool`、参数=`params`）+ 轮次(`step`)，DB 完整可查。前端 `RightViewer` 已有 `historySteps`（C2 步骤数据，经 `toExecutionSteps` 浅过滤保留原结构）可作提取源，**无需新后端接口**。

### 3.3 治理约束

- 后端为主，前端迎合（AGENTS.md §1.5）——本次**后端零改动**，前端按既有后端字段/接口数据迎合，不新增后端能力。
- 不重复造轮子（DRY）：产出物/token/model/耗时读既有 TaskDetail 字段；工具调用链复用 C2 步骤数据，不另起炉灶。
- 仅前端改动，无 DB 迁移；数组处理一律 `?.`/空值兜底。
- 注释署名+日期；编辑历史规范；测试不入 commit。

## 四、后端改动设计

**后端零改动**（北京老陈 2026-09-01 拍板去「跨任务注入上下文」后成立）。

- 头部信息（开始/结束/运行耗时/SSE总事件/LLM次数/Token/model/逻辑步数）与产出物明细各字段，**均在 `chat_tasks` 既有列**（`created_at`/`updated_at`/`duration`/`total_steps`/`llm_call_count`/`accumulated_usage`/`sessionModel`→派生 model/provider/`artifacts`），`get_task_detail` 已 `SELECT *` 全量返回。
- 工具调用链：复用既有 C2 步骤接口 `/chat/execution/task/{task_id}/steps`，DB 已存完整 action `tools[]`，**无新接口**。
- 故：**不改 DB、不改 storage、不改 agent_runner、不新增接口、不新增列**。前端完全在既有后端数据之上增强展示。

> 说明（审计留痕）：SSE接收耗时原拟新增 `sse_elapsed` 列、跨任务注入上下文原拟新增 `context_injected_*` 两列——均经北京老陈 2026-09-01 裁定去掉：前者本质=任务完成耗时与运行耗时重复；后者属遥测监控域（已落 monitoring.db task_metrics）、补落 chat.db 跨域冗余且引入后端改动。两者皆**不做**。

### 6.2 布局/样式约定（极简可读，不堆控件 · 北京老陈 2026-09-01 指示）

- **容器**：`marginTop: Spacing.SM` + `padding: Spacing.SM`，`background: transparent`，`border: none`，仅顶部 `borderTop: 1px solid Colors.BORDER.LIGHT` 一条淡线；全块行距 `lineHeight: 1.6`，节间 `marginTop: 10`，整齐透气。
- **分节标题②③④⑤⑥**：`fontSize: 12 / fontWeight: 500 / color: #595959`，左侧 2px `Colors.PRIMARY` 色条或 8px 左距，无大色块、无粗分割；标题与内容间 6px。
- **状态①**：不做大字 Statistic；同行极简 `Tag(状态色, 12px)` + `Typography.Text type="secondary" 12px` 显示“运行Xs”，一行解决，不占纵向空间。
- **基本信息②**：`display:grid gridTemplateColumns: 72px 1fr 72px 1fr`，`label: {color:#8c8c8c, fontSize:12}`，`content: {color:#262626, fontSize:12, whiteSpace: nowrap}`；7 项排 4 行（末行 3 格自动补齐），无 Descriptions 框线、无斑马纹，行距透气。
- **Token ③**：单行 `Typography.Text 12px`，`prompt/completion/total` 三值用 `·` 淡分隔（`color:#d9d9d9`），数字等宽 `fontVariantNumeric: tabular-nums`，无 Descriptions、无表格。
- **工具④**：汇总行纯文本 `12px`，`·` 分隔“工具×次”，无 Tag 堆叠；折叠区为唯一交互控件，复用 TrustPanel 轻量折叠（`role="button" aria-expanded tabIndex=0 onKeyDown Enter/Space`），标题 `12px / color:#595959`，箭头 `▸/▾ 10px`，默认收起，展开内容为极简行 `序号 工具 参数(JSON 截断80字)`，无重表格线（用 `Typography.Text code` 弱底）。
- **产出物⑤**：标题行“产出 N 个” `12px secondary`；列表为极简行：`序号(12px #8c8c8c, 宽20) 工具(12px #595959) 名称(12px #262626) 类型(11px #8c8c8c) 路径(12px mono #595959, ellipsis)`，行高 22px，行间 4px，无 Table 边框与表头重线；空产出显“0 个 — 无产出物” muted。
- **错误⑥**：有则显单行 `Typography.Text 12px color:#cf1322` 前置 `⚠ 11px`，`background: #fff1f0` 极淡底 + `1px solid #ffa39e` 细边，`borderRadius: 4`，不做大红块。
- **通用**：全部 `margin/padding/fontSize/lineHeight/borderRadius` 取 `Colors/FontSize/Spacing` 常量，不写裸值；不引入除折叠外的新控件，保持块面干净。

### 6.3 信息优先级与可读性

- 状态概览（①）置于最顶，作整块视觉锚点——先明确"任务成没成"，再下钻细节。
- 基本信息（② Token③）为聚合元信息，放产出物/工具明细之上，先总览后明细。
- 工具（④）与产出物（⑤）属于明细类，对比元信息次之；工具调用链在工具区可折叠，默认收起不挤占。
- 错误（⑥）条件出现，放最末，异常时醒目收尾不打断正常浏览。
- 全程**不重复**：耗时/Token/产出物各只出现一次（北京老陈 UI 去重指示），信息互补不冗余。

## 七、三堂会审（设计期自查）

### 7.1 合规检查（10 大规范）
- **SRP**：StaticStatsBlock 仍单一职责（任务统计展示）；工具调用链提取逻辑独立为纯函数 `_extract_tool_chain(steps)`，不进渲染。✅
- **DRY**：产出物/token/model/耗时读既有 `TaskDetail` 字段；工具调用链复用 C2 步骤数据，不重复造轮子。✅
- **KISS-DIRECT**：**后端零改动**，不新增接口、不增列、不加参数；前端纯展示增强，逻辑直接不绕弯。✅
- **SLAP**：StaticStatsBlock 拆「状态概览/基本信息/Token/工具/产出物/错误」六节构造为同级子组件或纯函数，不混排。✅
- **YAGNI**：只做老陈点名的字段（耗时/Token/model/产出物明细/工具调用链），不做测试记录第 4/5 节（SSE事件详情/DB验证），也不做遥测监控域指标（跨任务注入/LLM单轮延迟）——均超出范围。✅
- **禁止 backward**：纯增加新展示项/重组展示，不改既有渲染路径语义、不动后端。✅

### 7.2 合理检查
- 逻辑步数近似 `total_steps`：前端不再重复计算 SSE 事件数，直接复用 DB total_steps，单一来源。✅
- 工具调用链用 action 步骤（DB 权威），不依赖 SSE 实时 tool_calls（历史任务无）。✅
- 后端零改动：全部展示项基于既有 chat.db 字段 + 既有 C2 步骤接口，无跨库、无补列、无新接口，毕其功于前端。✅

### 7.3 关联逻辑（不退化）
- 现有功能语义**全量保留但去重整合**：状态 → ①概览 Statistic；总耗时 → 并入→运行耗时；token 终值 → ③Token 独立节；工具汇总 → ④工具区汇总行；错误 → ⑥条件节；产出物 → Tag 改为⑤明细表（增强非删除）。每一项信息仍可见，只是位置/形态重组，**不丢信息、不退化**。✅
- **后端零改动**：无 DB 迁移、无 `_ensure_column`、无 `update_task` 参数变更，老库老任务读取路径不变，零影响存量逻辑。✅
- 可折叠工具调用链：默认收起，不撑爆右侧查看区布局；不打断既有 auto-scroll（RightViewer 滚动逻辑不涉及本区块）。✅
