## 一、背景与现状问题

### 1.1 现状实码（2026-09-02 读码核实）

- 右侧查看区流水线实时流中，**思考流尾随光标 `▍`**（`ThinkingStream.tsx:48` + `index.css:32-48` `.thinking-cursor`，`thinking-blink 1s step-start infinite` 闪烁）。
- 光标出现条件：`PipelineRenderer.tsx:148-149` `cursor={streaming && i === lastThink}`——即**钉死在"最后一个 thinking 段"的尾部**。
- `lastThink = segs.reduce(...)`（最后一条 kind==='thinking' 的段索引，`PipelineRenderer.tsx:130-133`）。

### 1.2 缺陷

思考内容输出完成后，进入 **action 执行阶段**时：
1. 光标**仍停留在旧的思考段尾部**闪烁，**不跟随到流水线最新位置**；
2. 用户看不到"系统正在等待下一个 thought / 即将有内容输出"的指示；
3. 首次 thought/chunk 到来前，**没有任何"内容将从此处流出"的占位信号**。

### 1.3 北京老陈需求（2026-09-02 会话确认）

- 思考完成后、**等待下一个 thought 到来的期间**，应在**即将输出内容的位置**（step 段框右上角 / 新行首列）显示一个**等待指示符号**。
- 等待期间 = **一个转圈符号**，占用 **约 1.4em**（约 20px，正文 14px 明显一大圈；需求原文"最多 1~2 个字符位"为上限，老陈拍板定案 **SVG 取 1.4em**，见 §2.2），告知用户"在等";
- **首 token 一到**（下文统称"首 chunk"，二者同义——老陈口语混用，指首个流式输出 token），开始输出 chunk/thought 信息，进入现有打字机态（`▍` 跟随文本末尾）。
- **覆盖接管（老陈 2026-09-02 00:29 澄清，关键）**：首 chunk 到来、开始显示 thought 字符时，字符**直接从等待符号所在的那个位置开始逐字输出、把等待符号覆盖掉**——等待符号**随之消失，禁止一直常驻**。等待符号与输出字符是**同一个字符位**，不是"等待符号另占一行、字符再从别处出现"。
- 光标/等待符号要**高亮、明显**（不要灰色、不要现有慢呼吸闪烁样式）。

### 1.4 明确不做（边界）

- **不改** data 链路、后端、SSE、打字机本体（TextStream/ThinkingStream 逐字逻辑保持现状）。
- **不改** taskinfo，本次仅右侧查看区流水线。
- **不做**历史回放等待态（回放无流式，无等待语义，仅实时任务 streaming=true 时生效）。

## 二、设计定案

### 2.1 位置规则（核心）

> **一句话定案（北京老陈 2026-09-02 拍板）：等待符号 `↻` 停在"下一个 thought 的首 chunk 将要显示的那个新行首列"。**

- 即"**首 chunk 未到时的位置**"= 下一个 thought 内容将从那里开始输出的**内容输出起点**（step 段框右上角首列；"新行首列"即此位置的通俗说法），不跟在行尾、不钉在旧段尾部。
- **等待态**（streaming=true 且无正在流出的内容段，或**流已建立、首 token 尚未到达**——即老陈强调的"首 chunk 未到之时"）：
  在**该新行首列**渲染 `↻`，占约 1.4em（≈20px），锚定"下一个 thought/chunk 将从这里开始"。
- **首 chunk 到达 → 覆盖接管**：字符**从等待符号所在的那个字符位开始逐字输出**，等待符号被字符覆盖、随之消失；输出过程由现有打字机光标 `▍` 在文本末尾接管。等待符号→字符为**同一位置的替换交接**，永不叠加、永不常驻。
- **流出态**（有 thinking/text 段正在逐字输出）：仅打字机光标 `▍` 在文本末尾跟随（行为不变），无等待符号。
- 一句话总结：**等待符号 = 打字机光标尚未启动时的"空转占位"，首字符从它身上长出，它即刻让位。**

> 存活区间：等待符号只存在于"**需要输出、但首 chunk 尚未到来**"的时段；首 chunk 一到（无论流刚建立还是已开始流入），立即原位被字符接管。

### 2.2 符号定案（北京老陈拍板）

- 视觉形态 = **`↻`（U+21BB 圆形旋转箭头，逆时针）**——"循环/等待/刷新"语义。
- **实现载体 = SVG 缺口圆弧（老陈拍板）**：`↻` 是 Unicode 文本字符，**没有"线条粗细"属性，粗细由字体决定、不可控**；改用 SVG 矢量路径后由 **`stroke-width` 精确控制线条粗细**（详见 §2.4）。
- **线条要粗**：SVG `stroke-width: 2px`（可调 1.5~2.5px，默认 2px）。
- 宽度 **约 1.4em（≈20px，SVG 定案尺寸，老陈 2026-09-02 拍板）**：矢量放大无损、`stroke-width` 随放大同步变粗，落在需求"最多 1~2 字符位"容量内；独立等待行，不挤正文换行；正因占位不宽，首 chunk 到达时才能原地覆盖无缝接管。

### 2.3 颜色定案（北京老陈拍板：绿色，高亮）

| 项 | 定案 |
|----|------|
| 色相 | **高亮绿** |
| 具体色值 | **`#52c41a`（Ant Design green-6，项目主绿）**，与整体 AntD 视觉协调、饱和度放满 |
| 原因 | ①绿 = "进行中/就绪/等待"通行语义；②AntD 绿与本项目 AntD 5 生态协调；③高亮绿在浅底上对比明显，区别于正文灰、思考灰、错误红 |
| 备选（仅作万一调整参考） | `#73d13d`（green-5 亮绿）或 `#389e0d`（green-7 深绿）——**已定案 #52c41a（§六），备选不再激活** |

### 2.4 视觉实现方案（SVG 首选：stroke-width 精确控粗 + CSS 旋转）

- **载体：SVG 缺口圆弧**（视觉即 `↻`：开口圆环，开口即箭头位），单例一个 `<svg>`，尺寸 **1.4em × 1.4em（≈20px，老陈 2026-09-02 拍板）**，`viewBox 24`。
- **线条粗细：`stroke-width: 2px` 参数精确控制**（可调 1.5~2.5px），`stroke="#52c41a"`、`fill="none"`、`stroke-linecap="round"`——粗线条由参数锁定，跨机、跨字体、跨浏览器一致，不再依赖字体字形。
- **逆时针转圈动画**：外层 `.waiting-cursor` 容器 CSS `@keyframes waiting-spin { from {transform:rotate(0)} to {transform:rotate(-360deg)} }`，`1s linear infinite` 循环。
- 高度对齐：`display:inline-block` + `vertical-align` 与正文基线对齐，不引起行高跳动。
- **不再使用**：文本字符 `↻` 的 `font-weight`/`-webkit-text-stroke`/`text-shadow` 加粗方案（粗细不可控，废弃）。

## 四、验收要点（落码后人工/自动核验）

1. 任务进入 action 执行期（思考输出完、无新 thought）→ 在"**下一个 thought 的首 chunk 将要显示的新行首列**"出现 `↻` 型绿色转圈等待符号（SVG 缺口圆弧）。
2. **覆盖接管（关键验收）**：首个 thought chunk 到达、字符开始输出时，**字符从等待符号所在的同一个字符位开始逐字显示，覆盖等待符号**——等待符号立即消失，**不可常驻**；随后现有 `▍`/打字机光标在文本末尾跟随，等待符号不再出现。
3. 有 thinking/text 段正在逐字流出时无等待符号（仅**末段**打字机光标 `▍` 亮；完成段的旧光标熄灭——改动 A 修复，行为不退化）。
4. 任务结束（final/error/cancelled）→ 等待符号不再渲染（非 streaming）。
5. 历史回放拒绝显示等待符号。
6. **线条粗细：`stroke-width` 生效、视觉粗线稳定**（换字体/跨浏览器不变，不细成发丝）；宽度 **1.4em（≈20px）** 明显醒目但独立等待行不影响正文换行/布局；高亮绿在浅底可见无冲突。
7. `npm run check` 通过；`buildSegments` 既有单测回归不破坏（改动 A/B/C 均不动纯函数）。waiting/cursor 判定为组件内联计算、纯视觉态，无独立单测，靠第 1~6 条人工/目视验收 + E2E 流水线截图核对。

## 五、关联逻辑检查（三堂会审摘要）

- **合规**：SRP（PipelineRenderer 一处承载等待态，不散落各组件）；DRY（SVG 与动画唯一入口 .waiting-cursor，不重复实现）；KISS-DIRECT（判定"最新流出段"与现有 lastThink 同源，逻辑直线）；YAGNI（不做回放等待态、不做任务级进度）。
- **合理**：等待符号只出现于"实时且无流出处"，是打字机"未启动前置状态"；首 chunk 到达时**同一字符位被输出字符覆盖接管**（替换交接、禁止常驻、不叠加不并存），流出一启动即由打字机光标 `▍` 继续，逻辑直线无中间态；位置定"下一个 thought 的首 chunk 将要显示的新行首列"而非行尾，符合"内容将从此处开始"的心理预期。
- **关联**：与 13.8 打字机（TextStream/ThinkingStream 现状）兼容——等待态是打字机"未启动前置状态"，流出一启动即切换，永不叠加；与 taskinfo `[ ]` 实时格（另一专题）无冲突（一左一右不同寄存区）；数据链路零改动。
