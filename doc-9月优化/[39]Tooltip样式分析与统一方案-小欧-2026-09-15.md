## 一、背景

左侧菜单栏折叠态修复过程中（[38] 落地 + 折叠 Tooltip 黑框修复），对全站 Tooltip 做了一次样式盘点。反馈的问题聚焦三点：

1. **样式颜色怎么设置的**——是否有统一入口；
2. **视觉是否合理**——从整体页面视觉看是否协调；
3. **能否统一**——是否存在类似组件可复用。

本报告回答以上三点，并给出可落地的统一方案。

### 2.2 颜色设置方式——全部 AntD 默认值

**结论：全站没有任何一处自定义 Tooltip 颜色**，也没有全局覆盖。

证据链：
- `main.tsx:15` `ConfigProvider` 只配了 `locale={zhCN}`，**未配 `theme` token**；
- 全站 grep `ant-tooltip` / `--ant-tooltip` / `.ant-tooltip` **零命中**（index.css 及各组件均无覆盖）；
- 所有 `<Tooltip>` 未传 `color` / `popupClassName` / `rootClassName`。

因此 53 处 Tooltip 全部吃 AntD v5 默认样式：**黑底 `rgba(0,0,0,0.85)` + 白字**，字号 12px，圆角 6px，箭头默认。

## 三、视觉问题分析（从整体页面视角）

### 3.1 问题 A：黑底上叠浅灰字，对比度不足（NextActions 最严重）

`NextActions.tsx:44-55` 的 title 是**复合 JSX**（两行：描述 + 适用条件）：

```tsx
<Tooltip title={
  <div>
    <div>{action.description}</div>
    {action.when && (
      <div style={{ color: Colors.TEXT.TERTIARY, ... }}>适用：{action.when}</div>
    )}
  </div>
}>
```

内层"适用："行用了 `Colors.TEXT.TERTIARY = #999999`（stepStyles.ts:117，为白底设计的浅灰），叠在 AntD 黑底 `rgba(0,0,0,0.85)` 上：
- `#999999` 对黑底的对比度 ≈ **1.9:1**，远低于 WCAG 4.5:1；
- "适用"副信息几乎不可读，视觉呈"糊"。

**根因**：`Colors` 三档灰（PRIMARY `#595959` / SECONDARY `#8c8c8c` / TERTIARY `#999999`，stepStyles.ts:114-117）全部为**白底设计**，一旦出现在黑浮层上全部失效。黑底只能使用 `rgba(255,255,255,0.85)` 系白字。

> 附注：同文件里还有按钮 `Colors.PRIMARY #1677ff` 也是白底色，但按钮本身在白页面上，属正常；**只有错位进黑浮层的文字有问题**。

### 3.2 问题 B：结构型内容被塞进黑浮层，表现力不足

两类内容本质是"小卡片"，却用 Tooltip 黑浮层承载，缺层次：

| 内容 | 位置 | 问题 |
|------|------|------|
| 推荐操作（描述 + 适用条件两行） | NextActions.tsx:43-57 | 结构性信息挤在黑底扁条里，无边框/分层/可点感 |
| liveMeta 超长全文 | TaskInfoBar.tsx:328 tag | 超长 error 文本黑底上一团，无可读层次 |
| Token 分项 P/C 明细 | MetricItem.tsx:77 | 数据密集串,黑底可读性差 |

而项目**已存在白底卡片浮层** `FloatingEntry`（TaskInfoBar G6 历史上下文 / G8 事件序列在用，白底 + 卡片 + 内滚），同一功能区内两种"浮层语言"（黑 tooltip vs 白卡片）并存。

### 3.3 问题 C：与"省略-全文"体系冲突前的耦合点

`EllipsisTip`（省略号 + Tooltip 全文，DRY 通用封装）承担大量"截断兜底"，MetricItem/宽窄屏断点矩阵大量复用。该封装**本身合理**，但超长的全文（几十到几百字）进黑浮层，仍受问题 B 影响——文字越长，黑底阅读负担越大。

### 3.4 合理之处（保留项）

- `Layout` 菜单折叠 tooltip：AntD 黑底默认 + 已加 `title` 字符串（[38] 落地），简短、清晰、合适；
- `ChatHeader` / `TrustPanel` / `AttachmentArea` 等单行短文案提示，黑底白字完全合理；
- `TopbarStats` 时间悬浮用了 `<span style={{whiteSpace:'pre-line'}}>` 白字，对比度 OK。

## 四、统一方案定案（单一最佳方案，v1.1 已实施）

**北京老陈拍板**：放弃"层级一/层级二"拆分与多个决策点，取**一个动作统一全站**——全站 Tooltip 从"黑底系统默认"统一为"白底浅卡片"，与页面整体白底浅色体系（白底、5 档灰字、浅边框阴影、蓝主色）同语言。一次解决全部三个问题：灰色看不清 / 黑块突兀 / 双浮层不统一。

### 4.1 实施内容（v1.2 三堂会审定稿）
- **`main.tsx`** `ConfigProvider` 全局 theme：`Tooltip.colorBgSpotlight=#ffffff`、`colorTextLightSolid=#595959`，一处生效全站 53 处；
- **`index.css` 零覆盖**（三堂会审删除原 shadow/border/箭头样式）：antd 5.29.3 自带机制已完备——箭头背景经 `::before` + `--antd-arrow-background-color` 变量**自动继承 `colorBgSpotlight`**（见 antd `es/style/placementArrow.js`、`es/tooltip/style/index.js`），白底阴影/圆角走自带 `boxShadowSecondary`/`tooltipBorderRadius`（默认 8px），与 Popover/FloatingEntry 阴影变量同一来源。

### 4.2 效果
- 灰字不可读（问题A）→ 白底上全部现有灰阶（`#595959/#8c8c8c/#999`）对比度增强，NextActions"适用"行无需单独改字色；
- 黑块突兀（问题B）→ 白卡片与 `FloatingEntry`、页面同语言；
- 统一性（问题C）→ 全局一种浮层，后续调色只改 main.tsx 一处（DRY）；箭头/阴影/圆角全部随 token 自动跟随，零手写 CSS（YAGNI）。

### 4.3 保留项（原 3.4 结论不变）
菜单折叠 tooltip、短文案提示、`TopbarStats` 白字等，换白底后依然合适；结构型复合内容（NextActions 两行卡片）后续可评估升级 FloatingEntry，但**不再是本轮必需**。

## 六、结论

1. **颜色设置现状**：全站 53 处 Tooltip 零自定义、零全局覆盖，统一吃 AntD 默认黑底白字；
2. **视觉诊断**：默认黑底是唯一与白底页面脱节的浮层语言；`NextActions` `#999` 灰字对黑底对比度仅 1.9:1（不可读）为其典型症状；
3. **最佳方案（已实施）**：全站 Tooltip 统一白底浅卡片——ConfigProvider 一处全局配置 + index.css 补辨识度样式，一个动作解决全部三问题，工作量最小、效果最佳。
