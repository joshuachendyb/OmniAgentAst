# 多线程与异步编程详解

---

## 一、核心概念

### 1. 多线程（Multi-threading）

多线程是指在一个进程内同时运行多个执行流（线程），每个线程独立执行代码，共享进程的内存空间。它本质上是通过操作系统的调度器在多个线程之间切换，利用多核 CPU 并行执行任务。

**关键特征：**
- 每个线程拥有独立的调用栈、程序计数器和寄存器
- 线程共享进程的堆内存、全局变量和已加载的代码
- 存在线程安全问题（竞态条件、死锁），需要锁、信号量等同步机制保护共享资源
- 线程是重量级资源（在用户态），创建和切换有一定开销

### 2. 异步编程（Asynchronous Programming）

异步编程是一种编程范式，允许线程在发起一个耗时操作后不必阻塞等待结果，而是继续执行其他任务，待操作完成时通过回调、事件或 Future/Promise 等机制获取结果。其核心在于**非阻塞 I/O**。

**关键特征：**
- 不依赖多核并行，单线程也能利用异步实现高并发
- 通过事件循环（Event Loop）调度回调任务
- 无共享内存，天然避免竞态条件（单线程异步）
- 关注的是"等待资源"的时间利用，而非"CPU 计算"的并行

---

## 二、工作原理对比

| 维度 | 多线程 | 异步编程 |
|------|--------|---------|
| 并行方式 | 真正的 CPU 并行（多核） | 逻辑并发（事件驱动） |
| 调度主体 | 操作系统线程调度器 | 运行时事件循环 |
| 阻塞行为 | 线程阻塞时整个线程挂起，占用系统资源 | 阻塞操作让出控制权，事件循环继续调度其他任务 |
| 资源共享 | 共享进程内存，需同步 | 通常无共享状态（单线程异步时） |
| 并发上限 | 受限于 CPU 核数和线程创建开销 | 仅受限于内存和事件循环能力，理论上可数万 |
| 上下文切换 | 操作系统级切换，开销较大（约 1~10μs） | 用户态协作式切换，开销小（约 100ns~1μs） |

---

## 三、适用场景

### 多线程适合：
- **CPU 密集型任务**：如图像编解码、矩阵运算、视频转码、密码学计算
- **需要真正并行**的场景：多核 CPU 上每个核处理不同数据
- **需要调用同步阻塞 API** 且无法改造的场景

### 异步适合：
- **I/O 密集型任务**：网络请求、数据库查询、文件读写
- **高并发连接** 场景：Web 服务器、即时通讯、API 网关
- **等待外部资源** 的场景：请求远程服务、等待消息推送

## 四、代码示例

### 示例 1：多线程 —— Python `threading`（CPU 密集型任务）

~~~python
import threading
import time

def compute(n):
    """模拟 CPU 密集型计算"""
    result = sum(i * i for i in range(n))
    print(f"  线程 {threading.current_thread().name} 计算完成，结果={result}, 耗时={time.time()-t0:.2f}s")

threads = []
t0 = time.time()

for i in range(4):
    t = threading.Thread(target=compute, args=(10_000_000,), name=f"T{i}")
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print(f"总耗时: {time.time()-t0:.2f}s")
~~~

**说明：** 4 个线程在 4 核 CPU 上真正并行执行计算，总耗时约等于 1 个线程的时间，体现的是 **CPU 并行**。

---

### 示例 2：异步编程 —— Python `asyncio`（I/O 密集型任务）

~~~python
import asyncio
import time

async def fetch_resource(name, delay):
    """模拟网络 I/O 等待"""
    print(f"  {name}: 发起请求...")
    await asyncio.sleep(delay)  # 非阻塞等待，期间让出控制权
    print(f"  {name}: 响应就绪 (耗时 {delay}s)")
    return name

async def main():
    t0 = time.time()
    resources = ["API_A", "API_B", "API_C", "API_D"]
    results = await asyncio.gather(*[fetch_resource(r, 2) for r in resources])
    print(f"所有请求完成，共耗时: {time.time()-t0:.2f}s，结果: {results}")

asyncio.run(main())
~~~

**说明：** 4 个异步任务并发执行，每个任务都等待 2 秒的 I/O，但总耗时仅约 2 秒（而非 8 秒）。单线程通过事件循环在等待间隙调度其他任务，体现的是 **I/O 并发**。

## 五、总结

| | 多线程 | 异步 |
|---|---|---|
| 本质 | 操作系统级并行 | 用户态协作式并发 |
| 优势 | 真正并行，适合 CPU 计算 | 资源效率高，适合 I/O 等待 |
| 劣势 | 线程创建/切换开销大，调试困难 | 单线程瓶颈，CPU 密集任务无效 |
| 典型场景 | 视频处理、科学计算、加密 | 微服务调用、WebSocket、爬虫 |

**实践建议：** 现代应用中常将两者结合——用多进程/多线程处理 CPU 密集任务，用异步处理 I/O 密集任务，从而最大化系统吞吐量。
