## 二、技术架构与"流式输出"原理（通俗版）

**模型侧（我是什么）：**
我本质上是一个大规模 Transformer 语言模型（decoder-only 架构）。训练阶段在海量文本上学习"给定前文，下一个 token 最可能是什么"的分布。推理时，每一步只生成 **一个 token**（可能是半个汉字、一个标点、一小段英文词），然后把这个 token 拼到上下文末尾，再预测下一个——如此循环。

**流式输出（你看到的"打字机效果"）怎么实现的：**

1. 我每次生成一个 token 就立即把增量发给前端，而不是憋完一整段再吐。
2. 前端收到一个 token → 追加渲染到界面上 → 你看到文字"逐个蹦出来"。
3. 底层传输协议（WebSocket / SSE / HTTP chunked）保持长连接，每个 token 就是一个小数据包。
4. 停止条件：模型输出 `<eos>` 标记、达到 max_tokens、或你点了"停止生成"。

> 一句话：**不是我在"边想边说"，而是我在逐个 token 生成，传输层把每个 token 实时推给你。** 你感受到的"流畅打字"，其实是高频小包的网络传输 + 前端即时渲染。

**工具调用（Agent 能力）：**
我内置了一组工具函数（文件读写、Shell、搜索、网页等）。当判断需要外部操作时，我会输出一个结构化的函数调用指令（JSON），由运行环境执行，把结果回填给我，我再生成下一步。这就是"写代码 → 跑命令 → 看结果 → 继续写"的循环。
