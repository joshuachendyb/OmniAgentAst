## 四、重点Bug详情

### 1. 返回值不一致（RET-01）- 66个

**问题描述**：大量辅助函数直接返回dict，而非使用`build_success`或`build_error`统一构建返回值。

**影响范围**：
- File工具：`_get_file_encoding`, `_extract_zip_archive`, `_extract_tar_archive`, `_build_entry`, `_build_list_success`
- Shell工具：`_execute_python`, `_execute_javascript`, `_build_shell_result`, `_run_shell_background`
- Network工具：`_ping`, `_port_check`, `_fetch_via_playwright`, `_build_http_error`, `_map_network_error`
- Safety工具：`_resolve_import_aliases`, `validate_code_safety`

**风险等级**：P1

**修复建议**：统一使用`build_success`和`build_error`构建返回值，确保返回格式一致性。

---

### 2. 类型安全问题（TYP-01）- 7个

**问题描述**：使用`.get()`访问字典但未提供默认值，可能返回None导致后续代码异常。

**典型示例**：
```python
# action_handler.py
confirmed = result.get("confirmed")  # 无默认值，可能返回None

# tool_executor.py
code = result.get("code")  # 无默认值，可能返回None

# tool_safety_checker.py
action = params.get("action")  # 无默认值，可能返回None
path = params.get("path")  # 无默认值，可能返回None
```

**风险等级**：P1

**修复建议**：为所有`.get()`调用提供默认值，例如`.get("key", default_value)`。

---

### 3. 异常处理不完整（EXC-01）- 4个

**问题描述**：async函数有多个await调用但无try/except异常处理。

**典型示例**：
```python
# run_sse_stream.py
async def _stop_check():
    # 多个await但无异常处理
    await check_cancelled()
    await check_paused()

# action_handler.py
async def handle_action():
    # 多个await但无异常处理
    await check_safety()
    await execute_tools()
    await build_observation()
```

**风险等级**：P1

**修复建议**：为关键async函数添加try/except块，确保异常被正确捕获和处理。

---

### 4. 参数验证缺失（VAL-01）- 5个

**问题描述**：LLM数据构建函数缺少参数有效性检查。

**典型示例**：
```python
# write_text_file.py
def _build_write_text_file_llm_data(exec_code, duration_ms, path, ...):
    # 无参数验证
    return {...}

# execute_code.py
def _build_execute_code_llm_data(exec_code, duration_ms, ...):
    # 无参数验证
    return {...}
```

**风险等级**：P1

**修复建议**：添加参数有效性检查，例如检查path是否为空、duration_ms是否为负数等。

---

### 5. 日志完整性问题（LOG-01）- 1个

**问题描述**：except块捕获异常但未记录日志。

**典型示例**：
```python
# tool_executor.py
def auto_inject_from_search():
    try:
        ...
    except Exception:
        pass  # 未记录日志
```

**风险等级**：P1

**修复建议**：在except块中添加`logger.warning`或`logger.error`记录异常信息。

---

### 6. 边界条件问题（BND-01）- 1个

**问题描述**：重试引擎缺少显式的重试次数限制。

**典型示例**：
```python
# tool_retry_engine.py
async def execute_tool_with_retry():
    # 未找到max_retries参数或常量
    while True:  # 可能无限重试
        ...
```

**风险等级**：P1

**修复建议**：添加显式的max_retries参数或常量，防止无限重试。

---

### 7. 错误码缺失（ERR-02）- 2个

**问题描述**：错误返回缺少err_code字段。

**典型示例**：
```python
# http_request.py
def _parse_response_body():
    return {
        "error": True,
        "error_detail": "...",
        # 缺少err_code字段
    }

# download_file.py
def _stream_download():
    return {
        "error": True,
        "error_detail": "...",
        # 缺少err_code字段
    }
```

**风险等级**：P1

**修复建议**：为所有错误返回添加err_code字段，使用预定义的错误码常量。

---

### 8. 超时参数未传递（TMO-01）- 1个

**问题描述**：函数有timeout参数但未传递给底层调用。

**典型示例**：
```python
# download_file.py
def _map_network_error(timeout, ...):
    # timeout参数未使用
    return {...}
```

**风险等级**：P1

**修复建议**：将timeout参数传递给底层HTTP调用。

## 五、修复优先级建议

### 高优先级（建议立即修复）

6. **超时参数未传递（TMO-01）**：影响超时控制
