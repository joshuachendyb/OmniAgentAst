### 1. listdir (Step 1 / Step 29)

**问题 1 — 文件夹 size 字段为 "" 时显示"字节"无数字** ✅ 真  
位置: `observation_formatter.py:514-516`  
表现: `3NMermaidReader [目录, 字节]`  
根因: `entry.get("size", "")` 返回空字符串，`"" is not None` 为 True，进入 f-string 产生 `", 字节"`  
**修复方案（遵循 KISS-DIRECT + SRP）**:  
```python
# 改前
size = entry.get("size", "")
size_str = f", {size}字节" if size is not None else ""

# 改后 — KISS: 直接取原始值，None/""/0 三种情况清晰区分
size = entry.get("size")  # None = 无此字段, 0 = 0字节, "" = 空值
if size is None or size == "":
    size_str = ""
else:
    size_str = f", {size}字节"
```
**核心改动**: `entry.get("size")` 不设默认值，三种取值（None/0/""）语义明确

---

**问题 2 — listdir 被重复调用 2 次（完全相同的路径）** ✅ 真  
Step 1 和 Step 29 都调用了 `listdir(dir_path="E:\test_dir")`，输出基本一致，浪费约 2000 tokens  
**修复方案（遵循 YAGNI — 不提供无用的冗余信息）**:  
改进 `_format_llm_data` 的摘要行，在详情中包含 `[已含目录结构: 320项]` 标注  
LLM 看到后不会重复调用同一个目录。  
但本质上这是 LLM 决策问题，formatter 层面可以做的是:
- 在摘要行末尾加 `(列表已完整展示)` 提示 LLM 无需再看一遍
- 这遵循 KISS 原则——加一行文本成本极低，但能有效防止重复

```python
def _fix_encoding(text: str) -> str:
    """SRP: 编码修复独立函数 — 小沈 2026-07-08"""
    if not text:
        return text
    try:
        text.encode('utf-8')
        return text  # 已经是合法 UTF-8

        # 尝试常见编码修复
        for enc in ('gbk', 'gb2312', 'latin-1'):

        return text
```

```python
def _build_execute_sql_llm_data(exec_code, duration_ms, sql, affected_rows, ...):
    if exec_code == "warning":
        if affected_rows > 10000:
            msg = f"影响行数{affected_rows}>10000，已回滚"
            hint = "建议缩小条件范围"
        else:
            msg = "检测到危险SQL操作（CREATE/DROP/ALTER等），已回滚"
            hint = "建议使用 dry_run=true 先验证"
        return {
            "summary": f"执行{sql[:50]}，警告: {msg}",
            "status": {"exec_code": "warning", "message": msg, ...},
            ...
        }
```
