## 二、背景与目标

### 2.1 背景：碎片化的模块结构
在 v0.18.9 之前，后端 `backend/app/` 经过多轮功能迭代，逐步沉积出大量「单职能小文件」：
- `api/v1/sessions/` 下 7 个文件管理会话路由与模型；
- `api/v1/health/` 下 3 个文件管理健康检查与工具列表；
- `api/v1/ai_config/` 下 17 个文件管理模型配置；
- `services/task/` 下 6 个文件管理任务状态；
- 多处存在 `config.py` 中间层、`paths.py` 独立模块、分散的 `lazy_loader`/`model_adapters`/`fc_message_types`。

这种「目录即包、包内再分文件」的结构带来三类问题：
1. **循环导入风险**：`paths.py` 与 `config.py` 互相引用；`LogConfig` 经 `config.py` 间接依赖 `handler.py`。
2. **导航与维护成本**：一个逻辑变更需跨 3–7 个文件，reviewer 难以一眼看清全貌。
3. **测试盲区**：碎片文件缺乏一致 import 路径，重构易引入回归。

### 2.2 目标
1. **模块合并消除碎片**：把「包/多文件」压扁为「单文件」，每个业务边界一个 `.py`。
2. **循环导入治理**：通过内联（inline）关键类、合并 `paths`→`config`、把 `fc_message_types` 上移到 `agent/` 等手段消除环。
3. **内联 import 提升**：把函数体内 `from x import y` 提升到模块顶层，消除延迟导入掩盖的循环依赖，提升可读性与启动确定性。
4. **零回归兜底**：每轮合并后跑全量测试，最终达到 772 tests 0 failures。

### 2.3 原则约束（来自 AGENTS.md 铁规）
- **KISS-DIRECT**：「能复制就复制，不重写」——合并采用复制原代码逻辑、只改 import 路径的方式，杜绝行为改写引入新 bug。
- **禁止 backward**：合并后不再保留旧模块兼容别名（除约定别名表 sync 场景）。
- **复用优先**：新建公用函数前先查 `FUNCTIONS.md`；删除 `test_marker.py` 后同步 `FUNCTIONS.md`。

## 四、关键技术点

### 4.1 循环导入治理手法
扁平化战役采用四种手法消除环（均观测于 commit 与当前结构）：
1. **内联关键类**：`LogConfig` 从 `config.py` 内联到 `handler.py`，切断 config→handler 的环。
2. **合并互为依赖的模块**：`paths.py` 合并入 `config.py`，使路径与配置同源。
3. **上移/下沉归属**：`fc_message_types` 上移到 `agent/`，`stream_parser` 下沉 `core/`，让依赖方向单向。
4. **import 提升顶层**：把延迟 import 改为顶层 import，循环依赖在 import 期暴露，强制在设计期解决。

### 4.2 inline import 提升的工程意义
- Before：`def f(): from app.x import y` —— 调用时才 import，环被「藏」起来。
- After：`from app.x import y` 置于模块顶部 —— import 期即解析。
- 收益：启动确定性提升；静态分析（IDE/类型检查）可用；杜绝运行期偶发 `ImportError`。
- **实测覆盖**：小沈 2026-07-09 的 6 批次共 59 个文件（12+6+11+16+9+5）完成提升，覆盖工具层、注册层、服务层、agent 层、api 层，是全版本 import 图净化的主体工程。

### 4.3 合并-测试闭环（守门机制）
每次合并遵循「复制代码 → 改 import → 跑 pytest → 0 failure 才合入」：— 小欧 2026-07-12
```text
合并 sessions   → pytest → 0 failure
合并 health     → pytest → 0 failure
合并 ai_config  → pytest → 772 passed, 0 new failures
累计 8 轮完成   → 772 tests 0 failures
```
该闭环是「禁止 backward + 复制不重写」策略可落地的前提：无回归兜底，大规模合并即不可控。

### 4.4 772 tests 0 failure 兜底机制
- 每轮合并（sessions / health / ai_config / task …）后均跑 `pytest`。
- ai_config 合并后明确记录「772 tests passed, 0 new failures」。
- 累计 8 轮合并完成，全量测试维持 0 失败，证明「复制不重写」策略有效。

### 4.5 Shell 中文编码修复的技术要点
北京老陈 2026-07-09 的 Shell 中文编码修复采用「三管齐下」：— 小欧 2026-07-12
1. **编码设置统一**：`shell_engine.py` 的 PS stdin 编码改为 `locale.getpreferredencoding()`（v0.18.9 已落地 N1 修复），本次补全其余分支；
2. **Prompt 实际 shell 统一**：让执行路径与提示词中声明的 shell 一致，避免「提示 PowerShell 实跑 CMD」的编码错位；
3. **安全检查确认流程**：编码修复后重新走 `tool_safety_checker` 确认，确保乱码修复不绕过安全分级。
- 对应文档：`Shell 中文编码乱码分析报告 + 测试记录（unit / E2E-P9）`（3.12 节）。

### 4.6 extra_body_params 的协议不破坏设计
- `client_sdk.py` 的 `extra_body` 默认值 `None`，`if extra_body: body.update(extra_body)` 保证无特殊参数时行为完全不变（向后兼容由默认 `None` 保证，但代码未引入旧路径别名，符合「禁止 backward」——此处 `None` 是正常缺省而非兼容垫片）。
