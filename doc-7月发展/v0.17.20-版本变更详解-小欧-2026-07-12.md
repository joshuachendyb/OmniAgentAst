## 二、背景与目标

### 2.1 背景
v0.17.18 之前，后端 63 个工具在接收 LLM（大语言模型）返回的异常参数时缺乏前置防御。LLM 常返回 `None`、空字符串、整型、超范围枚举值，而各工具直接在业务函数中对参数做 `Path(x)`、`x.strip()`、`x.startswith(...)` 等操作，触发 `TypeError` / `AttributeError` / `ValueError`，导致 Agent 的 ReAct 循环在工具层而非结果层崩溃，错误无法回传给 LLM，表现为“工具无响应”或“500 内部错误”。— 小欧-2026-07-12

同时，v0.17.19 已启动工具命名归一（FILE/shell/fundamental 分类统一短名），v0.17.20 作为该轮重构的收尾版本，继续完成小文件合并、状态管理集中、残留重命名与死代码清理。— 小欧-2026-07-12

### 2.2 目标
1. **防御性**：工具入口对 `None`/空/非 str 参数统一前置校验，崩溃收敛到 `build_error` 返回结构化错误。
2. **诚实性**：错误提示区分真实原因（文件不存在 vs 权限不足 vs 格式错误），避免编造兜底提示（为后续 v0.18.13 诚实化埋下伏笔）。
3. **归一收尾**：完成 AgentStatus 集中管理、FILE/shell/fundamental 工具的正式重命名与全链路同步。
4. **健壮性补强**：修复引号内 `&&` 被破坏、月份截断、pre-1970 时间戳 `OSError`、表格被 `elif` 丢弃等具体缺陷。— 小欧-2026-07-12

#### 3.1.13 execute_shell_command.py — 引号内 `&&` 被破坏重写 + `_close_if_blocks` 右往左扫描
**文件**：`backend/app/tools/shell/execute_shell_command.py:105`
**动机**：PowerShell 5.1 不原生支持 `&&`/`||`，需翻译为 `if` 块。但初版翻译器在遇到引号内包含 `&&`（如字符串字面量）时误判为命令连接符，破坏语义；且 `if` 块闭合顺序错误。
**after（真实代码，核心片段）**：
```python
def _translate_powershell_operators(command: str) -> str:
    """将 && 和 || 翻译为 PowerShell 5.1 兼容语法"""
    if '&&' not in command and '||' not in command:
        return command
    ...
    in_dq = False; in_sq = False; depth = 0
    ...
    in_outer = not in_dq and not in_sq and depth == 0 and not in_lc and not in_bc and not stop
    if in_outer and command[i:i+2] == '&&':
        result.append('; $__ok=$?; if ($__ok) { ')
        i += 2; continue
    if in_outer and command[i:i+2] == '||':
        result.append('; $__ok=$?; if (-not $__ok) { ')
        i += 2; continue
```
关键改进：**仅当 `in_outer` 为真（不在引号/子表达式/注释中）才翻译 `&&`/`||`**，引号内的 `&&` 被视为字面量保留。
`_close_if_blocks` 采用**右往左（reverse）扫描**补 `}`：
```python
def _close_if_blocks(s: str) -> str:
    markers = ['; if ($__ok) { ', '; if (-not $__ok) { ']
    positions = []
    for marker in markers:
        start = 0
        while True:
            pos = s.find(marker, start)
            if pos == -1: break
            positions.append((pos, marker)); start = pos + len(marker)
    positions.sort(key=lambda x: x[0], reverse=True)   # 右往左
    for pos, marker in positions:
        after = s[pos + len(marker):]
        next_block = len(after)
        for m in markers:
            p = after.find(m)
            if p != -1 and p < next_block: next_block = p
        insert_pos = pos + len(marker) + next_block
        s = s[:insert_pos] + ' }' + s[insert_pos:]
```
**before**：旧版（或版本错配中的缺陷态）未区分引号内外，且从左往右顺序闭合导致嵌套 `if` 的 `}` 位置错位，生成的脚本语法错误。
**影响**：PowerShell 翻译器可正确处理含字面量 `&&` 的命令，多段 `&&`/`||` 链闭合正确。— 小欧-2026-07-12

## 四、关键技术点

### 4.1 路径校验 None 防御的统一范式
v0.17.20 在 `validate/file_path_checker.py` 与 `validate/registry_path_checker.py` 确立统一守卫范式：
```python
if not isinstance(x, str) or not x.strip():
    return False, "…不能为空", None
```
该范式随后被 `validate_str_param`（:257）抽象为可复用函数，供 `create_task` 等 8 个工具在 v0.17.21 直接调用，实现 DRY。— 小欧-2026-07-12

### 4.2 execute_shell_command 引号内 `&&` 重写
核心在于 `in_outer` 判定（:152），综合 `in_dq`/`in_sq`/`depth`/注释态，确保仅在命令顶层翻译 `&&`/`||`。这是 PowerShell 5.1 兼容性的关键防线，避免字符串字面量被破坏。— 小欧-2026-07-12

### 4.3 `_close_if_blocks` 右往左扫描
嵌套 `if` 块必须从内到外（右到左）闭合，故 `positions.sort(key=..., reverse=True)`（:180）。若从左往右，外层 `}` 会先于内层插入，破坏层级。该设计保障了多段 `cmd1 && cmd2 || cmd3` 的正确括号配对。— 小欧-2026-07-12
