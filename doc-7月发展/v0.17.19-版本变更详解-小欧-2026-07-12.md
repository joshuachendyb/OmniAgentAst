## 二、背景与目标

### 2.1 背景：模块碎片化与命名不一致

在 v0.17.19 之前，代码库中积累了大量「小文件 / 零散 helper」：

- `chat/`、`task/`、`sessions/`、`conversation/` 各目录中存在多个仅含一两个函数的 helper 文件，分散在宿主模块之外，导致 import 链路冗长、阅读成本高；
- 工具命名风格不统一：同一类工具中，有的工具名是「动词+名词」长名（如 `read_text_file`、`execute_shell_command`、`get_system_info`），有的已是短名（如 `readtext` 此前的部分文件命名），LLM 在工具选择时缺乏一致性锚点；
- `AgentStatus` 状态枚举散落在多处，`list_tools` 逻辑与 health 路由混杂；
- `TOOL_TIMEOUTS` 中保留了已删除工具的陈旧条目（`shell_background` / `execute_python` / `execute_javascript`），误导超时配置阅读。

### 2.2 目标

1. **消除碎片**：将零散 helper 合并进同层宿主模块，减少文件数与跨文件调用；
2. **命名归一**：将 16 个工具统一为「小写短名 + 语义化」命名，并同步更新 schema 类名、别名表、常量键、超时键、前端引用；
3. **清理陈旧配置**：删除 `TOOL_TIMEOUTS` 已失效条目，修正 `version.txt` 路径，统一 observation 截断逻辑；
4. **稳定性增强**：`DEFAULT_LLM_TIMEOUT` 由 120s 提升至 150s，L1 重试新增 `RemoteProtocolError` 捕获；
5. **可运行性**：新增 `start_backend.bat` 后端启动脚本。

> 编写人：小欧 - 2026-07-12

## 四、关键技术点

### 4.1 命名归一规则

v0.17.19 确立的命名归一规则（后续 v0.17.20、v0.18.13 沿用并扩展）：

1. **小写短名**：工具名全小写、无下划线，语义自包含（`readtext` / `shell` / `sysinfo` / `httpget`）；
2. **四类联动更新**：每次重命名必须同步 4 处——① 实现函数名；② `file_schema.py`/`shell_schema.py` 等 Pydantic 输入类；③ `register.py` 的 `tool_methods`/`TOOL_INPUT_MODELS`；④ 别名表 + `TOOL_TIMEOUTS` 键 + 前端引用；
3. **别名兼容**：旧名作为别名保留在参数别名表 / 工具别名表，保证历史 prompt 与调用不立即失效（向后兼容过渡期，但代码本身遵循「禁止 backward」——新代码不再使用旧名）。

### 4.2 TOOL_TIMEOUTS 清理

`TOOL_TIMEOUTS`（工具层常量，`backend/app/tools/tool_constants.py`）与系统层 `constants.py` 的 `SYS_DEFAULT_LLM_TIMEOUT` 严格分层、互不引用。v0.17.19 删除 3 个失效键，避免运维误读。当前超时键与工具名一一对应（如 `shell: 120`、`readmedia: 60`、`edittext: 60`、`timenow/timeadd/timediff: 10`）。

### 4.3 DEFAULT_LLM_TIMEOUT 与重试层

- `DEFAULT_LLM_TIMEOUT`（系统层，LLM 客户端超时）= 150s，独立于工具层 `TOOL_TIMEOUTS`；
- L1 重试（系统级）针对网络/服务器瞬时异常；v0.17.19 新增 `RemoteProtocolError` 纳入可重试，后续由 error_classifier 黑名单策略天然覆盖。

## 六、风险与遗留

1. **别名过渡期**：v0.17.19 重命名后以别名表兼容旧名，但项目铁规「禁止 backward」。后续版本（v0.18.13）进一步做参数短名化，仍保留别名表以支持 LLM 历史调用，需在最终稳定版评估是否彻底移除旧名别名。
2. **L1 重试策略演进**：v0.17.19 显式新增 `RemoteProtocolError` 捕获；v0.17.22（2026-07-05）`error_classifier.py` 重构为黑名单策略，默认未识别异常即 `SERVER`(retryable)，`RemoteProtocolError` 已被该默认分支覆盖。两处不冲突，但实现位置已迁移，后续维护应以 `error_classifier.py` 为准。
3. **模块合并的回归面**：12 项合并重构改动文件多，依赖 `FUNCTIONS.md` 与 import 路径全部同步；v0.17.20 的 20 项工具内部缺陷修复部分是对本次合并后暴露问题的补强。
4. **`__init__.py` 抽离**：3.2.2 抽离包级代码依赖各处 import 顺序正确，需在 CI 中验证无循环导入（后续 v0.18.x 的扁平化重构进一步解决）。
