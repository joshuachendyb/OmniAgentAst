## 二、背景与目标

### 2.1 背景

v0.17.20 已建立「工具内部功能代码缺陷修复（20 项）+ 路径校验基础」。但在真实 E2E 与 prompt-log 挖掘中暴露出三处系统性脆弱点：— 小欧-2026-07-12

1. **Shell 执行引擎健壮性不足**：PowerShell 5.1 下 `&&`/`||` 翻译状态机存在未闭合 `if` 块；CMD 分支使用 `Popen(shell=True)` 时引号被 `CommandLineToArgvW` 吞噬；安全检查正则因 `re.DOTALL` 跨行误匹配导致假阳性拦截。
2. **文件工具安全增强缺口**：`read_text_file` 无行号、超长行未截断；`edit_text_file` 仅用软级冲突检测（警告而非阻断），多轮 Agent 编辑存在覆盖外部变更风险。
3. **路径校验不统一**：保留字符检查误伤整路径、缺少盘符存在性检查，27 个工具与 Safety 层注释口径不一致。

### 2.2 目标

- 提升 Shell 引擎在 PS5.1/CMD 下的执行正确性（去假阳性、去引号丢失、补状态机）。
- 强化文件工具可读性与安全性（行号、长行截断、相似文件提示、严格冲突阻断）。
- 统一路径校验入口，新增盘符检查与 `validate_str_param` 空参校验。
- 通过 PersistentShell 替换一次性 `subprocess`，消除反复启动开销并清理废弃 `runcode`。

— 小欧-2026-07-12

### 3.1 fix：shell 执行引擎缺陷修复（3 项）

#### 3.1.1 safety.py DOTALL 假阳性 — 小欧-2026-07-05

**动机**：`SHELL_DANGEROUS_PATTERNS` 中 `Remove-Item ... -Recurse` 等规则在用户把命令写成多行（如 `Remove-Item \` 换行 `-Recurse`）时，因正则带 `re.DOTALL` 跨行串到无关文本，误判为高风险并阻断。— 小欧-2026-07-12

**Before**（`execute_shell_command_safety.py` 旧逻辑，概念示意）：

```python
# 旧：直接用原始多行命令匹配，DOTALL 跨行串文本
for pattern_str, desc, level in SHELL_DANGEROUS_PATTERNS:
    if re.search(pattern_str, command, re.IGNORECASE | re.DOTALL):
        ...
```

**After**（实测 `execute_shell_command_safety.py:57-62`）：

```python
# 归一化多行命令为单行，防止 DOTALL 的跨行误匹配 — 小欧 2026-07-05
normalized = command.replace('\r\n', ' ').replace('\n', ' ')
for pattern_str, desc, level in SHELL_DANGEROUS_PATTERNS:
    if re.search(pattern_str, normalized, re.IGNORECASE):
        if level == "HIGH":
            return SafetyResult(is_safe=False, blocked=True, ...)
```

**影响**：多行高危命令仍能被识别（仍含 `-Recurse` 关键字），但不再因换行串到后续无关文本而假阳性拦截合法命令。— 小欧-2026-07-12

#### 3.1.3 PowerShell 翻译器状态机修复 + 关闭 if 块（B4）— 小沈-2026-07-05

**动机**：`_translate_powershell_operators` 将 `&&`/`||` 翻译成 `; if ($__ok) { ... }`，但原实现可能漏闭合右花括号，导致 PowerShell 语法错误（B4 缺陷）。— 小欧-2026-07-12

**关键代码**（`execute_shell_command.py:105-190`）：状态机用 `in_dq/in_sq/depth/in_lc/in_bc/stop` 跟踪引号/子表达式/注释块，遇 `&&`/`||` 在外层才插入 `; $__ok=$?; if ($__ok) { ` 或 `; if (-not $__ok) { `；翻译后统一调用 `_close_if_blocks(translated)` 从右往左补 `}`：

```python
def _close_if_blocks(s: str) -> str:
    """为翻译后的 if 块补上闭合 }"""
    markers = ['; if ($__ok) { ', '; if (-not $__ok) { ']
    positions = []
    for marker in markers:
        start = 0
        while True:
            pos = s.find(marker, start)
            if pos == -1:
                break
            positions.append((pos, marker)); start = pos + len(marker)
    positions.sort(key=lambda x: x[0], reverse=True)  # 右→左，保证嵌套正确闭合
    for pos, marker in positions:
        after = s[pos + len(marker):]
        next_block = len(after)
        for m in markers:
            p = after.find(m)
            if p != -1 and p < next_block:
                next_block = p
        insert_pos = pos + len(marker) + next_block
        s = s[:insert_pos] + ' }' + s[insert_pos:]
    return s
```

**影响**：修复 PS5.1 下 `&&`/`||` 链式命令的语法完整性，消除 B4 运行期报错。— 小欧-2026-07-12

def add_line_numbers(content: str, offset: int = 1) -> str:

def check_conflict_strict(file_path: str) -> Optional[str]:
    """严格冲突检查（阻断级）：与 check_conflict 同逻辑但语义为阻断 — 小欧 2026-07-05"""
    resolved = Path(file_path).resolve()
    key = str(resolved)
    recorded = _state.get(key)
    if recorded is None:

    recorded_mtime, _ = recorded

        current = resolved.stat().st_mtime_ns

## 四、关键技术点

### 4.1 PersistentShell 替换一次性 subprocess

核心收益是「进程复用」。旧实现每命令 `Popen` 启动 `powershell.exe`（~100ms/次），多轮 Agent 调用累积显著。新引擎按 `cwd` 建池，`exec()` 直线调用 `_ensure_alive() → _exec()`，失败自动 `_close()` 重启（最多 2 次重试）。输出经临时文件回传规避管道死锁，`_poll_for_file` 指数退避避免忙等。— 小欧-2026-07-12

### 4.2 file_state 严格冲突检测

`check_conflict_strict` 与软级 `check_conflict` 共用「mtime_ns + content_hash」状态表，但语义不同：软级仅返回 warning（数据仍进 metrics），严格级返回 `str` 即阻断编辑。这是多轮 Agent 安全的必要约束——防止 LLM 基于过期 `readtext` 内容覆盖外部变更。— 小欧-2026-07-12

### 4.3 路径校验盘符检查

盘符检查置于第 1 层最前，是最外层快速否决；额外检测路径中段多余盘符（如 `E:\dir\E:\file`），防 LLM 畸形路径穿透。保留字符检查收窄到 `Path(path).name`，避免把合法的 `/` 路径分隔符误判为非法字符。— 小欧-2026-07-12

### 4.4 ReDoS 防护

对 `grep` 的 `pattern` 在编译前做嵌套量词静态检测（`(a+)+`、`(a+){2,}`）与长度上限（200），literal 模式因已 `re.escape` 跳过检测。属「输入前置拦截」而非正则引擎层防护，实现简单且零误伤。— 小欧-2026-07-12

## 六、风险与遗留

- **PersistentShell 单进程串行**：同 cwd 实例加锁（`self._lock`），并发工具调用会串行化；高并发场景可能成为瓶颈（已在 v0.18.x 通过实例池进一步优化）。
- **file_state 进程内内存表**：`_state` 为模块级 dict，进程重启即丢失，跨进程无效（Agent 单进程内有效）。
- **盘符检查依赖 `os.path.exists(drive + "\\")`**：可移动盘未挂载时可能误判，但给出可用盘符列表缓解。
- **遗留**：CMD 分支仍用一次性 `subprocess.Popen(bat_path)`（未并入 PersistentShell），属有意的双引擎并存设计。— 小欧-2026-07-12
