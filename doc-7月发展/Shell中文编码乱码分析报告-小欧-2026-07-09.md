# Shell 中文编码乱码全链路分析报告

**创建时间**: 2026-07-09 08:30:29
**编写人**: 小欧
**版本**: v1.0

## 一、问题描述

PowerShell 执行中文命令时输出乱码，如"高级计算器"显示为"楂樼骇璁＄畻鍣"。

## 二、全链路分析（10遍代码熟读后）

### 2.1 当前启动的 Shell 类型

```python
# shell_engine.py:210
pwsh = shutil.which("pwsh.exe") or shutil.which("powershell.exe")
```

**启动优先级**: pwsh.exe (PS 7+) → 找不到 → powershell.exe (PS 5.1)

### 2.2 编码链路

```
Python 输出 "高级计算器" (UTF-8)
  → PS5.1 2>&1 合并流（错误流/管道用GBK解读UTF-8字节）
  → 变成 "楂樼骇璁＄畻鍣"（数据已损坏）
  → Out-File -Encoding utf8 写入文件（写的是乱码的UTF-8）
  → safe_read_file 用utf-8读取（读到的是乱码str）
```

### 2.3 四大薄弱点

| # | 问题 | 位置 | 严重性 |
|---|------|------|--------|
| ① | **PS命令模板没设 `[Console]::OutputEncoding`** | `shell_engine.py:244` | ⚠️ 根源 |
| ② | **PS 分支输出没过 `_fix_encoding`** | `exec_shell_cmd.py:395-397` | ⚠️ 缺少安全兜底 |
| ③ | **`_fix_encoding` 对 CJK 乱码完全无效** | `exec_shell_cmd.py:276-289` | 🔴 设计局限 |
| ④ | **`2>&1` 合并流时错误流被GBK编码** | `shell_engine.py:245-246` | ⚠️ 加剧乱码 |

### 2.4 `_fix_encoding` 为什么对 CJK 乱码无效？

```python
text = "楂樼骇璁＄畻鍣"   # 每个字都是合法CJK码位(0x4E00-0x9FFF)
text.encode('utf-8')       # ✅ 能编码，不抛异常！
→ 函数直接 return text，检测不到乱码！
```

`_fix_encoding` 只能修复**码位 > 255**的乱码（latin-1中间转换），而 CJK 乱码字符在 0x4E00-0x9FFF 范围内，完全无法检测。

### 2.5 扩展发现的问题

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| ⑤ | **Prompt与实际shell不一致** | `system_prompts.py:95` | 始终说"Windows PowerShell 5.1"，有pwsh时实际用PS7+ |
| ⑥ | **MEDIUM风险确认缺失** | `exec_shell_cmd.py:373-379` | 只处理 `blocked`(HIGH)，忽略 `requires_confirmation`(MEDIUM) |

## 三、修复方案

### 3.1 三管齐下修复编码乱码

**修复① — 源头阻断**（`shell_engine.py:245`）：
```diff
- $OutputEncoding=[System.Text.Encoding]::UTF8;
+ [Console]::OutputEncoding=[System.Text.Encoding]::UTF8; $OutputEncoding=[System.Text.Encoding]::UTF8;
```
- `[Console]::OutputEncoding` 控制 PS5.1 **所有输出管道**的编码
- 设 UTF-8 后不管 `2>&1` 还是 Out-File 都统一走 UTF-8

**修复② — 安全兜底**（`execute_shell_command.py:395-397`）：
```diff
  stdout_str = result.get("stdout", "")
  stderr_str = result.get("stderr", "")
+ stdout_str = _fix_encoding(stdout_str)
+ stderr_str = _fix_encoding(stderr_str)
```
PS 分支输出也过 `_fix_encoding`，与 CMD 分支保持一致。

**修复③ — 去掉 false positive 检测**（`_fix_encoding` 回退）：
- 原来的 CJK 双通道检测（`('utf-8', 'gbk')` 方向）会把正确中文误修成乱码
- 回退到只保留 latin-1 兜底方案

### 3.2 Prompt与实际shell统一

`system_adapter.py` 新增 `get_default_shell_name()`，按 `shell_engine.py` 的启动优先级（pwsh → powershell）返回实际默认 shell 名称。`system_prompts.py` 改用此函数，消除信息差。

### 3.3 安全检查确认流程统一

`execute_shell_command.py:373` 从 `if safety and safety.blocked:` 改为 `if safety:`，分两分支：
- `safety.blocked` (HIGH) → 阻断
- `safety.requires_confirmation` (MEDIUM) → 记录日志，放行（上层确认流程已处理）

## 五、PS7 vs CMD 推荐

| Shell | 编码问题 | 推荐度 |
|-------|---------|--------|
| **PS7 (pwsh.exe)** | 默认 UTF-8，无 GBK 问题 | ⭐⭐⭐⭐⭐ **最优** |
| **PS5.1 + 已修复版** | 修好后稳定 | ⭐⭐⭐⭐ 可行 |
| **CMD** | GBK 编码更严重，不推荐 | ⭐ |

**最不折腾的解法**: 系统装 pwsh.exe (PS 7+)，一切默认 UTF-8，零编码问题。
