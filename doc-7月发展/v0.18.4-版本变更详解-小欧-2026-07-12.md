## 二、背景与目标

### 2.1 背景

v0.18.3 之前，fetch_webpage 对 SPA（单页应用）站点的正文抽取能力偏弱：当页面纯前端渲染、HTML 层仅有空 `<div id="root">` 壳时，传统 `html2text` 转换几乎拿不到有效正文，且 Playwright 渲染路径的超时控制存在"条件分支遗漏"问题，部分站点会卡死到进程级超时。同时，grep / shell / http_request 三类高频工具在「观测输出如何呈现给 LLM」这件事上积累了若干体验债：

- grep 的 `files_with_matches` 模式只返回文件路径，LLM 无法定位具体行号；
- shell 超时/警告信息在 summary 与 detail 两处重复，且 warning 摘要词不达意；
- http_request 在异常 `str(e)` 为空字符串时，会向 LLM 返回「无详细信息」的空 fallback，难以排障。

### 2.2 目标

1. **fetch_webpage 质量跃升**：支持 SSR 嵌套 JSON 抽取（window.__INITIAL_STATE__ / __NUXT__ / __NEXT_DATA__），Playwright 无条件超时，整体性能优化。— 小欧-2026-07-12
2. **grep 展示增强**：files_with_matches 输出「文件路径 + 行号列表」，表头语义化。— 小欧-2026-07-12
3. **shell / search / grep 冗余信息去重**：超时、警告只在最合理的位置出现一次。— 小欧-2026-07-12
4. **错误提示诚实化**：http_request 空 `str(e)` 给出 LLM 可读的详细指引，不再编造空兜底。— 小欧-2026-07-12

## 三、逐项变更详解

### 3.1 feat：fetch_webpage 全面增强（SSR 嵌套 JSON + Playwright 无条件超时 + 性能优化）

**提交**：2461dfcb4（小沈-2026-07-08）；**涉及文件**：`backend/app/tools/network/fetch_webpage.py`

#### 3.1.1 动机

旧版 `_extract_main_content` 仅用 `HTMLParser` 抓 `<article>/<main>/<div id="main">` 等语义容器；对 Nuxt/Vue/Next 等 SSR 框架站点，正文已序列化为 JS 变量（如 `window.__INITIAL_STATE__ = {...}`），HTML 中根本无可见正文，导致抽取的 markdown 为空或极短，触发 `<100字走warning` 分支，输出质量差。

#### 3.1.2 关键技术实现（真实代码）

新增 `_balanced_braces_extract`，用**栈式扫描**替代旧版正则 `{.*?}`（正则无法正确处理嵌套大括号）：— 小沈-2026-07-08

```python
def _balanced_braces_extract(text: str, start: int = 0) -> Optional[str]:
    """从start位置找第一个{，返回平衡大括号匹配的完整JSON字符串 — 小沈 2026-07-08"""
    brace_start = text.find('{', start)
    if brace_start == -1:
        return None
    depth = 0
    in_string = False
    escape = False
    for i in range(brace_start, len(text)):
        ch = text[i]
        if escape:
            escape = False
            continue
        if ch == '\\' and in_string:
            escape = True
            continue
        if ch == '"':
            in_string = not in_string
            continue
        if not in_string:
            if ch == '{':
                depth += 1
            elif ch == '}':
                depth -= 1
                if depth == 0:
                    return text[brace_start:i + 1]
    return None
```

`_extract_ssr_json_content` 依次匹配三种 SSR 前缀，用平衡括号提取后递归扫描：— 小欧-2026-07-08

```python

    r'window\.__NUXT__\s*=\s*',

]
...

data = json.loads(json_str)
```

`_scan_json_for_articles` 递归深度上限 6、条目上限 50，防止超大 JSON 拖垮性能：— 小欧-2026-07-08

```python
def _scan_json_for_articles(obj, results, max_items=50, depth=0):
    if depth > 6 or len(results) >= max_items:
        return
    if isinstance(obj, dict):
        title = obj.get("title") or obj.get("articleTitle") or ""
```

#### 3.1.3 Playwright 无条件超时

新增 `_has_embedded_state` 与 `_needs_browser` 判定函数，从 rolling-reader 的 `needs_browser()` V4 借鉴。当 HTTP 层 HTML 检测到是 SPA 空壳（`id="root"`/`__next` 等标记、脚本占比 >50%、空白 `<title>` 且 `<20000` 字节等）时，**自动回退 Playwright**；Playwright 本身用 `page.set_default_timeout(timeout * 1000)` 做「无条件超时」，杜绝卡死：— 小沈-2026-07-08

```python
async def _fetch_via_playwright(url, proxy, timeout, extract_format, max_tokens):
    ...
    await page.set_default_timeout(timeout * 1000)
    await page.goto(url, wait_until="networkidle", timeout=timeout * 1000)
```

主流程 `fetchpage` 在 HTTP 抓取后做 Playwright 回退决策，仅当 `len(pw_extracted) >= len(http_extracted) * 1.5` 才采用浏览器结果，否则回退 HTTP HTML，避免无谓的性能损耗：— 小沈-2026-07-08

```python
if _needs_browser(html_content, status_code, mime)[0]:
    logger.info(f"[fetchpage] SPA空壳检测,自动回退Playwright: {url}")
    pw_res = await _fetch_via_playwright(url, proxy, timeout, extract_format, max_tokens)
    ...
    if len(pw_extracted) >= len(http_extracted) * 1.5:
        extracted_content = pw_extracted
    else:
        extracted_content, truncated = http_extracted, http_truncated
```

#### 3.1.4 性能优化点

- 流式读取 HTTP 响应，硬截断 `MAX_READ_BYTES = 5_242_880`（5MB）防 OOM；`content-length > 100MB` 直接报错。— 小沈-2026-07-05（延续至本版）
- SSR JSON 抽取作为 `_html_to_markdown` 的**兜底分支**，仅在 `_extract_main_content` 为空时启用，优先走轻量 html2text。— 小欧-2026-07-08

**影响**：CSDN/掘金/Next.js 等 SSR 站点正文抽取成功率显著提升；SPA 空壳不再返回空 markdown，且浏览器回退有严格超时。

### 3.2 feat：fetch_webpage 新增 `_clean_markdown_content`

**提交**：a147217d6（小欧-2026-07-08）；**文件**：`fetch_webpage.py:168-178`

新增导航噪音清理函数，剥离 markdown 链接、Hacker News 风格 "points by / N comments / hide?id=" 噪声，合并多余空行与空格：

```python
def _clean_markdown_content(text: str) -> str:
    """清理markdown导航噪音 — 小沈 2026-07-05"""
    text = re.sub(r'\[([^\]]*)\]\([^)]*\)', r'\1', text)
    text = re.sub(r'\bnew\b\s*\|\s*\bpast\b\s*\|\s*\bcomments?\b[^\n]*?(?:login|submit)\b[^\n]*?1\.', '1.', text, flags=re.IGNORECASE)
    text = re.sub(r'\d+\s+points?\s+by\s+\S+[^\n]*', '', text, flags=re.IGNORECASE)
    text = re.sub(r'\|?\s*\d+\s+comments?\b', '', text, flags=re.IGNORECASE)
    text = re.sub(r'\|?\s*hide\?id=\S+', '', text, flags=re.IGNORECASE)
    text = re.sub(r'\n{3,}', '\n\n', text)
    text = re.sub(r' {2,}', ' ', text)
    return text.strip()
```

**影响**：HN/Reddit 类站点抽取结果更干净，LLM 直接消费质量提升。— 小欧-2026-07-12

**After**（真实代码）：warning 分支统一用「部分成功」语义，且按是否有 detail 决定 detail 内容，避免重复：

```python
if exec_code == "warning":
    _warn_msg = detail or f"退出码{returncode}，标准错误{stderr_len}字符"
    return {
        "summary": f"执行Shell命令{cmd_short}，部分成功,提示说明: {_warn_msg}",
        "action": {...},
        "status": {"exec_code": "warning", "message": "执行成功（有警告）",
                   "code": err_code or "",
                   "detail": "" if detail else f"退出码{returncode}，标准错误{stderr_len}字符",
                   "hint": hint},
        ...
    }
```

**影响**：LLM 对「命令跑了但非零退出 / 有 stderr」的语义理解更准确，且不再重复渲染 detail。— 小欧-2026-07-12

## 四、关键技术点

### 4.1 SSR 嵌套 JSON 抽取

核心难点是 SSR 框架把整站数据序列化为一个**可能多层嵌套**的 JS 对象字面量。旧版用正则 `{.*?}` 在嵌套大括号处必然截断，导致 `json.loads` 失败。本版引入 `_balanced_braces_extract`（栈式扫描），正确处理字符串内转义引号、嵌套 `{}`，再用 `_scan_json_for_articles` 递归（深度 ≤6、条目 ≤50）提取所有 `title + description/summary` 文章对。

> 该方案对 Vue/__INITIAL_STATE__、Nuxt/__NUXT__、Next.js/__NEXT_DATA__ 三类主流 SSR 框架均生效。— 小欧-2026-07-12

### 4.2 Playwright 无条件超时

`_fetch_via_playwright` 中：

```python
await page.set_default_timeout(timeout * 1000)
await page.goto(url, wait_until="networkidle", timeout=timeout * 1000)
```

`networkidle` + 显式 `timeout` 双保险，确保即使页面持续发请求也不会无限挂起；且回退决策有「1.5 倍内容长度」门槛，避免浏览器结果反而更差时拖累。— 小欧-2026-07-12

### 4.3 cmd_short 阈值演进

| 版本阶段 | 阈值 | 取舍 |
|----------|------|------|
| 早期 | 100 | 过长，易撑爆上下文 |
| 过渡 | 200 | 一度放宽，发现冗余 |
| 最终(v0.18.4) | 50 | 前35+后15 / 否则前50，平衡可读与精简 |

阈值收敛到 50 是观测输出「去冗余」主线（始于 v0.18.1 llm_data 重构）的延续。— 小欧-2026-07-12

### 4.4 grep 超时双标记

`truncated_by_deadline` 与 `truncated`（达 `MAX_SEARCH_RESULTS` 上限）解耦，使 summary 能精确表述「超时( N 秒)」还是「结果数量达到上限」，LLM 据此选择「增大 timeout」或「缩小范围」。— 小欧-2026-07-12

## 六、风险与遗留

### 6.1 风险

1. **Playwright 自动回退开销**：SPA 空壳检测触发浏览器渲染，单次 fetch 耗时上升（约 +1~3s），但已有 1.5 倍内容门槛与超时上限约束，风险可控。— 小欧-2026-07-12
2. **SSR 扫描深度限制**：递归深度 6 / 条目 50，极深嵌套或超大 JSON 可能漏抓，属性能与覆盖的折中。
3. **generate_chart 内联 JSON 误判**：`data` 以 `{` 开头但非图表数据时走 JSON 错误分支，已在 v0.18.5+ 进一步优化（见 §七）。— 小欧-2026-07-12

### 6.2 遗留

- `fetch_webpage` 的 `<100字走warning` 阈值（fetch_webpage.py:642-655）为经验值，后续版本可参数化。
- grep `only_files` 行号仅在 `data.matches[].lines` 承载，前端展示样式依赖 observation_formatter，未单独做 UI 适配回归。— 小欧-2026-07-12
