### 2.2 操作步骤

2. **临时**改动 `config.yaml:3`，把 `model: sensenova-6.7-flash-lite` 改为一个**确定拒收**的非法名（如 `model: __reject_me_invalid__`）。**只改 model 名一处**，不动 `provider` / `api_base` / `reasoning_effort`，以隔离变量、确保必出 400。
3. 独立 PowerShell 窗口启动后端：
   `Start-Process powershell -ArgumentList "-NoExit","-Command","cd 'G:\OmniAgentAs-desk\backend'; python -m uvicorn app.main:app --reload --reload-dir app --host 0.0.0.0 --port 8000"`
4. 触发一次真实对话（任意问题），让请求打到 sensenova。

### 2.4 回滚（强制）

## 三、M2 设计预案：provider 能力归一化（按 provider 裁剪参数）

### 3.1 问题陈述
- `config.yaml:90-101` 的 LLM 段把 `reasoning_effort`、`temperature`、`top_p` 等参数**按一份全局配置**下发，不区分 provider。
- 当某 provider 不支持其中某参数，服务端即返回 400（即便该参数对其余 provider 合法）。
- 当前 M1 只**透传**真因，不**消除**根因；要根治需"只把目标 provider 支持的参数发出去"。

### 3.2 设计原则（严守 10 原则）
- **KISS-DIRECT / YAGNI**：不引入 ProviderAdapter 抽象族、不建注册表；仅用一个**平面能力字典** `PROVIDER_PARAM_CAPS: dict[str, set[str]]` 描述每个 provider 接受的 optional 参数集合。
- **SRP**：参数裁剪逻辑收敛到 `client_sdk.py` 请求构建处的一个纯函数 `filter_supported_params(provider, params)`。
- **复用优先**：复用 `config.yaml` 已加载的 provider 名与参数 dict，不新增全局状态；能力字典作为常量放 `client_sdk.py` 顶部（或 `app/services/llm/` 内小常量模块，先查 `FUNCTIONS.md` 有无同类）。
- **禁止 backward / 禁止双解析**：直接对 request payload 的 `extra_body` 过滤，不保留"兼容旧 provider"分支。

### 3.3 能力字典草样
```python
# client_sdk.py 顶部常量（作者+日期署名）
PROVIDER_PARAM_CAPS: dict[str, set[str]] = {
    "sensenova": {"reasoning_effort", "temperature", "top_p"},
    "zhipu":     {"temperature", "top_p"},
    "ollama":    {"temperature", "top_p"},
    # 其余 provider 按实测补全；未列出的参数一律不下发
}
```
- 默认策略：**白名单**（只发能力字典内且配置中存在的参数），杜绝"未声明即下发"。

### 3.4 实施步骤与防退化验证
1. 先按第二章复现并锁定真因，确认是哪个参数被哪个 provider 拒收，据此填充能力字典（**用真凭实据，不许臆测**）。
2. 在 `client_sdk.py` 请求构建处插入 `filter_supported_params`，裁剪 `extra_body` / 顶层可选参数。
3. **防退化核查**：
   - 既有 5 个失败测试（与本次无关）不新增回归；`py_compile` 全过。
   - 单测：构造 `provider=未知` 时，未声明参数被剥离；`provider=sensenova` 时 `reasoning_effort` 保留。
   - 重启后端跑一次真实对话，确认 400 消失且响应正常。
4. 提交：`fix: client_sdk.py M2 provider能力归一化按provider裁剪参数 - 小欧-<日期>`，头部补编辑历史（署名+日期+根因+提升能力）。
