## 一、需求要点（北京老陈拍板）

1. **临时注入 conversation_history** — thought-only 直接写入 `conversation_history`（加 `_temp_reasoning=True` 标记），不走分离瞬态通道
2. **持久化是要的** — 持久化系统不改不动，终端路径 pop 弹掉标记再入库
3. **好的 reasoning（无重复）** — 带标记注入 → `continue` → 终端 `pop`
4. **坏的 reasoning（有去重）** — 不注入、不持久、不发射 ThoughtStep → `logger.warning` → `continue`

> **"不持久化" 的范畴说明（避免前后矛盾）**：
> - 本设计"不持久化"指 **`conversation_history`（对话上下文）**——既不在任务内持久、也不跨轮经 `chat_messages` 重载回灌。
> - 好的分支仍会发 `ThoughtStep(content=推理)` 落 `execution_steps`（DB 执行步骤日志），这是既有 UI/审计行为，**不在本次去除范围**；坏的支连 `ThoughtStep` 都不发，反而减少 DB 污染。
> - 验证链：`chat_messages.content` 只来自最终答案（`finalize_message(saved_content)`），`_load_previous_messages` 仅从 `chat_messages.content` + steps 里的 tool_calls/observations 重建上下文，**不会**把推理 ThoughtStep 回灌进 `conversation_history`。故推理污染上下文的问题被根绝，与 DB 执行步骤日志互不矛盾。

## 二、设计概要

### 2.1 核心机制

```
LLM 返回 reasoning-only
    │
    ├─ _deduped = _dedup_repeat(reasoning)
    │
    ├─ _consecutive_reasoning_only += 1
    │
    ├─ 超限(>3) → FinalStep(outcome=failed) → return
    │
    ├─ [好的] _deduped == reasoning (无重复)
    │     ├─ append {role:assistant, content:"", reasoning:_deduped, reasoning_content:_deduped, _temp_reasoning:True} 到 conv_hist  # OpenAI为主+兼容DeepSeek
    │     ├─ emit ThoughtStep (前端可见)
    │     └─ return → continue
    │
    └─ [坏的] _deduped != reasoning (有去重)
          ├─ ❌不注入 conversation_history
          ├─ ❌不持久化
          ├─ ❌不发射 ThoughtStep
          ├─ ✅ logger.warning 记录一次
          └─ return → continue

后续终端路径（真实答案/错误/MAX_ROUNDS失败等）：
    → pop_temp_messages() 弹掉所有(全表扫描) _temp_reasoning 标记消息  # 单一收口于 react_cycle._finalize_cycle(finally出口)
    → add_assistant_message(真实内容)
    → 持久化（干净，无推理）
```

### 2.2 两条关键约定

| 约定 | 说明 |
|------|------|
| **好的** 注入后需要 `pop` | 单一收口于 `react_cycle._finalize_cycle`（finally 出口）直调 `agent.message_builder.pop_temp_messages()` 弹掉标记；answer_handler 各终端路径不再散插 pop（收敛去冗余） |
| **坏的** 不注入所以不需要 `pop` | 没有标记入过 `conversation_history`，无需清理 |

### 2.3 内部标记 `_temp_reasoning`

- 类型：`bool`，值 `True`
- 作用：标识 `conversation_history` 中的临时推理条目
- 范围：仅在 `conversation_history` 字典中存在；**不会泄漏到 LLM 请求 wire**（`prepare_messages_for_llm` 中 strip）

### 2.4 `pop_temp_messages()` 方法

新增在 `MessageBuilder`：

```python
def pop_temp_messages(self) -> int:
    """移除 conversation_history 中所有 _temp_reasoning 标记的消息, 返回移除数量。
    【修正】全表扫描移除(非仅尾部): B3 warning(无标记)会插在连续reasoning-only轮之间,
    仅弹尾部会遗留被隔开的早期标记推理。"""
    removed = 0
    kept = []
    for _m in self.conversation_history:
        if _m.get("_temp_reasoning"):
            removed += 1
        else:
            kept.append(_m)
    self.conversation_history = kept
    return removed
```

调用位置（单一收口）：
- `react_cycle._finalize_cycle`（finally 出口）直调 `agent.message_builder.pop_temp_messages()`
- `answer_handler.py` 各终端路径不再调用（已收敛删除, 避免冗余散插）

### 2.5 `prepare_messages_for_llm` strip 标记

```python
def prepare_messages_for_llm(self) -> List[Dict[str, Any]]:
    self._cap_temp_history()
    messages = [dict(msg) for msg in self.conversation_history]  # 浅拷贝防篡改
    if self.temp_history:
        messages += [dict(msg) for msg in self.temp_history]
    for msg in messages:
        msg.pop("_temp_reasoning", None)
    return messages
```

### 2.6 安全网：`_finalize_cycle` 兜底 pop

```python
def _finalize_cycle(agent):
    agent.message_builder.pop_temp_messages()
    agent._on_after_loop()
    agent._step_emitter.complete_task(agent.status == AgentStatus.COMPLETED)
```

## 三、逐文件代码 diff

### 3.1 `answer_handler.py`

#### 3.1.1 reasoning-only 分支改写（L156-173 旧 → L156-178 新）

**旧代码**:

```python
if not content and reasoning:
    _deduped = _dedup_repeat(reasoning)
    agent._consecutive_reasoning_only += 1
    if agent._consecutive_reasoning_only > REASONING_ONLY_MAX_ROUNDS:
        logger.warning(...)
        yield FinalStep(outcome="failed", ...)
        return
    logger.info(f"[handle_answer] LLM返回推理内容(step={step}), 注入助理消息继续循环...")
    agent.message_builder.add_assistant_message(_deduped)
    yield ThoughtStep(step=step, content=_deduped, reasoning="")
    return
```

**新代码**:

```python
if not content and reasoning:
    _deduped = _dedup_repeat(reasoning)
    agent._consecutive_reasoning_only += 1
    if agent._consecutive_reasoning_only > REASONING_ONLY_MAX_ROUNDS:
        logger.warning(f"[handle_answer] 连续{agent._consecutive_reasoning_only}轮reasoning-only无进展(step={step}), 终止任务")
        yield FinalStep(outcome="failed", ...)
        return

    if _deduped == reasoning:
        # ── 好的：无重复 → 带标记注入 ──
        logger.info(f"[handle_answer] LLM返回推理内容(step={step}), 注入临时推理(连续reasoning-only={agent._consecutive_reasoning_only})")
        agent.message_builder.conversation_history.append({
            "role": "assistant",
            "content": "",
            "reasoning": _deduped,
            "reasoning_content": _deduped,
            "_temp_reasoning": True,
        })
        yield ThoughtStep(step=step, content=_deduped, reasoning="")
    else:
        # ── 坏的：重复去重 → 不注入, 日志后继续 ──
        logger.warning(f"[handle_answer] reasoning检测到重复去重(step={step}), 跳过注入")

    return
```

> **关键差异**：
> - 旧：不分好坏，一律 `add_assistant_message`（无标记，持久化）
> - 新：好的带标记注入；坏的跳过；两者都 `return`

#### 3.1.2 ~~各终端路径前插 `pop_temp_messages()`~~ （v3.0 已收敛删除）

> **v3.0 重构**：原 v2.0 在 answer_handler 5 处终端路径（error/未知类型/真空/MAX_ROUNDS失败/真实答案）各插一次 `pop_temp_messages()`。
> 因 `_finalize_cycle` 位于 `run_react_cycle` 的 `finally` 出口，**所有终态路径（正常/错误/取消/异常/max_steps）必经**，故 5 处散插全部冗余。
> v3.0 将 pop **单一收口**于 `_finalize_cycle` 直调 `agent.message_builder.pop_temp_messages()`，answer_handler 不再散插（更 KISS-DIRECT、单一职责、消除冗余）。
> pop 仅针对已注入的好的推理；坏的（有去重）子分支不注入标记，无需清理。

### 3.2 `message_builder.py`

#### 3.2.1 新增 `pop_temp_messages()`（L161-166 之后）

```python
def pop_temp_messages(self) -> int:
    """移除 conversation_history 尾部 _temp_reasoning 标记的临时消息,返回移除数量"""
    removed = 0
    while self.conversation_history and self.conversation_history[-1].get("_temp_reasoning"):
        self.conversation_history.pop()
        removed += 1
    return removed
```

## 四、十大规范核验

### 4.1 日常 6 条

| 原则 | 符合 | 说明 |
|------|------|------|
| **SRP** 单一职责 | ✅ | `pop_temp_messages` 只弹标记；各分支职责单一 |

| **KISS-DIRECT** 简单直接 | ✅ | 设计直线：注入→continue→pop→持久。无分离通道无异步清理 |
| **SLAP** 同抽象层 | ✅ | answer_handler 层只调 `pop_temp_messages()`，底层实现在 MessageBuilder |
| **YAGNI** 不过度 | ✅ | 坏的直接跳过，不造新概念来处理它 |
| **禁止 backward** | ✅ | 不保留旧代码旧路径 |

## 五、边界条件

| # | 场景 | 预期 | 保障 |
|---|------|------|------|
| 1 | 连续多轮好的 → 正常 answer | pop（全表扫描）弹掉所有标记消息 | `_finalize_cycle` 直调 `pop_temp_messages`，全表移除非仅尾部 |
| 2 | 好的 → 坏的 → 好的 → answer | pop 弹掉两轮好的标记，坏的没注入所以无残留 | pop 全表扫描，只移除带 `_temp_reasoning` 的（坏的未注入故不在） |
| 3 | 坏的轮次 → answer | 上一轮好的无，pop 弹 0 条；answer 正常入库 | pop 不加标记就无操作 |
| 4 | 坏的直接连续多轮超限 failed | `_consecutive_reasoning_only` 照加，超限 termination 正常触发 | 增量在好的/坏的统一入口 |
| 5 | 好的 + action（调工具） | 标记消息留在 conv_hist（action 不是 terminal，不 pop） | `pop_temp_messages` 仅在 `_finalize_cycle`(finally出口) 调用 |
| 6 | 异常中断（finally 前 crash） | 标记消息可能残留，但 `_finalize_cycle` 兜底覆盖绝大多数 | 安全网 pop |
| 7 | 坏的跳过注入导致 LLM 不知自己空转 | 不影响 termination 机制（counter 照加） | 超限终止不依赖注入内容 |
| 8 | `_temp_reasoning` 泄漏到 wire | 被 `prepare_messages_for_llm` strip 防御（浅拷贝后 pop） | 双层防御：strip + pop before persist |

## 六、验证方案

### 6.1 单元测试

| 测试 | 内容 | 验证方式 |
|------|------|---------|
| UT-1 | `pop_temp_messages` 弹所有(全表)标记消息 | 注入 2 标记 + 1 普通 → pop → 仅剩普通 |
| UT-2 | 无标记时 pop 不报错 | 空列表 → pop → 0 |
| UT-3 | `prepare_messages_for_llm` 未 strip conv_hist 但 strip wire | conv_hist 中标记仍在，wire 无 `_temp_reasoning` |
| UT-4 | 连续多轮标记一次 pop 全清 | 3 标记（含被普通消息隔开的）→ pop → 全清 |
| UT-5 | 好的分支注入带标记 | `handle_answer`(好的) → `conversation_history[-1].get("_temp_reasoning")` == True |
| UT-6 | 坏的分支不注入 | `handle_answer`(坏的) → 上一轮的标记不动，本轮无新标记 |
| UT-7 | 好的→坏的→好的→answer pop 正常 | 两轮好的标记被 pop，answer 正常入库 |
| UT-8 | MAX_ROUNDS 失败路径 pop | 标记弹掉后 `FinalStep(outcome="failed")` |
| UT-9 | action 路径不被 pop | `pop_temp_messages` 不调用 |

### 6.2 E2E 测试

| 场景 | 预期 | 检查点 |
|------|------|--------|
| 正常 answer（单轮） | 无退化 | 调用链/最终答案正确 |
| 一/多轮好的 reasoning-only → answer | 最终答案正确；DB 无推理内容 | `~/.omniagent/chat_history.db` 查询 |
| 多轮 reasoning-only 超限 failed | 任务终止；DB 无推理 | DB 查询 + FinalStep(failed) |
| reasoning-only + action + answer | action 正常执行 | 调用链 + DB |
