### 3.1 #10 / #11 sysinfo 摘要行冗长 → 简短化

**动机**：sysinfo 的 summary 原本拼接 hostname / platform / CPU% / 内存 / 磁盘 / 网络 等一整段关键数据（50+ 字），详情区 `_format_sysinfo` 又完整分节展示同样数据，导致观测行又长又重复，浪费 token 且 LLM 阅读负担重（报告问题 #11）。问题 #10（重复调用）属 LLM 决策，本次只在文本层缓解。

**涉及文件**：`backend/app/tools/fundamental/get_system_info.py`


**After（当前代码 get_system_info.py:119-124）**：

### 3.2 #19 grep 删除 `_MAX_LINE_CONTENT=200` 行内容截断

**动机**：grep 工具层曾存在模块级常量 `_MAX_LINE_CONTENT=200`，在构造匹配行 `content` 时对单行内容做 200 字符硬截断。该截断与 formatter 层的 `OBS_MAX_STRING_LENGTH=10000` 双重管控，既冗余又造成「截断导致 JSON 不完整 / 行内容被提前腰斩」的隐患（报告问题 #19）。统一原则：工具层只返回原始 data，截断只允许发生在前端 yield 层 / observation_formatter 层。

**涉及文件**：`backend/app/tools/file/grep_file_content.py`（本次提交 851176c24 改动 4 行）

**Before**：源码中存在 `_MAX_LINE_CONTENT = 200` 及其在 `match_item["content"]` 构造处的截断调用（如 `line.rstrip('\n\r')[:_MAX_LINE_CONTENT]`）。

**After**：`_MAX_LINE_CONTENT` 常量被彻底删除，grep 不再在工具层截断行内容，完整行直接进 `data["matches"]`：

```python
# grep_file_content.py（当前）
match_item = {
    "file": str(fpath),
    "line": line_no,
    "matched": matched_texts,
    "content": line.rstrip('\n\r'),   # 不再做 200 字符截断
}
```

**统一管控点**：`observation_formatter.py:274-275` 与 `:851-852` 对所有 scalar / text 值统一按 `OBS_MAX_STRING_LENGTH=10000` 截断（见 `tool_constants.py:116` 定义 `OBS_MAX_STRING_LENGTH: int = 10000`）。grep 行内容即走此通道，既保证上限又避免「双重截断 + 提前腰斩」。

**影响**：消除工具层与 formatter 层双重截断冲突；长匹配行在 formatter 层以 10000 字符为统一上限，避免 JSON 截断与信息误导。

> 编写人：小欧 2026-07-12 22:02:14

### 3.5 #35 CREATE TABLE IF NOT EXISTS 安全豁免

**动机**：`_check_sql_safety` 用正则 `\b(CREATE|DROP|...)\b` 捕获 CREATE 操作并触发「危险操作拦截」。但 `CREATE TABLE IF NOT EXISTS` / `CREATE VIEW IF NOT EXISTS` 语义上安全（已存在的表不二次创建、不破坏数据），不应一律拦截（报告问题 #35 / M6 延伸）。v0.18.5 在检测到 `IF NOT EXISTS` 时豁免 CREATE 危险标记。

**涉及文件**：`backend/app/tools/dataanalysis/execute_sql.py`（commit 851176c24 改动 5 行）

**Before**：CREATE 一律进入 `dangerous_matches`，必然触发警告并拦截（除非 dry_run）。

**After（execute_sql.py:28-30）**：

```python
# CREATE TABLE/VIEW IF NOT EXISTS 语义安全，不警告 — 小沈 2026-07-08
if 'CREATE' in dangerous_matches and re.search(r'CREATE\s+(TABLE|VIEW)\s+IF\s+NOT\s+EXISTS', sql, re.IGNORECASE):
    dangerous_matches = [d for d in dangerous_matches if d != 'CREATE']
```

**影响**：`CREATE TABLE IF NOT EXISTS` 类语句不再被误判为危险操作并拦截，开发者/LLM 可正常建表；真正的 `CREATE TABLE`（无 IF NOT EXISTS）仍受安全校验保护。

> 编写人：小欧 2026-07-12 22:02:14

### 3.6 content_preview 改为文首50 + 文末50 + 「已写入内容」提示

**动机**：writetext 写入后 LLM 看不到内容，无法验证写入正确性（报告问题 #13 / M10）。原实现返回 `checked_content[:200]`（取前 200 字），对长文件既丢弃尾部又展示不直观。改为「短文件全展示、长文件文首50+文末50」，并在 formatter 渲染前加「已写入内容」标签，提升可读性。

**涉及文件**：`backend/app/tools/file/write_text_file.py`、`backend/app/services/agent/observation_formatter.py`（commit ffba7e763，2026-07-08 11:23:51 小沈）

**Before（write_text_file.py 原 3 处）**：

```python
return build_success(data={"content_preview": checked_content[:200]}, llm_data=llm_data)
# warning / 冲突 / 成功 三路径均为 checked_content[:200]
```

**After（write_text_file.py:22-26 新增函数 + 3 处替换）**：

```python

    if len(content) <= 100:

    return f"文首(50字符):{content[:50]}\n...(中间省略)...\n文末(50字符):{content[-50:]}"

return build_success(data={"content_preview": _build_content_preview(checked_content)}, llm_data=llm_data)
```

**formatter 特殊渲染（observation_formatter.py:228-230）**：

**影响**：长文件写入后 LLM 既能看到开头又能看到结尾（用于核对文件头/尾/签名），短文件完整可见；提示「已写入内容」避免与读取类输出混淆。

## 四、关键技术点

### 4.1 content_preview 文首 + 文末策略

- 阈值 100 字：≤100 全展示（短文件完整可验）；>100 取 `content[:50]` 与 `content[-50:]`。
- 中间以 `\n...(中间省略)...\n` 衔接，明确告知 LLM 有省略。
- formatter 层 `#23 content_preview` 在返回前拼接 `已写入内容\n`，与读取类输出语义区分。
- 该设计遵循 KISS-DIRECT：一个纯函数 `_build_content_preview`，无分支嵌套、无中间层。

### 4.2 CREATE TABLE IF NOT EXISTS 豁免机制

- 位置：安全校验函数 `_check_sql_safety`（execute_sql.py:21-39）。
- 逻辑：先用 `DANGEROUS_PATTERN` 捕获 CREATE，再立即用 `re.search(r'CREATE\s+(TABLE|VIEW)\s+IF\s+NOT\s+EXISTS', ...)` 检测豁免条件，命中则从 `dangerous_matches` 中剔除 `CREATE`。
- 边界：`CREATE TABLE`（无 IF NOT EXISTS）、`CREATE VIEW`（无 IF NOT EXISTS）、`CREATE INDEX` 等仍受拦截，安全边界不放松。

### 4.3 截断策略收敛

| 层 | 职责 | 常量 |
|----|------|------|
| 工具层 | 返回原始 data，不截断 | `_MAX_LINE_CONTENT` 已删除（grep #19） |
| formatter 层 | 按值统一截断 | `OBS_MAX_STRING_LENGTH = 10000`（tool_constants.py:116） |
| 前端 yield 层 | 最终 UI 截断 | truncate_data_for_frontend（工具层禁止调用） |

> 编写人：小欧 2026-07-12 22:02:14
