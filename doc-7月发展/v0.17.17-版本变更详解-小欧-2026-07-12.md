### 3.1 fix（8 项）

#### 3.1.1 prompt_logger：threading.local → contextvars 并发安全修复

**动机**：`PromptLogger` 在 v0.17.16 用 `threading.local()` 做「每线程独立日志」。但本系统为 asyncio 异步架构，多个协程可能运行在同一线程，`threading.local` 无法隔离协程，导致并发请求互相串日志。 — 小欧-2026-07-12

**Before（v0.17.16）**：
```python
import threading
...
class PromptLogger:
    """... 使用线程局部存储，每个线程/请求独立的日志数据"""
    def __init__(self):
        ...
        # 线程局部存储 - 每个线程独立的日志数据
        self._local = threading.local()

    def _get_current_log(self) -> Optional[Dict[str, Any]]:
        return getattr(self._local, 'current_log', None)

    def _set_current_log(self, log_data: Optional[Dict[str, Any]]):
        self._local.current_log = log_data
```

**After（v0.17.17）**：
```python
import contextvars
...
class PromptLogger:
    """... 使用 contextvars，每个协程/请求独立的日志数据"""
    def __init__(self):
        ...
        # contextvars - 每个协程独立的日志数据，避免 asyncio 协程间串数据
        self._current_log: contextvars.ContextVar = contextvars.ContextVar('prompt_log', default=None)

    def _get_current_log(self) -> Optional[Dict[str, Any]]:
        return self._current_log.get()

    def _set_current_log(self, log_data: Optional[Dict[str, Any]]):
        self._current_log.set(log_data)
```

**影响**：并发 / 流式场景下 prompt 日志不再错乱，是后续「状态切换写入 prompt 日志」的前置条件。

#### 3.1.2 prompt_logger：新增 `log_status()` 记录 Agent 状态变更

**动机**：v0.17.16 已把状态集中到 `status_table`，但状态切变过程未落 prompt 日志，事后审计无法看到「THINKING→EXECUTING」流转。新增 `log_status()` 补齐。 — 小欧-2026-07-12

```python
def log_status(self, old_status: str, new_status: str, reason: str = ""):
    """记录Agent状态变更到prompt log — 小欧 2026-07-01"""
    current_log = self._get_current_log()

```

### 3.2 refactor（3 项）

#### 3.2.1 message_builder + initialize_run_state + react_cycle：裁剪单一入口 + 消息数阈值

**动机**：v0.17.16 中 `trim_history()` 被三处调用（`add_observation`、`initialize_run_state._inject_conversation_history`、`react_cycle._process_single_step`），存在重复裁剪与入口分散问题。本项收敛为「唯一入口」，并新增按消息数触发裁剪的阈值。 — 小欧-2026-07-12

**(1) message_builder.py — 新增常量与双条件触发**

```python
_ROUND_CAP = 20             # 消息数触发裁剪阈值 — 小欧 2026-07-01
_ROUND_TRIM_BUDGET = 30000  # 消息数触发时收紧预算 — 小欧 2026-07-01
```

`trim_history()` 由「字符单条件」改为「字符 OR 消息数」双条件：
```python
    def trim_history(self) -> None:
        """对话历史裁剪 — 唯一裁剪入口 — 小欧 2026-07-01
        裁剪策略:
        - 触发条件: 字符 >160K 或 消息数 >_ROUND_CAP(20) 条，任一达标即触发
        - 方法: _trim_to_budget 从后往前扫，保留最新 N 轮完整 FC 对
        - system+user 消息永保
        - 配对不完整的 FC 对由 _trim_fc_pairs 清理
        """
        total = self._total_chars(self.conversation_history)
        msg_count = len(self.conversation_history)
        # 入口: 两个条件都不达标 → 不裁剪 — 小欧 2026-07-01 新增消息数条件
        if total < self.MAX_CONTEXT_CHARS * 0.8 and msg_count <= _ROUND_CAP:
            return
        if len(self.conversation_history) <= 2:
            return
        system_msgs, user_msgs, obs_list, assistant_msgs = self._classify_messages()
        always_keep_chars = self._total_chars(system_msgs) + self._total_chars(user_msgs)
        available_budget = max(10000, int(self.MAX_CONTEXT_CHARS * 0.7) - always_keep_chars)
        # 消息数触发时: 收紧预算 — 小欧 2026-07-01
        if msg_count > _ROUND_CAP:
            available_budget = min(available_budget, _ROUND_TRIM_BUDGET)
        trimmed = self._trim_to_budget(obs_list, assistant_msgs, available_budget)
        rebuilt = self._rebuild_and_validate(system_msgs, user_msgs, trimmed)
        if rebuilt is not None:
            self.conversation_history = rebuilt
        logger.info(f"[trim_history] 裁剪: {msg_count}条({total} chars) "
                    f"→ {len(rebuilt)}条(触发: {'消息数' if msg_count > _ROUND_CAP else '字符'})")
```

### 3.3 feat（2 项）

#### 3.3.1 L1 退避公式改首跳 + FCFormatError 增强 + parallel 限制注释

**(a) L1 退避公式（`base_service.py`）**

**动机**：原 `for attempt in range(...)` + `min(0.5*2^(attempt+1), 10)` 退避，在 `attempt` 语义与 `should_retry` 判断耦合。改为 `while` + `retry_count` 显式计数，退避改为 `2**retry_count`。 — 小欧-2026-07-12

**Before**：
```python
        for attempt in range(max_retries + 1):
            try:
                ...
            except Exception as e:
                if self._should_retry(e) and attempt < max_retries:
                    wait_time = min(0.5 * (2 ** (attempt + 1)), 10)
                    logger.warning(f"[Retry][L1] 重试 {attempt+1}/{max_retries}, "
                                   f"等待{wait_time:.1f}s, "
                                   f"错误: [{type(e).__name__}] {e} (args={e.args})")
                    await asyncio.sleep(wait_time)
                    continue
```
**After**：
```python
        retry_count = 0
        max_retries = LLM_STREAM_MAX_RETRIES
        ...
        while retry_count <= max_retries:
            try:
                ...
            except FCFormatError:
                raise  # 穿透给call_llm_with_fallback重试/降级 — 2026-06-26
            except Exception as e:
                if self._should_retry(e) and retry_count < max_retries:
                    retry_count += 1
                    wait_time = 2 ** retry_count
                    logger.warning(f"[Retry][L1] 重试 {retry_count}/{max_retries}, 等待{wait_time}秒, 错误: [{type(e).__name__}] {e}")
                    await asyncio.sleep(wait_time)
                    continue
```
**说明（忠实于代码）**：`retry_count` 从 0 起，首次失败 `retry_count` 变为 1，`wait_time = 2**1 = 2s`；后续为 4s、8s……（注：`version.txt` 标注「首跳 1s」，但代码实际首跳为 2s，此处以真实代码为准，标记为待复核项，见第六章 6.2）。`FCFormatError` 仍按 `raise` 穿透到 `call_llm_with_fallback` 做降级。 — 小欧-2026-07-12

**(b) FCFormatError 增强（`core.py`）**

`FCFormatError` 在 v0.17.15 已定型为「强制关键字参数 + details 字段」，本版本在 L1 重试层被规范使用：
```python
class FCFormatError(Exception):
    """FC格式错误 — LLM返回的tool_calls无法解析 — 小欧 2026-06-25"""
    def __init__(self, *, message: str, details: dict = None):
        super().__init__(message)
        self.details = details or {}
```
`*` 使 `message` 成为仅关键字参数，调用方必须写 `FCFormatError(message=..., details=...)`，杜绝位置参数误用；`details` 携带结构化诊断信息（如残缺 tool_call 内容）。 — 小欧-2026-07-12

**(c) parallel 限制注释（`client_sdk.py`）**

`parallel_tool_calls` 的禁用逻辑加注释说明「限制粒度太粗」待测试验证：
```python
            # TODO: 2026-06-30 北京老陈确认 — 此限制粒度太粗:

```
**影响**：明确技术债，为后续「按工具对并发安全」精细控制预留接口。

#### 3.3.2 system_adapter + system_prompts：PS 版本动态检测 + Shell 运行环境 prompt

**(a) system_adapter.py 新增 PS 版本探测（带缓存）**

**动机**：不同机器 PowerShell 5.1 与 pwsh 7+ 语法差异大（如 `?.` `??` 三元、`Get-ComputerInfo` `Join-String`）。需在系统提示词中告知 LLM 当前实际 Shell 环境，避免生成不可用语法。 — 小沈-2026-07-12

**After（新增）**：
```python
import shutil
import subprocess
from typing import Optional

_POWERSHELL_VERSION: Optional[str] = None
_PWSH_VERSION: Optional[str] = None

def get_powershell_version() -> str:
    """检测 Windows PowerShell 5.1 版本号（带缓存）— 小沈 2026-07-01"""
    global _POWERSHELL_VERSION
    if _POWERSHELL_VERSION is not None:
        return _POWERSHELL_VERSION
    try:
        r = subprocess.run(
            ['powershell.exe', '-NoLogo', '-Command', '$PSVersionTable.PSVersion.ToString()'],
            capture_output=True, text=True, timeout=5
        )
        _POWERSHELL_VERSION = r.stdout.strip() or "5.1"
    except Exception:
        _POWERSHELL_VERSION = "5.1"
    return _POWERSHELL_VERSION

def get_pwsh_version() -> str:
    """检测 pwsh.exe (PS 7+) 版本号（带缓存）— 小沈 2026-07-01"""
    global _PWSH_VERSION
    if _PWSH_VERSION is not None:
        return _PWSH_VERSION
    pwsh = shutil.which("pwsh.exe")
    if not pwsh:
        _PWSH_VERSION = ""
        return _PWSH_VERSION
    try:
        r = subprocess.run(
            [pwsh, '-NoLogo', '-Command', '$PSVersionTable.PSVersion.ToString()'],
            capture_output=True, text=True, timeout=5
        )
        _PWSH_VERSION = r.stdout.strip()
    except Exception:
        _PWSH_VERSION = ""
    return _PWSH_VERSION
```

**(b) system_prompts.py 将 Shell 环境注入 TOOL_CALL_RULES**

`TOOL_CALL_RULES` 由常量改为「property」，动态拼接 PS 版本信息：
```python
    _TOOL_CALL_RULES_BASE = """
【文本工具】(.txt .py ...)  读→read_text_file 写→write_text_file 改→edit_text_file
【Office工具】(docx .xlsx .pptx .pdf),禁止用文本工具 ...
【媒体工具】... 读 → 必须用read_media_file，禁止用read_text_file和office文档读取工具比.
 """

    @property
    def TOOL_CALL_RULES(self) -> str:
        """工具调用规则 + Shell运行环境 — 小沈 2026-07-01"""
        from app.services.prompts.system_adapter import get_powershell_version, get_pwsh_version
        ps_ver = get_powershell_version()
        pwsh_ver = get_pwsh_version()
        pwsh_line = f"pwsh.exe {pwsh_ver} 已安装" if pwsh_ver else "pwsh.exe 未安装"
        shell_rules = f"""
【Shell 运行环境】
- 默认 Shell: Windows PowerShell {ps_ver} (powershell.exe)
- {pwsh_line}
- 不支持 PS7+ 语法: ?. ?? ??= 三元运算符 Get-ComputerInfo Join-String
- findstr 查找无匹配时 exit code=1 (正常行为,非错误)
- PowerShell 管道变量用 $_.Property 形式,注意下划线不要遗漏
"""
        return self._TOOL_CALL_RULES_BASE + shell_rules
```
**影响**：LLM 在生成 Shell 命令时获得真实运行环境，显著降低「生成 PS7 语法却跑在 PS5.1」类失败；版本探测带 5s 超时与缓存，零成本。

## 四、关键技术点

### 4.1 message_builder 裁剪单一入口（KISS-DIRECT）

v0.17.16 裁剪分散在 3 处，违反「单一职责 / 同一抽象层」。v0.17.17 移除 `add_observation`、`_inject_conversation_history` 中的裁剪调用，仅保留 `_process_single_step` 一处，符合 KISS-DIRECT「逻辑直线」。新增 `_ROUND_CAP=20` + `_ROUND_TRIM_BUDGET=30000`，触发条件「字符 OR 消息数」双维度，消息数触发时收紧预算，避免长对话 token 爆量。 — 小欧-2026-07-12

### 4.2 FCFormatError 强制关键字参数（防御式 API）

`def __init__(self, *, message: str, details: dict = None)` 的 `*` 强制调用方用 `message=`/`details=`，从语言层杜绝位置参数错配；`details` 承载结构化诊断，是 v0.17.18 统一 `_format_fc_error` 降级链路的数据基础。 — 小欧-2026-07-12

### 4.3 PowerShell 版本动态检测（运行时自省）

`system_adapter` 用 `subprocess.run` 调 `$PSVersionTable.PSVersion.ToString()`，结果缓存为模块级变量；`get_pwsh_version` 先 `shutil.which` 判断 pwsh 是否存在，不存在返回空串并生成「未安装」提示。把运行环境约束从硬编码改为运行时探测，符合 YAGNI。 — 小欧-2026-07-12

### 4.4 e2e_helpers 超时重构（asyncio.wait_for 替代 asyncio.timeout）

v0.17.16 用 `asyncio.timeout(...)` 包裹 SSE 流，但其取消信号在 httpx/anyio 内部常被「吞掉」，导致超时无效、测试挂死。v0.17.17 改为独立协程 `_stream()` + `await asyncio.wait_for(_stream(), timeout=1600)`——`wait_for` 创建独立 task，超时强杀，`TimeoutError` 可靠上抛；超时由 900s 提至 1600s。 — 小欧-2026-07-12

## 六、风险与遗留

### 6.1 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| PS 版本探测失败阻塞 | `subprocess.run` 设 5s 超时并吞异常，失败时回退 "5.1"，不会阻塞启动 | 已内置 try/except + 默认回退 |
| contextvars 未覆盖同步路径 | 若某处用线程而非协程调用 prompt_logger，contextvars 可能取不到 | 当前全链路 asyncio，风险低 |
| 裁剪阈值 `_ROUND_CAP=20` | 极短消息也可能被裁剪（如 21 条极短消息未超字符但仍触发消息数裁剪） | 预算收紧到 30K，优先保留最新轮 |

### 6.2 遗留 / 待复核

1. **L1 退避首跳取值**：`version.txt` 标注「首跳 1s」，但 `base_service.py` 实际代码 `wait_time = 2**retry_count`，首跳为 **2s**（retry_count 首增为 1）。需与北京老陈确认是以文档意图（1s）还是以代码（2s）为准，建议后续统一。 — 小欧-2026-07-12
2. **parallel_tool_calls 限制粒度**：`client_sdk.py` 已标注 TODO，待测试验证后下放并发控制到 `action_handler`。本版本仅加注释，未改行为。
3. **thought 字段语义**：action/answer_handler 删除显式 `thought=` 传参，但 `ThoughtStep` 仍保留 `thought` 字段（由 `content` 推导）。属过渡态，后续版本可彻底移除 `thought` 仅留 `content`/`reasoning`。
