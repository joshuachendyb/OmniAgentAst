## 二、背景与目标

### 2.1 背景：summary 格式混乱

在 v0.18.2 及之前，工具 `_build_*_llm_data` 中的 `summary` 字段写法高度不一致，举例如下（均为真实历史写法）：

- 失败态有的用"X 失败: 原因"，有的用"获取当前时间，失败"；
- 成功态有的用"复制成功: src -> dst"，有的用"复制文件 src，成功 目标 dst"；
- fundamental 类（time_now/tool_search）成功态用逗号分隔而非冒号前置，如"获取当前时间，2026-07-07，Monday，成功"。

这种不统一带来两个问题：
1. **LLM 解析成本**：summary 是要被模型当作"这一轮工具发生了什么"的核心信号，格式飘忽会增加误读；
2. **Observation 闭环不完整**：v0.18.2 已把全量信息从 `data` 搬到 `llm_data`，但 summary 这一行本身未规范，等于"桶"统一了、"桶外标签"没统一。

> 编写人：小欧，日期：2026-07-12

### 2.2 目标

1. 建立 summary 统一范式：`操作+对象，成功/失败[: 补充信息]`；
2. 失败态一律"对象，失败"；成功态一律"对象，成功[: 信息]"；
3. 消除 `build_error` 中 `data` 里夹带的 `error_detail/params` 冗余（全量承载到 llm_data 的 status 字段）；
4. 补齐 download 的可选路径与 NaN 防护等安全性收口。

> 编写人：小欧，日期：2026-07-12

## 三、逐项变更详解

### 3.1 build_error 去冗余（data 空 + llm 承载全量）

**动机**：v0.18.2 已约定 error 的 detail/hint 放进 `llm_data.status`，但 `send_notification` 等工具仍在 `build_error(data={"error_detail":..., "params":...})` 里夹带冗余，前端/LLM 拿到两份重复信息。

**涉及文件**：`backend/app/tools/tool_response.py`（build_error 实现）、`backend/app/tools/fundamental/send_notification.py`（提交 bd56f2502）。

**真实代码 before/after（节选自 commit bd56f2502）**：

```python
# BEFORE（冗余 data 夹带 error_detail/params）
return build_error(data={"error_detail": err, "params": {"title": title}}, llm_data=llm_data)
return build_error(data={"error_detail": "win10toast库未安装", "params": {"library": "win10toast"}}, llm_data=...)

# AFTER（data 置空，全量入 llm_data）
return build_error(data={}, llm_data=llm_data)
```

**summary 同步优化（send_notification）**：

```python
# BEFORE
"summary": f"通知发送失败: {title}"
"summary": f"通知已发送: {title}"
# AFTER（统一"操作+对象，成功/失败"）
"summary": f"发送系统通知，\"{title}\"，失败"
"summary": f"发送系统通知，\"{title}\"，{notif_duration}秒，成功"
```

**影响**：错误详情单一来源（llm_data.status），不再出现 data 与 llm_data 双写导致的不一致。

> 编写人：小欧，日期：2026-07-12

## 四、关键技术点

### 4.1 build_error 去冗余的设计原则

v0.18.2 已确立"error 详情进 `llm_data.status`（含 code/detail/hint），`data` 仅承载可观察原始数据"。v0.18.3 把这一原则在 `send_notification` 等遗漏点补完：

- **before**：`build_error(data={"error_detail":..., "params":...}, llm_data=...)` —— 同一错误信息在 data 与 llm_data 双写；
- **after**：`build_error(data={}, llm_data=...)` —— data 为空，全量信息由 llm_data.status 承载。

这是 Observation 闭环真正闭合的最后一块拼图：前端 yield 层消费 llm_data，data 不再承担"错误说明"职责。

> 编写人：小欧，日期：2026-07-12

### 4.2 summary 冒号前置规范

统一范式定义为：

```
成功: "{操作}{对象}，成功[: 补充信息]"
失败: "{操作}{对象}，失败[: 补充信息]"
```

要点：
1. **对象优先**：把被操作的目标（路径/URL/标题）紧贴动词，如"读取Word{file_path}"；
2. **成败居中**：",成功"/",失败" 作为分隔符，而非把"成功/失败"放句首或句尾；
3. **冒号前置补充**：额外信息（行数、字节、图表类型、错误 detail）用冒号引出，如"生成图表X，成功 折线图，已保存为Y"。

> 编写人：小欧，日期：2026-07-12

### 4.3 NaN 防护

`timer_set` 在 `delay` 为 `float('nan')` 时，原 `int(delay)` 直接抛 `ValueError`。防护写法（现有代码 `backend/app/tools/timer/timer_set.py:58`）：

```python
_delay_sec = 0 if isinstance(delay, float) and math.isnan(delay) else int(delay)
```

该防御在 success/error 两条 summary 支路均生效，确保任何浮点异常输入都不会让定时器工具崩溃，错误态会正常回写 `llm_data.status`。

> 编写人：小欧，日期：2026-07-12
