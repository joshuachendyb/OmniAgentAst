## 二、背景与目标

### 2.1 edit_text 安全检测背景

`edittext` 工具（F4）承担 LLM 对源码/配置/文本的高频精确改写。在 v0.18.8 及之前，工具仅做「old_string→new_string」的字符替换与模糊回退，存在两类隐患：

1. **结构性破坏无感知**：当 LLM 用短锚点做 `replace_all` 或整段替换时，可能意外删掉函数/类定义，而工具照常返回「成功」，导致后续代码无法运行。
2. **短 old_string 批量误伤**：`old_string` 仅 1~2 个字符且在文件中匹配 ≥5 处时，`replace_all` 会大范围改动，风险极高且无任何预警。
3. **参数颠倒无提示**：当 `new_string` 实际存在于原文而 `old_string` 找不到时，错误提示只说「未找到匹配」，LLM 难以判断是参数填反。

v0.18.9 引入 `_safety_structure_loss` 与 `_safety_short_old` 两个纯检测函数，并在 error 分支补充「参数可能填反」提示，将风险在写入落盘前即预警，但不阻断正常编辑（属 warning 级）。— 小欧 2026-07-12

### 2.2 表格归一化背景

`write_docx` / `write_pdf` / `write_pptx` 三个文档工具此前各自处理表格输入格式，且 `write_pptx` 内联了一份 `dict_table_to_rows`、对 `content`/`tables` 的可接受结构参差不齐。v0.18.9 的目标：

1. 将表格解析能力抽取到公共 `app/utils/table_helper.py`，消除 write_pptx 内联副本（DRY）。
2. 扩展 `normalize_table_data` 使其支持 `dict{headers,rows}` / `list[dict]` / `None` 三种新形态，供 docx/pdf 统一调用。
3. write_pptx 的 `content` 与 `tables` 做全面归一化，覆盖 C1~C11、T1~T6 共 17 种输入结构，使 LLM 无论以何种形态传参都能正确渲染。— 小欧 2026-07-12

### 2.3 PS 中文编码背景

`PersistentShell`（shell_engine.py）在 v0.18.7 起已通过 `PYTHONIOENCODING` / `Out-File -Encoding utf8` 解决输出侧中文乱码。但输入侧仍有残留问题：PS5.1 通过 stdin `-Command -` 读取命令时，按系统 OEM 编码（中文 Windows = cp936/GBK）解码；若以 UTF-8 写入 stdin，中文字节会被 GBK 错误解码，命令本身出错（N1 问题）。v0.18.9 将 stdin 编码改为 `locale.getpreferredencoding()`，从根上对齐 PS5.1 的读取编码。— 小欧 2026-07-12

### 3.1 edittext：_safety_structure_loss 函数检测

**动机**：替换后若函数/类定义数量减少，说明编辑破坏了代码结构，应在落盘后（仍有 diff 上下文）给出 warning，而非静默成功。

**涉及文件**：`backend/app/tools/file/edit_text_file.py`

**Before（v0.18.8）**：`_apply_replacement` 后直接构造 diff 并写入，无任何结构校验。

**After（v0.18.9 引入，当前文件 edit_text_file.py:175-190）**：

```python
def _safety_structure_loss(original: str, new_content: str) -> str:
    """检测替换是否导致函数/类定义丢失 — 小沈 2026-07-08"""
    orig_funcs = set(re_mod.findall(r'^\s*(?:async\s+)?def\s+(\w+)', original, re_mod.MULTILINE))
    new_funcs  = set(re_mod.findall(r'^\s*(?:async\s+)?def\s+(\w+)', new_content, re_mod.MULTILINE))
    parts = []
    if len(new_funcs) < len(orig_funcs):
        lost = orig_funcs - new_funcs
        if lost:
            parts.append(f"函数: {', '.join(sorted(lost))}")
    orig_classes = set(re_mod.findall(r'^\s*class\s+(\w+)', original, re_mod.MULTILINE))
    new_classes  = set(re_mod.findall(r'^\s*class\s+(\w+)', new_content, re_mod.MULTILINE))
    if len(new_classes) < len(orig_classes):
        lost = orig_classes - new_classes
        if lost:
            parts.append(f"类: {', '.join(sorted(lost))}")
    return "替换将删除以下定义: " + "；".join(parts) if parts else ""
```

**调用点（edit_text_file.py:363-366，位于 `_replace_sync` 落盘前）**：


**影响**：仅在替换确实造成定义丢失时给出 `safety_hint`，经 `_build_edit_text_file_llm_data` 汇总为 warning 级 `summary`，不影响文件落盘（属风险提示，不阻断）。— 小欧 2026-07-12

```python
def dict_table_to_rows(dict_table: dict) -> List[List[str]]:
    """把dict型表格{headers,rows}转成list[list]
    — 小欧 2026-07-08（从write_pptx迁入共享）
    """
    rows = []

    for row in dict_table.get("rows", []):

        else:

    return rows
```

### 3.5 table_helper：normalize_table_data 扩展多格式

**动机**：LLM 可能以 `dict{headers,rows}` / `list[dict]` / `None` / `list[list]` 多种形态传 `table_data`，工具需统一归一化为 `list[list[str]]`。

**Before（v0.18.8）**：`normalize_table_data` 仅处理 `list[list]` 基本情形。

**After（v0.18.9 扩展，当前 table_helper.py:154-185）**：

```python
def normalize_table_data(table_data: Any) -> Optional[List[List[str]]]:
    """归一化表格数据为list[list[str]]标准格式
    — 小欧 2026-07-08 扩展支持dict/list[dict]/None
    """
    if not table_data:
        return None
    if isinstance(table_data, dict):
        rows = dict_table_to_rows(table_data)
        return _normalize_table_widths(rows) if rows else None
    if isinstance(table_data, list):
        if not table_data:
            return None
        first = table_data[0]
        if isinstance(first, dict):
            result = []
            for td in table_data:
                rows = dict_table_to_rows(td)
                if rows:
                    result.extend(rows)
            return _normalize_table_widths(result) if result else None
        return _normalize_table_widths(
            [[str(c) if c is not None else "" for c in row] for row in table_data]
        )
    return None
```

> 注：`_normalize_table_widths`（table_helper.py:16-26，补空串对齐列数）于 v0.18.14 增补，此处作为当前归一的收口保障一并说明，避免渲染层 IndexError。v0.18.9 时各分支已确保列数一致。— 小欧 2026-07-12

**影响**：docx/pdf 调用 `normalize_table_data(table_data)` 即可接受任意兼容形态；`None`/空返回 `None`，上层跳过建表。— 小欧 2026-07-12

## 四、关键技术点

### 4.1 _safety_structure_loss 的设计哲学

该函数是纯函数（无副作用、只返回 str），符合项目「铁规1：helper 只返回 raw dict / 原始值，不碰 build3/llm_data」。它用 `re.findall` 配合 `MULTILINE` 提取 `def`/`class` 顶层定义名集合，比较替换前后集合差集。设计上：

- 仅检测**减少**情形（定义被删），不检测新增，避免正常重构误报。
- 返回空串表示安全，非空串即 warning 文本，便于 `；`.join 拼接多个提示。
- 阈值用集合大小比较，不依赖 AST，成本低、对残缺代码鲁棒。— 小欧 2026-07-12

### 4.2 normalize_table_data 的多格式归一化

核心是「先识别顶层类型 → 再逐层转换 → 列宽对齐」三步走：

1. `None`/空 → 返回 `None`（上层跳过建表）。
2. `dict` → 视为单张 `{headers,rows}` 表。
3. `list` 且首项为 `dict` → 视为多张 `{headers,rows}` 表，逐张 `extend` 合并。
4. `list` 且首项为 `list` → 视为二维数组，元素转 `str`、`None` 转 `""`。
5. 最终 `_normalize_table_widths` 补空串对齐列数，杜绝渲染 IndexError。

此设计对 LLM 友好：无论以何种「人类直觉」形态传参，都能落到统一的 `list[list[str]]`。— 小欧 2026-07-12

### 4.3 PS 编码的双向闭环

| 侧 | 修复 | 落地版本 |
|----|------|---------|
| 输入（stdin 编码） | `locale.getpreferredencoding()` 写入 | v0.18.9（根因 N1） |
| 输出（> 重定向） | `Out-File -Encoding utf8` + `$OutputEncoding=UTF8` | v0.18.8 |
| 子进程环境 | `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1` | v0.18.8 |
| BOM 清理 | `.lstrip('\ufeff')` | v0.18.8 |

v0.18.9 补齐输入侧最后一环，与 v0.18.8 的输出侧修复形成完整编码闭环。— 小欧 2026-07-12

## 六、风险与遗留

### 6.1 风险

1. `_safety_structure_loss` 基于正则提取定义名，对装饰器嵌套、动态 `exec` 定义、字符串内伪定义可能误报/漏报；当前仅作 warning 不阻断，影响有限。
2. `normalize_table_data` 将 `list[dict]` 多张表合并为单表（横向 extend），若 LLM 本意是多张独立表，会被合并成一张。当前 pptx/docx/pdf 均按「单表」渲染，属已知语义约定。
3. `_safety_short_old` 阈值（≤2 字符、≥5 处）为经验值，极端场景（如单字符合法 token 批量替换）可能误提示，但属保守安全侧。

— 小欧 2026-07-12

### 6.2 遗留

1. edittext 的 `before`/`after` 独立行插入（避免行拼接污染）在 v0.18.9 尚未实现，于 v0.18.13（2026-07-12）补 `_insert_line_after` 修复。
2. `_normalize_table_widths` 列宽对齐在 v0.18.9 未统一抽取，于 v0.18.14 增补并接入 `parse_markdown_table`。
3. `replace_all` → `mode` 重命名在 v0.18.10 完成，本文 3.2 已说明命名差异。

— 小欧 2026-07-12
