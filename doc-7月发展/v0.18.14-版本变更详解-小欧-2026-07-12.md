## 二、背景与目标

> 本章节：阐明本版本要解决的核心问题与设计目标。— 小欧 2026-07-12

### 2.1 背景：错误 hint 长期处于"编造兜底"状态

在 v0.18.13 及更早版本中，各工具在 `except` 分支给出的 `hint` 多为**硬编码通用话术**（如"请检查文件路径和权限""请检查路径和权限"），存在两大问题：

1. **与真实异常脱钩**：不管底层是 `IndexError`（Markdown 表格列数不一）、`ValueError`（内容/格式异常）、还是 `OSError(errno=28)`（磁盘满），统统回显同一句兜底提示。LLM 据此无法判断真实故障，往往反复重试同一条错误路径。
2. **存在编造性误导**：对非磁盘类异常谎称"磁盘/权限问题"，属虚假归因。

### 2.2 目标

- **诚实化**：hint 必须与真实异常类型精准对应，未知异常如实回显异常类型（`type(e).__name__`），绝不编造原因。
- **集中化**：将分散在 13 个 file 类工具、8 个 document 工具、download_file 中的 hint 逻辑收敛到 `file_path_checker.py` 的 `hint_for_read_error` / `hint_for_write_error` 两个集中函数。
- **健壮性**：补齐易导致崩溃的边界（null byte 命令、幂等删除、Markdown 表格列数不一、多模型 reasoning 解析）。

```python
def _normalize_table_widths(table_data: List[List[str]]) -> List[List[str]]:
    """列宽归一化：以最大列数为基准，短行右侧补空串，保证各行列数一致 — 小欧 2026-07-12
    仅补空、不截断、不丢数据；整齐表格为恒等变换，无行为变化。

    if table_data:
        _max_cols = max(len(row) for row in table_data)

                row.extend([""] * (_max_cols - len(row)))
    return table_data

    rc = getattr(delta, 'reasoning_content', None) or delta.get('reasoning_content')
    if rc:
        return rc
    thinking = delta.get('thinking')
    if thinking:
        return thinking
    reasoning = delta.get('reasoning')
    if reasoning not in (None, "", False):
        return reasoning
    # 2) 思考混在 content 中，但有 is_reasoning/reasoning_flag 标记
    if delta.get('is_reasoning') is True or delta.get('reasoning_flag') is True:
        return delta.get('content') or ""
    return None
```

**识别顺序（优先级）**：`reasoning_content` → `thinking`(Claude) → `reasoning`(OpenAI) → `content`且 `is_reasoning=True/ reasoning_flag=True`。任一命中即返回 thinking 文本，否则返回 `None`（交由 content 走答案通道）。

**数据流**：`reasoning.py`（判定 True/False）→ `base_service.py`（`if reasoning_text: StreamChunk(is_reasoning=True)`）→ `llm_stream.py`（`chunk.is_reasoning` 决定进 reasoning 通道还是 content 通道）。单一真相源 `StreamChunk.is_reasoning` 在三者间接力，无重复解析。

**影响**：DeepSeek / Claude / OpenAI 等多模型推理内容均能被正确提取并注入 observation，Agent 跨轮决策连贯性提升。

### 3.12 fc_message_types.py 补充 FC 消息配对结构说明 + thought 入历史科学原理注释

**涉及文件**：`backend/app/services/agent/fc_message_types.py`
**commit**：`3a22e4221`（docs:fc_message_types.py等 补充FC消息配对结构说明+thought入历史科学原理注释）

**要点**：在模块 docstring 中以结构化注释补全：
- 四种角色（system/user/assistant/tool）配对规则：1 条 assistant(tool_calls) + N 条 tool(tool_call_id 关联)，一对多而非一对一。
- 三个代码文件关系：`fc_message_types.py`(模型) ← `message_builder.py`(管理) ← `action_handler.py`(编排)。
- **5.1 thought 入历史的科学原理（修正通俗比喻）**：原"结果替代过程"不严格；真正开关是"下一轮迭代还需不需要这段信息"。三条硬约束：① OpenAI FC 协议无 thought 角色（主因）；② 状态连续性约束（reasoning-only 时是唯一轨迹必须保留）；③ 上下文预算约束。结论为"状态最小持久化原则"：情况 A（answer+reasoning，循环终止）丢弃 reasoning；情况 B（reasoning-only，循环继续）伪装成 observation 注入。

**影响**：为后续维护者提供精确的 FC 消息协议与 thought 持久化决策依据，杜绝误改。

## 四、关键技术点

> 本章节：提炼本版本最具通用价值的技术要点。— 小欧 2026-07-12

### 4.1 file_path_checker 集中 hint（DRY + 诚实化）

`hint_for_read_error` / `hint_for_write_error` 作为唯一错误归因来源，按 `OSError.errno` / 具体异常类型精准映射。覆盖 `errno=2/13/21/28/36/63` 及 `IndexError`/`ValueError`/`FileNotFoundError`/`IsADirectoryError`/`PermissionError`。未知异常一律 `type(e).__name__` 如实回显。

### 4.2 IndexError / ValueError 精准提示

`IndexError`→"Markdown 表格列数不一致"；`ValueError`→"内容或格式异常"。二者针对文档写入类工具最频发的两类结构性错误，直接指向根因。

### 4.3 幂等删除

`validate_path(OpCategory.EXISTS, path, force=True)` 在目标不存在时返回成功，使 `delete_file` 具备幂等语义，契合 HITL 重放/重试场景。

### 4.4 null byte 拒绝

命令层在进入持久 Shell 前以 `"\x00" in command` 前置拦截，属"最小信任边界"式输入净化。

### 4.5 `_normalize_table_widths` 列宽归一

以最大列数为基准右侧补空，恒等变换、不丢数据，从根上消除表格渲染 `IndexError`，同时不破坏整齐表格的既有行为。

## 六、风险与遗留

> 本章节：诚实列出风险与未竟事项。— 小欧 2026-07-12

1. **`hint_for_read_error` 未纳入 `__all__`**：函数已定义并使用，但 `file_path_checker.py` 的 `__all__`（第17-23行）未列出 `hint_for_read_error`，属导出清单遗漏（不影响运行时，因均为显式 import）。遗留待补。

3. **dry_run 仅 sqlite 拆分**：`execute_sql` 的 SAVEPOINT 拆分仅作用于 sqlite 分支；mysql/postgresql 走 sqlalchemy `text()`，未引入等价 SAVEPOINT 机制，跨库 dry_run 语义不完全一致。
4. **reasoning 字段优先级**：若某模型同时返回 `thinking` 与 `reasoning`，按当前优先级取首个非空的，可能存在个别模型需调序，需真实联调确认。
