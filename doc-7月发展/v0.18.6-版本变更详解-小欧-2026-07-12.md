## 二、背景与目标

### 2.1 PDF 中文乱码问题（P001）

在 v0.18.5 及之前，read_pdf 工具仅依赖 `pdfplumber` 提取文本。部分 CJK（中日韩统一表意文字）PDF 在生成时丢失了字符编码映射信息，pdfplumber 提取出的文本中出现大量 `?` 或 Unicode 替换字符 `U+FFFD`（即乱码）。这类乱码会导致：

1. 下游 LLM 收到失真文本，理解错误；
2. 表格/图片元数据正常但正文不可读；
3. 用户无法获知"该 PDF 是否已不可恢复"，只能看到乱码。

因此目标明确：**（a）能检测乱码；（b）检测到后用 PyMuPDF 后备提取尝试恢复；（c）若仍不可恢复则诚实告知用户而非糊弄**。 — 小欧 2026-07-12

### 2.2 requirements.txt 中文注释二次编码

根目录 `requirements.txt` 在 v0.18.5 之前存在 9 处中文注释被"UTF-8 二次编码"（Mojibake）。典型表现为 `# FastAPI妗嗘灦` 这类乱码 —— 原意为 `# FastAPI框架`，因注释字符串经历了"UTF-8 编码 → 误当 Latin-1 重新编码"或类似往返导致中文字符被破坏。虽不影响 pip 安装（注释不参与依赖解析），但损害可读性与专业度，且易误导维护者。目标：将 9 处全部修复为正确中文。

### 2.3 CJK 字体缺失导致图表中文显示为方块

`generate_chart` 用 matplotlib 绘图。默认字体 DejaVu Sans 不含中文字形，当 labels/title 含中文时，matplotlib 会输出方块（tofu）并刷屏 `Glyph ... missing from font` 警告（stderr 噪声极大）。早期实现可能在每次调用都无条件注册中文字体，存在重复 `addfont` 与无谓 I/O 开销。目标：**（a）按需加载**（仅含中文时注册）；（b）防重复注册；（c）抑制 Glyph 警告。

### 2.4 prompt_logger 记录冗余与信息损失

prompt_logger 在记录工具观察结果时，键名带冗余 `tool result` 字样，且只记录格式化后内容，未保留格式化前的原始 `data`，致使事后审计时无法对照"原始数据 vs 呈现给 LLM 的数据"。目标：去冗余键名 + 记录 raw_data。 — 小欧 2026-07-12

#### 3.1.2 新增 `_is_garbled_text()` 乱码检测（read_pdf.py:25-30）

```python
# ===== 现状（v0.18.6，已落地）=====
def _is_garbled_text(text: str, threshold: float = 0.30) -> bool:
    """检测文本是否含大量 ? 字符（CJK编码丢失）— 小欧 2026-07-08"""
    if not text.strip():
        return False
    q_count = sum(1 for c in text if c == '\ufffd' or c == '?')
    return (q_count / len(text)) > threshold
```

要点：以 `?` 与 Unicode 替换字符 `U+FFFD` 计数，占比超过 30% 阈值即判定为乱码。阈值 0.30 是经验值——正常中文文本偶发个别 `?` 不应误判。 — 小欧 2026-07-12

#### 3.1.3 新增 `_extract_with_fitz()` PyMuPDF 后备提取（read_pdf.py:33-51）

```python
# ===== 现状（v0.18.6）=====
def _extract_with_fitz(file_path: str, page_count: int) -> Tuple[str, list, list]:
    """PyMuPDF后备提取文本+表格+图片 — 小欧 2026-07-08"""
    import fitz
    all_text, tables_data, images_data = [], [], []
    doc = fitz.open(file_path)
    for pn in range(doc.page_count):
        page = doc[pn]
        text = page.get_text() or ""
        all_text.append(f"--- 第 {pn + 1} 页 ---\n{text}")
        tables_data.append({"page": pn + 1, "note": "PyMuPDF不提供表格提取"})
        for img in page.get_images():
            images_data.append({
                "page": pn + 1,
                "width": 0, "height": 0,
                "note": "图片引用索引, 实际尺寸需渲染后获取",
            })
    doc.close()
    full_text = "\n\n".join(all_text)
    return full_text, tables_data, images_data
```

```python
# ===== 变更前（v0.18.5 及之前）=====

```

要点：PyMuPDF 通过底层 PDF 内容流解析文本，对编码损坏型 PDF 常有更好表现；明确声明其不提供表格提取（table 仅作占位 note），保持对 pdfplumber 表格能力的诚实差异说明。 — 小欧 2026-07-12

## 四、关键技术点

### 4.1 乱码阈值 `_is_garbled_text` 的 30% 设计

- 以 `?` 与 `U+FFFD` 为乱码特征字符；
- 阈值 0.30：正常中文文档偶发 `?`（如公式/标点）不应误判，但编码全失的文档 `?`/`U+FFFD` 占比通常远超此值；
- 空文本 (`not text.strip()`) 直接返回 False，避免除零与误判。

### 4.2 PyMuPDF 后备提取的防御性二次校验

并非"fitz 提取即采纳"，而是 `_is_garbled_text(fitz_text)` 再判一次。理由：部分 PDF fitz 同样提取失败，盲目替换反而丢失 pdfplumber 已有的表格/图片结构。 — 小欧 2026-07-12

### 4.3 CJK 按需注册的三重保护

| 保护层 | 手段 | 目的 |
|--------|------|------|
| 按需判定 | `ord(c) > 0x2E80` 扫描 | 纯英文零开销 |
| 防重复 | `_registered` 集合 | 避免重复 addfont |
| 鲁棒降级 | try/except + 文件存在性检查 | 字体缺失不崩 |

### 4.4 Glyph 警告抑制的副作用

`warnings.filterwarnings('ignore', message='Glyph.*missing from font')` 仅抑制字形缺失类警告，不影响其他 matplotlib 警告（如字体找不到的 FontNotFound 仍可见），定位问题时不至于被噪声淹没。

## 六、风险与遗留

| 风险点 | 说明 | 建议 |
|--------|------|------|
| fitz 表格能力缺失 | 后备提取不提供真实表格，编码损坏 PDF 后备后表格降级为占位 note | 长期可接入 PyMuPDF 表格提取或 pdfplumber 表格优先策略 |

| 乱码阈值 0.30 为经验值 | 极端短文本可能误判 | 后续可按文本长度自适应阈值 |
| prompt_logger raw_data 体积 | 原始 data 可能很大，日志膨胀 | 可后续对 raw_data 做长度截断（当前未做） |
