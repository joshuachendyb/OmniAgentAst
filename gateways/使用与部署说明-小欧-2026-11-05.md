## 一、场景速查（先看这）

- **全新机器首次部署** → 直接走第二节三步（放 CLI → 配 token → 起）；CLI 源文件哪来的都行
- **CLI 已装在别处**（Zencode / 官网下载 / npm 等）→ 原地不动它：`setup_cli.bat <完整路径>` 复制进 `runtime\`；或 `config.json` 的 `cli.executable` 钉死路径
- **改了网关代码 / 换了网关文件** → CLI 与 token 都不用动：`stop.bat` → 替换/重启 → `start.bat`（首次改码后建议跑一遍第四节测试）
- **网关迁移到新电脑** → 拷贝整个 `gateways\`（不含 `runtime\` 与 `logs\`）→ 新机放 CLI（上一条）→ token 两处同值 → `setx NO_PROXY` → 重启后端
- **CLI 升级了版本** → 旧 exe 换新的即触发网关版本校验：在 `>=2.2.0 <2.3.0` 区间内直接可用；区间外 `/healthz` 报 `cli=down` 给 `version-not-in-range`，届时再改 `cli.compatible`
- **只用打包版（dist exe）** → 默认不含网关（第五节方案 A）；确要走网关 → 按方案 C 放插件目录 + 手动启动，托管路径同本节
- **接手别人的机器，不知道装没装** → 查三件事：`runtime\opencode-cli.exe` 在不在、`config.json` 在不在（token）、`/healthz` 活不活；都在就只做日常启停
- **只想试一下** → 装 Python 依赖 + `setup_cli.bat <路径>` + `start.bat`，`curl /healthz` 看到 `status=ok` 即跑通；宿主接入（第三节）可后做

> 原则：CLI 原始文件**从不移动、从不删除**——只复制/引用，原始目录保持原样。

## 二、三步部署运行

**第 1 步 · 放 CLI**（装一次就行）

`opencode-cli.exe`（约 240 MB 大文件）是**网关要启动的"模型后端程序"**——网关本体（gateway.py 等）不带它，启动时会去 `gateways\runtime\` 找这个文件，找不到或版本不对就拒绝工作。

- 原始文件在哪都行：官网下载的、其他软件带出来的（本机器 Zencode 在 `F:\agenttool\Zencode-20261104\code\`），给得出完整路径即可
- **自动（推荐，一条命令）**：`gateways\setup_cli.bat <opencode-cli.exe 的完整路径>`
  - 例（本机）：`setup_cli.bat F:\agenttool\Zencode-20261104\code\opencode-cli.exe`
  - 脚本自动：复制进 `gateways\runtime\` → 校验大小 ≥100 MB → `--version` 探活
- **手动（效果一样）**：自己把 exe 复制进 `gateways\runtime\`，**文件名必须叫 `opencode-cli.exe`**（不管原件叫什么）；网关启动时同样校验兜底，不合格报 `cli=down` 并给原因
- **进阶钉死**：不想放 `runtime\`，在 `config.json` 的 `cli.executable` 写绝对路径（解析优先级最高；完整 5 级解析见设计文档 6.3.3）

**第 2 步 · 配 token**：复制 `config.example.json` → `config.json`，token 换成随机 64 位 hex（默认端口/池参数不动）

**第 3 步 · 起停**

- 启动：`start.bat`（自动设 NO_PROXY，回环不走代理）
- 停止：`stop.bat`（只杀 8199 端口进程）
- 判活：`/healthz` 返回 `status=ok`；`cli=idle` 是正常（按需启动），对话后转 `up`

- 环境要求：Python 3.11+，`pip install fastapi uvicorn httpx`
- 硬约束：**先起网关，再拉模型**，反序会报错

## 三、宿主接入（零代码）

`config\config.yaml` 的 `ai:` 下新增：

```yaml
  opencli:
    label: opencli本地网关
    api_base: http://127.0.0.1:8199/v1
    api_key: <与网关 token 同值>
    timeout: 900
    max_retries: 2
    models: []
```

- `api_base` **必须带 `/v1`**（唯一契约锚点，两边一致）
- 环境变量 `setx NO_PROXY "127.0.0.1,localhost"` 后**重启后端**
- UI 四步：建 provider → 拉模型（免费层 9–10 个，个数波动正常）→ 勾选 → 保存对话
- 鉴权两层不用管：宿主 token 部署时已写入；下游密码网关自动捕获，不暴露

## 四、测试

```
python gateways\tests\run_cases.py            # 快速套件（约 1 分钟）12 过/0 败/3 跳
python gateways\tests\run_cases.py --full     # 加重型 C4/F1/F2/F3/D7（约 5 分钟）
```

- `--only A3,D1` 点选复跑；FAIL 退出码 1，可挂 CI
- **C4（并发 40）可能触发免费层 429 → 网关冷却约 1 小时**，空闲窗口单独跑；F3→D7→F1→F2 已实测全过
- SKIP 项（断网/停服/思考模型类）须手工，60 项归账见 `doc-11月优化\[11]网关验收测试自动化执行记录-小欧-2026-11-05.md`

## 五、打包部署

- **默认不进包**：`OmniAgentBackend.spec` 不收 `gateways/`，打包版不含 opencli（推荐 A，境内免费层多直连 429，预置无用）
- **按需插件（方案 C）**：单独编译 `gateway.exe`，放 `dist\OmniAgentBackend\gateways\`（与源码同形）；随后手动启动
- **注意**：.py 塞进 `_internal` 跑不起来（包内无解释器）；体积代价 ≈ 260 MB

## 六、常见问题

- **401** → 宿主 api_key ≠ 网关 token，两处对齐
- **连接拒绝** → 网关没起 / 端口不对，`start.bat` 后核对
- **大量 429 free-limit** → 等冷却（最长约 1 h）或换出口，不改配置
- **未知模型 404** → UI 重拉模型再勾选保存
- **流式偶发断流** → 重试即过；持续断流按执行记录 §三 手工排查
