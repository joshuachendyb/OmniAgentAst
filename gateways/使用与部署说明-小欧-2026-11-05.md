## 一、场景速查（先看这）

先对号入座，再跳到对应节操作。一条一个场景，不绕弯。

- 全新机器，从来没装过网关 —— 走第二节的三步：放 CLI、配 token、启动。
- CLI 已经装在别的地方（Zencode 带出的、官网下载的、npm 装的都算）—— 原地不动它。给路径让脚本复制：setup_cli.bat <完整路径>；或者干脆不动文件，在 config.json 的 cli.executable 里写它的绝对路径。
- 改了网关代码，或换了一版网关文件 —— CLI 和 token 都不用动。stop.bat 停，换文件，start.bat 起。改码后第一次建议跑一遍第四节的测试。
- 网关要搬到新电脑 —— 把整个 gateways 文件夹拷过去（runtime 和 logs 两个文件夹不用拷）。新机上：放 CLI（同上一条）、token 两处写同一个值、setx NO_PROXY、重启后端。
- CLI 升级了新版本 —— 把 runtime 里的旧 exe 换成新的就行。网关自动校验版本：在 2.2.0 以上 2.3.0 以下的区间直接能用；区间外 /healthz 会报 cli=down 并写明 version-not-in-range，那时再改 config.json 的 cli.compatible。
- 只用打包版（dist 里的 exe）—— 安装包默认不含网关（见第五节）。确要用，按方案 C 手动放插件目录再启动，其余操作和本手册一样。
- 接手别人的机器，不知道装没装过 —— 查三样：runtime 里有没有 opencode-cli.exe；config.json 在不在；/healthz 活不活。三样都在就只做日常启停。
- 只想先试一下通不通 —— 依赖装好、CLI 就位、start.bat 起来，浏览器或 curl 访问 /healthz 看到 status=ok 就算通；宿主接入（第三节）以后再做。

原则一句话：CLI 原始文件从不移动、从不删除，只复制或引用，原始目录保持原样。

## 二、三步部署运行

第 1 步 放 CLI（装一次就行）

opencode-cli.exe 是一个约 240 MB 的大文件，它是网关要启动的"模型后端程序"。网关本体（gateway.py 那几个文件）不带它，启动时会去 gateways\runtime 文件夹里找这个文件，找不到或者版本不对就拒绝工作。

- 原始文件在哪都行：官网下载的、其他软件带出来的都行，只要给得出完整路径。本机器的原始文件在 F:\agenttool\Zencode-20261104\code\opencode-cli.exe。
- 自动做法（推荐，一条命令）：gateways\setup_cli.bat <opencode-cli.exe 的完整路径>
  - 本机实例：setup_cli.bat F:\agenttool\Zencode-20261104\code\opencode-cli.exe
  - 脚本会自动做三件事：复制进 gateways\runtime；校验文件大小不小于 100 MB（防拷错文件）；执行 --version 探活。
- 手动做法（效果一样）：自己把 exe 复制到 gateways\runtime 文件夹，文件名必须改成 opencode-cli.exe，不管原件原来叫什么。网关启动时会做同样的校验兜底，不合格报 cli=down 并写明原因。
- 进阶做法：不想放 runtime，就在 config.json 的 cli.executable 里写 CLI 的绝对路径，解析优先级最高，排障方便。完整的五级解析顺序见设计文档 6.3.3。

第 2 步 配 token

复制 config.example.json 改名为 config.json，把里面的 token 换成随机 64 位十六进制。端口和池参数不动，默认就是对的。

token 生成参考（PowerShell）：
    -join ((0..31) | ForEach-Object { '{0:x2}' -f (Get-Random -Max 256) })

第 3 步 起停和判活

- 启动：start.bat。它会自动设 NO_PROXY，回环请求不走系统代理。
- 停止：stop.bat。只杀 8199 端口上的进程，不碰宿主和别的程序。
- 判活：访问 http://127.0.0.1:8199/healthz，看到 status=ok 就是活的。cli=idle 是正常的（下游按需启动），打过一次对话会变成 cli=up。

环境要求：Python 3.11 以上，装 fastapi、uvicorn、httpx 三个包。
硬约束：先起网关，再拉模型。顺序反了会报错，别误判成配置错。

## 三、宿主接入（零代码）

在宿主的 config\config.yaml 里 ai 段下新增（和 ZenFree 并列）：

    ai:
      opencli:
        label: opencli本地网关
        api_base: http://127.0.0.1:8199/v1
        api_key: <与网关 token 同值>
        timeout: 900
        max_retries: 2
        models: []

要点逐条：

- api_base 必须带 /v1 结尾。宿主拿它直接拼 /chat/completions 和 /models，这是两边唯一的契约锚点。
- 设环境变量 NO_PROXY 和 no_proxy 都为 127.0.0.1,localhost（setx 命令），然后重启后端才生效。
- 界面四步：建 provider 填上面的地址和 key，拉模型（免费层 9 到 10 个，个数波动属正常），勾选要用的模型，保存后对话。
- 鉴权两层都不用你管：宿主到网关的 token 部署时已写入两处；网关到下游的密码由网关自动捕获，不落盘不暴露。

## 四、测试

命令就两条：

    python gateways\tests\run_cases.py            快速套件，约 1 分钟，现状 12 过 0 败 3 跳
    python gateways\tests\run_cases.py --full     追加重型 C4/F1/F2/F3/D7，约 5 分钟

- 用 --only A3,D1 可以点选复跑。有失败退出码为 1，可以直接挂 CI。
- 注意：C4 是并发 40 路，可能把免费额度打满触发网关约 1 小时冷却，放到空闲窗口单独跑。其余四项 F3、D7、F1、F2 已实测全过。
- 跳过（SKIP）的项是断网、停服、思考模型三类，必须手工做。60 项的台账见 doc-11月优化 里的执行记录文档。

## 五、打包部署

- 默认不进包：OmniAgentBackend.spec 不收 gateways，打包版没有 opencli 能力。这是推荐方案 A，境内用户免费层多数直连 429，预置了也用不了。
- 确要打包版用网关（方案 C）：单独编译 gateway.exe，放到 dist\OmniAgentBackend\gateways 目录（和源码同形），手动启动。其余配置操作照本手册第二节。
- 两个坑：把 .py 塞进 _internal 跑不起来，包里没有 Python 解释器；体积代价约 260 MB（gateway.exe 加 CLI 文件）。

## 六、常见问题

- 对话返回 401 —— 宿主的 api_key 和网关的 token 不是同一个值，两处对齐就通。
- 连接拒绝（10061）—— 网关没起或端口不对，先 start.bat，再核对 config.json 的 port 和宿主 api_base 是否一致。
- 大量 429 free-limit —— 免费层额度或地区限制，等冷却（最长约 1 小时）或换网络出口，不需要改任何配置。
- 未知模型 404 —— 模型名不在当前免费层清单里，去 UI 重新拉一次模型再勾选保存。
- 流式偶尔断一下 —— 免费层远端瞬时波动，重试通常就过；持续断开按执行记录第三节的手工项排查。
