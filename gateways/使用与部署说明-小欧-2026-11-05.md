[1] 场景速查（先看这）

说明：部署或排障前先对号入座，找到自己属于哪种情况，再按括号里的指引去对应序号操作，不用通读全文。

(1) 全新机器，从来没装过网关 —— 走 [2] 的三步。

(2) CLI 已经装在别处（Zencode 带出的、官网下载的、npm 装的都算）—— 原地不动它，给路径让脚本复制，做法见 [2.1]。

(3) 改了网关代码或换了一版网关文件 —— CLI 和 token 都不用动：stop.bat 停，换文件，start.bat 起；改码后第一次建议跑一遍 [4] 的测试。

(4) 网关要搬到新电脑 —— 拷整个 gateways 文件夹（runtime 和 logs 两个文件夹不用拷），到新机按 [2] 重来，token 两处写同一个值。

(5) CLI 升级了新版本 —— 把 runtime 里的旧 exe 换成新的即可，网关自动校验版本区间：2.2.0 至 2.3.0 之内直接可用，区间外 /healthz 报 cli=down 并写明 version-not-in-range，那时再改 config.json 的 cli.compatible。

(6) 只用打包版（dist 里的 exe）—— 安装包默认不含网关，见 [5]；确要用按方案 C 放插件目录再手动启动。

(7) 接手别人的机器，不知道装没装过 —— 查三样：runtime 里有没有 opencode-cli.exe，config.json 在不在，/healthz 活不活；三样都在就只做日常启停。

(8) 只想先试通不通 —— 依赖装好、CLI 就位、start.bat 起来，访问 /healthz 看到 status=ok 就算通，[3] 以后再做。

原则一句话：CLI 原始文件从不移动、从不删除，只复制或引用，原始目录保持原样。

[2] 三步部署运行

说明：全新环境的完整安装路径，三步之内把网关跑起来。环境要求：Python 3.11 以上，装 fastapi、uvicorn、httpx 三个包。

[2.1] 放 CLI（装一次就行）

opencode-cli.exe 是一个约 240 MB 的大文件，它是网关要启动的"模型后端程序"。网关本体（gateway.py 那几个文件）不带它，启动时会去 gateways\runtime 文件夹里找这个文件，找不到或者版本不对就拒绝工作。

(1) 原始文件在哪都行：官网下载的、其他软件带出来的都算，只要给得出完整路径。本机器的原始文件在 F:\agenttool\Zencode-20261104\code\opencode-cli.exe。

(2) 自动做法（推荐，一条命令）：gateways\setup_cli.bat <opencode-cli.exe 的完整路径>；本机实例：setup_cli.bat F:\agenttool\Zencode-20261104\code\opencode-cli.exe。

(3) 脚本自动做三件事：复制进 gateways\runtime；校验文件大小不小于 100 MB（防拷错文件）；执行 --version 探活。

(4) 手动做法（效果一样）：自己把 exe 复制进 gateways\runtime 文件夹，文件名必须改成 opencode-cli.exe，不管原件叫什么。网关启动时做同样的校验兜底，不合格报 cli=down 并写明原因。

(5) 进阶做法：不想放 runtime，就在 config.json 的 cli.executable 写 CLI 的绝对路径，解析优先级最高，排障方便；完整五级解析顺序见设计文档 6.3.3。

[2.2] 配 token

复制 config.example.json 改名为 config.json，把里面的 token 换成随机 64 位十六进制数；端口和池参数不动，默认就是对的。生成 token 用 PowerShell 一行：

    -join ((0..31) | ForEach-Object { '{0:x2}' -f (Get-Random -Max 256) })

(1) token 必须放在双引号里：token 是字符串（十六进制文本），JSON 里字符串一律要双引号。替换时只换引号中间那串，引号本身一个不动。

(2) 对比记忆：数字（port: 8199）和开关（r6_enabled: true）不要引号——加了引号会被当成字符串，端口读错。

[2.3] 起停和判活

(1) 启动：start.bat，它会自动设 NO_PROXY，回环请求不走系统代理。

(2) 停止：stop.bat，只杀 8199 端口上的进程，不碰宿主和别的程序。

(3) 判活：访问 http://127.0.0.1:8199/healthz，看到 status=ok 就是活的。cli=idle 是正常的（下游按需启动），打过一次对话会变成 cli=up。

(4) 硬约束：先起网关，再拉模型。顺序反了会报错，别误判成配置错。

[3] 宿主接入（零代码）

说明：这一步不改宿主一行代码，只加一段配置。做完 [2] 之后，让宿主能"看见"网关这个模型来源。

在宿主的 config\config.yaml 里 ai 段下新增（与 ZenFree 并列）：

    ai:
      opencli:
        label: opencli本地网关
        api_base: http://127.0.0.1:8199/v1
        api_key: <与网关 token 同值>
        timeout: 900
        max_retries: 2
        models: []

要点逐条：

(1) api_base 必须带 /v1 结尾，宿主拿它直接拼 /chat/completions 和 /models，这是两边唯一的契约锚点。

(2) 在 UI 里建 provider 即建即生效，不需要重启宿主：宿主把新增配置写回 config.yaml 后当场热重载（设置页保存就生效）。一个例外场景：你自己手工改 config.yaml 文件的话，改完也要靠热重载机制，保险起见可重启后端一次（v1.7 之前手册写"必须重启"是查实宿主代码前的保守口径，已按实测更正）。

(3) 备用保险（你现在用不上）：宿主发请求会跟随系统代理变量。本机现在系统代理是关的、代理变量是空的，所以 NO_PROXY 可设可不设；假如你将来开全局代理/VPN 软件接管出网，先 setx NO_PROXY "127.0.0.1,localhost"（用户级），让之后新启动的进程不受劫持——网关的 start.bat 自身每次都带这条，不用管。

(4) 界面四步：建 provider 填上面地址和 key；拉模型（免费层 9 到 10 个，个数波动属正常）；勾选要用的模型；保存后对话验证。

(5) 鉴权两层都不用人工填：宿主到网关的 token 部署时已写入两处；网关到下游的密码由网关自动捕获，不落盘不暴露。

[4] 测试

说明：验收回归脚本，零第三方依赖（只用 httpx），改了代码或换了环境跑一轮就能知道有没有退化。命令两条：

    python gateways\tests\run_cases.py            快速套件，约 1 分钟，现状 12 过 0 败 3 跳
    python gateways\tests\run_cases.py --full     追加重型 C4/F1/F2/F3/D7，约 5 分钟

(1) 用 --only A3,D1 可以点选复跑；有失败退出码为 1，可直接挂 CI。

(2) 注意：C4 是并发 40 路，可能把免费额度打满触发网关约 1 小时冷却，放空闲窗口单独跑；其余四项 F3、D7、F1、F2 已实测全过。

(3) 跳过（SKIP）的是断网、停服、思考模型三类，必须手工做；60 项台账见 doc-11月优化 里的执行记录文档。

[5] 打包部署

说明：给"只用打包版 exe"的用户看的。默认安装包不含网关，这里是确要用时的进路。

(1) 默认不进包：OmniAgentBackend.spec 不收 gateways，打包版没有 opencli 能力。这是推荐方案 A，境内用户免费层多数直连 429，预置了也用不了。

(2) 确要用（方案 C）：单独编译 gateway.exe，放到 dist\OmniAgentBackend\gateways 目录（与源码同形），手动启动；其余配置操作照 [2]。

(3) 两个坑：.py 塞进 _internal 跑不起来（包里没有 Python 解释器）；体积代价约 260 MB（gateway.exe 加 CLI 文件）。

[6] 常见问题

说明：五个最常撞的问题，每条一现象一处置，先按现象对上再动手。

(1) 对话返回 401 —— 宿主的 api_key 和网关的 token 不是同一个值，两处对齐就通。

(2) 连接拒绝（10061）—— 网关没起或端口不对：先 start.bat，再核对 config.json 的 port 与宿主 api_base 是否一致。

(3) 大量 429 free-limit —— 免费层额度或地区限制：等冷却（最长约 1 小时）或换网络出口，不需要改任何配置。

(4) 未知模型 404 —— 模型名不在当前免费层清单里：去 UI 重新拉一次模型再勾选保存。

(5) 流式偶尔断一下 —— 免费层远端瞬时波动：重试通常就过；持续断开按执行记录第三节手工项排查。
