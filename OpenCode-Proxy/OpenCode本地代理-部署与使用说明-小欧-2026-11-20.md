## 一、用途与原理

### 1.1 解决的问题

opencode 桌面版 CLI 是 Bun 单文件程序，其 uSockets 网络栈在本机无法直连外网，所有模型请求报 `AI.Error: ECONNREFUSED`。node 网络栈正常，因此用一个 **node 写的本地代理** 承接 Bun 的出网请求。

### 1.2 数据流

```
opencode-cli.exe (Bun)
      │  HTTPS_PROXY=http://127.0.0.1:18080
      ▼
opencode-proxy.js (node, 127.0.0.1:18080)
      │  CONNECT 隧道 / HTTP 转发
      ▼
models.opencode.ai 等外网站点 (443/80)
```

### 1.3 组成与端口

| 角色 | 实现 | 端口/路径 |
|------|------|-----------|
| 代理进程 | `opencode-proxy.js`（node） | 监听 `127.0.0.1:18080` |
| 开机自启 | `start-opencode-proxy.vbs` + 启动文件夹 | 用户登录时触发 |
| 故障自愈 | `watchdog-opencode-proxy.ps1` + 计划任务 | 每 5 分钟探测一次 |
| 手动兜底 | `start-opencode-proxy-manual.bat` | 双击运行 |
| 运行体检 | `check-opencode-proxy.bat` | 双击运行，7 项给结论 |
| 手动停止 | `stop-opencode-proxy.bat` | 双击运行，`/keepoff` 连看门狗一起停 |
| 运行日志 | `E:\Appsw\opencode-proxy.log` | UTC 时间，5 MB 滚动 |
| 守护日志 | `E:\Appsw\opencode-proxy-watchdog.log` | 本机时间，1 MB 滚动 |

## 三、部署步骤

> **推荐做法**：直接双击 `deploy-opencode-proxy.bat`（第四章 4.2），它把下面 3.2～3.7 全部串起来并自带验收，还会顺带复制体检/启动/停止三个 bat。
> 本章保留手工步骤，用于理解流程或在没有 bat 时逐项排查。

### 3.1 前置条件

```powershell
# 1) node 是否存在
Test-Path E:\Appsw\nodejs\node.exe

# 2) opencode 桌面版进程是否存在（存在说明桌面端已安装）
Get-Process opencode-cli -ErrorAction SilentlyContinue | Select-Object Id,ProcessName
```

两条都必须为真，否则先修环境再部署。

### 3.2 第一步：复制脚本到 E:\Appsw

```powershell
$src = "F:\OmniAgentAs-01\OpenCode-Proxy"
Copy-Item "$src\opencode-proxy.js"              E:\Appsw\ -Force
Copy-Item "$src\watchdog-opencode-proxy.ps1"    E:\Appsw\ -Force
Copy-Item "$src\run-watchdog-hidden.vbs"        E:\Appsw\ -Force
Copy-Item "$src\start-opencode-proxy.vbs"       E:\Appsw\ -Force
Copy-Item "$src\start-opencode-proxy-manual.bat" E:\Appsw\ -Force
Copy-Item "$src\check-opencode-proxy.bat"        E:\Appsw\ -Force
Copy-Item "$src\stop-opencode-proxy.bat"         E:\Appsw\ -Force

# 语法自检（应无输出，退出码 0）
& E:\Appsw\nodejs\node.exe --check E:\Appsw\opencode-proxy.js
```

### 3.3 第二步：启动代理并验证

```powershell
# 隐藏窗口启动
Start-Process "$env:WINDIR\System32\wscript.exe" -ArgumentList '"E:\Appsw\start-opencode-proxy.vbs"'

# 等 2 秒后看端口是否有监听（应看到 127.0.0.1:18080 LISTENING）
Start-Sleep -Seconds 2
Get-NetTCPConnection -LocalPort 18080 -State Listen

# 走代理实测外网（应返回 HTTP:200）
curl.exe -s -x http://127.0.0.1:18080 -o NUL -w "HTTP:%{http_code}`n" `
  "https://models.opencode.ai/experimental/v2.0/api.json?type=chat"
```

### 3.4 第三步：让 opencode 走代理

官方入口（opencode CLI 在当前 PATH 中时）：

```powershell
opencode service set env HTTPS_PROXY http://127.0.0.1:18080
opencode service restart
opencode service get env
```

若 CLI 不在 PATH，可直接编辑服务配置文件 `C:\Users\chend\.config\opencode\service.json`，`env` 段写入：

```json
{
  "env": {
    "HTTPS_PROXY": "http://127.0.0.1:18080"
  }
}
```

> 注意：`service.json` 中还有 `password` 字段，编辑时不要覆盖或删除；改完需重启 opencode 桌面端读取新配置。

### 3.5 第四步：确认 opencode 真的走了代理

```powershell
$pid0 = (Get-CimInstance Win32_Process -Filter "Name='opencode-cli.exe'").ProcessId
Get-NetTCPConnection -OwningProcess $pid0 -State Established |
  Where-Object { $_.RemotePort -eq 18080 }
```

**验收标准**：能看到 `127.0.0.1:xxxxx → 127.0.0.1:18080` 的 ESTABLISHED 连接，且 opencode 进程**没有**直连外网 443 的连接。

### 3.6 第五步：配置开机自启

```powershell
$startup = [Environment]::GetFolderPath("Startup")
Copy-Item E:\Appsw\start-opencode-proxy.vbs $startup -Force
Test-Path (Join-Path $startup "start-opencode-proxy.vbs")
```

### 3.7 第六步：注册看门狗计划任务

计划任务**不直接调用 powershell**，而是调用 `wscript.exe` 执行静默启动器 `run-watchdog-hidden.vbs`，由它把 powershell 以窗口样式 0（隐藏）启动——否则每 5 分钟会闪出一个黑色控制台窗口。

```powershell
$tr = '"C:\Windows\System32\wscript.exe" "E:\Appsw\run-watchdog-hidden.vbs"'
schtasks /Create /TN "OpenCodeProxyWatchdog" /SC MINUTE /MO 5 /TR $tr /F
```

> 若任务已存在，改动作命令用：`schtasks /Change /TN "OpenCodeProxyWatchdog" /TR $tr`
> 改完用 `schtasks /Query /TN "OpenCodeProxyWatchdog" /XML` 确认 `<Command>` 是 `wscript.exe`。

### 3.8 部署验收清单

| 序号 | 检查项 | 命令 | 期望结果 |
|------|--------|------|---------|
| 1 | 代理监听 | `Get-NetTCPConnection -LocalPort 18080 -State Listen` | 有 LISTENING |
| 2 | 转发可用 | `curl.exe -x http://127.0.0.1:18080 ...` | `HTTP:200` |
| 3 | 配置生效 | 查 `service.json` 的 `HTTPS_PROXY` | `http://127.0.0.1:18080` |
| 4 | opencode 已接入 | 见 3.5 命令 | 有到 18080 的连接 |
| 5 | 自启已部署 | 启动文件夹存在 VBS | `True` |
| 6 | 看门狗已注册 | `schtasks /Query /TN "OpenCodeProxyWatchdog"` | 状态"就绪"、下次运行时间在 5 分钟内 |
| 7 | 看门狗不弹窗 | 任务动作是 `wscript.exe ...run-watchdog-hidden.vbs` | 每 5 分钟无控制台窗口出现 |

## 四、脚本工具箱（4 个 bat）

全部脚本随本目录发布，`deploy-opencode-proxy.bat` 会自动把它们复制到 `E:\Appsw\`。脚本统一按 **GBK 编码 + CRLF 换行**保存，双击运行，输出为中文，无需管理员权限。

### 4.1 一览

| 脚本 | 用途 | 参数 | 退出码 |
|------|------|------|--------|
| `deploy-opencode-proxy.bat` | 一键部署/升级：备份 → 复制 → 语法自检 → 启动 → 开机自启 → 计划任务 → 联调验收 | 无 | 0 成功 / 1 失败 |
| `check-opencode-proxy.bat` | 运行状态体检：端口、进程身份、转发、opencode 接入、代理配置、看门狗、日志 | 无 | 0 健康 / 1 异常 |
| `start-opencode-proxy-manual.bat` | 手动启动；已在运行则只做健康确认 | `/restart` 先停再起 | 0 成功 / 1 失败 |
| `stop-opencode-proxy.bat` | 停止代理并确认端口释放 | `/keepoff` 同时禁用看门狗 | 0 完成 |

### 4.2 部署脚本 `deploy-opencode-proxy.bat`

在源目录 `F:\OmniAgentAs-01\OpenCode-Proxy\` 下双击运行（脚本用 `%~dp0` 定位源文件，换目录也能用）。

| 步骤 | 动作 | 失败处理 |
|------|------|---------|
| 1/7 | 检查 node 与 7 个源文件齐全 | 打印缺失项后中止 |
| 2/7 | 备份 `E:\Appsw` 现有同名文件到 `E:\Appsw\backup\deploy-yyyyMMdd-HHmmss` | 备份目录不可写则中止 |
| 3/7 | 复制脚本到 `E:\Appsw`，并同步部署脚本自身 | 任一复制失败即中止 |
| 4/7 | `node --check` 代理脚本语法 | 语法错误即中止 |
| 5/7 | 启动代理（已在跑则跳过）并等待端口监听 | 10 秒未监听即中止 |
| 6/7 | 复制 VBS 到启动文件夹；重建看门狗计划任务 | 任务注册失败提示用管理员身份 |
| 7/7 | 校验 `service.json` 配置 + 走代理实测 HTTP 200 | 返回非 200 即判失败 |

> 部署是**幂等**的：重复运行只会刷新文件、重建同名任务，不会产生重复任务或重复开机自启项。

### 4.3 体检脚本 `check-opencode-proxy.bat`

不确定"现在到底好不好"时双击它，7 项逐一给结论：

| 序号 | 检查项 | 判定标准 |
|------|--------|---------|
| 1/7 | 监听状态 | 18080 有 LISTENING，并给出 PID |
| 2/7 | 进程身份 | 该 PID 命令行含 `opencode-proxy.js`（防止端口被别的程序占用） |
| 3/7 | 转发实测 | 经代理请求 `models.opencode.ai` 返回 HTTP 200 |
| 4/7 | opencode 接入 | opencode 进程存在到 18080 的 ESTABLISHED 连接 |
| 5/7 | 代理配置 | `service.json` 含 `127.0.0.1:18080` |
| 6/7 | 看门狗 | 任务存在且未被禁用，并显示下次运行时间与上次结果 |
| 7/7 | 日志尾部 | 打印代理与看门狗日志各若干行 |

`上次结果` 取值含义：`0` 正常，`267009` 正在运行，`267011` 尚未运行，其他值为异常。

### 4.4 启动脚本 `start-opencode-proxy-manual.bat`

- 未运行 → 隐藏启动并等端口，随后做一次真实转发测试；
- 已运行但不是代理进程（端口被占用）→ 直接报错并给出 `taskkill` 命令，不盲目启动；
- `start-opencode-proxy-manual.bat /restart` → 先杀现有代理再启动，用于改了参数或脚本后的热更新。

### 4.5 停止脚本 `stop-opencode-proxy.bat`

- 默认：停进程 + 确认端口释放，并提示"看门狗 5 分钟内会重新拉起"；
- `stop-opencode-proxy.bat /keepoff`：同时 `schtasks /Change /DISABLE` 看门狗，适合长时间停用；
- 恢复自愈：`schtasks /Change /TN "OpenCodeProxyWatchdog" /ENABLE`。

### 4.6 编码与调用约定

| 约定 | 说明 |
|------|------|
| 编码 | bat 一律 **GBK**（`chcp 936` 已写在首行），禁止存成 UTF-8，否则中文乱码甚至语法报错 |
| 换行 | 必须 CRLF，LF-only 会导致 `goto :label` 跳转异常 |
| 延时 | 用 `ping -n 2 127.0.0.1 >nul` 代替 `timeout /t 1`，因为 `timeout` 在输入重定向下会立即报错退出 |
| 路径 | 所有脚本用绝对路径（`E:\Appsw\...`），不依赖 PATH，也不需要管理员权限 |

## 五、日常使用说明

### 5.1 一句话判断"现在好不好"

```powershell
Get-NetTCPConnection -LocalPort 18080 -State Listen; Get-Content E:\Appsw\opencode-proxy.log -Tail 5
```

有 LISTENING、日志最后一条是 `PROXY_READY` 或正常转发记录 → 正常。

### 5.2 启动与停止

| 目的 | 操作 |
|------|------|
| 启动 / 体检 / 停止（推荐） | 双击 `E:\Appsw\` 下的 `start-opencode-proxy-manual.bat`、`check-opencode-proxy.bat`、`stop-opencode-proxy.bat`（说明见第四章） |
| 改完脚本想立刻生效 | 双击 `start-opencode-proxy-manual.bat /restart`，先停再起并做转发测试 |
| 长时间停用（不让看门狗拉起） | `stop-opencode-proxy.bat /keepoff`；恢复自愈 `schtasks /Change /TN "OpenCodeProxyWatchdog" /ENABLE` |
| 静默启动（无窗口） | 双击 `E:\Appsw\start-opencode-proxy.vbs`，或部署脚本 / 开机会自动调用 |
| 前台调试 | `E:\Appsw\nodejs\node.exe E:\Appsw\opencode-proxy.js`，Ctrl+C 停止 |
| 命令行停止（不想用 bat 时） | `Get-NetTCPConnection -LocalPort 18080 -State Listen` 拿 PID → `Stop-Process -Id <PID> -Force` |
| 触发自愈（不等 5 分钟） | `schtasks /Run /TN "OpenCodeProxyWatchdog"` |

### 5.3 看日志

```powershell
# 代理日志：UTC 时间（与 opencode.log 一致），记录启动/报错/超时
Get-Content E:\Appsw\opencode-proxy.log -Tail 30

# 看门狗日志：本机时间，只在异常时写行
Get-Content E:\Appsw\opencode-proxy-watchdog.log -Tail 20
```

日志关键字对照：

| 关键字 | 含义 |
|--------|------|
| `PROXY_READY` | 代理启动成功，开始监听 |
| `PROXY_ALREADY_RUNNING` | 已有实例，本次启动自动退出（正常） |
| `tunnel connect timeout` | 对外建连 15 秒未完成，已断开 |
| `tunnel idle timeout` | 隧道 10 分钟无数据，已回收 |
| `FATAL server error` | 端口被占用等致命错误，进程已退出，等看门狗拉起 |
| `WARN port 18080 not listening` | 看门狗发现代理不在，正在拉起 |

### 5.4 修改参数

参数集中在 `opencode-proxy.js` 顶部常量，改完**覆盖到 `E:\Appsw\` 并重启代理**（或杀进程后等看门狗自动拉起）：

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | 18080 | 改端口后必须同步改 `service.json` 的 `HTTPS_PROXY` |
| `CONNECT_TIMEOUT_MS` | 15000 | 对外建连超时 |
| `IDLE_TIMEOUT_MS` | 600000 | 隧道空闲回收时间 |
| `LOG_FILE` | `E:\Appsw\opencode-proxy.log` | 日志路径 |
| `LOG_MAX_BYTES` | 5242880 | 日志滚动阈值 |

### 5.5 VBS / PS1 编码约定（易踩坑）

- VBScript 宿主按**系统 ANSI（本机 GBK）** 读取 `.vbs`。文件若存成 **UTF-8 无 BOM**，中文注释会被错误解码，严重时把下一行一起吞掉并报 `缺少对象`，`wscript` 还会弹出错误框**卡住计划任务**（任务状态一直显示"正在运行"）。
- 因此 `start-opencode-proxy.vbs`、`run-watchdog-hidden.vbs` 一律**只写 ASCII 注释**（2026-11-20 已统一改造）。
- 确需中文注释时，请存成 ANSI 或 UTF-16 LE（带 BOM），不要存 UTF-8 无 BOM。
- `watchdog-opencode-proxy.ps1` 同样只输出 ASCII 日志文本，避免 PowerShell 5.1 按 ANSI 读取时出现乱码。

## 六、故障处理

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| opencode 又报 `ECONNREFUSED` | 代理没在跑 | `schtasks /Run /TN "OpenCodeProxyWatchdog"`，仍不行按 5.2 手动启动 |
| 18080 无监听，看门狗也没拉起 | 计划任务被禁用 / 用户未登录 | `schtasks /Query /TN "OpenCodeProxyWatchdog" /V /FO LIST` 查状态与上次结果 |
| 看门狗日志 `node not found` | node 目录变更 | 同步修改 `watchdog-opencode-proxy.ps1`、`start-opencode-proxy.vbs` 中的路径 |
| 代理日志 `FATAL server error ... EADDRINUSE` | 端口被别的程序占用 | `netstat -ano \| findstr ":18080"` 查占用 PID，`taskkill /PID <PID> /F` 后重启代理 |
| 代理正常但 opencode 仍直连失败 | `HTTPS_PROXY` 未生效 | 查 `service.json`，重启 opencode 桌面端 |
| 请求偶发 502 | 上游站点不通 | 看代理日志 `http forward failed`，先确认外网与目标站点可达 |
| 每 5 分钟闪一个黑色控制台窗口 | 任务直接调用 `powershell.exe`（控制台程序），且任务未隐藏 | 任务动作改为 `wscript.exe "E:\Appsw\run-watchdog-hidden.vbs"`（见 3.7） |
| 计划任务一直显示"正在运行"、代理却没起来 | VBS 含中文注释被按 ANSI 解析，解析报错弹框卡住 | 两个 VBS 一律用 ASCII 注释；杀掉卡住的 `wscript.exe` 后重新 `schtasks /Run` |

## 七、回滚（彻底撤销）

按顺序执行：

```powershell
# 1) 删除看门狗任务
schtasks /Delete /TN "OpenCodeProxyWatchdog" /F

# 2) 取消开机自启
Remove-Item (Join-Path ([Environment]::GetFolderPath("Startup")) "start-opencode-proxy.vbs") -Force

# 3) 撤销 opencode 代理配置（CLI 可用时）
opencode service unset env HTTPS_PROXY
opencode service restart

# 4) 停止代理进程
$p = (Get-NetTCPConnection -LocalPort 18080 -State Listen -ErrorAction SilentlyContinue).OwningProcess
if ($p) { Stop-Process -Id $p -Force }

# 5) 删除部署文件（可选，保留也不影响）

```

若 CLI 不在 PATH，第 3 步改为手工删除 `C:\Users\chend\.config\opencode\service.json` 中 `env.HTTPS_PROXY` 一项，再重启 opencode 桌面端。
