## 一、总体架构：四大数据库

| 序号 | 库文件（位于 `~/.omniagent/`） | 职责 | 连接名（db.get_conn 参数） |
|------|----------------------------------|------|---------------------------|
| 1 | `chat_history.db` | 对话会话、消息、任务、步骤、token、信任清单 | `"chat"` |
| 2 | `operations.db` | 文件操作审计、定时器 | `"operations"` |
| 3 | `task_tracker.db` | 任务追踪（tasks 主表 + task_operations 步骤明细） | `"task_tracker"` |
| 4 | `tool_observer.db` | 工具调用审计（**占位未启用**，`init_observer()` 为空实现） | `"observer"` |

**统一入口**: 所有 DB 操作经 `db.get_conn(db_name)` / `db.get_conn_with_retry(db_name)`（database.py:124/230），自动事务（commit/rollback）、WAL 模式、`busy_timeout=500ms` + 指数退避重试（0.5/1/2s，仅对 locked）、`foreign_keys=ON`、参数安全闸门（`_ParamSafeConnection`，仅允许 str/int/float/bytes/bool/None）。

**启动初始化**: `app.main.startup_event → db.init() → init_chat_db/init_operations_db/init_task_tracker_db`（main.py:188，幂等，`CREATE TABLE IF NOT EXISTS` + `_ensure_column` 补列）。

**时区约定**: 全部时间列 TEXT 类型存储，格式为**本地 ISO 无 Z**（`get_local_iso_timestamp()`，2026-08-08 全程统一）；时间排序/格式 `format_timestamp` 对外兜底。

| user_message_id | INTEGER | append_execution_step（:389） | 步骤落库 | 本任务 user 消息 id（`_user_msg_id`，冗余免 JOIN，v2.0 新增） |

**写入时序（agent_runner._persist, agent_runner.py:201-232）**:
1. 首步出现时惰性：`db_ops.allocate_and_insert(conn, session_id)` → 分配 ai_message_id + 插入 chat_messages 空白 assistant 行（allocate_and_insert_message）→ 更新 chat_sessions.message_count+1
2. 从 `agent._usage_events` 取本步骤所属轮（`ed["step"]` 匹配）的 usage 明细，序列化为 usage JSON（改动8后半，v1.3）
3. `db_ops.append_step(conn, ai_message_id, session_id, 步骤idx, step dict, usage)` → INSERT chat_task_steps（含 usage 列）

**落库 step 类型**: 仅 `thought` / `start` / `action` / `final` 及未分类事件落库；`chunk` 纯实时不落库；`error/usage/paused/resumed/retrying/cancelled` 仅 SSE 不落库（§10.4.3 P3/P5/P6）。

**索引**: idx_steps_message(ai_message_id) / idx_steps_session(session_id, step_index) / idx_steps_task(task_id, step_index)。

## 九、关键设计约束与注意事项（升级必读）

1. **id 即关联**：chat_messages.id / chat_user_message.id / chat_tasks.user_message_id / chat_tasks.ai_message_id / chat_task_steps.ai_message_id 五者以"消息 id"为枢纽贯通；**新增关联必须走这套 id 语义，禁止另造 ID**。
2. **相邻配对规律**：user 消息 id 与对应 assistant 消息 id **相差 1**（assistant = user + 1，storage allocator）；历史数据实测 24/24 验证。可用于审计/回填。
3. **任务系统双轨**：chat_tasks（对话任务）与 task_tracker.tasks（agent 任务）并行；升级时须明确"哪套任务体系"，禁止混用 task_id。
4. **冻结表不可写**：chat_messages 的 execution_steps 列已废弃（新库无此列）；新链路写步骤只允许 chat_task_steps。
5. **幂等守卫**：迁移经 schema_migrations 登记，一次性；改迁移必须可重入（删登记可重跑，已有行跳过）。
6. **时区统一**：所有时间列本地 ISO 无 Z；新写入必须用 `get_local_iso_timestamp()`（2026-08-08 后统一）。
7. **锁与重试**：DB 写统一 db.get_conn_with_retry（locked 自动重试 3 次）；并发写冲突返回 409 由调用方处理。
8. **参数安全**：DB 参数仅允许 str/int/float/bytes/bool/None；datetime 自动转本地 ISO；严禁传对象/Mock。
