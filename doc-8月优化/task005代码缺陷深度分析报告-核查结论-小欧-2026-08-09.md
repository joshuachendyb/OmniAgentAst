### 2.6 问题6: migrate_utc_to_local.py 时区检测边界

#### 2.6.1 报告主张

`has_tz = s.endswith('Z') or ('+' in s[10:]) or ('-' in s[10:])` 对非ISO格式(如 `2026/08/08 08:00:00+0800`)误判为有时区, 迁移脚本"误报已处理而实际未转换"。报告定级: 🟢 极低。

#### 2.6.2 代码定位

- **Commit**: `892cc4f18` (2026-08-08) "ETL迁移脚本: UTC Z/偏移→本地ISO无Z"
- **文件**: `backend/scripts/migrate_utc_to_local.py` (line 47-64)

#### 2.6.3 确认过程(逐步验证)

**步骤1 — 代码现状核验** (line 56-64):
```python
    has_tz = s.endswith('Z') or ('+' in s[10:]) or ('-' in s[10:])
    if not has_tz:
        return utc_str  # 已是本地naive无偏移，跳过(幂等)
    try:
        dt = datetime.fromisoformat(s.replace('Z', '+00:00'))
        local_dt = dt.astimezone()
        return local_dt.replace(tzinfo=None).strftime('%Y-%m-%dT%H:%M:%S.%f')
    except (ValueError, TypeError, OverflowError):
        return utc_str  # 解析失败原样返回(幂等)
```
→ **确认: 检测逻辑与报告描述一致**。

**步骤2 — 边界场景验证**:
- `"2026-08-08T08:00:00-05:00"` → `s[10:]`="T08:00:00-05:00" 含`-` → 正确识别 ✓
- `"2026-08-08T08:00:00+00:00"` → 含`+` → 正确识别 ✓
- `"2026-08-08"` → `s[10:]`="" → 跳过(幂等) ✓
- `"2026-08-08T08:00:00.123456"` → 无`+/-` → 跳过 ✓
- `"2026/08/08 08:00:00+0800"`(非ISO) → `s[10:]`含`+` → 误判有时区 → fromisoformat 解析失败 → **原样返回(幂等)**

**步骤3 — 实际影响评估**:

#### 3.2.2 合理检查(口径一致性)

### 3.3 可选优化: 问题3 cmdlet 名误报收紧 — 三堂会审

#### 3.3.1 报告原方案(全删)不采纳

报告建议"移除全部 cmdlet 名"。反例已证(2.3.3 步骤4): PowerShell 真实错误 `Get-Process : Access is denied.` 中 `Access is denied` 不在 markers, 移除 `Get-Process` 会漏报真实错误 → **报告方案不合理, 弃用**。

#### 3.3.2 推荐收紧方案(可行性已核实)

```python
# 收紧为: cmdlet 名后须跟随 ": " + 错误上下文 — 小欧 2026-08-09
r"\bGet-ChildItem\b\s*:",
r"\bGet-Process\b\s*:",
r"\bGet-CimInstance\b\s*:",
r"\bGet-WinEvent\b\s*:",
r"\bSet-ItemProperty\b\s*:",
```

PowerShell 错误消息标准格式为 `Cmdlet名 : 错误文本`(行首锚点 + 冒号 + 空格)。收紧为 `\b名\b\s*:` 后:
- `Get-Process : Access is denied.` → 命中(行首锚点+冒号) ✓
- 正常输出 "Get-Process 命令执行成功" → 无冒号, 不命中 ✓

#### 3.3.3 三堂会审

- **合规**: 不破坏实证回归(131/17/2)的 cmdlet 错误识别, 仅收窄误报面;
- **合理**: 词边界+冒号双重约束, 比全删(漏报)与现状(误报)都精确;
- **关联逻辑**: 误判点是 error/warning 三级判别(execute_shell_command.py:1262-1268), 收紧后对 returncode!=0 分支的真实 cmdlet 错误仍能识别。**注意: ForEach-Object/Sort-Object/New-Object 等管道动词不产生 "cmdlet : " 行首错误, 收紧后识别不到(但错误文本往往伴随 Cannot find/ParserError 等其它 marker, 漏报风险低), 需回归验证。**

#### 3.3.4 修正方案结论

⚠️ **方案合理可行, 但需回归验证**(shell 相关用例/实测 PowerShell 错误), 属可选优化, 优先级低于问题2。
