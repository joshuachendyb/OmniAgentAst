## 一、审查背景

用户反馈前端 toast 长期存在三类现象：
1. **显示不正常**（主题/样式错乱）
2. **点不动**（无法交互）
3. **点了不消失**（无点击关闭）

经三堂会审定位，根因为：**antd v5 静态 `message`/`notification` 方法脱离 React 树、不消费 `<ConfigProvider>` 主题上下文**（官方明令警告："Static function can not consume context... Please use 'App' component"）。已于 2026-08-28 提交 `de1cafc0e` 根治（`<App>` 包裹 + `App.useApp()` 桥接单例 + 错误 toast 点击消失）。

本报告对前端做**彻底复查**，确认是否还存在同类/衍生问题。

---

## 二、审查范围与方法

- 全仓 `frontend/src/**/*.{ts,tsx}` 静态扫描
- 关键词：`import { message|notification|Modal } from 'antd'`、`message./notification./Modal.(confirm|error|warning|info|success|destroy)`、`App.useApp`、`getPopupContainer`、`duration: 0`、antd 子路径导入 `antd/es|antd/lib`

## 三、审查结果（逐类）

### 3.1 antd 静态 `message` 调用 — ✅ 已根治（无残留）
- 全量 `message.(success|error|warning|info|loading|destroy)` 调用点：
  - `utils/errorHandler.ts`（5 处）→ 已改 `getMessage()`
  - `hooks/useLoadingMessage.ts`（1 处）→ 已改 `getMessage()`
  - `components/Chat/NewChatContainer.tsx`（`message.destroy`）→ 已改 `getMessage()`
- 反证：`sse.ts:30` 仅注释残留（`已迁移到errorHandler统一处理`），无激活调用。

### 3.2 antd 静态 `notification` 调用 — ✅ 已根治（无残留）
- `components/SecurityNotification/index.tsx`（`notification.warning`）→ 已改 `getNotification()`
- 全仓再无其它 `notification.*` 静态调用。

### 3.3 antd 静态 `Modal.confirm` 等命令式调用 — ✅ 无（无同类问题）
- 扫描 `Modal.(confirm|error|warning|info|success|destroy)`：**0 命中**
- 全仓 3 处 `import { Modal }`（`ShortcutPanel`、`DangerConfirmModal`、`AuthorizationModal`）均为 **JSX 组件 `<Modal>` 用法**，渲染在 React 树内、消费 `<App>` 上下文，非命令式静态调用，**不存在上下文 bug**。

### 3.4 `App.useApp` 重复包裹 — ✅ 无
- 全仓仅 `utils/antdApp.ts` / `utils/antdAppBridge.tsx` 使用 `App.useApp()`，单一桥接，无重复挂载。

### 3.5 `getPopupContainer` Portal 隐患 — ✅ 无
- 全仓 0 处 `getPopupContainer`，无因父容器 `overflow/transform` 导致弹层被裁剪/点不动的风险。

### 3.6 antd 子路径静态导入 — ✅ 无
- 无 `import ... from 'antd/es'` / `'antd/lib'` 等绕过单例的静态入口（除 sse.ts 注释）。

### 3.7 `duration: 0` 悬挂风险 — ⚠️ 设计内（非 bug）
- `errorHandler.ts:43` `UI_CONFIG.loading.duration:0` 与 `NewChatContainer.tsx:172` `useLoadingMessage({duration:0})`：
  - 属 **loading 语义**（操作完成前持续显示），由调用方显式 `hideLoading()` 关闭。
  - `useLoadingMessage` 已含 ctx 修复（按 key 精确隐藏、卸载清理、不误清全局队列），不会泄漏/悬挂。
  - **判定**：非静态上下文问题，属正常设计；仅需运行时回归确认各 `hideLoading` 调用路径闭环（非本次代码缺陷）。

## 四、总体结论

| 类别 | 结果 | 说明 |
|------|------|------|
| 静态 `message` | 已根治 | 全部改走 `antdApp.getMessage()` 上下文实例 |
| 静态 `notification` | 已根治 | 全部改走 `antdApp.getNotification()` 上下文实例 |
| 静态 `Modal.*` | 无问题 | 仅 JSX 组件用法，消费上下文 |
| Portal/裁剪 | 无问题 | 无 `getPopupContainer` |
| 子路径静态入口 | 无问题 | 无 `antd/es|lib` 绕过 |
| loading 悬挂 | 设计内 | 手动 hide，已有清理保障 |

**彻底审查结论**：前端"显示不正常/点不动/点击不消失"的根因（antd v5 静态方法脱离 `<App>` 上下文）**已唯一存在且唯一根治**，无同类残留问题。本次 toast 修复（`de1cafc0e`）为终态修复，无需二次改动。
