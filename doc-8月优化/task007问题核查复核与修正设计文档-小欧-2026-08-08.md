## 三、需要修正的真实系统问题（经深挖，共 2 处必须修正 + 1 处可选扩展）

### 修正 A（🔴 高，必须）：良性 stderr 误判为错误

**病根（经源码深挖定位，级别：准确）**：
`execute_shell_command.py` **阶段 5 状态判定**中，良性 stderr 过滤 `_filter_benign_stderr` 仅在下述分支被调用：

```text
L1207  elif returncode == 0 or returncode in (success_codes or []):   # 成功分支才过滤
L1208      stderr_clean = stderr_str.strip()
L1209      if stderr_clean:
L1210          benign_filtered = _filter_benign_stderr(stderr_str)
L1211          if not benign_filtered.strip():
L1212              data["stderr"] = ""                   # 通过: 全良性→清空
L1214          else:
L1215              _exec_code = "warning"                 # 有非良性→warning

L1216  else:                                            # returncode≠0 的 error 分支
L1217      _exec_code = "error"
L1218      _err_code = ERR_SHELL_EXEC
L1219      _detail = stderr_str ...                      # ← 直接取原始 stderr, 未过滤
```

**根因**：**error 分支（returncode≠0）未应用良性过滤**，导致「进程非零退出但 stderr 全为良性提示（CPU/Deprecation/UserWarning）」被判定为 `ERR_SHELL_EXEC`。实测 `ocr_recognition.py` 返回 1146 字符 detail 100% 良性却报 error。

**修正设计（防御式 + 单一职责 + 幂等 + 可测试性）**：

```python
# ─── execute_shell_command.py 新增纯函数(可单测) ───
_REAL_ERROR_MARKERS = (
    r"\bTraceback\b", r"\bError\b", r"\bException\b", r"\bSyntaxError\b",
    r"\bImportError\b", r"\bModuleNotFoundError\b", r"\bFileNotFoundError\b",
    r"\bPermissionError\b", r"\bOSError\b", r"\b拒绝访问\b", r"\b系统找不到\b",
    r"\b不是内部或外部命令\b", r"\bfatal:\b",
)

def _contains_real_error(text: str) -> bool:
    """检测文本是否含真实错误信号 — 小欧 2026-08-08 新增
    词边界正则: 避免 "no error"/"error-free" 等良性措辞被误判为真实错误。"""
    if not text:
        return False
    return any(re.search(m, text, re.IGNORECASE) for m in _REAL_ERROR_MARKERS)
```

```python
# ─── execute_shell_command.py L1207 起, 修正 error 分支 ───
else:  # return ≠ 0（且不在 success_codes）
    # 修正: 先过滤良性行, 提取真实错误
    filtered_err = _filter_benign_stderr(stderr_str)
    meaningful = filtered_err.strip()
    if meaningful:
        _exec_code = "error"
        _err_code = ERR_SHELL_EXEC

    else:

        if _contains_real_error(stdout_str):

            _err_code = ERR_SHELL_EXEC
            _detail = stdout_str.strip() or f"退出码{returncode}({_EXIT_CODE_MEANING.get(returncode, '未知错误')})"
        else:
            _exec_code = "warning"   # 全良性且无真实错误信号 → 降级 warning, 不误判 error
            _err_code = ERR_SHELL_EXEC   # 语义一致: 退出码异常, 不误用超时码

```

### 修正 B（🟡·真实，推荐增强）：自动修复覆盖不足

**病根**：三个 `_auto_fix_*` 函数各覆盖 4/1/1 种，未覆盖高频 `import xxx`（缺 python 前缀）与参数名未对齐。

**设计（KISS + DRY + 防御式）**：
```python
def _auto_wrap_python_import(command: str, shell_type: str) -> str:
    """把裸 import/from 包装为 python -c，避免 cmd/bash 把 import 当外部命令 — 小欧 2026-08-08
    幂等: 已含 python 前缀则不动; 空串/全空白直接返回(防御空split IndexError)"""
    if not command or not command.strip() or shell_type not in ("cmd", "bash"):
        return command
    head = command.strip().split(None, 1)[0].lower()
    if head == "python" or head == "python3" or head == "py":
        return command                                  # 幂等
    if re.match(r'^\s*(import|from)\s+\w', command):
        # cmd/bash 对内层双引号转义处理不同, 统一走 shell 引号转义函数
        inner = command.replace('"', '""')              # cmd 双引号加倍转义
        return f'python -c "{inner}"'
    return command
```
接入点：在 `execute_shell_command.py` 阶段 1.2 分支（L1022/L1026）的 `_auto_fix_cmd_syntax` / `_auto_fix_bash_syntax` 前追加 `_auto_wrap_python_import`（复用现有 4/1/1 调用结构，零侵入）。
