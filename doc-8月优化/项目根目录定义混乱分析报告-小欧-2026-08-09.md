## 二、项目根「唯一正源」应当是什么(北京老陈裁定)

- 项目根目录 = 配置文件显式定义的值(`app.project_root`);
- 若配置文件未定义, 项目根 = 用户主目录(`Path.home()`);
- 任何场合都不应把「代码安装位置」充当项目根。

**此定义不因授权目录/白名单变化而改变**(2026-08-10 00:18 北京老陈重申): 项目根始终「有配置用配置值, 无配置用用户主目录」; 授权目录(`app.allowed_dirs`)只是**额外扩展** tool 可访问目录的白名单, 与项目根定义互不干涉。

此口径已在本次确认, 作为本次修复的判定基准。


- **层级一: 真实目录(实体, 有获取方式/配置位置)** —— 代码库根、项目根、用户主目录、系统临时目录、系统目录、系统磁盘根、授权目录、任务临时目录;
- **层级二: 判定集合(代码逻辑判断用的规则, 不是实体目录, 3.2.7~3.2.11)** —— 白名单(`validate_tool_path` 放行判定)、黑名单=禁区(`_is_forbidden_path` 拦截判定, **按操作分写黑名单/删除黑名单**)、白名单外路径(临时授权判定);
- **三区互斥**: 任意路径必落且仅落一区——白名单(可操作区) / 白名单外·非禁区(临时授权区) / 黑名单=禁区(禁止区);
- **集合与成员**: 白名单 = 用户主目录 + 系统临时目录 + 项目根 + 授权目录 的并集; 黑名单 = 系统禁区(系统目录+盘根) + 非系统禁区(代码库根及其子/父级); 黑名单内按操作分**写黑名单/删除黑名单**两个判定集合(3.2.8);
- **用户下命令提到的目录**: **不是第四区, 不是独立概念**——它就是一个路径, 落哪区按哪区判定; 只是触发「临时授权机制」的任务级场景(3.2.13): 任务启动时把用户点名的路径一次性临时授权, 任务结束清除。

**3.2.2 代码库根——获取方式与使用方法**

- **定义**: 程序安装/代码所在目录;
- **获取方式**: `config._get_code_root()` = `Path(__file__).parent.parent.parent`(基于代码位置推算); 公开 API `get_code_root()`(str);
- **使用方法**: 仅用于定位程序自身资源(`config/config.yaml`、`version.txt`、`logs/`、模板); 属**非系统禁区**(=普通禁区, 读✅/写⚠️临时授权/删❌硬拦); **严禁充当项目根**(3.4 函数命名分离)。

**3.2.3 项目根——获取方式与使用方法**

- **定义**: 用户实际工作/数据目录 = tool 工作区;
- **获取方式**: `config.get_project_root()`(str) —— 配置 `app.project_root` **优先**; 未配置(空) → 用户主目录 `Path.home()`(不再用代码位置当项目根, ①);
- **使用方法**: R3-R6 删除判定、下载目录、输出目录、prompt 注入、规则文件注入; 属**白名单**(读/写/删放行)。

**3.2.4 用户主目录——获取方式与使用方法**

- **定义**: 当前系统用户的 home 目录;
- **获取方式**: `Path.home()`;
- **使用方法**: 白名单自动放行区(读/写/删, 删受 R3-R6); **双重身份**——既是白名单成员, 又是项目根未配置时的兜底(3.2.3)。

**3.2.5 系统临时目录——获取方式与使用方法**

- **定义**: 操作系统临时目录(`/tmp`、`/var/tmp`);
- **获取方式**: 常量 `Path("/tmp")`、`Path("/var/tmp")` 恒定拼入白名单;
- **使用方法**: 白名单自动放行区, tool 可在系统临时目录内读/写/删(删受 R3-R6 判定); 3.3决策② 明确保留。

**3.2.6 授权目录——获取方式与使用方法**

- **定义**: 除项目根外, 用户额外授权 tool 访问的工作目录(可多个);
- **获取方式**: `config.get_allowed_dirs()`(list) —— 配置 `app.allowed_dirs`(YAML 列表); 项目根天然在授权内, 无需重复列入(决策④);
- **边界约束**: 指向代码库根或其子/父级 → `ValueError` 拒绝加载(3.3 边界约束/⑦禁区冲突); 非字符串条目 → `ValueError`;
- **使用方法**: 等同项目根——读/写/删/浏览, 参与 R3-R6 删除判定; 属白名单。

**3.2.7 白名单——目录组成与使用规则(判定集合)**

- **目录组成**: = 用户主目录(`Path.home()`) + `/tmp` + `/var/tmp` + 项目根 + 授权目录(3.3决策②, `get_default_allowed_paths()`/`ALLOWED_PATHS`); **废除「所有现存盘符」全盘放开**——各盘只有落在用户主目录/项目根/授权目录内的路径才允许;
- **使用规则**: 白名单内**读/写/删都容许**(删受 R3-R6 约束); **递归删除(删目录树)需用户授权**;
- **代码逻辑用途**: `validate_tool_path()` 对白名单内路径判定放行。

**3.2.8 黑名单(禁区)——完整目录清单与使用规则(判定集合, 按操作分写黑名单/删除黑名单)**

- **目录组成(6类, 按判定方式)**:
  - 第1类 跨平台精确: `/etc/shadow`、`/etc/sudoers`;
  - 第2类 跨平台前缀: `/proc`、`/sys`;
  - 第3类 Windows 精确: `C:\Windows`、`C:\Program Files`、`C:\Program Files (x86)`、`System32\config\SAM`、`System32\config\SYSTEM`、`System32\config\SECURITY`、`System32\config\SOFTWARE`、`System32\config\DEFAULT`;
  - 第4类 Windows 前缀: `System32\config`、`WinSxS`;
  - 第5类 磁盘根: 所有盘根(如 `C:\`、`E:\`);
  - 第6类 代码库根: `F:\OmniAgentAs-repair` 及其子/父级(⑦动态判定, 含 get_code_root)。
- **归属禁区**: 第1-5类 → **系统禁区**; 第6类 → **非系统禁区**(=普通禁区);
- **按操作拆分**(北京老陈 2026-08-10: 黑名单分写/删好处理):
  - **写黑名单**: 命中即拦写——系统禁区写硬拦永不授权(3.2.9), 非系统禁区写需临时授权(3.2.10);
  - **删除黑名单**: 命中即拦删——系统禁区删硬拦、非系统禁区删硬拦, **删一律硬拦永不授权**(3.2.9/3.2.10);
- **判定位置**: 系统禁区 = `tool_constants.FORBIDDEN_PATHS_*` + `_is_forbidden_path` 盘根判定; 非系统禁区 = `_is_forbidden_path` ⑦ 代码库根判定;
- **代码逻辑用途**: `_is_forbidden_path()` 命中即按操作分流——写操作走写黑名单规则, 删除操作走删除黑名单规则。

**3.2.9 系统禁区——目录与使用规则(写黑名单+删除黑名单)**

- **目录组成**: FORBIDDEN_PATHS 常量(系统敏感, 3.2.8 第1-4类) + 所有磁盘根(3.2.8 第5类);
- **使用规则**: 读✅放行(内容敏感性由 contentFilter 兜底); 写❌硬拦; 删❌硬拦; **永不参与临时授权**。

**3.2.10 非系统禁区(=普通禁区)——目录与使用规则(写黑名单+删除黑名单)**

- **目录组成**: 代码库根及其子/父级(3.2.8 第6类, ⑦ `_get_code_root()` 动态判定);
- **使用规则**: 读✅放行; 写⚠️临时授权后放行; 删❌硬拦; 临时授权**仅写可授权**。

**3.2.11 白名单外路径——目录与使用规则(判定集合)**

- **目录组成**: 白名单与禁区之外的路径(如用户主目录/项目根/授权目录之外、非禁区的其他盘路径);
- **使用规则**: 读✅只读工具直接放行(不弹确认); 写/删⚠️弹窗/对话临时授权本次放行, 未授权 blocked(3.3决策⑤)。

**3.2.12 临时授权机制(对应 3.3 决策⑤)**

- 一次一申请 + 支持递归 + per-request 隔离(3.3决策⑤/补A); 操作结束即清除(BUG-E finally);
- 系统禁区永不参与临时授权(写/删均不可); 非系统禁区**仅写可授权**, 删不可;
- 临时授权不写入 `allowed_dirs`(持久授权仍走配置)。

**3.2.13 任务级临时授权(用户下命令提到的目录)**

- **定位**: 用户下命令时在任务文本中提到的目录(如 `D:\我的视频`)**不是独立概念、不是新分区**——它就是一个路径, 落哪区按哪区判定(3.2.14); 它只是触发「临时授权机制(3.2.12)」的**任务级场景**: 用户点名 → 任务期间临时授权;
- **触发流程**: 任务启动(`initialize_run_state`)解析用户任务文本中的路径(`盘符:\...` 模式) → 前端一次性确认清单 → 批量 `grant_temp_auth(recursive=True)` → 任务结束 `clear_temp_auth()` 恢复;
- **读写定义**(按该路径落在三区中的位置判定):
  - 落白名单内(用户主目录/项目根/授权目录) → 本就放行, 无需任务授权(递归删除仍需用户授权);
  - 落白名单外·非禁区 → 读✅ / 写⚠️任务授权 / 删⚠️任务授权;
  - 落非系统禁区(代码库) → 读✅ / 写⚠️任务授权 / 删❌硬拦;
  - 落系统禁区 → 读✅ / 写❌硬拦 / 删❌硬拦, **永不授权**。

**3.2.14 完整判定规则(读/写/删, 文字版)**

- **白名单内**(用户主目录+`/tmp`+`/var/tmp`+项目根+授权目录): 读✅ / 写✅ / 删受 R3-R6 判定, **递归删除需用户授权**;
- **白名单外·非禁区**: 读✅放行 / 写⚠️临时授权 / 删⚠️临时授权(递归);
- **非系统禁区**(代码库及父子级): 读✅放行 / 写⚠️临时授权 / 删❌硬拦;
- **系统禁区**(系统目录/盘根): 读✅放行 / 写❌硬拦 / 删❌硬拦。

**3.2.15 操作类型(mode)判定依据**

- **读**(只读工具, 按 tool_name 集合): listdir/tree/find/grep/readtext/readmedia/read_pdf/read_docx/read_pptx/read_xlsx/stat 等只读操作;
- **删**: delete;
- **写**: 其余路径类工具(compress/extract/move/copy/rename/writetext/download/generate_chart/screen_capture 等)。

### 3.3 授权目录定稿(北京老陈需求 2026-08-09 23:47, 决策项全部确认)

**需求**: 除项目根外, tool 可访问多个「授权目录」, 配置在配置文件中。

**决策项**(全部确认):
| # | 决策项 | 结论 |
|---|--------|------|
| ① | 配置项名称 | `app.allowed_dirs`(列表, 多个授权目录) |
| ② | 与现有白名单关系 | **白名单 = 用户主目录(`Path.home()`) + `/tmp` + `/var/tmp` + 项目根 + 授权目录**; **废除「所有现存盘符」的全盘放开**——各盘只有落在用户主目录/项目根/授权目录内的路径才允许 |
| ③ | 删除判定 R3-R6 | **授权目录等同项目根**: 授权目录内的递归删除走 R4 确认, 不再按「项目根外」误拦 R6 |
| ④ | 项目根与授权目录关系 | **项目根天然在授权内**, 无需重复列入 `allowed_dirs` |
| ⑤ | 白名单外路径 | **写/删必须临时授权才能访问**: 弹窗/对话授权, 您点击允许后本次放行, 未授权则 blocked; **一次一申请**——仅本次操作, 结束即失效不缓存; **支持递归**——授权目录后其子目录树递归操作一并放行 (北京老陈 2026-08-10 裁定); **v1.14 补注: 白名单外「读」直接放行(只读工具), 不再需授权**(3.2.11) |

**配置示例**:
```yaml
app:
  project_root: E:\test_dir
  allowed_dirs:
    - D:/data
    - G:/backup
```

**边界约束**:
- 授权目录**禁止指向代码库根或其子目录/父级**(与 tool 禁区冲突) → 配置校验时拒绝并报错;
- 授权目录可指向任意其他盘符/用户主目录下任意目录(用户显式授权即允许);
- 授权目录**不继承**项目根的自动建目录职责(下载目录/输出目录仍在项目根下, 见 7.8);
- 白名单内 = 用户主目录+`/tmp`+`/var/tmp`+项目根+授权目录, 自动放行;
- **白名单外 = 弹窗/对话临时授权才放行本次**(3.3决策⑤), 未授权一律 blocked。

**审计发现的 2 个既有漏洞**(独立于⑦, 且必须先于⑦修正):

1. **漏洞A: `dest` 目标/输出参数全面漏检**(高危)
   - 8个工具的目标/输出路径参数名是 `dest`(compress/extract/move/copy/rename/generate_chart/download/screen_capture), 全部不在 `_PATH_PARAM_KEYS` 中 → `validate_tool_path` 找不到、不校验 → **dest 可指向任意目录(含代码库根/系统目录)而放行**。
   - 即使不加⑦禁区, 当前白名单机制对 dest 也形同虚设: copy/move 可把文件拷入系统目录或任意盘, compress 可把压缩包输出到任意位置。
   - 修法: `_PATH_PARAM_KEYS` 增加 `"dest"`, 并在 `validate_tool_path` 中对**所有**命中路径参数逐一遍历校验(当前只取第一个命中参数, 见下漏洞B)。

2. **漏洞B: `validate_tool_path` 只校验第一个路径参数**(path_safe_check.py:265-272)
   - 当前逻辑 `for key in _PATH_PARAM_KEYS: real_path = params.get(key); if ...: break` — **只取第一个命中的参数校验, 其余路径参数放行**。
   - 即使补了 `dest`, 若 path 先命中, dest 仍漏检。**必须改为遍历所有命中参数逐一校验**, 任一越权即拒绝。
   - 修法: 遍历 `_PATH_PARAM_KEYS`, 对 params 中出现的每个路径参数都调 `validate_path`, 全部通过才算通过。

**⑦禁区正确实施的前置条件**(缺一不可):
- ⑧ 补 `_PATH_PARAM_KEYS` 加 `dest`(漏洞A)
- ⑨ `validate_tool_path` 改为多路径参数全量校验(漏洞B)
- ⑦ `_is_forbidden_path` 新增代码库根及其父级→forbidden(本义)
- ⑦ 经 ⑧⑨ 覆盖后, 才真正封死代码库根的一切 read/write/delete/浏览

### 7.8 授权目录与白名单外临时授权设计(北京老陈需求 2026-08-09 23:47 + 2026-08-10 00:18, 决策项确认见 3.3)

**目标**: 除项目根外, tool 可访问多个「授权目录」; 白名单=主目录+`/tmp`+`/var/tmp`+项目根+授权目录; 白名单外路径经弹窗/对话临时授权本次放行; 项目根定义不变(有配置用配置值, 无配置用用户主目录)。

**配置格式**(config.yaml):
```yaml
app:
  project_root: E:\test_dir
  allowed_dirs:
    - D:/data
    - G:/backup
```

**实现要点**:
1. **config 新增 `get_allowed_dirs()`**(修改⑩):
   - 读 `app.allowed_dirs`, 返回 `List[str]`;
   - 空/未配置 → 返回空列表(不报错, 白名单=主目录+`/tmp`+`/var/tmp`+项目根);
   - **校验: 任一授权目录是代码库根或其父/子级 → 抛 ValueError 拒绝加载**(与⑦禁区冲突, 防止授权目录变相开放代码库);
   - 授权目录存在性: 不强制存在(可在运行期创建), 但不存在时不自动创建(与项目根下载/输出目录自动创建区分)。

2. **白名单设定**(修改⑪, `path_safe_check.py:90`):
   - `ALLOWED_PATHS = [Path.home(), Path("/tmp"), Path("/var/tmp")] + [Path(project_root)] + [Path(d) for d in get_allowed_dirs()]`;
   - **废除**「所有现存盘符」的全盘放开: `get_default_allowed_paths()` 不再拼接 `get_existing_drives()`;
   - 效果: 各盘只有落在主目录/项目根/授权目录内的路径才允许, 其余盘位置拒绝。

3. **删除判定多授权域**(修改⑫, `delete_safety.py:51`):
   - `allowed_roots = [Path(project_root)] + [Path(d) for d in get_allowed_dirs()]`;
   - 目标在任一 allowed_roots 内 → R3-R5 正常流程, 递归走 R4 确认;
   - 目标在全部 allowed_roots 外 → R6 拒绝(递归)或按 R5 判定;
   - **授权目录等同项目根**: 授权目录内的递归删除不再被误判 R6。

4. **`_guard_forbidden_delete`(delete_file.py:56/94)同步扩展**:
   - 保护对象从「项目根」扩展为「项目根+授权目录」: 禁止删除任一授权根自身及其父级祖先(与⑦禁区配合, 代码库根由⑦承接)。

5. **白名单外临时授权**(修改⑮, 北京老陈 2026-08-10 裁定, **一次一申请, 支持递归**):
   - **原则**: 白名单(主目录+tmp+项目根+授权目录)外路径**默认拒绝**, 必须**弹窗/对话授权**后才放行**本次申请的那一次操作**;
   - 交互: tool 要访问白名单外路径 → 安全检查 blocked + 前端弹授权框(显示路径+操作) → 用户点击允许 → **本次**放行; 拒绝/超时 → blocked;
   - **一次一申请(老陈裁定)**: 授权**仅针对本次申请的精确路径**, 本次操作结束后即失效; 再次访问/其他操作必须重新申请, 不缓存复用;
   - **支持递归(老陈裁定)**: 授权某目录后, **其整个子目录树的递归操作在该授权范围内**(如整体复制/删除/打包该目录树可一并授权, 不需逐目录重复申请);
   - 实现: `validate_path` 白名单未命中时, 若本次操作已被用户允许(临时一次性标记, 含递归范围) 则放行, 否则返回需授权信号(前端弹框);
   - **代码库根(⑦)不参与临时授权**: tool 禁区不受任何授权影响, 永久封锁, 即使弹窗也不能开(硬拦截, 与 R1/R2 同级);
   - 临时授权**不写入 `allowed_dirs`**(持久授权仍走配置)。

**与现有机制的边界**:
- 下载目录/输出目录仍在项目根下(`project_root/download`、`project_root/output`), 不受授权目录影响(授权目录不承接自动建目录职责);
- 授权目录仅影响**路径白名单与删除判定**, 不改变项目根定义、不改变配置定位(config.yaml 仍在代码库根);
- 授权目录与项目根可重叠(重复配置无副作用, 去重即可);
- 临时授权**不覆盖** R1/R2/R3-R6 与⑦禁区(仅跳过白名单范围检查, 危险操作确认流程仍走安全层)。

**回归用例**(实施后必测):
- 白名单: 授权目录内操作 → 放行; 项目根内操作 → 放行; 主目录内操作 → 放行(保留); 未授权盘位置(如 `D:\娱乐\视频`) → 默认 blocked(废除全盘放开);
- 临时授权: 对 `D:\娱乐\视频` 弹窗点允许 → 本次放行; 未点/拒绝 → blocked;
- 禁区: `F:\OmniAgentAs-repair\*` 即使弹窗授权也 → blocked(⑦ 硬拦截, 不受临时授权影响);
- 删除: 授权目录内递归删除 → R4 确认; 授权目录外递归删除 → R6 拒绝;
- 禁区冲突: `allowed_dirs` 含代码库根 → 配置加载报错;
- 配置缺省: 无 `app.allowed_dirs` → 白名单=主目录+`/tmp`+`/var/tmp`+项目根。

### 7.9 禁区分级 + 读放行 + 任务目录临时授权设计(北京老陈 2026-08-10 08:25 裁定, v1.13 新增, **待三堂会审/实施**)

> **背景**: 北京老陈 2026-08-10 提出——①任务信息中提到的目录应作为临时授权可访问; ②禁区内**读取**应放行, **删除**绝不可; ③禁区按性质分两类。据此对 7.8「禁区全操作硬拦」模型做分级重构。

**7.9.1 禁区分级(两类, 老陈裁定)**

| 禁区类别 | 内容 | 读 | 写 | 删 |
|---|---|---|---|---|
| **系统禁区** | `C:\Windows`、`C:\Program Files`、`C:\Program Files (x86)`、`System32\config`(含 SAM/SYSTEM/SECURITY/SOFTWARE/DEFAULT)、`WinSxS`、`/etc/shadow`、`/etc/sudoers`、`/proc`、`/sys`、**所有磁盘根**(盘根写删高危, 安全优先归此类) | ✅ 放行 | ❌ 硬拦 | ❌ 硬拦 |
| **非系统禁区** | 代码库根 `F:\OmniAgentAs-repair` 及其子/父级(⑦) | ✅ 放行 | ⚠️ 临时授权后放行 | ❌ 硬拦 |

> 与 7.8「⑦ 代码库根永久封锁、不参与临时授权」的差异: 新规下非系统禁区(代码库)**读放行、删硬拦、写可临时授权**; 系统禁区仍不参与任何授权(写删永久封锁)。

**7.9.2 只读放行(第一层)**: 只读工具(list/read/search/stat/file_tree 等, 按 tool_name 集合判定)操作白名单外**非禁区**路径 → 直接放行, 不触发确认。理由: 只读不改数据, `_is_forbidden_path`(禁区)仍硬拦, 风险仅内容敏感 → contentFilter 兜底。此层解决 LLM 读取卡确认最常见阻塞。

**7.9.3 任务目录临时授权(第二层)**: 任务启动时解析用户任务文本中的路径(`盘符:\...` 模式) → 前端一次性展示确认目录清单 → 全部 `grant_temp_auth`(recursive=True) → 任务结束 `clear_temp_auth`。授权后任务目录内读/写/删顺滑执行(删仍受 R3-R6 判定)。与 7.8-5 临时授权一致: 一次一申请、支持递归、per-request 隔离。

**7.9.4 Prompt 告知(第三层) — 经评估可省(YAGNI)**: 二层任务目录授权为**递归**(recursive=True), 子目录树变体全覆盖; 一层读全放行; 写/删确认流兜底 → LLM 无需额外被告知任务目录, 单独注入 `【任务目录】` 属过度设计, 不实施。(已实施的 7.9 前置: `_get_project_root_info`/`_get_environment_info` 注入授权目录与项目根同源, 2026-08-10)

**7.9.5 完整判定矩阵**

| 目标路径 | 读 | 写 | 删 |
|---|---|---|---|
| 白名单内(主目录+tmp+项目根+授权目录) | ✅ | ✅ | R3-R6 判定 |
| 白名单外·非禁区 | ✅ 放行 | ⚠️ 临时授权 | ⚠️ 临时授权(递归) |
| **非系统禁区**(代码库) | ✅ 放行 | ⚠️ 临时授权 | ❌ 硬拦 |
| **系统禁区**(系统目录/盘根) | ✅ 放行 | ❌ 硬拦 | ❌ 硬拦 |

**7.9.6 实现改动清单(待实施)**
