## 四、最终缺陷清单 (5 个真实缺陷)

### BUG-01: read_text_file float参数致切片崩溃 — P1

| 项目 | 内容 |
|------|------|
| **日志** | `read_text_file.py:380` — `slice indices must be integers` (09:07:09 ×2) |
| **代码** | `line_pager.py:69` — `lines[start_idx : start_idx + limit]` |
| **根因** | `readtext(offset=1.5)` 绕过 Pydantic schema，`select_lines` 接收 float → Python slice 崩溃 |
| **影响** | 直接调用或 schema 验证失效时，读文本文件必失败 |
| **验证** | `test_read_text_file_deep.py:160-186` test_bug_11/12 |
| **修复** | 在 `read_text_file.py:270` 前加 `offset = int(offset); limit = int(limit)` 类型强转 |

### BUG-02: http_request headers非dict致ValueError — P1

| 项目 | 内容 |
|------|------|
| **日志** | `http_request.py:343` — `ValueError: dictionary update sequence` (09:05:38) |
| **代码** | `http_request.py:222-223` — `request_headers.update(headers)` |
| **根因** | `coerce_json(headers)` 可能返回 list；`dict.update(list)` 抛 ValueError |
| **影响** | LLM 传 list 类型 headers 时 HTTP 请求必失败 |
| **验证** | 无对应 test，log 路径为 test_httpget_direct 调用 |
| **修复** | `if headers and isinstance(headers, dict): request_headers.update(headers)` |

### BUG-03: database.py 47处 get_conn(无retry)缺少重试 — P0

| 项目 | 内容 |
|------|------|
| **日志** | `database.py:167` — `database is locked` (09:11:16 ×2) |
| **代码** | `database.py:120-159` get_conn (无 retry) vs `get_conn_with_retry` (lines 186-214) |
| **根因** | 47 处调用方使用 `db.get_conn()` (无重试)，包括 task_db.py(8处)、action_handler.py(2处)、storage.py(1处) 等 |
| **影响** | SQLite 并发写入锁死时，操作记录/任务记录/对话历史静默丢失 |
| **验证** | grep 结果: 47 处 `db.get_conn()` vs operation_record.py 3 处 `get_conn_with_retry` |
| **修复** | 将 47 处 `db.get_conn()` 替换为 `db.get_conn_with_retry()` (或统一入口) |

### BUG-04: operation_record.py generator throw 异常传播断裂 — P0

| 项目 | 内容 |
|------|------|
| **日志** | `operation_record.py:156/214` — `generator didn't stop after throw()` (09:11:16 ×2) |

| **修复** | 在 `get_conn_with_retry` 的 except 块中，用 `sys.exc_info()` + `raise` 而非 bare `raise`，或改为 try/finally 确保 generator 清洁退出 |

### 6.1 引证修正说明

v2.0 在 BUG-05 表内将 09:10:46 (ascii 写中文) 归因于 `test_bug_11` 并称"明确 assert is_error"，**引证不实**：

- `test_write_text_file_deep.py:147-158` 的 `test_bug_11_encoding_gbk_content_utf8` 实为 **gbk + emoji**（内容"测试emoji😂"），对应 **09:11:34** 日志，与 ascii 无关。
- 09:10:46 ascii 写中文的真实来源是 `test_twelfth_boundary.py:194-200 test_write_read_ascii_fallback`，写入 `ascii_fail.txt`、`content="中文内容"`、`encoding="ascii"`，**该测试无任何 assert**（注释仅"写回中文应失败或降级"）。
- 结论方向不变：用户强制指定 `encoding="ascii"` 写中文，属显式参数选择，非生产路径缺陷。BUG-05 修复后 `_write_file_atomic` 已自动降级 utf-8（见五、BUG-05 修复落地）。
