## 二、真实代码缺陷（11个）

### 2.1 P0 — 必须修复（3个）

#### BUG-01：write_text_file ASCII编码写中文失败

| 项目 | 内容 |
|------|------|
| **日志** | `write_text_file.py:88` — `'ascii' codec can't encode characters` (09:10:46) |
| **病根** | `_write_file_atomic()` 使用检测到的 `ascii` 编码写入，内容含中文时崩溃 |
| **代码位置** | `write_text_file.py:83-89` — `open(path, mode, encoding=encoding)` |
| **缺陷** | 编码检测返回 `ascii` 后无 fallback 到 `utf-8` 的重试逻辑 |
| **影响** | LLM 写入中文文件必失败 |
| **修复方案** | 捕获 `UnicodeEncodeError` 后重试 `utf-8`，或 `_detect_file_encoding_for_write` 永不返回 `ascii` |

#### BUG-02：write_text_file GBK编码写emoji失败

| 项目 | 内容 |
|------|------|
| **日志** | `write_text_file.py:88` — `'gbk' codec can't encode '\U0001f602'` (09:11:34) |
| **病根** | 同 BUG-01，GBK 不支持 U+FFFF 以上字符（emoji） |
| **代码位置** | `write_text_file.py:83-89` |
| **缺陷** | 编码 fallback 链缺失——GBK 失败后没有尝试 UTF-8 |
| **影响** | LLM 写入含 emoji 的文件必失败 |
| **修复方案** | 同 BUG-01，统一加 UTF-8 重试 |

#### BUG-03：operation_record generator 异常传播断裂

| 项目 | 内容 |
|------|------|
| **日志** | `operation_record.py:214` — `generator didn't stop after throw()` (09:11:16, ×2) |
| **病根** | 异步生成器在 `throw()` 后未正确 `stop()`，导致异常传播链断裂 |
| **代码位置** | `operation_record.py:156` (Phase 1) 和 `:214` (Phase 3) |
| **缺陷** | async generator 的 `throw()` 使用方式有误，或 generator 内部 try/finally 未正确处理 |
| **影响** | DB 锁定时异常无法正常传播，可能导致状态不一致 |
| **修复方案** | 检查 generator 的 `throw()` 调用点，确保 generator 在 throw 后正确 close/stop |

### 2.2 P1 — 应该修复（4个）

#### BUG-04：read_text_file 切片参数类型错误

| 项目 | 内容 |
|------|------|
| **日志** | `read_text_file.py:380` — `slice indices must be integers` (09:07:09, ×2) |
| **病根** | LLM 传入 `offset`/`limit` 为字符串类型，`select_lines()` 做切片时 Python 报错 |
| **代码位置** | `read_text_file.py:316` — `select_lines(lines, offset, limit, tail)` |
| **缺陷** | 入口处缺少 `int()` 强制类型转换 |
| **影响** | LLM 传字符串数字时读文件必失败 |
| **修复方案** | 在入口处加 `offset = int(offset)` / `limit = int(limit)` 类型守护 |

#### BUG-05：http_request headers 类型不校验

| 项目 | 内容 |
|------|------|
| **日志** | `http_request.py:343` — `ValueError: dictionary update sequence` (09:05:38) |
| **病根** | LLM 传入的 `headers` 不是 dict，`request_headers.update(headers)` 崩溃 |
| **代码位置** | `http_request.py:221-223` — `request_headers.update(headers)` |
| **缺陷** | 缺少 `isinstance(headers, dict)` 校验 |
| **影响** | LLM 传非 dict 类型 headers 时 HTTP 请求必失败 |
| **修复方案** | `if headers and isinstance(headers, dict): request_headers.update(headers)` |

#### BUG-06：database is locked 无重试

| 项目 | 内容 |
|------|------|
| **日志** | `database.py:167` — `database is locked` (09:11:16, ×2) |
| **病根** | SQLite 并发写入时锁竞争，当前无重试机制 |
| **代码位置** | `database.py:167` — DB 操作直接抛异常 |
| **缺陷** | `database.py:210` 有重试逻辑（3次×0.5s），但 operation_record.py 的调用路径可能绕过了重试 |
| **影响** | 操作记录/任务记录静默丢失 |
| **修复方案** | 确认所有 DB 写入路径都走重试逻辑；启用 WAL 模式 `PRAGMA journal_mode=WAL` |

#### BUG-07：LLM 调用异常 tuple 属性错误
