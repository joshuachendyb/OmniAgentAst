## 2. 系统架构设计与目录对应关系

### 2.1 理想分层架构

backend/app 的理想分层应为单向依赖结构，上层可调用下层，下层不反向依赖上层：

```
┌─────────────────────────────────────────────────────────────┐
│  API / 接口适配层（Backend-for-Frontend）                    │
│  app/api/v1/                                                │
│  职责：HTTP 路由、请求/响应 DTO、参数校验、协议封装           │
│        （SSE/WS 传输格式、HTTP 状态码、错误码映射）           │
│      │                                                      │
│      ▼                                                      │
│  编排层（ReAct 循环、Agent 状态管理、聊天流编排）             │
│  app/services/agent/  app/services/chat/stream_orchestrator  │
│      │                                                      │
│      ▼                                                      │
│  业务服务层（聊天、任务、LLM、模型、提示词等）                 │
│  app/services/chat/  app/services/task/  app/services/llm/   │
│  app/services/model/  app/services/prompts/                  │
│  app/services/lifecycle/  app/services/monitoring/           │
│      │                                                      │
│      ▼                                                      │
│  安全层（工具执行前检查、操作记录、回滚）                     │
│  app/services/safety/                                        │
│      │                                                      │
│      ▼                                                      │
│  工具层（具体工具实现与注册）                                │
│  app/tools/                                                 │
│      │                                                      │
│      ▼                                                      │
│  公共基础设施层（通用工具、数据库、日志、配置）                │
│  app/utils/  app/db/  app/logger/  app/config.py             │
└─────────────────────────────────────────────────────────────┘
```

## 4. 问题逐一分析、修复方案与三堂会审

### A1. P0 — tools 层与 services 层双向依赖

#### 3.1.1 当前问题

**依赖方向一：tools → services**

大量文件操作工具直接导入 services 层：

```python
# app/tools/file/copy_file.py:36
from app.services.safety import record_operation, execute_with_safety

# app/tools/file/delete_file.py:32
from app.services.safety import record_operation, execute_with_safety

# app/tools/file/write_text_file.py 等同理
```

以及任务上下文：

```python
# app/tools/file/copy_file.py:37
from app.services.task.task_context import get_current_task_id
```

**依赖方向二：services → tools**

安全层路径校验依赖工具注册表：

```python
# app/services/safety/path_safe_check.py:55-63
from app.tools.registry import tool_registry
from app.tools.tool_types import ToolCategory
from app.tools.tool_constants import (
    FILE_OPERATION_TOOLS, SKIP_DIRS, WINDOWS_SYSTEM_DIRS, ...
)
from app.tools.tools_alias_mapper import get_aliases_for_tool

# app/services/safety/tool_safety_checker.py:64
from app.tools.registry import tool_registry
```

#### 3.1.2 病根

- 工具执行需要"被记录"和"被保护"，所以工具直接调用 `record_operation`/`execute_with_safety`；
- 安全校验需要知道"这是哪个工具""参数是什么"，所以 safety 层直接读取 `tool_registry`；
- 双方都把对方当成基础设施，导致层间边界破裂。

#### 3.1.3 修复方案（推荐：依赖注入 + 安全 hook 抽象）

**目标**：让工具层不再直接依赖 services 层，让安全校验在 tools 层内部闭环。

**步骤**：

1. **新建安全 hook 接口** `app/tools/tool_security_hooks.py`（或 `app/tools/toolhelper/security_hooks.py`）：

```python
from typing import Protocol, Callable, Any

class ToolSecurityHooks(Protocol):
    """工具执行前后的安全/记录 hook 接口"""
    async def before_execute(self, tool_name: str, params: dict, task_id: str | None) -> dict:
        """返回可能被修改后的 params，或抛出异常阻止执行"""
        ...

    async def after_execute(
        self,
        tool_name: str,
        params: dict,
        result: dict,
        task_id: str | None,
        operation_meta: dict | None = None,
    ) -> None:
        """记录操作、触发回滚准备等"""
        ...

# 默认空实现，保证不传入 hooks 时工具仍可独立运行
class NoOpSecurityHooks:
    async def before_execute(self, tool_name: str, params: dict, task_id: str | None) -> dict:
        return params
    async def after_execute(self, **kwargs) -> None:
        pass
```

2. **改造 tool_executor.py**，在调用工具时传入 hooks：

```python
# app/services/agent/tool_executor.py
async def execute_tool_with_hooks(
    tool_name: str,
    params: dict,
    hooks: ToolSecurityHooks | None = None,
    task_id: str | None = None,
) -> dict:
    hooks = hooks or NoOpSecurityHooks()
    params = await hooks.before_execute(tool_name, params, task_id)
    result = await _call_tool_impl(tool_name, params)
    await hooks.after_execute(tool_name, params, result, task_id)
    return result
```

3. **在 `app/services/safety/` 中实现 `DefaultToolSecurityHooks`**：

```python
# app/services/safety/default_hooks.py
from app.tools.toolhelper.security_hooks import ToolSecurityHooks
from app.services.safety.operation_record import record_operation
from app.services.task.task_context import get_current_task_id

class DefaultToolSecurityHooks(ToolSecurityHooks):
    async def before_execute(self, tool_name, params, task_id):
        # 原有 execute_with_safety 中的"执行前记录/校验"逻辑迁移至此
        return params

    async def after_execute(self, tool_name, params, result, task_id, operation_meta=None):
        _tid = task_id or get_current_task_id()
        record_operation(tool_name, params=params, result=result, task_id=_tid, **(operation_meta or {}))
```

4. **移除 tools/file/*.py 中对 `app.services.safety` 和 `app.services.task.task_context` 的直接导入**：
   - 删除 `from app.services.safety import record_operation, execute_with_safety`；
   - 删除 `from app.services.task.task_context import get_current_task_id`；
   - 工具函数签名中不再主动记录，改为通过 executor 传入的 hooks 完成。

5. **把 `path_safe_check.py` 迁回 tools 层** `app/tools/security/path_safe_check.py`：
   - 该文件本质是"工具参数层面的路径安全校验"，属于工具层能力；
   - 保留 `validate_path(file_path, mode, tool_name)` 接口不变；
   - 它依赖 `tool_registry` 获取工具分类和参数，这在本层内是合理的（工具层内部闭环）。

6. **`tool_safety_checker.py` 调用新位置的 `path_safe_check`**：

```python
# app/services/safety/tool_safety_checker.py
from app.tools.security.path_safe_check import validate_path, is_temp_authorized
```

此时依赖方向变为：
- `services/safety/tool_safety_checker.py → tools/security/path_safe_check.py`（services → tools，单向）
- `services/agent/tool_executor.py → services/safety/default_hooks.py`（编排层 → 安全层，单向）
- `tools/file/*.py` 不再依赖 services

#### 3.1.4 备选方案（改动较小但不彻底）

仅把 `path_safe_check.py` 从 `services/safety` 迁到 `tools/security`，保留 tools/file/*.py 对 services.safety 的导入。

**缺点**：只解决 services→tools 方向的越层，未解决 tools→services 方向的双向依赖，架构仍不健康。

#### 3.1.5 三思三省

| 维度 | 分析 |
|------|------|
| **可行性** | 高。Python Protocol + 依赖注入机制成熟；已有 `execute_with_safety` 逻辑可直接迁移到 hook 实现。 |
| **风险** | 中。涉及 file 分类下 10+ 个工具文件、tool_executor、action_handler 等核心链路，需全量回归。 |
| **替代方案** | 备选方案改动小但治标不治本；推荐方案虽改动大，但能根治双向依赖。 |
| **是否引入新抽象** | 是，但 `ToolSecurityHooks` 是必要抽象，符合 OCP（后续新增审计、权限等 hook 无需改工具代码）。 |

#### 3.1.6 三堂会审

| 规范 | 审查 | 结论 |
|------|------|------|
| SRP | 工具只负责执行，安全/记录由 hook 处理 | PASS |

```python
# app/services/tool/tool_facade.py
from typing import Any
from app.tools.registry import tool_registry
from app.services.safety.tool_safety_checker import check_tool_safety
from app.services.safety.default_hooks import DefaultToolSecurityHooks
from app.services.agent.tool_executor import execute_tool_with_hooks
from app.services.task.task_context import _current_task_id

async def list_tools() -> dict:
    """供 API 调用的工具列表"""
    tools = tool_registry.to_openai_tools()
    result = []
    for t in tools:
        func = t.get('function', {})
        name = func.get('name', '')
        desc = func.get('description', '')
        params = func.get('parameters', {})
        required = params.get('required', [])
        props = list(params.get('properties', {}).keys())
        required_set = set(required)
        result.append({
            "name": name,
            "description": desc[:100] if desc else "",
            "required_params": required,
            "optional_params": [p for p in props if p not in required_set],
            "inputSchema": params,
        })
    return {"total": len(result), "tools": result}

async def execute_tool(tool_name: str, params: dict) -> dict:
    """供 API 调用的安全工具执行入口"""
    # 1. 安全检查
    safety = await check_tool_safety(tool_name, params)
    if safety.blocked:
        return {"success": False, "error": f"安全拦截: {safety.message}"}

    # 2. 设置任务上下文
    task_id = str(uuid.uuid4())
    _current_task_id.set(task_id)

    # 3. 通过 Agent 编排层的 executor 执行，带上安全 hooks
    hooks = DefaultToolSecurityHooks()
    result = await execute_tool_with_hooks(tool_name, params, hooks=hooks, task_id=task_id)

    return {"success": True, "result": result if isinstance(result, dict) else {"output": str(result)}}
```

#### 3.8.2 病根

- 项目早期把"API 入口"和"入口后的第一个处理函数"写在同一个文件里，随着业务增长没有拆分；

```python
# app/services/chat/stream_orchestrator.py
import asyncio
import time
import uuid
from dataclasses import dataclass
from typing import Optional, AsyncGenerator

from app.services import get_service
from app.services.model.resolver import get_ai_config_resolver
from app.services.chat.handlers import create_error_response, send_start_step
from app.utils.sse_formatter import format_agent_sse
from app.services.agent.agent_runner import run_agent_in_background
from app.services.agent.universal_agent import UniversalAgent
from app.services.agent.steps.final_step import FinalStep
from app.services.task.task_registry import register_task
from app.services.task.task_runtime import (
    task_cancel_check,
    task_pause_check_and_yield,
    task_cancel_check_and_yield,
    create_stream_buffer,
    get_stream_buffer,
)
from app.services.task.task_context import _current_task_id
from app.logger.shared_handler import set_session_id
from app.logger import logger, log_and_print
from app.services.agent.steps.base import create_step_counter
from app.services.chat.storage import get_user_message_id

_agent_tasks: set = set()


# 注：orchestrator 不依赖 api/v1 的 DTO，避免 services 层反向依赖 API 层。
# API 层负责把 ChatRequest 解包为原始参数传入。


def generate_task_id() -> str:
    return f"task-{uuid.uuid4().hex}"


async def validate_chat_config():
    """聊天配置校验 — 从 api/v1/chat/openai.py 迁入 orchestrator"""
    try:
        resolver = get_ai_config_resolver()
        is_valid, final_provider, final_model, error_messages = resolver.validate_config()
        if not is_valid:
            return {
                "valid": False,
                "message": f"配置验证失败: {', '.join(error_messages)}",
                "provider": final_provider or "unknown",
                "model": final_model or "",
            }
        return {
            "valid": True,
            "message": f"配置验证通过: {final_provider} ({final_model})",
            "provider": final_provider,
            "model": final_model,
        }
    except Exception as e:
        logger.error(f"验证AI服务配置失败: {e}")
        return {
            "valid": False,
            "message": f"验证失败: {str(e)}",
            "provider": "unknown",
            "model": "",
        }


@dataclass
class StreamState:
    llm_call_count: int = 0
    current_content: str = ""
    current_thought: str = ""
    step_events: list = None

    def __post_init__(self):
        if self.step_events is None:
            self.step_events = []


async def chat_stream_orchestrator(
    messages: list,
    session_id: Optional[str] = None,
) -> AsyncGenerator[str, None]:
    """聊天流编排入口：负责任务生命周期、Agent 启动、SSE 消费。"""
    if not messages:
        yield create_error_response(error_type="invalid_request", error_message="消息列表不能为空")
        return

    user_input = messages[-1].content or ""
    if not user_input.strip():
        yield create_error_response(error_type="invalid_request", error_message="消息内容不能为空")
        return

    ai_service = get_service()
    session_id = session_id or str(uuid.uuid4())
    _model_warning = get_ai_config_resolver().pop_model_warning()

    task_id = generate_task_id()
    _current_task_id.set(task_id)
    set_session_id(session_id)
    next_step = create_step_counter()
    execution_steps = []
    state = StreamState()

    # Task 生命周期日志
    _task_start_time = time.time()
    _user_msg_id = None
    try:
        _user_msg_id = get_user_message_id(session_id)
    except Exception:
        logger.warning(f"[chat] 获取user_message_id失败: session_id={session_id}")
    log_and_print(f"INFO: {time.strftime('%Y-%m-%d %H:%M:%S')}")
    log_and_print(
        f"[TASK_START] provider={ai_service.provider} model={ai_service.model} |\n "
        f"task_id={task_id} session_id={session_id} "
        f"user_message_id={_user_msg_id} |\n "
        f"user_input={user_input}"
    )

    try:
        buffer = create_stream_buffer(task_id)
        await register_task(task_id, ai_service)

        is_cancelled, cancel_msg = await task_cancel_check(task_id)
        if is_cancelled:
            yield cancel_msg
            return

        async for event in _step_start(
            ai_service, task_id, next_step, user_input, execution_steps, session_id, warning=_model_warning
        ):
            yield event

        if _model_warning:
            _final = FinalStep(
                step=next_step(), response="",
                outcome="failed",
                error_type="config_error",
                error_message=_model_warning,
                model=ai_service.model, provider=ai_service.provider,
                display_name=f"{ai_service.provider} ({ai_service.model})",
            )
            yield format_agent_sse(_final.to_dict())
            return

        agent = UniversalAgent(llm_client=ai_service, task_id=task_id)
        bg_task = asyncio.create_task(run_agent_in_background(
            agent, task_id, user_input, None, next_step, session_id, state, _task_start_time))
        _agent_tasks.add(bg_task)
        bg_task.add_done_callback(_agent_tasks.discard)

        async for sse_chunk in _stream_with_control(
            buffer, task_id, next_step, session_id, execution_steps, state
        ):
            yield sse_chunk
    except asyncio.CancelledError:
        logger.info(f"[chat_stream_orchestrator] 客户端断开(task={task_id})，agent 后台继续")
        return
    except Exception as e:
        logger.error(f"[chat_stream_orchestrator] Error: {e}", exc_info=True)
        yield create_error_response(error_type="orchestrator_error", error_message=f"编排异常: {str(e)}")


async def _step_start(ai_service, task_id, next_step, user_input, execution_steps, session_id, warning=None):
    """发送 start 步骤"""
    try:
        start_step = await send_start_step(
            ai_service=ai_service, task_id=task_id, next_step=next_step,
            user_message=user_input, security_check_result={}, warning=warning,
        )
        start_dict = start_step.to_dict()
        execution_steps.append(start_dict)
        yield format_agent_sse(start_dict)
    except Exception as e:
        yield create_error_response(error_type="start_failed", error_message=f"start步骤失败: {e}")


async def _stream_with_control(buffer, task_id, next_step, session_id, execution_steps, state=None, after_seq: int = 0):
    """SSE 消费者包装"""
    from app.services.chat.stream import stream_reader
    async for sse_chunk in stream_reader(buffer, task_id, after_seq):
        async for pause_event in task_pause_check_and_yield(task_id, next_step):
            yield pause_event
        cancelled_sse = await task_cancel_check_and_yield(
            task_id, next_step, session_id, execution_steps,
            state.current_content if state else "")
        if cancelled_sse:
            yield cancelled_sse
            return
        yield sse_chunk


async def chat_stream_reconnect_orchestrator(
    task_id: str, session_id: Optional[str] = None, after_seq: int = 0
) -> AsyncGenerator[str, None]:
    """SSE 重连编排"""
    buffer = get_stream_buffer(task_id)
    if not buffer:
        yield create_error_response(error_type="not_found", error_message="任务不存在或已结束")
        return
    next_step = create_step_counter()
    async for sse_chunk in _stream_with_control(
        buffer, task_id, next_step, session_id or "", [], None, after_seq
    ):
        yield sse_chunk
```
