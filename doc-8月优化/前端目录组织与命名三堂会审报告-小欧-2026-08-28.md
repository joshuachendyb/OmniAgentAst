## 二、第一轮 合规检查（10大规范 + 文档铁规）

| 规范 | 判定 | 实证 |
|------|------|------|
| **SRP 单一职责** | ❌ 违反 | `utils/sse.ts` 1837行 混 连接管理/重连/空闲超时/步骤解析/存储/渲染回调；`utils/errorHandler.ts` 1196行 混 分类/展示/重试/SSE错误/API错误/特殊场景；`services/api.ts` 1123行 多端点聚合 |
| **DRY 不重复** | ⚠️ 局部违反 | `utils/formatSafeTimestamp.ts:3-10` 自实现 `new Date(s)` 解析，未复用 `utils/timestamp.ts:72` 已导出的 `parseTimeSafe`；前端无 `FUNCTIONS.md` 共享清单（后端有），存在重复造轮风险 |
| **KISS-DIRECT** | ❌ 违反 | `utils/errorHandler.ts:28` `import * as ErrorHandlerSelf from './errorHandler'` 自引用仅为测试 `vi.spyOn` 可观测——非直线、加间接层 |
| **SLAP 同抽象层** | ⚠️ 部分违反 | `utils/sse.ts:712` 高层编排循环内直接 `reader.read()`/`decoder.decode()` 字节级操作，抽象层混杂 |
| **YAGNI** | ✅ 未见**明显** | 无显著过度设计/预留抽象 |
| **禁止backward** | ✅ 遵守 | 未见向后兼容垫片 |
| **OCP/LSP/ISP** | ✅ 结构层未见**明显** | 框架级，需深读确认 |
| **复用优先** | ❌ 违反 | 同 DRY：缺前端 `FUNCTIONS.md`，"先查后建"无落地载体 |
| **文档铁规·kebab-case 文件名** | ❌ 文档与现实冲突 | 全库 PascalCase(组件)/camelCase(utils)，与 AGENTS "kebab-case" 冲突 |
| **文档铁规·组件无默认导出** | ❌ 文档与现实冲突 | 31 文件（含全部组件）用 `export default`（如 `NewChatContainer.tsx:700`、`App.tsx:90`） |
| **文档铁规·`@/` 别名** | ⚠️ 不一致 | `hooks/chat/useChatStreaming.ts:29-34` 用 `../../` 深层相对路径，别名已配(tsconfig `paths."@/*"`)却未统一使用 |

## 三、第二轮 合理检查（组织合理性）

- ✅ 顶层分层清晰：`components/ hooks/ utils/ services/ pages/ contexts/ types/ theme/ tests/`
- ✅ `hooks/chat/` 11 个 hook 按域组织；`components/Chat/` 虽 40+ 文件但已分子目录（input/layout/left/right/pipeline/renderers/taskinfo/topbar/config/constants）
- ⚠️ `components/Chat/` 体量过大（神文件夹），可进一步按"消息/任务/工具栏/顶栏"聚合（非错误，可优化）
- ⚠️ 神模块：`sse.ts`/`errorHandler.ts`/`api.ts` 单体过大，按职责拆分建议（见第六节）
- ⚠️ **时间类 3 文件应合并**：`timestamp.ts`(formatTimestamp+parseTimeSafe) / `timeFormatters.ts`(formatTime+formatRelativeTime, 已复用 parseTimeSafe) / `formatSafeTimestamp.ts`(独立重实现解析) → 建议合并为单一 `time.ts`，`formatSafeTimestamp` 改调 `parseTimeSafe`
- ⚠️ **命名失真**：`utils/chatLogger.ts` 实为 `console.log` 样式常量(`LOG_STYLES`)，非"日志器" → 应改名 `logStyles.ts`；`components/Chat/pipeline/steps.ts` 是分流工具(`META_STEP_TYPES`+过滤) → 应改名 `stepFilter.ts` 以名符其实

## 四、第三轮 关联逻辑检查（导入图谱实证，核心发现）

### 4.1 `sse.ts` 既是 hook 又是全局类型源（层破坏·高）
- **值依赖**：`hooks/chat/useChatStreaming.ts:31,136`（`useSSE`）
- **类型依赖（≥7 处从 `utils/sse` 导入类型）**：
  - `TaskInfoBar.tsx:20` `TaskMetaFrames`
  - `StatusLine.tsx:15` `ExecutionStep`
  - `useChatCallbacks.ts:39` `SSEError, SSEMetadata`
  - `useTaskInfo.ts:23` `TaskMetaFrames`
  - `useChatState.ts:24` `ExecutionStep`
  - `types/chat/groups.ts:16` `ExecutionStep`
  - `useChatStreaming.ts:79` 动态 `import('../../utils/sse').TaskMetaFrames`
- **类型归属混乱实证**：`types/execution.ts:1-7` 明确记载"`ExecutionStep` 已从 `utils/sse.ts` 抽至本文件以断类型环"，但 `StatusLine.tsx:15`/`useChatState.ts:24`/`groups.ts:16` **仍从 `utils/sse` 导入 `ExecutionStep`** → `sse.ts` 仍充当事实类型源，层被破坏（utils 不应是类型权威，types/ 才是）

### 4.2 `formatSafeTimestamp` 重复解析（DRY·关联）
- 被 `ErrorDetail.tsx:7,274` 引用；其 `new Date(s)` 解析与 `timestamp.ts:72 parseTimeSafe` 重复，应改为 `import { parseTimeSafe } from './timestamp'`

### 4.3 `sessionStorage` 反向依赖 `chatHistory`（耦合方向）
- `utils/sessionStorage.ts:2` `import { STORAGE_KEY } from './chatHistory'` → 存储层依赖历史层，方向不佳，二者宜合并或共置

### 4.4 错位文件搬迁影响面（改名/移动成本）
| 文件 | 现状 | 目标 | 影响面 |
|------|------|------|--------|
| `utils/sse.ts` | hook 在 utils + 名 `sse` | `hooks/useSSE.ts` | 需改 ≥8 处 import（含 3 处 type-only `ExecutionStep/SSEError/SSEMetadata/TaskMetaFrames`），并清类型归属 |
| `utils/antdAppBridge.tsx` | 组件在 utils | `components/AntdAppBridge.tsx` | 改 `App.tsx:22` |
| `utils/markdown.tsx` | 渲染器在 utils | `components/renderers/` | 需查其引用点统一 |
| `utils/chatLogger.ts` | 名失真 | `utils/logStyles.ts` | 改所有 `chatLogger` 引用 |

## 五、三堂会审结论（回答三个问题，附可信度）

- **Q1 有错误放置吗？** → **有，且比首轮更确凿**：
  - 🔴 高：`utils/sse.ts` 既错位（应为 `hooks/`）又错名（应为 `useSSE.ts`），且同时是全局类型源→层破坏（实证 4.1）
  - 🔴 高（关联）：`ExecutionStep` 类型归属混乱，3 处仍从 `utils/sse` 导入
  - 🟡 低：`antdAppBridge.tsx`/`markdown.tsx` 组件在 utils
  - 🟢 轻微：`chatLogger.ts`/`steps.ts` 命名失真
- **Q2 组织合理吗？** → **大体合理，2 处神模块 + 1 神文件夹可优化**（实证第三节）；时间类 3 文件、chatLogger 命名属可优化非错误
- **Q3 守 10 大规范吗？** → **未完全遵守**：SRP(神模块)❌、KISS(自引用)❌、DRY(局部)⚠️、复用优先❌；YAGNI/禁止backward 遵守

> 可信度声明：本轮所有结论均来自**实读文件内容 + 导入图谱 grep**，非仅看文件名；首轮"仅看文件名"的浅审已升级为上述实证审查。

## 六、整改建议（按 ROI 分级）
1. **🔴 必做（高价值·中风险）**：`utils/sse.ts` → `hooks/useSSE.ts`；同步将 `ExecutionStep` 等类型统一改从 `types/execution.ts` 导入（清 4.1 层破坏）；更新 ≥8 处引用

4. **🟢 规范补齐**：建 `frontend/FUNCTIONS.md` 落实"复用优先/先查后建"
5. **⚠️ 可选大改**：`sse.ts`/`errorHandler.ts`/`api.ts` 按职责拆分（SRP），单独排期
