## 一、方法论、范围与重构铁规（先定尺子，再实检）

### 1.1 三轮方法论
- **三轮**：① 合规检查（10大规范 + AGENTS 文档铁规）② 合理检查（SRP/KISS/组织合理性）③ 关联逻辑检查（导入图谱/类型归属/耦合方向/改名影响面）
- **可信度纪律**：每条结论均附 `文件:行号` 实证，不凭文件名拍脑袋

### 1.2 范围
- `frontend/src` 共 142 个 .ts/.tsx（含 tests/）

### 1.3 重构铁规（日常6+重构4+拆分纪律，先摆尺子）
| 类别 | 规则 | 约定 | 违反后果 |
|------|------|------|----------|
| **日常6条** | **SRP** 单一职责 | 一个类/模块/函数只做一件事 | 改了 A 影响 B |
| | **DRY** 不重复 | 相同逻辑只写一次，抽取共用 | 改了 A 漏了 B |
| | **KISS-DIRECT** 简单直接 | 设计简单+逻辑直线，不提前引入抽象，不七绕八绕 | 代码看不懂、数据流混乱 |
| | **SLAP** 同一抽象层 | 一个函数不混搭高层编排和底层细节 | 读代码像天书 |
| | **YAGNI** 不要过度设计 | 不加用不上的接口/模式/抽象 | 废弃代码越积越多 |
| | **禁止backward** | 所有代码修改/更新/重构坚决杜绝向后兼容做法 | 新旧混杂、代码混乱 |
| **重构4条** | **OCP** 开闭原则 | 对扩展开放，对修改封闭 | 库/框架/公共组件难扩展 |
| | **LSP** 里氏替换 | 子类不违反父类约定 | 继承体系崩 |
| | **ISP** 接口隔离 | 接口职责单一，不塞入不相关方法 | 多实现/插件系统臃肿 |
| | **复用优先** | 有公用则复用，能够公用的则新建并入库；新增函数前必须先查 `FRONTEND_FUNCTIONS.md`（前端）/`FUNCTIONS.md`（后端），禁止局部重造轮子 | 重复造轮子 |
| **拆分纪律** | **能复制就复制，不重写** | 拆分大文件/函数时最安全的做法是**复制原代码逻辑，只改导入路径，不改业务逻辑**。重写会引入新错误，复制能保证行为不变 | 重构造新 bug、已修问题丢失 |

## 六、合理架构（四层+一横切）重构方案

> 本章按"四层+一横切"定义本项目目标架构，**逐层补全职责/目录/命名/依赖/禁止事项/现状→目标映射**，并与二～四章所有错位/神模块问题一一对齐；第七章整改按此分层分阶段落地。

### 6.0 总览
- **设计原则**：页面薄、特性厚、共享精、基础纯、横切稳；**特性间不互引、基础层不向上依赖、横切被所有层依赖**
- **本项目痛点**：缺"特性层"致 `components/Chat/` 40+ 神文件夹 + `utils/sse.ts` 三合一跨层；`services/api.ts` 6域 God（health/chat/config/session/task + 共享 client）；时间/存储碎片化
- **目标**：新建 `features/` 收敛聊天/会话/设置三域；`utils/` 回归纯函数；`services/api/` 按域拆分；`types/constants/theme` 横切稳固

### 6.1 页面层 `pages/` — 只做路由装配（<100行，不写业务）
- **职责**：路由声明 + 布局装配 + 特性层/共享层组合；禁止任何业务 `useState/useEffect`、禁止直接 `import {sessionApi} from '@/services/api'`
- **目录**：
```

├── ChatPage.tsx          # 由 NewChatContainer.tsx:1-700 瘦身而来，仅 <100行：useChatFacade + SessionLayout + 特性hooks
├── History/index.tsx     # 保留
└── Settings/index.tsx    # 保留
```
- **命名**：`PascalCase` 页面组件（`ChatPage`），`index.tsx` 仅用于 barrel
- **依赖**：可依赖 `features/*`、`components/`、`hooks/`、`types/`；**禁止依赖 `utils/` 业务实现**
- **本项目现状问题**：`components/Chat/NewChatContainer.tsx:50-700` 承担 7 域（授权/滚动/持久化/会话元数据/任务选择/面板工厂），`16 useEffect` 超标，严重违反 SRP/SLAP
- **目标形态示例**（`ChatPage.tsx` <100行）：

### 6.3 共享层 `components/ hooks/ services/` — 跨域复用
- **职责**：被 ≥2 特性/页面复用的通用能力
- **目录与本项目落点**：

- **命名**：共享组件 `PascalCase`，hook `use*`，服务 `*.api.ts`/`*.service.ts`
- **依赖**：可依赖基础层、横切；**禁止依赖特性层/页面层**（只能被上层依赖）
- **现状问题映射**：`services/api.ts` 6域 God（health/chat/config/session/task + 共享 client）→ 拆 `client.ts`/`health.api.ts`/`chat.api.ts`/`config.api.ts`/`session.api.ts`/`task.api.ts`；`utils/errorHandler.ts` 基础层越界 → 迁 `services/error/`

#### 7.4.1 `utils/time.ts` — 合并新建（统一 5 份时间格式化，复用 `parseTimeSafe`）
```ts
// 编辑历史: 2026-08-28 小欧 - 合并 timestamp/timeFormatters/formatSafeTimestamp+组件内formatTime为单一源
import { parseTimeSafe } from './timestamp'; // 保留 parseTimeSafe 定义在 time.ts 内，或直接内联如下

export const parseTimeSafe = (input: Date | string | number): Date | null => {
  try {
    const d = input instanceof Date ? input : new Date(input);
    return isNaN(d.getTime()) ? null : d;
  } catch { return null; }
};

export const formatTimestamp = (ts: number | string | undefined): string => {
  if (ts === undefined || ts === null || ts === '') return '';
  const d = parseTimeSafe(ts as string | number | Date);
  if (!d) return '';
  return `${d.getFullYear()}-${String(d.getMonth()+1).padStart(2,'0')}-${String(d.getDate()).padStart(2,'0')} ${String(d.getHours()).padStart(2,'0')}:${String(d.getMinutes()).padStart(2,'0')}:${String(d.getSeconds()).padStart(2,'0')}.${String(d.getMilliseconds()).padStart(3,'0')}`;
};

export const formatTime = (date: Date | string | number): string => {
  const d = parseTimeSafe(date);
  if (!d) return '';
  return d.toLocaleTimeString('zh-CN', { hour: '2-digit', minute: '2-digit' });
};

export const formatRelativeTime = (date: Date | string | number): string => {
  const d = parseTimeSafe(date);
  if (!d) return '';
  const diff = Date.now() - d.getTime();
  if (diff < 0) return d.toLocaleDateString('zh-CN');
  const m = Math.floor(diff / 60000);
  if (m < 1) return '刚刚';
  if (m < 60) return `${m}分钟前`;
  const h = Math.floor(m / 60);
  if (h < 24) return `${h}小时前`;
  return d.toLocaleDateString('zh-CN');
};

export const formatSafeTimestamp = (s?: string | number | Date): string => {
  if (s == null) return '';
  const d = parseTimeSafe(s as string | number | Date);
  return d ? d.toLocaleString('zh-CN') : '';
};

export const formatDate = (s?: string | number | Date): string => {
  const d = s == null ? null : parseTimeSafe(s as string | number | Date);
  return d ? `${d.getMonth()+1}/${d.getDate()} ${String(d.getHours()).padStart(2,'0')}:${String(d.getMinutes()).padStart(2,'0')}` : '-';
};
```

## 八、重构铁规及本次三堂会审合规性自检

### 8.1 重构铁规（日常6+重构4+拆分纪律）

| 类别 | 规则 | 约定 | 违反后果 |
|------|------|------|----------|
| **日常6条** | **SRP** 单一职责 | 一个类/模块/函数只做一件事 | 改了 A 影响 B |
| | **DRY** 不重复 | 相同逻辑只写一次，抽取共用 | 改了 A 漏了 B |
| | **KISS-DIRECT** 简单直接 | 设计简单+逻辑直线，不提前引入抽象，不七绕八绕 | 代码看不懂、数据流混乱 |
| | **SLAP** 同一抽象层 | 一个函数不混搭高层编排和底层细节 | 读代码像天书 |
| | **YAGNI** 不要过度设计 | 不加用不上的接口/模式/抽象 | 废弃代码越积越多 |
| | **禁止backward** | 所有代码修改/更新/重构坚决杜绝向后兼容做法 | 新旧混杂、代码混乱 |
| **重构4条** | **OCP** 开闭原则 | 对扩展开放，对修改封闭 | 库/框架/公共组件难扩展 |
| | **LSP** 里氏替换 | 子类不违反父类约定 | 继承体系崩 |
| | **ISP** 接口隔离 | 接口职责单一，不塞入不相关方法 | 多实现/插件系统臃肿 |
| | **复用优先** | 有公用则复用，能够公用的则新建并入库；新增函数前必须先查 `FRONTEND_FUNCTIONS.md`（前端）/`FUNCTIONS.md`（后端），禁止局部重造轮子 | 重复造轮子 |
| **拆分纪律** | **能复制就复制，不重写** | 拆分大文件/函数时最安全的做法是**复制原代码逻辑，只改导入路径，不改业务逻辑**。重写会引入新错误，复制能保证行为不变 | 重构造新 bug、已修问题丢失 |
