### 2.1 P01 — execute_sql 危险 DDL 拦截

**核实结论：准确（有意安全设计）；仅剩一处"略严"可优化**

**更新历史**（`execute_sql.py:4-14`）：
- 2026-07-23 `#6 fix`：豁免从"仅 CREATE INDEX/VIEW IF NOT EXISTS"扩展为 **INDEX / TRIGGER / TEMP TABLE（有 IF NOT EXISTS）/ UNIQUE INDEX / DROP·VIEW·INDEX·TRIGGER IF EXISTS**，并修 `_AFFECTED_ROWS_LIMIT` 常量 DRY（原约 **60% 误拦**）。
- 2026-07-31 Bug①：剥离注释/字符串内关键字防绕过。

**测试证据**（`tests/tools/param_combination/test_execute_sql.py`）：
- L142-149 `test_create_and_drop_table`：裸 `CREATE TABLE` / `DROP TABLE` → warning 拦截。
- L351-384：`CREATE INDEX`/`CREATE TRIGGER`/`TEMP TABLE IF NOT EXISTS`/`UNIQUE INDEX`/`DROP ... IF EXISTS` 均豁免通过。
- L82-88 `test_create_table`：`dry_run=True` 预演成功（`syntax_valid=True`，不实际建表）。

**"过于严格"分析**：豁免已很充分。唯一未豁免的是**裸 `CREATE TABLE` / `DROP TABLE`（无 IF EXISTS）**，这正是危险操作，保留拦截合理。但若业务需频繁建"分析用临时表"，可考虑加 `CREATE TABLE ... (临时路径)` 显式确认放行——**属可优化项，非缺陷**。

**"临时建表"定义澄清（v2.1）**：切勿以"临时"这种模糊语义放开 DDL。正确做法是**加显式标识**，如 execute_sql 新增 `confirm_ddl: bool = False` 参数：用户显式传 `confirm_ddl=true` + 明确意图时才放行裸 CREATE/DROP，且仍记录日志供审计。其余（带 IF NOT EXISTS 的 CREATE、dry_run 预演）已有逃生通道，无需放开。

**判定**：安全设计合理，非缺陷。

### 2.4 P04 — write_xlsx 覆盖而非追加

**核实结论：准确（明确语义设计）；"追加"为新功能需求**

- 代码位置：`write_xlsx.py:166` `Workbook()` 新建 + `:187` `wb.save(path)`，从不加载已有文件 → 整篇覆盖，无追加/merge。
- **"追加"是否合理**：追加到已有 xlsx 表确为真实业务场景，但**这是新功能需求**（增量写入/合并），与"整篇生成报表"的现语义不同。若要支持，应新增 append 参数或独立工具（openpyxl `load_workbook` + 追加行），**默认保持覆盖不变**。

**判定**：覆盖为明确设计语义，非缺陷。追加为新功能，按需立项。

**追加设计评估（v2.1）**：追加需要**中等复杂度参数处理**，不简单：
- 需 `load_workbook`（保留格式/多 sheet）+ 定位目标 sheet + `append` 行 + 表头对齐。
- **关键风险**：新 data 的列名与已有表头不一致（需补齐/忽略策略）、sheet 不存在、重复写表头。
- **建议**：新增 `append_mode: bool = False`（默认 False 保持覆盖语义，不破坏现有行为）；append=True 走 load_workbook 追加；并做**表头一致性校验**，不一致时返回 warning 而非静默错乱。属可行但需谨慎默认值。

### 2.7 P07 — read_xlsx 将 CSV 降级为 readtext

**核实结论：v2.1 最终判定——真实存在的工具分流缺陷（tool 名自动改写导致）**

**两层真相**：
1. **read_xlsx 内部确实支持 CSV 结构化读取**：
   - `read_xlsx.py:205` `.csv` → `_read_csv_stdlib_inner`（L136-173）：标准库 `csv.reader` 结构化解析，返回 `{"headers","rows","row_count"}`。
   - observation_formatter #25 `_format_xlsx_result`（L1362-1392）对 CSV 也有表格预览分支。
2. **但前置工具名自动纠正层会把 read_xlsx 改写为 readtext（真正根因）**：
   - `action_handler.py:105` `_EXT_TO_READ_TOOL = {ext: "readtext" for ext in TEXT_EXTENSIONS}`，而 `.csv` 在 `TEXT_EXTENSIONS`（`file_type_checker.py:49`）中 → `.csv` 映射到 `readtext`。
   - `_auto_correct_file_tool`（L122-139）：`tool_name.startswith("read")` 时按 `_EXT_TO_READ_TOOL` 改写，`read_xlsx` + `.csv` → 被改写为 `readtext`。
   - **结果**：LLM 调用 `read_xlsx(path=sales.csv)` 时，实际执行的是 `readtext`（纯文本读），CSV 结构化表格视图**确实拿不到**。

**判定（v2.1 修正）**：task001"CSV 自动降级为 readtext"**属实**。此前的"文档无据、实为结构化"判定**错误**，现修正为**真实缺陷**——`_auto_correct_file_tool` 将 `.csv` 强制归 text 工具，屏蔽了 read_xlsx 对 CSV 的支持。

**优化方向**：
- `action_handler._EXT_TO_READ_TOOL` 中移除 `.csv`，或 read_xlsx 对 `.csv` 调用时不改写（CSV 同时属 text 与 document 双域，应允许 read_xlsx 优先处理表格语义）；其余工具（readtext 仍可读 csv 文本）不受影响。
