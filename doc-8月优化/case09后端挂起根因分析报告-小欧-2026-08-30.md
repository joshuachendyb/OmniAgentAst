## 一、结论先行

**病根与诱因分层结论**：

1. **结构性代码缺陷（病根）**：asyncio **事件循环线程上执行同步 stdout 写**——`log_and_print`（`app/logger/__init__.py:28`）与 `action_handler.py:919` 等 `print()` 直接睡在 loop 线程上，写阻塞时无任何防线，可永久冻结整个 uvicorn 事件循环。这是与 **2026-08-24 "后端卡死修复"（`db.atxn` 将 DB 同步写离线化）同一家族的缺陷**——那次只离线了 DB 同步写，**stdout 同步写是漏网同门**。
2. **环境触发源（诱因）**：进程 stdout 当时处于**阻塞态**（满管道 64KB 缓冲写满 / Windows 控制台选中阻塞），使 `print()` 永久阻塞。若 stdout 永为普通文件，本挂死永不发生。
3. **结果**：case09 agent 卡在 step=15 的 `handle_action` 同步前奏里 44 分钟（05:08:34→05:52:49 全局零日志、零 SSE、零 TASK_END），这是**真实后端挂起**。

**诚实声明**：此前（E2E 验证期间）我方曾输出"后端已完成(126s)、SSE 等待超时"结论，经本报告证据证明为**谎报**——case09 是真实后端挂起。且 v1.0 版将病根笼统归于"log/print 语句"、并给出看门狗兜底方案，经老陈复核指正后修正为"结构缺陷（loop 线程同步 stdout 写）"+"环境诱因（stdout 阻塞态）"双层框架，v1.1 更正。

**一句话因果链**：

> LLM 返回 action → `[Thought]` 日志入文件成功 → **事件循环线程上的 `print()` 写阻塞型 stdout（满管道/控制台选中）→ WriteFile/WriteConsole 永不返回 → 事件循环全局冻结** → 44 分钟零日志、零 SSE、零 TASK_END → DB 残留 `executing`。

## 三、病因（双层框架）

### 3.1 病根 · 结构性代码缺陷：事件循环线程上的同步 stdout 写

- `log_and_print`（`app/logger/__init__.py:27-28`）= `logger.info()` 后**在同一 loop 线程直接执行 `print()`**；
- `action_handler.py:919` 等约 N 处 `print()` 直接写在 coroutine 里；
- 事件循环线程一旦被 `WriteFile`/`WriteConsole` 永久占住，uvicorn 的**所有** task（health、SSE、其他会话）全部停摆。
- **家族定性**：这与 2026-08-24 "后端卡死修复"（`database.py:257 atxn` 把同步 sqlite 写离线化到子线程）**同属"事件循环线程同步阻塞 I/O"缺陷家族**。当日修复覆盖了 DB 写路径，**stdout 写路径被遗漏**，本次 case09 即为漏网点首次爆发。

### 3.2 诱因 · 环境触发源：stdout 处于阻塞态

| 场景 | 机制 | 后果 |
|---|---|---|
| 管道 | 进程 stdout 接管道，读端长时间不排空 → 64KB 缓冲写满 | `write()` 永久阻塞（长跑 E2E + 无人持续读 stdout 时最易复现） |
| 控制台 | Windows 控制台文本被选中（QuickEdit 选择态）/conhost 阻塞态 | `WriteConsole` 一直等待直到选择被清除，可永久阻塞 |

**为什么不能只修环境（只防诱因不修病根）**：
1. 无法承诺每种部署环境 stdout 永久是非阻塞文件（生产/Docker/systemd/手动起服都可能出现管道或控制台）；
2. 健康 HTTP 服务**不应因"没人读控制台"整体宕机 44 分钟**——这正是 08-24 把 DB 同步写离线化的同一理由，console 不能例外。

## 四、解决方法（两层治本，删除看门狗兜底方案）

### 4.1 第 1 层 · 病根根治：事件循环线程零同步 stdout 写（代码必改）

1. 新增 `app/logger/console_writer.py`：全局单例 `queue.Queue` + 一个 daemon 消费线程（可容忍线程内阻塞），提供 `console_put(msg)` **非阻塞入队**。
2. 改造 `log_and_print`：`logger.info(msg)` 保留；`print(msg)` 改为 `console_put(msg)`。
3. 全仓直连 `print()` 统一收口：至少 `action_handler.py:919`、react_cycle 内直接 print 处，改走 `log_and_print` 或 `console_put`。

效果：即使 stdout 永久阻塞，也只是**消费线程**卡住，事件循环与 agent 流程零影响，日志 / SSE / TASK_END 照常。

### 4.2 第 2 层 · 诱因根治：环境防再犯（配套必做）

1. E2E 启动后端改为 **stdout/stderr 重定向到文件**（`Start-Process -RedirectStandardOutput backend_console.log`），彻底移除"管道写满/控制台选中"两个触发源（第3层 v1.0 相关内容并入本层）。
2. 把"事件循环线程禁止同步写 stdout"列入编码规范（与"禁同步 DB I/O"并列），从源头杜绝同类漏网。

### 4.3 明确排除的方案（v1.0 曾提出，经复核废弃）

**"agent 无进展超时看门狗"（连续无 Step 产出超过阈值→强制 fail）已废弃**，理由：
1. 它把"永久卡死"变成"10 分钟后判失败"，成果照样丢、rework 照走——只是收尸，不治病；
2. 阈值无法定准：单次 LLM 调用即 107s、长工具更久，10min 阈值会**误杀正常慢任务**；
3. 不消除冻结点，只确认死亡。

### 4.4 验证方案

1. 修改后单测：monkeypatch stdout 为"写即永久阻塞"的假管道，断言 agent 仍能正常走完任务（事件循环不被拖垮）。
2. 回归：重跑 case09，确认 TASK_END 正常、DB 终态完成、SSE 全量送达；后端 16 用例无退化。

## 七、修复代码设计（待老陈审核 · 未落地代码）

> 本版修复设计**仅为代码 diff 供审核**，未对本地代码做任何修改；审核通过后再实施。核心原则：**事件循环线程零同步 stdout 写**。

### 7.1 设计决策（三堂会审前置审查）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 离线化载体 | 全局 `queue.Queue(maxsize=512)` + daemon 写线程 | 一次启动长驻消费；stdout 阻塞只卡写线程，事件循环永不被占。不用 `asyncio.to_thread`（每次调用起线程池任务、且依赖 loop 可用，不匹配"长驻消费"语义） |
| 入队函数 | `console_put(msg)` 非阻塞 `put_nowait` | 永不等待 |
| 丢弃策略 | 队列满则丢弃新消息 | 控制台仅是镜像，**权威日志在文件（logger.info 不受影响）**；阻塞时丢帧换事件循环存活，收益最大化 |
| 控制台语义 | 保留镜像输出，不删控制台 | 实时观察 agent 进度是运维能力，仅离线化 |
| 退出方式 | daemon 线程 + 进程退出即回收 | YAGNI：不引入优雅关闭/join/哨兵 |
| 线程异常 | 单条写失败 `except Exception: pass` + `finally task_done` | 一个坏消息不杀线程 |
| 乱序容忍 | stdout 阻塞时镜像可能丢帧/乱序 | 文件日志（logger）始终完整有序，为权威决策源；控制台仅人工观察 |

### 7.2 新增 `app/logger/console_writer.py`（完整 diff）

```
新增文件：
'''
# -*- coding: utf-8 -*-
# 编辑历史:
# 2026-08-30 - 小欧 - 新增 console_writer: 控制台镜像输出离线化(根治 App_2026-08-30.log:20790~20801 case09 挂起)
#   病根: log_and_print(约20处: react_cycle/action_handler/tool_safety_checker等) 与裸print(action_handler.py:919)
#         在 asyncio 事件循环线程同步写 stdout, 遇阻塞型 stdout(满管道64KB缓冲/Windows控制台选中)永久阻塞,
#         事件循环冻结44min, 全服务停摆.
#   方案: 全局单例 queue.Queue(maxsize=512) + daemon 写线程, console_put(msg) 非阻塞入队;
#         stdout 阻塞时队列满则丢弃新消息(控制台仅镜像, 权威日志在文件), 事件循环永不被占.
#   10规范: SRP(只做控制台镜像) / DRY(log_and_print复用) / KISS-DIRECT(queue+线程模型最简) /
#           SLAP(console_put单层入队) / YAGNI(不加优雅退出/多消费者) / 禁止backward(直接替换print)
"""
console_writer — 控制台镜像输出(事件循环线程零同步 stdout 写)
编写人 小欧 2026-08-30
"""
import queue
import sys
import threading
from typing import Optional

_console_queue: "queue.Queue[Optional[str]]" = queue.Queue(maxsize=512)


def _console_worker() -> None:
    """daemon 消费线程: 从队列取消息写 sys.stdout, 单条异常不杀线程 — 小欧 2026-08-30"""
    while True:
        msg = _console_queue.get()
        try:
            sys.stdout.write(msg)
            sys.stdout.flush()
        except Exception:
            pass
        finally:
            _console_queue.task_done()


_console_thread = threading.Thread(
    target=_console_worker, name="console-writer", daemon=True,
)
_console_thread.start()


def console_put(msg: str) -> None:
    """控制台镜像写(非阻塞): stdout 阻塞时队列满则丢弃新消息, 绝不阻塞调用线程 — 小欧 2026-08-30
    语义对齐原 print(): msg 追加换行写进程 stdout; 文件日志留痕走 logger, 两者互不阻塞.
    """
    try:
        _console_queue.put_nowait(msg + "\n")
    except queue.Full:
        pass
'''
```
