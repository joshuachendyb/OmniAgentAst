## 二、问题 A — 纠偏消息 role/措辞（部分属实，病根定位不准）

### 代码事实（结论属实部分）
- `react_cycle.py:197` 注入的纠偏消息 role=`assistant`，文本温和（"请检查……是否需要更换策略"），未制造紧迫感。
- 死循环检测 `_check_same_tool_loop`（react_cycle.py:167-179）按 `tool_name+规范化tool_params` 签名判断，`count==2/3/4` 各发 1 条纠偏（`_SAME_TOOL_WARN_ROUNDS=2`/`_SAME_TOOL_WARN_MAX=3`），`_MAX_CONSECUTIVE_SAME_TOOL_CALLS=5` 硬终止。

### 病根定位偏差（重要）
- 报告把 5 个死循环异常归因"纠偏无效"。**实际真相**：5 个死循环是**代码硬终止正常工作**的结果（连续 ≥5 次相同工具签名，react_cycle.py:485-497）。即保护机制确实拦截了 LLM 复读，任务终结是"兜底救场成功"，**不是"纠偏功能失效导致任务终结"**。
- 且该纠偏消息本就会进 conversation_history 发往 LLM（`message_builder.prepare_messages_for_llm` L240-246 只剥离 `_temp_*` 标记键，不删消息；`pop_temp_messages` L218 统一清理）。

### 可落地增强（可选，非解药）
若想让纠偏更有力，可行方向：role 改 `user` + 文本加紧迫感（"否则将终止任务"）——但这是**设计取舍增强**，不影响 5 个异常的正确拦截。单纯此改动**不能**减少 5 场景牺牲。

## 三、问题 B — 流式错误无重试（证伪）

报告断言"5xx 被包装成 error-type 直接 set_failed 无重试"。**对照代码证伪**：

真实重试链路（多层）：
1. **L2 重试**：`llm_stream.py:264-283` `call_llm_with_fallback` 收到 `type=="error"` → 立即转 `LLMResponseError` → 按 `LLM_RESPONSE_RETRIES=2`（constants.py:68）指数退避重试。
2. **L1 重试**：`base_service.py:198-340` 底层 `_stream` 自带重试循环，`_should_retry`（L458）默认 SERVER 可重试（黑名单策略），HTTP 500/502/503/504→SERVER→retryable。
3. **FC 降级**：重试耗尽后 `call_llm_with_fallback` L286-295 降级 Text 模式再试。

`react_cycle` 中 `type=error → set_failed` 是**穷尽多层重试后的最终兜底**，正确。002930 的"LLM 流式错误"是**多层重试耗尽后的真实最终失败**，非"无重试"。

## 五、独立复核：真正可落地的点

- A 的"纠偏措辞/role 增强"可作为**设计优化**选项，但宣称可解 5 个异常 **不成立**（那些是保护正常拦截）。
- 若欲降低 5 场景牺牲，应审视**硬终止阈值（5 次）与纠偏阈值（2-4 次）的设设取舍**——属设计参数，非 bug。

### 已实施修改（role 改 user + 措辞增强，三堂会审 2026-08-09）
按北京老陈指示落地问题 A 优化，`react_cycle.py:_warn_same_tool_loop`：

- **role 改 `user`**：纠偏本质是"系统给 LLM 的下一条指令/反馈"，非 assistant 自推理，用 user 更符合语义且对 LLM 服从性更强。
- **文本增强紧迫感**：点明"这是严重重复循环""否则系统将强制终止本次任务"，要求"改工具/不同参数 或 直接给出结论结束"，把后果讲清。
- **可清除性已核实**：消息带 `_temp_same_tool_warn: True`，受通用 `_temp_*` 前缀清除保护（`message_builder.pop_temp_messages` v1.6，L209-223）；发 LLM 前由 `prepare_messages_for_llm`（L245-246）剥离标记；终态由 `react_cycle._finalize_cycle`（L312）统一收口清，生产持久化前弹掉。
- **发送即清 v1.7（2026-08-09 落地）**：纠偏消息是**一次性指令，发完即无用**。`prepare_messages_for_llm`（message_builder.py:250-253）浅拷贝 `messages` 后，立即从 `conversation_history` 源中剔除 `_temp_*` 临时消息——纠偏"活本轮发送这一次"即从源历史消失，后续轮次/压缩/持久化均无残留、不重复携带、不占 token。压缩触发时历史里天然无纠偏（而非"保留"）。

### 落地效果说明（重要）
- 该优化是**设计增强**，非 5 个异常的解药——5 个死循环本就被硬终止正确拦截。期望收益是提升 LLM 在 2-4 次阶段更早调整，减少触发硬终止（5 次）的次数，属渐进改善。
- **纠偏生命周期终态**：注入 → 下一轮 `prepare_messages_for_llm` 副本含纠偏发 LLM → 同轮从源剔除 → 终态 `pop_temp_messages` 双保险清异常残留。`_temp_reasoning`（推理空转）同步受益，推理亦"发完即弃"，与"空转不持久化"设计契合。
