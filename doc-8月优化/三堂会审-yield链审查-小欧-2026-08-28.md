## 二、yield总量与分类

| 类别 | 数量 | 性质 |
|------|------|------|
| 直接事件 `yield emit(...)` / `yield event` | ~45 | 真实事件源（step/chunk/usage/stats/error/pause/resumed/cancel等） |
| 透传 `async for _s in emit_final_with_stats(): yield _s` | 10 | 伪异步仪式（每个展开=2事件：final+final_stats） |
| 透传 `async for event in handler/_process_single_step: yield event` | 3 | 管道转发（Python无async `yield from`，强制写法） |

结论：65个yield中，~45为真实事件，3为语言强制管道转发，10为 ceremony（源于伪异步包装）。

## 三、4层异步生成器管道图

```
run_react_cycle (编排循环)
  ├─ _process_single_step (单步LLM处理) → step_emitter.emit   [3层]
  └─ _dispatch_handler (type路由)
        └─ handle_answer / handle_action (业务逻辑) → step_emitter.emit   [4层]
```

每层职责单一：
- run_react_cycle：循环编排、取消/暂停检测、终态兜底
- _process_single_step：单步LLM调用→响应处理→分发
- _dispatch_handler：按type路由到answer/action handler，并做终态推断
- handle_answer/handle_action：具体业务（说/工具）
- step_emitter.emit：步骤记录+错误捕获+token注入+日志

## 四、三堂会审判定（合规/合理/关联）

### 4.1 非KISS（唯一真问题）
`step_emitter.emit_final_with_stats`（step_emitter.py:54）为 `async def`，但**体内零 await**：
```python
async def emit_final_with_stats(self, final_step):
    yield self.emit(final_step)
    yield self.emit(self.agent.telemetry.build_final_stats_step())
```
emit() 本身为 sync 方法。此 async 包装无任何真实异步工作，纯仪式代码，逼出10处调用点写 `async for _s in ...: yield _s`（异步版 `yield from`）。属七绕八绕。

10处调用点：answer_handler×4（L112/129/170/214）、action_handler×1（L1010）、react_cycle×5（L618/669/751/781/852）。

### 4.2 合法SRP（非冗余）
`async for event: yield event` 三层转发（_dispatch_handler:330、run_react_cycle:687、:801）是 Python 异步生成器无 `yield from` 的**语言强制写法**；每层有真实独立职责，符合SRP，不算设计冗余。

### 4.3 无死yield（关联逻辑）
- `wait_for_resume(emit_sse=False)`：纯阻塞不产SSE，前端消费路径由 `task_pause_check(emit_sse=True)` 统一下发（task_runtime.py已拆分，P4 2026-08-09），无死路。
- `task_pause_check` / `stream_reader` 全部被 `_stream_with_control` 消费链路接住，无丢弃事件。

### 4.4 无重复事件（DRY）
`build_stats_step(type="stats", 每轮, 带step_count/llm_call_count/retry_count)` 与 `build_final_stats_step(type="final_stats", 终态, 带artifacts)` 为**不同事件类型**（agent_telemetry.py:128 / :145 核对确认）。每轮stats + 终态final_stats 不重复，语义自洽。

### 4.5 合规
全部yield点沿用既有 `agent._step_emitter.emit` 单一出口，未引入新抽象/注册表，无backward兼容代码，符合日常6条+重构4条规范。

---

## 五、修正建议（最小KISS，行为等价）

1. `emit_final_with_stats` 由 `async def` 改为 sync，返回 `(final_step, stats_step)` 二元组（或list）。
2. 10处调用点 `async for _s in agent._step_emitter.emit_final_with_stats(X): yield _s` 改为 `for _s in agent._step_emitter.emit_final_with_stats(X): yield _s`。
3. 仍按序 yield 两个 step，前端无感；无backward问题；零风险。

预期效果：65个yield点中的"透传层"消掉，日志覆盖不变（step_emitter.emit 单一出口已统一加 logger.debug）。
