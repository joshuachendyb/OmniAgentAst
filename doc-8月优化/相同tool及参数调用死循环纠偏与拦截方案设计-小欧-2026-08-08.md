# 相同tool及参数调用死循环纠偏与拦截方案设计

**创建时间**: 2026-08-08 06:49:20
**编写人**: 小欧
**状态**: 待实施（当前代码 v0.19.7 为单阈值简版，本方案为双阈值正式版，北京老陈批准后落码）
**依据**: P6-01（file_not_found）E2E 超时 2900s 根因定位 + `tests/output/P6_01_result.xml` 实测

## 一、问题背景与需求

### 1.1 现象与病根

P6-01（file_not_found）E2E 超时（2900s）根因：LLM 在 step~130 陷入死循环，连续 40+ 步**逐字重复同一 Thought**，反复调用**完全相同** `writetext`（内容为 diff_tool.py），每次工具执行均 success，但 LLM 从不前进，直至 pytest timeout=2900s 被杀。

### 1.2 需求（Why）

1. **产品缺陷**：LLM 可能陷入"反复调用**完全相同**工具 + 相同参数"的死循环，系统无防御（真实产品缺陷，需修复）。
2. **现有防御盲区**：`_consecutive_reasoning_only`（answer_handler.py:160）仅拦截"纯推理无工具调用"空转；本场景**每轮均调工具→计数归零，永远不会触发**。
3. **硬兜底失效**：当前 `max_steps=10000` 远大于 pytest 外部 timeout 2900s → 必超时失败。
4. **期望**：既尽早**察觉并尝试纠偏**（Soft），又必有**硬终止兜底**（Hard），杜绝死循环耗尽 timeout。

## 二、修复思路（双阈值纠偏/拦截）

| 连续相同调用次数 | 行为 | 采取行动 |
|---|---|---|
| 第1~2 次（count 1~2） | 正常，无感知 | `agent._consecutive_same_tool_calls` 累加 |
| 第3 次（count=3） | **纠偏（软）** | 注入 role=assistant、标记 `_temp_same_tool_warn` 的警告消息，让 LLM 自然感知并调整；幂等（最多 1 条） |
| 第4 次（count=4） | 观察期 | 警告已注入（幂等不重复），继续循环等待 LLM 响应 |
| 第5 次（count>=5） | **硬终止** | `set_failed` + `FinalStep(outcome="failed", error_type="same_tool_loop")`，return |

- **签名检测**：`_tool_call_signature` = `(tool_name, sort_keys_json(tool_params))`（含并行 pending），参数内容变化即签名变化，杜绝"换参数不算循环"的误判。
- **Soft 纠偏**：连续相同调用 **第3次（count==3）** → 注入 role=assistant、标记 `_temp_same_tool_warn` 的观察消息，试图唤醒 LLM 调整（幂等：同轮仅 1 条）。
- **Hard 硬终止**：连续相同调用 **第5次（count>=5）** → `set_failed` + `FinalStep(outcome="failed")` 彻底中断。
- **归零/重置**：非 action 一律归零计数+标记；action 签名变化=重置 count=1（新序列起点，见 §6.1）；`_temp_same_tool_warn` 消息复用 `pop_temp_messages()`（扩展为 `_temp_*` 前缀统一清理）终态弹出，不污染 DB。

> 警告（message）用于**纠偏尝试**，终止用于**彻底失败兜底**；二者互补，既给 LLM 一次纠正机会，又避免无休止浪费 token。

## 三、核心函数设计

### 3.1 `_tool_call_signature(llm_response)` — react_cycle.py

计算 action 响应的工具调用签名（全调用含并行）。

```python
def _tool_call_signature(llm_response: Dict) -> str:
    calls = []
    _primary = (llm_response.get("tool_name", "") or "", llm_response.get("tool_params") or {})
    calls.append(_primary)
    for _pc in llm_response.get("_pending_calls") or []:
        calls.append((_pc.get("tool_name", "") or "", _pc.get("tool_params") or {}))
    return json.dumps(calls, sort_keys=True, ensure_ascii=False)
```

- `sort_keys=True` → 参数顺序无关
- 含 `_pending_calls` → 并行多工具场景也覆盖

### 3.2 `_check_same_tool_loop(agent, llm_response)` — react_cycle.py

返回 int count，**count 即"第几次连续相同调用"**（首个相同签名=1），供调用方分支（count==3 纠偏 / count>=5 中断）。

> **阈值对齐（北京老陈 2026-08-08）**：要求"第3次开始发纠偏信息（assistant role），第5次调用时 agent 中断（count>=5，第5次即中断，不含'后'）"。为使 count 直接等于"第几次"、消除歧义：无上次签名（首调用）定为 count=1；后续与上轮签名相同则 +1；签名变化则重置 count=1 且 `_warned_same_tool_loop=False`。

```python
def _check_same_tool_loop(agent, llm_response: Dict) -> int:
    _sig = _tool_call_signature(llm_response)
    if _sig and _sig == getattr(agent, "_last_tool_call_sig", None):
        agent._consecutive_same_tool_calls = getattr(agent, "_consecutive_same_tool_calls", 0) + 1
    else:
        agent._consecutive_same_tool_calls = 1      # 新签名起点=1，标记同步重置
        agent._warned_same_tool_loop = False
    agent._last_tool_call_sig = _sig
    return agent._consecutive_same_tool_calls
```

> **三堂会审修正 v1.1（溯源）**（小欧 2026-08-08 06:53:54）：当前代码 v0.19.7 返回 bool（单阈值判定）；本设计改返回 int 支撑双阈值。初稿从 0 起算导致"第4次"歧义，后按老陈指定语义定为"第3次纠偏/第5次中断"。

### 3.3 `_warn_same_tool_loop(agent, llm_response, count)` — react_cycle.py（NEW）

注入纠偏提醒（幂等、带标记、终态清理）。

> **三堂会审修正 v1.1**（小欧 2026-08-08 06:53:54）：
> ① `message_builder.add_assistant_message(content: str)` 签名仅接受 content 一个参数，不支持 extra；
>    故改手动 `conversation_history.append({...})` 带 `_temp_same_tool_warn` 标记（与 answer_handler.py:172 reasoning-only 注入 `_temp_reasoning` 方式一致，DRY 复用同模式）。
> ② `log_and_print` 时间用 `time.strftime('%H:%M:%S')` 逐次取，与场景 F 终止分支一致。
> ③ 该函数为 v1.1 新增待实现函数（当前 v0.19.7 代码中不存在）。

```python
def _warn_same_tool_loop(agent, llm_response: Dict, count: int) -> None:
    if getattr(agent, "_warned_same_tool_loop", False):
        return  # 幂等：同一轮相同循环只警告一次
    agent._warned_same_tool_loop = True
    _tool = llm_response.get("tool_name", "") or ""
    _sig = _tool_call_signature(llm_response)
    obs_text = (
        f"[Observation] 警告: 你刚才连续调用了相同的工具 {_tool} 且参数**完全相同**, "
        f"已连续 {count} 次, 签名={_sig[:80]}... "
        f"结果本质相同, 可能陷入思维循环。请检查: 1) 是否获得了新信息; 2) 是否需要更换策略。"
    )
    agent.message_builder.conversation_history.append({
        "role": "assistant",
        "content": obs_text,
        "_temp_same_tool_warn": True,
    })
    logger.info(f"[run_react_cycle] LLM连续{count}次调用相同工具 {_tool}, 注入纠偏警告")
    log_and_print(f"{time.strftime('%H:%M:%S')} [Loop] step={agent.llm_call_count} same tool warn={_tool}")
```

## 四、场景 F 修改（react_cycle.py `_process_single_step`）

> **三堂会审修正 v1.1**（小欧 2026-08-08 06:53:54）：
> 当前代码 v0.19.7 为单阈值 bool 分支（仅 `if _check_same_tool_loop(...)` 终止），本设计改为双阈值 int 分支：
> `_cnt == 3` 触发纠偏注入；`_cnt >= 5` 触发硬终止。else（非 action）补 `_warned_same_tool_loop = False` 归零。

```python
# 场景F: 相同工具调用死循环检测(纠偏-硬终止) ---- 2026-08-08 小欧
# count 即"第几次连续相同调用": count==3 → 纠偏; count>=5 → 硬终止
if llm_response.get("type") == "action":
    _cnt = _check_same_tool_loop(agent, llm_response)
    if _cnt == _SAME_TOOL_WARN_ROUNDS:                # count==3(第3次相同调用): 纠偏
        _warn_same_tool_loop(agent, llm_response, _cnt)
    elif _cnt >= _MAX_CONSECUTIVE_SAME_TOOL_CALLS:  # count>=5(第5次相同调用): 硬终止
        logger.warning(f"[run_react_cycle] LLM连续{_cnt}步调用相同工具(step={step}), 判定死循环, 终止")
        log_and_print(f"{time.strftime('%H:%M:%S')} [Cancel] step={step}, same_tool_loop")
        set_failed(agent, f"模型连续{_cnt}步重复调用相同工具, 疑似死循环, 任务终止")
        yield agent._step_emitter.emit(FinalStep(
            step=step,
            response="模型反复调用相同工具未取得进展，任务已终止（疑似死循环）",
            thought=llm_response.get("reasoning", "") or llm_response.get("thought", ""),
            outcome="failed",
            error_type="same_tool_loop",
            error_message=f"模型连续{_cnt}步重复调用相同工具，疑似死循环",
        ))
        return
else:
    # 非 action(正常 answer/final/reasoning-only): 归零防残留
    agent._consecutive_same_tool_calls = 0
    agent._last_tool_call_sig = None
    agent._warned_same_tool_loop = False
```

## 五、常量定义

> 计数语义（北京老陈 2026-08-08）：count 即"第几次连续相同调用"。首调用（无上次签名）count=1，与上轮相同则 +1。
> 故：count==3（第3次相同）触发纠偏；count>=5（第5次相同）触发硬终止。

```python
_SAME_TOOL_WARN_ROUNDS = 3             # 纠偏阈值: count==3(第3次相同调用)时注入警告
_MAX_CONSECUTIVE_SAME_TOOL_CALLS = 5   # 硬终止阈值: count>=5(第5次相同调用)时硬终止
```

## 六、归零 / 清理

### 6.1 清零 / 重置规则（三条，落码必须严格对齐 — 北京老陈 2026-08-08 强调）

| 时机 | count | `_last_tool_call_sig` | `_warned_same_tool_loop` |
|---|---|---|---|
| **初始化**（`initialize_run_state`，会话/任务开始时） | 0 | `None` | `False`（**新增字段，落码时一并初始化**） |
| **action 且签名变化**（via `_check_same_tool_loop` else 分支） | **1**（新循环起点，非归零） | 新签名 | `False` |
| **非 action**（answer/final/reasoning-only，场景 F else 分支） | **0**（归零） | `None` | `False` |

> 三条规则语义区别（小欧 2026-08-08）：「初始化」=任务起点无上下文；「action 签名变化」=上一轮工具/参数已改变，进入**新的连续序列起点（count=1）**；「非 action」=无工具调用上下文，计数归零。不可混淆，尤其"签名变化"是 **重置 count=1** 而非归零 0（否则首个相同调用被误计为"第0次"）。

### 6.2 清理
- `_warned_same_tool_loop = False` 随 `_consecutive_same_tool_calls` 重置（见 6.1 三条规则 + 3.2）
- 标记 `_temp_same_tool_warn` 的 assistant 消息，将在终态清理（否则持久化到 DB 污染会话历史）。

> **不识别 `_temp_same_tool_warn`**。原设计"复用 pop_temp_messages() 统一清理"有误，需扩展。

## 七、交互关系（关联逻辑审查）

- 与 `_deny_counts`（block/reject ≥3 → failed，react_cycle.py:197）：防御维度不同，互不冲突
  - `_deny_counts`：工具被拒/阻止
  - `same_tool_loop`：工具 success 但 LLM 不前进
- 与 `_consecutive_reasoning_only`（reasoning-only >3 即 ≥4 → failed，answer_handler.py:160）：互补
  - reasoning-only：LLM 没调工具，纯推理空转
  - same_tool_loop：LLM 反复调相同工具
- 前端：警告不变更状态，继续循环；硬终止 `FinalStep(outcome="failed")` 前端按 outcome 分流，无破坏

## 八、单元测试（tests/test_same_tool_loop_defense.py）

- `_tool_call_signature`：参数顺序无关 / 参数变化即变 / 并行 pending 纳入
