本文档记录对以下三处修复代码进行"熟读多遍 + 三堂会审"后确认的问题，以及与修复直接相关的关联逻辑缺陷：

2. `backend/app/services/agent/handlers/action_handler.py` 的 B'分支 DRY 优化
3. `backend/app/tools/fundamental/execute_shell_command.py` 的 cmdlet 名正则收紧

## 一、确认属实的问题（含修复方法）

### 问题 1 — Add-Type 未加同策略收紧（不一致）

- **位置**: `backend/app/tools/fundamental/execute_shell_command.py:650-651`
- **证据**: L650 注释写明"稳健收紧：加 cmdlet 名后须紧跟冒号"，`Get-ChildItem/ForEach-Object/Get-CimInstance/New-Object/Sort-Object/Get-WinEvent/Set-ItemProperty/Get-Process` 8 个 cmdlet 均已改为 `\b名\b\s*:`，但 `r"\bAdd-Type\b"` 仍是裸词边界。Add-Type 是 cmdlet（且被并入了 `InvalidOperation / MethodInvocationException` 异常类型名下），正常输出仅含 "Add-Type" 字样时会被误判 error，正是本次收紧逻辑要规避的 false-positive。
- **修复**: `r"\bAdd-Type\b"` → `r"\bAdd-Type\b\s*:"`。

### 2. 5 内容 — 从 650-651 收紧 `\s*:` 应改为 `[ \t]*:`

- **位置**: `execute_shell_command.py:652-654`
- **核实**: `\s` 在 Python re.includes 含 `\n`,`\r`,`\t`,`\f`,`\v`。`r"\bForEach-Object\b\s*:"` 可跨行匹配 `ForEach-Object\n:`，不满足"cmdlet 名与冒号同行"的真实错误行首格式，属正常范围误命中。虽大概率出现次数低，但为正确定性问题。
- **修复建议**: 8 个 cmdlet 及 Add-Type 的 `\s*:` 统一改 `[ \t]*:`（只匹配同行内空白）。

### 3. total_steps 只排除 usage，Meta 步骤排除不完整

- **位置**: `backend/app/services/chat/stream.py:163-165`
- **核实**: 注释声明 "usage 为 Meta 步骤非业务步骤"，但 `counter.pop("usage", None)` 仅删除该键。而 `paused`（action_handler:190 检查确认）、`retrying`（answer_handler:140 / react_cycle:574），以及 `start/cancelled` 等 MetaStep 同样经 agent_runner.py:174 `current_execution_steps.append` 进入 steps 数组，进而被计入 total_steps。注释既宣称"Meta 步骤非业务步骤"，当前实现与之一致性不高。
- **修复建议**: 将非业务 Meta 类型统一从计数中剔除后再求出 sum，如 `for t in ("usage","paused","resumed","retrying","cancelled","authorization_required","start"): counter.pop(t, None)`。是否纳入 start/cancelled 需三堂会审确认，避免误伤其它业务统计。

### 4. 暂停/恢复 SSE 在后台路径为重复/死路产出（修复: 拆分阻塞与上报）

- **位置**: `react_cycle.py:561-562` ←→ `task_pause_check`（`backend/app/services/task/task_runtime.py:90-126`）
- **核实（定级修正）**: 该问题此前初判"最严重/前台漏事件"系夸大。真实情况:
  1. `task_pause_check` 产出的是**字符串**（`format_agent_sse`），在 react_cycle 上抛。
  2. agent_runner.py:158 `async for event` 收到字符串——既非 dict、也无 `.to_dict()`，命中 `else` 分支（L162-168）被 `continue` 丢弃（死路）。
  3. **但前端并未丢失暂停提示**: 前端实时流/重连走 `openai.py:283` 的 `_stream_with_control`，其独立调用 `task_pause_check_and_yield` 产出 SSE 下发。故暂停/恢复 SSE 有**真实有效**的路径（openai），后台 react 路径产出的这份字符串属**重复死路**。
- **修复（三审后实施）**: 拆分职责——
  - `task_runtime.py`: 新增 `_pause_core`（纯阻塞核心）+ `wait_for_resume(task_id)`（纯阻塞、不产 SSE）；
  - `react_cycle.py`: 后台循环改只 `await wait_for_resume(task_id)`，不再产出死路 SSE 字符串；
  - `task_pause_check` 保留产 SSE，专供前端消费路径（openai）。
  - 结果: 阻塞逻辑与 SSE 上报各司其职，后台无死路事件，前端提示不变。

## 三、未证实/待检验（暂不列为 bug）

### 1. 全角冒号（U+FF1A）风险

- **说明**: `\b名\b\s*:` 只匹配 ASCII 冒号。中文 Windows PowerShell 的错误分隔符由引擎按 `cmd : msg` 格式化，分隔符本身为 ASCII 冒号，与系统区域无关（仅消息文本可中文）。因此全角冒号导致的漏杀风险极低，未实证为缺陷。
- **处置**: 仅作风险提示，不列入本报告问题，待 E2E/实证后再定是否处理。
