### 1.3 10 大原则遵守策略

| 原则 | 如何遵守 |
|------|---------|
| **SRP 单一职责** | 每项增强只改一个模块的一个职责点，不改无关代码 |
| **DRY 不重复** | 行号格式化/标签包裹抽取为 `_format_content_lines()` 共用函数 |

| **SLAP 同抽象层** | 行号/标签逻辑在展示层封装，不混入数据层 |
| **YAGNI 不过度设计** | 不做可配置/插件化，硬编码默认值。未来有需求再加 |
| **禁止backward** | 新增字段/行为只在新版本生效，不保留旧格式开关 |

| **ISP 接口隔离** | 不改工具注册 schema，不影响其他工具 |
| **复用优先** | 行号格式化抽取为 `app/utils/file_formatter.py` 公用函数 |

## 二、增强 1 — readtext 输出带行号

### 2.1 问题

当前 `readtext` 输出 `content` 为纯文本，没有行号前缀。LLM 在后续调用 `edittext` 时无法精确定位行，导致 edit 准确率低。

### 2.2 Go 参考

`view.go` 的 `addLineNumbers()` 函数：
```go
func addLineNumbers(content string) string {
    lines := strings.Split(content, "\n")
    var sb strings.Builder
    for i, line := range lines {
        fmt.Fprintf(&sb, "%d\t%s\n", i+1, line)
    }
    return sb.String()
}
```

### 2.3 设计

**改动位置**: `read_text_file.py` 的 `_select_lines()` 返回值改造

**设计方案**:

| 方案 | 方案A（推荐） | 方案B |
|------|--------------|-------|
| **做法** | `content` 字段直接带行号前缀 | 新增 `content_with_lines` 字段 |
| **原理** | KISS-DIRECT，不破坏已有字段 | 保留原始 `content` |
| **缺点** | LLM 看到的 content 带行号 | 多一个字段，LLM 可能用旧的 |
| **选择** | ✅ **方案A** — 简单直接 | |
| **后续** | LLM 只看 `content`，行号嵌入其中最可靠 | |

**实现代码**（`read_text_file.py` _select_lines 调用方改造）：

在 `_select_lines` 返回原始行后，对 `content` 字段做追加处理：

```python
# 在 readtext() 中，_select_lines 之后，build_* 之前追加：
lines_content = _data.get("content", "")
if lines_content:
    _data["content"] = _add_line_numbers(lines_content, offset=actual_offset)
```

抽取公用函数 `_add_line_numbers`：

```python
def _add_line_numbers(content: str, offset: int = 1) -> str:
    """给文本内容添加行号前缀 — 小欧 2026-07-05"""
    lines = content.rstrip("\n").split("\n")
    # 计算行号宽度（对齐用）
    last_lineno = offset + len(lines) - 1
    width = len(str(last_lineno))
    return "\n".join(
        f"{offset + i:>{width}}|{line}"
        for i, line in enumerate(lines)
    )
```

**输出示例**：
```
 1|import os
 2|import sys
 3|
 4|def main():
 5|    print("hello")
```

| 文件 | 变更内容 |
|------|---------|
| `app/tools/file/read_text_file.py` | 新增 `_add_line_numbers()`；`readtext()` 中调用 |
| `app/utils/file_formatter.py` | **新建**，存放 `_add_line_numbers()` 作公用函数 |

### 2.5 10 原则遵守情况

| 原则 | 遵守说明 |
|------|---------|
| SRP | `_add_line_numbers` 只做格式化 |
| DRY | 抽到 `file_formatter.py`，未来 `edittext` diff 也可复用 |
| KISS-DIRECT | 8 行函数 + 1 行调用，无抽象 |
| SLAP | 展示层格式化，不混数据层 |
| YAGNI | 不做行号样式可配置 |
| 禁止backward | 直接修改 content，不保留旧版字段 |
| OCP | readtext 签名不变 |

| ISP | 不涉及 |
| 复用优先 | 先抽取后复用 → 新建 `file_formatter.py` |

## 三、增强 2 — check_conflict 从警告改为阻断

### 3.1 问题

当前 `check_conflict` 返回**警告**字符串，`writetext` 和 `edittext` 使用方仅记录日志或展示，不阻断写入。Go 版 `edit.go` 对外部修改**严格阻断**写入。

### 3.2 Go 参考

```go
// 如果文件在读取后被外部修改，直接报错
if modTime.After(lastRead) {
    return "", fmt.Errorf("file modified externally, read first")
}
```

### 3.3 设计

**改动位置**: `file_state.py` + `write_text_file.py` + `edit_text_file.py`

**三步改动**：

1. **`file_state.py` 新增 `check_conflict_strict()`**（不改旧函数，SRP）

```python
def check_conflict_strict(file_path: str) -> Optional[str]:
    """严格检查：文件自上次记录后被外部修改 → 返回错误信息（非警告）— 小欧 2026-07-05"""
    resolved = Path(file_path).resolve()
    key = str(resolved)
    recorded = _state.get(key)
    if recorded is None:
        return None
    recorded_mtime, _ = recorded
    try:
        current = resolved.stat().st_mtime_ns
    except OSError:
        return None
    if current != recorded_mtime:
        return (
            f"文件 {file_path} 自上次读取后被外部修改。"
            "请先调用 readtext 确认最新内容后再进行写入操作"
        )
    return None
```

2. **`write_text_file.py` 写入前调用 `check_conflict_strict()`**：

```python
# writetext() 中，validate_path 之后、写入之前：
conflict = check_conflict_strict(file_path)
if conflict:
    return build_error(data={"error_detail": conflict, ...})
```

3. **`edit_text_file.py` 同样加严格检查**（同 writetext 模式）

**注意**：保留旧 `check_conflict` 函数（向后兼容外部调用），但工具内部入口只用 `check_conflict_strict`。

### 3.4 涉及文件

| 文件 | 变更内容 |
|------|---------|
| `app/tools/file/file_state.py` | 新增 `check_conflict_strict()` |
| `app/tools/file/write_text_file.py` | 写入前调用 `check_conflict_strict()` 并阻断 |
| `app/tools/file/edit_text_file.py` | 编辑前调用 `check_conflict_strict()` 并阻断 |

### 3.5 10 原则遵守情况

| 原则 | 遵守说明 |
|------|---------|
| SRP | 只新增 `check_conflict_strict`，不改旧函数 |
| DRY | writetext/edittext 共用同一函数 |
| KISS-DIRECT | ~15 行，直线逻辑 |
| SLAP | 调用在编排层，实现在工具层 |
| YAGNI | 不做可配置严格/宽松模式 |
| 禁止backward | 新工具调用全走严格，无开关 |
| OCP | `check_conflict` 旧函数不动 |
| LSP | 返回值类型一致 |
| ISP | 不涉及 |
| 复用优先 | 已有 `check_conflict` 复用其内部逻辑 |

## 四、增强 3 — readtext 用 `<file>` 标签包裹输出

### 4.1 问题

当前 `readtext` 的 `content` 直接返回文件内容，无包裹标签。LLM 在长上下文中难以区分文件边界。Go 版 `view.go` 用 `<file>...</file>` 包裹。

### 4.2 Go 参考

```go
func (v *View) viewFile(path string) (string, error) {
    content, err := os.ReadFile(path)
    ...
    output := "<file>\n"
    output += addLineNumbers(string(content))
    output += "</file>"
    return output, nil
}
```

### 4.3 设计

**改动位置**: `read_text_file.py` 的 `_select_lines()` 返回值改造

**设计方案**：在 content 两侧加 `<file>` / `</file>` 标签。

```python
# _select_lines 后，加标签：
lines_content = _data.get("content", "")
if lines_content:
    _data["content"] = f"<file>\n{lines_content}\n</file>"
```

**注意**：行号（增强1）应用在标签**内部**，即：

```
<file>
 1|line1
 2|line2
...
</file>
```

所以调用顺序：先加行号 → 再加标签。如果只加标签不加行号（如用户没选择增强1），则无行号直接包裹。

### 4.4 涉及文件

| 文件 | 变更内容 |
|------|---------|
| `app/tools/file/read_text_file.py` | `readtext()` 中对 content 加 `<file>` 标签 |

### 4.5 10 原则遵守情况

| 原则 | 遵守说明 |
|------|---------|
| SRP | 标签包裹是展示层职责 |
| DRY | `_wrap_file_tag()` 可复用，或和行号一起在 `file_formatter.py` |
| KISS-DIRECT | 1 行字符串格式化 |
| SLAP | 展示层，不混数据层 |
| YAGNI | 不支持自定义标签名 |
| 禁止backward | 不论旧调用方，一律加标签 |
| OCP | readtext 签名不变 |
| LSP | content 字段类型不变 |
| ISP | 不涉及 |
| 复用优先 | 放 `file_formatter.py` 方便未来复用 |

## 五、增强 4 — grep 结果按 mtime 排序

### 5.1 问题

当前 `grep` 结果按文件路径字母序排列，最新修改的文件可能排在尾部。Go 版 `grep.go` 按 `modTime` 降序排列，最新改的文件在最前，更符合开发者直觉。

### 5.2 Go 参考

```go
sort.Slice(results, func(i, j int) bool {
    return results[i].ModTime.After(results[j].ModTime)
})
```

### 5.3 设计

**改动位置**: `grep_file_content.py` 的 `_grep_directory_sync()` 或主函数

**方案**：在 `_grep_directory_sync()` 扫描完后，按 `mtime` 排序。

当前各个文件的匹配结果在 `result` 中是 `{"file_path": ..., "matches": [...], "match_count": ...}` 结构。只需在主入口 `grep_file_content` 中对 `results["files"]` 做排序：

```python
def _sort_by_mtime(files: List[Dict]) -> List[Dict]:
    """按修改时间降序排序 — 小欧 2026-07-05"""
    return sorted(files, key=lambda f: Path(f["file_path"]).stat().st_mtime, reverse=True)
```

在主函数中 `return build_success` 之前调用：

```python
results["files"] = _sort_by_mtime(results["files"])
```

**如果 mtime 获取失败**：用 `-1` 兜底，排在最后（避免 OSError 崩溃）。

### 5.4 涉及文件

| 文件 | 变更内容 |
|------|---------|
| `app/tools/file/grep_file_content.py` | 新增 `_sort_by_mtime()`；主函数返回前调用 |

### 5.5 10 原则遵守情况

| 原则 | 遵守说明 |
|------|---------|
| SRP | `_sort_by_mtime` 只排序 |
| DRY | 不重复，只在 grep 中用 |
| KISS-DIRECT | 1 行排序 + 异常兜底 |
| SLAP | 展示层排序，不混业务 |
| YAGNI | 不做排序方向可配置 |
| 禁止backward | 默认降序，无开关 |
| OCP | grep 输出结构保持 `files` 字段不变 |
| LSP | `files` 列表元素结构不变 |
| ISP | 不涉及 |
| 复用优先 | 不涉及（grep 专用） |

## 六、增强 5 — listdir 默认忽略噪声目录

### 6.1 问题

当前 `listdir` 只忽略 `.` 开头的隐藏目录（`include_hidden=False`），但 `node_modules`、`__pycache__`、`.git` 等非隐藏噪声目录大量占用输出。Go 版 `ls.go` 有 `shouldSkip()` 函数默认跳过这些目录。

### 6.2 Go 参考

```go
func shouldSkip(name string) bool {
    skipDirs := map[string]bool{
        "node_modules": true, "__pycache__": true,
        ".git": true, "target": true, ...
    }
    return skipDirs[name]
}
```

### 6.3 设计

**改动位置**: `list_directory.py` 的 `_scan_directory_sync()` 函数

**设计方案**：新增 `skip_patterns` 默认忽略列表，对 `include_hidden=True` 时**也生效**（因为 `__pycache__` 不是隐藏目录）。

```python
# 新增全局常量
_SKIP_DIRS: FrozenSet[str] = frozenset({
    '__pycache__', 'node_modules', 'bower_components',
    '.git', '.svn', '.hg',
    '.next', '.nuxt', 'dist', 'build', 'target', 'out',
    '.venv', 'venv', '.env', 'env',
    '.idea', '.vscode', '.yarn', '.pnp', 'coverage',
    '.terraform', '.serverless', 'vendor',
})
```

在 `_scan_directory_sync` 的 `for item in current_path.iterdir()` 循环中加入过滤：

```python
# 在 include_hidden 检查后新增：
if item.name in _SKIP_DIRS:
    continue
```

**注意**：这是**默认行为**，未来可通过参数控制（当前不做，YAGNI）。

### 6.4 涉及文件

| 文件 | 变更内容 |
|------|---------|
| `app/tools/file/list_directory.py` | 新增 `_SKIP_DIRS` 常量；`_scan_directory_sync` 中应用 |
| `app/utils/file_formatter.py` | 可选：`_SKIP_DIRS` 放此处作公用常量 |

### 6.5 10 原则遵守情况

| 原则 | 遵守说明 |
|------|---------|
| SRP | `_SKIP_DIRS` 只做过滤 |
| DRY | 常量集中一处 |
| KISS-DIRECT | `if name in _SKIP_DIRS: continue` |
| SLAP | 扫描层过滤，不给上层感知 |
| YAGNI | 不做可配置参数 |
| 禁止backward | 默认生效，无开关 |
| OCP | listdir 签名不变 |
| LSP | 输出结构不变 |
| ISP | 不涉及 |
| 复用优先 | grep 已有 `_SKIP_DIRS`（行 29-36）→ **统一到 `file_formatter.py`** |
