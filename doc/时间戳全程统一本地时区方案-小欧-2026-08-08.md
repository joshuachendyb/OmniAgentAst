## 一、需求与要求

1. **核心需求**：全程统一到本地时区，杜绝UTC/本地混用
2. **覆盖范围**：DB存储、API输出、前端展示、日志文件（prompt log）
3. **约束**：
   - 不能固定偏移（如+8），必须用实际时区偏移（`safe_utc_offset()`）
   - 排序字符串必须一致（新旧混存会导致乱序）
   - 前端零改动（`Date.parse` 对无Z ISO按本地解析）
   - 关联逻辑正确，增强不能退化

## 二、解决的问题

### 2.1 task004报告问题1（属实）
prompt log 中 `步骤产出[].数据.timestamp` 是 UTC Z（唯一），其余7个时间字段是本地，差8小时。

### 2.2 老陈发现（DB存储线全UTC）
整个存储线（chat/task/operations 三库）全部写入 `get_utc_timestamp()`（UTC Z 字符串），不止日志。

### 2.3 输出层破坏本地化
- `format_timestamp()` 对字符串**强制追加 Z** → DB 本地时间也会被标成 UTC
- `convert_to_utc()` 用于输出 title_updated_at → 转回 UTC
- `database.py _validate` datetime/date 参数自动转 UTC

### 2.4 duration计算bug
`operation_record.py:146-148` 把 naive datetime 强制补 UTC，与 `executed_at_dt = datetime.now(timezone.utc)` 相减 → TypeError（naive vs aware）

## 四、方案设计

### 4.1 核心原则

1. **存储统一本地**：三库所有时间列写 `get_local_iso_timestamp()`（本地 ISO，T分隔，**无Z/无偏移**）
2. **转换动态偏移**：UTC→本地 用 `safe_utc_offset()` 获取实际偏移，**不能固定+8**
3. **输出统一本地**：`format_timestamp()` 改语义——字符串原样返回，不再强制加Z
4. **前端零改动**：本地无Z ISO 格式 Date.parse 自动按本地解析

#### 4.2.2 新增 `to_local_iso(time_value)`

```python
def to_local_iso(time_value: Any) -> Optional[str]:
    """任意时间值 → 本地ISO(无Z/无偏移) — 小欧 2026-08-08
    
    支持: None→None; datetime(aware/naive)→本地; int/float(毫秒)→本地;
          str(含Z/+00:00/+08:00等任意偏移/naive)→本地。解析失败原样返回。
    用于: database.py 参数归一化、迁移脚本、输出层。
    会审修正: 不依赖'Z'/'+00:00'判断分支, 统一 fromisoformat 解析(Python3.11+
             fromisoformat 原生支持 Z/+08:00 偏移), 转 astimezone 本地后去偏移。
    """
    if time_value is None:
        return None
    # datetime 类型
    if isinstance(time_value, datetime):
        if time_value.tzinfo is not None:
            time_value = time_value.astimezone()  # aware → 本地
        return time_value.replace(tzinfo=None).isoformat()
    # int/float 毫秒
    if isinstance(time_value, (int, float)):
        try:
            return datetime.fromtimestamp(time_value / 1000).isoformat()
        except (OSError, OverflowError, ValueError):
            return str(time_value)
    # 字符串: 统一 fromisoformat 解析(原生支持 Z/偏移), 成功则转本地去偏移, 失败原样返回
    s = str(time_value).strip()
    if not s:
        return None
    try:
        dt = datetime.fromisoformat(s.replace('Z', '+00:00'))  # 兼容裸Z(Python<3.13)
        if dt.tzinfo is not None:
            dt = dt.astimezone()  # 任意偏移 → 本地
        return dt.replace(tzinfo=None).isoformat()  # 去偏移
    except (ValueError, TypeError, OverflowError):
        return s  # 解析失败原样返回
```

#### 4.2.4 `safe_utc_offset()` 保留不动

```python
def safe_utc_offset() -> int:
    """安全获取本地UTC偏移小时数 — 小沈 2026-07-26
    datetime.now().astimezone().utcoffset() 在某些环境返回None, 此时默认UTC+8。
    注意: 此函数获取的是实际偏移, 不固定+8。"""
    try:
        offset = datetime.now().astimezone().utcoffset()
        if offset is None:
            return 8
        return int(offset.total_seconds() / 3600)
    except (OSError, AttributeError, TypeError):
        return 8
```

### 4.4 迁移脚本设计

新建 `backend/scripts/migrate_utc_to_local.py`：

**关键点**：UTC→本地 转换用 `astimezone()` 自动转本地（Python 自动处理时区/夏令时），**不能固定+8，也不用手动 safe_utc_offset**。

```python
def utc_z_to_local(utc_str: str) -> str:
    """UTC Z / 带偏移 字符串 → 本地ISO无Z — 小欧 2026-08-08
    会审修正: 用 astimezone() 自动转本地(Python 按当前系统时区/夏令时处理),
    替代 safe_utc_offset() 手动加偏移(后者对历史数据/夏令时切换不准确, 且是绕路)。
    判断逻辑扩展: 以 Z 结尾 或 含时区偏移(如+08:00) 均需转换; 本地naive无偏移原样跳过。"""
    if not utc_str or not isinstance(utc_str, str):
        return utc_str  # 空/非字符串，跳过
    s = utc_str.strip()
    # 判断是否含时区信息(Z 或 +08:00 偏移) — 会审修正: 兼容 timers 表的 +08:00 格式
    has_tz = s.endswith('Z') or ('+' in s[10:]) or ('-' in s[10:])
    if not has_tz:
        return utc_str  # 已是本地naive无偏移，跳过(幂等)
    try:
        dt = datetime.fromisoformat(s.replace('Z', '+00:00'))  # Z → +00:00
        local_dt = dt.astimezone()  # 任意时区 → 本地(自动处理偏移/夏令时)
        return local_dt.replace(tzinfo=None).strftime('%Y-%m-%dT%H:%M:%S.%f')
    except (ValueError, TypeError, OverflowError):
        return utc_str  # 解析失败原样返回(幂等)
```

**迁移步骤**：
1. 自动备份三个DB文件（.bak）
2. 遍历三库所有时间列
3. 逐行判断：以 `Z` 结尾 → 用 `utc_z_to_local()` 转换
4. 已是非Z格式跳过（幂等）
5. SQL抽查验证
