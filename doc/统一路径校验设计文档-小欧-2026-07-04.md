# 统一路径校验设计文档 — `validate_path`

**版本**: v3.0
**创建时间**: 2026-07-04 22:04:29
**更新时间**: 2026-07-04 23:09:28
**作者**: 小欧
**批准人**: 北京老陈

> **目标**：将当前分散在 27 个 tool 中的路径校验（`path.exists()`/`is_dir()`/`is_file()` + `validate_path_for_*()` + `validate_not_system_path()`）统一到 `validate_path()` 编排函数中，**零 safety 层依赖**。

---

## 一、设计红线

| 红线 | 说明 |
|------|------|
| **Safety 层不动** | `action_handler.py` → `tool_safety_checker.py` → `path_validator.py` 整条链不动，不 import、不复制、不调用 |
| **validate_path 在 tools_file_path_checker.py 内** | 不新建文件，防止碎片化 |
| **validate_path 编排同文件函数** | 只调用同文件的 `validate_not_system_path`/`validate_path_for_write/delete/overwrite/extract`，无外部依赖 |
| **`path = Path(xxx)` 变量赋值保留** | 后续业务代码需要 `path` 变量，只删校验逻辑（`if not path.exists()` / `is_file()` / `is_dir()`） |
| **零向后兼容** | 所有工具直接替换，不留旧代码 |
| **10 大原则** | SRP、DRY、KISS-DIRECT、SLAP、YAGNI、禁止backward、OCP、LSP、ISP、复用优先 |

## 二、最终设计：`validate_path`

### 2.1 文件位置

追加到已有文件 `backend/app/tools/validate/tools_file_path_checker.py`（126 行，追加约 75 行，不修改现有函数）

### 2.2 OpCategory 枚举（4 个值）

| 值 | 含义 | 第3层行为 |
|----|------|----------|
| `WRITE` | 写入 | 跳过存在性检查 |
| `READ_FILE` | 读取文件 | 检查存在 + 是文件 |
| `LIST_DIR` | 遍历目录 | 检查存在 + 是目录 |
| `EXISTS` | 存在性确认 | 检查存在（不限类型） |

**明确不含**：`APPEND`（append 只是 WRITE 的 options 参数）、`DELETE`（delete 用 `EXISTS` + `recursive`/`force` options）

### 2.3 4 层流水线

```
第1层 基础校验（ALL）:
  ① 路径非空 + Windows保留字符
  ② Windows保留名 → _has_windows_reserved_name

第2层 系统目录拒绝（ALL）:
  ③ → validate_not_system_path

第3层 存在性+类型（WRITE 跳过）:
  ④ path.exists()
  ⑤ path.is_file() / path.is_dir()

第4层 业务警告（按 options）:
  ⑥ content/append → validate_path_for_write
  ⑦ recursive/force → validate_path_for_delete
  ⑧ overwrite+source → validate_path_for_overwrite
  ⑨ extract_dir → validate_path_for_extract
```

### 2.4 完整代码

```python
from enum import Enum
from typing import Any, Dict

class OpCategory(Enum):
    WRITE     = "write"
    READ_FILE = "read_file"
    LIST_DIR  = "list_dir"
    EXISTS    = "exists"

_OP_RULES: Dict[OpCategory, Dict[str, Any]] = {
    OpCategory.WRITE:     {"check_exist": False, "must_be": None},
    OpCategory.READ_FILE: {"check_exist": True,  "must_be": "file"},
    OpCategory.LIST_DIR:  {"check_exist": True,  "must_be": "dir"},
    OpCategory.EXISTS:    {"check_exist": True,  "must_be": None},
}

_WINDOWS_RESERVED_CHARS = '<>:"/\\|?*'


def validate_path(
    op: OpCategory,
    path: str,
    **options: Any,
) -> Tuple[bool, Optional[str], Optional[str]]:
    """
    统一路径前置校验（编排层，同文件调所有 validate_path_for_*）

    Args:
        op:     操作类型
        path:   路径字符串
        **options:
            content:    写入内容（触发写警告）
            append:     追加标记（触发写警告）
            recursive:  递归（触发删除警告）
            force:      强制（触发删除警告）
            overwrite:  覆盖标记（触发覆盖警告）
            source:     源路径（需配 overwrite 使用）
            extract_dir: 解压目录（触发解压警告）

    Returns:
        (is_valid, error_msg, warning_msg)
    """
    # ── 第1层：基础校验 ──
    if not isinstance(path, str) or not path.strip():
        return False, "路径不能为空", None
    if any(c in path for c in _WINDOWS_RESERVED_CHARS):
        return False, f"路径包含Windows保留字符: {path}", None
    reserved = _has_windows_reserved_name(path)
    if reserved:
        return False, f"文件名包含Windows保留名: {reserved}", None

    # ── 第2层：系统目录拒绝 ──
    is_valid, sys_err, _ = validate_not_system_path(path)
    if not is_valid:
        return False, sys_err, None

    # ── 第3层：存在性+类型（WRITE 跳过）──
    rule = _OP_RULES[op]
    if rule["check_exist"]:
        p = Path(path)
        if not p.exists():
            return False, "路径不存在: " + path, None
        if rule["must_be"] == "file" and not p.is_file():
            return False, "不是文件: " + path, None
        if rule["must_be"] == "dir" and not p.is_dir():
            return False, "不是目录: " + path, None

    # ── 第4层：业务警告 ──
    warnings = []
    if op == OpCategory.WRITE or "content" in options:
        _, _, w = validate_path_for_write(
            path, options.get("content", ""), options.get("append", False)
        )
        if w:
            warnings.append(w)
    if op == OpCategory.EXISTS and (options.get("recursive") or options.get("force")):
        _, _, w = validate_path_for_delete(
            path, options.get("recursive", False), options.get("force", False)
        )
        if w:
            warnings.append(w)
    if options.get("overwrite") and "source" in options:
        _, _, w = validate_path_for_overwrite(options["source"], path, True)
        if w:
            warnings.append(w)
    if "extract_dir" in options:
        _, _, w = validate_path_for_extract(options["extract_dir"])
        if w:
            warnings.append(w)

    return True, None, "; ".join(warnings) if warnings else None


__all__ = [*existing_names, "OpCategory", "validate_path"]
```

**追加 ~75 行**，不修改现有函数。

### 3.1 通用改动模式

from app.tools.validate.tools_file_path_checker import validate_path, OpCategory

async def some_tool(file_path, ...):

## 五、10 大原则逐条复核

| 原则 | 检查结果 |
|------|---------|
| **SRP** — 单一职责 | `validate_path` 只做"路径前置校验"一件事，不掺业务逻辑 |
| **DRY** — 不重复 | ~31 处分散校验集中到 1 个函数，去掉 safety 层重复的系统目录检查 |
| **KISS-DIRECT** — 简单直接 | 4 层流水线：基础→系统→存在→警告，直线返回，无七绕八绕 |
| **SLAP** — 同一抽象层 | 全部在工具层编排，不混入 safety 层的 blacklist/whitelist |
| **YAGNI** — 不过度设计 | 不加 safety 层已做的事（黑名单、白名单、路径穿越），不加用不上的 OpCategory |
| **禁止backward** | 25 个 tool 直接替换，不留旧校验代码，无 if/else 分支 |
| **OCP** — 开闭原则 | 新增 OpCategory 枚举值即可扩展，不修改 `validate_path` 主体 |
| **LSP** — 里氏替换 | 无继承体系 |
| **ISP** — 接口隔离 | `(op, path, **options) → (bool, str, str)` 极简接口 |
| **复用优先** | `validate_path` 只编排同文件已有函数（`validate_not_system_path`/`validate_path_for_*`），不重写 |
