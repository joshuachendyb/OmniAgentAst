# 三、功能提示能力增强（3 项）

## 3.1 MouseScrollInput.amount 加 ge=1 约束

| 项目 | 详情 |
|---|---|
| 文件 | desktop_schema.py |
| 变更 | `amount: int = Field(default=3, ge=1, description="...必须为正整数")` |
| 设计理由 | 滚动次数语义上必须为正整数，schema 层前置拦截比纯依赖运行时 guard 更明确 |
| 运行时 guard | mouse_scroll.py 保留 `amount <= 0` guard，双重防御 |
| 影响 | LLM 传 amount=0 或负数现在被 schema 层直接拦截，返回 ValidationError |

## 3.2 KeyboardControlInput.text_or_keys 加 min_length=1

| 项目 | 详情 |
|---|---|
| 文件 | desktop_schema.py |
| 变更 | `text_or_keys: str = Field(..., min_length=1, ...)` |
| 设计理由 | 空字符串对 type 和 shortcut 操作均无意义，前置拦截比依赖运行时 guard 更早 |
| 运行时 guard | keyboard_control.py 保留 `not text_or_keys.strip()` guard，双重防御 |
| 影响 | LLM 传空 text_or_keys 现在被 schema 层直接拦截 |

## 3.3 KeyboardControlInput docstring 补单键指引（核心能力提示）

| 项目 | 详情 |
|---|---|
| 文件 | desktop_schema.py |
| 变更 | docstring 补充单键示例（enter/esc），明确 shortcut 支持单键和组合键 |
| 设计理由 | 实测 `pyautogui.hotkey("enter")` 已支持单键按下，但旧 docstring 仅写"支持组合键"，误导 LLM 认为 shortcut 必须含 + 号。补充后 LLM 知道 single-key 通过 shortcut 即可完成，无需新增独立的 press action（避免冗余） |

## 3.4 MouseClickInput 加 clicks 参数（新能力）

| 项目 | 详情 |
|---|---|
| 文件 | desktop_schema.py, mouse_click.py, desktop_register.py |
| 变更 1 | MouseClickInput 加 `clicks: Literal[1, 2] = Field(default=1, description="点击次数:1=单击/2=双击")` |
| 变更 2 | mouse_click 函数签名加 `clicks: int = 1`，`pyautogui.click(..., clicks=clicks)` |
| 变更 3 | `_build_mouse_click_llm_data` 根据 clicks 动态生成 click_type (single/double) 和文本 (单击/双击) |
| 变更 4 | desktop_register.py 描述和示例补双击场景 |
| 设计理由 | 双击是高频桌面操作（打开文件/双击单元格编辑），此前 LLM 只能用两次单击模拟，但两次调用间 LLM 编排延迟常超过双击时间窗口（~500ms），导致双击失效。新参数使双击原子化、可靠 |
| 影响 | clicks=1 完全向后兼容，默认值不变 |

## 3.5 Window{Focus,Resize}Input.window_title description 补非空提示

| 项目 | 详情 |
|---|---|
| 文件 | desktop_schema.py |
| 变更 | description 末尾加"不能为空" |
| 设计理由 | window_title 在 schema 层是 `str`（允许空串），但运行时工具层要求非空。前置在 description 提示可减少 LLM 无效调用 |
